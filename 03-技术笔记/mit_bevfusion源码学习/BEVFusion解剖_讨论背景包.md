# 已学内容 1：Dataset / DataLoader 分工（胶水a）

厨房类比：

| 角色 | 类比 | 职责 |
|---|---|---|
| pkl 索引文件 | 菜单/索引卡 | 只存每帧的文件路径+标定+标注，不存数据（473MB 索引对应 398GB 数据）|
| Dataset | 厨师 | 接号 idx **只做一帧**：查索引 → 过 pipeline（加载点云/叠帧/增强等一串加工）→ 吐一个字典 |
| DataLoader | 传菜系统 | 发号(shuffle)、雇工人(多进程)、凑单(batch)、摆盘(collate) |

要点：
- **Dataset 只懂单数，DataLoader 才懂复数**（batch 概念只存在于后者）
- 摆盘规则 collate：图像尺寸相同可堆成 (B,3,H,W)；**点云每帧点数不同堆不了**，
  只能保持"每帧一个张量的列表"进模型（DataContainer = "别帮我堆叠"的标签）
- 训练时若某帧没有有效目标框，Dataset 会随机换一帧重做（保证 batch 无空样本）
- CBGS（类别平衡重采样）是套在发号环节的包装层：稀有类样本的号多发几次
- 我的配置：batch=1、工人=1（单卡小机器）

# 已学内容 2：第 1 站——体素化（点云 → 柱子）

## 要解决的矛盾

点云是**无序、数量不定**的点集；卷积网络要求**有序、尺寸固定**的网格。体素化 = 切网格。

## 两种刀法

| | voxel 体素 | pillar 柱子（我用的）|
|---|---|---|
| 切法 | x/y/z 三向都切 → 3D 小方块 | 只切 x/y，z 整根不切 → 2D 网格上的柱子 |
| 后续卷积 | 3D 稀疏卷积(spconv) | 普通 2D 卷积 ← 快、免疫 spconv bug |

## 关键配置（我机器实况）

| 配置 | 值 | 含义 |
|---|---|---|
| point_cloud_range | ±51.2m(xy), -5~3m(z) | 出界点直接丢 |
| voxel_size | [0.2, 0.2, 8] | 柱底 0.2m×0.2m；z 一格=8m 全高，即"不切z"的写法 |
| → 网格 | 102.4/0.2 = **512×512** | 输入画布尺寸，恒定 |
| max_num_points | 20 | 每柱最多 20 点，超了随机丢，不足补零（hard voxelization）|
| max_voxels | 训 30000 / 测 60000 | 非空柱子名额，先到先得，超了整柱丢 |

## 实测（我亲手跑的形状打印脚本，nuScenes val）

**符号：N=点总数，M=非空柱子根数**（即张量 shape 的第一个数字）。

测了两个样本，一个正常（场景中段 idx20），一个意外踩中退化样本（场景首帧 idx0）：

| 指标 | idx20 单帧 | idx20 叠10帧 | idx0 单帧 | idx0 "叠10帧"(退化) |
|---|---|---|---|---|
| N | 32 120 | 229 846 | 33 686 | 252 458 |
| M / 画布占比 | 7 689 / 2.9% | **27 186 / 10.4%** | 7 324 / 2.8% | **7 324 / 2.8%(纹丝不动!)** |
| 每柱均点 / 满载率 | 2.9 / 1.0% | 5.9 / 9.7% | 3.4 / 1.9% | 16.1 / 61.3% |
| 进不了柱子的点 | 31.4% | 29.9% | 27.1% | 53.2% |

**四个大发现**：
1. **点数×7，画布纹丝不动 512×512**——变的只是"有墨的格子数"(M×3.5)和
   "墨的浓度"(每柱点数×2)。单帧占用率仅 2.9% = 点云稀疏性的第一手数字
2. **idx0 的 M 完全相同是个事故**：它是场景第一帧，**没有历史可叠**，
   加载器的 pad_empty_sweeps 机制用当前帧自我复制凑数 → "10帧"实为同一帧
   多份拷贝落进相同格子（已查 pkl 证实 idx0 的 sweeps 数=0）。
   教训：选样本要避开场景首帧
3. **叠10帧的 M=27186 已达训练配额 30000 的 91%**——贴线运行，更稠密的
   市区场景很可能越界 → 训练中部分帧的柱子被静默丢弃
4. 丢点率单帧/叠帧都 ~30%，主因是超出 51.2m 的远点出界，不是叠帧的锅

## 统计脚本输出逐列说明（应 2026-08-28 纪要要求补充）

脚本 anatomy_s1.py 只做前向的第一步（体素化），**不训练、不更新权重**：

| 输出 | 含义 | 为什么看它 |
|---|---|---|
| points (N,5) | 输入点数 N，每点 5 维（x,y,z,反射强度,时间戳偏移） | 确认输入规模：单帧~3.2万，叠10帧~23万 |
| voxels (M,20,5) | M 根非空柱子，每根最多 20 点原样保留 | **M=网络真正要算的柱子数**，对照训练配额 30000 看是否越界 |
| coords (M,3) | 每根柱子在 512×512 网格中的整数坐标 | 柱子放回画布的"地址"，下一站 scatter 全靠它 |
| num_pts (M,) | 每根柱子实际装的点数 | 算浓度和满载的原材料 |
| 非空占比 | M ÷ 262144 | 点云稀疏性（单帧仅 2.9%，97% 画布是空的） |
| 每柱均点 | 浓度 | 叠帧"墨变浓"的量化（2.9 → 5.9） |
| 满载率 | 装满 20 点被截断的柱子比例 | **信息丢失警报**（退化样本曾飙到 61%） |
| 丢点率 | 出界 + 截断而进不了网络的点比例 | 衡量"叠的帧有多少真进了网络"（~30%，主因远点出界） |

# 实验全景（当前状态快照，任何相关提问以此为准）

## 环境与数据

- 单卡 RTX 4060 Ti 16G 工作站；nuScenes 全量 398G 已落地（850 场景：train 700 / val 150）
- 训练用固定子集 **q25**（175 场景 / 7026 帧，按场景切分防信息泄漏）；
  **评测永远用全量 val 6019 帧**（nuScenes 评测器不接受子集）
- 无 AMP（仓库不支持 fp16），全程 fp32；CBGS（类别重采样，会把 epoch 放大 4.4 倍）默认关闭

## 已完成的里程碑

1. **阶段 0 基准测速**：各模型×batch 的 s/iter 与显存实测完毕
2. **阶段 A 可行性验证**：PointPillars + 叠10帧 + q25 + lr 3e-5 训 20 轮，
   **mAP 0.3153 / mAVE 0.6920** ——这就是 T1 消融的 10 帧基线（=T1-B）
3. **T1 Part 1 可视化实验**（叠多帧与运动补偿的定性+定量分析）：
   - 两级补偿：第①级自车运动补偿用定位数据（ego_pose），推理时可用；
     第②级目标运动补偿要用人工标注的目标速度，**只能用于真值生产，推理时不可用**
   - BEVFusion 只做第①级 → 运动目标留拖影（实测残影率：运动目标 49.3% vs 静止 14.3%）
   - 拖影不全是坏事：配合点云第 5 维时间戳（当前帧=0，历史帧=时间差），
     网络可分辨新旧点，拖影方向长度=速度线索——这正是叠帧助攻 mAVE 的机制假设

## T1 专题：叠多帧 × 运动补偿消融（当前主线）

面试高频丢分专题的补强实验（参考朋友的 Radar 叠多帧实验设计），评价指标 mAP + mAVE：

**2026-08-28 战略转向**：目标从"应对面试专题"转向"胜任工作的框架全貌"（用户原话：

| 组（白话名） | 输入 | 状态 |

**结题结论（2026-08-28）**：核心假设一半应验一半被推翻——
①速度：mAVE ×2.4 且单帧全程平台期（1.60~1.66），训练量救不了，假设成立；
②检测："mAP 受影响较小"**被数据否定**——掉三成，塌方集中在小目标
（bicycle≈0 / motorcycle 0.16 / cone 0.21，car 基本无损），机制=叠帧稠密化
救的正是点少的小目标（与体素化实测柱子浓度×2 互证）。
面试一句话：叠帧收益双重——时序线索喂速度头（主）+ 稠密化救小目标（次）。

**学习率窗口链条**（实测）：8卡 1e-4 → 单卡10帧 3e-5 → 单卡单帧 1e-5，
输入密度每降一档窗口下移一档，机制=点少→梯度噪声大。

**T1-A（单帧组）重训始末**（2026-08-28）：
  1. 首训沿用 10 帧组的 lr 3e-5（cyclic 峰值 3e-4），第 5 轮 lr 爬到 2e-4
     越过单帧发散阈值 → 梯度爆炸 → NaN 崩溃。前 4 轮 iou 仅 0.016（一直没学明白）
  2. 重扫学习率 {1e-5, 1.5e-5, 2e-5} 各 2 轮：1e-5 健康(iou 0.223)、
     2e-5 略高(0.236)但峰值 2e-4 正好贴发散阈值、1.5e-5 反常地烂(0.016)——
     验尸确认是无固定 seed 下抽中坏初始化，不是 lr 的错（学习率影响是单调的，
     夹中间的值不可能单独坏）
  3. 选 1e-5 重训（5% 分差小于运气噪声，安全余量优先）。
     **重训与首训的唯一区别 = 学习率 3e-5→1e-5**，模型/数据/单帧输入全部不变
  4. **审计钉死（2026-08-28 日志核验）：lr 1e-5 从未崩溃**（无 Traceback、loss 无
     nan、扫描跑满 2 轮）。用户"1e-5 又崩了一次"的记忆锚点是：code 窗口一次已更正的
     误报 + 日志开局的一条瞬时 grad_norm: nan（见下），均不构成崩溃
  5. 新发现：三组扫描**开局（步50）grad_norm 全为 nan**——是本模型初始化阶段的
     普遍现象（初始 loss ~670），三组均扛过、权重未受实质污染；1.5e-5 独多一次
     （ep1 步2350），其"坏彩票"又添一证
  6. 正式重训（20轮）**2026-08-28 13:25 已启动**（按第2次纪要指令由 code 窗口
     代执行，用户休息），预计 13–15 小时，每 5 轮在全量 val 评一次 mAP/mAVE
