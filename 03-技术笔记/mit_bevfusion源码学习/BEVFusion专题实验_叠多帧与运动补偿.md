# 一、实验设计总览

## 1.1 为什么用 LiDAR 而不是 Radar（与朋友实验的差异）

朋友的实验对象是 **Radar 多帧输入**，我们做 **LiDAR**，三个理由：

1. **代码现实**：MIT BEVFusion 的模态配置 `use_radar: False`，整条管线没接 Radar；
   我们已跑通的 PointPillars 吃的就是 LiDAR 点云，`LoadPointsFromMultiSweeps` 现成
2. **面试对口**：简历项目（BCGOneNet）的叠帧稠密化做的是**激光点云**；
   专题文档全部围绕激光展开。Radar 实验借鉴的是**实验设计方法**，不是对象
3. **原理展示更强**：LiDAR 点密、无逐点速度属性，补偿做不做的差异肉眼可见
   （拖影/糊成一片），适合把原理学透

同一套自车补偿机制（帧间位姿刚体变换）对两种传感器完全一样，学会了即可迁移。

# 二、Part 1 · 可视化与残影率量化（CPU）

## 2.0 术语表（第一次出现的符号都在这）

| 术语 | 含义 |
|---|---|
| `info` | pkl 索引里**一帧的记录**（字典），字段见实验记录 [00] |
| **sweep** | nuScenes 激光 20Hz 转、标注只标 2Hz 关键帧，**两关键帧之间无标注的中间帧** |
| `info["sweeps"]` | 该帧向前最多 10 个 sweep 的列表，每项含点云路径、时间戳、变换 R/t |
| `sensor2lidar_rotation/translation` | "sweep 时刻激光系 → 当前关键帧激光系"的刚体变换 (R, t)，**即第 1 层自车补偿** |
| `obtain_sensor2top` | `tools/data_converter/nuscenes_converter.py` 里的函数，生成 pkl 时**预先算出** R/t；`top` 指车顶雷达 LIDAR_TOP。算法：sweep激光系→当时车体系→全局系→现在车体系→现在激光系（串标定外参与 ego_pose） |

**关键认知**：自车补偿的**计算**发生在数据准备期（`create_data.py`），
训练期 `LoadPointsFromMultiSweeps` 只是**应用**（一行矩阵乘法）。

## 2.1 原理（对应专题〇总图）

nuScenes 的 `info["sweeps"]` 每项带 `sensor2lidar_rotation/translation`——
这是数据准备阶段（`create_data.py` 的 `obtain_sensor2top`）算好的
**历史帧激光坐标系 → 当前帧激光坐标系** 的变换，本质就是两帧间自车位姿差。

`LoadPointsFromMultiSweeps` 对每帧 sweep 做：

```python
points_sweep[:, :3] = points_sweep[:, :3] @ R.T + t     # ← 这一行就是第 1 层自车补偿
```

**关掉这一行 = 朋友实验的"无补偿"组 = 专题 A1 的"整个世界拖影"。**

自车补偿后，静止世界对齐；但**运动目标自己走过的位移没人管**——nuScenes 输入聚合
**故意不做**第 2 层目标补偿（专题 Q15：拖尾留给模型当运动线索）。

## 2.2 残影率定义（对应专题 §4.2）

对每个运动目标（|v| > 1 m/s）：
- 其在 sweep 时刻的位置 ≈ 当前框中心 − v·Δt（匀速倒推，nuScenes sweeps 无标注，只能近似）
- 落在该倒推框内的补偿后 sweep 点 = 该目标的历史点
- **残影率 = 历史点中落在当前 GT 框之外的比例**

静止目标（|v| < 0.5）同样计算作为对照，应接近 0。

## 2.4 v1 首跑结果与发现的问题（2026-08-27）

v1 脚本首跑（帧 index=93）**自检项失败**，由此挖出两个发现：

**① yaw 存储约定 bug（脚本错误，已修）**
GT 框画歪、残影率被污染（静止目标 22%，应≈0）。
根因：pkl 存的 yaw = **-几何朝向 - 90°**（mmdet3d 旧约定）。
实证：修正后框内点数 441 → 558。详见踩坑记录第 19 条。

**② 自车近场"补偿反而更糊"是真实物理（不是错误）**
激光打在自车周围地面的同心扫描环，补偿后每帧的环被搬到自车**当时的**位置
→ 沿行驶轨迹排开，看似拖影，实为自车历史足迹。
不补偿时所有环叠在原点反而"整齐"。
**近场地面环纹理是补偿是否生效的反向指标**——反直觉但正确。

**②b 补偿后自车位置上有点，不补偿反而"干净"（同类认知反转，v2 复跑再次确认）**
- 不补偿：每帧 sweep 的自车盲区（洞）都在原点，十个洞叠一起 → 原点永远干净
- 补偿后：0.3s 前那帧能看到"现在车底下"的这块地面（当时在车前方），
  搬运后这些点正好落在当前车底 → **历史帧填补了当前帧的盲区**
- 这是叠帧的一个真实收益（盲区填补），"车底有点"恰恰说明聚合在正常工作

**归纳（两次认知反转的共同规律）**：自车补偿把"以自车为中心的固定模式"
（扫描环、盲区洞）打散成世界坐标下的真实分布——模式消失让画面显得"乱"，
但那才是真实世界；"整齐"的反而是十帧都假装车没动。
**判读叠帧图时，不要用"看起来整齐"当正确性标准，要用"静止物体是否重合"。**

**②c 追问：自车位置有点云，会不会造成误检？（2026-08-27 实验中的提问）**
不会，三个理由：
1. 检测靠"高于地面的立体结构"，不是"有没有点"——一片平坦路面点构不成车形结构
2. 训练分布一致：训练数据每帧都这样聚合，模型从第一天就在这种输入上学习
3. 反证：若"有点就报框"，整条马路都是误检
**边界**：若补偿本身错（位姿差），历史点落错位形成假结构才可能诱发误检——
这正是专题 Q3 里"位姿精度 ~10cm"存在的意义：位姿精度是搬运不产生噪声的前提。

**②d 点数守恒律：补偿只搬运点，不增减点**
图2/图3 总点数完全相同，疏密差异 = 点被放在哪的差异，必然成对出现：
| 位置 | 补偿 | 不补偿 |
|---|---|---|
| 真实静止结构 | 十帧精确重合 → 细而浓的线 | 各偏一点 → 宽而淡的带 |
| 自车中心图案(环/盲区) | 沿轨迹摊开 → 变稀 | 叠在原点 → 假性浓密 |
判读法："补偿更密处"=真实静止物；"不补偿更密处"=自车中心采样图案。
肉眼陷阱：糊开的宽带覆盖面积大显得"点多"，实为局部密度低——
所以全景肉眼比密度不可靠，要靠特写+残影率数字。

**③b 特写图糊的原因（v2 发现，v3 修复）**：特写窗口没滤地面点，
地面铺满窗口且平坦（补不补偿视觉差异小），淹没了目标本体的对齐/错位差异。
v3 起特写只显示目标高度层（z ∈ 框z±h/2）内的点。

**③ v1 选帧自车太慢（0.5s 仅 1.38m）**，全景补偿开关差异不可见
→ v2 选帧条件加"自车位移 >4m"。

v1 残影率数字（受 yaw bug 污染，仅存档不采用）：运动 43.7% / 静止 22.1%。

## 2.5 v2/v3 结果（2026-08-27 实测，4 帧：385/766/1098/1408，自车位移均 >4m）

### 残影率实测（核心数字，面试可引用）

| | 加权平均残影率 |
|---|---|
| **运动目标（41 个）** | **49.3%** |
| **静止目标（72 个）** | 14.3% |

**核心规律成立**：只做自车补偿时，运动目标约一半历史点落在当前框外（残影），
是静止目标的 3.4 倍——这正是第 2 层目标补偿存在的理由（专题 Q5）。

### 静止 14.3% 超自检线（<10%）的拆解 —— 指标定义的适用边界

| 静止目标类型 | 实测残影率 | 解释 |
|---|---|---|
| 孤立规整（truck/car/锥桶） | **0~6% ✅** | 补偿工作正常的直接证据 |
| 成排/细长/密集（barrier 排、人群） | 15~42% ❌ | ①邻居串扰：1.2×归属框吃进隔壁目标的点 ②细长目标边缘壳占比大 ③标注抖动 |

**结论**：污染来自归属歧义而非补偿失效。**指标定义有适用边界**——
残影率在孤立目标上可信；密集场景需一对一分配归属或只统计孤立目标。

### 运动目标数字里的规律

- 10.4 m/s 小车残影率 97%（0.5s 跑 5m，历史点全甩出车外）
- 10.2 m/s 大货车仅 6.3%（车长十几米，尾巴没出自己的框）
→ **残影率 ≈ f(位移 / 目标长度)**，同速度下小目标残影更严重——
   这解释了为什么行人/自行车最吃目标级补偿（专题 Q9 非刚体表述的补充证据）

### 追问沉淀：点是必要条件不是充分条件（2026-08-27）

"自车上有点会不会误检"的完整回答：
- 没有点出不了框（网络只见点）→ 检测框必然贴合点团（仿真可视化的日常观感）
- 但有点的地方绝大多数不出框（地面/墙面占每帧点数 90%+ 却零检测）
- 观感偏差来源：可视化只展示"出了框的地方"，看不到"有点无框"的海量区域
- **决定出框的是点团结构（高度/形状/密度模式），源自标注监督学出的判别力**
- 边界：补偿错误时历史点堆成车形假结构才可能误检 → 位姿精度（~10cm）是前提

# 六、Part 1 高潮：亲手抓到残影本尊（2026-08-27，帧 1408）

用户在 f1408/2_comp.png 圈出前车尾后拖着一串历史点，质疑"点云跑到车屁股后面"；
又发现 3_nocomp.png 里同一辆车的点反而"贴合"。**这正是专题的核心现象**：

## 数字还原

```
自车 8.2 m/s（0.5s 走 4.1m），前车 10.8 m/s 同向 → 跟车场景
图2（世界系）：前车历史点留在真实经过的位置 → 车尾后 ~5.4m 尾巴 = 残影
图3（自车系）：相对速度仅 2.6 m/s → 前车十帧点只错开 ~1.3m → 看似"贴合"
              但代价：两侧墙/护栏变成黄红梯状宽带（整个静止世界拖影）
```

## 镜像定律（本实验最重要的一句话）

> **补偿（世界系）：静止物清晰，运动物拖影。
> 不补偿（自车系）：与自车同速的物体清晰，其余一切拖影。**
> 谁糊谁清只取决于坐标系钉在世界还是钉在自车——两图是同一份数据的忠实呈现。

跟车场景是最迷惑的特例：前车恰好属于"与自车近似同速"，所以不补偿反而显得"对"。

## "点跑到自车位置"的正解

点没动，**原点动了**。那块路面在世界里位置不变；坐标以"现在的自车"为原点，
自车开到路面上，路面点的坐标就成了 (0,0) 附近。变的是原点，不是点。

## 直觉冲突的根源（Q15 的亲身版）

用户的直觉"点应贴在目标上"来自**公司项目做过两级补偿的点云**（目标点被搬进当前框）；
nuScenes 输入聚合只做第 1 层，尾巴保留为运动线索。
两种都对——正是 Q15 区分的"真值生产语境（两级）"与"输入聚合语境（一级）"。
稠密化的准确表述：只做第1层时，静止物稠密化到**目标本身**、
运动物稠密化到**轨迹** → 第2层的意义 = 把轨迹上的点搬回目标。

## 视频问题

连续帧聚合视频里拖影持续存在（彗尾随车移动），非单帧假象。
且 PointPillars 训练输入就是图2这种带尾巴的点云——尾巴是输入分布的一部分，
模型可借尾巴方向长度估速（Part 2 用 mAVE 验证此假设）。

## 六.b "图是不是画反了"的三个判别点（2026-08-27 用户质疑后总结）

判断一张聚合点云图**有没有做自车补偿**，看三处（按可靠性排序）：

| 判别点 | 补偿了 | 没补偿 |
|---|---|---|
| **同心扫描环** | 拉散成 N 套错开副本（沿自车轨迹） | 一套完美同心圆（N 帧叠在同一圆心） |
| **自车盲区剪影** | 剪影内有历史点（盲区被填补） | 干净的白洞（N 个洞叠在原点） |
| **垂直于行驶方向的静止墙** | 细线 | 梯状宽带（总宽 ≈ 自车位移） |

**陷阱**：不要看"哪张顺眼"。中心环和同速前车在**不补偿**图里反而整齐
（它们是"自车系整齐族"），视觉注意力会被它们带偏。
判别永远以**世界系静止物**（横墙/杆/停放车辆）为准。

## 术语补充：真值生产（Ground Truth 生产）

= 离线制造"给 loss 用的教师信号"的管线，与输入聚合是两条流水线：

```
输入聚合: 点云 → 叠帧(仅第1级) → 模型输入          【训练+推理都跑】
真值生产: 点云 → 叠帧(第1+2级) → 投影图像 → 稠密深度图 → loss 的答案  【离线，仅训练前】
```

第2级只能住在真值生产里：真值可奢侈使用标注/未来帧（离线不限算力与信息），
输入必须推理期同样可得。若输入聚合在训练期做第2级 → 训练(无拖影)/推理(有拖影)
分布不一致，反而有害。——"收益进权重，代价留训练侧"（专题 Q7/Q8）

## 七.c 两级补偿的信息来源对照（2026-08-27 用户提问沉淀）

**问**：目标补偿用标注做，那自车补偿也是标注做的吗？
**答**：不是。一句话：**自己的运动自己知道，别人的运动只有标注知道。**

| | 自车补偿（第①级） | 目标补偿（第②级） |
|---|---|---|
| 要知道什么 | 我自己 0.5s 挪了多少 | 他车 0.5s 挪了多少 |
| 信息来源 | 定位系统实测（IMU+轮速+GNSS/RTK） | 人工标注（自车无传感器能直接测他车位姿） |
| 推理期可得 | ✅ 实时输出 | ❌ 路上没人标注 |
| nuScenes 对应文件 | `ego_pose.json`（机器记录） | `sample_annotation.json`（人工标注） |
| 我们实验中用到 | `sensor2lidar` R/t（viz_moc.py 第①级） | `gt_velocity`（viz_moc_level2.py 第②级） |

**第①级能进输入聚合、第②级只能进真值生产——不是规定，是信息来源天然决定的。**
（若用模型预测代替标注做第②级 = "用检测结果帮检测"的鸡生蛋问题）
