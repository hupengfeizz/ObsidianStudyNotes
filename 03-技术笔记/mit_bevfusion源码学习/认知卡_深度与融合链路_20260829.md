# 认知卡 · 深度与融合链路
## 一条线：深度从哪来 → 放到哪去 → 融合融的是什么 → 头怎么出框

---

## 一、激光的双重身份（本卡地基）

> **激光既是训练期的老师，也是推理期的传感器——前者可以毕业，后者不能缺席。**

| 身份 | 存在于 | 干什么 | 能不能去掉 |
|---|---|---|---|
| ① 老师（监督） | **只在训练期** | 点云投影成稀疏深度图，给 DepthNet 当真值算 loss | 能——训好即"毕业"，推理模型里这一项不存在 |
| ② 传感器（支路） | **推理期全程在跑** | 自己走体素化 → backbone → 出一张 BEV 特征图，与相机拼接 | 不能——这是融合版的半壁江山 |

**为什么前向必须留激光**：相机的深度是**猜**的（从像素推断，遇到没见过的目标 / 反光 / 恶劣天气会错且不自知）；激光的深度是**量**的（物理反射时间，与目标长相无关）。前向是高速行驶的主要风险方向，那里需要一份**不依赖学习的物理测距**。侧向让相机猜是可接受的风险（车速低、距离近、决策余量大）。

**量产实况（真经验，论文里没有）**：192 线这类高线束激光是**半固态、前向**的，FOV 约 120°，不是机械旋转 360°（那是 nuScenes 的 32 线老式方案）。所以量产车天然分成——
- **激光区域**（前向扇形，多模态，深度可靠）
- **视觉区域**（侧后方，纯视觉，深度靠估）

→ **查 case 先问目标在哪个区域，评测分区域统计指标。** 这句是杀手锏：把"侧向说不清"变成"侧向的弱我们知道、能测出来"。

## 二、DepthNet 与内外参：一份权重服务六路相机

### 训练怎么监督

- 有激光真值的地方（前向投影落点处）：显式深度 loss。
- **camera-only / 没有真值的地方：没有深度监督，隐式学**——唯一梯度来自检测头（框错了 → 梯度经视图变换传回 DepthNet）。原始 LSS / BEVDet 就这么干；BEVDepth 的贡献就是把激光深度图加回来当显式监督。

> **显式 / 隐式说的是"监督的来源"，不是"预测的方式"。** 两种情况下 DepthNet 都在预测同一串深度分布，前向传播一模一样；差别只在训练时有没有直接反馈。
> **推论：加不加深度监督，网络结构一行不改，导出的 onnx 完全相同——它是 loss 里的一项，不是架构的一部分。**（真正改架构的是"深度相机当输入"：DepthNet 整个模块消失。见配置迁移卡基石 2。）

### 内外参怎么进（⚠️ 我犯过的错）

- ❌ 我原来的理解：前侧不用调，侧后方需要输入内外参"修正"。
- ✅ 正确：**六路相机统一把各自的内外参喂进 DepthNet，前视也不例外。** 这不是给弱区打的补丁，是模块的**标准输入**——六路共用一份 DepthNet 权重，靠参数输入区分"这张图是哪个相机、装在哪、焦距多少"（BEVDepth 做法：相机参数过小 MLP 调制图像特征）。
- **一句话记法：共享一份权重，靠内外参当区分彼此的钥匙。** 监督有没有 ↔ 参数喂不喂，两件独立的事。

### 真题「前向训的 DepthNet 能直接用在侧向吗」——三段答法

1. **几何差异**（焦距 / 位姿 / 朝向不同 → 同样表观尺寸对应不同深度）：靠内外参编码对齐，主要手段。
2. **语义与分布差异**（前视看车尾和远处灭点，侧视看横穿行人和车身侧面；监督集中在前向远距段）：靠**数据本身覆盖**——六路的图都进网络、都参与检测 loss，侧视内容是学过的，只缺深度那一项显式监督。
3. **剩下的残差 = 已知弱区**：分区域评测量化，不靠推理说"应该没问题"。

### 监督为什么稀疏也能教会全图

两百万像素落几千到一两万个激光点，**九成以上像素没监督**；且垂直方向线间距远处拉开（横条状分布）、距离上密度按平方衰减（50m 外几乎无点）。靠两个东西补：
- 卷积的空间连续性——有监督像素把梯度传给邻域共享权重，学的是"什么纹理对应什么深度"的**可泛化规律**，不是逐像素查表；
- 检测头 loss 的隐式约束一直在。

## 三、侧向深度到底从哪来（真题原题）

> **推理期它压根不知道哪边有激光。** 侧向深度就是 DepthNet 的正常输出——同一模块、同一份权重、同一条路径。

- 凭什么估得出：内外参告知"我是哪路相机" + 六路共享的卷积权重（前向监督学出的规律跨路生效） + 训练期检测 loss 的隐式纠正。
- **⚠️ 阶段纪律（我被抓过的措辞）**：不能说"推理靠检测任务反传纠正"——**推理期没有 loss、没有梯度、什么都不反传**。正确说法：「**侧向的深度能力是训练期靠框的 loss 间接练出来的；推理期只是在消费这个已经练好的能力。**」训练期的东西和推理期的东西是两个世界（同一条纪律的另一个化身："当标签"=进 loss 只在训练期，"当输入"=进前向推理期也在）。
- 被追「怎么改善」三条真实路径：侧向补盲激光 / 深度相机（硬件）；侧向相机时序自监督（相邻帧重投影一致性，零真值）；**或接受它，侧向检测范围设短——量产最常见是第三条，侧向本来不需要看 100m**。

## 四、融合融的是什么（⚠️ 最容易说错的一题）

- ❌ 错误图景："相机深度 + 激光深度两个数值加权融合出最终深度"。
- ✅ **融合之后没有"深度值"这个东西了，只有 BEV 特征。**

| | 相机支路 | 激光支路 |
|---|---|---|
| 位置怎么定 | **先估深度才知道往哪个格子放**——深度是中间量，决定"放哪儿"，放完即弃 | 点天生带 xyz，**位置已知，直接落格子**，全程不存在"深度估计" |
| 支路在学什么 | 语义 + 深度分布 | **纯特征提取**：柱内点分布形状是什么（车顶平面 / 行人竖直轮廓）、相邻格子连起来是一辆车还是两辆——**位置不用学，学的是"这团点是什么"** |
| 强弱 | 语义强、位置靠估 | 位置准、语义弱（50m 外一辆车十几个点，形状像车也像绿化带） |

- 融合 = 两张同坐标系、同形状的 BEV 特征图 concat → 几层**普通卷积**压通道（ConvFuser，无注意力）。
- 相机深度估偏的后果：不是"和激光打平均"，而是**特征被放进错误的格子**——融合图上激光那半在正确位置有响应、相机那半在偏移位置有响应，检测头靠训练学"该信谁"。**这就是"丢目标能查根因"成立的原因：两路 BEV 特征可分别可视化，一眼看出哪路没响应。**
- 收口句：**深度在相机支路里是中间量，用完即弃；距离信息最后以框坐标的形式出现（检测头在融合特征上直接回归中心点）。融合不是数值仲裁，是让网络在特征层面学会取舍——互补：激光给几何，相机给语义。**

## 五、Transformer 在哪 & 头怎么出框

- **BEVFusion 的融合是纯卷积；Transformer 只在检测头（TransFusion head）。** "TransFusion"的 Trans 指头用了 Transformer，**不是**指用注意力做模态融合。
- 头的流程：融合 BEV → heatmap（哪里可能有东西）→ 取响应最高 ~200 个位置的特征当**初始 query** → 几层 decoder（自注意力 + 交叉注意力）→ 每个 query 回归中心 / 尺寸 / 朝向 / **速度 (vx,vy)**。
- 代码路标（MIT 仓）：头 `mmdet3d/models/heads/bbox/transfusion.py`（搜类名 `TransFusionHead`）；底层算子 `mmdet3d/models/utils/transformer.py`；融合 `mmdet3d/models/fusers/convfuser.py`（名字里就写着 conv）。
- **对比 BEVFormer**：它的 Transformer 用在**视图变换**——BEV query 投影到图像上用交叉注意力"取"信息，不需要 DepthNet、不需要深度。**BEVFormer 用注意力代替深度估计，BEVFusion 用注意力做目标解码**——同一个工具，一个在中间，一个在末端。选型理由接量产段落：注意力隐式取信息精度可能更高，但中间没有可解释的深度，丢目标查不出是哪一路的问题。
- 若配置换 CenterHead：没有 query，heatmap 峰值位置密集回归；**速度两维依然在**，只是搬到 CenterHead 的回归分支。「速度是回归分支的一个输出维度」对两种头都成立，「query」只对 TransFusion 成立。

## 六、他车运动补偿真题：「怎么区分静止和运动目标？」

> **答案：不需要区分。**

- 机制：自车补偿完成后，对**每个前景目标**统一做一次位移 = 估计速度 × 时间差。**静止目标速度估出来 ≈ 0，位移自然 ≈ 0——不是跳过它，是它算出来本来就不动。**
- 为什么这个设计好：统一处理，**没有动静判别分支就没有判别错误**——慢速行人这种边界情况最容易被误判静止然后彻底不补。
- 速度哪来的：**检测头回归分支的两个输出维度 (vx,vy)**，与中心 / 尺寸 / 朝向并列，共享同一个头。loss 上是独立一项（L1，权重单独配）——是"总 loss 里的一项"，**不是"靠总 loss 间接学"**（有真值直接监督：nuScenes 标注自带速度，由相邻帧框位置差分而来）。
- 为什么学得出来：输入叠了多帧，同目标在几帧里的位置形成拖尾，网络从拖尾形状读出速度。**单帧模型学不出速度——没有时间信息。**（mAVE 测的就是这两维的误差。）
- 两级的分工：自车补偿用 IMU / 轮速积分的位姿、作用于**全场**（背景由它对齐，世界系里本来不动）；他车补偿用回归速度、**只作用于前景目标**。精度差一到两个数量级 → 时间窗拉长时**他车那级先崩**。
- 追问「速度不准怎么办」：**提高帧率、缩短时间窗**（误差 = 速度误差 × Δt，Δt 是唯一能直接压的项），不是改网络。

## 七、一个值得留着的思维工具：「模型」的两套标准

同一个问题——"加不加深度监督算不算两个模型"——两个答案都对，取决于标准：

| 标准 | 模型 = 什么 | 加 / 不加深度监督 | 谁用这套标准 |
|---|---|---|---|
| 结构标准 | 前向传播那条链 | **同一个模型**（每层、每个形状、onnx 完全一致） | 部署的人（只关心算子和耗时） |
| 训练标准 | 权重 | **两个模型**（loss 不同 → 梯度不同 → 权重不同 → 指标差几个点） | 评测的人（同结构为什么这版高两个点） |

多任务 loss 的一般规律：**主任务 loss 决定"学成什么样"，辅助 loss 决定"某个中间量别学歪"**。深度监督是典型辅助项——约束中间的深度分布别飘，主任务就不用浪费力气纠正它。这句解释了"为什么加了会涨"，比"加了指标好"有说服力。

## 禁句墓地（本轮新增）

| 💀 禁句 | 死因 |
|---|---|
| 「推理的时候靠检测 loss 反传来纠正深度」 | 推理期无 loss 无梯度。正确：能力训练期获得，推理期消费 |
| 「前侧不用喂内外参，侧后方才需要」 | 内外参是六路统一的标准输入，不是弱区补丁 |
| 「两条支路的深度值融合 / 加权出最终深度」 | 融合的是 BEV 特征，深度是相机支路的中间量，用完即弃 |
| 「TransFusion 用 Transformer 做模态融合」 | 融合是 ConvFuser 纯卷积；Transformer 只在检测头 |
| 「他车补偿要先区分动静目标」 | 统一按速度×Δt 位移，静止目标位移自然为零 |
| 「速度是靠总 loss 间接学出来的」 | 有独立 L1 项 + nuScenes 真值直接监督 |
| 「左右两侧距离不远所以前向训的够用」 | 侧向远距（路口横穿）恰是高危目标；正确理由 = 内外参泛化 + 隐式约束 + 分区评测承认弱区 |
