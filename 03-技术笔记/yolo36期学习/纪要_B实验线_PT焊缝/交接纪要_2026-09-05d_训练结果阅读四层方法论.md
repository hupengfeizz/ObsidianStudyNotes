> 场景:实验一(焊缝 PT 渗透探伤)BCE 基线跑完后,第一次系统学习"怎么读 YOLO 的训练输出"。

## 零、为什么需要固定动作

训练结束后 `runs/xxx/` 里会吐出十几个文件、十几张图。没有顺序地乱翻,结果是"每个数都看了,但不知道下一步该改什么"。

**固定动作:两个数字 → 三个走势 → 哪个 loss 卡住 → 翻图找样本。**

四层是**漏斗**,从粗到细。前一层不通过,后一层不用看。

## 第一层:只看两个数字,判断"跑成没成"

**文件:`results.csv` 最后一行**(或训练日志最后一行)

只看两个数:

| 指标 | 回答的问题 |
|---|---|
| **mAP50** | 找得到吗? |
| **mAP50-95** | 框得准吗? |

三十秒定性,不合格就不用往下看了。

### mAP50 与 mAP50-95 的区别 = IoU 判定阈值

- **mAP50**:IoU 阈值取 0.5 这**一个点**算出的 mAP。
- **mAP50-95**:IoU 取 0.5 / 0.55 / 0.60 / … / 0.95 共**十档**,各算一次 mAP,再取平均。

⚠️ 常见误解:mAP50-95 **不是**"50 分到 95 分"或"50 到 59"的意思,是**十个 IoU 档位的平均**。

### 结论:mAP50-95 不可能大于 mAP50

mAP50 本身就是那十档里的**第一档,而且必然是最大的一档**(阈值最松)。
最大值不可能小于平均值 → **极限情况只能相等,不可能超过。**

> **实用价值**:哪天看到某份报告里 mAP50-95 > mAP50,直接怀疑指标算错或抄反了。

### 两者的关系:永远同向,但不同步。**差距才是信息量。**

- 差距小 → 找到的框基本都框得准。
- 差距大 → **能找到,但框不准**。定位是主要矛盾。

> ⚠️ **后续做定位类改进(DIoU / NWD / 关 DFL)时,收益主要体现在 mAP50-95 上涨,mAP50 可能几乎不动。别盯错地方。**

### 补充:两种"尺子"

| | 做法 | 用途 |
|---|---|---|
| **验收尺** | 从下游需求倒推,按类定阈值(车 IoU 0.7、骑行人放宽) | 业务验收 |
| **通用尺**(mAP50-95) | 抹掉"选阈值"的自由度,十档平均 | 论文/横向比较 |

两者是同一件事的两种包装。

**落到焊缝项目**:
- 若只为判 NG、送人工复检 → **mAP50 是业务指标**。
- 若要标尺寸做质量分级 → **mAP50-95 才是硬伤**。

## 第二层:看曲线**形状**,不看数值,判断"训练健康吗"

**文件:`results.png`**

问三个问题:

1. **指标曲线末端还在涨吗?**
   - 还在涨 = 训少了
   - 平了 = 到位
   - 掉头往下 = 过拟合
2. **val 与 train 是否同向?**
   - 同降 = 健康
   - train 降 / val 涨 = 过拟合
3. **有没有崩掉?**(飙高、nan、剧烈锯齿)

### 什么叫收敛 —— 判据不在 train,在 val

"升的降的都持平"只说对了一半,**漏掉了最关键的过拟合情况**:train loss 继续降,val loss 掉头涨。

> **train loss 下降是理所当然的**(答案模型见过)。**只有 val 也跟着降,才说明模型能推广。**

### 图上括号里的 (B)

= **Box**(检测框任务)。分割是 (M) Mask,姿态是 (P)。单纯的检测任务,这个标记不带信息。

### 为什么 P / R / mAP 没有 train / val 之分

这四个指标**只在验证集上算,没有训练集版本**。

- loss:训练时顺手就算出来了 → train / val 两份都有。
- P/R/mAP:要跑完整推理 + NMS + 匹配,代价高 → **每轮只在 val 上跑一次。**

### `patience` 参数 —— 不是总轮数

| 参数 | 角色 |
|---|---|
| `epochs` | **天花板**,跑到就停 |
| `patience` | **逃生门**,val 连续 N 轮不提升就提前停 |

**谁先到停哪个。**

本次基线 `epochs: 50` / `patience: 100` → **门比天花板还远,永远不会触发。**
这不是"设大了",是**两个数不匹配、形同虚设**。

> 后续测 150 轮时,patience 要跟着调。惯例取总轮数的 1/5 ~ 1/3,即 **30~50**。
> 调太小的风险:val 本身有抖动,会被误判成"不提升"而早停。

## 第三层:三个 loss 各代表什么 —— 只在总分不理想时看

**看谁降不下去,那里就是主要矛盾。**

| loss | 管什么 | 本次权重 |
|---|---|---|
| `box_loss` | 定位(框的位置) | **7.5** |
| `cls_loss` | 分类(是哪一类) | 0.5 |
| `dfl_loss` | 边界的精细程度 | 1.5 |

### DFL = Distribution Focal Loss(分布式焦点损失)

- **传统做法**:直接回归一个数 —— "边界在 12.3 像素处"。
- **DFL 做法**:让网络输出一个**概率分布** —— "在 12 的可能性 0.4、13 的 0.35、14 的 0.15…",再加权求期望当作答案。

`dfl_loss` 训练的就是**这个分布的形状**。

> ⚠️ 澄清:这里的 12.3 **不是**"是不是缺陷"的概率(那是 cls 管的),是**框的边落在哪个像素坐标**。
>
> 📌 **与 DepthNet 的类比成立**:都是对**连续几何量**给分布,不是对类别给分布。

### 三个 loss 怎么分工 —— 在同一个头上

检测头输出**两组通道**:

```
                 ┌── 分类通道 ────────────→ cls_loss
检测头 ──┤
                 └── 回归通道 ──┬→ 分布本身 ──→ dfl_loss  (管过程)
                                └→ 期望值算出的最终框 → box_loss (管结果)
```

三个同时算,按权重加权求和成总 loss。

> **box 权重是 cls 的十五倍。** 而单类任务里 cls 十轮就躺平了,这 0.5 几乎是白给 —— **权重本身也是一个可动的旋钮。**

### 关掉 DFL 意味着什么

回归通道不再输出分布,**直接输出四个数**。

- **可能有收益**:分布要把边界离散成固定格子,在 36px 的小目标上,量化误差占比可观。
- **也可能没有**:丢掉了表达不确定性的能力,而焊缝缺陷的边界确实是模糊的。

**必须实测** —— 所以它在路线图里单独占一级。

> ⚠️ 表述订正:关掉 DFL 后,**是"回归通道那条链上只剩 box_loss"**,cls_loss 还在。总 loss 从三项变两项。

### 第三层的正确用法

难易**不是 loss 的固有属性,是被数据决定的**。

本次 cls 躺平,是因为只有一个类(送分题);等难点 3 新增焊渣类别后,cls 完全可能变成最难的那个。

> **本层的产出只有一句话:这次的主要矛盾在定位。**

## 第四层:翻图,找**具体错在哪些样本**

### 4.1 `confusion_matrix_normalized.png`

本次:ng 列 **0.84 检出 / 0.16 漏检**。

⚠️ **右上角那个 1.00 不要被误导。**

background 那一列**没有真值框可数**(图上没人标出"背景框"),分母只能拿自己那列的和 —— 79 除以 79 恒等于 1。

> **任何检测任务的这个格子都是 1.00,不带任何信息。有用的只有左边那一列。**
>
> 假如背景真有一万个可数实体,79 / 10000 = 0.0079,那才是有意义的误报率。**现在的 1.00 是分母缺失造成的假象。**

📌 **通用习惯:看到一个数,先问它的分母是什么。**

⚠️ 混淆矩阵**只按 IoU 0.5 判定**,能告诉你漏没漏,**不能告诉你框正不正** —— 所以第一层的两个 mAP 必须先看,顺序不能倒。

### 误检重不重要?

**误检当然重要,不重要的只是那个 1.00 这个数。**
误检的真实信息在:未归一化图上的绝对数 **79**,以及 **precision 0.890**。

> **焊缝质检场景:漏检代价 > 误检代价。**
> 漏检 = 缺陷件流到下游,可能是安全问题。
> 误检 = 好件被挑出来人工复检,浪费工时。
>
> → 所以 P 0.890 / R 0.821 这个工作点**偏保守,应该往降阈值的方向挪。**

### 判定 IoU 是谁定的、能不能改

0.5 是 COCO 定的,**完全可以改**。

⚠️ **注意区分两个 IoU:**

| | 比较对象 | 作用 |
|---|---|---|
| **NMS 的 IoU**(args 里 `iou: 0.7`) | 预测框 ↔ 预测框 | **去重** |
| **判定的 IoU**(默认 0.5) | 预测框 ↔ 真值框 | **算对错** |

> 🔧 **可做的小动作(不占一级)**:让 Code 在 val 时把判定阈值扫一遍(比如卡到 0.7 单独算一次),看检出率随阈值的衰减曲线 —— 比看 mAP50-95 那个十档平均值更直观地印证定位不准。

### 4.2 `BoxF1_curve.png`

F1 = precision 与 recall 的**调和平均**,防止只盯一边自嗨(两者天生打架)。

**峰值位置 = 最划算的阈值。本次:F1 峰值 0.84,落在 conf = 0.345。**

#### ⚠️ 置信度不是"绝对可信程度",是模型自己校准的**相对刻度**

COCO 上检测车容易吐 0.9(特征强、见过几万次);
焊缝缺陷 36px、对比微弱、训练框只两千多、只训 50 轮 → **整个模型的置信度分布本身就压在低位。**

**0.345 不是"只有三成把握",是"在这个模型的刻度上的最优分界线"。**

两个推论:

1. **不要跨臂比阈值。** Focal 臂的最佳阈值可能是 0.6,那只说明刻度不同。**要比就比 F1 峰值的高度,不比位置。**
2. **置信度分布压低本身是诊断信息。** 150 轮那一级跑完后,看最佳阈值有没有右移 —— 右移 = 模型变自信 = 训练充分的侧面证据。

#### 曲线形状怎么读

本次曲线在 **0.1 ~ 0.5 之间是宽阔平台**。

- **平台宽** = 部署时对阈值不敏感,不用精调。
- **若是尖峰** = 现场条件稍变就得重调阈值。

> **这张图的真正用法:先读出可用区间(0.1~0.5),再按业务需求在区间内选点。**
> 结合"漏检更贵",可以放心往左端挪(比如 0.2)。

#### ⚠️ 置信度阈值 vs NMS 阈值

| | 管什么 | 比较什么 |
|---|---|---|
| **置信度阈值**(0.345) | 这个框**收不收** | 分数 ↔ 门槛,一框一独立判断 |
| **NMS 阈值**(0.7) | **去重** | 预测框 ↔ 预测框的重叠 |

**顺序:先按置信度筛掉低分,再 NMS 去重。**

#### ⚠️ 因果方向订正

不是"根据 precision 和 recall 来决定这个框收不收" —— **方向反了。**

实际是:**定线 → 留框 → 算出 P 和 R。**

P/R 是**整个验证集上的统计量**,它不知道任何单个框的存在;判定单框去留的,只有它自己的分数和那条线。

> **F1 曲线的作用,就是把这个因果画出来:横轴是你可能定的每一条线,纵轴是那条线的后果。**

📖 **"收进来"** = 留下、当作最终输出的框。模型吐出候选框 → 阈值扔掉低分的 → 剩下的拿去和真值比对算指标。

### 4.3 `BoxPR_curve.png`

横轴 recall,纵轴 precision。**IoU 固定 0.5,全程不变。**

⚠️ **曲线上不显示阈值,但每个点背后都对应一个阈值** —— **从左上往右下走,就是阈值从高往低降的过程。整条曲线是一次阈值扫描的轨迹。**

#### 右端垂直坠落的含义(本次核心诊断)

阈值降到 0 = 模型吐出的每个框全部收下。此时:

- **recall 达到理论最大值 0.86,然后一动不动**
- **precision 垂直坠落到 0**

原因:最后收进来的那批框**基本全是误检** —— 分母涨,分子不涨。recall 不动是因为**已经没有框可收了**。

> ### 🔴 **所以那 14%(约 77 个框)不是"难检出",不是被阈值筛掉的 —— 是模型压根没为它们生成任何框。模型盲了,降阈值救不了。**

与 R-conf 曲线上的 "0.86 at 0.000" 是同一个数,**两张图交叉印证**。

#### 这条信息把改进方向劈成两半

| 情况 | 对策 | 成本 |
|---|---|---|
| 框生成了、被阈值筛掉 | 调阈值 | **零成本** |
| **框压根没生成(本次)** | **必须动模型或数据** | 高 |

具体手段:提高输入分辨率 / 改小目标特征层 / 加数据 / 改 anchor 或标签分配。

> **降阈值最多捞到 86%,剩下的 14% 得靠 Phase 4~6 的真改动。**

### 4.4 `val_batch*_labels.jpg` ↔ `val_batch*_pred.jpg`

**唯一能看到"错在什么样的缺陷上"的地方。** 左右对照,找 labels 有框、pred 没框的位置 = 漏检。

**本次实查结果**:val_batch0 这一批(约 16 张子图)**没有漏检**,真值框全部检出。

⚠️ 这不矛盾 —— **val_batch0 只是验证集的一小批**,86 个漏检散在 1576 张子图里,这批恰好没摊上。

**但这批图看到了另一件事**:所有预测框的置信度都是 **0.4 / 0.6 这一档,一个 0.8 以上的都没有** —— 这是"模型不自信"的直接目视证据,与 F1 最佳阈值 0.345 相互印证。

## 五、本次基线的完整读数(runs/bce)

### 训练配置

`yolov8n.pt` | epochs 50 | batch 16 | imgsz 640 | optimizer auto | seed 0
box 7.5 / cls 0.5 / dfl 1.5 | lr0 0.01 | patience 100 | NMS iou 0.7 | mosaic 1.0 / close_mosaic 10

### 最终指标(epoch 50,耗时 4850 秒 ≈ 81 分钟)

| P | R | mAP50 | mAP50-95 |
|---|---|---|---|
| 0.890 | 0.821 | **0.807** | **0.370** |

混淆矩阵:真值 ng 552(466 检出 + 86 漏检)= 步 3 的 val 框数 552 ✓;误检 79。

### 四条关键结论

1. **基线站住了,且比老师的好看。**
   老师:R 0.89 / P 0.70(偏召回);我们:R 0.82 / P 0.89(偏精度)。
   ⚠️ **F1 峰值 0.84 落在 conf 0.345 —— 任何比较都必须先说清阈值。**

2. 🔴 **最重要的诊断:mAP50 0.807 vs mAP50-95 0.370 的巨大落差 = 能找到但框不准。**
   小目标的典型症状。定位类改进(DIoU / NWD / 关 DFL)的靶子,现在有实测数字了。

3. **50 epoch 根本没训完。**
   四条指标曲线末端仍在上升,train / val 的 box_loss 都还在降,**无过拟合迹象。**
   → 基线不改,把 epoch 作为独立一级来测(建议 R0.7:50 vs 150,patience 同步调到 30~50)。

4. **置信度整体偏低。** R-conf 曲线在 conf 0.6 之后断崖,预测框普遍是 ng 0.6 / ng 0.4。

### 次要观察

- mosaic 把四张子图拼成一张,产生大量灰边 —— **天然的消融点。**
- `labels.jpg` 的 x 分布呈**双峰**(缺陷集中在焊缝的弧形环带上)。
- 归一化宽高 0.01~0.02 → 换算 29~58 px,与步 2 统计的中位数 36 px 吻合 —— **独立交叉验证通过。**
