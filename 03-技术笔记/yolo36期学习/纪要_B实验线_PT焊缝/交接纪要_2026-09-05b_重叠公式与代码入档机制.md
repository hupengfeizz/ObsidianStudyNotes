## 1. 子图尺寸公式(核心逻辑,本节可直接誊入实验记录步 2/步 3)

### 1.1 公式

```
子图宽 = (原图宽 + 重叠) ÷ 2 = (5472 + 320) ÷ 2 = 2896
子图高 = (原图高 + 重叠) ÷ 2 = (3648 + 320) ÷ 2 = 1984
```

### 1.2 每个数是什么(逐项拆解)

| 项 | 含义 |
|---|---|
| **3648 / 5472** | 原图的高 / 宽,一张图的物理尺寸 |
| **÷ 2** | 因为切 **2×2**:竖一刀横一刀,每个方向被分成两半,所以除以 2。不切图就没有这个除法 |
| **+ 320** | 补重叠。**这一段是上下两块共用的**,被数了两遍——上块用一次、下块用一次,所以总账要按加了 320 之后的长度去分 |
| **结果 1984 / 2896** | **子图的高 / 宽**。两者配起来才是一张子图的完整尺寸 |

### 1.3 为什么必须"加了再除",而不是"除了再加"

不留重叠时,上下各 1824,正好拼成 3648,一刀落在正中间——**骑在缝上的框直接废掉**。要让两块存在一段 320 的公共地带,总长就得比原图多出 320 来分,因为那 320 会被两块各领一次。

### 1.4 双向验算(本人自行走通,两个方向都验过才算握住)

- **高**:上块 [0, 1984],下块 [3648−1984, 3648] = [1664, 3648] → 公共段 [1664, 1984],长 **320** ✓
- **宽**:左块 [0, 2896],右块 [5472−2896, 5472] = [2576, 5472] → 公共段 [2576, 2896],长 **320** ✓
- 通用校验式:**上块长 + 下块长 − 原图长 = 重叠**。1984 + 1984 − 3648 = 320 ✓

> **教训(上一轮踩过)**:宽度当场验了,高度溜过去了,错就出在没验的那条。**验算要逐条验全,验通一条不代表整段成立。**

## 2. 480 勘误:归因与结论(争议澄清)

### 2.1 结论先说

**判据从未被违反,数据是安全的,不重切。**

### 2.2 争议是什么

记录里同时出现"重叠 320(> 最大框 306)"和"竖向实际重叠 480",看起来自相矛盾,像是某个方向没满足判据。

### 2.3 归因

- 判据是 **重叠 > 最大框尺寸**(最大框 宽 260 / 高 306,取最坏值 306)。
- **320 > 306 成立;480 > 306 同样成立,而且更宽松。**
- 出错的不是判据,是**算术**:语音端把 (3648+320)÷2 算成了 2064(正确 1984)。脚本按 2064 执行,反推竖向实际重叠 = 2×2064 − 3648 = **480**。

### 2.4 性质判定

**这是"给多了",不是"不满足"。** 错在安全侧。

- 唯一代价:重叠带更宽 → 落在带内被复制成两份的框更多 → 这正好解释切后框数 +581 偏多。
- **反例才是事故**:若当初算成 1900(重叠仅 152 < 306),306 的框会被两刀同时切坏,残框判据一删,该缺陷从两张子图里**同时消失**。那才必须重切。

### 2.5 决定

**保留 2064 不重切。** 重切要付 4 分钟切图 + 全部子图编号错位 + 下游全部重跑的代价,换一个纸面上更整齐的数字,不值。文档以本节勘误为准。

### 2.6 现行真实参数(以此为准,覆盖一切旧数)

| 项 | 设计值 | **实际执行值** |
|---|---|---|
| 切法 | 2×2 | 2×2 |
| 子图宽 | 2896 | **2896** |
| 子图高 | 1984 | **2064** |
| 横向重叠 | 320 | **320** |
| 竖向重叠 | 320 | **480** |
| 子图总数 | — | train 6288 / val 1576 |
| 切后框数 | — | train 2163 / val 552(合计 2715,+581) |

## 5. 挂账:步 3 的理解收口(尚未完成)

**任务**:亲手 trace 一个框走完完整坐标链——

```
归一化(cx cy w h) → 原图绝对像素 → 四条边 x1 x2 y1 y2
→ 残框判定(四边全在子图内?) → 减子图原点 → 按子图宽高重新归一化
```

**挑一个落在重叠带里的框做**,价值最高:它会同时出现在两张子图里,能看到同一个物理框换算出**两组不同的归一化坐标**——那一刻坐标系这件事就通了。
