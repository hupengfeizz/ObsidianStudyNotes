## 四、用户点名要记的原话（本次为 chat 产出的可直接复用话术）

### 4.1 "BEV 在割草机上怎么用"标准答法（骨架）

> 前提先认边界：割草机这个成本和算力档位，直接搬车上那套 BEV 网络不现实（车上 7 针孔 + 4 鱼眼 + 激光 + 毫米波，90M 参数、3.2G 内存，MDC 平台；割草机 5–10T NPU 还要同时跑检测、分割、VSLAM）。
>
> **能带过来的是三样：**
> 1. **多相机到统一坐标系的几何链路**——割草机也是多目/双目 + IMU + RTK，也要落到车体坐标系再交控制。本质同一件事，尺度从 180m 缩到十几米。数字本身没意义，**"在网格分辨率、感知范围、算力之间做折中"的判断力是通用的**。
> 2. **时序**——线上是历史 2 帧 0.2s 融合 + 速度差分。草坪对应痛点：宠物小孩是移动的，落叶光斑细树枝是单帧噪声；帧间一致性能压掉大半。这个价值在割草机上比车上更直接：车上误报是安全冗余，割草机上误报是产品体验。
> 3. **部署**——固定句式："公司线上是 MDC；我个人在 Orin 上把 BEV 走完了 pth→ONNX→TensorRT，在 RK3588 上做过 YOLO 的 INT8 量化和端到端部署。"
>
> **最后的加分判断**：如果算力允许上 BEV 类方案，割草机比车简单得多，不该照搬。草坪世界近似二维、地面基本平坦，车上 LSS 要预测深度概率分布、在高度维做体素建模，是因为路面有坡有起伏、目标高度差异大；草坪场景这些约束大部分不成立，**深度分布可极大简化，极端情况下退化成一个地面单应变换**，标定一次固定下来，几乎不吃算力，省下的预算给分割和 VSLAM。
>
> 收尾：BEV 这套模型我不硬推，但多相机几何、时序建模、低算力部署这三块能力能直接用，而且我知道在这个场景该砍掉什么。

**追问预案**：若被问"什么情况下地面假设不成立"→ 坡地草坪、高草区，那时仍需回到有深度估计的方案。

**提醒**：第一段"不现实"必须主动说，别等对方质疑（对应减分点"不影响啊式秒回质疑"）；数字宁可报整数（0.4m 网格、180m 纵向），别报到小数点后又报错（B04）。

### 4.2 割草机五痛点 ↔ 用户真实项目解法映射（记五个关键词）

**切图 · 曝光补偿 · 难负样本 · 保守兜底 · 后处理上板**

| # | 割草机痛点 | 用户真实对位 | 一句话解法 |
|---|---|---|---|
| 1 | 低矮小目标（躺姿儿童 <20×20 px）、碎石漏检，漏检=安全事故 | 焊缝：5K×3K 原图，缺陷有效像素 <1% | 象限切图，整图四分割（优于九分割），目标相对尺寸放大约 4 倍。割草机上可加高分辨率检测头或近场切片推理；**可用"速度只有 0.4m/s，远处漏检有时间靠近后补上"换算力**——这是车上没有的余量 |
| 2 | 草地在阴影/过曝/泛红/黄土边界下纹理剧变 | 焊缝：母材偏暗 + 余高反光过曝 + 孔洞偏黑，三重光照失衡 | IAT 曝光补偿做前处理，P、R 双升。**主张：优先在前处理解决而非堆数据**——光照分布无穷，归一化后模型看到的分布收敛。代价：吃端侧算力，看能否融进 ISP 或 NPU 图 |
| 3 | 落叶/细树枝/光斑误判为障碍物，频繁绕行劣化效率 | 焊缝：鱼鳞纹、焊渣飞溅与缺陷高度相似 | 难负样本挖掘 + 类内 NMS（P +10%）；**Focal 在高置信预训练模型上梯度消失而失效，改 BCE² 抑制硬 FP**（此条是硬货：说明遇到过标准方案失效并自己诊断出原因）。再叠车上的误检挖掘判据 + 时序一致性投票 |
| 4 | 灌木被分为"非草"实为硬障碍；长尾未知物体闭集模型无解 | **无直接对位，只给原则，不装懂细节** | 分割回答"能不能走"、检测回答"是什么"，冲突时取更保守一方；长尾靠 unknown 类兜底，置信度可疑时保守避障。可引车上通用障碍物经验：宁可绕不可撞 |
| 5 | 5T NPU 同时跑检测/分割/VSLAM，单算法仅约 5 FPS 预算 | 焊缝工控机部署；RK3588 上 YOLO INT8 量化与端到端部署；Jetson Orin 上 BEV 全链路 | **把解码和 NMS 从 CPU 挪到 NPU**（改写成算子编进模型图或做融合算子）——端侧 CPU 弱，常是真瓶颈，收益往往大于压模型本身。再加感知频率按场景自适应，与控制速度档位联动 |

> **纠错备案：围棋对弈机器人项目是朋友简历里的，不是用户的。** 本次 chat 曾误引"NMS 60ms→5ms"，已当场纠正。第 5 条只挂焊缝 / RK3588 / Jetson Orin 三处真经历。

## 六、割草机器人感知真实场景资料（培训班材料）

**来源**：`割草机器人感知算法.pptx`（课件）+ `割草机项目.pdf`（实操笔记），用户由培训班获得。
**定性**：真实项目材料，数据流 / 算力分配 / 选型理由三者自洽，**可信度高于朋友那份包装简历**。
**视角**：算法外包方（15 人团队为硬件公司做方案，一人负责 2D，两周一版小步快跑）。白马是自研整机的甲方，工作模式不同——**不要把"一人两周一版"当作对方节奏说出去**。
**用途边界**：仅作场景知识、行业口径、面试谈资。**不得当作本人经历。**

### 6.1 真实数据流

- 2D 检测 → 2D xy（左上角+右下角）→ 视差图 → 3D 世界坐标 → 规控算法决策
- 分割 → 分割坐标点 → SLAM → 3D 坐标点 → 控制算法 → 走位
- 3D 点云是**采购的双目 SDK**（元橡，约 300 元/套），2D 感知只需交出框的 xy
- 选双目不选激光的原因是**成本**：面向欧美市场的庭院割草机售价约 5000 元

**面试价值**：这条链路解释了白马 JD 为何把点云 / vslam / 特征点匹配放在第一条——**该行业的 3D 靠双目视差，不是 BEV**。讲 BEV 可迁移性时可顺此衔接："你们的 3D 来源是视差，我在车上是把多相机特征投到 BEV 网格，本质是同一件事：把 2D 观测变成可供规控使用的三维位置。"

### 6.2 算力分配

RK3588，5T 算力，3 个 NPU，16G 内存。**3D 点云算法一家占 60%**；检测 11 FPS、模型 11M（INT8）、CPU 占 30%、内存 0.9%；分割每 5 帧推一次（pp-seg 30MB 15fps）。

割草速度 0.2–0.55 m/s（正常 0.4），11 FPS 够用。低帧率的额外好处：省电（续航是核心需求）、少发热（户外长时间作业）、不跑满 NPU 更稳定。

→ 印证此前"用低速换算力"的说法，且给出了完整理由链。

### 6.3 量化实战点（补 K17 洞）

**YOLOv11 的 DW 卷积量化后掉点极严重，极端情况精度归零，因此换回 YOLOv8。**

原理需能自己顺出来：深度可分离卷积每通道独立，通道间数值范围差异大，per-tensor 量化被极端通道拉死；方向是 per-channel 量化或敏感层回退。

### 6.4 "为什么不用 X" 经典题

分割用 SegFormer 不用 YOLO 实例分割：后者先框后分，可能把一整块草地切成多块，要写后处理合并，边缘线不干净；草地分割要的就是明确边界。

对照组：别家检测分割全用 DeepLabv3，只有 8 FPS，兔子漏检、石头误检多——**全语义分割误检率更高**。

### 6.5 四个分割难点的真实解法

| 难点 | 解法 |
|---|---|
| 红草（RGB 色域与绿草差异大） | HSV 离线增强，把色调 H 偏移至绿色区间，同时增强饱和度亮度 |
| 强光阴影 / 过曝 | gamma 校正 + 直方图均衡；**过曝到看不清细节就新增"强光"干扰类，不硬分割** |
| 泥土草（纹理亮度与草高度相似） | 边缘检测增强（Canny / 拉普拉斯）+ 形态学开运算、连通域分析过滤小面积误检 |
| 灌木（与草同为绿色高饱和） | **直接放进检测任务当硬障碍建类**，不靠 unknown 兜底 |

现有类别：检测 20 类 + 新增灌木、强光 = 22 类；分割 4 类（过曝草 / 草 / 泥土草 / 背景）。

### 6.6 帧间不稳定的产线证据

同一物体帧间数量 / 类别跳变（这帧 3 个下帧 5 个）→ 下游 costmap 在 128 和 254 之间震荡 → 频繁误触发停车。

根因：输入图像特征帧间剧变（运动模糊 / 视角变化 / 光照波动）导致置信度波动。
解法：数据增强（加入运动模糊、角度变化、光线变化）+ 后处理时序平滑（ID 追踪、滤波）。

**话术**：讲时序价值时可说"我理解这类场景最典型的表现是下游 costmap 震荡"。

### 6.7 其他可引用数字

14 万张、COCO 清洗 20 类 + 爬虫、4090 训练一版 24 小时、检测 map50 97.5% / map50-90 90%（量化掉约 5 点）、SegFormer miou 95%、参考实现 `github.com/bubbliiiing/segformer-pytorch`。
