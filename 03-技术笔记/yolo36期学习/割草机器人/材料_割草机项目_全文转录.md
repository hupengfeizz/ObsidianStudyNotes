## 项目背景

### 技术路线选择

3D 视觉方案选择上,团队采用了双目视觉而非激光雷达,核心原因是成本控制。户外的激光价格高。

虽然有些公司会结合激光雷达和双目视觉,但当前方案专门针对欧美市场的庭院割草机场景(售价约 5000 元),这种特定需求下双目视觉已经足够。

简单来说,割草机的智能性依赖于这三个算法:识别障碍、区分草地、规划路线,确保它能安全、高效地工作。

## 割草机器人障碍物检测 + 定位的逻辑

### 双目相机

- 2 路码流,推理分辨率:
  - 左边:480×480,左目小
  - 右边:640×480,主要用右目做障碍物的检测(避障和分割)
- 实际的相机分辨率,2 目都是 200 万
- 避障(检测算法)推理时不需要 resize,很多板端部署的算法在推理时都直接用 640×480,平衡精度和速度,适配板端部署
- 摄像头格式是 YUV,需要 YUV 转 RGB,用 RGB 推理
- 检测推理后拿到的是 2D 的 xy(左上角和右下角的坐标)

**两条链路:**
- 2D 感知 → 2D xy → 3D 点云算法接口 → 3D 世界坐标 → 控制算法决策
- 分割算法 → 分割的坐标点 → SLAM → 3D 坐标点 → 控制算法 → 走位

其他背景:
- 公司里代码是分隔的,不同的人管理
- 左目裁剪过了,分辨率降低了
- 3D 点云采购的是元橡的(立体视觉)

### 角色定位

作为算法提供方,核心职责是根据硬件公司反馈的需求来设计和调整算法方案,**不是盲目开发**,要与硬件方保持紧密沟通。

「我」负责 2D 感知算法(障碍物检测 + 草地分割),3D 点云另外一个同事做,整个研发团队 15 个人。

## 难点

### 1. 障碍物类别
- 20 个类别,总共 14 万张左右
- 类别是产品经理定的

### 2. 数据源
- 新开发项目缺乏现成数据集,需要从头构建
- 一是通过爬虫获取,二是使用开源数据集——COCO 原本 80 类,实际使用时只选取其中 20 个类别来训练检测模型
- 数据迭代:开卖以后、有了用户以后,才有自己的数据集,做后续优化和迭代

### 3. 部署,选芯片
- 部署阶段通常用 C,硬件如 RK3588 开发板,成本约 700–800 元

### 4. 3D 感知的交互问题
- 车辆避障需要实时处理 3D 环境信息
- 这三个难点环环相扣——没有好的数据就训练不出识别模型,而模型最终又受限于硬件部署条件

## 算法

障碍物识别确保割草机不会撞到东西,草地分割则帮助机器判断是否跑出了需要修剪的草地范围。

### 障碍物检测算法

| 项 | 内容 |
|---|---|
| 模型 | YOLOv8 |
| 精度 | mAP50: 97.5%,mAP50-90: 90%(量化之后精度掉 5 个点左右) |
| 数据 | COCO 清洗出 20 类 + 爬虫 + 开源数据,共 14 万张,20 类 |
| 部署 | RK3588(8 线程、3 个 NPU),5T 算力,16G 内存 |
| 训练 | 一个版本 24 小时(4090) |
| 推理指标 | 模型 11M(INT8),FPS 11,CPU 占用 30%,内存占用 0.9% |
| 迭代节奏 | 每两周发布一个版本,每次性能只需提升一点点,只有一个人负责,开发策略是"小步快跑" |
| 主要工作 | 清数据,解决漏检 |

**帧率设置是否合理:**

割草速度很慢(0.2–0.55 米/秒;正常 0.4,快 0.55,慢速 0.2),不需要每帧都检测障碍物,系统帧率设定在 11 帧是合理的。

对嵌入式设备,低帧率反而有实用价值:
1. 降低功耗:NPU/CPU 算力用得少,提升电池续航(割草机器人核心需求之一)
2. 减少发热:3588 芯片算力利用率低,发热更少,适合户外长时间工作
3. 稳定性更高:不用强行跑满 NPU,不易出现算力过载导致的崩溃

三套算法并行:一套检测、一套分割、一套 3D 点云。3D 点云算法比较占内存,单独占用一个 NPU,基本占了 60%。

**YOLO 版本选择:** YOLOv11 不适合——DW(深度可分离)卷积量化后出问题,掉精度很厉害,量化后精度有可能为 0,所以换 YOLOv8 更好、适配更好。DW 卷积不适合做量化。

**检测的实际工作:** 清数据、训练、测试有 bug 就解决,另外写一下推理代码,估计一个多月。

### 3D 感知(障碍物检测与定位方案)

系统先从图像中框出目标物体,然后通过一个包含内参(cx, f 等)的坐标转换公式,把 2D 图像坐标换算成 3D 空间位置。

- **3D 点云 = 2D 坐标 + 深度信息**
- 视差图是预先处理好的中间数据,作为桥梁将 2D 像素坐标映射到 3D 空间。这个转换过程由规控算法完成,最终输出可用于导航的精确世界坐标
- 流程:**2D 框坐标 → 视差图 → 3D 世界坐标**,算法已封装好,只需提供 2D 点即可自动完成后续计算
- 2D 检测识别到障碍物后计算出 xy 坐标,输入到视差图中,通过转换公式算出该障碍物在世界坐标系中的 XYZ 位置
- 得到世界坐标后,数据传递给 3D 避障算法(也叫规控算法),负责避障逻辑,比如触发报警或直接控制机器停止运行
- 核心流程:只需要写个推理函数,把推理结果(矩阵形式的视差图)传给规控算法就完成任务了,因为工作重点只是 2D 检测这个环节
- 这套双目点云算法是现成的,花 300 块买的打包好的 SDK;网上能买到带源码的版本,但调优很费时间

## 检测遇到的问题:模型不稳定

**难点:帧间检测结果不一致 / 置信度波动**(同一物体在连续帧中被识别为不同数量/不同类别)

**表现:**
- 同一物理位置的目标,连续帧中检测数量波动(如这帧 3 个、下帧 5 个)
- 同一目标在帧间被误判为多个,或类别/置信度跳变

**引发两个核心问题:**
1. 处理时间随目标数剧烈波动
2. 容易误判(把同一目标当成多个,或分到不同类别)

**核心原因:** 模型对连续帧的分类/检测输出不稳定,本质是输入图像特征在帧间剧烈变化,导致模型置信度波动:
- 运动模糊:目标快速移动,图像模糊,纹理细节丢失
- 视角变化:不同观察视角下目标外形、轮廓变化,模型对"同一目标"的特征学习不足
- 光照变化:户外光线强弱、阴影/过曝变化,目标颜色、亮度特征波动

**处理方案:**
- 数据增强优化:训练集中加入运动模糊、角度变化、光线变化等增强数据,提升复杂场景鲁棒性
- 后处理平滑:加入目标追踪算法(如 ID 追踪、卡尔曼滤波),对同一目标的检测框/类别做时间域平滑,避免帧间跳变,解决识别框闪烁

## 草地分割(SegFormer 语义分割)

### 模型选择

Seg-Former 语义分割。

**面试问题:为什么不用 YOLO 这类实例分割模型?**

答:YOLO 实例分割是先框后分,有可能把一个目标分为多段、把一块草地分割为多块,就要写后处理合并;有可能只有框、没有边缘线。SegFormer 语义分割有良好的边缘线,分割草地就是要有明确的边界。

**别家公司的方案对比:** 检测和分割都用 DeepLab v3(语义分割),只能做到 8fps,漏检比较多(比如兔子),石头误检比较多——全部用语义分割,误检就会比较高。更合理的方案是:检测用 YOLO,分割用 SegFormer。另外,20 个类别打分割标签也很恐怖,花费大量时间,有 YOLO 检测更省时。

### 难点

**1. 有的草发红,很难分割**
- 核心原因:发红草地在 RGB 色域中与正常绿色草地特征差异大,模型无法学习到统一的草地特征;红草区域亮度偏低、颜色对比度差
- 处理方案:
  - 用离线的 HSV 增强调颜色,将红色草的色调(H)偏移至绿色区间,同时增强饱和度和亮度
  - 增加红色草的数据,让模型直接学习"红草 = 草地"的特征

**2. 强烈的阳光,导致草地阴影被误分割成非草**
- 核心原因:强光照导致草的颜色和纹理变化,分割算法混淆
- 处理方案:
  - 对偏暗的阴影草样本做光线调整,提升亮度与对比度
  - 伽马校正、直方图均衡化,动态调整过曝/欠曝区域亮度
  - 如果草已经过曝到看不清细节:在障碍物里增加一个新类叫"强光",让模型归为干扰类别,避免强行分割无意义区域

**3. 泥土草(树旁边泥土混杂的草,没法割干净)**
- 核心原因:泥土与草地的纹理、亮度高度相似(泥土偏黄/灰,草稀疏时纹理也偏黄),边界难区分
- 处理方案:
  - 训练集补充「泥土混杂草」样本,针对性采样
  - 对泥土草样本做边缘检测增强(Canny、拉普拉斯算子),提升纹理边界对比度
  - 形态学开运算、连通域分析,过滤小面积误检,平滑边界

**4. 机器冲上灌木**
- 核心原因:
  - 灌木在 RGB 色域中与草地颜色特征高度相似(均为绿色 + 高饱和度),易被误分割为草地
  - 灌木区域纹理更密集、高度更高,视觉上与草地有差异,但模型对"灌木 = 非草"的边界特征学习不足
  - 这类样本训练集占比极低
- 处理方案:
  - 数据补充:训练集补充更多灌木样本
  - **检测增加新类别:将灌木放入检测任务的类别中训练**
  - 安全约束层:通过高度、纹理等特征约束,将高/密的绿色区域归为非草
