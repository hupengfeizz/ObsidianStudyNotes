## 三、collate / DataContainer(用户此前完全不了解,本段从头讲)

- collate 是 **DataLoader 的合并函数**,不在 Dataset 里。流程:DataLoader 拿一批 index → 逐条问 Dataset 要 → 交 collate_fn 拼 batch。Dataset 只懂单数。
- 默认 collate 不够用的场合:**各条形状不一**。YOLO:图可堆叠,标签变长堆不了 → 框拼长列表 + 额外一列记属于 batch 内第几张图(YOLOv5 datasets.py 里的静态方法 collate_fn)。
- DataContainer(mmdet3d):给字典每个键贴"说明书",告诉 collate 哪个要堆、哪个装列表别碰。**collate 是合并动作,DataContainer 是说明书**。
- BEVFusion 与 demo/YOLO:**骨架完全一样,三件套一个不少,差别全在"一条样本是什么"**。demo 一条=图+整数标签;YOLO 一条=图+变长框列表;BEVFusion 一条=六路图+点云+六套标定+ego pose+时间戳+3D 框的十几键字典。
- BEVFusion collate 三难:①一条是字典、不同键规则不同;②点云天生不可对齐(不能裁点);③3D 框数量可变且字段多。归纳:**YOLO 是"图像好办、标签变长",BEVFusion 是"三类合并规则并存 + 一类天生不可对齐"**。
- 实操结论:mmdet3d 已实现好,基本不用自己写。**知道 collate 在哪、干什么、为什么 BEVFusion 要自定义——这个程度够用也够面试**。此知识点已放下。

## 四、36号脚本(36_custom_dataset_digits.py)收尾

### 维度理解纠正(用户曾说错)
`(1, 32, 32)` 是**一张图的形状 C,H,W**:通道 1(灰度)、高 32、宽 32。**与标签无关**;标签是单独返回的 y,0 维标量 int64。用户曾理解为"第三个 32 是标签维度"——已纠正。

### 脚本目的(day6 的"去训练、只留数据侧"干净版)
1. 三件套跑通(自造五类灰度图,零下载)。
2. **看清"单条"与"一批"的分界**:`dataset[0]` → (1,32,32);过 DataLoader → (4,1,32,32)。**batch 维不是你加的,是 DataLoader 加的**——全脚本最核心一句。
3. 顺手验证 8:2 固定切分 + dtype 三坑(float32 / int64)。

### DataLoader / collate / Dataset 三层分工(本段最后敲定)
- **Dataset 你写**(只有你知道数据在哪、怎么读、标签怎么解析);
- **collate_fn 有时候你写**(它是 DataLoader 的一个**参数**,普通函数,接列表返回 batch,传进去即可;不是改 DataLoader 内部代码);
- **DataLoader 永远不写**(发 index、收结果、拼 batch、多进程、预取——通用活,框架给)。
- YOLO、BEVFusion 都不重写 DataLoader,都是从 collate_fn 这个口子改。
