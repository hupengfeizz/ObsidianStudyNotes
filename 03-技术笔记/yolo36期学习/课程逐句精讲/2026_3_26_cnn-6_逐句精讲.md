### 03 自定义算子必须继承 nn.Module（00:05:48 – 00:06:40）

> **文老师**：「因为 PyTorch，你要自定义算子的话，必须写内的——自定义算子它是必须要写内的，而且必须要继承 nn.Module。所以这个是必须的。」

- **【直译】** "写内的"是 Whisper 把 `nn.` 听岔了。规矩只有一条：任何你想让 PyTorch 当成"层"来管的东西，都必须 `class X(nn.Module)`，并且 `__init__` 里第一行 `super().__init__()`。
- **【推导/代码】** 继承 `nn.Module` 白拿三件能力：① 子模块自动注册进 `_modules`，`model.parameters()` 递归收集到所有权重 ② `.to(device)/.train()/.eval()` 自动向下传播 ③ `model(x)` 触发 `__call__` → `forward`。
- **【为什么】** 不继承会怎样？`self.conv = nn.Conv2d(...)` 写在普通类里，optimizer 拿不到权重，那层永远不更新，而且**不报错**——最阴的一类 bug。
- **【连接】** BEVFusion 里每个 `@MODELS.register_module()` 的类往上追都继承自 `nn.Module`（经 BaseModule 中转）。给 BEV 加新模块时忘写 `super().__init__()` 是最常见的翻车点。

### 04 第一块砖：class Conv = conv + bn + relu【画面·完整代码】（00:06:00 – 00:07:40）

> **文老师**：「然后这里这些参数我不用解释了。」

- **【推导/代码】** 【画面】`day9_1.py` 第 19–31 行，这是全课的地基，一字不差：

```python
"""
1. conv-bn-relue
"""
class Conv(nn.Module):
    def __init__(self, in_channel, out_channel, kernel_size, stride, padding=0, is_relu=True):
        super(Conv, self).__init__()
        self.conv = nn.Conv2d(in_channel, out_channel, kernel_size, stride=stride, padding=padding)
        self.bn   = nn.BatchNorm2d(out_channel)
        self.relu = nn.ReLU()

        self.is_relu = is_relu
    def forward(self, x):
        x = self.conv(x)
        x = self.bn(x)
        x = self.relu(x)     # ← 此刻还没加 if，02:33:03 的 34 版本才补上 if self.is_relu
        return x
```

- **【为什么】** BN 的参数为什么是 `out_channel`？因为 BatchNorm2d 对**输出的每个通道**各自统计均值方差，卷积做完通道已变成 `out_channel`。这行写错是新手第一大坑。
- **【连接】** 这就是 YOLOv8 `ultralytics/nn/modules/conv.py` 里 `class Conv` 的极简版——YOLO 版多了 `autopad(k,p,d)`、可传激活（默认 `nn.SiLU()`）、以及推理时 conv+bn 融合的 `forward_fuse`。结构完全同构。

### 05 is_relu 开关：为什么残差要留一个"不激活"的出口（00:07:00 – 00:08:00）

> **文老师**：「这个知道为什么要用这个吗？是因为残差有的地方它不用——有的残差地方它是不用 ReLU 的。你看它是什么，卷积之后加了再 ReLU，所以我们要控制它要不要用激活函数。」

- **【直译】** 残差块最后那个 1×1 卷积**不能**立刻 ReLU，必须先跟捷径分支相加，加完再 ReLU。所以 `Conv` 需要一个布尔开关。
- **【推导/代码】** 数学上：正确写法是 `y = ReLU(F(x) + x)`；错误写法是 `y = ReLU(F(x)) + x`。差别看着小，后果很大——ReLU 把 `F(x)` 的负半轴砍掉后再加 `x`，残差分支就永远只能"往上抬"，失去了表达负修正量的能力，梯度也少了一条干净通路。
- **【为什么】** 这是 He Kaiming 原论文 Fig.2 的画法，也是"预激活 ResNet（v2）"后来要改的那个点。用一个 `is_relu=True` 默认参数就把它编码进砖块，非常干净。
- **【连接】** YOLOv8 的 `Bottleneck` 里 `self.add = shortcut and c1 == c2`，走 `x + self.cv2(self.cv1(x))`，两个 cv 内部都带 SiLU——它没做"最后一层不激活"。两种设计都对，你要能说出区别。

---

**【小结】** ① 实现模型三条路：手撕 / 改库 / 读配置，今天走最笨的第一条。② 自定义算子的硬规矩是继承 `nn.Module` + `super().__init__()`，否则参数不进 optimizer 且不报错。③ 第一块砖 `Conv(conv+bn+relu)` 必须带 `is_relu` 开关，因为残差是"加完才激活"。

## Part 2 · 第二块砖：Bottleneck 残差块（00:08:00 – 00:14:03）

**【本段在讲什么】** 有了砖，开始砌第一片砖墙。文老师打开 arXiv 的 ResNet 论文 Table 1，指着 50-layer 那列的 `[1×1,64 / 3×3,64 / 1×1,256]`，把它翻译成一个只要**一个参数**的 Python 类。精华是他抽出的不变量：bottleneck 块 `in_channel == out_channel`，中间压到 1/4——正是它让类签名从四个参数瘦成一个。

---

### 06 从论文表格反推：块的输入输出通道是相等的（00:08:00 – 00:09:00）

> **文老师**：「最残差这个模块是怎么定？就拉到下面来看。我们写 ResNet50 的话，就是这边——输入通道数是输出的什么？这中间是它的四分之一。」

- **【直译】** 看 Table 1 的 conv2_x 那格：`[1×1,64 / 3×3,64 / 1×1,256]`。进来是 256，出去也是 256，中间那两层是 64 = 256/4。
- **【推导/代码】** 为什么必须相等？因为块的末尾要做 `x = res_x + x`，**逐元素相加要求两个张量形状完全一致**。这不是设计者的偏好，是加法的硬约束。
- **【为什么】** "bottleneck（瓶颈）"这个名字就是这么来的：中间细两头粗。1×1 先把 256 压到 64，让昂贵的 3×3 只在 64 通道上算（`3·3·64·64 ≈ 36.9k` vs 直接在 256 上算的 `3·3·256·256 ≈ 590k`，差 16 倍），算完再 1×1 升回 256。这也是 MobileNet inverted residual 要"反过来"的那个原始版本。

---

### 07 把不变量写进 docstring【画面】（00:09:00 – 00:10:00）

> **文老师**：「所以残差它有一个特点，我们这里可以备注一下——ResNet 的特点是 in_channel 等于 out_channel。然后压缩的时候、降维的时候，是它的四分之一。」

- **【推导/代码】** 【画面】`day9_1.py` 第 34–43 行，他真的把这两句写成了注释：

```python
class Bottleneck(nn.Module):
    def __init__(self, in_channel):
        """
        resnet的特点是 in_channel == out_channel
        降维是 1/4 *in_channel

        :param in_channel:
        """
        super(Bottleneck, self).__init__()
        out_channel = in_channel // 4
```

- **【为什么】** 注意 `out_channel` 这个局部变量名其实指**中间通道**（真正的输出通道是 `in_channel`），命名有点误导。但重点是他把"发现的规律"写进代码而不是脑子里——两小时后排查 bug 时正是靠回看这两行注释定位的。

### 08 只传一个参数的设计取舍（00:10:30 – 00:11:00）

> **文老师**：「所以我们这里只需要定一个，只需要定一个 in_channel。其实我们只需要一个 in_channel，实际上只需要一个 in_channel。为什么只需要 in_channel？因为 in_channel 等于 out_channel。」

- **【直译】** 类签名 `def __init__(self, in_channel)`，一个参数打天下。
- **【为什么】** 参数越少，调用点越难写错（讽刺的是最后那个 bug 恰恰出在这唯一一个参数传错了值）。代价是灵活性：写死 1/4 压缩比，没法复用到 ResNeXt 的分组版本。
- **【连接】** 对比 torchvision 的 `Bottleneck(inplanes, planes, stride, downsample, groups, base_width, dilation, norm_layer)`——8 个参数换来的是同时表达 ResNet / ResNeXt / Wide-ResNet / 空洞版。这是"教学代码 vs 生产代码"的分水岭，两种你都要能读。

### 09 三个卷积一行行长出来【画面·完整代码】（00:11:00 – 00:12:20）

> **文老师**：「现在要实现这里的 1×1，就是 1×1，就是四。这里就是四分之一，是整除对不对。第一个是 1，步长也是 1。这是我们的卷积一。好，我们现在是卷积二，卷积二三乘三，这里就是 out_channel，步长也是 1。我感觉这里要 padding，padding 一个。」

- **【推导/代码】** 【画面】第 44–47 行：

```python
self.Conv1 = Conv(in_channel,  out_channel, kernel_size=1, stride=1)
self.Conv2 = Conv(out_channel, out_channel, kernel_size=3, stride=1, padding=1)
self.Conv3 = Conv(out_channel, in_channel,  kernel_size=1, stride=1, is_relu=False)
self.relu  = nn.ReLU()
```

- **【推导/代码】** 三行的通道流水（以 conv3_x 为例，in=512）：`512 →(1×1) 128 →(3×3,p=1) 128 →(1×1) 512`。尺寸方面：1×1 stride=1 天然不变；3×3 stride=1 **必须配 padding=1** 才不变，公式 `H_out = ⌊(H + 2·1 − 3)/1⌋ + 1 = H`。
- **【为什么】** "我感觉这里要 padding"不是拍脑袋——`k=3,s=1,p=1` 是保尺寸的黄金三元组，跟 `k=1,s=1,p=0`、`k=3,s=2,p=1`（减半）并列，是必须背下来的三组数。

---

### 10 Conv3 传 is_relu=False：伏笔在这里兑现（00:12:00 – 00:14:00）

> **文老师**：「还要控制一下这个地方，最后一步不要——因为你这里是卷积之后啊，你不能激活的，要加了之后才、加了之后再、再激活啊。所以这里就是一个 False。」

- **【直译】** 第三个 1×1 卷积传 `is_relu=False`，把激活留到相加之后。这正是 05 卡那个开关的唯一用武之地。
- **【推导/代码】** 【画面】forward 的四行（第 48–53 行）：

```python
def forward(self, x):
    res_x = self.Conv1(x)
    res_x = self.Conv2(res_x)
    res_x = self.Conv3(res_x)
    x = res_x + x            # add之后再relu
    return self.relu(x)
```

- **【为什么】** 变量名从 `x` 换成 `res_x` 是**必须的**，否则第一行 `x = self.Conv1(x)` 就把原始输入覆盖了，捷径分支无从谈起。老师专门喊了句"这就要改名字了啊"——手撕残差最经典的低级错误。
- **【连接】** BEVFusion 的 SECOND 骨干里是同样模式：`identity = x` 先存好，末尾 `out += identity; out = self.relu(out)`。变量名不同，骨架一模一样。

### 11 Bottleneck 定稿：11 行代码一个块【画面 00:14:17】（00:14:00 – 00:14:30）

> **文老师**：「就这里就实现了，这也是实现了残差嘛。这里能看懂吗？对残差完了之后，ReLU——你看这里是加了之后才 ReLU。好，这是残差，残差基本上就搞完了。」

- **【推导/代码】** 【画面】截图里能看到 IDE 右上角显示 `⚠4 ⚠5 ✓1`，说明此刻已有告警但不影响运行；光标停在第 52 行 `x = res_x + x`，行首有黄灯泡（PyCharm 提示 Tensor 未定义 `__add__` 的误报，02:41:02 在 34 版本里同样出现过）。
- **【为什么】** 到这里"一片砖"完成了：一个 `Conv` + 一个 `Bottleneck`，25 行代码覆盖了 ResNet50 里 **16 个块中的 13 个**。剩下 3 个（conv3_1/conv4_1/conv5_1）是下采样块，正是 Part 3 的内容。

---

**【小结】** ① Bottleneck 的核心不变量是 `in_channel == out_channel`，中间压 1/4，因为末尾要逐元素相加。② 三个卷积 `1×1 降 → 3×3(p=1) 保尺寸 → 1×1 升回`，最后一个必须 `is_relu=False`。③ forward 里一定要用新变量 `res_x` 承接主分支，别覆盖原始 `x`。

## Part 3 · 第三块砖：ConvDown 下采样块（00:14:03 – 00:26:01）

**【本段在讲什么】** 全课信息密度最高、也最容易迷路的一段。文老师带大家在 Table 1 上"数尺寸"：conv2_x 出来 56×56×256，conv3_x 出来 28×28×512，中间既降尺寸又翻通道——可论文中括号里根本没画这一步。他花 12 分钟把这个"隐形块"从表格里推出来写成 `class ConvDown`。这条推理链必须跟下来，Part 6 的 40 分钟 bug 就是它的直接后果。

### 12 下采样藏在哪：论文脚注那一句话（00:14:30 – 00:16:30）

> **文老师**：「另外一个我们还有一个什么，Down，因为下采样，叫 Down。这里要进行下采样，下采样我们就要看哪里了？有点隐秘，有点隐秘啊。我们写 50，你看它这个是 56、56，这里就变成了什么，28。所以他这个第一次这个块，应该是进行一个什么下采样。」

- **【直译】** 论文表格只给了每个 stage 的 `output size`（56×56 → 28×28 → 14×14 → 7×7），下采样发生在**每个 stage 的第一个 block**，但中括号里的三行卷积看起来 stride 全是 1。
- **【推导/代码】** 【画面】Table 1 脚注写得明明白白：*"Down-sampling is performed by conv3_1, conv4_1, and conv5_1 with a stride of 2."* 也就是说 conv3_x 的第 1 个块里，那个 3×3 的 stride 是 2；conv2_x 完全不下采样（尺寸已经被 conv1 的 s=2 和 maxpool 的 s=2 降到 56 了）。
- **【为什么】** 论文为排版把这条规则塞进脚注、中括号里不体现——这是所有"照着表格抄"的人第一次翻车的地方。老师用"有点隐秘"四个字点破。
- **【连接】** YOLOv8 的 yaml 里这件事是显式的：每个 stage 前单独一行 `[-1, 1, Conv, [128, 3, 2]]`，下采样和残差块分两行写。看惯 yaml 再回看论文表，就知道论文省了什么。

### 13 通道 256→512 与尺寸 56→28 同时发生（00:16:30 – 00:17:30）

> **文老师**：「这里变成了 28。你这是 256 嘛，他不是 128 吗，这里不是 512 吗？所以这里应该还有一个 1×1 的 512。那尺寸呢？你现在考虑通道吧。我们第一个问题就是这里是 4 嘛，你拆成 1 和 3 嘛。」

- **【解释·修正】** conv3_x的整体目标是输出512通道、28×28的特征。这份结构把从256通道、56×56到这个新形状的转换安排在第一个块中，后续块保持输出形状。两种转换可以由块内不同层完成，也可以在其他网络设计中分开安排；并非必须交给同一层或同一个stage。详见文末“下采样和改变通道数，能不能分给两个stage？”答疑。
- **【推导/代码】** 于是他把 `×4` 拆成 `1 + 3`：**第 1 次 = 下采样块（尺寸减半 + 通道翻倍），后 3 次 = 普通残差块（形状不变，特征数值仍会变化）**。这个"4 = 1 + 3"是本课出现频率最高的一句口诀。
- **【为什么】** 本stage只需从56×56降到28×28，所以安排一次下采样。若4次都按本例3×3、stride=2、padding=1下采样，会得到56→28→14→7→4，偏离目标形状；不会出现3.5个像素。这里的次数是当前结构安排，不是所有stage必须遵守的规定。
- **【连接·限定】** 本例的1+(n−1)是“总共n次块执行，首块转换形状，后续保持形状”，与奇偶性无关。跨到SECOND等实现时，必须先核对层数参数究竟统计总数还是首层之后追加的数量，不能看到两个列表便套用减1。

### 14 学生质疑："1×1 怎么会 stride=2？"（00:17:30 – 00:18:30）

> **学生 / 文老师**：「1×1 是 1 是 1，一乘一怎么 S 等于 2？你是什么时候见到 1×1 搞个 S=2 的？」

- **【直译】** 老师最初想让那个 1×1 卷积去做 stride=2 的降采样，被学生当场怼了。
- **【推导/代码】** 学生是对的，但理由要说准：`Conv2d(k=1, s=2)` 在语法和运行上**完全合法**，输出 `⌊(H−1)/2⌋+1`，等价于"隔一个像素取一个"。它的问题是**丢信息**：1×1 核只看一个像素，stride=2 直接扔掉 75% 的空间位置，没有任何聚合。而 3×3 stride=2 的感受野覆盖了被跳过的邻居。
- **【为什么】** 有趣的是 torchvision 官方 ResNet 的 **downsample 捷径分支**恰恰就是 `Conv2d(k=1, s=2)`（论文里的 option B 投影捷径）。所以"从没见过"这个说法本身是错的——只是不该用在主分支上。面试问"ResNet 降采样时捷径怎么对齐"，标准答案就是 1×1 conv + stride 2 + BN，你答"没人这么写"就挂了。

### 15 先升后降：为什么要多插一个 1×1 升维（00:19:30 – 00:21:30）

> **文老师**：「这里要不要放一个 1×1×512？你们觉得要不要放啊？我从 256 升到 512。人家这个块已经写死了，就是 128、128，所以你要先升后什么——后降。所以这里要先 512，因为你这里是一个块嘛，人家已经给你写死了，所以你这里肯定要有一个 1×1×512，然后再来用这个块来下采样。」

- **【直译】** 论文的块内部是 `128 → 128 → 512`，入口期望 512。但上一个 stage 出来只有 256。差的这一倍，只能在块**之前**用一个 1×1 卷积补上。所以顺序是：先升到 512 → 再进入"降维-降尺寸-升维"的块。
- **【推导/代码】** 完整通道轨迹：`256 →(1×1 up) 512 →(1×1 down_c) 256 →(3×3 s=2 down_wh) 256 →(1×1 up_c) 512`，尺寸 `56 → 56 → 56 → 28 → 28`。等号两端：进 256×56×56，出 512×28×28。✅
- **【为什么】** 这一步就是论文表格**完全没画**的那个隐藏操作。老师原话："论文经常就是给你少一点东西"。他在 01:00:02 会因为漏掉同类的一步（conv1 之后 64→256）而崩溃 40 分钟。
- **【连接】** 跟你在 BEV 里改 neck 通道数一模一样：论文图上 `(64,512,512) → (384,128,128)` 一根箭头，实际代码里是三个 stage 加两个 1×1 过渡。图永远比代码少画东西。

### 16 ConvDown 四行定稿【画面·完整代码】（00:21:30 – 00:24:30）

> **文老师**：「我们先用一个 1×1 吧，把它 up 上去嘛，所以我们取名叫 up。这里是上一层的 256，out 肯定是 512，256 乘以 2，所以这里其实只需要一个 in 就可以了。」

- **【推导/代码】** 【画面】`day9_1.py` 第 58–77 行，注意每一行的行内中文注释：

```python
class ConvDown(nn.Module):
    def __init__(self, in_channel):
        """
        :param in_channel: 256
        :param out_channel: 256 * 2
        """
        super(ConvDown, self).__init__()
        # 先升上去
        self.conv1_up      = Conv(in_channel,      2 * in_channel,  kernel_size=1, stride=1)

        self.conv1_down_c  = Conv(2 * in_channel,  in_channel // 2, kernel_size=1, stride=1)
        self.conv3_down_wh = Conv(in_channel // 2, in_channel // 2, kernel_size=3, stride=2, padding=1)
        self.conv1_up_c    = Conv(in_channel // 2, in_channel * 2,  kernel_size=1, stride=1)
    def forward(self, res_x):
        res_x = self.conv1_up(res_x)       # 先升c
        res_x = self.conv1_down_c(res_x)   # 再降c
        res_x = self.conv3_down_wh(res_x)  # 再降wh
        res_x = self.conv1_up_c(res_x)     # 再升c
        return res_x
```

- **【推导/代码】** 代入 `in_channel=256` 验算：up 得 512；down_c 得 128（=256//2）；down_wh 保持 128、尺寸 56→28；up_c 得 512（=256×2）。与论文 conv3_x 的 `[1×1,128 / 3×3,128 / 1×1,512]` 严丝合缝。
- **【为什么】** 注意 `ConvDown` **没有捷径分支**，只是一条直路。老师 03:03:00 说得很清楚："虚线不是残差，虚线是一个下采样。" 这跟官方 ResNet 不同（官方下采样块保留了 1×1 投影捷径），是简化但不影响跑通。

### 17 3×3 stride=2 要不要 padding：先按经验补，等调试验证（00:24:00 – 00:25:30）

> **文老师**：「128 出来也是多少，k 就是 3，padding 就应该要 padding 的。哪里 padding，3×3 按经验是需要 padding 的啊。等会试一试，先放在那里啊，等会来调试啊。」

- **【推导/代码】** 验算 `H=56, k=3, s=2`：不补 padding 时 `⌊(56−3)/2⌋+1 = 27`（少了 1）；补 `p=1` 时 `⌊(56+2−3)/2⌋+1 = 28` ✅。所以 padding=1 不是"经验"，是算出来的必然。
- **【为什么】** 但"先写上、等会调试验证"这个态度值得学：**有调试器时不要用脑子跟公式较劲，用 shape 说话**。他在 00:31:00 看到 28 时那句"padding 对了"就是闭环。
- **【画面】** 00:25:26 截图右侧他用红笔手写了推导：`56×56×256` → `1×1×512`（圈住）→ `1×1×128 / 3×3×128 S=2 / 1×1×512 S=1` → `28×28×512`，这是 ConvDown 的设计草稿。
- **【连接】** 你的 MNIST 模板里 `Conv2d(32,64,3,2,1)` 那组 `(3,2,1)` 就是"精确减半"配方。记牢 `k=3,s=2,p=1 → H/2`，backbone 里 90% 的降采样都是它。

---

**【小结】** ① 论文表格把"下采样发生在 conv3_1/conv4_1/conv5_1"藏在脚注里，把"stage 之间的 1×1 通道升维"完全省略了。② `×4` 要拆成 `1 次下采样 + 3 次残差`。③ ConvDown 的四步是"先升 c → 降 c → 降 wh → 升 c"，进 256×56×56 出 512×28×28。

## Part 4 · 写一个测一个：单元测试实操（00:26:01 – 00:35:08）

**【本段在讲什么】** 两块砖砌完，文老师没急着往下拼，而是停下来讲了本课最重要的一句工程方法论：**"你写一个函数，你马上要测；写完再测基本上你判死刑。"** 然后现场演示怎么给 `nn.Module` 造假输入、打断点、看形状，中间顺手补了 Python 基础（实例化 vs 调用）和一个显存优化小 trick。

---

### 18 三步法：定义算子 → 测试算子 → 堆叠模型（00:26:00 – 00:27:20）

> **文老师**：「你写个代码，第一步你肯定先定义主要算子，这是第一步嘛。第二步完了就是要测试定义的算子是正确的，对不对。第三个才是按模型结构堆叠。你写一个函数，你马上要测，你不要写完了再测——写完了再测，基本上你判死刑，你根本就不知道哪里是对的。」

- **【直译】** 三步走：定义 → 单测 → 堆叠。中间那步不能省。
- **【为什么】** "判死刑"这个词很准确。深度学习模型的报错信息有个特点：**错误位置和报错位置常常隔着好几层**。你在 `MyResNet.forward` 第 5 行看到 `RuntimeError: The size of tensor a (256) must match the size of tensor b (512)`，真正的错在 `__init__` 里某个参数传错。如果每个块都单测过，搜索空间瞬间从"整个网络"缩到"拼装那一层"。
- **【连接】** 这在 BEV 里回报更大：BEVFusion 一次迭代 0.481s（你实测过），等它崩一次的代价远高于 CNN。养成"新写一个 module 就 `torch.randn` 造假输入跑一遍"的肌肉记忆。

---

### 19 Python 基础插曲：实例化对象 vs 实际调用（00:28:30 – 00:30:00）

> **文老师**：「因为这边是定义的一个类，知道吧。然后这个 x 实际上去哪里了？去的 forward。然后这里其实是实例化一个对象，叫实例化类对象。然后这个就是给这个类传一个值——这叫形式上的，这叫实际调用。」

- **【推导/代码】** 测试代码长这样（【画面】第 84–86 行）：

```python
x = torch.randn(1, 512, 28, 28)
conv3_net_bottle = Bottleneck(in_channel=512)   # ① 实例化：走 __init__
y = conv3_net_bottle(x)                          # ② 调用：走 __call__ → forward
```

- **【为什么】** 有学生在这里卡住（第 82 行报错），根因是没分清这两步。`nn.Module.__call__` 内部做了三件事：跑 `_forward_pre_hooks` → 调 `self.forward(*args)` → 跑 `_forward_hooks`。所以**永远写 `model(x)` 而不是 `model.forward(x)`**，后者会跳过所有 hook（钩子失效，剪枝/量化/特征可视化全废）。

---

### 20 实测 ConvDown：(1,256,56,56) → (1,512,28,28)（00:30:00 – 00:31:30）

> **文老师**：「现在我们就打断点，肯定打 forward 的嘛。这里如果正确了，我们执行一下，是不是就变成 512 了。现在有问题，尺寸变小没有？没有尺寸变小……对了，这里才是 down，28，是不是对了？所以我 padding 应该是 padding 对了。然后又回来，回来就变成了 28、512 了，对不对。这里就对了啊。」

- **【推导/代码】** 断点逐行的实测值（他一步步 F8 走出来的）：进入 `res_x = (1,256,56,56)` → conv1_up 后 `(1,512,56,56)` → conv1_down_c 后 `(1,128,56,56)` → conv3_down_wh 后 `(1,128,28,28)` ← 这一步尺寸终于变了 → conv1_up_c 后 `(1,512,28,28)`。
- **【为什么】** 注意调试节奏：**尺寸不变时先怀疑自己走错行**，而不是怀疑公式。他在 conv1_down_c 那行看到 56 就慌了，走到下一行才是 28。新手最常见的时序错觉——断点停在某行时，**这行还没执行**。

### 21 显存小优化 + 实测 Bottleneck（00:31:30 – 00:34:30）

> **文老师**：「但是这里有个小问题，如果这样写的话性能会低。为什么性能会低呢？你看这里搞了，有几个内存了？这是不是有两个内存了，就叫内存 copy 了两份。然后你保险起见的话，你就把它——是不是这样就只有一份了。所以你看这里就只有 res_x 了。」

- **【推导/代码】** 原来他写的是 `x = self.conv1_up(x); res_x = ...` 混用两个变量名，改成全程复用同一个 `res_x`。中间张量是否释放，取决于有没有其它引用还指着它。
- **【为什么】** 严格说收益有限（引用计数会自动回收），但**训练时反向图保留所有中间激活**，多一个活引用就多占一份显存。真正的大杀器是 `inplace=True` 和 `torch.utils.checkpoint`。先让代码跑对，再谈性能。
- **【推导/代码】** 随后他测 Bottleneck：`x = torch.randn(1,512,28,28)` → `Bottleneck(in_channel=512)` → 中间 `(1,128,28,28)`（他念的"28×128"）→ 输出仍是 `(1,512,28,28)`，并现场演示了"两个必须相同才能加"——`res_x + x` 之后数值"一下就变大了"。

---

**【小结】** ① "写一个测一个"是全课最高优先级的工程纪律，写完再测等于判死刑。② `model(x)` 走 `__call__` 会触发 hook，`model.forward(x)` 不会，永远用前者。③ 单测的标准动作就是 `torch.randn` 造假输入 + 断点逐行看 shape，不要用脑子跟公式较劲。

## Part 5 · 第四块砖 + 拼装 MyResNet（00:35:08 – 00:52:10）

### 22 conv1 与 maxpool：唯一不属于任何 stage 的两层（00:35:30 – 00:37:30）

> **文老师**：「哪里还要看那表啊，大哥你记得住吗？我没有那个功能啊。第一个是 3，输出是 64，卷积是 7。要不要 padding？我感觉要 padding，步长是 2。」

- **【推导/代码】** 【画面】`MyResNet.__init__` 的前两行：

```python

self.maxpool = nn.MaxPool2d(kernel_size=3, stride=2, padding=1)
```

- **【推导/代码】** 验算：`224 →(7×7,s=2,p=3) ⌊(224+6−7)/2⌋+1 = 112` ✅；`112 →(3×3 maxpool,s=2,p=1) ⌊(112+2−3)/2⌋+1 = 56` ✅。两步把 224 干到 56，**降了 4 倍**。
- **【为什么】** 为什么开头就用 7×7 这么大的核？2015 年的思路是"第一层要大感受野快速降分辨率省算力"。2020 年之后普遍改成三个 3×3 堆叠（ResNet-D / ResNetV1.5 的 deep stem），感受野相同但参数更少非线性更强。你面试被问"7×7 stem 有什么问题"就答这个。
- **【连接】** YOLOv8 的 stem 是两个 `Conv(k=3,s=2)`，同样 4 倍降采样。你在 YOLO 里加 P2 检测头，就是去接 stem 之后那一级高分辨率特征——对应这里的 56×56。

### 23 发现规律：conv2_x 全残差，其它 stage 首块下采样（00:37:30 – 00:41:30）

> **文老师**：「我有一个新的想法……你不是第一个块 conv2_x 是残差吗？那就是 is_first 为 True 的时候就直接复制三次。第二个块，如果 is_first 是 False，那就是第一次 stride 等于 2，后面都是残差。你看这里的 4、6、3，是不是第一次你都要下采样。所以我干脆直接把它搞在一起就行了。」

- **【直译】** 四个 stage 分两类：conv2_x（`is_first=True`）纯残差重复 3 次；conv3/4/5_x（`is_first=False`）= 第 1 次下采样 + 后 n−1 次残差。
- **【为什么】** conv2_x 为什么特殊？conv1 的 s=2 加 maxpool 的 s=2 已把 224 降到 56，而论文表里 conv2_x 的 output size 也是 56×56——不需要再降。前提是你去看 output size 那一列而不是只看中括号。
- **【连接】** BEVFusion 的 SECOND `layer_strides=[1,2,2]` 第一个是 1，正是同一个道理：稀疏卷积编码器已经把分辨率降到位了，第一个 dense stage 不再降。你看到 `[1,2,2]` 里那个孤零零的 1，别以为是笔误。

### 24 "4 = 1 + 3" 的拆分口诀（00:42:00 – 00:43:00）

> **文老师**：「force 就是这三种情况，第一次是 s 等于几？s 等于 2。那我们这里就把 4 拆成什么——1 和 3。其实我想做的事就是这样，我就直接定了一个块，叫 ConvDown_And_Bottleneck，下采样并且残差。那后面我去拼的时候就方便了。」

### 25 ConvDown_And_Bottleneck：两层判断【画面·完整代码】（00:43:00 – 00:48:30）

> **文老师**：「为什么这里要两个 if 对吧？是因为你首先要判断是不是第一个块，因为它第一个块是全残差。所以 else 就不是啊，这个是第二个块、第三个块、第四个块。但是你这里又要判断一次，如果你是 index 等于 0，那么就是下采样，否则残差。」

- **【推导/代码】** 【画面】`day9_1.py` 第 78–105 行：

```python
class ConvDown_And_Bottleneck(nn.Module):
    def __init__(self, in_channel, stride=2, repeat_num=1, is_first=False):
        super(ConvDown_And_Bottleneck, self).__init__()
        self.stride     = stride
        self.repeat_num = repeat_num
        self.is_first   = is_first
        self.bottle = Bottleneck(in_channel)
        self.down   = ConvDown(in_channel)
    def forward(self, x):
        """ 如果第1次，那么直接进行残差 """
        if self.is_first:
            for _ in range(self.repeat_num):
                x = self.bottle(x)
        else:
            for index in range(self.repeat_num):
                if index == 0:          # 只要不是first，则第1次进行下采样
                    x = self.down(x)
                else:                   # 其它进行残差
                    x = self.bottle(x)
        return x
```

- **【为什么】** ⚠ **这里埋着本课的两个大坑**，你必须看出来：① `self.bottle` 只实例化了**一个**对象，`for` 循环里反复调用同一个模块 —— 这意味着 3 次残差**共享同一组权重**，而论文里它们是 3 组独立权重。这是教学简化，实战必须换成 `nn.ModuleList`。② `self.bottle = Bottleneck(in_channel)` 用的是**下采样之前**的通道数，但 `x` 走完 `self.down(x)` 之后通道已经翻倍了 —— 这正是 40 分钟 bug 的根因（02:15:00 修复）。
- **【连接】** 坑①在 BEV 里同样致命：用 `for` 复用同一个 `SparseConv` 实例堆 5 层，参数量只有预期的 1/5，精度上不去且不报错。检查方法：`sum(p.numel() for p in model.parameters())` 跟论文对一下。

self.conv3_x = ConvDown_And_Bottleneck(in_channel=256,  repeat_num=4, is_first=False)
self.conv4_x = ConvDown_And_Bottleneck(in_channel=512,  repeat_num=6, is_first=False)

### 27 尾巴：全局平均池化 + view + 全连接（00:51:00 – 00:52:30）

> **文老师**：「最后还有一个全局平均池化对不对……最后输出对不对，2048。因为这里输出是多少，2048。它维度要变化一下……负一就是自动推断的意思，就变成 2048 个，再搞一个什么，全连接就输出 1000 个类了。」

- **【推导/代码】** 【画面】forward 的末三行：

```python
x = self.avgpool(x)          # (1,2048,7,7) → (1,2048,1,1)
x = x.view(x.size(0), -1)    # → (1,2048)
x = self.fc1(x)              # → (1,1000)
```

调试器实测（【画面 02:23:00】）：`x = {Tensor: (1, 2048)} tensor([[1.0267, 1.0008, 1.0300, ..., 0.9618, 0.9515, 0.9417]])`。

- **【为什么】** `AvgPool2d(7, stride=1)` 在 7×7 上做等价于全局平均池化——但它**写死了 7**，输入尺寸一变就崩。官方用 `nn.AdaptiveAvgPool2d((1,1))`，任意输入都能出 1×1，这才是能吃变尺寸输入的写法。这是本课代码值得你自己改进的一点。
- **【推导/代码】** `x.view(x.size(0), -1)` 的 `-1` 自动推断出 `2048×1×1 = 2048`；等价写法 `torch.flatten(x, 1)`。注意 `view` 要求内存连续，若前面做过 `permute` 必须先 `.contiguous()` 或改用 `reshape`。
- **【连接】** 这三行是"CNN 分类头"的通用尾巴：`GAP → flatten → Linear`。而 BEV 的 CenterPoint 头完全不做 GAP——它要保留 BEV 平面空间位置来回归中心点，这是分类头与检测头的根本分野。

---

**【小结】** ① 抽象出 `ConvDown_And_Bottleneck` 之后，`MyResNet` 的四个 stage 就是论文表格的直译，改 101/152 只改 `repeat_num`。② `is_first` 判 stage 类型、`index==0` 判块位置，两层布尔覆盖全部情况。③ 代码里 `self.bottle` 单实例被循环复用，是教学简化，实战要换 `nn.ModuleList`。

### 29 排查手法：从最外层往里跳断点（00:54:30 – 00:57:00）

> **文老师**：「这里是对的，这里就是 1×64×56×56，这个地方是对的。然后它就跳到 conv2_x，这里有个问题啊：你看这里为什么输出是这个？这里应该是 56 啊。这里应该是输出 1×256×56×56 应该是。这个模块啊，你就只能把它拔了，你只能结束——然后跑哪去了？是跑这里打断点，你只能这里才打断点啊。」

self.conv2_x_up = Conv(in_channel=64, out_channel=256, kernel_size=1, stride=1)

### 33 根因复盘（下）：残差块入口通道没跟着翻倍（02:11:00 – 02:16:00）

> **文老师**：「我错就错在这里了。conv3_x 输入是 256×56×56，然后我们这一步是由两个操作来构成的——先下采样一下，再残差。第一次这里输出的是 512×28×28，因为下采样嘛。那残差它这个 Bottleneck 的输入应该是多少？512×28×28。但是我上面的定义这个地方就出问题了：如果我原来的代码是这样写的，其实这个是 256。所以它一直报错，报的是哪个错啊——这个通道不等。」

- **【直译】** 在 `ConvDown_And_Bottleneck.__init__` 里，`self.bottle = Bottleneck(in_channel)` 用的是**进 stage 时**的通道数 256。但 forward 里 `x` 先经过 `self.down(x)` 变成了 512 通道，再喂给期望 256 的 Bottleneck —— 通道不等，`res_x + x` 加不起来。
- **【推导/代码】** 修复只有 4 行【画面 02:15:00，红笔圈出】：

```python
if not self.is_first:
    self.bottle = Bottleneck(2 * in_channel)   # 下采样后通道翻倍 → 512
else:
    self.bottle = Bottleneck(in_channel)       # conv2_x 不下采样 → 256
self.down = ConvDown(in_channel)
```

- **【为什么】** 老师自己总结的那句话就是本课最该背下来的一条：**"下采样之后，你的通道变成了 512，但你残差的输入我指定的还是 256，而没有翻两倍，所以就导致你残差的输入通道不对。"** 更抽象地说：`ConvDown` 的输出契约是 `out_C = 2 × in_C`，任何接在它后面的模块都必须按 `2×in_C` 声明入口。这个契约老师在 02:18:01 明确写成公式：`out_C = 2 * in_C`。
- **【连接】** 这类"模块 A 的输出契约没传达给 B"的 bug 在多分支网络里指数放大。BEVFusion 相机 `neck` 输出通道、点云 `SECONDFPN` 输出通道、融合层输入通道三处必须手工对齐——config 里 `in_channels=[128,128]` 那种列表就是在做这件事，改了 backbone 必须同步改它。

### 34 五步法回顾：这套代码是怎么长出来的（02:16:30 – 02:19:00）

> **文老师**：「我们再来回顾一下这个怎么写出来的，就以前人工写代码就是这样写。第一步其实就是先定义卷积这个算子。第二步我们这里就定义的是一个残差算子。第三步呢，因为我们还有一个下采样，所以我们又定义了一个下采样的算子。然后这里就有教训了：又有残差又有下采样的时候，Feature Map 极其容易搞错。然后我们下一步就是把这两个组在一起。这一步就是按我们的网络结构把它串起来。」

- **【推导/代码】** 五步固化下来就是一张工作流卡片：
  1. 定义最小卷积算子（conv-bn-relu，带激活开关）
  2. 定义残差算子（Bottleneck / BasicBlock）
  3. 定义下采样算子（ConvDown），**明确它的输出契约 `out_C = 2·in_C`**
  4. 把 2、3 组合成"stage 单元"（is_first / index 两层判断）
  5. 按论文表格把 stage 串成网络
- **【为什么】** 第 3 步后面那句"教训"是用 40 分钟换来的：**残差与下采样混在一个 stage 时，Feature Map 的通道和尺寸都在变，是全网络最容易错的地方**。你以后写任何 backbone，stage 交界处都要额外画一遍 shape。
- **【连接】** 这五步能一比一套用到"手撕 SECOND 骨干"：① Conv+BN+ReLU（3D 稀疏版）② SparseBasicBlock ③ 每 stage 首层 stride=2 ④ `make_layer` ⑤ 按 `layer_nums=[3,5,5]` 串起来。

```python
# conv2_x 1,256,56,56 -> Bottleneck -> torch.Size([1, 256, 56, 56])

# conv3_x, 256 x 56 x 56  -> 512 x 56 x 56
# 1,256,56,56  下采样 torch.Size([1, 512, 28, 28])
# torch.Size([1, 512, 28, 28])  残差 torch.Size([1, 512, 28, 28])

# conv4_x  512 x 28 x 28 -> 1024 x 14 x 14
# 512 x 28 x 28 下采样 torch.Size([1, 1024, 14, 14])
# torch.Size([1, 1024, 14, 14]) 残差 torch.Size([1, 1024, 14, 14])

# 1024 x 14 x 14 下采样 torch.Size([1, 2048, 7, 7])
# torch.Size([1, 2048, 7, 7]) 残差 torch.Size([1, 2048, 7, 7])
```

- **【为什么】** 注意这里体现的一条规律：**每过一个 stage，通道 ×2、尺寸 ÷2，总"信息量"（C×H×W）减半**。`256×56×56 = 802816`，`512×28×28 = 401408`，`1024×14×14 = 200704`，`2048×7×7 = 100352`。这个"每 stage 减半"是所有 CNN backbone 的共同呼吸节奏，也是 FLOPs 能被控住的原因。

### 36 哪些能复用、哪些必须重写（02:24:00 – 02:28:30）

> **文老师**：「你看 34 的网络里面残差的结构有点不一样啊。那就怎么办呢？你就要去改你的残差块，要把这个残差块重写。卷积要变吗？卷积不用变——不是卷积 BN ReLU，这里是不用变的。你先构建的是最底层的卷积算子，这是底层卷积算子，这是卷积 BN ReLU 套餐，这玩意要变吗？这玩意不变。」

- **【直译】** `class Conv`（conv-bn-relu）原封不动搬过来；`Bottleneck` 换成 `BasicBlock`；`ConvDown` 要按 34 的结构重写。
- **【推导/代码】** 论文里 34-layer 的 conv3_x 是 `[3×3,128 / 3×3,128] × 4`：**两个 3×3，没有 1×1，不做 1/4 压缩，in == out**。这是"basic"和"bottleneck"的全部区别。

- **【连接】** "最底层砖块可复用、上层组合要重写"正是他 03:05:01 讲的"最小单元重用"。给 BEV 换 backbone 时的判断同理：`ConvModule` 能复用，`ResLayer` 要重写。

### 37 从论文表推 34 的下采样在哪（02:28:30 – 02:31:00）

> **文老师**：「这里下采样是怎么下采样的？第一个不会下采样，你只有哪里才会下采样？它先是 3×3 乘以多少，128。你看它只有 3×3×128，它是两个。哪里下采样？你肯定是第一个进行下采样，对吧。或者你这个时候就要去看论文了……万一有一天你没有画好的怎么办？那也很正常啊。你就要习惯从这里推论出来。」

### 39 ConvDown（34 版）：升维 + 降尺寸 + 保尺寸【画面·完整代码】（02:34:30 – 02:38:00）

> **文老师**：「下采样应该是 in_channel……因为下采样你要先跟我升，所以这里升上去，这里应该是几倍了？两倍啊。然后这里就是 3×3，2 倍 in_channel 出去，这个 s 就应该等于几了？s 等于 2 对不对。这个不用写，用默认就是要 ReLU。这是第一个 3×3，你还有一个什么……肯定要 padding。」

- **【推导/代码】** 【画面】`day9_2.py` 第 25–36 行：

```python
class ConvDown(nn.Module):
    def __init__(self, in_channel):
        super(ConvDown, self).__init__()
        self.conv1x1   = Conv(in_channel,     2 * in_channel, kernel_size=1, stride=1)
        self.conv3x3_1 = Conv(2 * in_channel, 2 * in_channel, kernel_size=3, stride=2, padding=1)
        self.conv3x3_2 = Conv(2 * in_channel, 2 * in_channel, kernel_size=3, stride=1, padding=1)
    def forward(self, input: Tensor) -> Tensor:
        x = self.conv1x1(input)
        x = self.conv3x3_1(x)
        x = self.conv3x3_2(x)
        return x
```

- **【推导/代码】** 代入 `in_channel=64`：`64×56×56 →(1×1) 128×56×56 →(3×3,s=2,p=1) 128×28×28 →(3×3,s=1,p=1) 128×28×28`。契约同样是 `out_C = 2 × in_C`，尺寸减半。
- **【为什么】** 对比 50 版的 ConvDown（四个卷积、先升后降再升），34 版只要三个——因为 BasicBlock 里没有 1/4 压缩，不需要"降 c"那一步。**同一个抽象（ConvDown），因块类型不同而有不同实现**，这正是"接口稳定、实现可换"。
- **【连接】** 注意他用了类型注解 `def forward(self, input: Tensor) -> Tensor`——这是 IDE 补全和类型检查的前提，mmdet3d 那种大项目里几乎是标配，写 BEV 模块时养成习惯。

### 40 BasicBlock：两个 3×3，in == out【画面·完整代码】（02:38:00 – 02:41:30）

> **文老师**：「搞残差啊。残差好像这里不需要 1×1 了，那我们刚才的分析就不需要 1×1 了，因为出来就是那么多了对吧……这还有一个 ReLU 啊，哦这也不应该进行，因为是残差嘛。然后我们这个 x 等于 input 加上我们这个 x。」

- **【推导/代码】** 【画面】`day9_2.py` 第 37–52 行：

```python
class BasicBlock(nn.Module):
    """
    conv2_x的时候，in_channel = 64
    其它应该是 2 * in_channel = 128
    """
    def __init__(self, in_channel):
        super(BasicBlock, self).__init__()
        self.conv3x3_1 = Conv(in_channel, in_channel, kernel_size=3, stride=1, padding=1)
        self.conv3x3_2 = Conv(in_channel, in_channel, kernel_size=3, stride=1, padding=1, is_relu=False)
        self.act = nn.ReLU()
    def forward(self, input: Tensor) -> Tensor:
        x = self.conv3x3_1(input)
        x = self.conv3x3_2(x)
        x = input + x
        x = self.act(x)
        return x
```

- **【为什么】** 三个细节值得记：① 第二个 3×3 传 `is_relu=False`，跟 Bottleneck 完全同理（加完才激活）② `x = input + x` 而不是覆盖 `input`，捷径分支得以保留 ③ **docstring 里直接写死了"conv2_x 时 in=64，其它是 2×in_channel"** —— 他把 40 分钟 bug 的教训直接写进注释，防止在 34 版本再踩一次。
- **【画面】** 截图里 PyCharm 弹出警告 `Class 'Tensor' does not define '__add__', so the '+' operator cannot be used on its instances`。这是 IDE 把 `Tensor` 误解析成了 `pyarrow.lib.Tensor`（提示里明写了 `Ignore all unresolved attributes of 'pyarrow.lib.Tensor.Tensor'`），是**误报**，不影响运行。你遇到同样告警时不要慌着改代码。
- **【连接】** BasicBlock 就是 YOLOv8 `Bottleneck(shortcut=True)` 的直系祖先：两个卷积 + 一条捷径，YOLO 版只是把核做成可配置的 `k=(3,3)` 并加了宽度系数 `e`。

### 41 拼 ResNet34 并跑通【画面·完整代码 + 调试值】（02:41:30 – 02:55:00）

> **文老师**：「这里就是如果是第一个，因为第一个 64 的输入和输出相等的，所以他不是两倍；但是如果其它就是输入的两倍啊……卷积核是 3，哦忘了 padding 了。现在好像调完了啊，全部调完了。」

```python

    def __init__(self, in_channel, repeat_num=1, is_first=False):
        if is_first: self.bootle = BasicBlock(in_channel)
        else:        self.bootle = BasicBlock(2 * in_channel)   # ← 50 版的教训在这里兑现
        self.down1 = ConvDown(in_channel)
    def forward(self, x):                # 逻辑与 50 版完全相同
        ...  if self.is_first: 全残差 ; else: index==0 走 down1，其余走 bootle

class MyResNet(nn.Module):
    def __init__(self, num_classes=1000):
        # input: 3 x 224 x 224
        self.conv1   = Conv(3, 64, kernel_size=7, stride=2, padding=3)
        self.pool    = nn.MaxPool2d(kernel_size=3, stride=2, padding=1)
        self.conv2_x = ConvDownBottle(in_channel=64,  repeat_num=3, is_first=True)
        self.conv3_x = ConvDownBottle(in_channel=64,  repeat_num=4, is_first=False)
        self.conv4_x = ConvDownBottle(in_channel=128, repeat_num=6, is_first=False)
        self.conv5_x = ConvDownBottle(in_channel=256, repeat_num=3, is_first=False)
        self.avgpool = nn.AvgPool2d(kernel_size=7, stride=1)
        self.fc1     = nn.Linear(in_features=512, num_classes)
```

- **【推导/代码】** 【画面 02:54:01】跑通后的逐行注释与调试器实测：
  `conv1 # 64×112×112` → `pool # 1×64×56×56` → `conv2_x # 1×64×56×56` → `conv3_x # 1×128×28×28` → `conv4_x # 1×256×14×14` → `conv5_x # 1×512×7×7` → `avgpool`，调试器变量面板显示 `x = {Tensor: (1, 512, 1, 1)}` → `view` → `fc1`。✅

- **【连接】** 34 层 FLOPs 3.6×10⁹ vs 50 层 3.8×10⁹ 几乎一样，所以老师 03:16:02 建议学员"先把 18/34/50 对比一下"——同等算力下选哪个是实验问题。你在 BEV 里选 image backbone（R50/R101/Swin-T）是同一套逻辑。

**【小结】** ① 换网络时最底层的 `Conv` 砖块可以完全复用，要重写的是残差块和下采样块。② BasicBlock = 两个 3×3、in==out、第二个 `is_relu=False`；34 版 ConvDown = 1×1 升 2 倍 + 3×3(s=2) + 3×3(s=1)。③ ResNet34 通道链 `64→64→128→256→512`，fc 入口是 512 不是 2048。

> **学生 / 文老师**：「先升再降是可以啊……但是它这个整个块就是这样的，就跟这条线。比如 64 到 128 这里，它这里有个 1×1，就有一个通道控制器……虚线不是残差，虚线是一个下采样。它在这个模块里标注成 ×4，实际上不是 4 次残差，是**下采样 1 次加 3 次残差**。」

- **【直译】** ResNet 论文 Fig.3 那张长条图里，实线捷径 = 恒等映射（残差），虚线捷径 = 需要投影/下采样（尺寸和通道都变）。学生把虚线当成残差，老师纠正。
- **【推导/代码】** 换成代码语言：实线 = `x + F(x)` 直接加；虚线 = `downsample(x) + F(x)`，捷径分支上有一个 `Conv2d(in, out, 1, stride=2)` + BN。文老师的简化实现里，虚线块干脆**不做残差**，只是一条直路 ConvDown。
- **【为什么】** 老师还澄清了另一个学生方案："你的意思是我先从 64 到 128，然后执行这个——这里不是一个残差，这里只是一个卷积块。" 也就是说：把 1×1 升维放在块外面（他 50 版的做法）和放在块里面（34 版的做法）都行，但**放在外面时那一层就不是残差了，别再加捷径**。

### 44 方法论核心：最小单元重用 = 砖 → 一片砖 → 小房间 → 大房子（03:05:30 – 03:10:30）

> **文老师**：「你的意思就是我怎么想到要拆分的，对不对？其实很简单。第一，你的卷积、BN、ReLU 这玩意天然的就要合并成一个算子。第二步，你对这个式子的理解——本来我们就说是 1 加 3 嘛，那是不是我先搞一个下采样的算子，然后再搞一个残差的算子。第三个想法就是你要看嘛，3、4、6、3，每次传的就是 3463，那你如果要满足它这个系数，那是不是这个要合并……我们写代码一个叫最小单元重用。这玩意其实跟我们建房子一样：你首先要有一块砖，就是我们的卷积；第二你要搭一片砖，那我们这里就会有一个残差；然后你就要建一个小房间，小房间就是我们封装的这个算子；然后小房间构成一个大房子，就是 MyResNet。」

- **【推导/代码】** 四级抽象和代码的对应关系：

| 层级 | 比喻 | 本课的类 | 判断依据 |
|---|---|---|---|
| L1 | 一块砖 | `Conv`（conv+bn+relu） | "天然要合并"——三者从不单独出现 |
| L2 | 一片砖 | `Bottleneck` / `ConvDown` | 论文中括号 = 一片砖；"1+3" 拆分 |
| L3 | 一个小房间 | `ConvDown_And_Bottleneck` | 为了让调用点能直接吃 3/4/6/3 |
| L4 | 大房子 | `MyResNet` | 论文表格从上到下的直译 |

- **【为什么】** "什么时候该抽象"的判据很实用：**当调用点在重复写同样的组合、而且论文给的参数（3463）没法直接喂进去时，说明中间缺一层封装**。这是从"代码变丑"反推抽象需求，而不是先设计后写。
- **【连接】** 对照 mmdet3d：L1=`ConvModule`、L2=`BasicBlock/SparseBasicBlock`、L3=`ResLayer/make_res_layer`、L4=`SECOND/ResNet`。再读 mmdet3d backbone 源码，四级结构会自动浮现。

### 45 三级测试：单元 / 集成 / 系统（03:10:30 – 03:15:00）

> **文老师**：「我刚才跟你讲，是调试的是一个算子搞好了就调试一个算子，找准输入和输出。但我犯的错，其实就是——我们最开始是先下采样然后再残差，我们是先调的下采样，然后再调的残差嘛，是分开来的……其实就是你写好的最小单元要测试，最小单元测试这个在这个行业里面叫**单元测试**。然后你现在有一个小房子，小房子其实我们应该叫**集成测试**，为什么叫集成测试呢？因为你集成了多个单元。然后你最后有一个大房子，大房子我们就叫**系统测试**。」

- **【推导/代码】** 对应到今天的实操：
  - **单元测试**：`x=torch.randn(1,256,56,56)` → `ConvDown(256)` → 期望 `(1,512,28,28)`；`x=torch.randn(1,512,28,28)` → `Bottleneck(512)` → 期望不变。✅ 两个都过了。
  - **集成测试**：`ConvDown_And_Bottleneck` 整个 stage 跑一遍。
  - **系统测试**：`MyResNet()(torch.randn(1,3,224,224))`。
- **【为什么】** 老师自嘲的那句最关键：**"小房子串大房子的过程错了。"** 他单元测试全过、集成测试也过，唯独错在"往小房子里传参数"这一步——也就是 `Bottleneck(in_channel)` 传的值不对。这说明**单元测试通过不代表接口契约正确**，参数传递本身也需要被验证。这是全课最深的一层教训。
- **【连接】** 在 BEV 里这个问题更严重：mmdet3d 靠 config 字典传参，`in_channels` 写错不会有任何类型检查，只会在跑到那一层时爆 shape mismatch。防御手段就是老师做的那件事——**在模块 docstring 里写死输入契约**（`conv2_x的时候 in_channel = 64，其它应该是 2*in_channel`）。

# C:\Users\qwen\.cache\torch\hub\checkpoints\resnet50-0676ba61.pth
def my_resnet(class_num=10):
    # 下载预训练权重模型
    model = torchvision.models.resnet50(pretrained=True)

    # 获取输入特征数（ResNet50 的 fc 层输入是 2048 维）

### 47 预训练权重最阴的坑：ImageNet 可能已经见过你的数据（03:26:00 – 03:33:00）

> **文老师**：「但是我要跟你们说一个事情：如果你们用预训练权重来进行训练，这里有可能会有什么坑呢？因为你要知道这里有一千个分类，但是你现在的蔬菜的 25 个分类，有没有可能就是这一千个分类里面被训练过的？有可能啊……所以有可能出现一个假象：你训练出来的结果非常的好，因为 ImageNet 有可能已经训练过你的数据了。然后你又把这批数据喂给他，那就有可能是一个假的结果……这种情况你只有在生产环境才会发现。」

- **【直译】** ImageNet-1k 的 1000 类里本来就有大量蔬菜、鸟类、花卉。你拿预训练权重去训自己的蔬菜数据集，验证集精度冲到 97~98%，很可能不是你的模型好，而是**模型早就认识这些图**（训练集/验证集污染）。
- **【推导/代码】** 老师给的判断法则很实用：
  - 效果好到"自己怎么都搞不到"（比如别人 94.5，你上来就 97.8）→ 高度怀疑污染
  - **工业数据（缺陷检测、3D 打印件）基本不在 ImageNet 里** → 放心用预训练当初始权重
  - 蔬菜、鸟、花这类自然图像 → 很可能在里面
  - **医学图像除外，建议从零训**（他的经验是医学图像分布和自然图像差太远）
- **【为什么】** 可怕之处在于**验证集也被污染了**，离线指标全绿、上线才崩。这不是过拟合，是数据泄漏（data leakage）。
- **【连接】** 街景数据（nuScenes/Waymo）不在 ImageNet 里，BEV 用 ImageNet 预训练安全且必要。但小心另一种泄漏：**nuScenes 场景在时间上连续**，同一段路的相邻帧可能分别落进 train 和 val，指标虚高。

### 48 微调的两面性 + 下节课安排（03:33:00 – 03:48:00）

> **文老师**：「你那个权重它是这样：一百万张数据集，你如果在你的数据集再微调的话，你会破坏它那个特征提取的能力。就相当于你见了一千个美女，那你肯定知道美女是啥样的；但是你只见了十个美女，那你只认为十个美女是这个样的——你的泛化能力其实没有人家原来的好……本来人家是个学霸，你非要为了这一点纠正他。所以我们现在大模型就是这样的：你数据量少，你最好不要去微调它，你微调了有可能就傻了。」（随后）「下节课我来跟你们讲训练脚本控制。讲了的话，这儿就开始讲目标检测了，不讲 YOLO——先讲起源，从 RCNN 开始。」

- **【直译】** 预训练权重有两面：好的一面是初始化好、收敛快；坏的一面是小数据微调会破坏它在百万张图上学到的通用特征。
- **【推导/代码】** 老师给的决策树（很实用，直接抄进你的工作笔记）：
  1. 先**直接用**预训练模型跑一遍你的验证集 → 效果好（97/98）就**别训了，直接上线**
  2. 效果一般 → 拿它当初始权重微调
  3. 数据量太少（几百张） → 只训最后一层，冻结前面（`for p in model.parameters(): p.requires_grad=False`，只放开 `model.fc`）
  4. 但他的个人经验是："如果你在一千个分类里都有，就按一千个类输出，别训——训了这玩意也会变差"
- **【为什么】** 这个比喻糙但准确刻画了灾难性遗忘（catastrophic forgetting）：小数据微调会把泛化特征拉向局部分布。工业界的缓解手段是 layer-wise 学习率衰减（浅层小 lr、深层大 lr）、LoRA 式低秩微调、EMA。
- **【连接·课程路线】** 下节课路线图（对你规划很关键）：**训练脚本控制（完整训练的几个要素）→ 目标检测起源 RCNN / Fast RCNN / Faster RCNN → SSD & YOLOv1 → V2/V3/V4 打包讲 → V5 理论 → V5 代码 → 3D 打印机项目（指标：置信度 0.6 下 mAP50-95 要 90 以上）**。他明确说 "RCNN 讲了就讲 YOLO 了"。你的"先吃透 YOLO 再进 BEV"路线，从下一节课正式开始。

**【小结】** ① 最小单元重用四级：砖（Conv）→ 一片砖（残差块）→ 小房间（stage 单元）→ 大房子（网络），对应单元/集成/系统三级测试。② 工作中默认走 torchvision 三行方案，手撕是为了应付"只有图没有代码"的新论文。③ 预训练权重可能已经见过你的数据（蔬菜/花/鸟高危、工业数据安全、医学图像建议从零训），小数据微调会破坏泛化能力。

## 课后问答：下采样和改变通道数，能不能分给两个stage？

**问题：** 原文说conv3_x第一个块必须同时把56×56变成28×28、把256通道变成512。为什么不能分成两个stage，一个下采样，另一个改变通道数？

**回答：可以分开。** “必须”是原分析表述过于绝对，不是网络计算的限制。这份结构选择把两种转换放在同一个块中；其他结构可以安排在不同层、不同模块，甚至不同stage中。

### 1. 相同的目标形状，可以通过不同顺序得到

以下形状省略批量维度，按“通道×高×宽”书写。

| 方案 | 第一步 | 第二步 |
|---|---|---|
| 先改变通道，再下采样 | 256×56×56 → 512×56×56 | 512×56×56 → 512×28×28 |
| 先下采样，再改变通道 | 256×56×56 → 256×28×28 | 256×28×28 → 512×28×28 |
| 一层卷积同时完成 | 用3×3卷积，输入256通道、输出512通道、stride=2、padding=1 | 直接得到512×28×28 |

这些方案在形状上都可行，但不保证计算量、特征或精度相同。例如同一个1×1通道转换，在56×56上要处理的空间位置数，是在28×28上的4倍。改变运算先后，还会改变每一步看到的特征，因此不能认为输出shape一样就数学等价。

### 2. 同一个块完成两件事，不代表同一层完成两件事

一个block（块）可以包含多层。此前回答用三层瓶颈路径说明“不同层分工”，但那不是本脚本ConvDown的完整结构。核对当前day9_1.py，老师实际写了四层：

```text
输入：256×56×56
  ↓ conv1_up：1×1，stride=1
512×56×56                 先升通道
  ↓ conv1_down_c：1×1，stride=1
128×56×56                 再压缩通道
  ↓ conv3_down_wh：3×3，stride=2，padding=1
128×28×28                 降低空间尺寸
  ↓ conv1_up_c：1×1，stride=1
512×28×28                 恢复到本stage需要的通道数
```

所以这份代码本身已经让不同卷积层分别处理通道与空间尺寸，只是将四步封装成了一个ConvDown。这里是在忠实说明课堂脚本，不是在确认这个四层写法就是标准ResNet瓶颈块；该ConvDown本身也没有捷径相加。

### 3. 为什么通常不把每一种操作都叫一个stage？

stage是网络的一组连续模块的组织单位，不能理解为“一种操作必须单独占一个stage”。在当前ResNet的组织中，conv3_x先通过首块进入28×28、512通道这个输出形状，后续块就在这个形状上继续提取特征。

这类似一个处理阶段先做好输入转换，再连续加工；转换动作虽然不同，仍可以归到同一个阶段。你可以进一步拆分和重新命名，但命名本身不改变计算。如果真的改变层、顺序或连接方式，那才是在改变网络设计。

### 4. 与前面“4=1+3”的关系

4数的是块执行次数，不是通道数：本例安排1次形状转换，再执行3次保持形状的块。它描述当前结构分工，不是在规定所有网络都只能这样设计，更没有拆分结果必须为奇数的要求。

**原句的准确版本：** conv3_x的整体目标是输出512通道、28×28的特征。这份结构把尺寸和通道的转换安排在第一个块中，后续块保持这个形状。两种转换可以由块内不同层完成，也可以在其他网络设计中分开安排。

## 课后核对：图中×4是四个stage吗？day9_1.py是否准确复现？

**结论：不是四个stage。** 图中每一行1×1/3×3表示一层卷积；中括号三行表示一个Bottleneck块的主分支；中括号外×4表示串联四个块，四块合起来组成conv3_x这个stage。完整残差块还包含BN、激活和捷径，表格没有逐项画出。

```text
conv3_x：一个stage
  块1：三层主分支卷积 + 对齐形状的捷径 → 相加
  块2：三层主分支卷积 + 原样捷径 → 相加
  块3：三层主分支卷积 + 原样捷径 → 相加
  块4：三层主分支卷积 + 原样捷径 → 相加
```

ResNet50的四组conv2_x、conv3_x、conv4_x、conv5_x分别含3、4、6、3个块，共16块。×4不是并行四路，也不表示四次下采样。首块与后续块的输入通道/步长可以不同，各块参数独立。

**脚本审查结论：同形状Bottleneck里的add有正确的形状依据，但整份day9_1.py不能当作标准ResNet50复现模板。** 本次为静态源码对照，没有运行或修改脚本，不能把“形状推导可通”当成实跑结论。

| 位置 | 当前脚本行为 | 与所要复现结构的关键差异 |
|---|---|---|
| 98–113行 | 只创建一个self.bottle，在循环中多次调用 | 后续块共享同一套参数；应逐块创建独立实例 |

| 122、133行 | 在conv2_x前串行加64→256卷积 | 不能用这一步代替首块内部的两路结构：主分支64→64→64→256，捷径64→256，再相加 |
