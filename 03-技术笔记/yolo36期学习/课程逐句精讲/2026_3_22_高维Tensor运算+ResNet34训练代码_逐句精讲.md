**一句话主旨**：神经网络里所有的"维度运算"只有两类——**合并维度**和**拆分维度**（外加一个不改元素只改坐标的**换轴**）；你之所以要做它们，唯一的理由是"下一步那个算子对输入形状有要求"；而只要你会算"某个数变形后跑到哪个坐标去了"，你就再也不会怕形状报错。

## Part 1 · 复习：特征图 (N,C,H,W) 里每个数字的物理含义（00:00:00 – 00:12:01）

**【本段在讲什么】** 谢博用 12 分钟复习，但复习的方式很关键：他不是罗列上节课的结论，而是拿残差连接图里那个 `X` 追问"这个 X 到底是什么、形状是什么、形状里每个数字代表什么"。这一路问下来，他把 `(1, 8, 16, 16)` 这个抽象形状翻译成了三件具体的事：**H/W 对应原图上的一块区域（感受野+空间位置不变性）、C 对应特征的种类数、N 对应第几张图**。这个"把形状读出物理意义"的能力，正是后面两小时维度运算的地基。

---

### 01 残差也是多分支：X 是特征图，形状是 NCHW（00:01:10 – 00:03:00）

> **谢博**：「AlexNet 给我们的一个启发是，一个网络设计的时候，我们并不总是一个分支从头到尾，我们可以设计多分支的架构。ResNet 是不是多分支啊？肯定是多分支啊。残差这种你也可以理解成它是多分支——这是不是有一支？特征是不是这样子从这条路径传播？这是不是又有一条分支？这特征是不是就这个 X？这 X 是特征图吗？那它的形状是多少？NCHW 啊。」

- **【直译】** 残差块的 `out = F(x) + x` 里，`x` 那条捷径就是第二条分支。所以"多分支"不是 Inception 的专利，ResNet 也是。
- **【为什么】** 老师此刻讲这个，是为了引出下一个问题："既然 X 是特征图，它的形状是 NCHW，那 N、C、H、W 各自代表什么？"整堂课的主题是维度运算，他必须先把"形状是有物理含义的"这件事钉死——否则后面 `view(2,16,2)` 这种操作在学生眼里就只是数字游戏。
- **【连接】** 你在 BEVFusion 里看到的 `(64,512,512) → (384,128,128)`，就是这个 NCHW 去掉了 batch 的写法。SECOND 骨干里每个 stage 的输出都是这样一个"有物理含义的四阶张量"。

---

### 02 8×16×16 里那个 0.6：感受野与空间位置不变性（00:04:00 – 00:08:20）

> **谢博**：「假如这张图是 1×8×16×16，原图是 32×32。这个 16×16 里面比如这个像素的值是 0.6，那这个像素的值代表什么？是不是代表原图这个 2×2 区域的特征？那假如它是 8×8 的，那这个像素在原图上它的感受野不就变了吗？变多少？4×4 的。而且这个位置一定是在这里，会在那边吗？不会。这就是卷积能够保证空间位置不变性。」

- **【推导/代码】** 32×32 的原图降到 16×16，缩放比 2 → 特征图上一个像素 ≈ 原图 2×2；降到 8×8，缩放比 4 → 一个像素 ≈ 原图 4×4。这个"块"的**位置也一一对应**：特征图左上角的像素对应原图左上角的区域。
- **【为什么】** 老师用 6 和 9 举例：如果没有空间位置不变性，网络分不出 6 和 9（圈在下面还是上面）。所以他顺带警告：做数据增强时随手加"翻转"，对数字识别就是自杀。
- **【连接】** 这正是 YOLO 检测头能"在 P3/P4/P5 上按格子回归框"的前提——特征图 (i,j) 位置的向量天然对应原图第 (i,j) 个 grid。BEV 里更直接：BEV 特征图的 (x,y) 就是自车坐标系下的一块 0.4m×0.4m 的地砖，位置对应关系是硬约束。

---

### 03 通道数 = 特征的种类数，但不是越多越好（00:08:30 – 00:11:20）

> **谢博**：「这个 8，这个通道数，代表什么意思呢？代表有 8 种特征。从计算上来说它是 8 个核计算出来的。这个 8×8 的，这个数字代表某一种特征，比如轮廓，比如大小，比如纹理。那你说我要把这张图片看得更清楚，这个数字是不是越大越好？我可以把它变成 16——但这里有个问题，越多了它就分不出重要的和不重要的。本来识别一只猫，5 个特征就够了，结果你搞了 50 个特征出来，反而没力。」

- **【推导/代码】** 通道数 C 有两个等价读法：**计算上** = 这一层用了多少个卷积核；**语义上** = 网络在这一层抽出了多少种特征。两者是同一件事的两面。
- **【为什么】** 老师给了两个代价：① 物理意义上，冗余特征会稀释重要特征的权重；② 计算量上，后面每一层都要为这 45 个没用的特征买单，还需要更复杂的结构去把它们筛掉。所以"什么东西在我们这里，你全部都不能说越大就越好"。
- **【连接】** 这就是 YOLOv8 的 `width_multiple`（n/s/m/l/x 五档）在做的事——同一套拓扑，只按比例缩通道。你调 BEVFusion 时把 `out_channels` 从 256 加到 512 通常涨不了点、显存翻倍，就是这一条。

---

### 04 ResNet 解决网络退化：什么叫"退化"（00:12:14 – 00:15:30）

> **谢博**：「ResNet 核心在解决什么问题呢？网络层数的加深。它解决网络退化的问题。其实解决网络退化问题呢，它只是从前向传播、特征提取的角度来说这个事情，那我们还有反向传播这个角度。如果他本来就没这个功能，那能叫退化吗？他只能维持原理，没进化。退化就是说他本来有这个功能——比如说小杨，他本来有能力拿 50k 的，结果他拿个 10k 的，就叫退化。」

- **【直译】** "退化"有严格的语义前提：**深网络的表达能力理论上一定 ≥ 浅网络**（它至少能学成恒等映射），所以深网络表现反而不如浅网络，才叫退化；如果本来就没那个能力，那叫"没进化"，不叫退化。
- **【为什么】** 老师在这里立了一条贯穿全课的方法论：**任何一个网络结构的"为什么"，至少要从前向传播和反向传播两个角度回答**。ResNet 的常规答案（缓解梯度消失）是反向角度，而"退化"是前向角度。面试时两个角度都说，才算答完整。
- **【连接】** 你写 MNIST 默写模板时，从 2 层卷积堆到 6 层如果反而掉点，那就是退化的实感版本——这时候加 shortcut 是标准解法。

---

**【小结】** ① 特征图形状 (N,C,H,W) 的每一位都有物理含义：H/W 编码"原图哪块区域"，C 编码"哪种特征"，N 编码"第几个样本"。② 通道数不是越大越好，冗余特征既稀释语义又吃计算。③ 讲清一个结构的"为什么"，标准套路是前向 + 反向两个角度。

## Part 2 · DenseNet 拆解：cat 与 add、通道爆炸、注意力雏形（00:12:01 – 00:45:01）

**【本段在讲什么】** 这一段是"看懂一张网络结构图"的方法论演示。老师把 DenseNet 图当成**图论意义上的图**来读：先只看节点（有几类），再把边全部蒙住（还原成一条直线的扁平结构），最后分两个角度把边加回来。读完他反问一个工程问题——特征融合为什么用 concat 不用 add——答案朴素得让人放心：因为 add 太难用。这一段的隐藏收获是**注意力机制的第一性来源**：给每条边配一个权重，就是注意力。

---

### 05 图 = 节点 + 边，先看节点：两类节点（00:17:00 – 00:20:15）

> **谢博**：「首先我们看，要看懂它是怎么做的，这是第一件事情。你不要一上来就想说为什么出现这个，你很多事情想不明白的。我看了这个图，我就能够用代码写出来这个结构，这个就代表你看懂了。图是什么呢？节点加边。那你就关注一下这里面的节点是什么，边代表什么。节点这里是不是两种类型的节点？」

- **【画面】** PPT 第 149 页（共 296 页，文件名 `15-YOLOv8算法原理+代码分析.pptx`），标题 DenseNet，正文三行：「DenseBlock 的每一层输入都是前面基层输出的 concat / DenseNet 由多个 DenseBlock 组成 / DenseBlock 之间由 Transition Layer，为 1X1 的卷积，用于减少通道数」。图上老师手写标注了通道数 **3 → 64 → 128 → 256 → 512**。
- **【推导/代码】** 两类节点：彩色的一叠叠方块 = `x`（特征图），白色小框 = `H`（模块，图上写着 BN-ReLU-Conv）。
- **【为什么】** "看懂 = 能照着写出代码"是一个可验证的标准，比"感觉懂了"硬。老师故意先禁止问"为什么"，因为动机只有在你知道它怎么做之后才解释得通。
- **【连接】** 你看 BEVFusion 的架构图时用同一套：节点是 tensor（点云 voxel 特征 / 图像特征 / BEV 特征），边是算子（voxelize / view transform / fuse）。先把图读成"哪个 tensor 经过哪个算子变成哪个 tensor"，再问为什么。

### 06 H 是什么：hypothesis，不是随便一个字母（00:20:15 – 00:23:30）

> **谢博**：「这个 H 怎么理解呢？H 有好多理解的，一个叫隐藏层 Hidden layer。也可以，H 还有一个意思——你们看残差网络是不是也用了 H？那 H 叫 hypothesis，假设的意思。其实就是函数的意思。为什么假设是函数呢？就是假设 x 和 y 之间的关系。我们一般写 y = f(x)，在人工智能算法里面也可以写成 y = h(x)。你还会看到 y = h_c(x)——传统的机器学习算法它的系数是 c，我们现在的神经网络里面用 w 来表示。」

- **【推导/代码】** 逻辑回归的经典写法 `h_c(x) = c0 + c1·x1 + c2·x2`，求解就是求 c；深度学习换成 `h_w(x)`，求解就是求 W。**符号变了，事情没变。**
- **【为什么】** 老师用"广东打工被叫靓仔"打比方：换个地方换个叫法，还是那个人。这不是废话——初学者被 h/f/θ/W/c 这堆符号劝退的比例极高，把它们打通是一次性收益。
- **【连接】** ResNet 论文里的 `H(x) = F(x) + x` 用的就是这个 H = hypothesis：**H 是我们希望这一段网络拟合的那个目标映射**，而 F 是它实际去学的残差。你把 H 读成"hidden"就永远理解不了 ResNet 那句"学残差比学恒等容易"。

---

### 07 蒙住所有边：DenseNet 先还原成一条直线（00:24:20 – 00:26:10）

> **谢博**：「那边的话，这个边比较复杂绕来绕去的。那你就用我的方法怎么办呢？我先蒙住它嘛，我先不看嘛。不看那不就变成一个最简单的扁平结构了吗？x 经过 H1 得到 x1，x1 再经过 H2 得到 x2，再经过 H3 得到 x3。对不对？这个你总看得懂了。」

- **【直译】** 复杂图的读法：**先删掉所有 skip 边，看主干**。DenseNet 删完 skip 就是一条最普通的串行 CNN。
- **【为什么】** 这是认知负载管理，不是偷懒。老师说"要不然今天再看半天你还是乱的，被这箭头绕来绕去"。任何 skip/dense/attention 结构都可以这样降维——先看主路，再一类一类把旁路加回来。
- **【连接】** 读 YOLOv8 的 `yolov8.yaml` 时完全一样：先把所有 `[-1, 6]`（跨层引用）当成 `[-1]`，你会发现主干就是 Conv/C2f 交替；然后再把 FPN/PAN 的横向连接一条条补回去。

---

### 08 两个角度把边加回来：从 x 看 vs 从 H 看（00:26:10 – 00:30:40）

> **谢博**：「第一个从这个 x 的角度来看。x0 除了会送给 H1 做加工之外，还会送给谁？送给 H2，还会送给 H3。也就是它后面每一个操作都要用到它。那我也可以从 H 的角度来看：本来他的输入只有 x2，但是现在是 DenseNet，H3 说 x1 过来、x0 我也要——你前面出来的结果我全要，全都是我的。你看 H3 前面产生了几个 x 呢？x0、x1、x2，三个呀。」

- **【推导/代码】** 两个角度是等价的但对应两种代码写法。从 x 的角度是"广播"，从 H 的角度是"收集"，PyTorch 里当然按后者写：`x = torch.cat(features, dim=1); features.append(H(x))`。
- **【为什么】** 老师用 DenseNet 式学习法开玩笑（每次上课都要复习到开课第一天），既好笑又准确地点出了 DenseNet 的代价——**依赖数随层数平方增长**。
- **【连接】** 这两个角度就是你以后读任何 attention 的姿势：从 query 的角度（我要看谁）和从 key/value 的角度（我被谁看）。BEVFormer 的 spatial cross-attention 用的就是"从 BEV query 的角度去采样多相机特征"。

---

### 09 为什么是 cat 不是 add：因为 add 太难伺候（00:30:40 – 00:34:15）

> **谢博**：「x1 和 x0 之间要做什么操作呢？其实你只有 add 和 cat 操作。那为什么不选 add 选 cat 呢？因为 add 它要什么？形状严格相等。你想想嘛，假如说你去设计你也会选 concat。你如果选择 add，我告诉你绝对很多人会骂你——太难用了，稍微改长一点，结果形状不匹配了。那你这样子设计的话，我只需要把这些别的维度保持不变就可以了。因为这个 H1、H2，里面操作我可不可以自己选择？比如 H1 用 8 个核，H2 任务简单一点，他用 4 个核。」

- **【推导/代码】** `add` 要求两个张量形状**逐维相等**（或可广播）；`cat(dim=1)` 只要求**除拼接维外的其他维相等**。所以 cat 给了每个 H 自由选择 out_channels 的权力，add 直接剥夺了这个自由。
- **【为什么】** 这是全课我最喜欢的一段"工程动机"讲法：设计决策的理由不是数学美，而是**别人用起来烦不烦**。老师随即补充：ResNet 之所以每个残差块只有 2~3 层，正是因为 add 的约束——你非要拉长也行，但必须自己保证两端形状一致。
- **【连接】** YOLOv8 的 C2f 里 `torch.cat` 和 Bottleneck 里的 `x + self.cv2(self.cv1(x))` 同时存在，且后者有个 `shortcut=True/False` 开关——那个开关的本质就是"这里形状对不对得上"。BEVFusion 融合相机 BEV 和 LiDAR BEV 用的也是 cat（`ConvFuser` 先 cat 再 1×1 卷积），道理一样。

---

### 10 通道爆炸：H4 的输入通道是加起来的（00:41:10 – 00:43:00）

> **谢博**：「假如这里面这个 H1 用了 64 个核，这个是不是又 128 呀？这个是不是 256？这是不是 512？那你看 H4 这个输入，他是不是 x0 cat x1、x2、x3？x0 我就假如通道是 3。那我问你，H4 的输入这个特征图，他的通道数是不是要加起来？一加起来，是不是增加他计算量呢？所以你往后面一堆，会堆出什么问题呢？参数量太大了。」

- **【推导/代码】** 【画面】PPT 上老师手写的 3 / 64 / 128 / 256 / 512 就是这条链。H4 的输入通道 = 3 + 64 + 128 + 256 = 451；再往后堆，通道数是**累加**的，卷积参数量正比于 `C_in × C_out × k²`，于是爆炸。
- **【为什么】** 这就是 DenseNet 不能像 ResNet 那样随便堆到 50/100 层的根本原因，也直接推出了下一张卡的 Transition Layer。
- **【连接】** 你在 BEV 里做多帧时序融合时会遇到一模一样的问题：把过去 8 帧的 BEV 特征全 cat 起来，通道数 ×8，显存直接炸。工业界的解法和 DenseNet 一样——先 1×1 降通道，或者干脆改成加权求和。

---

### 11 1×1 卷积 = Transition Layer，然后才有 DenseBlock（00:42:30 – 00:45:00）

> **谢博**：「那这个问题怎么来解决呢？对，上个 1×1 卷积。这个 1×1 卷积就是谁呢？就是这个 Transition。他就是要解决这个问题——你堆了一段时间之后，我又来干嘛？就把通道数减化一下，这样子我们才可以继续友好地往下走。我们刚刚看到的整个这个结构，其实我们准确的叫 DenseBlock。那我们整个 DenseNet 呢，是由很多 DenseBlock 组成的。为什么这么做呢？就是因为我们不可能靠这种模式构造出一个 net 出来。」

- **【推导/代码】** 层级关系被彻底理清：**DenseBlock**（内部全连接，通道累加）→ **Transition Layer**（1×1 卷积降通道 + 池化降分辨率）→ 若干个这样的组合串起来 = **DenseNet**。老师补充：Transition 之间还可以插普通卷积整理特征、做池化压缩分辨率。
- **【为什么】** "封装成 block 再堆" 这个思路是本课的**伏笔**——3 小时后讲 ResNet34 的 `_make_layer` 时，用的是完全同一个套路。老师这里就明说了："那我们就把它封装成一个 block，然后由这个 block 再堆成这个 net。"
- **【连接】** YOLOv8 的 SPPF 前后、每个 stage 之间的 `Conv(k=1)` 干的都是这件事。而 GhostConv/DWConv 那一套"先降通道再干活"的省算力技巧，源头也在这里。

---

### 12 给每条边加权重，就是注意力机制（00:38:40 – 00:40:30）

> **谢博**：「随着路径的增长，它的关联性肯定会弱化。那我就这样子：x4 的输入是 x3，还有 x2，但是 x2 呢我给它乘一个权重，比如一个衰减系数 0.5；x1 再乘一个 0.3；x0 再乘一个 0.1，然后再 concat 在一起。可不可以啊？可以。我这更聪明的做法——这就叫注意力机制呀。注意力机制就是说我该关注哪块，关注度比较大，权重就给大一点。如果 x0 跟我没关系，那我就把他权重设成 0，那不就跟我没关系了吗？这个很深奥吗？没有嘛。」

- **【推导/代码】** 把 DenseNet 的"无差别全要"改成"按权重要"：`out = H(cat([w0*x0, w1*x1, w2*x2, x3]))`。当 `w` 从人工设定的常数变成**由数据算出来的函数**时，它就是标准的注意力。
- **【为什么】** 老师是在给后面的课埋钩子（"这就是我们后面学的注意力机制，叫长距离依赖"）。这个讲法的价值在于：它把注意力从"Transformer 的黑魔法"降格成"DenseNet 的自然改良"，门槛一下子没了。
- **【连接】** 你笔记里已有的 CA（Coordinate Attention）就是这一条：给 H 方向和 W 方向各算一组权重去缩放通道。BiFPN 的 `fast normalized fusion`（每条输入边配一个可学习标量 w_i，再归一化）**字面上就是老师这里手写的那个 0.5/0.3/0.1**——只不过 w 变成可学习的。

---

**【小结】** ① 读网络图的固定流程：认节点 → 蒙住边看主干 → 从两个角度把边加回来。② concat 战胜 add 的理由是工程可用性（形状约束松），不是数学优越性。③ DenseBlock + Transition(1×1) 的"封装成块再堆"是所有现代 backbone 的通用组织法，注意力则是给每条边配权重的自然推论。

## Part 3 · Normalize 大统一：区别只在"选哪堆数"（00:45:01 – 01:20:04）

**【本段在讲什么】** 学生提问引发的一段即兴讲解，但含金量极高。老师先拆掉一个常见误解（BN 在训练和推理时"不一样"），再把所有 Normalize 变体压缩成一句话：**公式只有一个，规则只有一个，唯一的区别是你把哪些数划成一堆**。然后他用调试器里真实的 `(2,16,32,32)` 张量，一刀一刀切给你看 BN 是怎么分组的，最后回答"为什么按通道分组而不按 H 或 W"。

### 13 训练和推理走的是同一条前向传播（00:46:00 – 00:50:00）

> **谢博**：「你们问的问题不是前向传播反向传播，是推理和训练。训练和推理我告诉你，它这个阶段是一样的。因为 Normalize 在哪里做呢？在前向传播的时候做。无论你是训练还是推理，他都会有个前向传播，而且他的前向传播是一模一样的——除非你人为地搞成不一样。其实推理就是训练过程中的一步啊，就是前向传播啊，有什么不一样呢？」

- **【直译】** 训练 = 前向传播 + 反向传播 + 更新；推理 = 只做前向传播。所以推理走的那条路和训练走的那条**是同一条**，除非你在 `forward` 里显式写了分支。
- **【推导/代码】** 老师随后给了这个分支的写法：`if self.training: 走这条 else: 走另一条`。他举的实例是 **GoogLeNet/Inception 的辅助分类头**——训练时才经过辅助头，推理时不经过（或者经过但不用它的输出）。
- **【为什么】** 这段回答其实**不完全对**（见纠错表 B-3）：`nn.BatchNorm2d` 恰恰就是 PyTorch 自己写了 `if self.training` 分支的典型——训练时用当前 batch 的均值方差并更新 running_mean/running_var，推理时用累计的 running 统计量。老师讲的是"框架层面的通则"，学生问的是"BN 这个特例"，两人说的不是一回事。**面试遇到这题必须答 BN 的双模式。**
- **【连接】** 你导出 BEVFusion 的 ONNX 前必须 `model.eval()`，原因正是 BN 和 Dropout 这两个"有 if self.training 分支"的模块。忘了 eval，推理结果会随 batch 组成漂移。

### 14 Normalize 的公式与 γ、β 的默认值（00:49:50 – 00:51:00）

> **谢博**：「我们来看这个，这就是 Normalize 的公式。这个是他的均值看到没有，这个是他的方差，方差开根号就得到 standard deviation，然后加个 epsilon。默认不偏移是什么意思呢？beta set to 0，gamma set to 1，Default 是这样子的。你就把它当不存在。」

- **【推导/代码】** 完整式子：`y = γ · (x − μ) / √(σ² + ε) + β`。ε 是防止除零的小常数（PyTorch 默认 1e-5）。γ 默认 1、β 默认 0 意味着**刚初始化时 BN 就是纯粹的标准化**，缩放和偏移是网络后来自己学出来的。
- **【为什么】** 老师说"当不存在"是学习策略：先把 γ、β 屏蔽掉，Normalize 就只剩"减均值除标准差"这件小学生都会的事，注意力可以全部集中到真正难的地方——**哪些数算一堆**。
- **【连接】** 你在 BEV 部署时做的 BN 折叠（BN fusion）就是把 `γ/√(σ²+ε)` 和 `β − γμ/√(σ²+ε)` 分别吸收进前一个卷积的 weight 和 bias。看懂这个公式，折叠公式一行就推出来了。

### 15 关键概念：Normalize 是"一堆数"的事（00:55:30 – 00:57:00）

> **谢博**：「记住这里面你要理解一个本质：做 Normalize，首先你要确定是一堆数。一堆数做 Normalize，一个数没意义。就是小杨很有钱，我愿意跟他一起做 Normalize——我一个人做 Normalize，我的钱还不是还是这么多吗？我一 Normalize，钱就到我口袋里来了。那比如他很穷，我就不愿意跟他做 Normalize，一 Normalize 我的口袋钱就到他口袋去了。这是杀富济贫的行为。不是说不可以做，你这没意义。」

- **【直译】** 单个数标准化的结果恒等于 0（`(x−x)/0`），毫无信息。Normalize 的语义天生是"一群数互相拉平"。
- **【为什么】** 这个"杀富济贫"的比喻是全场最好用的一个心智模型：**同一堆里的数会互相影响**。它直接推出了两个后续结论——(a) 一个 batch 里混进纯白图会污染其他图的特征；(b) LN 因为一个样本自成一堆，所以样本之间互不影响。
- **【连接】** 这也解释了为什么 BEVFusion 训练在小 batch（你的 mini 数据集，batch=1~2）下 BN 统计量极不稳定，工业界会换成 SyncBN 或者干脆冻结 BN。你的训练计划文档里"无 AMP、只有 mini 数据"这个条件下，BN 的方差估计本来就不可靠。

---

### 16 Normalize 只改值不改位置（00:57:00 – 00:58:40）

> **谢博**：「做 Normalize 的时候，他只改值不改形状。比如说你原来在这个 tensor 里面，你是在哪个位置？那你 Normalize 完之后，你还是这个位置。就比如说这个数 0.4618，他现在的位置是哪一个？做完 Normalize 之后，他变成另外一个数了呀，比如 0.001。会不会把他的位置改变一下？不会，他还是原来在那个位置。你原来坐在这里，你还给我在那儿呆着，只不过是你原来是 200，现在变成 2 了。」

- **【推导/代码】** BN 是**逐元素**（element-wise）操作：`out[n,c,h,w] = f(in[n,c,h,w])`，形状完全不变。老师引用的 0.4618 就是调试器里 `x = {Tensor: (2,16,32,32)}` 展开后的第一个数（【画面】cnn_network.py 调试器 15:35 显示 `-0.4618, 0.4485, -0.1941, ...`）。
- **【为什么】** 老师此刻强调"只改值不改位置"，是在为下一大段做对照铺垫：**view 只改位置不改值，Normalize 只改值不改位置**。这两个正交的概念放在一起讲，学生才不会混。
- **【连接】** 这也是为什么 BN 可以被折进卷积——它不动数据的排布，只是对每个通道做仿射变换。

---

### 17 各种 Norm 的唯一区别：选哪些数做一堆（00:58:40 – 01:00:00）

> **谢博**：「我再说一下，所谓的我们不同的 Norm，还有更多的 Norm，它的区别是什么呢？不是改变它那个计算公式，也不改变这两个规则，它改的是什么呢？我选哪些数来做 Norm。选择不同的数——你比如说我们这里，我可以一起做 Norm，也可以分成两组做 Norm，也可以分成三组，每一组自己做 Norm。然后我分成三组的时候，我也可以选不同的人，比如说以前第一组是他们三个人，现在我第一组换成另外三个人。本质区别就是这个。」

- **【推导/代码】** 用 `(N,C,H,W)` 说话，就是"沿哪些轴求均值方差"：BN 沿 (N,H,W)、LN 沿 (C,H,W)、IN 沿 (H,W)、GN 把 C 分成 g 组后沿 (C/g,H,W)。**公式一模一样，只是求和的下标集合不同。**
- **【为什么】** 这是全课性价比最高的一句总结。市面上讲 Norm 的材料都在画那张"立方体切法"图，但很少有人先把"公式不变、规则不变、只有分组变"这句话讲出来。有了这句，那张图才看得懂。
- **【连接】** BEV 的 transformer 分支（BEVFormer）全用 LN，卷积分支（SECOND/CenterPoint）全用 BN。你现在知道原因了：LN 不跨样本，序列长度可变也不影响；BN 跨样本，需要稳定的 batch 统计。

---

### 18 BN 到底怎么切：用调试器里的 (2,16,32,32) 数给你看（01:00:00 – 01:04:10）

> **谢博**：「做 BN 的话，它是按通道来分组，把 batch size 和 H 和 W 混在一起。那比如像这个 tensor，我们分几组呢？好，x 看到没有，这个维的数全取，然后这是第一组——去拧索引，后面两个维的数全取，取出来就有 32×32 个数。这 32×32 个数当做一堆数，然后他们独立做 Norm。那就是把这个改成 1，同样也是 32×32 个数，然后他们做 Norm。我就问你，这堆数里面是不是有这个 batch 里面所有图片的数据？第一个 32×32 的数来自第一个样本，第二个 32×32 来自第二个样本。这个才是 Batch Norm。」

- **【画面】** 此刻屏幕上是 `cnn_network.py` 的调试器：`x = torch.randn(2, 3, 32, 32)` 经过 `conv1 = Conv2d(3,16,k3,s1,p1)` 后变成 **`x = {Tensor: (2, 16, 32, 32)}`**，老师还在代码区手写了一个红色的"BN"。
- **【推导/代码】** 切法是 `x[:, c, :, :]`，冒号在 N/H/W 三个位置。对 (2,16,32,32) 来说：**一共 16 组**（通道数），**每组 2×32×32 = 2048 个数**（老师口误说成 32×32，漏了 batch 维，见纠错表 B-2）。每组独立算一个 μ 和一个 σ，所以 `BatchNorm2d(16)` 的参数量是 16 个 γ + 16 个 β。
- **【为什么】** 老师用"为什么它叫 Batch Norm"这个命名疑问切入：不是把整个 batch 的 2×16×32×32 = 32768 个数一锅烩（"那太粗暴了"），而是**每一组里都混有 batch 中所有样本的数据**——这才是 Batch 这个词的来历。
- **【连接】** 这解释了 `nn.BatchNorm2d(num_features)` 那个参数为什么等于**通道数**而不是 batch size。你在 BEVFusion 配置里看到的 `norm_cfg=dict(type='BN', eps=1e-3, momentum=0.01)` 后面跟的都是通道数。

### 19 为什么按通道分组：体重和身高不能一起标准化（01:04:10 – 01:07:30）

> **谢博**：「那为什么是按通道分组呢？不是按 H 分组呢？我们说通道代表什么？是不是代表某一种特征？我把这个 batch 里面所有样本的某一类型的特征放在一起做 Norm，这是不是更合理？你比如打个比方，我第一个通道表示大小尺寸的特征，那第一张图片也大，第二张图片也很大；第二个通道表示纹理，那数据都很小。你比如说第一个特征是体重，第二个特征是身高，那它的数值范围是不是不一样？你把体重的数据和身高的数据放在一起做 Normalize，那这个数据最后就会变形了，就相当于你没有提效，反而做了污染。」

- **【推导/代码】** 一句话：**同一组里的数必须量纲可比**。通道 = 特征种类 = 量纲，所以按通道分组天然满足这一点；按 H 分组则会把"第 1 行的轮廓值"和"第 1 行的纹理值"混在一起，量纲错乱。
- **【为什么】** 老师顺手回答了一个常被问但很少答好的面试题。这个"体重 vs 身高"的类比直接来自传统机器学习的特征标准化，学生一秒就懂。
- **【连接】** 你在 BEV 里对点云做归一化时，x/y/z/intensity 四个通道也是**各自**归一化的，绝不会把 intensity 和坐标混在一起——同一条原理。

---

**【小结】** ① Normalize 的公式和规则永远不变，变的只是"把哪些数划成一堆"。② BN 按通道切，一组 = N×H×W 个数，所以组内数据跨样本、图片之间会互相影响；LN 按样本切，组内不跨样本。③ 按通道分组的理由是量纲可比（通道 = 特征种类），不是随便定的。

### 20 Transformer 图：Add & Norm 用 LN，Feed Forward 就是全连接（01:11:00 – 01:16:00）

> **谢博**：「这个网络结构是什么意思啊？是不是很简单？这里来一个特征图，经过这个模块之后出来一个 X'，这里面先干嘛呢？就是 X 加上什么——你把这个框都能看懂。Feed Forward 这里叫前馈神经网络，其实就是全连接。这里是不是代表有一层全连接？这个是不是激活函数？这里是不是又有一层全连接？注意这些都是向量的，因为它不止一个神经元嘛。这个 b 也表示所有的神经元，比如它有十个，那这个 b 代表里面十个数。看这里有个问题：LN 你知道怎么做——但你不知道的是，为什么这里用 LN？」

- **【画面】** 屏幕是 `31-Diffusion模型.pdf` 第 21 页「Transformer 模型架构」，正文给出了转写里完全丢失的三条关键信息：**① 残差连接：模块输出为 `Normalization(F(x) + x)`，和 ResNet 不同，Transformer 使用的归一化方法是 LayerNorm；② 残差连接要求输入 x 和输出 F(x) 的维度必须等长，Transformer 中所有向量长度 `d_model = 512`；③ 前馈网络 `FFN(x) = max(0, xW₁ + b₁)W₂ + b₂`，中间隐藏层维度 `d_ff = 2048`（默认）。**
- **【推导/代码】** `max(0, ·)` 就是 ReLU。所以 FFN = `Linear(512, 2048) → ReLU → Linear(2048, 512)`，是一个先升维再降维的两层 MLP。
- **【为什么】** 老师的教学意图是"用已知打通未知"：残差你会了、LN 你会了、全连接你会了，那 Transformer 的 encoder block 就没有新东西。他留的那个问题（为什么这里用 LN 不用 BN）正好接上 Part 3 的结论——**NLP 的序列长度可变，且样本之间不该互相影响**。
- **【连接】** BEVFormer 的每个 encoder layer 就是这个结构：`Norm(x + SelfAttn(x))` → `Norm(x + CrossAttn(x))` → `Norm(x + FFN(x))`。你现在能把这三行代码原封不动写出来了。
- **【顺带·多模态】**（01:16:00–01:20:04）老师由 Transformer 引出："神经网络可以处理图片吗？文本吗？声音吗？视频也在这里。**不同的数据就叫一种模态**，你也可以叫多数据类型——不显得有点 low 啊？说一些高大上的词位，所以就叫多模态了。"**BEVFusion 就是标准的多模态**：相机（图像）+ LiDAR（点云）各过一个 backbone 变成 BEV 特征，在 BEV 空间对齐后 concat，再用 ConvFuser 降维。你以后被问"你做的是不是多模态"，可以直接这么答。

### 21 图片变 tensor 的两步：OpenCV 负责第一步，PyTorch 负责第二步（01:19:54 – 01:21:10）

> **谢博**：「那你的图片怎么变成 tensor 呢？很简单，你分两步。第一步你是不是要用 CV 把这种图片读进来？它读进来是个 tensor 吗？不是啊，它是一个 ndarray 的数据结构啊。这玩意神经网络能处理吗？不行啊。第二步要把 ndarray 转成 tensor。第一步把图片读成 ndarray 是谁做的呢？OpenCV。第二步把这个数据转成 tensor 是谁做的呢？PyTorch。CV 知道怎么转吗？CV 没有这个接口啊——OpenCV 出来的时候还没有 PyTorch 呢。」

- **【推导/代码】** 具体是 `img = cv2.imread(path)` → `np.ndarray, (H,W,3), uint8, BGR` → `torch.from_numpy(img)` 或 `torchvision.transforms.ToTensor()` → `torch.Tensor, (3,H,W), float32, [0,1]`。**注意 ToTensor 同时干了三件事：换轴 HWC→CHW、转 float、除 255。**
- **【为什么】** "OpenCV 出来的时候还没有 PyTorch"是个很有说服力的历史解释——库之间的职责边界往往是时间顺序决定的，不是设计出来的。
- **【连接】** 后面 04:33:00 的 `transforms.Compose([Resize((224,224)), ToTensor()])` 就是这条链的工业写法。而你的 MNIST 默写模板里 `transform=transforms.ToTensor()` 那一行，现在你知道它悄悄做了换轴。

### 22 数据集尺寸不统一：谁替你保证图片都是 32×32？（01:21:10 – 01:25:00）

> **谢博**：「我还做了一个尺寸上的统一。你说我读来就是 32×32 的数据？那是因为你这个数据集里面全部都是 32×32。一般的数据集里面，它能保证这件事情吗？谁替你保证这件事情呢？这个是 640×480，这个是 481×321……你拿到这些数据全是散乱的。你不能以为每次吃饭人家快速摆到桌上，就以为这是一个理所当然的事情。因为你一个神经网络，是不是都会设计一个输入？你如果输入不确定的话，你这个神经网络就会出错。」

- **【推导/代码】** 老师报的 481×321、640×480 是 VOC/BSDS 这类真实数据集的典型分辨率。神经网络在设计时就绑定了一个输入尺寸（因为最后那层 `nn.Linear` 的 `in_features` 是硬编码的）。
- **【为什么】** "MNIST/CIFAR 把你惯坏了"是这一段的潜台词，他在 04:43:02 又原话说了一遍："你被这个手写数字给你惯坏了，手写数字数据所有的问题都不需要考虑，因为它就是一个最标准的。"这是从玩具数据集迈向真实项目的第一道坎。
- **【连接】** 你的 MNIST 模板里 `nn.Linear(64*7*7, 128)` 那个 `7*7` 就是被 28×28 这个输入尺寸锁死的。换成 32×32 的 CIFAR，这一行必须改成 `8*8`。BEV 里对应的是 `point_cloud_range` + `voxel_size` 决定的 BEV 网格尺寸——改一个就得连锁改一串。

### 23 【翻车现场】把输入改成 32×64，让它当场报错（01:25:00 – 01:30:30）

> **谢博**：「你比如说这个神经网络，我们设计的时候默认输入是 32×32 的。但是你如果对图像不同尺寸的话，来了一个 32×64 的，经过这个网络……这个是不对的。看会不会出错？肯定会出错。哪里会出错？这个地方是不是会——这行代码会不会出错？因为你这样出来的这个，和这个对不上啊。」

- **【画面】** `cnn_network.py` 此时的完整状态：`conv1 = Conv2d(3,16,k3,s1,p1)`、`conv2 = Conv2d(16,32,kernel_size=2,stride=2,padding=0)`、`fc1 = nn.Linear(32*16*16, out_features=10)`，测试代码 `x = torch.randn(4, 3, 32, 64)`，forward 里那行是 `x = x.view(4, 3, -1)`。调试器里的异常是：**`RuntimeError: shape '[4, 3, -1]' is invalid for input of size 65536`**，同时可以看到 `x = {Tensor: (4, 32, 16, 32)}`、`fc1: Linear(in_features=8192, ...)`。
- **【推导/代码】** 把这条链算干净：`(4,3,32,64)` →conv1(k3,s1,p1，尺寸不变)→ `(4,16,32,64)` →conv2(k2,s2)→ `(4,32,16,32)`。总元素数 = 4×32×16×32 = **65536**。`view(4,3,-1)` 要求 65536 能被 4×3=12 整除，**65536 ÷ 12 = 5461.33**，除不尽 → 报错。就算改成 `view(4,-1)` 也只是把错误往后推一格：`(4, 16384)` 进 `Linear(8192, 10)` 依然形状不匹配。**只有输入是 32×32 时，`(4,32,16,16)` → 4×8192，才和 fc1 对得上。**
- **【为什么】** 老师故意不直接讲 view 的语法，而是先制造一个报错。因为形状 bug 是每个人都会遇到的，只有先被它咬一口，你才会认真听"总元素数必须整除"这条规则。
- **【连接】** 这就是你在 4060 上跑 BEVFusion 时最常见的一类崩溃。以后遇到 `shape 'X' is invalid for input of size N`，**第一反应就是：算 N，算 X 里已知维的乘积，看能不能整除。**

### 24 view 的三条规则：整除、只能一个 -1、第 0 维必须是 batch（01:37:40 – 01:42:10）

> **谢博**：「你刚刚不是说把这个形状转换一下？第一个维度就是定 batch 维度，然后这一个维度让你自己算。然后你一算，算出来个 2.5？它除死它就会先出错了。因为你除不尽嘛，会出来小数嘛，这个维度是小数就不合适。所以不要去考虑这种情况。……从数学上来说这里可以写 1，但是这里是 4——从神经网络的物理意义上来说，这里不能写 1、2、4，只能写 4，因为这是分开 4 张图片的特征。当然我们写代码可以写成这样嘛，x 不是有个 shape 吗？可以获取它的 shape，这样我不管你这里怎么样，这里都会对。」

- **【推导/代码】** 三条硬规则：① **元素总数必须守恒且整除**——`numel(x)` 要能被你写死的那些维之积整除，除不尽直接报错；② **`-1` 是占位符，最多一个**——写两个 PyTorch 无法唯一确定分配方案；③ **数学上合法 ≠ 语义上正确**——`(4,32,16,16)` 你可以 `view(2,-1)` 甚至 `view(1,-1)`，数学都成立，但网络里第 0 维必须是 4，因为那是 4 个样本，混在一起就等于把 4 张图的特征拼成 1 个样本喂给分类器。
- **【推荐写法】** `x = x.view(x.shape[0], -1)` —— 老师原话"这样我不管你这里怎么样，这里都会对"。这就是所有开源代码里 `x.view(x.size(0), -1)` / `torch.flatten(x, 1)` 的来历。**把这一行写进你的 MNIST 默写模板**，替换掉硬编码的 `x.view(-1, 64*7*7)`：以后换输入尺寸只需改 Linear 的 in_features，不会连 view 一起改错。

---

**【小结】** ① 神经网络只吃 tensor，图片要经过 OpenCV/PIL → ndarray → PyTorch → tensor 两跳，尺寸统一是你自己的责任。② 网络的输入尺寸被最后那层 Linear 锁死，随便换尺寸必然在 view 或 Linear 处爆炸。③ view 三规则：整除、一个 -1、第 0 维必须是 batch；标准写法 `x.view(x.shape[0], -1)`。

### 25 演示脚本与"组织架构"心智模型（02:00:09 – 02:04:30）

> **谢博**：「一维你知道怎么摆嘛，那肯定就是 0、1、2、3……然后到 63 了。7 后面是不是直接就接 8 了呀？他们之间就不再有结构了呀。这八个家伙是一个平的，然后这四个左右是一个大平的，现在把它全部都放在一个大组里面。……这就是组织架构。首先这是一个大组，下面呢有两个部门，这个第三层有四个小组，这八个人归 L3。」

- **【画面】** `tensor_op.py` 前 7 行：
  ```python
  import torch
  # 创建 2*4*8 的张量，数值从 0 开始递增
  x = torch.arange(64).view(2, 4, 8)
  print("原始张量形状:", x.shape)
  print("原始张量:\n", x)
  ```
  调试器 Console 打出的真值是 `[[[0..7],[8..15],[16..23],[24..31]], [[32..39],[40..47],[48..55],[56..63]]]`。
- **【推导/代码】** 老师的"组织架构"比喻精确对应张量的**行优先（row-major / C order）内存布局**：整个张量是一家公司（64 个人按 0~63 排队），第 0 维 = 2 个事业部，第 1 维 = 每个事业部 4 个部门，第 2 维 = 每个部门 8 个人。**view 从来不动这个 0~63 的队列，它只改分组方式。**
- **【为什么】** 他反复警告不要用几何直觉理解四维五维（"四维十维的空间数，不要去这样尝试，那不是人干的事情"）。组织架构是个纯代数的心智模型，能一直用到 6 维。
- **【连接】** 这个"底层是一维队列 + 上层是分组"的模型，就是 `is_contiguous()` / `.contiguous()` 存在的原因，也是后面 permute 之后必须 `.contiguous()` 才能 view 的根因。BEV 代码里 `x.permute(0,2,3,1).contiguous().view(B,-1,C)` 这种连招，你现在能逐段解释了。

### 26 view 只改形状不改值：横看成岭侧成峰（02:00:00 – 02:01:10 & 01:43:11 – 01:43:50）

> **谢博**：「所以你在小时候看风景的那个 view——横看成岭侧成峰。为什么横看和侧看是什么意思呢？就是会看到不同的 view，就是不同的角度、不同的 view。但是那个山是不是还是那个山啊？他会改变吗？只是你换了个角度去看。所以 view 它只会改形状不改值，只是换了个班子上台，还是原来的那些人。」

- **【直译】** `view` 返回的是**同一块内存的另一个视图**，元素值、元素顺序、元素总数全都不变，变的只是"你按什么形状去读它"。
- **【推导/代码】** 可以直接验证：`y = x.view(2,32); y[0,0] = 99; print(x[0,0,0])` → 也变成 99。因为它们共享 storage。
- **【为什么】** 和 Part 3 的结论正好构成一对：**Normalize 只改值不改位置，view 只改位置不改值。** 老师把这两句话分开两个小时讲，但用词严格对仗，是有意的。
- **【连接】** 这也是 `view` 和 `reshape` 的区别所在：`view` 必须在内存连续时才能用（否则报错让你自己 `.contiguous()`），`reshape` 会在必要时**偷偷拷贝一份**。BEV 代码里两个都能看到，出性能问题时要知道 reshape 可能藏了一次内存拷贝。

### 27 合并维度：(2,4,8) → (2,32) → (64,)（02:04:30 – 02:09:20）

> **谢博**：「你看这里分了三层是不是？这样是不是两层呢？你想想它怎么做啊，是不是把第一个大组里面合并啊？合并变成 32。原来这个维度上是不是还有一个结构啊？现在意思就是把这个维度全都剃掉，他们三三一个小组不见了，他们就是一个大维度。然后 7 后面是不是 8 就接到后面了？」

- **【画面】** 代码里的两行（后来被注释掉）：`y1 = x.view(-1)` → shape `(64,)`；`y2 = x.view(2, 32)` → `print(y2) # torch.Size([2, 32])`。
- **【推导/代码】** 合并维度 = **把相邻的几个维度的大小相乘，取消它们之间的分组**。`(2,4,8) → (2,32)` 就是把 4 和 8 合并成 32；`(2,4,8) → (64,)` 是把三个全合并。合并后原来 `[0,3,7]` 后面接的是 `[1,0,0]`，合并成 (2,32) 就变成 `[0,31]` 后面接 `[1,0]`——**队列顺序完全没变，只是隔断消失了。**
- **【为什么】** 老师在 02:08:10 给出了做这件事的**唯一正当理由**："是因为你下一步计算——比如说卷积里面，下一步我们要接全连接了。全连接要求它的输入是二维的。所以你要把它形状转一下。**随时不要瞎转，说哎呀我今天心情好。理由是因为要参与下一个计算，你要用到的算子对它有要求。**"
- **【连接】** `x.view(x.shape[0], -1)` 就是"把 C、H、W 三个维合并成一个"，这是 CNN 接全连接的标准动作，也是本课 01:30:22 那个 8192 的来历（32×16×16）。

### 28 拆分维度：拆最后一维最简单，拆中间维才是考验（02:10:05 – 02:17:10）

> **谢博**：「现在是合并维度，我再给你演示一个拆分维度。拆分维度当然按你的理解最简单的是拆这个维度。前面都不变，8 这个维度拆，拆成 2 乘 4 可以吧？看原来 3 维是不是现在拆成 4 维？还是两个大组，每个大组里面还是分 4 个小组，但是原来这个小组里面有 8 个元素，现在他告诉你不行，你这 8 个人的团队还要继续拆。……那你也可以拆中间——中间是不是就有点抽象了？你把中间这个 4 拆成 2 乘 2。这里就不再是四个了，这个要变成两层结构。它是不是在中间插了两层了？」

- **【画面】** 代码里被注释掉的两行正是这两种拆法：`# y3 = x.view(2, 4, 2, 4)`（拆最后一维，`8 = 2×4`）和 `# y3 = x.view(2, 2, 2, 8)`（拆中间维，`4 = 2×2`）。
- **【推导/代码】** 拆分维度 = **把一个维度的大小分解成两个因子的乘积**，其他维原样保留。组织架构上：拆最后一维 = 在部门和员工之间插一层"小队"；拆中间维 = 在事业部和部门之间插一层"大区"。
- **【为什么】** 拆最后一维好理解，是因为每个元素在一维队列里的位置完全不受影响，你只是在最里层加了个括号。拆中间维会重排层级关系，但**关键洞察不变：无论怎么拆，元素在一维队列里的绝对位置永远不动**——拆分只是给这个绝对位置换一套坐标系（本质是进制转换）。
- **【连接】** 拆最后一维是 multi-head attention 的标准动作：`(B, L, 512) → (B, L, 8, 64)`，512 个通道拆成 8 个头 × 64 维。合并/拆分前面的维则对应 BEV 里的 `(B, N_cam, C, H, W) ↔ (B*N_cam, C, H, W)`——6 路相机特征在内存里本来就连着，这个变换零开销。

### 29 判断你有没有懂的唯一标准：那个数跑哪去了（02:18:06 – 02:20:00）

> **谢博**：「这就是张量 X[0][3][5]，我现在问 X[0,3,5] 这个数，在这个 Y3 这个张量里面，它的位置是多少？它的索引是多少？这个一眼你就看出来了？你不搞清楚这个，你变完之后这个数到哪儿去了就不知道了呀。你 view 完之后还在这个位置吗？小杨到哪儿去了？不知道，他不见了。」

- **【推导/代码】** 这是本课最有价值的一道题。解法只有两步：
  1. **先把多维索引压成一维绝对位置**（"先把 4×8 合并成一个维度"）：对 shape `(2,4,8)`，`x[0,3,5]` 的一维位置 = `0×32 + 3×8 + 5 = 29`。
  2. **再把一维位置按新形状展开**（除法取商、取余）。
- **【为什么】** 老师说"这个我觉得可能这里蛮重要的，这种你没搞懂你的心是虚的"。他是对的——**能算这个，你就真正理解了行优先布局；算不了，你对 view 的理解就停留在背语法。**
- **【连接】** 这套算法就是 CUDA kernel 里的 `idx = blockIdx.x * blockDim.x + threadIdx.x` 然后 `n = idx / (C*H*W); c = (idx / (H*W)) % C; ...` 那一套。你以后要写 BEV 的自定义算子，这是第一课。

### 30 实算一遍：x[0,3,5] 在 view(2,16,2) 里的坐标（02:31:00 – 02:38:20）

> **谢博**：「首颖是从 0 开始的。你看这里是 [0,3,5]，它的形状是这样子的：3 乘 8 加上 5，就这么多个数。然后现在除以什么呢？走到这个位置，然后余数才是这个位置的索引。每个组里都有 8 个，然后到了第四组里面它没有满 8 个。我们现在是每一组是 2 个，然后看它在自己走——就这个位置。」

- **【画面】** 屏幕上的代码是 `y3 = x.view(2, 16, 2)`，Console 打出的 y3 是 `[[[0,1],[2,3],...,[30,31]], [[32,33],...,[62,63]]]`。
- **【推导/代码】** 完整算一遍：
  - 第 0 维不参与（`x` 和 `y3` 的第 0 维都是 2，且后面的元素数都是 32），所以 **`y3` 的第 0 维还是 0**。
  - 在第 0 组内的偏移量：`3 × 8 + 5 = 29`。
  - 新形状里第 0 组内是 `(16, 2)`，每小组 2 个：`29 ÷ 2 = 14 余 1`。
  - **结论：`x[0,3,5] = 29` → `y3[0,14,1]`。** 可以对着 Console 验证：y3 的第 0 组第 14 行是 `[28, 29]`，第 1 个正是 29。✓
- **【为什么】** 老师中途口算错了一次（转写 02:31:42 "14 也不对啊"），然后重新走了一遍除法才对上。这个过程本身是有教学价值的——**这个题就是要老老实实做除法，不能靠感觉。**
- **【连接】** 把这个当成你的自测题：随便写一个 `(B,C,H,W)` 和一个目标形状，算某个元素的新坐标，能算对就说明你不会再被 BEV 里的形状变换绕晕。

### 31 更变态的情况：两个维度一起拆（02:26:00 – 02:29:10）

> **谢博**：「他一个合并也是……那我是不是也可以这样，也是合法的呀？每个人 8 个数，所以可以变成什么？也是合法的呀。你看这个就是说：中间分成两大组，然后每个组里再分成 16 组，每个组里面两个。现在我再问你，刚刚那个组里面是什么？这是不是就比较变态了？这两个维度，他不是说按单个去拆分——不是把一个维度拆分成两个，是两个维度合在一起拆。」

- **【推导/代码】** `(2,4,8) → (2,16,2)` 严格来说**既不是纯合并也不是纯拆分**：它先把 `4×8=32` 合并，再把 32 拆成 `16×2`。这就是老师说的"两个维度合在一起拆"。他给的通用解法也是这个：**先合并、再拆分**，两步分解永远能做。
- **【为什么】** 老师明确说这种操作"比较少见"、"你不会搞那种很无厘头的操作"、"本身 PyTorch 的设计者也不希望你这样去用"。他花时间讲不是因为常用，而是因为**能算这个，常见的那些就都是送分题**。
- **【连接】** 真实代码里最接近这个的是 pixel shuffle / space-to-depth：`(B, C*r², H, W) → (B, C, H*r, W*r)`，YOLOv5 早期的 Focus 层和一些 BEV 上采样模块都用它。

---

**【小结】** ① view 的全部内容就是合并维度和拆分维度，底层永远是那条 0~N-1 的一维队列。② 做形状变换的唯一正当理由是"下一步的算子对输入有要求"，不能凭心情。③ 检验理解的标准题：某个元素变形后的新坐标——解法固定为"压成一维绝对位置 → 按新形状做除法取商余"。

## Part 6 · 换轴与带 dim 的算子：permute / sum / max（02:40:00 – 03:10:00）

**【本段在讲什么】** view 讲完，老师转向另一类完全不同的操作：**换轴**。它和 view 的区别是——view 不动元素在内存里的顺序，换轴动。然后他给了一个非常实用的学习建议："PyTorch 提供了 transpose / permute / swapaxes / .T / flatten 一堆做法，你只学 view 和 permute 就够了。"最后一小段是带 `dim` 参数的归约算子。

---

### 32 transpose：交换两个维度，索引跟着换（02:44:09 – 02:48:00）

> **谢博**：「Y 是交换维度之后的结果。X 就是原本的 tensor，然后现在交换完之后变成什么呢？也就是说最后面……你交换的维度是哪个维度交换的啊？你看我们这个第 1 这个维度，然后 8 这个维度是第 2 维，所以它填的参数是 dim0=1, dim1=2。交换完之后长什么样子呢？就是在新的这个 tensor 里，它位置到哪里去了？」

- **【画面】** 代码 `y = x.transpose(dim0=1, dim1=2)`，行内提示 `y: tensor([[[0, 8, 16, 24], [1, 9, 17, 25], [2, 10, 18, 26], [3, 11, 19, 27]], ...`，下一行 `print(y.shape) # torch.Size([2, 8, 4])`。调试器里 `x = {Tensor: (2,4,8)}`、`y = {Tensor: (2,8,4)}`。
- **【推导/代码】** 规则一句话：**`transpose(i,j)` 把第 i 维和第 j 维的坐标对调，其他坐标不动。** 所以 `x[0,3,5] → y[0,5,3]`。验证：y 的第 0 组第 5 行是 `[5,13,21,29]`，第 3 个是 29 ✓，正好等于 `x[0,3,5]=29`。
- **【为什么】** 注意 y 的第一行是 `[0, 8, 16, 24]`——**元素在内存里的顺序变了**（原来 0 后面是 1，现在 0 后面是 8）。这是换轴和 view 的本质差别，也是 `permute` 之后 `.view()` 会报 "not contiguous" 的原因。
- **【连接】** `ToTensor()` 内部做的 HWC→CHW 就是一次 transpose。BEV 里 `img_feats.permute(0,2,3,1)` 把 NCHW 换成 NHWC 再喂给 attention，是最常见的用法。

---

### 33 permute：一次换多个维度，参数是"新维度来自旧的第几维"（02:54:14 – 02:56:10）

> **谢博**：「然后看这个 permute，permute 就是维度转换了，包括那个 swapaxes 是一样。swap 就交换，axes 是啥意思呢？就是坐标轴的意思。原来是 (2,4,8)，现在这个 (2,1,0) 是什么意思呢？好，我解释一下：就是原来的第 0 维是现在的第 2 维，原来的第 1 维还是现在的第 1 维，原来的第 2 维是现在的第 0 维。所以新的维度是原来的第 2 维，第 2 维这个是 8 呀；新的第 1 维……新的第 2 维这个是原来的第 0 维。」

- **【画面】** 代码 `# y = x.permute(2, 1, 0)` / `# print(y.shape) # torch.Size([8, 4, 2])`，下面还有一行 `# y = x.permute(2, 0, 1)`。
- **【推导/代码】** **`permute` 的参数读法是"新的第 k 维 = 旧的第 `args[k]` 维"。** 所以 `x.permute(2,1,0)` 把 `(2,4,8)` 变成 `(8,4,2)`。索引对应关系：`x[i,j,k] = y[k,j,i]`，也就是 `x[0,3,5] → y[5,3,0]`。老师随后补充：`permute` 一次能打乱多维，`transpose` 一次只能换两维——所以 `transpose` 是 `permute` 的特例。
- **【为什么】** 老师给了一条我很赞同的学习策略：「PyTorch 提供了这么多方法，你会一个就可以了。要学更少的东西，不要贪多。知识分散太快了，你要给大脑留点空间。下次遇到维度转换就用它。」他明确说 `flatten` 不用学（"因为你用 view 能做这个功能"）、`.T` 只对二维有用（"这个不是高级的"）。
- **【连接】** **对你的建议是：view + permute 两个记死，其余（reshape/flatten/squeeze/unsqueeze/transpose/movedim）遇到再查。** 唯一的例外是 `nn.Flatten()`——它是个 Module，能放进 `nn.Sequential`，而 `view` 不能，这是老师没提到的一个实用差别。

---

### 34 为什么要换轴：还是那句话，下一步算子有要求（02:57:13 – 02:58:20）

> **谢博**：「它跟 view 也是一样，为什么要交换维度呢？就是因为我们下一步要做计算的时候，计算对我们的形状和每一个维度有要求。会遇到维度的问题的时候，某一个维度的一个问题……也会遇到这些，看哪一个维度跟你说不匹配。」

- **【直译】** 换轴的动机和 view 完全相同：**下游算子对形状有要求**。区别只是 view 改的是"分组方式"，permute 改的是"哪个语义放在哪个轴上"。
- **【推导/代码】** 典型场景：`nn.Linear` 只在**最后一维**上做矩阵乘；`nn.Conv2d` 要求通道在**第 1 维**；`nn.MultiheadAttention`（默认 batch_first=False）要求序列长度在**第 0 维**。三个算子对"通道/特征维放哪"的约定不同，所以你必须 permute。
- **【连接】** BEVFusion 的 view transformer（LSS）里那一长串 `permute` 就是在图像坐标系（NCHW）和 BEV 坐标系（N, H_bev, W_bev, C）之间来回倒——每一次 permute 都对应下游一个算子的形状约定。

---

### 35 带 dim 的归约算子：不给 dim 就全局，给了就分组（02:58:20 – 03:09:40）

> **谢博**：「重要的是你要知道它怎么去（用）。那你比如说我也可以这样子，不仅是 max，这些都可以，都是在维度控制的。它这个比如说你如果不加维度控制的话，它就是 64 个数里面最大的数。那如果说加了维度控制，那就是分组啊——就是分组，就是做切片。好，这里还有一个参数叫 keepdim。」

- **【画面】** 代码是 `x = torch.arange(64).view(2, 4, 8)  # shape: [2, 4, 8]` + 注释 `# 维度含义：[批次/通道, 行, 列]` + `out = x.max(dim=-1)`。两次 Run 的输出：不带 dim 时是 `tensor(63)`；`x.sum(dim=0)` 的输出是 `tensor([[32,34,36,38,40,42,44,46],[48,50,...,62],[64,66,...,78],[80,82,...,94]])`。
- **【推导/代码】** 验算 sum：`x.sum(dim=0)` 是把两个 4×8 的块**逐元素相加**，`0+32=32`、`1+33=34`……`7+39=46` ✓ 完全对上。规则：**`dim=k` = "沿第 k 维归约，第 k 维消失"**，`(2,4,8) --sum(dim=0)--> (4,8)`；`keepdim=True` 保留成 `(1,4,8)` 方便广播。`x.max(dim=-1)` 返回 namedtuple `(values, indices)`：values = `[[7,15,23,31],[39,47,55,63]]`，indices 全是 7。
- **【为什么】** 老师把 dim 解释成"分组、做切片"，和 Part 3 讲 Norm 时的"选哪堆数"是同一个思维——**所有带 dim 的操作，dim 都在回答"按什么分组"。**
- **【连接】** 这就是分类头 `pred.argmax(dim=1)` 里那个 1 的含义。CenterPoint 的 heatmap 解码 `topk` 同理，`keepdim=True` 在注意力做 softmax 归一化时天天用。

---

**【小结】** ① view 只改分组不动内存顺序，permute/transpose 改内存顺序——所以 permute 之后往往要 `.contiguous()`。② `permute(args)` 读作"新的第 k 维来自旧的第 args[k] 维"，`x[i,j,k] = y[...]` 的坐标随之置换。③ 带 `dim` 的算子里，dim 永远在回答"按哪个轴分组"，`keepdim` 决定分组轴保不保留。

### 39 ResNet34 的顶层结构：三段式（03:55:00 – 04:04:40）

> **谢博**：「首先输入是不是 3 乘 224 乘 224？首先进入一个 conv1。conv1 在这里，kernel size……这个其实有点太大了，padding 等于 3。然后一个卷积模块——他一般画这个图的时候不会给你标 BN 和激活函数这些东西，你可以自己搭配。如果实在不会搭配，叫 batch normalize，然后再加 ReLU，默认就打这个不会有错的。好这里加一个池化，然后这个时候再接这个 ResNet 模块，他叫四组残差核心层。」

- **【画面】** `resnet.py` 的 forward 开头：
  ```python
  def forward(self, x):
      """ResNet34 完整前向传播过程"""
      # 1. 首层卷积+池化
      x = F.relu(self.bn1(self.conv1(x)))
      x = self.maxpool(x)
      # 2. 4组残差层核心前向传播
  ```
- **【推导/代码】** ResNet34 的三段式：**stem**（7×7 s2 conv + BN + ReLU + 3×3 s2 maxpool）→ **backbone**（4 组残差层）→ **head**（全局平均池化 + 全连接）。老师说"画结构图的人不会画 BN 和激活函数，你要自己补"，并给出默认配方 **Conv → BN → ReLU**。
- **【为什么】** 这个"看图补 BN 和激活"的能力就是 Part 2 说的"看懂 = 能写出代码"。图是给人看的，代码是给机器跑的，两者之间差的就是这些省略掉的胶水层。
- **【连接】** 你的 MNIST 默写模板里的 `Conv2d → ReLU`，按这个标准应该补成 `Conv2d(bias=False) → BatchNorm2d → ReLU`（有 BN 时前面的卷积不需要 bias，因为 BN 的 β 会吸收它）。

### 40 _make_layer：把"堆几个块"变成一个参数（03:59:50 – 04:03:50）

> **谢博**：「第一组这个 layer，它是一个对象。我们看它怎么构建的——它是这里调用了一个函数 `_make_layer`。这里面有什么？三个 block，输出通道是 64，这三个参数它会传到这里来。这里这个三个 block 它就是什么呢？说明里面有三个残差块。整个网络它又分第一组三个，第二组几个呢？一二三四，四个。所以这里就变成 make_layer。」

- **【画面】** `resnet.py`：
  ```python
  self.layer2 = self._make_layer(out_channels=128, num_blocks=4, stride=2)  # 128×28×28
  self.layer3 = self._make_layer(out_channels=256, num_blocks=6, stride=2)  # 256×14×14
  self.layer4 = self._make_layer(out_channels=512, num_blocks=3, stride=2)  # 512×7×7

  def _make_layer(self, out_channels, num_blocks, stride):
      """堆叠残差块：第一个块可能下采样，后续块步幅=1"""
      layers = []
      layers.append(ResidualBlock(self.in_channels, out_channels, stride))  # 第一个残差块
      self.in_channels = out_channels
      for _ in range(1, num_blocks):                                        # 剩余残差块
          layers.append(ResidualBlock(self.in_channels, out_channels))
      return nn.Sequential(*layers)
  ```
- **【推导/代码】** `_make_layer` 只干一件事：**第一个块负责改通道和下采样，剩下的块全是 stride=1 的等尺寸块。** 注意 `self.in_channels = out_channels` 的副作用——它让下一次调用自动知道输入通道数，是最容易被忽略的一行。
- **【★ 34 的来历】** 老师没算，我替你算：`3+4+6+3 = 16` 个 ResidualBlock × 每块 2 层卷积 = 32 层，加 stem 的 conv1 和最后的 fc，正好 **34**。ResNet18 = `[2,2,2,2]`（8×2+2=18），ResNet50 换成 3 层的 Bottleneck `[3,4,6,3]`（16×3+2=50）。**这三个数字记死，面试必问。**
- **【连接】** 这就是 Part 2"封装成 block 再堆"落到代码上的样子。mmdet3d 里 `SECOND` backbone 的 `layer_nums=[5,5]` / `layer_strides=[1,2]` / `out_channels=[128,256]` 是**一模一样**的三参数签名。看懂这个 `_make_layer`，就看懂了半个 mmdetection。

### 41 ResidualBlock：两层卷积 + 一条 shortcut（04:01:30 – 04:03:15）

> **谢博**：「ResidualBlock 就是这个残差模块。那你现在知道了，ResidualBlock 是不是就这个呀？两层卷积加一个残差边。你可以看一下它——因为 ResidualBlock 它在这里定义了，继承 nn.Module。你看它怎么做的：这是第一个卷积，这是第二个卷积，然后这个叫 shortcut。shortcut 是不是就那个残差边？加上这个残差边，然后这里干嘛呢？再接一个激活函数。」

- **【推导/代码】** 标准 BasicBlock：
  ```python
  out = F.relu(self.bn1(self.conv1(x)))     # 3×3, stride=s
  out = self.bn2(self.conv2(out))           # 3×3, stride=1
  out = out + self.shortcut(x)              # 残差边
  out = F.relu(out)                          # 注意 ReLU 在加法之后
  ```
  `shortcut` 在 `stride≠1 或 in_channels≠out_channels` 时是 `Conv2d(1×1, stride=s) + BN`，否则是 `nn.Identity()`。
- **【为什么】** 老师特别点出**"再接一个激活函数"在加法之后**，这是 ResNet v1 的原始设计。他还说"他写得太复杂了，你也可以不用这么写，还整个什么 Sequential——你不 Sequential 可不可以？直接在这里加进来。"这句话是对的：`nn.Sequential` 只是容器，不是必须的。
- **【连接】** 回到 Part 2 的第 9 张卡：**这里用的是 add，所以 shortcut 必须做那个 1×1 卷积来对齐形状**——这就是"add 难伺候"的实证。DenseNet 用 cat 就不需要这个补丁。

### 42 输出层：全局平均池化把 view 的麻烦一次性解决（04:04:39 – 04:05:20）

> **谢博**：「然后后面接什么呢？再加一个全连接。而且他做的是什么？全局平均池化。然后这里再 flatten，然后再接一个全连接。这里看一下他用的是多少，可能只有 512 个节点了。」

- **【画面】** 代码 + 注释：
  ```python
  # 输出层
  ```

### 43 416 能不能进这个网络？数下采样次数（04:05:20 – 04:07:10）

> **谢博**：「你现在图片是多少呢？你有两种做法，一种做法就是用 416 来输入——这个网络行吗？为什么是 32？为什么 31 不行？你 416 行不行，那你要掂量一下。为什么用 VGG 可以？VGG 是不是做了 5 次 pooling？就你这个越降尺寸，那这个数字呢……你看到能被 32 整除就可以了。416 你除以 2 就是 208，104，52，26，13，说明还可以啊。你看他选这个也不是乱选的，416 这个也是一个比较好的数字。」

- **【推导/代码】** ResNet34 一共下采样 **5 次**：conv1(s2)、maxpool(s2)、layer2(s2)、layer3(s2)、layer4(s2) → 总步长 2⁵ = **32**。所以输入边长必须能被 32 整除：224/32 = 7 ✓（对应代码注释 `512×7×7`），416/32 = 13 ✓，而 31 或 500 就不行（会在某一步出现向下取整的信息丢失和尺寸对不齐）。
- **【为什么】** 这条规则解释了一堆"魔法数字"：YOLO 的 416 / 640 / 1280 都是 32 的倍数，ImageNet 的 224 也是。**记住"总步长 32"，你就再也不用查表。**
- **【连接】** 你在 BEV 里选 `point_cloud_range` 和 `voxel_size` 时算 BEV 网格大小，用的是同一套逻辑——网格边长必须能被 backbone 的总下采样倍数整除，否则 FPN 的横向连接尺寸对不上。

### 44 letterbox：resize 必须保持宽高比（04:07:10 – 04:10:20）

> **谢博**：「还有一种做法就是把它 resize 到……resize 的时候你要注意，你的目标是 S×S，这是 416×416，你还要注意一个宽高比。原始图像和这个目标图像都是 1:1，但如果不是呢？你比如说这是 416 乘以 500，然后你把它 resize 到正方形——意味着你的图像会产生变形。这后面我们会讲一个做法叫 letterbox，这个就是要解决这个问题。保证宽高比之后，我要把 500 这个边放到 416，然后这个边它的值肯定要小于 S，但是我的神经网络又要求我输入 S×S，那我就在两边给它补一些。这就叫 letterbox，看起来就像你信封一样。」

- **【推导/代码】** letterbox 三步：① 算缩放系数 `r = min(S/h, S/w)`；② 按 r 等比缩放，得到 `(round(h*r), round(w*r))`，其中至少一边等于 S；③ 另一边用灰色（YOLO 用 114）填充到 S。以 416×500 缩到 416×416 为例：`r = 416/500 = 0.832`，缩放后是 `346×416`，上下各补 35 行。
- **【为什么】** 直接拉伸会让物体变形，"一拉伸完之后，他可能就会失去原来的特征了"。对分类影响还小，对检测就是灾难——框的宽高比全乱了。
- **【连接】** YOLOv8 推理时的 `LetterBox` 是标配，而且**推理完还要把框的坐标反变换回原图**（减 padding、除 r）。这是部署时最常见的一类 bug 来源。BEV 里相机图像做 resize/crop 时，内参矩阵 K 也必须同步做仿射变换——同一个道理。

### 49 虚线 shortcut 在代码里长什么样：那个 if 分支（04:14:00 – 04:15:40）

> **【画面 04_14_04 / 04_14_37】** `resnet.py` 第 7–31 行，`class ResidualBlock(nn.Module)` 的 `__init__` 全文：
> ```python
> def __init__(self, in_channels, out_channels, stride=1):
>     super(ResidualBlock, self).__init__()
>     # 主路径：两层 3x3 卷积
>     self.conv1 = nn.Conv2d(in_channels, out_channels, kernel_size=3,
>                            stride=stride, padding=1, bias=False)
>     self.bn1   = nn.BatchNorm2d(out_channels)
>
>     self.conv2 = nn.Conv2d(out_channels, out_channels, kernel_size=3,
>                            stride=1, padding=1, bias=False)
>     self.bn2   = nn.BatchNorm2d(out_channels)
>
>     # 捷径（shortcut）：若尺寸/通道不匹配，用1x1卷积下采样+调整通道
>     self.shortcut = nn.Sequential()
>     if stride != 1 or in_channels != out_channels:
>         self.shortcut = nn.Sequential(
>             nn.Conv2d(in_channels, out_channels, kernel_size=1,
>                       stride=stride, bias=False),
>             nn.BatchNorm2d(out_channels)
>         )
> ```
> **【画面 04_15_15】** 往下滚，`# 输出层` 和 `_make_layer` 同屏：
> ```python
> self.avgpool = nn.AdaptiveAvgPool2d((1, 1))   # 全局平均池化 → 512×1×1
> self.fc = nn.Linear(in_features=512, num_classes)   # 全连接分类
>
> def _make_layer(self, out_channels, num_blocks, stride):   # 4 usages
>     """堆叠残差块：第一个块可能下采样，后续块步幅=1"""
>     layers = []
>     # 第一个残差块
>     layers.append(ResidualBlock(self.in_channels, out_channels, stride))
>     self.in_channels = out_channels
>     # 剩余残差块
>     for _ in range(1, num_blocks):
>         layers.append(ResidualBlock(self.in_channels, out_channels))
>     return nn.Sequential(*layers)
> ```

- **【图和码的一一对应】** 上一张卡图上的**实线** = `self.shortcut = nn.Sequential()`（空容器 = 恒等，`nn.Sequential()` 对输入原样返回）；**虚线** = 走进那个 `if`，换成 `Conv2d(1×1, stride=stride) + BN`。而 `if` 的两个条件正好覆盖两种不匹配：`stride != 1` 是**空间尺寸**对不上，`in_channels != out_channels` 是**通道数**对不上。
- **【谁触发了 if】** 结合 `_make_layer`：每组的**第一个块**拿到的是 `(self.in_channels, out_channels, stride)`，layer2/3/4 的第一个块 stride=2 且通道翻倍 → 走 if（虚线）；layer1 的第一个块 stride=1 且 64→64 → 不走 if（实线）；**所有非第一个块**都是 `(out_channels, out_channels)` 默认 stride=1 → 一律实线。数一数：34 层里只有 3 条虚线，其余 13 条全是实线，和图上完全吻合。
- **【★ 作者判断】** 这个 `nn.Sequential()` 当恒等用的写法很值得记——**比 `nn.Identity()` 更老派，但效果一样，而且省掉了一个 `if` 在 forward 里**。整个残差网络"要不要补丁"的判断被压缩进构造函数的两行，forward 永远只写 `out + self.shortcut(x)`。这是把分支从运行期挪到构造期的经典手法。
- **【落到动作】** 拿一张纸，只凭"图上哪根线是虚的"把这个 `if` 的两个条件默写出来。写得出来，说明你真的把结构图和代码打通了（卡 05 的验收标准）。

### 52 相对路径与 PyCharm 工作目录：no such file 的根因（04:27:15 – 04:31:20）

> **谢博**：「`no such file`——这不就很常见了吗？那路径要怎么样才对呢？这个路径看你这里有个运行配置，运行配置里面看到没有，这里面有个工作目录。**这个工作目录是你这个里面所有的相对路径的起点，基础路径。**那我如果这样子写的话，那我的路径是这样子的：这是相对路径，然后这里再接上这个相对路径。……我们一般如果是作为一个项目的话，我们这个工作目录会统一设置成项目的路径。不会像现在这样。你如果不设，PyCharm 会默认把你这个文件所在的那个目录设置为你的工作目录。」

- **【连接】** 更稳的写法是用 `pathlib`：`ROOT = Path(__file__).resolve().parents[2]` 然后 `ROOT / "dataset/Vegetable/train"`——**跟工作目录彻底解耦**。你在 4060 服务器上用 ssh 跑脚本时 cwd 经常不是你以为的那个目录，这一招能省很多事。

### 54 transform 与那个必须改掉的 Normalize（04:32:45 – 04:34:00）

> **谢博**：「这个 transform 是做图像变形的：resize、转成 tensor、还有 normalize。normalize 他提供了什么呢？提供了这个均值和方差。这个你就不要用了——**这个做 normalize 的时候均值和方差，他是按照 ImageNet 的标准去做的，跟你这个不一样。**这个时候可能就有问题了，这个你可以改掉他，删掉也可以。你可以直接除以 255 就可以了呀，这是最简单的做法。」

- **【画面】** 最终代码（Normalize 那两行被注释掉了）：
  ```python
  # 图像预处理：416*416 → resize 到 224*224 + 转tensor
  transform = transforms.Compose([
      transforms.Resize((224, 224)),      # 强制缩放到 224×224
      transforms.ToTensor(),              # 转为 PyTorch Tensor
      # transforms.Normalize(mean=[0.485, 0.456, 0.406],   # ImageNet 均值标准差
      #                      std=[0.229, 0.224, 0.225])
  ])
  train_dataset = FruitVegDataset(root_dir="../../dataset/Vegetable/train", transform=transform)
  ```
  Run 输出：`图像形状: torch.Size([3, 224, 224])` / `标签长度: torch.Size([25])` / `数据集总数量: 18591`。
- **【推导/代码】** `[0.485,0.456,0.406] / [0.229,0.224,0.225]` 是 ImageNet 全量统计出来的 RGB 均值和标准差。**用不用它取决于你有没有用 ImageNet 预训练权重**：用预训练就必须保持一致，从头训练就该用自己数据集的统计量（或者干脆只 `ToTensor()`，它已经除了 255）。
- **【为什么】** 这是新手最容易无脑抄的一行。老师点破它是好事——但要注意他的说法不完全准确：**如果你加载 torchvision 的 ImageNet 预训练权重，那这两组数就必须用。**
- **【连接】** 你的 MNIST 模板里如果有 `Normalize((0.1307,), (0.3081,))`，那是 MNIST 自己的统计量，不能挪到别的数据集上。

### 复习最小集（能背下这三句，这节课就没白上）

1. **`view` 只做两件事——合并维度、拆分维度**；底层永远是那条 0~N−1 的一维队列，所以元素总数必须整除、`-1` 只能有一个、第 0 维在网络里永远是 batch。标准写法 `x = x.view(x.shape[0], -1)`。要检验自己懂没懂，就算"某个元素变形后的新坐标"：先把多维索引压成一维绝对位置（`0×32+3×8+5=29`），再按新形状做除法取商余（`29÷2=14余1` → `y3[0,14,1]`）。

2. **所有 Normalize 的公式和规则完全一样，唯一的区别是"把哪些数划成一堆"**：BN 按通道切（`x[:,c,:,:]`，一组 N×H×W 个数，跨样本，图片之间会互相影响）；LN 按样本切（`x[n]`，一组 C×H×W 个数，不跨样本，所以大模型用它）。按通道分组的理由是量纲可比——通道 = 特征种类，就像体重和身高不能一起标准化。

3. **ResNet34 = 1(conv1) + 16×2(残差块) + 1(fc) = 34**，四组 block 数是 `[3,4,6,3]`、通道 `64/128/256/512`；`_make_layer(out_channels, num_blocks, stride)` 只干一件事——第一个块负责下采样和改通道，其余全是 stride=1；总下采样倍数 32，所以输入边长必须是 32 的倍数（224→7、416→13）；最后用 `AdaptiveAvgPool2d((1,1))` 把 H×W 压成 1×1，网络才能吃任意尺寸。
