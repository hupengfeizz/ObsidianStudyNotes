## Part 1 · 坐标系：architecture 与 module 两个层次（00:00:00 – 00:07:01）

**【本段在讲什么】** 开场没有直接讲 AlexNet，而是先给了一个"看网络的坐标系"：任何神经网络都可以从两个层次去关注——**整体架构（architecture）**和**模块（module）**。他用 LeNet-5 和 GoogLeNet 做对照：前者告诉你最扁平的设计长什么样，后者的历史意义是提出 Inception module，从此**设计单位从 layer 升级成 module**。这个坐标系是本课后面判断"ResNet 是模块级还是架构级创新"的尺子，务必先立住。

---

### 01 学得开心比学得好重要 + 本课的坐标系（00:00:00 – 00:02:43）

> **谢博**：「看到你们这种状态我稍微有点放心了，我是不管学得好不好，学得开心很重要……对一个神经网络的设计，我们其实有两个层面去关注它：一个是从整体架构去关注它，整体架构这个是比较难的；第二个是从模块去关注它。」

开场半分钟是调节情绪（Whisper 在 00:00:00 输出的那串 `D,C,D,C…` 是静音幻觉，画面上只是 PPT 封面）。真正值钱的是后半句那个方法论：看网络分两层，architecture 和 module。

这句听着像客套的开场白，但**我认为它是全课最该先记住的一句**。绝大多数人看经典网络是"背结构表"，背完考完就忘，因为那些数字没有生成性；谢博每讲一个网络问的却是"**它给设计者留下了什么可复用的东西**"——LeNet-5 留下范式，GoogLeNet 留下 module 这个抽象层级，AlexNet 留下多分支加三要素，ResNet 留下残差块。这才是面试里能讲出层次感的答法。

**动作**：每听完一个网络，强迫自己回答一句"它给我留下的可复用件是什么"，写在笔记最上面，结构表统统往后放。落到你手上的活也一样——打开 BEVFusion 配置时先分清哪层是 architecture（各分支/融合/检测头怎么接线）、哪层是 module（`SECOND` 里那串 `BasicBlock`）。改 architecture 是动手术，几乎必然重训；改 module 是换零件，能局部微调、能复用预训练权重。你只有 mini 数据和一张 4060，**能动的基本只有 module 那一层**——这一句就砍掉了一半不切实际的改进方案。

### 02 从 LeNet-5 到 GoogLeNet：设计单位升级了（00:01:54 – 00:03:50）

> **谢博**：「上一次我们总结了两个网络，一个是 LeNet-5。LeNet-5 给我们一个什么启发呢？就是说神经网络那种最扁平的神经网络的设计，就是先什么呢，C-P C-P，卷积部分提取特征，再拿全连接做分类。然后升级到 GoogLeNet，GoogLeNet 里面很重要的一个就是提出了一个 Inception 这个 module 的概念。module 这个概念提出之后，我们的设计就变成了用 module 来堆叠了，以前是用 layer 来堆叠的。」

事实很简单：LeNet-5 给出"卷积提特征 + 全连接分类"这个最扁平的骨架，GoogLeNet 把若干层打包成可复用的 Inception module，之后大家搭网络就是在堆 module 而不是堆 layer。

但这个"升级"不是修辞，它**直接决定了后面所有网络的代码长什么样**，这点老师点到没展开，我替他补上。堆 layer 时你的 `__init__` 里是 `self.conv1 / self.conv2 / …` 一路手写，每加深一次重抄一遍；堆 module 时你写 `self.layer1 = self._make_layer(BasicBlock, 64, 2)`，加深只是把 `2` 改成 `3`。ResNet 能有 18/34/50/101/152 一整个家族，前提不是残差多神，而是**它先做到了 module 化**——没有这个抽象，152 层在工程上根本写不出来。

**动作：你那份 MNIST 默写模板该升级了**。它还停在 layer 堆叠（`conv1 → relu → pool → conv2 → …`），下次默写改成先定义 `ConvBNReLU` 或 `BasicBlock`，再 `nn.Sequential(*[BasicBlock(64,64) for _ in range(n)])`。代价不到二十行，却是你从"能跑通例子"到"读得懂 YOLOv8 `C2f` / BEVFusion `SECOND`"之间唯一的那块砖——那两份源码从第一行起就是 module 写法。

### 03 现代网络是 module 套 module，还带多头（00:03:50 – 00:07:01）

> **谢博**：「你看现在的这个神经网络都是靠 module 来堆叠的。看到没有，这是 module，这是 module……你比如说这个 module 叫 C2f，这个 module 你看在这里它又靠更小的 module 来堆叠。所以它这个 module 里面用了三种不同的子 module……我们这个现在看这个网络，它其实也有多头，看到吗？有三个头。」

【画面】老师现场点开的是 YOLOv8 的结构图——一张自上而下的彩色模块图，蓝/绿/红三色块交替，尾部分出三条支路。他借它说两件事：module 可以递归嵌套（大 module 里套小 module），以及这个网络尾部有三个头。

递归嵌套**是理解现代 backbone 的唯一入口，而且它给你一个可操作的读码顺序**：YOLOv8 的 C2f 拆开是若干 Bottleneck，Bottleneck 拆开是两个 ConvBNReLU，再拆才是 `Conv2d + BatchNorm2d + SiLU`。一上来就盯最底层的 `Conv2d` 会淹死在几百个数字里，正确姿势是**自上而下拆三层就停**。

还有一处老师埋了没挑明、值得你接住：**GoogLeNet 的多头是"辅助头"，只在训练时加监督、推理只留主头；YOLO 尾部这三个是"并行头"，三个输出全都要**。两者长得像，权重逻辑却完全相反（第 06 卡会看到辅助头按"离输出多远"打折，YOLO 三头按尺度分配），面试里混为一谈是很扎眼的失分点。**动作**：画个两列小表——"训练用不用／推理留不留／权重按什么定"，三行填完 Part 2、Part 3 就预习掉一半。

**【小结】** ①看网络分两层：architecture 与 module；②LeNet-5 给范式、GoogLeNet 给 module，设计单位从 layer 升级到 module；③现代网络是 module 递归嵌套 + 多头输出，多头又分辅助头和并行头两种。

## Part 2 · 补课：辅助头怎么写进损失函数（00:07:01 – 00:18:00）

**【本段在讲什么】** 这 11 分钟在还上节课 GoogLeNet 的债：辅助头听起来很美，但**它的标签是什么？**答案很反直觉——**辅助头的标签跟主头一模一样，都是最终标签**，区别只在损失函数里乘的系数。然后他用"梯度下降是贪心算法"解释为什么乘个系数就起作用，最后补了两个让这套做法成立的现实前提。这一段把一个"结构上的 trick"落到了"损失函数的一行式子"上，是本课教学质量最高的段落之一。

---

### 04 三个输出 → 三项损失，标签全是 10（00:07:01 – 00:10:09）

> **谢博**：「这里是不是有个输出 O1，这个呢也有个输出，这个也有个输出。那他的损失函数是不是就会有三部分？比如说输入 0，我们目标是要 10。这个位置大概输出 7 就很 OK 了，这个位置输出 3 或者 4……那这个输出他的标签是多少呢？你说 7 是我们假设的呀，其实你拿到的样本，S1 的 X 和 Y，X 是 0，Y 是 10。」

【画面】老师在 YOLOv8 结构图旁边手写：`S1: X=0, Y=10`，三个输出分别标 `→10 O1`、`7→10 O2`、`4→10 O3`，损失写成 `LOSS(W) = (10 − O1)² + (10 − O2)² + (10 − O3)²`，下面画了个箭头 `L → 0`。

这里的关键不是式子，而是他中途自己拆掉的那个陷阱："7 是我们假设的呀"。一个样本只有一个标签，就是 10。你也许**希望**中间层输出 7、4 这样的过渡值，但你根本无从知道中间层"应该"是多少——那两个数是老师随口举的例子，数据里不存在这样的东西。所以三个辅助头的监督目标只能都写成 10。

**这一问一答的价值被严重低估了**：它一次性解掉了"辅助头哪来的标签"这个困惑——没有额外标签，共用同一个。而且它顺手划出了适用边界：**既然共用标签，辅助头就只能做同质任务**，想一个头分类另一个头检测，标签根本对不上。这句老师没说，是从他给的前提直接推出来的。

**动作**：以后读到 `aux_loss_weight=0.25` 这类配置项，脑子里要浮现这三项式子而不是一个可随便调的魔法数；去翻 YOLOv7 `loss.py` 里 aux head 那一支，确认它用的 GT 跟主头是同一批——**亲眼确认一次"共用标签"**，比记住结论牢十倍。

### 05 不加系数会把活全压到前几层（00:10:09 – 00:11:43）

> **谢博**：「那你说这样我就不就完蛋了吗？我们最终的目标是要到 0，到 0 那这个位置就直接输出 10 了呀，这个位置也要输出 10 了呀。那就意味着你把工作压力都压到这一段去了，相当于后面这一段啥事也没干……就会造成这个神经网络实际上你虽然有 30 层，实际上只有前面 10 层在干，后面的 20 层相当于啥都没干。」

形式化：`L = Σᵢ (y − Oᵢ)²`，若 L→0 则每项都要→0，即 O₂ = O₃ = y。而 O₃ 是最浅层的输出，这等于要求网络在第 10 层就做完全部任务，第 11~30 层被逼成恒等映射——三十层的网络，二十层空转。

**这条推理链比结论值钱**：老师不是先给结论再解释，而是**先把"照字面做会怎样"推到荒谬，再从荒谬里逼出修正方案**（归谬）。面试被问"辅助头为什么要加权"，按这条链讲——"三项等权则最优解要求浅层就输出正确答案，后面所有层退化成恒等，所以必须打折"——比背"为了平衡损失"高一个档次：前者证明你推得出来，后者只证明你背过。

**动作**：看到任何多任务损失，先做一次"这一项权重给满会怎样"的极端推演。BEVFusion 的 `loss = loss_det + λ·loss_seg` 就是现成例子——λ 太大，检测分支会被分割分支带跑偏。权重不是拍脑袋，它在决定"哪一段网络承担哪部分工作"；在 4060 上调权重时，这个五秒推演比网格搜索先排掉一半候选值。

### 06 系数 0.5 / 0.1：离终点越远折扣越狠（00:11:43 – 00:14:04）

> **谢博**：「那我们就要在前面加个系数，比如说给他乘个 0.1……你觉得哪个系数要大一点呢？这个是 0.5，这个乘以 0.1，这样合理吗？合理。为什么呢？你想想最后我们这个 O1 输出 10 了其实就已经很正确了，然后这两个地方是允许他有误差的，也就是他的误差我们要把他权重降低。」

最终形式 `L(W) = (10 − O₁)² + 0.5·(10 − O₂)² + 0.1·(10 − O₃)²`：主头系数 1，中间 0.5，最浅 0.1。辅助头的目标仍是 10，但**允许它离 10 远**，实现方式就是给误差打折——O₃ 理想值可能只有 4，硬凑到 10 不讲理，那就把这 6 分误差乘 0.1 变成 0.6 分。

老师给的判据是"离最终输出越远，允许的误差越大，系数就越小"。**这个单调关系是站得住的**，理由不是经验而是能力上限：浅层特征的抽象程度本来就不够，逼它直接给出最终答案属于强人所难。但要小心，这条判据**只对辅助头成立，换一种多头就完全失效**——而这正是它的实用价值所在。对照 YOLO 的 P3/P4/P5：它们的权重通常按**目标尺寸和正样本数量**分配（`box: 7.5, cls: 0.5, dfl: 1.5` 再按各层 stride 缩放），跟"离输出多远"一点关系都没有，因为三个头是平等的并行头，谁也不比谁浅。

**动作**：打开 `ultralytics/cfg/default.yaml`，把 `box/cls/dfl` 三个数抄下来，旁边注一句"并行头，按尺度与正样本数分配，不是按深度打折"。这句注释日后会救你一次——加了 P2 之后正样本分布会变、box 权重往往要跟着动，而这跟"P2 更浅"毫无关系。

### 07 梯度下降是贪心算法：占便宜的算法（00:14:04 – 00:18:01）

> **谢博**：「损失函数会选择——我们说梯度下降算法，他是什么？他是占便宜的算法，就是哪个地方水最多他就会优先优化哪一项……这一项我把它的差距减少了 1，那对我整个损失是不是就减少了 1？如果这一项前面乘了个 0.5，是不是只有 0.5 的能力？这一项乘 0.1，就只减少了 0.1。专业术语叫贪心算法。」

为什么乘个系数就有用？因为反向传播时 `∂L/∂O₃ = 0.1 · 2(O₃ − 10)`，那个 0.1 原封不动乘在梯度上。**"乘系数"不是修辞，它就是在等比缩放那条支路回传的梯度**，优化器自然把力气花在性价比高的主链上。

他随后在 00:16:23 补了两个前提，我认为这两句才是这一段真正的收尾，可惜讲得很快容易漏：①`L` 实际上永远训练不到 0，所以第 05 卡里"后 20 层全白干"那个荒谬结论不会真的发生；②正因为不可能到 0，加权后的三项会形成一个折中——浅层被"往目标方向推"，但不被"逼到目标"。**这两句是把上一卡的归谬法收回来的关键**，没有它们，学生会留下一个"辅助头是个自相矛盾的设计"的印象。

这套"贪心 + 加权 = 控制哪条支路多学"可以立刻拿去解释一个你迟早会遇到的现象：**BEVFusion 训练时相机分支容易学不动**——LiDAR 分支的梯度更"便宜"（收敛快、损失掉得明显），贪心的优化器优先照顾它，相机分支被饿着；所以各家复现要么先预训练相机分支再冻结，要么给它单独权重。**动作**：在 4060 上看到相机分支 loss 几乎不动时，第一反应不是"代码写错了"，而是"梯度被抢走了"，去 config 找分支权重和冻结策略。

**【小结】** ①辅助头没有独立标签，共用最终标签；②不加权会把整个任务压到网络前段，后段退化成恒等传递；③加权之所以有效，是因为梯度下降是贪心算法，系数直接等比缩放回传梯度。

### 08 多分支登场：先把 55×55×48 读对（00:18:57 – 00:22:08）

> **谢博**：「这个叫多分支。这个是一个 224 的一个 RGB 的图，然后用一个卷积，这个卷积是 11 乘以 11，得到一个特征图。这个特征图是不是 55，然后 48？那这个卷积核有多少个呢？48 个嘛……你们是不是把这个 55 以为是通道数？」

【画面 00:19:44】是 `36-笔记.pptx` 第 8 页那张 AlexNet 原图：输入标 `224`、`Stride of 4`、核 `11×11`，上下两条支路各得 `55×55×48`，再 MaxPooling → `27×27×128` → `13×13×192` → `13×13×192` → `13×13×128` → MaxPooling → dense `2048` → dense `2048` → `1000`。

老师专门停下来问"你们是不是把 55 当成通道数"，这一停很值：图上标的三个数是 `H × W × C`，**两个 55 是高和宽，48 才是通道数**，而通道数唯一地告诉你这层用了多少个卷积核。接上上节课两条铁律（`C_out = 核的个数`、`核的通道数 = C_in`），你就能从任何结构图反推出完整的 `nn.Conv2d` 参数——这是基本功，不是记忆题。

⚠ 但老师照 PPT 念的 224 有个业界公案，**他没说，我判断你该知道**：按 `(224−11)/4+1 = 54.25` 根本算不出 55，实际要 227（`(227−11)/4+1 = 55`）。原论文确实写 224，公认是笔误或隐含 padding。这不是抬杠，**它是一个自检习惯的入口**：以后看任何结构图，随手用 `(H + 2p − k)/s + 1` 验一遍。**动作**：拿这张图现在就验 `55 → 27`、`27 → 13`，两分钟。这个习惯在你调 LSS 视锥或改 P2 头时能省掉大量"跑起来才发现形状对不上"。

### 09 两条分支独立发展：48 个核 ≠ 48 个核（00:22:08 – 00:25:20）

> **谢博**：「同一个 x 又经过一个卷积，得到一个 55×55×48 的。所以这边是不是又有 48 个核？这两个是一样的？形状一样，但是你不要以为这 48 个核和这 48 个核值是一样的——不一样。他两个是独立的分支。」

上下两支形状完全对称（都是 48 个 11×11 核），但**权重是两套独立参数**，各自随机初始化、各自更新。这就是"分支"的定义性特征：**同一个输入，不同的权重，独立演化**。如果两支权重相同，那不过是把同一结果算了两遍——这跟上节课"同一层里两个卷积核的 W 必须不一样"是同一条原则的放大版。

这里有个比知识点本身更有意思的判断：**AlexNet 分两支的真实原因是工程妥协，不是设计洞见**——GTX 580 只有 3GB，一张卡装不下，只好劈成两半塞两张卡，而这个凑合做法后来成了"多分支"的范式源头。**一个结构好不好用，和它当初为什么被发明，可以完全无关**；读论文时别对作者的动机故事太当真，该问的是"它现在还给我带来什么"。

**动作**：BEVFusion 的相机分支和 LiDAR 分支就是同一场景、两套独立权重，和 AlexNet 那两条支路是一回事。下次打开 config 确认两个 encoder 是各自独立的 `backbone` 块（不是共享权重的 siamese）、预训练权重分开加载——这决定了你能不能只冻结其中一支。

### 10 分支写成代码：x1 = C1(x)，x2 = C2(x)（00:25:20 – 00:27:02）

> **谢博**：「假如说你写代码的时候，这个卷积你要搞一个算子，比如说 C1 等于 nn.Conv2d，然后 C2 等于 nn.Conv2d，然后这里填你的参数。好，那你在 forward 里面怎么写呢？x 进来，x1 = C1(x)，x2 = C2(x)。x1 就代表这个特征图，x2 就代表这个特征图，就不能写成 x = C(x) 了。」

骨架：`__init__` 里两个独立算子 `self.c1 = self.c2 = nn.Conv2d(3, 48, 11, stride=4)`（各自一份），`forward` 里 `x1 = self.c1(x)`、`x2 = self.c2(x)`，后面接 C3 时写 `x3 = self.c3(x1)`，别把两支中间量串错。

老师反复强调"**不能写成 `x = C(x)`**"，听着琐碎，但**它是这一整段唯一必须当场记住的东西**：单主干可以一路 `x = layer(x)` 覆盖，一旦有分支就必须给每个中间张量单独命名，否则前一支的结果会被后一支冲掉。这是新手写多分支网络最高频的 bug，而且它**不报错**——形状都对，只是算出来的不是你要的，训练一晚上才发现。

这条纪律真正的杀伤力在下半节课：**残差块里一旦写了 `x = self.conv1(x)`，那个要被加回去的原始 `x` 就没了**。**动作**：定一条编码习惯——**forward 里一出现第二条支路，就改用 `out` 做工作变量，`x` 从头留到尾专供直连边**。这正是 torchvision `resnet.py` 和 mmdet3d `SECOND` 里 `identity = x` 的动机。

### 11 concat 融合：两个 team 中期同步（00:27:02 – 00:30:20）

> **谢博**：「这两个卷积出来的结果要做 concat 操作。concat 操作是不是把两个特征图按照通道把它堆在一起？操作你知道怎么做了，那我问这个操作的目的是干嘛？融合特征……用最简单的例子来说就是分组做项目：现在有个大的 problem，把它分成两个 task，这个分支干第一个 task，这个分支干第二个 task。那你这两个小组中间不能没有交流啊，到最后要交项目的时候再放在一起，这合适吗？过两个礼拜大家就要把自己的研究成果同步一下——这就是 concat 操作。」

concat 是按通道维把两个特征图摞起来，但老师问的是**目的**而非操作：目的是特征融合，不是"改变形状"。⚠ 转写里 concat 被听成"CAD 操作"共 6 次。

这段类比藏着多分支为什么有效的**完整论证链**：分工（两支独立提不同特征）→ 中期融合（信息交换，避免各自跑偏）→ 末端汇总（全连接必须看到全部信息）。老师点明末端那次是**必须的**——"已经到总结部分了，你不得综合全面的信息啊"。三段缺一不可：没有中期同步，两支会退化成两个互不相干的小网络；没有末端汇总，分类头只看到半张脸。

对你最直接的用处是**它把 BiFPN 从"一张看不懂的连线图"变成一句话**：每个节点干的就是"中期同步"——P4 既收自己这条路的特征，也收 P3 上采样和 P5 下采样来的。简历上写了 BiFPN，面试官十有八九让你说它比 FPN 强在哪，**用"两个 team 中期同步、同步次数更多、还带加权"去答，比背"双向跨尺度连接 + 加权融合"更像懂行的人**。**动作**：去 `block.py` 看 `C2f` 里那句 `torch.cat(y, 1)`，那是这套逻辑的最小实现。

### 12 多分支在 YOLO 与 SSD 里：以及多分支 vs 多头（00:31:08 – 00:39:11）

> **谢博**：「这个在我们现在的神经网络里面也用到。你看这个是主干，到这里来就分支了。branch 1、branch 2、branch 3——branch 1 和 branch 2 要不要讨论呢？要，看到没有，这里有个箭头，他们的结果共享分享……分支可以在过程中，也可以在输出。如果这个分支是直接在输出部分，那我们就有了一个更加具体的名字，叫多头。它本质上都是多分支。」

他现场翻出 SSD 结构图【画面】说"他有六个分支"——SSD 从 backbone 六个不同深度各拉一条支路做预测。由此定下层级关系：**多分支是大概念，多头是"分支落在输出端"的特例**。

这个层级关系**值钱在它能一次性收编一堆你零散记住的名词**：Inception 四条并行路 = 模块内多分支；ResNet 直连边 = 两分支；FPN/PAN = 架构级多分支 + 多次融合；YOLO 的 P3/P4/P5 = 多头；GoogLeNet 的 aux = 辅助型多头。**全是同一个东西在不同位置的实例化。**把它当成本课第二个坐标系（第一个是 architecture/module）：遇到新模块先问"它在哪分支、在哪融合"，比问它叫什么有用得多。

**动作**：用这个坐标系把 BEVFusion 重述成三句话——相机分支（Swin/ResNet + LSS）与 LiDAR 分支（VoxelNet/SECOND）独立提特征、在 BEV 平面 concat 融合、共享一个 CenterPoint 头。能脱口而出，"介绍一下 BEVFusion"这道必考题就稳了。

### 13 AlexNet 真正的历史贡献：数据 + 模型 + 显卡（00:32:45 – 00:36:43）

> **谢博**：「AlexNet 的贡献还不止这个。他还有一个是奠定了我们现代人工智能的一个基本框架，什么框架呢？三大要素：数据 + 模型 + 显卡……在 AlexNet 之前，训练这种神经网络是无法在消费级的显卡上面完成的，是在那种高性能计算机里面完成的。AlexNet 是第一次把神经网络跑在消费级的显卡上面训练出来。所以英伟达的崛起离不开他，老黄很喜欢他。」

【画面 00:42:20】PPT 右上角这时已写全四条，是本节最核心的画面增量：「网络架构：多分支，branch／多组分工合作／贡献：1. 三大要素：数据+模型+cuda显卡 2. 首次引入 ReLU 3. 首次引入 Dropout，**隐藏层**」。最后那三个字"隐藏层"是现写现划线的，提前剧透了第 14、15 卡的结论。

LeNet-5 提出了卷积算子但没展示出威力，真正证明"卷积网络能吃下大规模图像识别"的是 AlexNet，三根支柱是 ImageNet（数据）、深层 CNN（模型）、CUDA 消费级显卡（算力）。**这个框架至今一个字没变，变的只是数值**：数据从 1400 万张图到万亿 token，模型从 6000 万参数到几千亿，显卡从 GTX 580 到 H100。它不是历史知识，是一把还能用的尺子。

### 14 首次引入 ReLU 与 Dropout：Dropout 能放哪不能放哪（00:39:11 – 00:43:26）

> **谢博**：「AlexNet 是第一次引入 ReLU 这个激活函数，同时还采用了 Dropout。Dropout 是什么意思？随机丢掉一些神经元，为了解决过拟合的问题……那我问你，这个输出层可不可以 Dropout？这一层是一个全连接，有 1000 个节点。不行。输入层和输出层都不能 Dropout……那我问你，Dropout 这个操作可不可以用在卷积上面？可以的，因为它是针对神经元来说的，你卷积和全连接是不是都是有神经元的？」

三条结论：Dropout 的对象是神经元，随机置零；输入层和输出层不能做（输出层 1000 个类，丢一半等于凭空少 500 个类）；卷积层可以做，因为卷积也有神经元（上节课"特征图有几个数就有几个神经元"在这里兑现）。

学生最常见的误解是"Dropout 是全连接专属"，老师用"它针对神经元，而卷积也有神经元"一句话破掉，**这个破法是对的**。但要打个工程补丁：概念上没有禁区，**实践中卷积层用的是 `nn.Dropout2d`（整条通道一起丢）而不是按点丢**——特征图上相邻点高度相关，随机丢单点几乎丢不掉信息，正则效果接近于零。这点老师没提，你写代码时会直接踩到。

⚠ 转写里 Dropout 被听成"揪发我它 / Jobout / Jobalt / 就发的"至少 5 种写法，是本课最严重的转写噪声。**动作**：检查你 MNIST 模板里的 `nn.Dropout(0.5)` 接在哪——若紧挨最后的 `Linear(*, 10)`，按老师这条口径它就贴着输出层了，该往前挪一层。一分钟改完，但会影响收敛。

### 15 靠近输入做 Dropout = 特征选择："我不听我不听"（00:43:26 – 00:45:02）

> **谢博**：「这一层的卷积我们不用 Dropout。为什么呢？因为在这里如果做 Dropout，它会产生一个特征选择的作用。你给我这么多个数，224×224×3 这么多个特征，我一 Dropout，假如说 Dropout 50%，那我其实只用了一半……我有一半的特征没有采纳。就像你说"谢博我给你 10 个理由"，我一 Dropout，你说完 5 个我就说我不听我不听我不听——我一上来就拒绝你了。」

越靠近输入做 Dropout，丢掉的越是**原始的、没被加工过的特征**，等价于"没听完就下结论"；在中间隐藏层做，丢的是已加工过的中间表示，网络还有别的路径把同一信息补回来。

**这条给"Dropout 用在中间隐藏层"这个惯例补上了真实理由，比教科书说法更本质**：不是习惯，是**信息可恢复性**。原始输入丢了就永久丢失；中间表示丢了，同一信息往往在别的通道还有冗余——而"逼网络学出这种冗余"恰恰就是 Dropout 想要的。同一件事在中间层自洽，在输入层自相矛盾。

还有一条老师没说破的暗线值得接住：**Dropout 怕的是"浅层信息传不到深层"，而后半段的残差边解决的也正是这件事**——一个靠不去阻断，一个靠开旁路。**动作**：在复习卡上并排写一行"信息从浅到深会衰减：Dropout 选择不加剧它，残差选择绕过它"。被问"为什么现代 CNN backbone 里几乎看不到 Dropout 了"时直接用：BN 接管了正则、残差接管了信息通路。

### 16 过拟合的主语是"模型函数"，且样本永远带偏差（00:45:02 – 00:49:13）

> **谢博**：「我们说 Dropout 是为了防止过拟合。那过拟合说的是谁？是数据集，还是模型函数？过拟合是模型函数，是这个神经网络……现象是什么？他在训练集很 OK，但是在测试集很差。为什么？因为这个模型太复杂了。本来我是一个线性的模型，但是你把这个模型设计成一个二次的，那你就会完美地拟合这个样本的分布，但是样本的分布本身就存在错误。」

老师画的图很简单：三个采样点，真实规律是一条直线，用二次函数去拟合就会拐着弯精确穿过三点——**误差被当成规律学进去了**。

"过拟合的主语是模型，不是数据"**是这一段最有价值的一句**，而且它不是术语洁癖：随口说"这个数据集过拟合了"会误导排查方向——主语是数据你就去加数据加增强，主语是模型你才会想到降复杂度。两条路成本差一个数量级。**准确表述：过拟合描述的是模型函数的复杂度相对于数据信息量过剩。**

00:47:38 起他用"小杨的体重"把这件事推得更远："这世界上没有人知道他多重。买个电子秤称 10 次取平均，准确吗？我们拿到的数据永远只能无限接近真值。"——**数据带偏差是常态，不是意外**。这对你在 BEV 上的处境直击要害：nuScenes 的 3D 框标注本身就有误差，训练集上 mAP 刷得很高多半是在拟合标注噪声。**动作**：看训练曲线**永远同时看 train 和 val**，把"train 掉得很好但 val 不动"当成一个明确信号——处方是降复杂度/加正则，而不是继续训。

**【小结】** ①AlexNet 的架构贡献是多分支，两支权重独立、中途 concat 融合；②历史贡献是奠定"数据+模型+显卡"三要素，还首次引入 ReLU 与 Dropout（PPT 上补了"隐藏层"三个字）；③Dropout 针对神经元，卷积层能用（但实践中用 `Dropout2d`），输入层/输出层不能用，越靠近输入越像"特征选择"；④过拟合的主语是模型函数，且样本本身永远带偏差。

### 17 直连边就是残差：plain 与 residual 的分野（00:51:12 – 00:53:34）

> **谢博**：「ResNet 的结构呢是这样子的：这里有一个叫 weight layer，那你可以把它换成，比如说这个是卷积，两个卷积。正常来说我们是没有这条边的。那残差网络呢，他就是有一条直连边——这个就是残差网络……有了残差之后，我们的网络结构可以分为两种：一种叫扁平的，plain，plain 就是扁平的意思，比如 VGG；这个就是残差的。」

最小残差块的 forward 比普通两层卷积只多一行：`out = self.conv2(self.relu(self.conv1(x)))` 之后 `out = out + x`。**那一行就是全部的"残差"**。从此网络世界二分：plain（一杆子通到底，VGG 是代表）和 residual（带直连边）。

值得注意的是他的**教学顺序**：先讲"怎么做"（一行代码），再花 40 分钟讲"为什么"。**这个顺序是对的，而且和大多数教材相反**——教材先铺垫梯度消失和退化问题，铺到第五页才给结构，学生被动机绕晕反而记不住那个极简结构。你以后写技术分享时**直接抄这个顺序**。

⚠ 转写里 ResNet 被听成 zlet / 残仓 / 常常网络 / 瑞士代，VGG 听成 vc data，plain 听成 play / 点平，这一段基本没法靠转写读。**动作**：去 `mmdet3d` 打开 SECOND 里那个 `BasicBlock`，把它的 forward 和上面两行对一遍——除了多了 BN 和一个 `downsample` 分支，骨架一模一样。三分钟，但能直接消掉"ResNet 是课本知识"这个心理距离。

### 18 几个模块、什么模块都行，关键在 weight layer（00:53:34 – 00:55:13）

> **谢博**：「三个模块加一条残差边，这叫不叫残差网络呢？只要有直连边，就叫残差模块或者叫残差网络。那假如这个模块是个全连接呢？也叫残差……它这里面叫的是什么呢？叫 weight layer，weight layer 就是带权重的。那假如说这里是 pooling 呢？严格来说按照这个定义来说，这种就不叫残差，为什么呢？因为没有 weight。pooling 有 weight 吗？没有。」

两套口径：严格口径要求跨过去的是 **weight layer**（有可训练参数），FC 可以、Conv 可以、Pooling 不可以；广义口径是只要有直连边就叫残差。

**这个区分不是措辞讲究，它是机制要求**——老师点到没说透：残差的两个作用里，**反向那个作用只有跨过带权重的层时才有价值**，梯度消失是权重矩阵连乘导致的，pooling 本来就不怎么衰减梯度，跨它零收益。所以 "weight layer" 是从机制里长出来的词。

最有用的延伸在 `BasicBlock` 里：主路 `stride=2` 改变形状时，直连边上会插一个 `1×1 Conv + BN` 对齐。**注意那个 1×1 卷积本身是 weight layer，严格说它已经不是纯 identity 了**，业界叫它 projection shortcut。面试问两者区别，答案就在这：形状一致用 identity（零参数零风险），形状变化才被迫用 projection。**动作**：读 SECOND 源码时专门看 `downsample is not None` 那个分支，确认里面是不是 `1×1 Conv(stride=2) + BN`。

**第二条那句英文，我认为比老师后面讲的两个角度更根本**：make it easy to represent the **identity mapping**。残差的最本质动机不是"传特征"也不是"传梯度"，而是"**如果这一层什么都不该学，让 F(x)→0 比让一整层卷积拟合出恒等映射容易得多**"。这一句正好补上后面第 24 卡那个论证的缺口——"理论上多加层不该变差、实际却变差"，缺的就是"恒等映射难以表达"这一环。老师跳过了这页英文，你不要跳。

### 20 H(x) = F(x) + x ⇒ F(x) = H(x) − x：吃剩的那桌菜（00:56:03 – 00:58:22）

> **谢博**：「F(x) 代表这两层模块的函数，然后这边是 x，所以这个地方输出来是 F(x) + x。那为什么叫残差呢？我们把整个这个过程看作一个函数，假如说这个叫 H(x)，他是不是等于 F(x) 加上 x？你变换一下，那 F(x) 等于多少呢？等于 H(x) 减去 x。他是从这个表达式来说的，叫残差……吃剩的一桌饭，有 H 这么多菜，吃掉了 x，剩下的就叫残差。如果从 H(x) 这个角度来讲，他就不叫残差了，他叫 add module，或者叫 combine module。」

同一结构两个视角：**相加视角** `H(x) = F(x) + x`（代码里实际发生的事，所以也叫 add / combine module）；**残差视角** `F(x) = H(x) − x`（名字的来源）——整块要学的是 H(x)，其中 x 白送，卷积分支只需学**差额**。

**这个恒等变换是理解残差威力的钥匙，也是本课最该背下来的两件事之一**（另一件是第 31 卡那个 +1）：假设理想映射恰好是恒等（H(x)=x），F(x) 只要学成 0 就行——把权重压向 0 是优化器最擅长的事（weight decay 天天在干），而让一堆卷积核精确拟合出恒等，难度高几个数量级。这跟上一卡那句 "make it easy to represent the identity mapping" 严丝合缝对上了。"吃剩的一桌菜"比喻生动，但**真正要记的是"学 0 比学恒等容易"这个判断**。

**动作**：把这句背下来当面试标准答法——「残差块并不学目标映射本身，而是学它相对于输入的残差。当最优解接近恒等映射时，把残差压到 0 远比拟合恒等容易，所以加深网络不会变差。」这一句话同时把 Part 5 的退化问题也答掉了，一句抵两句。

### 21 module 级创新可以升级成 architecture 级（00:58:22 – 01:00:00）

> **谢博**：「ResNet 他的创新不是整个网络的架构，他这个是 module 层的创新，就是他提出了一个 module。那整个网络怎么构建呢？就反复地堆叠这个 module 就可以了……当然我们后面也会把这个 module 扩展到整个网络架构层面。怎么个简单法呢？你比如说这个地方我就把这个特征图在这里再加一条边，到这里来，然后把这个特征图和这个特征图相加，再往后面传播——这不就是整个架构层面的吗？」

回到 Part 1 的坐标系：ResNet 的创新落在 **module 层**（提出 BasicBlock），网络本身只是把它堆 18/34/50/101/152 次；但同一思想可以升级到 architecture 层——在网络两个相距很远的位置之间拉一条长跳连。

**这条"module → architecture"的升级路径是本课隐藏的主线，也是最该抄走的一个思维工具**：模块级的好想法几乎总能试着往上提一层，U-Net、FPN、DenseNet 全是这条路走出来的（老师这里其实在给 01:34 的 DenseNet 铺路）。反过来也成立：架构级想法也能往下压成模块，SPPF 就是把多尺度融合压进一个模块。

你在 BEV 里天天同时用着这两层而不自知：**`SECOND` 里是 module 级残差（BasicBlock 内部），FPN neck 把高分辨率那一级跨越几十层送到低分辨率那一级去融合——那是 architecture 级跳连**，两者一起用不冲突。**动作**：打开 BEVFusion 配置，用两种颜色把这两类连接分别标出来。标完你会发现整个网络其实只有两种连线，图立刻就读得动了，比逐行读代码高效得多。

**【小结】** ①残差 = weight layer 组 + 一条直连边，跨几层、跨什么层都行，但严格定义要求跨的是带权重的层；②`H(x)=F(x)+x ⇒ F(x)=H(x)−x`，名字来自后一个式子，本质是让恒等映射变得容易表达；③ResNet 是 module 级创新，但同一思想可以升级到 architecture 级。

| 34 layers | **28.54** | **25.03** |

**这四个数把整节课的论点一次性钉死**，比任何曲线都清楚：plain 从 18 层加到 34 层错误率**不降反升**（27.94 → 28.54）；换成残差同样加深，从 27.88 掉到 25.03。而且 18 层时两者几乎打平（27.94 vs 27.88）——**说明残差在浅网络上根本没用，收益只在"深到优化不动"时才出现**。这句老师没说，但它是判断"要不要给某个网络加残差"的实操标准。

还有一个最关键的点，老师点到了但极容易被漏掉：**退化不是过拟合**。过拟合的标志是"训练误差低、测试误差高"，而 plain-56 是**训练误差就更高**，它连训练集都学不好。这属于"优化困难"而不是"泛化困难"，所以加正则、加数据、加增强全都救不了，只能改结构。**动作**：把这条做成你的诊断分支——看到深模型效果差，先看 **train loss**：train loss 也高 → 优化问题（改结构/改初始化/改 lr）；train loss 低而 val 差 → 泛化问题（加正则/加数据）。这一个分支能省掉你在 4060 上大量的无效试错。⚠ 另注：老师口述"这是 18 层这是 34 层"时指的是右边那张 ImageNet 图，左边两张是 CIFAR-10 的 20/56 层 plain 网络，按转写顺序读会串。

### 24 理论上不该退化：杀鸡用牛刀（01:05:04 – 01:07:25）

> **谢博**：「这个东西要这样子来理解：理论上来说是不可能的。什么意思呢？比如说我的函数假如说是一个二次方的，但你真正的是一个一次方的。我用了一个二次方的、非线性的，逻辑上来说理想情况下我一定可以拟合好你的，跟你用线性的效果是一模一样的……杀鸡用牛刀，只是说成本高一点，但是效果一定是——你说小刀和牛刀，那肯定牛刀。你还说效果干不过小的？那不可能的。」

他在 01:07:25 给了数学形式："如果真的是线性模型最好，我用二次的，理想情况下那个 x² 前面的 W 就会变成 0，它就退化成线性了。"即 `y = w₂x² + w₁x + b`，只要 `w₂` 能学成 0，二次模型就等价于线性。推广到网络：**更深的网络在假设空间上包含更浅的网络**（多出来的层学成恒等即可），所以更深模型的最优解不可能更差——这是数学事实，不是直觉。

**这个论证是全课逻辑链的枢纽，我认为它比残差本身更值得学**，因为它做的是**把问题重新定位**：既然理论上不该差，实际变差就一定是"优化器没找到那个解"而不是"那个解不存在"。问题从「表达能力不够」转到「可优化性不够」——一旦定位到可优化性，残差的设计动机（让恒等映射易于表达）就是唯一自然的答案。**没有这一步定位，残差只是一个凑出来的 trick。**

这套"理论上界 vs 实际可达"的分离你在调 BEV 时天天用得上：**模型容量够不够，和能不能训出来，是两个正交的问题**。mini 数据训不出效果不是模型太小（它的容量足够拟合整个 nuScenes），是数据和迭代不够——跟退化问题是同构的误判。**动作**：定一条排查纪律——动手改结构之前先问"这是表达能力问题还是优化/数据问题"；答不上来就先做过拟合小实验（10 个样本训到 loss 接近 0），能过拟合就说明容量没问题，别动结构。

### 25 三个现实因素：时间、算力、优化器（01:07:25 – 01:08:14）

> **谢博**：「但是为什么实际上我们又会遇到这个问题呢？很简单，就是因为我们在训练这个模型的过程中，你从来不会到理想的情况。首先你不会无穷无尽地训练它，时间无限长，不会；第二个你的资源不可能，算力不可能是无限的；第三你的优化器——梯度下降不可能是理想的。基于这三点的现实因素，才限制了我们当把模型增加的时候反而它的效果会出现退化。」

三个约束：训练时间有限、算力有限、优化器本身不完美（陷局部极小、梯度消失）。

**这里有一个老师没点破、但对你极其重要的推论：三条里只有第三条是残差直接对症的。**前两条残差解决不了——残差网络该训多久还是多久，显存还更多；第三条里最要命的那项就是梯度消失，正好引到 Part 6 那个 `+1`。**所以别指望"加了残差就能在小算力小数据上出好结果"**——残差买的是"更深的网络能训得动"，不是"同样预算出更好结果"。

这套"理想 vs 现实"的框架可直接迁移：分析任何"论文说好用但我跑不出来"的模块，先问表达能力不够（理论）还是训练条件不够（现实），后者再问时间/算力/优化器。**动作**：把这个两级问题写进实验记录模板，每次失败强制填一遍。你的训练计划里"无 AMP、只有 mini 数据、0.481s/iter"正好卡在①②上——**所以 mini 数据上 mAP 低，不能推出"这个改动不行"**，那和 plain-56 训练误差高就断言"深网络不行"是同一类误判。

### 26 残差真正的意义：帮你解决"层数选择问题"（01:08:14 – 01:10:37）

> **谢博**：「残差网络核心是要解决什么问题呢？从神经网络的设计角度来讲，核心是要解决层数的选择问题……我们设计神经网络的时候，除了卷积核多少个、核的大小，是不是还涉及到这个网络到底我要构建多少层？有了残差网络之后，这个还是个问题吗？不是个问题了。准确率不够的时候，我就很简单，我就堆……以前我们必须要找到一个非常适中的、balance 的数字：少了欠拟合，多了他退化了。」

ResNet 对"用网络的人"最实际的价值：**层数从一个需要精心权衡的超参数，变成了一个可以放心往上加的旋钮**。30 层只到 80%、老板要 90%？再堆 30 层。

老师自己加了限定："当然也不是那么简单，他在逻辑上解决这个问题。"**这个限定必要，我再补硬一点**：堆到几百层收益明显饱和（ResNet-1202 在 CIFAR 上反而不如 ResNet-110），显存和延迟则线性上涨。准确说法不是"层数不再重要"，而是"**层数从一个有风险的选择变成了受预算约束的选择**"——搜索空间从"找恰到好处的那个数"变成"在延迟/显存预算内尽量深"。前者是玄学，后者是工程问题。

这也解释了一个你早就见过但可能没想过的现象：**ResNet 有 18/34/50/101/152 一整个家族，而 VGG 只有 16 和 19 两个**。残差让"同一套设计缩放到不同深度"变成了几乎免费的事。YOLOv8 的 n/s/m/l/x 五个尺寸也是同一原理——`depth_multiple` 直接乘在每个 stage 的 block 数量上。**动作**：打开 `ultralytics/cfg/models/v8/yolov8.yaml`，找到 `depth_multiple` 和 backbone 里 `C2f` 后面那个重复次数参数，亲眼确认"改一个小数就能生成五个模型"这件事。**这是你在 4060 上做对比实验最省钱的一个旋钮**——同一套代码、同一套超参，只改缩放系数，就能做出一张有说服力的"深度 vs mAP vs 延迟"表，比你手改结构靠谱得多。

**【小结】** ①ResNet 之前 20 层是天花板，ResNet-152 把 ImageNet top-5 error 从 6.7% 干到 3.57%；②退化不是过拟合——更深的 plain 网络连**训练**误差都更高（Table 2：plain-18 27.94 → plain-34 28.54），是优化问题；③理论上更深不该更差（牛刀能退化成小刀），实际更差是因为时间/算力/优化器三个现实约束，其中只有第三条残差能治；④残差的工程价值是把"层数"从超参数变成了受预算约束的旋钮。

## Part 6 · 残差的两个角度：前向融合 + 反向 +1（01:10:00 – 01:37:04）

**【本段在讲什么】** 本课最有方法论价值的一段。先给出**可复用的分析模板**：任何模块都从前向、反向两个角度各问一遍；然后分别执行——前向得到"低级 + 高级特征的融合"，反向得到那个著名的 `+1`。中间他还顺手给了一个更大的模板："前向传播的所有改进最终都归结为更好地提取特征，而核心是特征融合"。最后落到代码：残差怎么写、为什么 block 里全是 3×3/s1/p1、add 与 cat 的门槛差别。

### 27 分析模板：任何模块都从前向/反向两个角度问（01:10:37 – 01:11:27）

> **谢博**：「他为什么能解决这个退化的问题呢？分析这种算法里面的问题，都可以从两个角度去分析：一个前向传播，一个反向传播。」

一句话的方法论：**前向问"它让特征变得更好了吗"，反向问"它让梯度更容易流动了吗"。**

**这是全课性价比最高的一句话**：它把"评价一个模块"从感性变成一张两格表，而且两格正交互补。老师在 01:23:25 说得很硬："这两者缺一不可。你前向传播确实能提取更好的特征，但如果从反向传播来讲，你这个网络梯度消失风险增大了，也很难堆叠到很深的层数。"换句话说，**一个模块只有两边都不亏，才可能被行业长期采用**。

拿它当场过一遍已知的东西，你会发现它真的能用：**BN**——前向让分布更易学、反向落在大梯度区，两边都赚；**膨胀卷积**——前向增大感受野、反向不改链长，前向赚反向中性；**残差**——前向融合浅深、反向 +1，两边都赚；**单纯加深网络**——前向表达力增强、反向链长增加梯度消失风险上升，**前向赚、反向亏**，所以才非要残差来对冲不可。

**动作**：把这张两格表做成你的模块阅读模板，以后每读一篇提新模块的论文（BiFPN、CA、Deformable Conv）强制填两格再决定要不要复现。填不出反向那格通常说明你还没读懂——而这正是最容易翻车的地方：很多前向看着漂亮的模块，在深网络里训不动。

### 28 浅层是低级特征，深层是高级特征（01:11:27 – 01:14:04）

> **谢博**：「特征有哪些特征呢？总体来说我们可以分为浅层特征和深层特征。一个网络前面的浅层的这些模块提取的是低级特征，越到后面越是高级特征。低级特征是什么呢？轮廓啦、纹理啦、颜色啦、明暗啦。高级特征也叫抽象特征、语义特征，比较抽象。比如说这上面这张图片上这个东西有两只耳朵——耳朵就是一个抽象的概念。你不能说椭圆形的那玩意，椭圆形的那玩意这叫低级特征、几何特征。」

对照关系：浅层/低级 = 几何特征（轮廓、纹理、颜色、明暗）；深层/高级 = 抽象/语义特征（"有两只耳朵"、"腿很短"）。【画面 01:13:36】他就在 `11-8 ResNet实战.pdf` 第 3 页那张 ResNet18 竖排图旁边，靠近 image 一端写"低"、靠近 fc 一端写"高级"。

老师给的判据是"**越贴近人类的认知，越是高级特征**"。**这个判据比"看层数深浅"本质得多**：它解释了为什么高级特征不可能靠单层算出来——"腿短"必须先有"腿"（中级）再有"腿与身体的比例"（更高级），它是被**层层组合**出来的，层数只是这个组合过程的副产品。

这条跟你手上的东西完全对齐：YOLO 的 P2 分辨率高、语义弱，擅长小目标定位；P5 分辨率低、语义强，擅长大目标分类。**你简历上那条"加 P2 检测头提升小目标"，理论依据就是这张表**——小目标在深层已被下采样成几个像素，语义再强也定位不了，必须回浅层拿几何信息。**动作**：把 P2 那道题的标准答法定成"小目标的困难是定位而非分类，所以要把检测头下放到几何特征还在的浅层"，而不是含糊的"P2 分辨率高所以对小目标好"——前者说明你知道为什么。

### 29 判断是猫，低级和高级特征都要；你画我猜的传递损失（01:14:04 – 01:19:27）

> **谢博**：「理想的情况来说，我们要综合判断这个图片上是一只猫，我们不仅需要高级特征，也需要低级特征。那如果我们没有这个残差边，这个低级特征就传不过来。为什么？因为每个特征往前面传的过程都要被加工一次……你有没有记得有一个综艺游戏，我画你猜，然后传递，结果本来是一只包，到了他那里变成一只火箭了。他每次一传递特征就会出现损失，最后出现偏差。」

两层意思：分类需要多尺度证据（"四条腿很短"里"很短"是高级的、"矩形高 10 像素"是低级的，缺一不可）；没有直连边，低级特征传不到深层，因为每过一层卷积就被重新加工一次，加工 30 次后原始信息已面目全非。

**"你画我猜"这个类比精确得惊人**：每个玩家 = 一层网络，画 = 特征提取，传递 = 前向传播，最后变成火箭 = 特征漂移；而残差边就是**允许你直接看第一个人的原图**。老师还给了自己的版本（01:15:32）："同学转述我的话，一加工就偏了，所以我说'我用什么词你就用什么词'——这就是让他走这条直连边。"

他在 01:19:27 把这件事升华到了学习方法上："**你们学习也要建立残差边**，学完今天的，上周的也拿过来融合一下……走到最后前面学的梯度下降都忘记了。"听着像鸡汤，**但对你的处境是真成立的**：33 级阶梯的长战线，最容易出的问题就是学到 CNN 时把回归忘光。**动作**：落成机制——每写一节精讲，强制回指至少两处更早的内容（本课就一直在回指上节课的 Conv2d 铁律和更早的梯度下降）。

### 30 通用模板：前向传播的改进都归结为特征融合（01:19:27 – 01:22:39）

> **谢博**：「这里面再给你个通用的模板：任何问题从前向传播来讲，都是为了更好地提取特征。更好地提取特征，核心是什么呢？核心就是特征融合。那特征融合又会有很多维度：比如说浅层加深层；还有什么呢？还有尺度、多尺度……比如说 GoogLeNet 他就是多尺度，我用个 5 的核和 3 的核，提取的特征融合。我范围大一点看看这张图片，范围小一点看看这张图片，感受一下颗粒度不一样……而且这个特征融合可以在模块内部，也可以在网络架构。」

他给的分类是三个维度：**融合什么**（浅↔深，即低级↔高级；多尺度，即不同大小的核或不同分辨率的特征图）；**在哪融合**（module 内部如 Inception/BasicBlock，architecture 层面如 FPN/DenseNet/U-Net）；**怎么融合**（add 如残差，concat 如 Inception/DenseNet）。

老师给这个模板的定位很妙："任何一个网络、任何一个模块，他提出来的理由都是为了更好地提取特征……这就活了，你可以胡说八道了，为什么？方向没错。"**这句听着像玩笑，说的却是件严肃事**：面对没见过的新模块能不能立刻说出像样的东西，取决于你手上有没有这种"框架级默认答案"——有了它，你至少不会哑口无言，而且大概率方向是对的。

拿它套你熟悉的东西，一个不漏：**BiFPN** = 多尺度 + architecture 层 + 加权融合；**CA 注意力** = 通道×空间两个维度的重加权（本质也是融合）；**SPPF** = 多个池化核的多尺度融合；**BEVFusion 融合模块** = 跨模态融合，还是"两个 team 中期同步"。老师 01:21:52 还补了细分维度：小目标、密集目标、遮挡目标各要提什么特征——**那就是你做 BEV 检测的实际难点清单**。**动作**：把简历上那四个关键词（P2、BiFPN、CA、GIoU）各填一遍"融合什么/在哪融合/怎么融合"，填不出的那个就是薄弱点，优先补。

### 31 反向角度：∂L/∂x = ∂L/∂h · (∂h/∂x + 1)（01:22:39 – 01:26:34）

> **谢博**：「第二个是反向传播。反向传播理由就是什么？所有优化他核心理由就一个：降低梯度消失的风险……我们是不是这样说的呀，h(x) = F(x) + x。那梯度传递到这里来的时候，假如说没有这个残差边，因为输入是 x 嘛，所以 ∂L/∂x 应该等于 ∂L/∂h 乘以 ∂h/∂x。这些他都是一个很小的数……如果这里一百层就一百项相乘。但是有了这个残差边之后，一切就变得不一样了：∂L/∂x 就变成 ∂L/∂h 乘以（∂h/∂x 加 1）。」

【画面 01:26:15】他在 ResNet18 那页幻灯片的空白处手写了完整推导：

```
h(x) = F(x) + X
无残差：  ∂L/∂x = ∂L/∂h × ∂h/∂x
有残差：  ∂L/∂x = ∂L/∂h × ( ∂h/∂x + 1 )
```

数学上一步就能得到：`h = F(x) + x ⇒ ∂h/∂x = ∂F/∂x + 1`，代入链式法则即可。**那个 1 就是直连边贡献的常数导数**（`d(x)/dx = 1`）。

**这是全课最该背下来的式子**，它的价值在于它是"结构上几乎免费、效果上决定性"这句话的唯一证明。为什么加法这么灵？因为**加法在反向传播时把梯度原样复制到两条支路**——直连边上梯度永远是 1 倍，不管前面隔了多少层。零参数、零计算量，买到一条无损的梯度高速路。

⚠ 转写里"梯度"被听成 T度 / 剃度 / T2消失 / 推销的风险，全篇 20 多处，这一段只能靠画面。**动作**：把这三行手写推导抄进复习卡，练到能在纸上五秒默写。被问"残差为什么防梯度消失"时，**写出这两行、用笔点着那个 +1**，比说一百句"缓解梯度消失"都有说服力。

### 32 10⁻⁶ 加个 1：把"必然"降成"概率"（01:26:34 – 01:28:55）

> **谢博**：「假如说他原来是 10 的负 6 次方，已经是个很小的数了，现在一加 1，那这一项是不是就又大起来了呀？意味着他是不是就有概率传得更远了？……原来 ∂L/∂x 是很多项相乘，可能有 100 项，这里面每个项，如果是 10 的负 3 次方，万一中间有三个这样的数，他不就变 10 的负 9 次方了吗？但是我们现在不一样了，好多项里面有加 1……这样子的话就可以——不是说一定会防，一定不会，是降低概率。」

数量级演算很直观：`10⁻³ × 10⁻³ × 10⁻³ = 10⁻⁹`，三项就崩了；而 `(10⁻⁶ + 1) ≈ 1`，连乘 100 项仍是 1 量级。

**关键全在他最后那句限定："不是一定会防止，是降低概率"——这句是专业和半吊子的分界线。**残差不能保证梯度不消失（∂h/∂x 若接近 −1，加 1 后反而更小），它只是让每一项从"必然远小于 1"变成"大概率接近 1"。很多人背成"残差解决了梯度消失"，一被追问"那为什么还要 BN、还要好的初始化、还要梯度裁剪"就哑了——真解决了这些就该退休了。**正确表述是"显著降低梯度消失的概率"，一个词都不能多。**

老师在 01:28:11 顺手给了 ResNet 部分的考纲，值得原样记下："残差网络你要理解三个问题：第一个他怎么做的（严格意义与广义）；第二个为什么他能解决网络退化的问题；第三个从设计角度他给我们的启示是什么——就是层数。"**动作**：写成三行，每行一句话作答（第 17/18 卡答第一问、24+31 卡答第二问、26 卡答第三问）。这三行就是你面试前最后五分钟要看的东西。

### 33 残差的代码写法：x = x + C2(C1(x))（01:28:55 – 01:30:28）

> **谢博**：「残差网络代码怎么写呢？你比如这个叫 C1，这叫 C2，你的 forward 里面要这样写：x1 = C1(x)，然后 x2 = C2(x1)，然后 x 要等于什么呢？x 加上 x2。」

【画面】他在 `ResNet实战.pdf` 第 2 页 "Res Block" 那页旁边手写 `x₁ = C₁(x) / x₂ = C₂(x₁) / x = x + x₂`；幻灯片上是三个串联的残差块，每块 `x → Convolution layer → ReLU → Convolution layer → F(x) → ⊕`，旁路标 `x: Identity`。

工程上完整的版本比老师的板书多两样东西，**他没写，但你写代码时必须有**：

```python
def forward(self, x):
    out = self.relu(self.bn1(self.c1(x)))   # c1/c2 都是 Conv2d(c, c, 3, 1, 1)
    out = self.bn2(self.c2(out))
    return self.relu(out + x)               # ← 注意：第二个 ReLU 在相加之后
```

一是每个卷积后跟 BN（下一 Part 的内容，顺序 Conv→BN→ReLU）；二是**第二个 ReLU 必须在相加之后**。第二点尤其容易写错且不报错：写成 `out = relu(bn2(c2(out))); return out + x`，残差分支输出被强制非负，`F(x)` 再也表达不了"负的差额"，块的表达能力直接砍半。**这是本卡最该带走的判断。**

**动作**：把这个 7 行 BasicBlock 加进你的 MNIST 默写模板。注意它兑现了第 10 卡那条纪律——**原始 `x` 全程不被覆盖，工作变量叫 `out`**（`resnet.py` 和 `SECOND` 里的 `identity = x` 更保险，直接另存一份）。能默写出来，第 02 卡说的"从 layer 堆叠升级到 module 堆叠"就真的完成了。

### 34 add 要求形状全等：为什么 block 里全是 3×3 / s=1 / p=1（01:30:28 – 01:33:00）

> **谢博**：「这个 x 和这个 F(x) 结果是要加起来，加起来就意味着两个 tensor 要相加，这两个形状要一样才好加。形状不一样那一加就错了。比如说他是 3×5×6，然后他是 4×7×8，能加吗？不行……所以在设计残差模块的时候，要尽量保证他出来的形状不变。怎么样做到不变？最简单的常规操作就是 3×3 的卷积、stride 1、padding 1。核的数量好配吗？通道数好配吗？这就是为什么你看到这个网络里面都是 3×3。」

推理链三步：`Conv2d(c, c, 3, s=1, p=1)` 的尺寸公式 `(H + 2·1 − 3)/1 + 1 = H`，H、W 不变；`out_channels = in_channels`，C 不变；三维全不变，所以能 add。

**这一条把"所有 ResNet 都是 3×3"从"经验"提升成了"必然"，是本课我最欣赏的一个论证。**再推一步（老师没推）：3×3 + s1 + p1 是**同时满足"有空间感受野增长 + 尺寸不变 + 参数量可控"的最小配置**——1×1 没有空间感受野，5×5 要 p=2 且参数量翻两倍多，所以它几乎是唯一解。以后你自己设计模块，只要里面有 add，就该条件反射地问"两条支路形状对得上吗"。

⚠ 老师随后自己打了个补丁（01:32:57）："你不要一回又拿我的话来说，卷积不改变 size 就看情况，我只是说通用的原则。你如果完全这样，那你就属于过拟合了。"这个补丁必须接住：**当 block 需要下采样时（stride=2、通道翻倍），直连边上必须插一个 `1×1 Conv(stride=2)` 来对齐形状**。【画面】ResNet18 那张图上的**虚线箭头**就是这种 projection shortcut，实线才是纯 identity——图上每次通道从 64→128、128→256、256→512 的那一跳都是虚线，其余都是实线。**动作**：拿这张图数一遍虚线有几条（三条），再去 SECOND 源码里数 `downsample is not None` 成立几次，两个数对上，你就真的读懂这张图了。

### 35 add / cat / 矩阵乘的门槛排序；DenseNet 与 CBR 顺序（01:33:00 – 01:37:12）

> **谢博**：「现在有两个 tensor，x1、x2 要做 cat 操作，有什么要求？这个要求比 add 高还是低？低。这个操作只要求 x1、x2 它的 H、W 一样就可以了。当然 cat 也可以指定哪个维度去 cat，一般我们是从 C 这个维度去 cat。所以加的要求是最高的，cat 的要求又低了一点，然后矩阵相乘要求又很高……最高的是矩阵乘，然后是加。」

三种融合的门槛从高到低：**矩阵乘** `A@B` 要求 `A.shape[-1] == B.shape[-2]`、输出形状改变；**add** 要求 N、C、H、W 全相同、输出形状不变；**cat** 只要求除拼接维外全相同（即 N、H、W 相同）、输出 C 相加。

**这个排序看着琐碎，但它是一张真正能用的调试速查表**：遇到 shape mismatch 报错时，先看是哪种操作，立刻就知道该去对齐哪几个维度。而且它还解释了一件事——01:34:35 起老师引出 **DenseNet**（"dense 就是很密的意思"，【画面】幻灯片上一串彩色特征图，每层弧线连到后面所有层，标注 "Element-wise addition" 和 "Channel-wise concatenation"）：**DenseNet 用的是 cat 不是 add，正因为 cat 门槛低（不要求通道数相同），"每层连所有后续层"才可行**。如果它非要用 add，所有层的通道数都得锁死成同一个值，这个架构根本立不起来。**门槛决定了架构的可能性**——这是我从这一段里读出的最有意思的一条。

紧接着 01:36:09 他抛了个选择题：`Conv → ReLU → BN` 还是 `Conv → BN → ReLU`？**答案是后者，所以叫 CBR**：先线性变换，再 Normalize，最后过激活。这不是约定俗成，理由是下一 Part 的主题——**BN 的作用就是把数压到激活函数梯度大的区域，放在激活之后就完全失去意义**。**动作**：把这三行门槛表抄到你的调试备忘里（"报 shape 错先看操作类型"），然后在你的 BasicBlock 默写模板里检查一遍 BN 的位置是不是在 ReLU 之前——这两件事各花一分钟，但都是高频踩坑点。

**【小结】** ①分析模板：任何模块都从前向（特征融合）与反向（梯度消失）两个角度问一遍，两边都不亏才值得用；②前向上残差让低级特征绕过层层加工直达深层；③反向上 `∂L/∂x = ∂L/∂h·(∂h/∂x + 1)`，那个 +1 把梯度消失从必然降成概率（是降概率，不是解决）；④add 要求形状全等，所以 block 里全是 3×3/s1/p1，需要下采样时直连边上加 1×1 卷积；⑤门槛排序：矩阵乘 > add > cat，门槛决定架构的可能性。

### 36 反向角度：压回 0 附近，激活函数才有梯度（01:37:12 – 01:39:48）

> **谢博**：「为什么要这样做呢？防止梯度消失。如果我把这个 ReLU 换成 Sigmoid 你就好理解了……激活函数我们保证的是 0 附近左右的梯度，你无法去保证在整个实数域它都有好的梯度，这种函数不好找。所以它要在做完线性变换之后压缩，因为你做完线性变换这个数据的取值范围是负无穷到正无穷。然后你把它压缩到 0 附近，再去进激活函数，这个时候对激活函数求导数的时候，它才能够求出一个比较大的值。」

逻辑链干净得可以直接背：线性变换（Conv/FC）的输出范围是 (−∞,+∞) → 直接喂给激活函数大概率落在饱和区 → 导数≈0 → 梯度消失。**Normalize 就是插在中间、把数搬回 0 附近的那个操作。**配个数字更硬：Sigmoid 的导数 `σ'(z)=σ(z)(1−σ(z))` 在 z=0 处最大 **0.25**，`|z|>4` 时已小于 **0.018**——**输入落在哪个区间，直接决定这一层能回传多少梯度**。老师用"这种函数不好找"解释为什么不干脆造一个全域梯度都好的激活函数，这个说法是对的：真造出来它就不是非线性的了。

**这一卡真正的落点是它锁死了 CBR 的顺序**：BN 必须在 Conv 之后、激活之前，因为它服务的对象就是激活函数。⚠ 转写里 Normalize 被听成 novalize / 浪漫那一只 / loin，Sigmoid 听成 SSIGMOD。**动作**：以后在任何代码里看到 `BatchNorm` 出现在激活函数之后，别当成"新写法"，去确认一遍是不是写错了——五秒钟的检查，能抓到真 bug。

### 38 前向角度：神经网络是"分布 → 分布"的映射（01:45:00 – 01:50:33）

> **谢博**：「我们要知道整个神经网络，比如说这里有个 x，这里出来 y。你熟悉数字识别，是不是 10 个数？里面是概率，加起来等于 1。那如果画成直方图呢？这 10 个数是不是就变成一个分布了呀……我们常规的理解是说从一个数映射到另外一个数，但实际上你不能这么简单地理解，他应该是——神经网络是从一个分布映射到另外一个分布。你要这样理解，你就能理解为什么 Normalize 能够强化前向传播。」

他两头都画了直方图。输出端：10 类的概率向量 `[0.1, 0.7, …]` 就是一个分布——判断为"1"只要求**峰值落在 1 这个位置**，并不要求输出是 `[0,1,0,0,…]`；峰陡说明自信、峰平说明犹豫，但**两者属于同一分布类型**。输入端：`1×32×32 = 1024` 个像素值（0~255）也是一个分布。所以网络干的不是"把一个数变成另一个数"，而是**把输入侧 1024 点的分布加工成输出侧 10 点的分布**。

**这个视角一旦建立，好几件你以前当独立知识点背的东西会同时通掉**，这是本卡的真正价值：交叉熵为什么被定义成两个分布之间的距离？为什么同一类图片"分布一定是类似的"（01:52:08）？为什么标签平滑有用？——**都因为网络拟合的对象是分布，不是点**。老师只说了 Normalize 那一条，其余是这个视角自然带出来的。

对你最直接的一条：**CenterPoint 头输出的 heatmap 就是一张空间概率分布，训练时的 GT 是用高斯核铺出来的分布而不是单个像素点**。你之前疑惑过"为什么 GT 要画成一个高斯圆而不是打一个点"，答案就是这一句——网络学的是分布对分布，你给它一个只有单点为 1 的目标，等于要求它拟合一个几乎不可能的极端分布，梯度会极度稀疏。**动作**：去 mmdet3d 的 CenterPoint 头里找 `draw_heatmap_gaussian` 那个函数，看一眼 `radius` 是怎么按目标尺寸算出来的——看完你就同时理解了"为什么是分布"和"为什么大目标的高斯圆更大"。

### 39 归一化后分布好抓规律 + 为什么每层都要做（01:50:33 – 01:53:53）

> **谢博**：「为什么我们做完 Normalize 之后这个特征提取就会更加简单呢？你做完 Normalize 之后，你这个直方图是不是就 0 到 1 之间了呀？0 到 1 之间它的分布是不是很好画？但如果说你里面的数是负无穷到正无穷，那它的这个分布是不是很凌乱、很不容易看出来？……神经网络它同样很烧大脑的呀，当然它烧的是 GPU。GPU 跑烧掉了他也没发现这个分布是个什么鬼分布，最高点在哪里、有几个最高点、它的趋势是怎么样……为什么每一层都要做？因为每一层你的激活函数都有可能会消失。不是说做一次就够了。」

前向侧的收益说白了：把数据压到有限区间后，**分布的形状（峰在哪、几个峰、趋势如何）变得容易被后续层"看见"**；值域若是 (−∞,+∞)，同样的形状被拉得极散，网络要花更多参数和迭代才能抓住。

**最后那句"为什么每一层都要做"是本卡的关键，它回答的是一个几乎人人会问、却很少有材料正面回答的问题。**两条理由：归一化效果会被后续线性变换重新破坏（乘上 W 之后值域又散开），且每一层都有自己的激活函数和饱和风险。所以 BN 不是"入口处做一次的预处理"，而是**必须跟着每一层走的常驻算子**——这就是 `Conv-BN-ReLU` 三件套被无脑重复几十次的全部理由。

**这里有一个新手最容易混的坑，我必须替你点破**：你的 MNIST 模板里如果在 `transforms` 里写了 `Normalize((0.1307,), (0.3081,))`，那只是**在输入端做了一次**，用的还是全数据集算出来的固定常数；网络内部需要的是 `nn.BatchNorm2d`，它的 μ、σ 是随每个 batch 变化的、可学习的。两者名字几乎一样，作用位置和性质完全不同。**动作**：现在就去你的 MNIST 模板里确认这两处**同时存在**——`transforms.Normalize` 在 DataLoader 那边，`nn.BatchNorm2d` 在每个 Conv 后面。缺哪个补哪个，这是一分钟的活。

### 40 具体操作两步：算均值、算标准差（01:54:45 – 01:59:28）

> **谢博**：「Normalize 是不是个操作？跟卷积、激活函数、矩阵相乘、全连接一样，都是个操作。那这个操作它的对象是什么？对象就是个 tensor，是一堆数。你别说我拿个 1 来 Normalize，有意义吗？……长什么样才叫规范呢？要符合正态分布，均值是 0、标准差是 1。比如说 X 是 6、1、8，这三个数规不规范？不规范。要有正有负才叫规范……先求均值，三个数加起来除以 3；然后再求方差，方差开根号就是标准差。」

【画面 01:59:43 缩略图第 5 页】`3-什么是规范化Normalization.pptx`「第 1 步：求均值，标准差」页：

```
μ = (1/n) Σ Xᵢ = (6 + 1 + 8)/3 = 5
σ = √[ (1/n) Σ (Xᵢ − μ)² ] = √[ ((6−5)² + (1−5)² + (8−5)²)/3 ] = √(26/3) ≈ 3
```

**这一段真正被点破的是两个前提，第一个是整个 Part 8 的地基**：①**Normalize 的对象必须是"一堆数"**——单个数没有均值方差可言。听着像废话，但正因为必须是"一堆"，才产生了"到底是哪一堆"这个问题，而 BN/LN/IN/GN 的唯一区别就是它。记牢这句，下一 Part 省你半小时。②规范的标准是"均值 0、标准差 1"，所以规范化后的数**必然有正有负**。

他那个方差的生活化解释（01:57:54）值得留着用："贫富不均就叫方差大，方差小就叫共同富裕……让他分一半给你，他 5.1 亿你 4.9 亿——这叫方差小。"⚠ 但他口语多次说"除以方差"，PPT 写的是**除以标准差 σ**，面试别照搬。**动作**：把 `{6,1,8} → μ=5, σ=3` 背下来当口算测试用例，下一卡就用得上。

### 41 x' = (x−μ)/σ：三个数的实算（01:59:28 – 02:00:22）

> **谢博**：「怎么做规范化呢？x 减去均值除以标准差。假如说你这里有一万个数，那一万个数也这样子：先求均值，再求标准差，然后每个数减去它的均值、除以它的标准差。这就是规范化了。看到没有，是不是有正有负啊？」

【画面 01:59:43】「第 2 步：规范化」页，公式框被绿笔圈着 `X'ᵢ = (Xᵢ − μ) / σ`，下面三行实算：

```
X'₁ = (6 − 5)/3 =  0.33
X'₂ = (1 − 5)/3 = −1.33
X'₃ = (8 − 5)/3 =  1
```

结果 `{0.33, −1.33, 1}` 果然有正有负、落在 −1~1。回头看原始的 `{6, 1, 8}`：全是正数、集中在 1~8，**整整齐齐落在 Sigmoid 的饱和区里**——这三个数把第 36 卡那条逻辑链具象化了。

**这里有一条老师完全没提、但对你理解 BN 至关重要的性质：这个操作是逐元素的，而且是可微的**（μ、σ 都是输入的函数），所以它能整个塞进反向传播里跟着一起求导。这一点跟"预处理阶段的归一化"有根本区别：预处理时 μ、σ 是提前算好的常数，BN 里的 μ、σ 是随每个 batch 现算的变量，反向传播时要穿过它们。**这就是为什么 BN 的反向公式比你想象的复杂，也是为什么 BN 在小 batch 下不稳定**——第 46 卡会用到这个判断。

**动作**：`[6,1,8] → [0.33,−1.33,1]` 是你验证任何 Normalize 实现的最小测试用例。你以后写 BEV 的自定义 norm 层、或者怀疑某个第三方实现有问题时，喂进去这三个数看输出，五秒钟就能定位。**注意一个坑**：PyTorch 的 `nn.BatchNorm` 默认用**有偏方差**（除以 n）做归一化、但用**无偏方差**（除以 n−1）更新 running_var，所以你手算对照时要用除以 n 的那版，否则会差一点点，别以为是 bug。

### 42 γ 与 β：不知道该设多少，就当 W 来训练（02:00:22 – 02:04:16）

> **谢博**：「实际上我们也可能会出现——就是 Normalize 但不是标准的 Normalize，这个就是对整个分布进行了缩放和平移……我们只要保证它符合 normal 的分布，它的均值点和它的方差我们可以不一样，就是非标准的。它只要是 normal 就可以了……这两个参数具体设置多少呢？我们可以把它当作 W 一样去训练。」

【画面 01:59:43 缩略图第 7 页】「缩放和平移」页，副标题"为了好训练……再来点小 trick"，公式框 `X_i^norm = γ * X'_i + β`，页脚一行老师没念的注释：「γ：缩放因子。β：偏置因子。**这两个参数和神经网络的权重一样，参与训练，由反向传播自动更新，并不需要人为指定。**」

为什么要多此一举？把所有层输出强行按成标准正态本身是很粗暴的约束，可能反而限制表达能力。γ、β 让网络**自己决定**这一层最终分布该有多宽、中心在哪；标准正态只是 γ=1、β=0 的特例。

**但这一卡真正值钱的不是 γβ，而是老师 02:02:39 顺口给出的那条通用方法论**："本来这个应该像超参数一样去指定它，像学习率一样。但是如果你不知道指定多少为好的时候，这里就告诉你一个思路——**把它看作 W 一样去训练**。"这是全课第三个可迁移的思维工具（前两个是 architecture/module 坐标系、前向/反向两格表），适用面极广：Swin 的相对位置偏置、可变形卷积的 offset、DFL 的分布参数、BiFPN 的融合权重——**全是"不知道设多少，那就学"**。

**动作**：两件事。一是在 PyTorch 里确认一下——`nn.BatchNorm2d(16)` 的 `weight`（就是 γ，初始化为全 1）和 `bias`（就是 β，初始化为全 0）确实出现在 `model.parameters()` 里，跟着优化器一起更新；顺手看一眼 `running_mean`/`running_var` 是 buffer 而不是 parameter，这个区分第 49 卡要用。二是把"不知道设多少就当参数学"记成一句话，下次你想给 BiFPN 的三路输入配融合权重时，别去网格搜索，直接学。⚠ 老师口误说"γ 和 β 都是偏置偏移"，实际 **γ 是缩放、β 才是偏移**。

**【小结】** ①反向角度：Normalize 把数压回 0 附近，激活函数才有像样的梯度，所以顺序必须是 Conv → BN → ReLU；②前向角度：神经网络本质是分布到分布的映射，规整的分布更容易被抓住规律，且**每层都要做**（后续线性变换会重新破坏它）；③操作三步半：算 μ、算 σ、`x'=(x−μ)/σ`、再可选地 `γ·x'+β`；④γ、β 不用人指定，当 W 一样训练——这是一个可迁移到任何"不知道设多少"场景的通用思路。

### 44 全局 Normalize：131072 个数一起算，且形状不变（02:09:04 – 02:12:58）

> **谢博**：「Normalize 这里面总共有多少个数啊？是不是 8 乘 16 乘 32 乘 32？如果我们做 Normalize 有好几种手段呢，什么 BN、LN、IN——如果不区分这个，那怎么做啊？就是全局 Normalize……先算这么多个数的均值，再算这么多个数的标准差，然后每个数再算自己 Normalize 之后对应的值。现在问你，做完 Normalize 之后它的形状会不会改变？……不会。形状会不会变、位置会不会变？都不会。原来这个位置是什么数，他还在这个位置，只是值不一样了。」

全局 Normalize 就是 `8×16×32×32 = 131,072` 个数一起算出**一个** μ、**一个** σ，然后每个数都做 `(x−μ)/σ`。两条结论：不加修饰词的 "Normalize" = 所有数一起算；**它是逐元素、保形状、保位置的操作**——跟 ReLU 一样只改值不改结构。

**"形状不变"这一点老师特意先钉死，这个教学顺序很聪明**：下一卡讲"BN 分成 16 组"时，学生几乎必然以为分组会改变张量结构。先说清"分组只影响统计量跟谁一起算，不影响输出张量的排布"，后面就不会乱。

这条还顺手解释了两件工程上的事，值得你收着：一是**BN 可以随便插在网络任何位置而不用改后面的层**，因为它 shape-preserving；二是**ONNX 导出后 TensorRT 能把 BN 折进前面的 Conv**（BN folding），前提正是它逐元素的线性性质——`γ(wx+b−μ)/σ + β` 可以合并成一个新的 `w'x + b'`，推理时一次卷积就算完，白赚一层的速度。**动作**：以后在 BEV 上做部署优化，看到 profiling 里 BN 层不见了别慌，那是被折进 Conv 了，正常且期望。

### 45 BN：按 C 切成 16 组（02:12:58 – 02:16:10）

> **谢博**：「我们做的 Normalize 叫 BN。BN 是什么意思？前面是不是加了个修饰词，这个 B 代表 batch，叫 batch normalize。那 batch normalize 是不是说把这个 batch 的数据放在一起 normalize 呢？是也不是……区别在于选的数据不一样，就是你跟谁在一起做 normalize。你看这个图：他把同一通道的数据拿出来放在一起做一次……如果按照 BN 的做法，是不是要把它分成 16 组啊？这个不就开窍了吗？」

【画面 02:18:44 右上】他把 `11-6 BatchNorm.pdf` 第 4 页拖成浮窗压在 IDE 上：四个立方体并排 **Batch / Layer / Instance / Group Norm**，三个轴标 `H,W`（纵）、`C`（左下）、`N`（右下），蓝色高亮就是"一起算统计量的那一组"——BN 沿 C 取薄片、在 N 和 H,W 铺满；LN 沿 N 取一片；IN 只剩一根柱子；GN 是几个相邻 C 合成一块。

对 `(8,16,32,32)`：BN 按 `C=16` 分成 **16 组**，每组含 `8×32×32 = 8192` 个数，算出 **16 对 (μ, σ)**。

**这一卡最实用的产出，是它一次性解掉了一个人人踩过的困惑：`nn.BatchNorm2d(num_features)` 里那个参数为什么必须等于通道数、而不是 batch size？**明明它叫 Batch Norm。答案就在这：那个参数是**组数**，而 BN 按通道分组，所以组数 = C。老师没直说，但它从"分成 16 组"直接推得出来，而且这是新手写模型第一个会报错的地方。顺带算清参数：`nn.BatchNorm2d(16)` 是 `16(γ)+16(β)` 两个可学习参数，加 `16(running_mean)+16(running_var)` 两个 buffer。**动作**：在你的 BasicBlock 模板里检查每个 `BatchNorm2d(...)` 的参数是不是等于紧邻上方 `Conv2d` 的 `out_channels`——不等就一定是错的，这条规则没有例外。

### 46 高考按省录取：跟谁一起排名决定你的命运（02:16:10 – 02:18:33）

> **谢博**：「但是你想想，这个跟你一起做 normalize 是不一样啊，为什么？因为他均值不一样啊。我跟比如说小杨是个大富豪，我跟他一起做 normalize，完蛋了，我就变成 0.00 几了。假如说我找一个比我还没钱的，那我一做 normalize 我就变成 1 了呀……就像你高考一样录取。我说高考，我们是不是按省去排名去录取啊？假如说清华去 1000 个人，我全国排名我就完蛋了，那不是西藏啊、贵州啊那不是 100 年出不了一个？我们是每个省给他设定比如说 200 个、300 个——这不就是分组做 normalize 吗？」

两个类比说的是同一件事：`(x−μ)/σ` 的结果**完全取决于 μ、σ 用哪一堆数算**。同一个 x，跟富人一组变成极小的负数，跟穷人一组变成正数。

**这一卡是全课比喻质量的顶点，因为它精确击中了 BN/LN/IN/GN 之争的本质：分组方式定义了"什么算正常"。**BN 按通道分组，等于说"同一特征通道内部互相比较"——某通道整体偏大是它的固有量纲（比如它专门检测亮度），归一化掉不影响判别；而所有通道一起算（全局），通道间的相对强弱就被抹平了，那才是真丢信息。**这个视角比记住四个立方体的形状有用一百倍。**

反过来它也解释了 BN 最著名的缺陷：统计量跨样本，所以 **batch size 太小时 μ、σ 抖得厉害**（8 个样本算出来的均值，和另外 8 个样本算出来的，可能差很多）。**这条对你是有直接后果的**：3D 检测因为体素/BEV 特征图巨大，单卡 batch 常常只有 1~2，BN 在这种条件下基本失效——这就是这类任务常改用 GN 或 SyncBN 的原因。**动作**：你在 BEVFusion 配置里看到 `norm_cfg=dict(type='BN')` 时，先看一眼实际的 `samples_per_gpu`；如果是 1 或 2，而你又打算多卡训练，那就该换成 `SyncBN`（跨卡凑够样本），理由就在"跟谁一起算"这五个字。

### 47 一组到底是哪些数：x[:, 0, :, :] 的调试器实证（02:18:33 – 02:22:45）

> **谢博**：「那就分成了 16 组。比如说其中一组变成什么样子的呢？第一个是不是全部取啊？第二个呢是 0，第三个是不是全部取？第四个是全部取。总共多少个数啊？是不是 8×32×32？这么多个数作为一组，他们自己做 normalize……那为什么这个叫 batch normalize 呢？因为这个组里面是不是有 8 个样本呢？就是第一个样本也要派点代表来参加，第二个样本也要派点代表来参加。」

【画面 02:18:44】PyCharm 的 **Evaluate** 对话框里输入 `x[:,0,:,:]`，Result 展开显示 `result = {Tensor: (8, 32, 32)}`、`data = {Tensor: (8, 32, 32)}`、`T = {Tensor: (32, 32, 8)}`、`grad_fn = <SliceBackward0>`、`is_cpu = True`。**这是本课最硬的一张画面证据**——一个抽象的"一组"，被一行切片打成了具体形状。

老师点破了 "Batch" 这个名字的真正来源，**他强调了三遍，完全值得**：BN 里的 batch **不是"整个 batch 一起算"**（那是全局），而是"**每一组里都包含 batch 中所有样本的一部分数据**"——每个样本派它的第 i 个通道来参加。"不是所有数据，如果是所有数据不就又变成全局了吗？"

**而这个"派代表"的机制，正是 BN 全部麻烦的根源，这条推论老师没说，但它是第 49 卡的伏笔**：一组里混了不同样本的数据，意味着**样本 A 的归一化结果依赖于同 batch 的样本 B**。训练时这是好事（等于给每个样本注入了噪声，是 BN 正则效果的来源）；推理时这是绝对不可接受的（同一张图跟不同的图组 batch，输出会不一样）。**动作**：在你自己那份 SimpleCNN 里把 Evaluate 这一步亲手做一遍，然后再多验一句 `x[:,0,:,:].mean()` 是否等于 `x.mean(dim=(0,2,3))[0]`——两个数相等，你就彻底拥有"BN 到底在跟谁算"这件事了。

### 48 LN 按 N 分 8 组；IN / GN 只是换个切法（02:22:45 – 02:25:22）

> **谢博**：「那我问你这个 LN 明白了吗？LN 是不是按 N 来分呢？N 来分，那他就分成 8 组嘛。那组 1 里面的数据只有来自哪个样本的啊？只有第 1 个样本的。那就是样本和样本之间他的数据是不会相互影响啊，但是 BN 是不是就有相互影响？所以他叫 batch normalize。所以 layer 他是这个样本内部自己做 normalize……那 instance 是不是就不用说了呀？group normal 还要说吗？如果你需要我说，那就说明你连这个 Python 最基本的切片都没学好。」

对 `(8,16,32,32)` 的四种切法，一张表说完：

| 方法 | 组数 | 一组是 | 每组元素数 | 统计量对数 |
|---|---|---|---|---|
| 全局 | 1 | `x[:,:,:,:]` | 131072 | 1 |
| **BN** | 16 | `x[:, i, :, :]` | 8×32×32 = 8192 | 16 |
| **LN** | 8 | `x[n, :, :, :]` | 16×32×32 = 16384 | 8 |
| **IN** | 8×16 = 128 | `x[n, i, :, :]` | 32×32 = 1024 | 128 |
| **GN**（g=4） | 8×4 = 32 | `x[n, 4i:4i+4, :, :]` | 4×32×32 = 4096 | 32 |

**"用一个切片模板统一四种 Norm"极其高效，是本课最该抄走的一张表**：记忆负担从"四个定义 + 四个立方体图"降成"一个切片 + 哪些维度被固定"。口诀一句——**被固定的维度是分组维度，被 `:` 铺满的维度是一起算统计量的维度**。老师那句"group normal 还要说吗"虽带调侃但结论对：掌握切片视角后 IN 和 GN 确实不必单独讲。而 LN 那句"**样本之间不相互影响**"才是本卡重点——**这正是它在 NLP/Transformer 里通吃的原因**（句子长度不同、batch 内差异大、推理时 batch 常为 1，BN 那套跨样本统计根本没法用）。**动作**：记住这条因果，因为你迟早要做 BEV 的 Transformer 那一路（BEVFormer/DETR3D）——**那里面全是 LayerNorm 而不是 BatchNorm**，面试被问"为什么 CNN 用 BN、Transformer 用 LN"，答案就是这一句，不用背别的。

### 49 推理时 batch=1 怎么办（02:25:22 – 02:28:00）

> **谢博**：「推理的时候方差怎么是一个数呢？推理走到这里是一样的……训练的时候这里是 8，推理的时候是 1，没关系啊，该怎么做怎么做。如果你是 1 的话，到这里是不是 1、16、32、32？那同样干嘛？跟刚刚那一样的逻辑，分 16 组啊……你们按照这个思路去推一下，自己就明白了。」

老师的口径是"按规则来"：batch=1 时张量是 `(1,16,32,32)`，照样按 C 分 16 组，每组 `1×32×32 = 1024` 个数，照样能算 μ、σ。

⚠ **这里必须打一个补丁，而且这是本课我唯一要当场纠正老师的地方：分组语义他讲对了，但 PyTorch 推理时并不是这么做的。**`nn.BatchNorm2d` 在 `model.eval()` 下**不重新计算 batch 统计量**，而是用训练期间以动量累积下来的 `running_mean` / `running_var`：

```python
# 训练（model.train()）：用当前 batch 的统计量，同时更新 running 值
running_mean = (1 - momentum) * running_mean + momentum * batch_mean
# 推理（model.eval()）：只用累积值，与同 batch 的其他样本完全无关
y = γ * (x - running_mean) / sqrt(running_var + eps) + β
```

原因正是第 47 卡那条推论：一组里混了多个样本，如果推理时现算，同一张图跟不同的图组成 batch 会得到不同的输出——这在部署上是灾难。所以老师说的"分 16 组"在**分组语义**上没错，但在**统计量来源**上要按 running stats 理解。这也是为什么第 42 卡我让你确认 `running_mean` 是 buffer 而不是 parameter——它不参与梯度更新，是被"记录"下来的。

**这条对你做 BEV 部署是三个直接的坑，当成检查清单**：①**导出 ONNX 前必须 `model.eval()`**，否则 BN 被导成训练模式，推理结果随输入批次乱跳；②TensorRT 做 BN folding 折进 Conv 的就是 `running_mean/running_var`，它们必须已收敛；③**mini 数据、迭代太少时 `running_var` 还没收敛**，会出现"训练 loss 很漂亮但一 eval 就崩"——遇到这个症状先打印 BN 的 running stats 看它是不是还停在初始值附近，而不是去怀疑数据或损失函数。这是你在 4060 上跑 mini 数据**大概率会撞上**的高频故障点。

⚠ 转写在 02:28:24 之后是 Whisper 幻觉（"我看不下"×19 加一句无关的频道广告），非课程内容。

**【小结】** ①不加修饰词的 Normalize = 所有数一起算，`(8,16,32,32)` 就是 131072 个数一个 μ 一个 σ；②Normalize 保形状保位置，只改值，所以能被 folding 进 Conv；③BN/LN/IN/GN 的唯一区别是"哪些数放一起算"，用一个切片模板就能统一描述——固定的维度是分组维度，`:` 铺满的维度是统计维度；④BN 叫 Batch 是因为每组里都有 batch 中所有样本派来的"代表"，这既是它的正则化来源、小 batch 失效的原因，也是它推理时必须改用 running stats 的原因。

### 复习最小集（三句话，背下来就够）

1. **残差 = `H(x)=F(x)+x`，等价于让卷积分支只学差额 `F(x)=H(x)−x`。** 前向上它让浅层低级特征绕过层层加工直达深层；反向上它把 `∂L/∂x = ∂L/∂h · ∂h/∂x` 变成 `∂L/∂h · (∂h/∂x + 1)`，那个 **+1** 把梯度消失从"必然"降成"概率"（是降概率，不是解决）。所以层数从"要精心权衡的超参数"变成"受预算约束的旋钮"。
2. **残差块里全是 3×3 / stride=1 / padding=1，不是习惯是必然**——因为 `add` 要求两个 tensor 的 N、C、H、W 完全相同；需要下采样时，直连边上要加 `1×1 Conv(stride=2)` 对齐（projection shortcut，对应图上的虚线）。门槛排序：矩阵乘 > add > cat，门槛决定了架构的可能性（DenseNet 只能用 cat）。
3. **Normalize 就四步：算 μ、算 σ、`x'=(x−μ)/σ`、`x^norm = γ·x' + β`（γ、β 当 W 一样训练）。** BN/LN/IN/GN 的唯一区别是"选哪些数一起算 μ、σ"：对 `(N,C,H,W)`，**BN 固定 C**（`x[:,i,:,:]`，C 组）、**LN 固定 N**（`x[n,:,:,:]`，N 组）、**IN 固定 N 和 C**、**GN 固定 N 和一组相邻 C**。它们都保形状保位置只改值；BN 推理时用 running stats，导出前务必 `model.eval()`。
