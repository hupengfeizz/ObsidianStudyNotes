**一句话主旨**：自注意力本身是**置换等变**的——把句子里的词换个位置，同一个词提取到的特征一模一样，所以必须外挂位置信息；正余弦编码用"加法"把位置塞进 embedding，但长序列下低频维度饱和、相邻位置编码趋同；**RoPE 换成"乘法"——把 Q/K 按每两维切成一个平面，第 m 个位置就把每个平面转 m·θᵢ 度**，于是两个 token 的内积只依赖它们的距离 (n−m)，这才是它能外推的根。

## Part 1 · 复习：Transformer 怎么堆，以及什么叫"注入"（00:00:00 – 00:16:04）

**【本段在讲什么】** 放假后第一节课，谢博用 16 分钟把 Transformer 架构重新捋一遍，但他捋的方式不是罗列组件，而是钉死一个提问框架：**任何一个"网络结构"只需要回答两个问题——核心模块长什么样、这些模块怎么堆。** 前一个问题上节课讲完了（多头注意力 + 前馈网络），今天要补的是第二个。补的过程中他抛出了本段最值钱的一个词：**注入（injection）**，用来区分 decoder 的"主输入"和"辅输入"。这个词后面会串起 U-Net 的跳连、DiT 的条件注入，是一条贯穿多种架构的线。开场他还先划了一条学习边界——「要学对找工作有帮助的东西，没帮助的学再多也没用」——这句定了全课的深度上限：凡是能展开三十分钟的地方（扩散模型、分割、RoPE 的严格外推证明），他一律说不展开。

### 01 Transformer 是"架构"，架构只需回答两个问题（00:02:46 – 00:03:40）

> **谢博**：「第一个就是我们说 Transformer，这个呢它叫一个架构，也可以叫一个网络结构。那作为一个网络结构的话，我们以前说过两件事情：第一个就是它的这个核心的模块长什么样子；第二个就是这些模块是怎么去堆叠的。……它核心的模块是不是两个？一个是编码模块，一个是解码模块。」

- **【直译】** 看懂任何网络 = 看懂"积木长什么样" + "积木怎么码"。Transformer 的积木有两种：Encoder Block、Decoder Block。
- **【为什么】** 这个二分法是老师反复用的通用工具。上节课讲完了积木（Multi-Head Attention + FFN + Add&Norm），今天讲码法。分开讲的好处是：码法一旦讲清楚，你换个积木（把注意力换成卷积）也照样能读懂新架构。
- **【连接】** 你写 YOLOv8 时也在用同一套思维：积木是 `Conv/C2f/SPPF`，码法是 `yaml` 里那张 backbone/head 表。BEVFusion 的 `SECOND` 骨干同理——积木是 `SparseBasicBlock`，码法是 `(64,512,512)→(384,128,128)` 这条下采样链。

### 02 Encoder 的产物 z：一个"更丰富语义的表征"（00:04:02 – 00:05:00）

> **谢博**：「这个先进行完这个编码完之后，我们说得到一个什么呢？得到一个隐状态是吧。这个状态它也是个特征，这个特征就记录了这句话的一个意思，或者是这个特征记录了对这句话的一个理解。我们说叫它更丰富语义的一个表征。」

- **【直译】** Encoder 吃进一整句话，吐出一个张量 z。z 不是"这句话"，是"模型对这句话的理解"。
- **【推导/代码】** 形状上 z 是 `[batch, seq_len, d_model]`，和输入 embedding 同形；变的是每个位置的向量含义——从"这个词本身"变成"这个词在这句话语境下的意思"。
- **【为什么】** 强调"表征"这个词是有目的的：后面讲 decoder 交叉注意力时，z 会被当成"被观察的对象"（K、V 的来源）。你必须先接受 z 是一个语义容器，才能理解 decoder 是在"问它"。
- **【连接】** 完全对应 BEV 里的 BEV feature：多相机图像编码完得到 `(C, 128, 128)` 的 BEV 特征，它也不是"图像"，是"模型对这块场地的理解"，后面 CenterPoint 头就在这上面提问。

### 03 decoder 的两个输入：一个叫 input，一个叫 injection（00:05:00 – 00:08:00）

> **谢博**：「decoder 的部分，它的输入其实是它的输出啊。……那这两个输入，它名字不一样。严格来说我们叫这个 decode 模块的输入，这边叫什么呢？虽然也是输入，我们叫**注入**，注水的注。……注入也就叫 injection。」

- **【直译】** Decoder 块有两条进线：下面那条（自己上一步的输出）叫 input，是主线；侧面那条（encoder 送来的 z）叫 injection，是辅线。
- **【推导/代码】** 落到代码就是 `DecoderLayer.forward(self, x, memory)`：`x` 是 input，`memory` 是 injection。`x` 走 masked self-attention，`memory` 只出现在 cross-attention 的 K、V 位置。
- **【为什么】** 老师非要造这个词，是因为"两个都叫输入"会让人以为它们地位对等。实际上主次分明：主线决定"我在生成第几个词"，辅线决定"我该往哪个方向生成"。区分了主次，后面 decoder-only 为什么能砍掉辅线就好解释了。
- **【连接】** 这个词后面复用了三次：U-Net 的 copy-and-crop 是注入、DiT 的条件是注入。在 BEV 里，BEVFusion 把 LiDAR 特征"注入"到相机分支，也是同一个模式——主干 + 侧路条件。

### 04 t1..t4 → t5：自注意力问自己，交叉注意力问 z（00:08:25 – 00:11:35）

> **谢博**：「比如说我们现在要输出 t5，那你这里面输入是不是要 t1 t2 t3 t4？……t1 到 t4 它也是一个句子，虽然这个句子不完整，我们也要对它进行理解，所以这里面是不是有一个自注意力呢？……然后它在这里产生一个问题：我下一个 token 应该是谁？那取决于什么呢？取决于这个 z。所以这里就产生了一个交叉注意力。」

- **【直译】** Decoder 每生成一个新词要做两件事：先把已经生成的半截句子读懂（自注意力），再拿这个"读懂的结果"去 z 里找答案（交叉注意力）。
- **【推导/代码】** 交叉注意力里 `Q` 来自 decoder 自己（半截句子），`K/V` 来自 encoder 的 z。这正好对应老师的"观察者/被观察者"说法：decoder 是观察者，z 是被观察者。
- **【为什么】** 老师用"提问"来包装 Q 这个字母，是极好的记忆锚点：Q = Query = 问句。一旦记住"谁提问谁就是 Q"，你在任何注意力变体里（cross-attn、DETR 的 object query、BEVFormer 的 BEV query）都不会搞反。
- **【连接】** BEVFormer 里 200×200 个 BEV query 去问 6 路图像特征，就是标准的 cross-attention：BEV query 是 Q（观察者），图像特征是 K/V（被观察者）。你换个词就读懂了那篇论文。

### 05 为什么每层都注入，以及 decoder-only 为何成立（00:12:33 – 00:16:20）

> **谢博**：「这个注入呢，它是每个 decode 的模块都注入进去。如果说它不注入，……他就只在这里问了一下，得到了这个 h，再经过几次特征提取之后，出来这个 t5 就跟这个关系不大了。相当于这个注入就反复提醒你。……就像我要你做个作业，我每天都要提醒你，我不提醒你，你过两三天我再来问，你可能跟我说：不好意思我忘记了。」
> **谢博**：「假如说我们 decoder-only，那这边是不是就没有？……那你只能问自己，是不是也是一样的呀？因为你把这个 Q 是不是放进来了呀？……当然可能效果没它那么好，但它快呀。」

- **【直译】** 两件事。①z 要接到**每一个** decoder 块，不能只接第一个——否则经过几层特征提取，原问题的信息就被稀释掉了。②decoder-only（GPT/Qwen 这一路）把问题本身当成前缀 token 塞进序列里，于是"问自己"就等价于"问了问题"。
- **【为什么】** 这是全课第一个真正有深度的设计动机解释。"反复提醒"这个比喻对应的是深层网络的**信息衰减**问题——和 ResNet 加残差、U-Net 加跳连是同一类药方。而 decoder-only 的合理性论证给了一个工程结论：**能用增大 d_model / 加头数换来的语义容量，就不必再单独堆一个 encoder**，因为后者慢。
- **【连接】** 这直接解释了为什么你在 HuggingFace 上看到的现代大模型（Qwen、LLaMA、DeepSeek）清一色是 decoder-only：不是 encoder 没用，是"把问题当前缀"这条捷径足够好且快得多。

---

**【小结】** ①架构 = 模块长相 + 堆叠方式，今天补第二问；②decoder 的侧路输入叫 injection（注入），要接到每一层，否则信息衰减；③decoder-only 把问题写进 token 串，用自注意力顶掉了交叉注意力，牺牲一点效果换速度——这是现代大模型的默认选择。

### 06 分割 = 388×388 个样本的二分类（00:26:13 – 00:28:35）

> **谢博**：「分割实际上本质上是一个什么呢？是一个多分类问题，叫非互斥的多分类问题。这个 388×388 代表什么意思呢？……它是 2 嘛，2 的话那这里面就是两个通道，两个通道里面的值呢，要么 0 要么 1。……也就是说这个像素点它的类别是哪一个，是背景还是前景，这就叫分割。」

- **【直译】** U-Net 输出 `388×388×2`，每个像素配一个长度为 2 的 one-hot，标它是前景还是背景。所以分割的本质是"给每个像素做一次分类"。
- **【推导/代码】** 严谨的表述是：**388×388 个样本（像素），每个样本 2 个类别**。老师第一次说成"388×388 个类别"，随后自己改口成"388×388 个样本要分类"——以后一种为准。
- **【为什么】** 老师要你记住的核心特点只有一句：**分割网络的输出 H、W 特别大**。分类输出是 `[num_classes]`，检测输出是 `[80,80,255]` 这种量级，分割输出直接和输入同量级。这个"输出特别大"的特点决定了它必须有上采样路径，也就必须长成 U 型。
- **【连接】** 任务词汇表也在这里给全了：分类 classification、检测 detection、分割 segmentation、追踪 tracking、姿态 pose。BEV 里的 map segmentation 头输出 `(200,200,num_map_classes)`，就是本条结论在鸟瞰图上的复刻。

### 07 读网络结构图的方法论：节点 vs 边，谁是数据谁是操作（00:29:32 – 00:31:00）

> **谢博**：「这是个图嘛，无非就要搞清楚节点和边嘛。那你要搞清楚这个节点代表数据还是边代表数据，是节点代表操作还是边代表操作。这人家已经标得很清楚了，首先你要问这个问题。……这些是不是代表数据嘛，tensor。好你看这里，这个箭头就代表操作嘛。什么操作？三乘三的卷积，激活函数是 ReLU。」

- **【直译】** 拿到任何一张网络结构图，第一件事不是看模块名，是先判定图的约定：方块=张量还是方块=算子。U-Net 原图的约定是"方块=特征图，箭头=操作"。
- **【推导/代码】** 这个判定直接决定你怎么把图翻译成代码：**方块 = 变量，箭头 = 函数调用**。U-Net 那张图逐箭头翻译就是 `x = F.relu(self.conv1(x))`。
- **【为什么】** 老师说"最不重要但你们最喜欢、也最简单"——读图是入门技能，真正难的是理解设计动机。但读图错了后面全错，所以他还是花了两分钟钉这个约定。
- **【连接】** 你看 mmdetection3d 的架构图时同样受用：BEVFusion 那张总图里方块是 `voxel_features / spatial_features / bev_feature`，箭头是 `voxelize / backbone / neck`。

### 08 572 → 570：没做 padding，"这网络上了年纪了"（00:30:47 – 00:32:10）

> **谢博**：「你看它出来 572，做完一个三乘三的卷积之后变成 570 了，这合理吧？……我们现在的神经网络用三乘三的卷积，卷积完之后这个特征图它的尺寸会变吗？现在是不是不变？因为我们做了 padding 去控制它不变嘛。如果你不 padding 的话，它是不是会少两个像素？……所以你就要想到，这里它没有做 padding 嘛。……那就说明它年纪比较大了嘛，它是上了年纪的人嘛，就提出来的时候比较早。」

- **【推导/代码】** `H_out = ⌊(H_in + 2p − k)/s⌋ + 1`。k=3, s=1, p=0 → 572 → 570，正好掉 2。现代写法 `p = k//2 = 1` 则 572 → 572。
- **【为什么】** 这是本段最漂亮的一手：**从张量形状的变化反推作者的设计年代和方法论水平**。"同分辨率卷积必须 same padding"是 2015 年之后才固化的共识，U-Net（2015）还没这个习惯，于是它每两次卷积掉 4 个像素，最后才需要 crop 才能拼接。
- **【连接】** 你 MNIST 默写模板里 `nn.Conv2d(1, 32, 3, 1, 1)` 尾巴上的那个 `1` 就是 padding，就是这条现代共识的体现。YOLOv8 的 `autopad(k, p)` 也是把这个共识函数化。

### 09 上采样两大类，以及 copy-and-crop 也是注入（00:33:00 – 00:39:10）

> **谢博**：「分辨率变大了就是上采样。上采样从大的方向来说有两种：一种是我叫传统的采样方法，它用固定算法就做了；还有一种是这里提到的叫 up convolution，这个叫反卷积，我们也叫转置卷积。转置卷积呢它有两个作用：一个是上采样，第二个是提取特征。……传统的上采样方法它只会放大特征图的分辨率，里面的数据它不变。」
> **谢博**：「这个灰色箭头代表什么？COPY，并且 crop。……就是把编码过程中的特征和当前这个解码的特征合并成一个特征，然后继续往后面提取特征。这条边相当于什么？是不是相当于**注入**啊？……只要你这个网络 U 起来了，都叫 U-Net。」

- **【推导/代码】** 上采样两条路：`nn.Upsample(scale_factor=2, mode='nearest')` 无参数、只放大；`nn.ConvTranspose2d(in_c, out_c, 2, stride=2)` 有 `in_c×out_c×2×2` 个参数，边放大边学特征。为什么要 crop：encoder 侧是 64×64，decoder 反卷积上来是 56×56，形状对不齐无法 `torch.cat`，所以中心裁剪 64→56。现代实现全程 same padding，通常直接 cat。
- **【为什么】** 这段的落点不是 U-Net 本身，而是把"注入"从 NLP 拔出来看成跨模态的通用模式：**主干负责推进，侧路负责不断提醒主干"别忘了原始信息"**。DiT / Seedance 这类文生视频模型的条件注入是同一个模式。老师顺带损了一句"你们最喜欢直接 resize，暴力"——把 64 硬 resize 成 56 就丢掉了对齐的语义。
- **【连接】** YOLOv8 的 neck 用的正是 `Upsample(nearest)` + C2f（第一类上采样）+ Concat 节点（注入）；BiFPN 的双向跨尺度连接本质也是同一件事。你已经会用了，现在有了统一的名字。

---

**【小结】** ①读图先定约定：节点是数据还是操作；②从形状变化能反推设计（572→570 说明没做 padding，说明网络"年纪大"）；③分割 = 逐像素分类，输出 HW 特别大，所以必须 U 型；④copy-and-crop / 跳连 / 条件注入，都是同一个"注入"模式。

## Part 3 · 为什么需要位置编码：我吃饭 vs 饭吃我（00:40:02 – 00:44:02）

**【本段在讲什么】** 正式进入主题。谢博先把问题立起来：Transformer 有两个"比较难理解"的遗留点——位置编码和掩码注意力，今天只讲前者。他用一对中文句子（我吃饭 / 饭吃我）把问题说得极其干净：**输入的 token 集合完全相同，只有顺序不同，但意思完全不同**。然后他补了一个对比：图像没有这个问题。这个对比很重要，因为它告诉你位置编码不是"网络的通病"，而是**序列数据独有的病**。

### 10 遗留的两个难点：位置编码与掩码注意力（00:40:25 – 00:41:10）

> **谢博**：「然后我们说这里面还遗留了两个问题，哪两个问题呢？一个是这个位置编码是不是？还有一个掩码注意力。这两个是比较难理解的，我知道。现在给你讲。」

- **【直译】** Transformer 结构里还有两块没拆：Positional Encoding 和 Masked Attention。本课只处理位置编码，掩码留到下次。
- **【为什么】** 他把这两个并列是对的——它们是同一类东西：**都是给自注意力打补丁的机制**。自注意力天生看不见顺序（→位置编码补），也天生能看见未来（→因果掩码补）。
- **【连接】** 复习清单这样组织：注意力本体（QKV/缩放/softmax）→ 补丁 A 位置编码 → 补丁 B 因果掩码 → 工程加速（KV Cache / FlashAttention）。

### 11 ViT 也有 position embedding（00:41:15 – 00:41:50）

> **谢博**：「我们看一下位置编码，这个是不是……VIT 是不是？都是有位置编码的，看到没有？这里有 patch 再加一个 position embedding。」

- **【画面】** 00:41:27 帧上是标准 ViT 结构图：左侧 `Patch + Position Embedding`，一排编号 0–9 的 patch token 前面挂着 `Class/Extra learnable [class] embedding`（图中标 `Class Bird Car`），中间 `Linear Projection of Flattened Patches`，右侧 Transformer Encoder 的 `L×` 堆叠。
- **【直译】** 图像切成 patch 送进 Transformer 后，同样要加位置嵌入——因为一旦切成 token 序列，patch 之间的空间关系就丢了。
- **【为什么】** 这里有个容易混的点：**图像本身没有顺序问题，但"把图像切成 patch 序列"之后就有了**。CNN 靠卷积核的滑动天然保留空间关系，ViT 把这个关系扔了，只能再补回来。老师后面讲的"图像不存在这个问题"说的是 batch 内样本的顺序，不是 patch 的顺序，别混。
- **【连接】** 这一条直通你的 BEV 方向：BEVFormer 的 BEV query 也要加 2D 位置编码，PETR 干脆造了 3D Position-aware 特征——都是"切成 token 就丢了几何，必须补回来"的同一个故事。

### 12 我吃饭 vs 饭吃我：token 一样，意思不一样（00:41:32 – 00:42:30）

> **谢博**：「假如说我们让神经网络去理解两句话，一个叫我吃饭，一个叫饭吃我。这是不是顺序变了呀？……如果没有位置编码的话，这个 Transformer 这个网络结构是分不清这两句话的。因为这里面的嵌入 token 是不是一样的嘛？同样是 T1 T2 T3，这里换成了 T3 T2 T1。因为它输入的 token 其实是一样的，但是呢它的意思变了。」

- **【直译】** 两句话用的是**同一个词表里的同三个词**，词向量逐个相同，只是排列不同。如果网络对排列不敏感，这两句就被压成同一个东西。
- **【推导/代码】** 用调试器里的真实数据说：`tokens1 = [[0,1,2]]`，`tokens2 = [[2,1,0]]`，查表出来 `word_emb1` 的三行和 `word_emb2` 的三行是同一个集合、只是顺序倒了。这就是"输入只差一个置换"的严格含义。
- **【为什么】** 这个例子选得好，因为它是**语义完全颠倒**的极端情况（施事和受事互换），而不是"读起来有点怪"。极端例子能让"分不清"的后果显得致命。
- **【连接】** 你在 BEV 里遇到的对应问题是：点云的点是无序集合（PointNet 靠对称函数处理），但一旦把点云体素化成规则网格，网格的空间位置本身就是位置编码，不需要额外加——这也解释了为什么纯 CNN 的 BEV 骨干从来不谈位置编码。

### 13 不叫 sentence，叫 sequence；图像 batch 内没有顺序（00:42:33 – 00:44:35）

> **谢博**：「所以为什么叫这句话，这句话它的专业术语叫什么？它不叫 sentence，我们叫它 sequence，序列。序列里面隐含了一个意思，就是里面的东西是有顺序的。……那你比如说我们图像里面会不会存在这个问题呢？图像里面不存在这个问题。……我把 img1 放前面，img0 放后面，这个结果有影响吗？没有影响啊。你取结果的时候按对应位置取就行了。」

- **【直译】** 术语上，NLP 的输入单位叫 sequence 而不是 sentence，因为 sequence 这个词自带"有序"的含义。相比之下一个 batch 里的多张图片是无序的，换个排列结果一一对应地跟着换，不影响任何东西。
- **【推导/代码】** 说得更准一点：模型对 **batch 维**是置换等变的（无害，符合预期），对 **序列维**也是置换等变的（有害，必须打破）。位置编码干的就是"打破序列维的置换等变性"这一件事。
- **【为什么】** 这个对比是全课的问题定义环节。它把"为什么要位置编码"从"因为顺序重要"这种同义反复，升级成"因为注意力对序列维是置换等变的，而任务要求它不等变"。**面试就答后面这一句。**
- **【连接】** 顺手把术语链补齐：`sequence → tokenize → token id → embedding → +PE → attention`。这条链你要能一口气默写出来。

---

**【小结】** ①位置编码和掩码注意力是自注意力的两块补丁；②我吃饭 / 饭吃我 token 完全相同、语义完全颠倒，是"顺序必须被感知"的极端反例；③专业说法是 sequence（有序）而不是 sentence；batch 维无序是良性的，序列维无序是致命的。

## Part 4 · 正余弦位置编码：pos 和 i 到底是什么（00:44:02 – 01:01:01）

**【本段在讲什么】** 谢博在这里立了一条讲课纪律：**先讲怎么算，再讲为什么这么算，两个问题分开**。这一段只干"怎么算"。核心是把公式里那两个下标钉死——`pos` 是 token 在句子里的第几个，`i` 是向量里的第几维。定位一个具体的数字需要这两个坐标，就像定位棋盘上一个格子需要行号和列号。他用 embedding 长度 = 3 的玩具例子（0.1 / 0.2 / 0.3）一个数一个数地代进公式，把抽象公式变成算术。

### 14 两种位置编码：正余弦（原版）vs 旋转（Qwen 在用）（00:44:22 – 00:45:00）

> **谢博**：「位置编码有两种，一种是传统的，标准的 Transformer 用的是什么呢？叫正余弦位置编码。现在我们用的是什么呢？旋转位置编码。这个新的包括千问，它也是 rotary position encode。」

- **【直译】** 本课要讲的两个方案：Sinusoidal Positional Encoding（2017 原版 Transformer）和 Rotary Position Embedding（RoPE，现代大模型标配）。
- **【为什么】** 一上来就把"新旧"关系摆明，是为了给后面的叙事定型：**先学旧的怎么算 → 再看旧的哪里坏了 → 新的怎么修**。这条叙事线你在面试里原样复述就是一个满分回答的骨架。
- **【连接】** 实际生态：Qwen、LLaMA、DeepSeek、Mistral 全线 RoPE；BERT 用的是**可学习**的绝对位置嵌入（第三种，本课没讲）；原版 Transformer 才是正余弦。这三种的分类是高频面试题。

### 15 【画面】PPT 给的两条性质，与被否掉的朴素方案（00:45:00 – 00:45:40）

> **【画面】PPT 第 5 页「位置编码 · 正弦余弦位置编码（Sinusoidal Positional Encoding）」原文**：
> 「嵌入层的输出是一个向量数组，即词嵌入向量的序列。设数组的位置叫 pos，向量的某一维叫 i。我们为每一个向量里的每一个数添加一个实数编码，这种编码方式要满足以下性质：
> **1.** 对于同一个 pos 不同的 i，即对于一个词嵌入向量的不同元素，它们的编码要各不相同。
> **2.** 对于向量的同一个维度处，不同 pos 的编码不同。且 pos 要满足相对关系，即 `f(pos+1) − f(pos) = f(pos) − f(pos−1)`。
> 要满足这两种性质的话，我们可以轻松地设计一种编码函数：`Encoding(pos, i) = pos / 1000^i`」

- **【直译】** PPT 先立了两条设计要求，再给一个"最容易想到"的方案 `pos/1000^i`，然后马上要否掉它。
- **【推导/代码】** 性质 2 的那个等差式很关键：它要求编码沿 pos 方向是**等差的**，这样 `f(pos+k) − f(pos)` 只和 k 有关、和 pos 无关——这就是"相对位置可感知"的最原始表述。正余弦用和角公式（`sin(a+b)=sin a·cos b + cos a·sin b`）做到了更强的版本：`f(pos+k)` 是 `f(pos)` 的一个**线性函数**。
- **【为什么】** 这一页把 RoPE 的种子已经埋下了：RoPE 的核心恒等式 `qₘᵀkₙ` 只依赖 `n−m`，正是把性质 2 从"编码本身"提升到了"注意力内积"这一层。
- **【连接】** 你在写任何位置编码变体时，都可以拿这两条性质当验收标准：跨维度要有区分度（性质1），跨位置要有稳定的相对结构（性质2）。

---

### 16 为什么不能直接给 token 加上位置序号（00:45:41 – 00:47:15）

> **谢博**：「我们不能说直接 T1 加 1，然后得到 T1'。……为什么不能这样做很简单，因为这个 T1 它实际上是要用它的嵌入啊，Embedding 比如说是 512 的长度。那里面这 512 个数，如果你这样加的话，是不是每个位置都加的一样？而它原来的这里面的数值它是大还是小啊？它很小的。你一加，整个这个其实就变成位置了。……也就是整个 T1' 它就不代表原来的 T1 了，它就代表位置 1 了。」

- **【直译】** 最土的方案——第 k 个 token 的每一维都加上 k——会失效，因为 embedding 里的数普遍在 ±1 量级，而 pos 可以到几千，位置数值会把语义数值彻底淹没。
- **【推导/代码】** 用调试器里的真数据算：`word_emb1[0] = [0.3367, 0.1288, 0.2345, 0.2303]`。给第 500 个 token 每维加 500，得到 `[500.34, 500.13, 500.23, 500.23]`——四个数几乎相等，语义信息在浮点精度里已经消失。
- **【为什么】** 这是"为什么位置编码必须有界"的根本理由。正余弦的取值恒在 [−1, 1]，和 embedding 同量级，这才敢直接相加。RoPE 更进一步，用旋转（正交变换）**完全不改模长**，连量级问题都不存在。
- **【连接】** 同样的量纲直觉在你调 BEV 时天天用：多模态特征拼接前要 BN / LayerNorm，就是怕一路特征的数值量级压死另一路。

### 17 pos 是什么：token 在序列中的第几个（00:47:27 – 00:48:35）

> **谢博**：「它有两个参数，一个叫 pos，一个叫 i。……pos 就是 1、2、3，也就是这个 token 在句子里面的位置。我先不管它，不去计较它是从 0 开始还是从 1 开始，这个无所谓。……这个 1 2 3 就是这里面说的序列中的位置，叫 pos。为什么叫序列中的位置？因为我们输入是一个 sequence。」

- **【直译】** `pos` = 这个词是句子里的第几个词。从 0 数还是从 1 数不影响原理（代码里是从 0）。
- **【推导/代码】** 代码对应 `position = torch.arange(0, seq_len, dtype=torch.float).unsqueeze(1)`，形状 `[seq_len, 1]`。`unsqueeze(1)` 是为了后面和 `div_term`（形状 `[d/2]`）做广播，一次算出整张 `[seq_len, d]` 的编码表。
- **【为什么】** 老师特意说"从 0 还是从 1 无所谓"，是为了让你不要卡在无关细节上。但工程上要注意：**推理时如果 pos 的起点和训练时不一致，模型会当场崩**——KV Cache 场景下 position_id 的对齐是实际会踩的坑。
- **【连接】** HuggingFace 里那个 `position_ids` 参数就是这个 pos。你调 Qwen 做长上下文时改的就是它。

### 18 i 是什么：向量的第几维（00:48:48 – 00:51:20）

> **谢博**：「第二个，向量的某一维叫 i。……我现在就说它的 embedding 的长度假如说是 3 好吧，那也就是 T1 是一个长度为 3 的一个向量。我打个比方，它是 0.1、0.2、0.3。……0.1 的 pos 是几呢？0.1 的 pos 是 0。0.1 的 i 是几呢？也是 0。……然后 0.3，pos 是 0，i 是 2。」

- **【直译】** `i` = 这个数字在词向量里排第几。定位到具体的某一个浮点数，需要 (pos, i) 这一对坐标。
- **【推导/代码】** 把它想成一张二维表：行 = pos（哪个词），列 = i（哪一维）。`pos_encoding` 张量的形状就是 `[seq_len, embed_dim]`，`pos_encoding[pos][i]` 就是要加到 `embedding[pos][i]` 上的那个数。老师举的第二个 token `T2 = [0.4, 0.5, 0.6]`，其中 0.5 的坐标是 `(pos=1, i=1)`。
- **【为什么】** 这一段花了两分半反复举例，因为**混淆 pos 和 i 是初学者理解位置编码失败的第一大原因**。很多人以为位置编码是"每个 token 一个数"，实际上是"每个 token 一个和 embedding 等长的向量"。
- **【连接】** 记住这张二维表，后面看那张 `1000 × 128` 的热力图时你会瞬间明白：纵轴就是 pos，横轴就是 i，每个像素就是 `PE(pos, i)` 这一个实数。

### 19 形状必须一致才能相加（00:51:32 – 00:53:05）

> **谢博**：「这个位置是不是就整个是这个 token，这个数组，三个数组成的数组？然后它要跟一个位置编码 position encoding 要相加。这两个要相加，那说明这个 pos encoding 是不是也跟它——我们说以前分析过相加呀，它 shape 一定要一样啊。不能缺呀知道吧。」

- **【直译】** PE 和 embedding 是逐元素相加，所以两者形状必须完全一致：embedding 是长度 3 的向量，PE 也必须是长度 3 的向量。
- **【推导/代码】** 实际代码里 `x = word_emb + pos_encoding`，形状 `[1, 3, 4] + [3, 4]`，靠广播在 batch 维对齐。注意 PE 是 `[seq_len, d_model]` 而不是 `[batch, seq_len, d_model]`——**同一个 batch 里所有样本共用同一张位置表**，因为第 5 个位置就是第 5 个位置，与是哪条样本无关。
- **【为什么】** 这条听着像废话，但它排除了一类错误理解："给每个 token 加一个标量"。**加的是向量，不是标量。** 在 BEV 里 `[B,N,C]` 和 `[N,C]` 的广播对齐天天遇到，形状对不齐是 shape mismatch 报错的头号来源。

### 20 偶数维用 sin、奇数维用 cos：2i 和 2i+1 是一对（00:53:22 – 00:58:30）

> **谢博**：「实际上他算的时候，他还要除以这个 d，就是他的 embedding 的长度，然后是 i，然后还分 cos 和 sin。……那你比如说这里，这两个是不是一对啊？……这两个 tensor 的时候，i 是几啊？i 是不是 0 呢？……这个地方 i 是 0，然后这个地方是不是 i 加 1 啊？那就是 1 啊。……0.5 这个要套上面这个公式还是下面这个？因为它是 2i、2i+1，它是奇数，这是奇数位置。」

- **【推导/代码】【画面】** PPT 给的完整公式：
  `PE(pos, 2i)   = sin(pos / 10000^(2i/d_model))`
  `PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))`
  关键在于 **`2i` 和 `2i+1` 共享同一个 `i`，也就是共享同一个角度**。d=4 时，维度 0/1 共用 i=0 的角度，维度 2/3 共用 i=1 的角度——一共只有 2 个不同角度，不是 4 个。
- **【直译】** 把 embedding 从左到右两个两个分组；每组算出一个角度；组内第一个维度填 sin，第二个填 cos。
- **【为什么】** 为什么必须成对？因为 `(sin θ, cos θ)` 组成的是**单位圆上的一个点**，两个凑一起才能唯一确定一个角度，也才能用和角公式把 `f(pos+k)` 表达成 `f(pos)` 的线性组合。**这正是 RoPE 的直接前身**——RoPE 把"两个维度共一个角度"从"填 sin/cos"升级成"在这个平面上真的转一下"。这一条是全课最值得画重点的伏笔。
- **【连接】** 记住这个"两两成对"，Part 7 里 RoPE 的分块 2×2 旋转矩阵你就完全不用重新理解。

### 21 10000 这个底数在控制什么（00:58:45 – 00:59:20）

> **谢博**：「这个 1 万还是 1000，它影响什么呢？……这个 1000 和 1 万这个有什么用啊？它是为了控制这个正余弦函数的**周期**的。听懂这意思吧？所以你 1 万 1000 都可以，看你怎么去调整。」

- **【推导/代码】** 第 i 组的角频率是 `ωᵢ = 1/base^(2i/d)`，波长是 `2π·base^(2i/d)`。i=0 时波长 = 2π（约 6.3 个位置就转一圈，变化极快）；i=d/2−1 时波长 ≈ 2π·base（base=10000 时约 6.3 万个位置才转一圈，几乎不变）。**base 决定的是最长波长，也就是这套编码"最多能区分多远"。**
- **【为什么】** 这一条是理解后面那张热力图的钥匙，也是理解现代长上下文技术的钥匙：所谓"NTK-aware 插值 / 把 base 从 10000 调到 1000000"来扩上下文，改的就是这一个数。老师说"1 万 1000 都可以"在原理上没错，但在长上下文场景里这个数恰恰是最要命的超参。
- **【连接】** 你要是被问"Qwen 怎么把上下文从 32K 扩到 128K"，答案的第一层就是"调 RoPE 的 base（rope_theta）"。

### 22 插话：AI 会取悦你，学糊涂了怪谁（00:59:47 – 01:00:35）

> **谢博**：「到这里来的时候，你不要想去 QKV 的长度，那不对了。到这里都没有 QKV。……今天我在群里面我还特意说了一下，AI 很多东西是在取悦你的，所以会造成你有时候会学糊涂了。当然你也可以不信我的，你去问 AI 也可以，最终只要不影响你面试就可以了。因为可能面试官也是 AI。」

- **【直译】** 两件事：①正余弦位置编码是加在 **embedding** 上的，这一步还没有 Q、K、V，别往那想；②别拿 AI 的答案当权威。
- **【为什么】** 第一点很重要，而且它埋了一个**只对正余弦成立的结论**。到了 RoPE，情况正好相反：RoPE **就是**作用在 Q 和 K 上的（见 Part 7 第 41 条 RoFormer Figure 1）。把这句话不加区分地套到 RoPE 上是最常见的错误理解，见纠错表 B-5。
- **【连接】** 记成一张对照表：正余弦 = 加在输入 embedding 上，**全网络只加一次**；RoPE = 乘在每一层的 Q、K 上，**有多少层就转多少次**，且不碰 V。

**【小结】** ①`pos` 是第几个 token，`i` 是第几维，定位一个数要两个坐标；②PE 与 embedding 同形、逐元素相加；③维度两两成对共享同一个角度，偶数填 sin 奇数填 cos——这是 RoPE 的直接前身；④base=10000 控制的是最长波长，也就是可区分距离的上限。

### 24 attention_weights 是 (1,3,3)：每行是一个词的观察分布（01:04:40 – 01:07:35）

> **谢博**：「这里有个 attention weight，看这个数据结构，是不是这个注意力分布嘛？你看它是什么呢，softmax 出来的嘛。……这里是不是 (1,3,3)？这个 (1,3,3) 我们怎么来理解呢？'我'是不是要观察自己啊、观察'吃'啊、观察'饭'啊？那它是不是会形成三个权重啊？然后'吃'是不是也是一样？……这三个数加起来要等于 1。」

- **【推导/代码】【画面】** 01:05:06 帧调试器弹窗：
  `attention_weights = {Tensor:(1,3,3)} tensor([[[0.2810, 0.4513, 0.2677], [0.3437, 0.2330, 0.4233], [0.2923, 0.4241, 0.2836]]], device='cuda:0', grad_fn=<SoftmaxBackward>)`

### 25 0.2923 和 0.2677：两句话里"我看饭"的权重完全一样（01:07:12 – 01:10:15）

> **谢博**：「这个 0.2923 是什么意思呢？我对'饭'的这个注意力。……然后'饭'是不是也要观察'我'呀？观察'我'这个权重在哪里呢？在 0.2677。……然后这个时候就发现了个问题：我'饭'放前面'我'放后面，和'我'放前面'饭'放后面，是一样的。……在这两句话里面，我去观察'饭'这件事情，你发现它的这个权重是一样的。」

- **【推导/代码】** 把两个矩阵摆一起看最清楚：
  句1（我吃饭）：`[[0.2810, 0.4513, 0.2677], [0.3437, 0.2330, 0.4233], [0.2923, 0.4241, 0.2836]]`
  句2（饭吃我）：`[[0.2836, 0.4241, 0.2923], [0.4233, 0.2330, 0.3437], [0.2677, 0.4513, 0.2810]]`
  句2 就是把句1 **上下翻转再左右翻转**（行倒序 + 列倒序），没有任何一个数改变。用符号写：`A₂ = P A₁ Pᵀ`，其中 P 是逆序置换矩阵。
- **【为什么】** 这就是"置换等变（permutation equivariance）"的实物照片。注意力算的是"内容与内容之间的相关性"，内容没变，相关性就不变；换了顺序，只是把同一张关系表重新排列了一遍而已。
- **【连接】** 面试标准答法："自注意力对输入序列是置换等变的——输入做置换 P，输出跟着做同一个 P，其余不变。所以必须外挂位置信息来打破这个对称性。"

### 26 关键澄清：不是"两个张量相同"，而是"对应位置相同"（01:10:50 – 01:15:15）

> **谢博**：「不是说它们比如说'饭吃我'和'我吃饭'这两句话进到一个自注意力里面，它出来的这个 tensor 是不一样的，明白这个意思吗？它 tensor 是不一样的。但是这个 tensor 不一样里面呢，你不能说 tensor 不一样，那就代表这个注意力能够区分饭和我的位置了，它不是这个意思。……我讲这个意思是什么呢？是让你真正的从这个底层去理解，什么叫区分不了顺序。」

- **【直译】** 两个输出张量当然长得不一样（因为输入本来就不一样）。真正的证据是：**句1 第 1 行 与 句2 第 3 行 逐位相等**——"我"这个词无论排第一还是排第三，提取到的特征一模一样。
- **【推导/代码】** 形式化：设 `f` 是自注意力，`P` 是置换。置换等变意味着 `f(Px) = P f(x)`，而不是 `f(Px) = f(x)`。后者叫置换**不变**（invariant），那是 PointNet 的 max-pool 才有的性质。**等变 ≠ 不变**，这两个词混用是本条要防的错。
- **【为什么】** 老师在这里连说了五分钟、换了四种说法，还预判了面试场景："可能你去面试，他也不一定那么清楚，他可能以为这两个不一样。"这说明他知道这是一个高频错误。**这是本课最值得背下来的一条。**
- **【连接】** 你的 BEV 背景里有个现成的对照：PointNet 对点的排列是**不变**的（max-pool 吃掉了顺序），Transformer 对 token 的排列是**等变**的。两种对称性，两种处理方式。

### 27 为什么会等变：同一个模块，同一份 V（01:13:20 – 01:14:20）

> **谢博**：「那这个'饭'在这个句子里面产生的 QKV，和这个'饭'在这个句子里面产生的 QKV，是一样的。……所以我这个 0.29 是不是要乘以'饭'的 V 呢？……然后这个位置是不是也是我对'饭'的注意力权重呢？那是不是也要乘以这个'饭'的 V 呢？……然后'饭'的 V 也是一样的，所以它最后提取到的特征是一样的。」

- **【推导/代码】** 因果链拆成三步：①`Q = W_q·x`、`K = W_k·x`、`V = W_v·x` 都是**逐位置独立**的线性变换 → 同一个词在哪个位置产生的 QKV 都相同；②`scores = QKᵀ/√d` 只看内容相关性，换顺序只是把这张表重排；③`output = softmax(scores)·V`，权重和 V 都没变，加权和自然没变。
- **【为什么】** 这一步把"实验现象"升级成"机制解释"。关键在第①步——**注意力里没有任何算子是"跨位置且位置相关"的**。逐位置的线性层不带位置信息，softmax 也不带位置信息，整条链路上没有一个地方知道"你是第几个"。
- **【连接】** 反过来想：CNN 为什么不需要位置编码？因为卷积核的滑动本身就是位置相关的——权重 w₁ 永远乘在"左上角那个像素"上。这就是 CNN 有归纳偏置而 Transformer 没有的具体含义。

### 29 解决思路低得离谱：只要不一样就行（01:19:50 – 01:22:35）

> **谢博**：「那无法区分 token 顺序，怎么去解决它呢？加位置编码嘛。其实还没这么高大上，就是只要让这个位置的四个数和这个位置的四个数不一样就可以了。……你不管你怎么加都可以。不是说一定要标个这里是 1、这里是 2、这里是 3。神经网络只要它不一样，那就知道它位置不一样了。……然后这个不一样具体代表谁在前谁在后，神经网络能分得清楚，你分不清楚。」

- **【直译】** 位置编码的功能需求极低：只要让同一个词在不同位置的输入向量产生可区分的差异就行，具体差成什么样，交给网络去学。
- **【为什么】** 这一条是很好的"祛魅"。学生容易觉得正余弦那一坨公式神秘无比，老师直接说：**它只是众多"能让向量不一样"的方案之一，之所以选它是因为它能说出道理（有界、周期、相对关系），不是因为它唯一正确。** BERT 用的可学习位置嵌入，就是"随便加，让网络自己学"的极端版本，效果也不差。
- **【推导/代码】** 但"能说出道理"的部分不能丢：①取值有界（不淹没语义）；②不同位置编码不同（区分性）；③相对位置有稳定结构（可泛化到没见过的长度）。正余弦满足前两条、第三条弱；可学习嵌入满足前两条、第三条完全没有（超长必崩）；RoPE 三条全满足。
- **【连接】** 这个"功能需求 vs 好方案的额外性质"的拆分，可以直接套到 BEV 里：BEV query 的位置嵌入，最低要求是"每个格子不一样"，好方案还要"平移等变"。

---

**【小结】** ①两句话只差一个置换，注意力权重矩阵也只差同一个置换（行列同时倒序），数值一位不差；②`output1` 与 `output2` 三行整行对调、逐位相等，这就是置换等变的实物证据；③要区分"等变"和"不变"——出来的整个张量不一样，但**对应位置**一样，这才是"感知不到顺序"的准确含义；④位置编码的功能底线只是"让它们不一样"。

## Part 6 · 工程实现与正余弦的死穴（01:22:00 – 01:45:01）

**【本段在讲什么】** 这一段分两半。前一半是代码阅读：为什么所有实现里的正余弦位置编码都要写成 `exp(-log(10000)/d)` 这种绕弯的形式（答案：防溢出，一个你已经见过两次的老套路）。后一半是本课的转折点：一张 `1000×128` 的热力图，直接展示正余弦编码在长序列上的失效——高维度区域上，相邻位置的编码几乎一模一样。有了这个缺陷，RoPE 的出场才有理由。

### 30 【画面】positional_encoding 函数全文（01:22:38 – 01:23:50）

> **【画面】01:27:41 帧 PyCharm，文件 `position_encode.py`（工程 `deepseek`，路径 `src/zg/`，conda 环境 `deepseek`）**：
> ```python
> def positional_encoding(seq_len, embed_dim, device):
>     # 初始化位置编码矩阵
>     pos_encoding = torch.zeros(seq_len, embed_dim, device=device)
>
>     # 生成位置索引
>     position = torch.arange(0, seq_len, dtype=torch.float).unsqueeze(1)
>
>     # 计算分母项
>     div_term = torch.exp(torch.arange(0, embed_dim, 2).float() * (-math.log(10000.0) / embed_dim))
>
>     # 偶数位置用sin,奇数位置用cos
>     pos_encoding[:, 0::2] = torch.sin(position * div_term)
>     pos_encoding[:, 1::2] = torch.cos(position * div_term)
>
>     return pos_encoding
> ```

- **【推导/代码】** 逐行对公式：`position` 是 `[seq_len,1]` 的 pos 列；`div_term` 是 `[d/2]` 的 `1/10000^(2i/d)`；两者相乘广播成 `[seq_len, d/2]` 的角度表；`[:, 0::2]` 取偶数列填 sin，`[:, 1::2]` 取奇数列填 cos。
- **【为什么】** 注意这段代码的形状魔法：`div_term` 只有 `d/2` 个元素，而 `pos_encoding` 有 `d` 列。正是"两两成对共享一个角度"的直接体现（Part 4「偶数维用 sin、奇数维用 cos」那一条的伏笔在这里兑现）。
- **【连接】** 这份代码你可以整段默写，长度和你的 MNIST 模板差不多。面试白板题"手写正余弦位置编码"考的就是这 8 行。

### 31 exp(−log(10000)/d) 到底在干嘛：等式变换（01:24:00 – 01:26:00）

> **谢博**：「这个就是我们常见的技巧。利用什么呢？这不是规划，这是**等式变换**。你比如说 5，5 可以写成什么样子呢？等于 e 的 ln 5。……因为你如果不这样写的话，直接写 1 万的多少次方，很容易造成什么呢？造成这个数**溢出**。比如说 1 万的 10 次方，那你想这个数多大了？这是为了防止它溢出。」

- **【推导/代码】** 完整的等式链：
  `1/10000^(2i/d) = 10000^(−2i/d) = e^(ln 10000^(−2i/d)) = e^(−(2i/d)·ln 10000) = exp(2i · (−ln(10000)/d))`
  代码里 `torch.arange(0, embed_dim, 2)` 生成的就是 `2i`，乘上常数 `−math.log(10000.0)/embed_dim`，再 `torch.exp`。**数学上完全等价，数值上安全得多**——直接算 `10000**x` 在 x 较大时会先算出天文数字再取倒数，中间就炸了。
- **【为什么】** 老师强调"这跟算法原理没关系，它只是一个数学的变形"——这句很重要。看代码时要能区分**算法逻辑**和**数值稳定性技巧**，否则会误以为 `exp` 和 `log` 是 RoPE 原理的一部分。
- **【连接】** 这个套路你要能一眼认出，因为它到处都是：LogSumExp、log-probability、`torch.logaddexp`。凡是看到"先取 log 再 exp"，八成就是在防溢出/下溢。

### 32 你至少在两个地方见过这个套路（01:26:00 – 01:26:30）

> **谢博**：「这个套路以前是见过的呀，你至少在两个地方见过。……第一个我们在求导数的时候，有一个导数的表示，它是指数部分也有自变量，底数部分也有自变量，那是没有公式可以套的，当时我们说要改写这个表达式。还有一个套路你应该也经历过：当我们求 softmax 或者是 sigmoid 函数的时候，你是不是也会用这个技巧？因为你怕 e 的多少次方容易造成溢出。」

- **【推导/代码】** ①幂指函数求导：`y = x^x` 无公式可套，改写成 `y = e^(x·ln x)` 再链式求导。②softmax 的数值稳定写法：`softmax(x)ᵢ = exp(xᵢ − max(x)) / Σ exp(xⱼ − max(x))`，先减最大值再取指数，防 `exp` 上溢。
- **【为什么】** 把新知识挂到已有知识上，是老师的一贯做法。你的收获不是记住这一个技巧，而是建立一条索引：**"底数和指数都在变" → 换成 e 的形式**。
- **【连接】** PyTorch 的 `F.cross_entropy` 内部就是 `log_softmax + nll_loss`，正是为了避免你先 softmax 再 log 的两步溢出。这也是为什么 YOLO 的分类损失从来不让你手动 softmax。

### 33 torch.arange(0, d, 2) 产生的就是公式里的 2i（01:26:25 – 01:31:35）

> **谢博**：「`torch.arange` 0 到 embedding 的长度，比如说我们在这里是 4，那这里是不是产生一个 tensor 嘛？是不是 0，这里是 2？然后你以为还有 4 嘛，但是我们说这个 range 最后面那一位它是不包含的嘛，**前包后不包**。所以这个结果就是 [0, 2]。……所以这个 0 和 2 就相当于公式里面的 2i。……你的 embedding 是 4 个数，这两个是 i 等于 0，这两个是 i 等于 1。」

- **【推导/代码】** d=4 时：`torch.arange(0, 4, 2) = tensor([0, 2])`，`.float()` 后是 `[0., 2.]`。这两个数就是公式里的 `2i`（i=0 和 i=1）。于是 `div_term = exp([0,2] × (−ln10000/4)) = [1.0, 0.01]`。**这两个数就是后面 RoPE 里的 θ₀ 和 θ₁**，一分不差。
- **【为什么】** 老师在这里对着学生发了脾气（"说明你连 torch.arange 都没搞懂"），因为这是把公式和代码接上的唯一一步。公式里写 `2i`，代码里没有任何一个变量叫 i——它是被 `arange` 的 step=2 隐式生成的。看不出这一层，代码和公式就永远是两张皮。
- **【连接】** `arange` 的左闭右开是 Python 全家的统一约定（`range`、切片、`arange`）。你写 `pos_encoding[:, 0::2]` 时用的也是同一套切片语义：从 0 开始步长 2。

### 34 加了 PE 之后：权重不一样了，但本质是输入不一样（01:32:50 – 01:37:45）

> **谢博**：「加完之后你再做注意力机制，你就发现相同位置提取出来的特征就不一样了。……这个是在这句话里面'我'是第一个位置，这是在这句话里面'我'是第三个位置。你看它的这个编码形式是不是不一样了？这个 0.3 这是 1.4。……其实是因为你输入不一样，所以才会导致这个不一样。因为你的自注意力模块是同一个自注意力模块，加了位置编码它不一样，进去之后权重也不一样。」

- **【直译】** 加 PE 之后，同一个词"我"在位置 0 和位置 2 拿到的输入向量不同了（`0.3367 + PE(0,0)` vs `0.3367 + PE(2,0)`），于是产生的 Q/K/V 不同，注意力权重不同，输出特征也不同——置换等变被打破。
- **【推导/代码】** 用真数据：`PE(0,·) = [sin0, cos0, sin0, cos0] = [0, 1, 0, 1]`；`PE(2,·) = [sin2, cos2, sin0.02, cos0.02] ≈ [0.909, −0.416, 0.020, 1.000]`。加到 `[0.3367, 0.1288, 0.2345, 0.2303]` 上得到两个明显不同的向量。**注意 pos=0 那一行的 sin 全是 0、cos 全是 1，这就是老师说"这个地方都是 0，没关系"的原因。**
- **【为什么】** 老师最后那句自我纠正很关键："本质上是因为你输入不一样。" 位置编码没有改动网络的任何一个参数，它只是改了输入。这也是为什么它能作为一个纯粹的"前置模块"插进任何 Transformer。
- **【连接】** 同一个模块 + 不同输入 = 不同输出，这是最基础的函数概念。但学生容易在这里犯迷糊，以为"加了位置编码所以注意力变聪明了"——不是，注意力还是那个注意力。

### 35 【画面】那张热力图怎么读（01:38:56 – 01:42:50）

### 36 长序列同质化：正余弦的死穴（01:42:14 – 01:44:20）

> **谢博**：「我们发现这个位置向量，从这个位置开始（假如说这个是 80）后面，它的那个值就都一样了。就 token1 的位置编码后面那 40 个数，和 token2 的位置编码后 40 个数是一样的。……随着序列长度增加，那假如说是 1 万的话，那就更加会产生灾难性的效果。……那它就起不了这个位置标记的作用了。……现在一个大模型都可以百万个 token 一起进去了，你百万 token 你用这个编码，后面这个位置完全就同质化了，那他就没法去区分这个位置了。」

- **【画面】PPT 第 20 页文字（本课最重要的一页结论）**：标题「正余弦位置编码不足：高频维度震荡加剧，长序列编码同质化」。核心发现：「随序列长度增加，高维度位置编码快速震荡，不同位置的编码值差异缩小，导致模型难以区分长序列末端的精细位置。」三条：①维度频率特性：高频震荡导致同质化；②核心机制缺陷：固定频率引发过震荡，频率由 `10000^(2i/d_model)` 决定，缺乏自适应能力；③业务影响：长文本上下文理解偏差，「在处理万字文档或长对话时，模型易混淆末尾段落的语义位置」。
- **【推导/代码】** 这里必须给出正确的机制（PPT 措辞有误导，见纠错表 B-6）：i 越大 → `10000^(2i/d)` 越大 → 角频率 `ωᵢ` 越小 → **波长越长**。d=128 时最后一组的波长约 `2π×10000 ≈ 62800`，也就是说在 1000 个位置的范围内，这一维总共才转了不到 1/60 圈，相邻位置的差异小到浮点精度都快分不出。所以图右侧是**低频饱和**（沿位置方向几乎不变），不是"震荡太快"。老师读出来的"80 后面的数都一样"完全正确。
- **【为什么】** 这就是 RoPE 出场的全部理由。**注意：这里坏掉的不是编码本身（它确实还在变），而是"变化量太小以至于下游注意力分辨不出"。** RoPE 的修法不是把变化搞大，而是换一条赛道——让位置信息进入**内积**而不是进入**数值**。
- **【连接】** 现代长上下文技术（Position Interpolation、NTK-aware scaling、YaRN）改的都是这个频率分布。你要是能把"波长 vs 序列长度"这层讲清楚，就已经超过大部分候选人了。

---

**【小结】** ①`exp(−log(10000)/d)` 只是防溢出的等式变换，与算法原理无关；②`torch.arange(0, d, 2)` 隐式生成公式里的 `2i`，`div_term` 只有 `d/2` 个元素；③加 PE 打破置换等变，本质是"输入变了"而非"网络变聪明了"；④正余弦的死穴是长序列下高维（低频）饱和、相邻位置编码趋同，百万 token 时代彻底失效。

## Part 7 · 旋转位置编码 RoPE：从加法到乘法（01:45:01 – 02:05）

**【本段在讲什么】** 最后 20 分钟。谢博的讲法是"望文生义 + 逐步落地"：旋转 → 就得有向量、有角度、有旋转矩阵 → 那 embedding 是不是向量？→ 但一整个 128 维向量没法"转"，于是两两一组切成平面 → 每个平面转一个角度 θᵢ → 最后一个问题：θᵢ 到底是多少？答案是直接继承正余弦的那套频率。这条链条推得很干净。他没讲的（也是最值钱的）是 RoFormer 论文式(16) 的相对位置恒等式，我在最后两条里补上。

### 37 所谓位置编码，就是"把 embedding 搞得不一样"（01:45:12 – 01:45:40）

> **谢博**：「然后我们再看另外一种编码方式，叫旋转位置编码。记住：所谓的位置编码，就是要把这个 embedding 搞得不一样。……也许这些说法有点糙，但是这是最简单的理解方式，你觉得呢？」

- **【直译】** 把 Part 5 的结论当作定义：位置编码 = 一个"让不同位置的向量产生差异"的算子。它可以是加法（正余弦），也可以是乘法（旋转）。
- **【为什么】** 这句话是全课的枢纽。老师用它把两种方案统一到同一个功能框架下，于是 RoPE 就不是"一个新的复杂东西"，而是"同一个坑的另一种填法"。**教学上这一手很高明。**
- **【连接】** 一句话对比：正余弦是 `x' = x + PE(pos)`，RoPE 是 `x' = R(pos)·x`。加法会改变模长和方向，旋转只改方向、模长严格不变——这是 RoPE 的第一个数学优势。

### 38 旋转是什么：模长不变，角度改变（01:45:39 – 01:47:07）

> **谢博**：「旋转，那旋转就会想到向量嘛。……比如说这里有个向量，我说旋转 45 度，是不是把这个向量旋转到这个位置来了呀？旋转后的这个向量和之前的这个向量，有什么相同有什么不一样？**长度一样**，但是它的角度不一样，当然坐标也会不一样。……然后旋转在这个图上面我们有两种坐标去理解它：一种是 XY 轴，还有一种是极坐标。那旋转这个关系，是用 XY 轴这种几何坐标去理解它，还是用极坐标去推导它更加容易呢？极坐标。」

- **【直译】** 旋转的定义性特征：模长（长度）不变，辐角改变。描述一个二维向量有两套坐标——直角坐标 (x,y) 和极坐标 (r, α)。推旋转公式用极坐标最省事，因为旋转在极坐标里就是"α 加上 θ"，一步到位。
- **【推导/代码】** 转换关系：`x = r·cos α`，`y = r·sin α`；`r = √(x²+y²)`，`α = atan2(y, x)`。
- **【为什么】** "模长不变"这一条是 RoPE 全部数学优雅性的来源：旋转矩阵是**正交矩阵**（`RᵀR = I`），所以 `‖R(θ)x‖ = ‖x‖`。这意味着加位置信息**不会改变 Q/K 向量的能量**，也就不会扰动注意力 logits 的整体尺度——不像加法编码，加完之后向量长度变了，softmax 的温度就被隐式改了。
- **【连接】** 正交变换保内积这个性质，你在 3D 点云里天天用：旋转矩阵作用在点云上不改变点之间的距离，这也是数据增强里"随机旋转"安全的原因。

### 39 (1,1) 转 45° 得到什么，46° 又怎么办（01:47:26 – 01:48:26）

> **谢博**：「你看我举一个很简单的例子啊，这个向量 (1,1) 逆时针旋转 45 度，那这个向量会变成多少？……那我说不是 45 度是 46 度，我说旋转 46 度，然后它旋转后新的位置这个向量是多少？那你如果不会这个公式，那是不是就不知道它是多少的呀？」

- **【推导/代码】** 正确答案是 **(0, √2) ≈ (0, 1.4142)**，不是 Whisper 转出来的 "(0,1)"。验算：`|(1,1)| = √2`，旋转保模长，转 45° 后正好落在 y 轴上，所以是 `(0, √2)`。**这正是上一条"模长不变"的第一个应用**，也是老师板书上写的那个带根号的式子（帧 244 手写可见）。若换成 46°：`x' = cos46°·1 − sin46°·1 ≈ 0.6947 − 0.7193 = −0.0246`，`y' = sin46°·1 + cos46°·1 ≈ 1.4140`，模长仍是 √2。
- **【为什么】** 老师用"45 度你能心算，46 度你就不行了"来制造对公式的需求——这是很好的教学设计，把公式从"要背的东西"变成"不得不有的工具"。
- **【连接】** 面试如果被问"RoPE 为什么用旋转不用别的变换"，第一句就答"因为旋转是正交变换，保模长保内积"，然后用 (1,1)→(0,√2) 这个例子说明。

### 40 【画面】旋转矩阵的五步推导（01:48:30 – 01:52:10）

> **谢博**：「你看这两个等式，是不是可以写成两个向量相乘呢？……那这个矩阵应该怎么填呢？这一行乘这一列是不是 x'？所以这里是 cos，这里呢 −sin。……其实这个矩阵就叫什么呢？就叫**旋转矩阵**。」

- **【画面】PPT 第 26 页「旋转矩阵的推导过程」五步全文**：
  `01. 极坐标表示原向量`：`(x, y) = (r cos α, r sin α)`
  `02. 旋转后的极坐标（逆时针 θ）`：`(x', y') = (r cos(α+θ), r sin(α+θ))`
  `03. 应用三角和角公式展开`：`cos(α+θ) = cos α cos θ − sin α sin θ`；`sin(α+θ) = sin α cos θ + cos α sin θ`
  `04. 代入原坐标并整理`：`x' = x cos θ − y sin θ`；`y' = x sin θ + y cos θ`
  `05. 最终结果：旋转矩阵 R(θ)` = `[[cos θ, −sin θ], [sin θ, cos θ]]`
- **【推导/代码】** 第 4 步的关键代换：把 `r cos α` 换回 `x`、`r sin α` 换回 `y`，`r` 就自动消掉了——这就是为什么旋转和向量的长度无关，同一个 `R(θ)` 对所有长度的向量都成立。
- **【为什么】** 这一段是全课唯一一次完整的数学推导，而且推得很利落：极坐标 → 和角公式 → 换回直角坐标 → 提取矩阵。老师说"你也可以直接记住它"，但推一遍的价值在于你能记住 **负号在右上角**（`−sin θ`）这个最容易记反的细节。
- **【连接】** 顺带回收 Part 4「PPT 两条性质」那一条的伏笔：PPT 讲正余弦时给过的那两条和角公式，就是这里第 3 步用的同一个东西。**正余弦编码和 RoPE 共用同一套三角学基础**，这不是巧合。

### 41 【画面】RoFormer Figure 1：每两维当作一个平面（01:52:22 – 01:56:10）

> **谢博**：「我们的这个 embedding 是不是也是个向量呢？只不过说我们这个向量比较长，刚刚举的是一个 2 维的向量，但现在我们可能是 128 或者 512 或者 768 或者 1024。那这个向量是不是也可以旋转呢？当然了。**但它不是整个向量去旋转**——整个去旋转那就麻烦了，因为它有很多个平面了，你是沿哪个平面旋转还是沿 x 轴？」

- **【画面】PPT 第 28 页 = RoFormer 论文 `Figure 1: Implementation of Rotary Position Embedding(RoPE)`**：上半部分是 `d=2` 的示意——`(x₁, x₂)` 标注为 **Query / Key**，配一个 `θ₁ Constant` 和一个 `m Position`，箭头指向坐标系里从 `(x₁,x₂)` 转 `mθ₁` 到 `(x'₁, x'₂)`，结果标注为 **Position Encoded Query / Key**。下半部分是句子 `Enhanced / Transformer / with / Rotary / Position / Embedding` 六个词，每个词的 Query/Key 被涂成成对的色块并标 `θ₁ θ₂ … θ_{d/2−1} θ_{d/2}`，中间一列 Position 是 `1 2 3 4 5 6`，右侧输出 `Position Encoded Query / Key`。
- **【推导/代码】** 高维向量没有唯一的"旋转"（n 维旋转群有 n(n−1)/2 个自由度），所以 RoPE 做了一个约定：**把 d 维空间拆成 d/2 个互不相干的二维子空间（第 0-1 维一个、第 2-3 维一个……），每个子空间里独立做一次平面旋转。** 论文原话是 "we divide the d-dimension space into d/2 sub-spaces"。
- **【为什么】** 这个图 **明确把被旋转的对象标成 Query/Key，不是 embedding**。这是老师口头讲法里省掉的一层（他一直说"对 embedding 旋转"），但对理解 RoPE 至关重要，见纠错表 B-4。
- **【连接】** 又一次回收 Part 4「维度两两成对共享一个角度」这条伏笔：正余弦已经在做"两两成对共享一个 θ"，RoPE 只是把这一对数从"填 sin/cos"改成"在这个平面上真的转 θ 度"。**同样的分组，不同的用法。**

### 42 4 维 → 2 个 θ，128 维 → 64 个 θ（01:56:10 – 01:59:20）

> **谢博**：「假如说我们的 embedding 长度是 4 好吧，这是 0.1、0.2、0.3、0.4，这四个数就是 Enhanced 这个词的 embedding。然后对它干嘛呢？我们不会把这个向量一起来旋转，那我们怎么做呢？把这两个看作一个 2 维的向量，这两个看作一个 2 维的向量。然后旋转 θ₁，这个旋转 θ₂。……那如果说你的 token 长度不是 4 是 128，那有 64 个 θ。」

- **【推导/代码】** 分组规则：`[x₀,x₁]` 转 `θ₁`，`[x₂,x₃]` 转 `θ₂`，……，`[x_{d−2}, x_{d−1}]` 转 `θ_{d/2}`。所以 **d 必须是偶数**——代码里那句 `if dim % 2 != 0: raise ValueError("RoPE requires even dimension")` 就是在守这条约束。
- **【为什么】** 不同的组转不同的角度，才能让整个 d 维向量的"位置指纹"足够丰富。如果所有组都转同一个角，那 d 维就退化成了一个角度，区分能力和一维一样差。**这就是"多频率"设计的意义**——和正余弦的多频率完全同源。
- **【连接】** 老师现场说了句"那你这里是不是有 118"随后自己改口"有 64 个 θ"，前者是口误（128/2=64），见纠错表 B-2。

### 43 θᵢ 到底是多少：直接继承正余弦（01:59:20 – 02:01:35）

> **谢博**：「但现在还有个问题，就是 θ₁ θ₂ 到底是多少？是 30 度还是 40 度还是 20 度？……你要告诉我旋转多少度，要不然你给了我 0.1 0.2 0.3 0.4，我还是算不出它旋转位置编码之后的那个 embedding。……其实 θ₁ θ₂ 的计算，就跟我们刚刚那个余弦位置编码里面的那个 pos 除以 1 万的多少次方是一样的。……**继承了正余弦位置编码里面那个计算方式**。」

- **【画面】RoFormer 论文式(15) 下方原文**：`Θ = {θᵢ = 10000^(−2(i−1)/d), i ∈ [1, 2, ..., d/2]}`。代码写法（i 从 0 起）：`inv_freq = 1.0 / (10000 ** (torch.arange(0, dim, 2).float() / dim))`。
- **【推导/代码】** 第 m 个位置、第 i 组的实际旋转角是 **`m · θᵢ`**（论文记作 `mθᵢ`，代码 `angles = positions.unsqueeze(1) * inv_freq.unsqueeze(0)`，形状 `[seq_len, d/2]`）。d=4 时：`θ₀ = 1/10000⁰ = 1`（弧度），`θ₁ = 1/10000^0.5 = 0.01`。
- **【为什么】** 这是理解 RoPE 的最后一块拼图，也是最漂亮的一块：**RoPE 并没有发明新的频率方案，它把正余弦的频率原封不动搬过来，只改了"怎么用"——从"当成数值加上去"改成"当成角度转过去"。** 你要是能把这句话说清楚，面试官就知道你真懂了。
- **【连接】** 老师在这里有一句口误："然后除以他的这个句子的长度，最大多少" —— θᵢ 的分母是 `10000^(2i/d)`，与句子长度无关；序列长度只以 `m` 的形式**乘在外面**。见纠错表 B-1，这个说错了会当场露馅。

### 44 【画面】位置1 / 位置2 的 4×4 旋转矩阵实测数值（02:01:35 – 02:03:10）

> **谢博**：「所以看这个下面是不是又看得懂了？这个是不是整个的一个旋转矩阵了？……因为你这个矩阵只是两个数嘛，这个矩阵是不是也是两个数啊？然后把整个 embedding 放在一起，那它的旋转矩阵就是这个。……这个旋转矩阵它是不是很多 0 呢？很稀疏。」

- **【画面】PPT 第 31 页（seq_len=4, dim=4 实跑输出）**：
  `位置1的4×4旋转矩阵（含大量0）`：
  `[[ 0.5403, −0.8415,  0.0000,  0.0000],`
  ` [ 0.8415,  0.5403,  0.0000,  0.0000],`
  ` [ 0.0000,  0.0000,  0.9999, −0.0100],`
  ` [ 0.0000,  0.0000,  0.0100,  0.9999]]`
  `位置2的4×4旋转矩阵`：
  `[[−0.4161, −0.9093,  0.0000,  0.0000],`
  ` [ 0.9093, −0.4161,  0.0000,  0.0000],`
  ` [ 0.0000,  0.0000,  0.9998, −0.0200],`
  ` [ 0.0000,  0.0000,  0.0200,  0.9998]]`
- **【推导/代码】** 逐个验算，全对上：`θ₀=1` → 位置1 的左上块是 `[cos1, −sin1; sin1, cos1] = [0.5403, −0.8415; 0.8415, 0.5403]` ✓；位置2 是 `[cos2, −sin2; sin2, cos2] = [−0.4161, −0.9093; 0.9093, −0.4161]` ✓。`θ₁=0.01` → 位置1 右下块 `[cos0.01, −sin0.01; …] = [0.9999, −0.0100; 0.0100, 0.9999]` ✓；位置2 是 `[cos0.02, −sin0.02; …] = [0.9998, −0.0200; …]` ✓。

### 45 为什么写成大稀疏矩阵 + 相对位置恒等式（02:02:27 – 02:03:20）

> **谢博**：「那这样子的话为什么要写成这个样子呢？为什么你不去——如果让我们来做，我们先把这个 embedding 先拆，这里两个数、这里两个数，然后每两个数跟这个做矩阵相乘。那这样子写是不是又是**并行**，一次就做完了？……跟我们多头注意力一样。」

- **【画面】RoFormer 3.2.2 General form 原文（PPT 第 29 页）**：
  式(14)：`f_{q,k}(xₘ, m) = R^d_{Θ,m} · W_{q,k} · xₘ`
  式(16)：`qₘᵀ kₙ = (R^d_{Θ,m} W_q xₘ)ᵀ (R^d_{Θ,n} W_k xₙ) = xᵀ W_q R^d_{Θ,n−m} W_k x`
- **【推导/代码】** **式(16) 是整个 RoPE 的心脏，也是老师完全没讲的部分。** 推导只用一步：旋转矩阵满足 `R(a)ᵀ R(b) = R(b − a)`（转 a 再转回来、再转 b，等于净转 b−a）。于是两个 token 的注意力分数只依赖 `n − m`——**绝对位置在内积里自动消掉了，只剩相对距离。** 这才是"显式相对位置建模"和"外推能力"的数学根源，不是"角度切了很多份"。
- **【为什么】** 老师讲的"写成大矩阵是为了并行"是工程理由（虽然实际实现反而用的是逐元素的 `x*cos + rotate_half(x)*sin` 优化形式，代码里两种写法都给了并做了误差对比验证）。而**式(16) 是原理理由**：无论句子多长、m 和 n 有多大，只要距离不变，注意力分数就不变。所以模型在训练时只见过 4K，推理时给 8K 也不会遇到"没见过的位置数值"——它见到的永远只是相对距离。
- **【连接】** 面试完整回答的最后一句：「RoPE 通过 `R(m)ᵀR(n) = R(n−m)` 把绝对位置消解成相对位置，因此长度外推时不会遇到分布外的位置编码，性能衰减平缓。」

### 46 外推能力，与两种编码的最终对比（02:03:33 – 02:04:56）

> **谢博**：「它的好处是什么呢？看到没有，**卓越的长序列外推能力**。什么意思呢？就不会出现正余弦位置编码那样：如果你的序列一长，到了高位的那个位置，它所有的位置数据都是一样的了。」
> **学员**：「……在 token 很长的情况下，它不会有重复吧？」
> **谢博**：「这个不会。你们回去想一下好吧。它相当于把这个角度也切了很多份。好，这个就是旋转位置编码。」

- **【画面】PPT 第 32 页最终对比表**：
  **正余弦位置编码 (Sinusoidal PE)**：核心原理 **加性融合**（通过正弦余弦函数生成固定位置向量，直接与词向量相加）；**相对位置建模弱**（仅能隐式捕捉相对位置，模型学习负担重，难以直接理解词间关系）；**长序列外推能力差**（序列过长时高频分量区分度下降，导致性能显著衰减）。
  **旋转位置编码 (RoPE)**：核心原理 **乘性旋转**（将位置信息编码为旋转角度，对 Q/K 向量进行正交旋转变换）；**显式相对位置建模**（严格数学证明内积仅依赖相对位置差，直接高效地建模词间关系）；**卓越的长序列外推能力**（旋转矩阵维持长距离关系，性能衰减平缓，是大模型长文本标配）。
  总结：「从加性融合到乘性旋转，从隐式建模到显式编码，RoPE 凭借其优异的数学性质和长序列表现，已成为现代大语言模型的标准位置编码方案。」
- **【为什么】** 老师留的那个思考题（"角度会不会转回来重复"）的答案值得补上：**会，但不致命。** 单看第 i 组，`m·θᵢ` 确实是周期的（周期 `2π/θᵢ`），最快的一组 i=0 每 `2π≈6.28` 个位置就转一圈。但 d/2 个组的周期各不相同、且比例是无理数关系，**d/2 个角度组成的联合"指纹"在极长范围内不重复**——这正是老师说的"把角度切了很多份"的严格版本。真正限制 RoPE 外推的不是周期重复，而是低频组在训练时没转满一圈、推理时转到了没见过的区域，这才有了后来的 PI / NTK / YaRN 那一堆插值方法。
- **【连接】** 完整对比记忆卡：**加法 vs 乘法 / 改数值 vs 改角度 / 加在输入端一次 vs 每层 QK 都转 / 隐式相对 vs 显式相对 / 外推差 vs 外推好。** 五句话讲完 RoPE，够任何一场面试用。

---

**【小结】** ①RoPE 把 d 维切成 d/2 个平面，每个平面在位置 m 处转 `m·θᵢ` 度；②θᵢ 完全继承正余弦的频率 `10000^(−2i/d)`，创新在"当角度用"而不是"当数值加"；③旋转是正交变换，模长严格不变，位置信息不污染特征能量；④核心恒等式 `R(m)ᵀR(n) = R(n−m)` 让注意力分数只依赖相对距离，这是外推能力的真正来源；⑤RoPE 作用在**每一层的 Q、K** 上，不作用在 V 上，也不是在输入 embedding 上加一次。

### 复习最小集（三句话，背下来就够）

1. **自注意力对序列维是"置换等变"的，不是"置换不变"的。** 把"我吃饭"换成"饭吃我"，输出张量整体确实不同，但**同一个词在两个句子里提取到的特征向量逐位相等**（实测 `output1[0] == output2[2] == [0.1719, 0.2484, −0.4549, 0.1084]`）。根源是 QKV 投影逐位置独立、softmax 与位置无关，整条链路上没有任何算子知道"你是第几个"。所以必须外挂位置信息来打破这个对称性。

2. **正余弦位置编码 = 加法。** `PE(pos,2i)=sin(pos/10000^(2i/d))`，`PE(pos,2i+1)=cos(...)`；维度**两两成对共享一个角度**，取值有界在 [−1,1] 所以敢直接和 embedding 相加；工程上写成 `exp(2i · (−ln10000/d))` 纯粹是防溢出。死穴：i 越大波长越长（d=128 时最长约 6.28 万），长序列下高维分量沿位置方向几乎不变，**相邻位置编码趋同**，百万 token 时代彻底失效。

3. **RoPE = 乘法。** 把 d 维切成 d/2 个平面，位置 m 处第 i 个平面转 `m·θᵢ`，`θᵢ = 10000^(−2i/d)` **完全继承正余弦的频率，只是把它从"数值"改成"角度"**；旋转是正交变换所以模长严格不变；作用在**每一层的 Q、K** 上（不碰 V，也不是输入端加一次）。它能外推的真正理由是恒等式 **`R(m)ᵀR(n) = R(n−m)`** ⇒ `qₘᵀkₙ` 只依赖相对距离 `n−m`，绝对位置在内积里自动消掉。d=4 的实测矩阵：位置1 = `[[0.5403,−0.8415,0,0],[0.8415,0.5403,0,0],[0,0,0.9999,−0.0100],[0,0,0.0100,0.9999]]`（θ₀=1, θ₁=0.01）。
