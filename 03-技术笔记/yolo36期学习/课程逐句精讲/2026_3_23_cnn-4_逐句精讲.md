## Part 1 · 还债：BN 的均值方差到底来自哪一批（00:00:00 – 00:24:03）

**【本段在讲什么】** 上节课留了一个悬案：BN 的官方说法「训练时用该批次的均值方差，**推理时用基于所有批次的期望**」，学员（张师兄）死活转不过弯——推理的时候哪还有 batch？老师这 24 分钟没有讲新知识，而是干了一件更重要的事：**把"训练/推理"这个二分法拆成三个阶段**，争议句立刻自洽。最后他带着大家翻 PyTorch 官方 `BatchNorm2d` 文档，用 `momentum=0.1` 和 `running_mean` 的滑动平均公式收尾。这一段是"术语歧义引发的伪问题"的经典标本，面试里也常考。

### 1 上节课的算式尾巴：LN 到底沿哪个轴求平均（00:00:00 – 00:02:02）
> **文老师**：「再加起来，还有一步没有求平均，还要求一次平均……所有对应位置的通道加起来求一个平均。这边这个图示但是它不一样啊，它是自己跟自己加；而 BN 是要……把比如三张图、三个图相同的通道加起来求的平均。」

- **【直译】** 开场是把上一节 LayerNorm / BatchNorm 的那张图补完：LN 是"一个样本内部、跨通道"求均值方差；BN 是"跨样本、同一通道"求均值方差。
- **【推导/代码】** 对输入 `(N, C, H, W)`：BN 沿 `(N, H, W)` 三个维度聚合，得到 `C` 个 μ 和 σ²；LN 沿 `(C, H, W)` 聚合，得到 `N` 个 μ 和 σ²。老师口中"1+4+7+2+5+8+3+…再除"就是在数 LN 那条求和路径。
- **【为什么】** 他要先把"沿哪个轴"钉死，后面"推理时的期望"才有讨论基础——因为争议的核心恰恰是"聚合的范围"。
- **【连接】** BEVFusion 的 SECOND 骨干里每个 `SparseConv3d` 后面跟的是 `BatchNorm1d`，聚合轴是"所有体素"；而 Transformer 那条线（BEVFormer）用的是 LayerNorm。你以后看到 norm 层第一件事就是问：**它沿哪些轴聚合**。

### 2 争议句本体：「推理时基于所有批次的期望计算所得」（00:02:02 – 00:08:01）
> **文老师**：「其实这里就是算的是 X 的均值方差，还是算的是 gamma、beta 的？……算的是 X 的。最开始是对的，后来被你们搞错了啊。」

- **【直译】** 第一个歧义先被排掉：BN 里滑动平均记录的是**输入 x 的均值与方差**，不是可学习参数 γ、β。γ、β 是靠梯度学出来的，跟"批次期望"没有关系。
- **【画面】** PPT 上写着「**四、训练与推理时 BN 中的均值、方差分别是什么？此问题是 BN 争议最大之处**，正确答案是：训练时，均值、方差分别是**该批次**内数据相应维度的均值与方差；推理时，均值、方差是**基于所有批次**的期望计算所得」，公式 `E[x] ← E_B[μ_B]`、`Var[x] ← m/(m−1)·E_B[σ²_B]`。右半屏是 BN 原论文（Ioffe & Szegedy）的 Algorithm 2 截图，第 10 行 `Process multiple training mini-batches B, each of size m, and average over them` 被老师用红框圈了出来。
- **【为什么】** `m/(m−1)` 是**无偏方差修正**（贝塞尔校正）：训练时每个 batch 只有 m 个样本，用有偏估计；推理时要还原成总体方差，所以乘 `m/(m−1)`。这一项在 PyTorch 实现里被吸进了 `running_var` 的更新里，代码上看不见。
- **【连接】** 这就是 `state_dict` 里 `running_mean` / `running_var` 两个 buffer 的来源——它们**不是参数**（`requires_grad=False`），但会被 `torch.save` 存进权重文件。

### 3 关键手术：把二分法拆成三个阶段（00:09:00 – 00:14:01）
> **文老师**：「其实这里是三个阶段。第一个是训练阶段，就是该批次的均值和方差；第二个阶段是你有一个保存，你保存的是那个 VAL 最佳的均值和方差；然后第三个，就是这个叫脱离训练时……脱离实验室，我们叫生产使用。」

- **【直译】** 老师把整条流水线切成三段：**① 训练**（用当前 batch 的 μ/σ²）→ **② 验证/保存权重**（此时用的是滑动平均值，并按验证指标挑最优 checkpoint）→ **③ 生产推理**（读死保存下来的那份 μ/σ²）。
- **【推导/代码】** 对应到 PyTorch 就是三行状态切换：`model.train()` 走分支 A（batch 统计量 + 更新 running 值）；`model.eval()` 走分支 B（直接读 running 值）；导出后的 ONNX 里 BN 已经被折叠成一次线性变换 `y = a·x + b`，连分支都没有了。
- **【为什么】** 争议的根源是"推理"这个词被用在两个地方：**验证集上的 forward 也叫推理**，生产环境的 forward 也叫推理。原文那句"推理时"指的是**第二类**（脱离 batch 统计、改读 running 值的那一刻），而学员理解成了第三类（线上部署）。拆成三段，两种理解各归其位。
- **【类比】** 老师随后用"实验室 → 公司"复述了一遍：训练+验证 = 实验室，生产 = 出社会；实验室攒下的 μ/σ² 就是"经验值"，出社会直接带着用。这也顺带解释了**微调时为什么常要冻结 BN**——换了域，旧"经验值"硬用会掉点。
- **【连接】** 这一刀对你写 BEVFusion 的 eval 脚本极其实际：忘了 `model.eval()`，BN 会继续用当前 batch 统计量并且污染 `running_mean`，验证 mAP 会随 batch size 抖动——这是新人最常踩的坑之一。

### 4 为什么不能在推理时现算 batch 统计量（00:12:13 – 00:16:00）
> **文老师**：「因为你推理的、生产使用的时候，你不知道你的 batch 是几……你训练的是 32，大部分时候你推理根本就用不上 32，我们不知道的。你无法控制这个事情。」

- **【直译】** 生产环境的 batch size 是**不可控**的：可能是 1（单帧摄像头进来），可能是 8（凑一个小批）。BN 如果现场算统计量，同一张图在不同 batch 里会得到不同输出——推理结果不可复现。
- **【推导/代码】** 极端情况 batch=1 时，`Var[x]` 在 (N,H,W) 上聚合虽然还有 H×W 个数不至于为 0，但对 `BatchNorm1d` 的 `(N, C)` 输入会直接方差为 0 → 除零。PyTorch 里 `BatchNorm1d` 在 train 模式下 batch=1 会直接报 `Expected more than 1 value per channel`。
- **【为什么】** 这就是 BN 必须"冻结统计量"的工程理由：**推理要确定性**。同样的输入必须给同样的输出，否则测试、验收、回归全都没法做。
- **【连接】** 也正因为这个缺陷，检测/分割里 batch 很小的场景更爱用 **GroupNorm / LayerNorm**（跟 batch 无关）。BEVFormer 用 LN 而不是 BN，一部分原因就在这里。

### 5 翻文档定案：momentum=0.1 与 track_running_stats（00:17:07 – 00:23:00）
> **文老师**：「我拍它去那个方案，找那个 BatchNorm2d 啊，他上面有一些解释的……在这里有一个滑动平均的，对不对？就是说他训练的时候，他会存一个值，这个是用滑动平均的。……他这里已经说了，其实有个参数，你不要滑动平均，你就把这个参数设成 False。」

- **【直译】** 老师让学员打开 `docs.pytorch.org` 的 `torch.nn.BatchNorm2d` 页面，用官方文档一锤定音。
- **【画面】** 文档正文清晰可读：`estimates are kept with a default momentum of 0.1`；Note 框里写着更新式 **`x̂_new = (1 − momentum) × x̂ + momentum × x_t`**，其中 `x̂` 是当前估计值、`x_t` 是新观测值；再往下是 `If track_running_stats is set to False, this layer then does not keep running estimates, and batch statistics are instead used during evaluation time as well.`；Parameters 里 `num_features (int) – C from an expected input of size (N, C, H, W)`、`eps` 默认 `1e-5`、`momentum` 可设 `None` 表示累积移动平均。
- **【推导/代码】** 注意 PyTorch 的 momentum 语义**和优化器里的 momentum 相反**：这里 momentum 越大，越看重"新来的这个 batch"。默认 0.1 = 新 batch 占 10%、历史占 90%。老师那句"最后那一轮占的权重多一点，前面的少一点"说的正是这个几何加权。
- **【为什么】** 老师坚持翻文档而不是背结论，是在示范一种工作方式：**术语争议一律回官方文档裁决**。他最后总结「以后我们都说三个阶段了」，把教学口径也改了——这一点很值得学。
- **【连接】** 你训 BEVFusion 时若显存吃紧只能用 batch=1~2，可考虑 `SyncBatchNorm`（跨卡聚合统计量），或把 momentum 调小（如 0.01）让 running 值更稳——这不是玄学，就是上面那条更新式的直接推论。

> 🗀 折叠【00:15:14 – 00:24:03】学员继续追问"二和三是不是等同"、老师回答"其实二就等同于三"，以及关于教学口径要不要改的来回讨论。结论已在卡 3、卡 5 覆盖。

**【小结】**
1. BN 有三个阶段：训练（用 batch 统计量并更新 running 值）→ 验证/保存（读 running 值，按 val 指标存最优）→ 生产（读死的 running 值）。争议句里的"推理时"指的是第二类。
2. 滑动平均的官方公式是 `x̂_new = (1−momentum)·x̂ + momentum·x_t`，默认 `momentum=0.1`；`track_running_stats=False` 可以关掉它。
3. 推理必须冻结统计量的根本原因是**生产环境 batch size 不可控**，而推理结果必须确定性可复现。

## Part 2 · 轻量化网络：工业的四个字与四个手段（00:24:03 – 00:32:01）

**【本段在讲什么】** 正式开新章。老师先给"轻量化"下一个**工业定义**——不是学术上的 FLOPs 小，而是"准、便宜、快、稳"四个字凑齐才叫有竞争力。然后给出一张万能答案式的手段清单，并顺手把两个"看起来像轻量化其实不是"的技术（空洞卷积、反卷积）剔出去。最后用一个 64MB 内存板子的真实项目，让你体会嵌入式的残酷。

### 6 准、便宜、快、稳 = 竞争力 = 轻量化（00:24:03 – 00:26:01）
> **文老师**：「轻量级网络，其实就是又要准、又要便宜、又要快、又要稳。这就是你们以后叫要有竞争力的……现在模型都有，你的竞争力在哪里？你的竞争力就是怎么搞一个轻量化的。」

- **【直译】** 现在开源模型遍地都是，能跑通不算本事；**能把它塞进客户那块破板子里还保住精度，才是你的护城河**。
- **【画面】** PPT 标题「轻量化网络」，正文：`工业：准、便宜、快、稳 ⇒ 竞争力 / 轻量化`（老师用红笔把四个字各圈一个圈，再画箭头指向"竞争力""轻量化"）；下面两行是拆解——「**准确率**：残差基本上解决了 ACC 准确率的问题」「**便宜**：模型小、运行速度要快、占用内存也要少【轻量化】」。
- **【为什么】** 一句被很多人忽略的判断：**"准"这一维已经被 ResNet 解决了**——2015 年之后精度不再是差异化来源，工程价值转移到"同等精度下更便宜"，这就是 2017 年后轻量化论文井喷的原因。
- **【连接】** 对应到你的路径：BEV 感知在车上跑，Orin 的算力是硬约束，"同等 NDS 下延迟更低"就是量产岗位最核心的 KPI。你面试时讲"我把某模块从 X ms 优化到 Y ms 且 mAP 不掉"，比讲"我复现了某论文"值钱得多。

### 7 轻量化的四个手段（00:25:03 – 00:27:00）
> **文老师**：「模型轻量化的手段……这个模型的层数呢不多；然后呢一般都用 1×1 或者 3×3 的卷积，还就是分组卷积、还就是深度可分离卷积；……当然了我们肯定还要吸残差，所以这是 1、2、3、4。……这里有句话叫牺牲了精度获取速度。如果你不牺牲精度、获取了速度，那你很牛逼。」

- **【直译】** 四条：①层数少 ②只用 1×1 和 3×3（配合分组卷积、深度可分离卷积）③残差 ④牺牲精度换速度。
- **【画面】** PPT 原文（可完整辨认）：
  `1。模型的层数要少`
  `2。多用 1x1 和 3x3 卷积、空间可分离卷积、分组卷积(减少 1/G 参数量，但是不同组之间的信息没有沟通)、深度可分离卷积(g=in_ch, 1/9) + 1x1 卷积`
  `3。残差【稀疏】`
  `4。牺牲精度，获取速度。一般是边缘设备（PC，台式机，笔记本，APP手机，其它都可以称之为边缘设备）`
  老师在旁边补板书：`1x1 / 3x3 / DW(3x3) / ResNet`，并写下"不牺牲精度也获得速度"。
- **【推导/代码】** 括号里的两个数字很关键：**分组卷积 groups=G 参数量降到 1/G**；**深度可分离卷积就是 groups=in_channels 的极限分组，3×3 时参数量约 1/9**，再补一个 1×1 把通道信息拉回来。这正好接上你上节课学的 `nn.Conv2d(..., groups=)`。
- **【连接】** 你写 MNIST 默写模板时用的是 `Conv2d(3,16,3,1,1)`；换成 DW+PW 就是两行：`Conv2d(3,3,3,1,1,groups=3)` + `Conv2d(3,16,1)`。YOLOv8 里的 `C2f` 之所以比 YOLOv5 的 `C3` 快，本质也在于减少了大核标准卷积的占比。
- **【为什么】** 老师把这张清单称为"**万能答案**"：「你不知道的时候，你跟我这么去吹，至少能得六十分」——面试问"怎么做模型轻量化"，照这四条答一定不跑题。

### 8 两个"不是轻量化"的技术：空洞卷积与反卷积（00:25:03 画面）
> **【画面独有】** PPT 底部单列一块：「**与轻量化无关。** 空洞卷积：参数量不变的情况下，感受野变大。反卷积、转置卷积：是一种可学习的上采样的方法（双线性插值法）」——转写里完全没有这段。

- **【直译】** 老师特意把这两个划到轻量化之外：**空洞卷积不省参数（只是扩感受野）**；**转置卷积不是压缩手段（是上采样手段）**。
- **【推导/代码】** 空洞卷积的等效核 `k′ = d(k−1)+1`（3×3 + d=2 → 感受野 5×5，权重仍是 9 个）——正是 3/13 那节课推过的公式。转置卷积可以理解成"带可学习权重的插值"，与固定的双线性插值相比多了参数。
- **【为什么】** 这一条是防"混淆型面试题"的：很多人一被问轻量化就把 dilation 抬出来，实际上它一个参数都不省。

### 9 轻量级网络家族与工业选型（00:27:00 – 00:31:00）
> **文老师**：「轻量级网络呢，这叫系列，有很多，这里是我们网上去 copy 到的……我们现在用的最多的其实是这两个系列，MobileNet。下面这些系列呢有没有用呢？偶尔看到网上有些文章，他们公司就用的，但我也没用过，我就只用过 MobileNet。」

- **【画面】** 左侧一长串家族名单（可辨认）：`SqueezeNet系列 / ShuffleNet系列 / ChostNet(GhostNet) / MnasNet / MobileNet系列 / CondenseNet / ESPNet系列 / ChannelNets / PeleeNet / IGC系列 / FBNet系列 / GhostNet / EfficientNet / WeightNet / MicroNet`；右侧结论文字：「精度会下降，但是推理速度会快。CPU 推理和 GPU 都可用。**CPU 推理较快的 ShuffleNet V2；工业上应用成功案例最多的是 MobileNet**。」再下面：「做项目：先考察精度→速度，**它提取特征的模块是什么，有什么意义！**」「板端【嵌入式 C 语言，C++】—— 单片机【开始也支持 python】/ 内存空间小 / 推理速度要快」。
- **【直译】** 家族很大，但真正在产线上被验证过的就 MobileNet 和 ShuffleNet 两条线；老师本人只用过 MobileNet。
- **【为什么】** 选型不看论文指标看**成功案例数**——这是工程师和研究者最大的思维差异。案例多意味着踩坑记录多、算子在各推理框架里支持好（TensorRT/NCNN/TFLite 对 MobileNet 的算子覆盖是最全的）。

### 10 3.5MB 的极端案例：64MB 内存怎么被吃光（00:28:01 – 00:31:00）
> **文老师**：「我曾经做过一个项目，它是 AMD 的 CPU，没有 NPU，然后它的内存只有 64 兆。操作系统 mini linux 占 30 兆，摄像头跑起来还要用个 15 兆左右……他们在里面做了一些定制化的程序，又用了 10 兆……它最后留了多少呢？就留了 3.5 兆。」

- **【画面】** 老师在 PPT 上手写了一条减法账：`64内存 / AMD cpu / miniLinux 30MB / +15MB → 45MB / +10MB → 55MB`，最后画框圈出 `实际可用 3.5MB`。
- **【直译】** 64MB 的板子，系统 30 + 摄像头 15 + 定制程序 10 = 55MB，再扣掉系统必须的冗余，**留给你的模型加运行时只有 3.5MB**。
- **【推导/代码】** 3.5MB 什么概念：fp32 下 ≈ 90 万参数，int8 后 ≈ 350 万。而 `yolov5s` 有 720 万参数（fp16 就 14MB）——**直接放不下**，必须裁 width/depth 或换 backbone。这就是下一节三因子存在的全部理由。
- **【为什么】** 这是给"轻量化"一个体感尺度：「你实际可用的不会超过 4 兆，非常痛苦，搞了一两个月」。他还举了个更狠的：板子 **150KB**、模型只有 **29KB**——「这个就叫地狱难度，一年能搞定也是重大成果」。
- **【连接】** 车端 Orin 当然比这个宽裕得多，但**同一套思维方式适用**：先算预算（算力/显存/延迟），再倒推模型规模，最后才谈涨点。反过来做（先冲 mAP 再想怎么塞进去）是典型的返工路径。

**【小结】**
1. 工业上的轻量化 = 准 + 便宜 + 快 + 稳；"准"这一维已被残差解决，差异化在后三个。
2. 四大手段：层数少 / 1×1+3×3+分组+深度可分离 / 残差 / 牺牲精度换速度；空洞卷积和转置卷积**不属于**轻量化手段。
3. 选型看工业成功案例：MobileNet 案例最多，CPU 上 ShuffleNetV2 更快；嵌入式的可用内存可能只有几 MB 甚至几百 KB。

## Part 3 · MobileNet V1：DW+PW、ReLU6 与 Int4（00:32:01 – 00:36:06）

**【本段在讲什么】** MobileNet V1（2017）的三板斧：DW+PW、ReLU6、三因子。这一节先讲前两个。DW+PW 上节课已经铺过底（分组卷积的极限），所以老师一带而过；重点花在 ReLU6 上——他不满足于"就是把上界截到 6"，而是追问"**为什么偏偏是 6**"，然后现场用 DeepSeek 查 Int4/UInt4 的数值范围来佐证。这是一个很好的"从超参数反推设计动机"的示范。

### 11 V1 的第一件事：DW + PW（00:32:01 – 00:33:00）
> **文老师**：「MobileNet 是 2017 年提出来的。他主要用了一个 DW 卷积……所以他的第一个是用了 DW 加 PW。DW 就是深度可分离，PW 就是 1×1。」

- **【画面】** PPT 深色底，标题 `MobileNetV1-2017`，六条要点全部可读：
  `1. MobileNet 的提出主要使用在嵌入式设备中，主要使用了 DW 卷积.`
  `2. 提出了宽度因子、分辨率因子`
  `3. DW 卷积的作用主要是减少了参数量，大约是普通卷积的 1/8。`
  `4. 一共 1 个普通卷积，13 个 DW 卷积块，1 个全局平均池化。`
  `5. 其训练速度非常快，收敛也非常快，参数量双少。爱了。`
  `6. 使用 relu6 函数的原因：……`
  老师在右侧用红笔编号：`① DW+PW  ② ReLU6  ③ 三者关系`。
- **【直译】** DW（Depthwise）= 每个通道自己卷自己，不跨通道；PW（Pointwise）= 1×1 卷积，专门负责跨通道混合。两个合起来才等价于一次标准卷积。
- **【推导/代码】** 标准卷积参数量 `Cin×Cout×k×k`；DW+PW = `Cin×k×k + Cin×Cout`。取 Cin=Cout=128、k=3：标准 = 147456，DW+PW = 1152 + 16384 = 17536，**约 1/8.4**——正好对上 PPT 里"大约是普通卷积的 1/8"。理论上限是 `1/k² = 1/9`，因为还要加 PW 的开销，所以是 1/8 而不是 1/9。
- **【连接】** `nn.Conv2d(128,128,3,padding=1,groups=128)` + `nn.Conv2d(128,128,1)` 就是一个 DW+PW 块。YOLOv5 的 `DWConv` 类、YOLOv8 的部分 neck 层用的都是它。

### 12 ReLU6 的定义与量化动机（00:33:00 – 00:34:01）
> **文老师**：「第二个他提出一个新的激活函数，叫 ReLU6。如果小于 0，X 就等于 0；如果 X 大于 6，X 就等于 6；0 到 6 之间肯定就不变。也就是他限制了 ReLU6 之后的最大值是 6。那为什么限制最大值是 6 呢？是因为我们嵌入式里面有个数据类型。」

- **【画面】** PPT 右栏一行公式：`Y = relu(x) if relu(x)<6 else 6`。左栏第 6 条完整解释：「这是为了在移动端设备 **float16/int8** 的低精度的时候，也能有很好的数值分辨率，如果对 ReLU 的激活范围不加限制，输出范围为 0 到正无穷，如果激活值非常大，分布在一个很大的范围内，则低精度的 float16/int8 无法很好地精确描述如此大范围的数值，带来精度损失。」老师板书：`若 x<0, x=0` / `若 x>6, x=6` / `0—6 不变`。
- **【推导/代码】** `nn.ReLU6()` 等价于 `torch.clamp(x, 0, 6)`。量化视角：int8 只有 256 个刻度，若激活值范围是 [0, 1000]，每个刻度 ≈ 3.9；限制到 [0, 6] 后每个刻度 ≈ 0.023，**数值分辨率提升 170 倍**。
- **【为什么】** 这是"**算法为部署让步**"的第一个教科书例子。ReLU6 在 fp32 训练里没有任何好处（甚至略微损失表达能力），它的全部价值都在量化那一步兑现。
- **【连接】** 你以后做 BEV 模型的 int8 量化（TensorRT PTQ/QAT）会立刻撞上同一个问题：**激活值动态范围过大导致量化误差爆炸**。ReLU6、Clip、LSQ/PACT 都是同一条思路。

### 13 现场查证：Int4 是 −8~7，UInt4 是 0~15（00:34:01 – 00:35:15）
> **文老师**：「Int4 的范围是多少？……应该叫 UInt4。0 到 15。很小。这玩意只占 0.5 个字节。你看 Int4 −8 到几了？−8 到 7。是不是很小？」

- **【直译】** 老师当场记不清，打开 DeepSeek 查，得到：**UInt4 = 0~15（2⁴=16 个刻度）**，**Int4 = −8~7**，每个数只占 **0.5 字节**。
- **【画面】** DeepSeek 页面显示 `uint4 中的位数有 4 位，因此可以表示 2⁴ = 16 个不同的值`，二进制表示表 `0→0000, 1→0001, 2→0010 …`；另一页给出"对比总结"表格：`uint4 | 4 | 0~15 | 2⁴−1`、`int4 | 4 | −8~7 | −2³ ~ 2³−1`。
- **【为什么】** 有了这个数字，ReLU6 里的"6"就不再是拍脑袋：**在 UInt4 的 0~15 刻度里，把激活截到 0~6 意味着你只用了 7 个刻度但保住了全部有效信息**；如果不截断，值域炸到几百，4bit 根本不够分。老师这一步是把"超参数"接回"硬件约束"。
- **【连接】** 现在大模型的 int4/nf4 量化（QLoRA 那一套）用的是同一套数值范围。你之前在 BEV 组打杂时如果见过"权重按 4bit 打包"的部署方案，底层就是这个 0.5 字节。
- **【提醒】** 严格说 MobileNetV1 论文本身只提 float16/int8，Int4 是老师为了讲清"低比特为什么怕大值域"举的更极端例子，别在面试里说成"ReLU6 是为 Int4 设计的"。

### 14 V1 的骨架：1 + 13 + 1（00:35:15 – 00:36:06，画面为主）
> **【画面】** 屏幕上是 MobileNetV1 完整结构表（`Type/Stride | Filter Shape | Input Size` 三列），逐行可读：`Conv/s2  3×3×3×32  224×224×3` → `Conv dw/s1  3×3×32 dw  112×112×32` → `Conv/s1  1×1×32×64  112×112×32` → `Conv dw/s2  3×3×64 dw  112×112×64` → …… → `5× {Conv dw/s1 3×3×512dw; Conv/s1 1×1×512×512}  14×14×512` → `Conv dw/s2 3×3×1024dw` → `Conv/s1 1×1×1024×1024  7×7×1024` → `Avg Pool/s1 Pool 7×7` → `FC/s1 1024×1000` → `Softmax/s1 Classifier`。

- **【直译】** 全网只有**开头一个标准 3×3 卷积**，中间**13 个 DW+PW 块**，结尾**一个 7×7 全局平均池化 + FC**。分辨率路径：224 → 112 → 56 → 28 → 14 → 7，一共 5 次下采样。
- **【推导/代码】** 注意 `5×` 那一组：**14×14×512 这一档重复了 5 次**——这个"5"就是下一节"深度因子"要乘的那个数。老师后面反复用 `5×1.5≈7`、`5×0.5≈2` 举例，指的正是这一行。
- **【为什么】** 结构表是理解三因子的物理载体：**宽度因子改的是 Filter Shape 里的通道数，深度因子改的是这个 5，分辨率因子改的是 Input Size 里的 224**。三个因子各改表里一列，一一对应。

**【小结】**
1. MobileNetV1 = 1 个普通卷积 + 13 个 DW 块 + 1 个 GAP；DW+PW 把参数量压到标准卷积的约 1/8。
2. ReLU6 的"6"来自低比特量化的数值分辨率需求（float16/int8，极端到 UInt4 只有 0~15 共 16 个刻度）。
3. 结构表的三列——通道数 / 重复次数 / 输入尺寸——正好对应宽度因子、深度因子、分辨率因子。

## Part 4 · 三者关系：宽度因子 / 深度因子 / 分辨率因子（00:36:06 – 01:03:02）

**【本段在讲什么】** 这是全课**对你最有用的一段**。MobileNetV1 的第三个贡献不是某个算子，而是提出"分辨率、宽度、深度这三个量应该协同调"。老师先讲论文观点，然后当场唱反调给出自己的实战观点，再逐个把因子落到具体数字上（怎么乘、怎么取整、为什么必须被 8 整除），最后打开 PyCharm 里的 `yolov5s.yaml`，把 `depth_multiple: 0.33` / `width_multiple: 0.50` 和结构里的 `3/6/9/3`、`64/128/256/512` 一一对应起来算给你看。学完这一节你就能自己裁模型了。

### 15 三个因子分别是什么（00:36:06 – 00:38:01）
> **文老师**：「模型的分辨率，模型的输入；模型的宽度，Model 的 C；还有就是我们的深度，Deep。分辨率是指的什么？叫 input，模型的输入分辨率的大小。它其实最核心的是提出这个，它探讨了他们三者的关系。」

- **【画面】** PPT 右栏原文：「**宽度因子：通道数** / **分辨率因子：输入图像的分辨率的大小** / 通道数应该随机(随着)分辨率来进行变化。」老师用绿笔在右侧板书 `宽度因子↑ Channel` / `深度因子↑ Deep` / `分辨率因子 ↑`。
- **【直译】** 三个因子各管一件事：**分辨率因子 = 输入图多大**；**宽度因子 α = 每层通道数缩放**；**深度因子 = 某个 block 重复多少次**。
- **【推导/代码】** 论文里的记号：`MobileNet(w_ratio, i_ratio)`，标准配置是 `MobileNet(1,1)`。乘上 α 后，第 l 层通道数变成 `round(α·C_l)`；乘上 ρ 后输入变成 `ρ·224`。计算量近似按 `α²·ρ²` 缩放（宽度平方、分辨率平方）。
- **【为什么】** 这三者不能独立调：图变大了但通道不够，特征装不下；图很小却堆一堆通道，纯浪费。论文的贡献就是把这件"大家凭感觉做"的事写成了可调的旋钮。

### 16 论文观点 vs 老师的实战观点（00:38:01 – 00:41:01）
> **文老师**：「如果你大于 224 的话，那你的模型的宽度这里要多，深度要什么？要深。……但是我好像上次跟你说的，我不是这个观点。我的观点是：如果你的分辨率大，那你浅层要少一些，那么这里（深层）要多一些通道。这是我们应用的观点。」

- **【画面】** 老师用红笔在 PPT 上写下三档：`448（宽度多，深）` / `224（标准）` / `64（宽度少，浅）`，并在旁边写"它们（三者）的关系 Input 分辨率"。PPT 右栏给出论文的三档配置：`224 MobileNet(w_ratio, i_ratio), MobileNet(1,1)` / `512 MobileNet(1.5,1.5)` / `112 MobileNet(0.5,0.5)`。
- **【直译】** 论文：分辨率大 → 宽度大 + 深度深；分辨率小 → 宽度小 + 深度浅。老师：分辨率大时**浅层的通道可以少给一点，把预算挪到深层**。
- **【为什么】** 差异来自任务不同。分类任务全图一个标签，浅层多给通道没坏处；**检测任务（尤其小目标）浅层特征图巨大（640 时 P2 是 160×160），浅层每加一个通道的算力代价是深层的 64 倍**。老师的经验是把算力花在深层更划算。老师自己也强调「你不要按现在的观点去评价啊，2017 年」。

### 17 深度因子的真实含义：重复次数（00:42:00 – 00:48:01）
> **文老师**：「比如说那个 1.5，比如说 5，我就重复 5 次 DW 加 PW。那 5 乘以 1.5 是多少？7.5 → 7，这里就要重复 7 次。……如果你是 0.5，5×0.5 就是 2 次。肯定向下取整啊。」

- **【直译】** 深度因子不是"层数×几"，而是**结构表里那个被标了 `5×` 的重复块，重复次数乘以因子再向下取整**。
- **【推导/代码】** `n_actual = floor(n_base × depth_factor)`。基准 5：`5×1.5=7.5→7`；`5×1.0=5`；`5×0.5=2.5→2`。老师反复强调"肯定是整数嘛，向下取整"。
- **【为什么】** 关键在于**只有那个重复块会变，别的行不变**：老师原话「这些地方不变啊，变的是这里，这就是五乘」。头部的 stem 卷积、尾部的 GAP+FC 都是固定的——因为它们各只有一层，乘个 0.5 也不能变成半层。
- **【纠错提示】** 转写在 00:46:00 有一段学员和老师算岔了（"如果是 48，深度因子取 0.5，重复 7 次"），老师随后自纠回 0.5→2 次。以卡里的规则为准。老师另外提醒一个连锁反应：**你把深度或分辨率改了，最后那层 7×7 就可能变成 1×1，池化核大小要跟着改，否则报错**。

### 18 宽度因子的真实含义：通道数，且必须被 8 整除（00:48:01 – 00:50:00）
> **文老师**：「如果我们宽度因子 w=1.0，这边的这个通道就不变，比如 32、64，这些不变。如果你 w=1.5，那就是 32×1.5=48。48 能被 8 整除吗？能。……反正你这个一定要被 8 整除，因为它最小通道就是 8。」

- **【直译】** 宽度因子乘的是**每层的输出通道数**，而且结果必须**被 8 整除、且不小于 8**。
- **【推导/代码】** 官方实现里的 `_make_divisible(v, divisor=8)` 就是干这件事：
  `new_v = max(8, int(v + 4) // 8 * 8)`，再补一条 `if new_v < 0.9*v: new_v += 8`（防止下降超过 10%）。老师板书的 `(64×0.5)//8` 正是这个整除写法，他还专门提了一句"整除是好像是两个斜杠吧"。
- **【为什么】** 8 的倒数根源是硬件：**SIMD 向量宽度、GPU 的 tensor core tile、NPU 的通道并行度都按 8/16/32 对齐**。通道数是 33 的卷积在硬件上会被 padding 到 40，白白浪费 7 个通道的算力。所以"能被 8 整除"不是美学要求，是省钱要求。
- **【连接】** 你以后看任何网络的通道表（32/64/128/256/512/1024、或者 MobileNetV2 的 16/24/32/64/96/160/320）会发现**没有一个不是 8 的倍数**——现在你知道为什么了。BEVFusion 的 `(64,512,512)→(384,128,128)`，384 = 48×8，同样守这条规矩。

### 19 打开 yolov5s.yaml：0.33 与 0.50（00:50:00 – 00:55:00）
> **文老师**：「讲到这里我们就可以拓展一下，看看 YOLO 的那网络，YOLO 一样有啊……你看这是 YOLO 里面的，这里有两个因子，这个叫深度因子 depth，然后这个位置就是我们宽度因子。」

- **【画面】** PyCharm 打开 `yolov5-7.0/models/yolov5s.yaml`，逐行可读：
  ```yaml
  nc: 80                 # 类别数，根据标签会自动覆盖这个值
  depth_multiple: 0.33   # model depth multiple    深度因子 0.33 * 9 = 3
  width_multiple: 0.50   # layer channel multiple  宽度因子 64 * 0.5 = 32, 最小是 8
  # backbone  # [from, number, module, args]；number 是重复次数，实际 number*depth_multiple
    [[-1, 1, Conv, [64, 6, 2, 2]],  # P0/2  320x320
     [-1, 1, Conv, [128, 3, 2]],    # P1/4  160x160
     [-1, 3, C3,   [128]],          # 160x160 P2
     [-1, 1, Conv, [256, 3, 2]],    # P3/8  80x80
     [-1, 6, C3,   [256]],          # 80x80 P4
     [-1, 1, Conv, [512, 3, 2]],    # P5/16 40x40
     [-1, 9, C3,   [512]],          # 40x40 P6
     [-1, 1, Conv, [1024, 3, 2]],   # P7/32 20x20
     [-1, 3, C3,   [1024]],         # 20x20 P8
     [-1, 1, SPPF, [1024, 5]]]      # P9 20x20
  ```
  老师红笔标注：`640, 0.33, 0.5`、`(64×0.5)//8 → 32`、`3×0.33=1`、`6×0.33=2`、`9×0.33=3次`。文件树里还有 `yolov5n/m/l/x.yaml` 和他自己改的 `yolov5s_80x80_40x40.yaml`。
- **【推导/代码】** 完整算一遍 yolov5s：
  - 通道：`Conv[64] → 64×0.5 = 32`；`[128]→64`；`[256]→128`；`[512]→256`；`[1024]→512`。全部被 8 整除。
  - 重复：`C3 3 → 3×0.33 = 0.99 → max(1)=1`；`C3 6 → 1.98 → 2`；`C3 9 → 2.97 → 3`；最后 `C3 3 → 1`。
  - 所以 yolov5s 的四个 C3 实际是 **1 / 2 / 3 / 1** 次。
- **【为什么】** 这就是 n/s/m/l/x 五个型号的全部秘密：**同一份 yaml 骨架，只换两个浮点数**。yolov5n = (0.33, 0.25)，s = (0.33, 0.50)，m = (0.67, 0.75)，l = (1.0, 1.0)，x = (1.33, 1.25)。老师在转写里一度说到 0.25，那是他先点开了 `yolov5n.yaml`。

### 20 调这两个系数的真实收益（00:58:01 – 01:03:02）
> **文老师**：「改这两个，实测微涨。微涨大概是多少呢？调的好可能是涨 0.3 左右……调这两个系数呢，根据你的任务的大小目标去调。速度有没有可能提升呢？也可能有提升，但是因为速度要提升这两个数就要小。……极端、非常极端的情况，你才需要调这两个。」

- **【直译】** 期待值管理：调 depth/width 不是涨点神器，**调得好也就 +0.3 mAP**；真正的用途是**换速度**（把两个数调小）。
- **【为什么】** 老师给了一个真实场景：「我以前做了一个 3.5 兆空间的模型，我要轻量化，我就慢慢调这个，去算每一层的内存占比是多少，我自己调的」——也就是说，**这两个旋钮的正确用法是在内存/延迟预算下做搜索**，而不是拿来刷精度。他还吐槽"大部分人也不会去调它，因为都不知道有这两个参数"。
- **【连接】** 记住这个 0.3 的量级："下采样去 ReLU"是 0.3~0.4，SE 是 0.5~1.5——**工程单点改进就这个数量级**。

> 🗀 折叠【00:55:00 – 00:58:01 & 01:00:00 – 01:03:02】学员追问"改了会不会有效""两阶段模型和一阶段模型比"，以及 CVPR 论文能卖 30~60 万的行业闲聊。技术点已在卡 20 覆盖。

**【小结】**
1. 三个因子各改结构表的一列：宽度因子→通道数、深度因子→重复块次数、分辨率因子→输入尺寸。
2. 落地规则：重复次数 `floor(n×depth)`；通道数 `_make_divisible(C×width, 8)`，最小 8、必须被 8 整除（硬件对齐）。
3. yolov5s = (depth 0.33, width 0.50)，四个 C3 实际重复 1/2/3/1 次，通道 32/64/128/256/512；调这两个数换来的是速度，精度顶多 +0.3。

## Part 5 · MobileNet V2：倒残差与"下采样时线性输出"（01:03:02 – 01:26:00）

**【本段在讲什么】** V2（2018）只有两个要点，但老师讲了 23 分钟，因为第二个要点（下采样时不用 ReLU）是**可以直接迁到 YOLO 上的实战技巧**。他先用自己画的三张对比图说清"瓶颈残差 vs 倒残差"，再解释"为什么 DW 前面必须先升维"，然后用论文里那张等高线还原图证明 ReLU 会丢信息，最后给出迁移到 YOLO 的具体做法和一个叫"权重迁移训练"的策略。

### 21 瓶颈残差 vs 倒残差：先降后升 vs 先升后降（01:03:02 – 01:05:01）
> **文老师**：「V2 其实这是 18 年，他引入了一个叫倒残差的结构……这就是普通残差，叫瓶颈残差。这个就 128 进来，64，卷积、BN、ReLU，你看 64、64、64，CBR 嘛，然后 128。……MobileNet 把它改成一个叫倒残差：128 先大，CBR6，卷积 BN ReLU6，然后 3×3 这个卷积就是用了 DW 卷积。」

- **【画面】** PPT「轻量级网络 MobileNet」页，图 4-72 三个并排的框图，通道数完全可读：
  - **瓶颈残差（ResNet）**：`channel0=128` → `1*1卷积CBR channel1=64` → `3*3卷积CBR channel2=64` → `1*1卷积CB channel3=128` → `+` → `Relu`。**128→64→64→128，先降后升。**
  - **s=1 倒残差（V2）**：`channel0=128` → `1*1卷积CBR6 channel1=256` → `3*3卷积DWBR6` → `1*1卷积CB channel3=128` → `+` → `Relu6`。**128→256→256→128，先升后降。**
  - **s=2 分支**：`1*1卷积CBR6 channel1=256` → `3*3卷积DWBR6, s=2` → `1*1卷积CB channel3=128`，**注意没有 `+` 也没有末尾激活**。
- **【直译】** ResNet 的 bottleneck 是"细腰"（中间通道少）；MobileNetV2 反过来做成"大肚子"（中间通道多），所以叫**倒**残差。
- **【推导/代码】** 命名约定要记住：**CBR = Conv+BN+ReLU；CBR6 = Conv+BN+ReLU6；CB = Conv+BN（无激活）；DWBR6 = DWConv+BN+ReLU6**。老师说"我取的名字啊"——但这套缩写在工业界很通用。
- **【连接】** 老师顺口点了一句极重要的话：「**比如说 YOLO 里面的残差，其实它也是一个倒残差，基本上就是倒残差**」。你以后读 `C3`/`C2f` 里的 `Bottleneck` 类，看到 `hidden_channels = int(c2 * e)` 里 e 默认 0.5 时是细腰，而 MobileNet 系是 e=6 的大肚子。

### 22 为什么必须先升维：DW 没有通道间融合（01:05:01 – 01:06:01）
> **文老师**：「因为你如果你小，你特征会压缩，你压缩这里就会丢特征，理论上是会丢的。然后你先小后大，那他特征的保留要好一些。……因为他这里有一个 DW 卷积，他本身是深度可分离卷积嘛，他没有通道信息的融合。……DW 卷积的特征提取能力小于标准卷积。」

- **【直译】** 倒残差存在的唯一理由：**中间那层是 DW 卷积，能力弱**。所以要在它前面先把通道撑大（默认 6 倍），给它更多"工作面"，卷完再压回去。
- **【推导/代码】** DW 卷积的每个输出通道只看输入的**同一个通道**，跨通道信息完全靠前后的 1×1 来补。如果按 ResNet 那样先降到 1/4 再做 DW，等于"弱算子 + 少通道"双重削弱。
- **【画面】** PPT 上 MobileNetV2 第 3 条给出了论文自己的说法：「进行线性输出的原因：因为 **Xception** 中已经证明，对于低维空间而言，进行线性映射会保存特征，而非线性映射会破坏特征。而 **Inverted Residual Block** 两端的输出通道数都比较少，属于这里说的"低维空间"，因此在 MobileNet V2 中，最后一个 1×1 conv 输出选择线性激活，即 **Linear Bottleneck**。」
- **【为什么】** 注意这里其实是**两个独立的设计**：①中间升维（保住 DW 的能力）②两端 1×1 后不加激活（低维空间用线性映射保特征）。合起来叫 Inverted Residual with Linear Bottleneck。

### 23 s=2 分支：下采样时线性输出、没有 ReLU（01:06:01 – 01:09:01）
> **文老师**：「你看这里就是 S 等于 2 的时候，就是下采样的时候。一个模型它有两部分，一个是下采样，一个是普通的（维度不变、提取特征）。……但是要注意一下，它这里没有 ReLU，所以 CB。简单来说就是下采样是线性的。」

- **【直译】** 一个 backbone 的 block 只有两种形态：**s=1（尺寸不变，走倒残差 + 残差连接）** 和 **s=2（下采样，没有残差连接、且末尾不加激活）**。
- **【为什么·两条】** ①下采样时**没法做残差**——老师原话「你下采样怎么残差？你尺寸都变了」，输入 56×56 和输出 28×28 无法逐元素相加（除非额外加 1×1+stride 的 shortcut，那是 ResNet 的做法）。②末尾**不加 ReLU** 是主动设计，理由见下一卡的等高线图。
- **【画面】** 老师用红笔在 PPT 上写下三行大字：`下采样时，① 没用 Relu`、`② 用了倒残差 S=1`，并把 s=2 那个框整个圈起来。

### 24 等高线还原图：ReLU 到底丢了多少（01:09:01 – 01:12:00）
> **文老师**：「这个叫等高线图，其实就是特征还原图，就信息还原图。这就是原图嘛。它 dim=2 是什么？就输出在第二层 output。……你看是不是还原的就好像只有一半？如果是 3 呢，就会多一点；如果这里到了 30，是不是这两个基本上差不多了？」

- **【画面】** 图 4-72 下方一排 6 张小图：`Input`（一圈闭合的螺旋等高线）、`Output/dim=2`、`Output/dim=3`、`Output/dim=5`、`Output/dim=15`、`Output/dim=30`。dim=2 时图形被一条直线切掉大半，dim=3 略好，到 dim=15、30 时基本还原成原始螺旋。PPT 底下写着：「**Relu 对于 x<0 为 0，破坏了特征。如果不经过 relu，那么 x 会得到保留；如果网络层次比较多时，减少非线性（起到一点正则化效果）**」。老师把"减少非线性"圈了出来，并在旁边标注"等高线图"。
- **【直译】** 实验做法：把一个二维螺旋嵌入到 n 维空间（n = dim），过一次 ReLU，再投影回二维看还能还原多少。**维度低时 ReLU 造成不可逆的信息损失；维度高时损失可忽略。**
- **【为什么】** 这就是"Linear Bottleneck"的实验依据：**倒残差两端是低维（通道少），恰恰是 ReLU 最伤的地方**，所以末尾那个 1×1 必须是线性的。

### 25 减少非线性 = 前向传播视角的正则化（01:12:00 – 01:13:00, 01:23:00 – 01:24:03）
> **文老师**：「其实它核心是减少了非线性。那减少非线性，那我们就想正则化——正则化是让我们的 W 等于 0，对不对？那是不是也就是减少了非线性？只是它是从前向传播的角度减少非线性。……你减少了非线性就相当于模型简单一点，模型简单一点就可以缓解过拟合。但是参数量还是没变的，因为参数量只跟卷积有关。」

- **【直译】** 老师做了一个很漂亮的类比：**L1/L2 正则化是从"反向传播/权重"这一侧降低模型复杂度（把 W 压向 0）；去掉 ReLU 是从"前向传播/激活"这一侧降低复杂度。两者殊途同归，都是让模型变简单、缓解过拟合。**
- **【推导/代码】** 三个精确的推论：①**参数量不变**（ReLU 无参数）；②**推理速度会变快**（少一次逐元素运算和一次访存）；③**表达能力下降**（少一层非线性）。老师原话："减少没有参数，没有减少……但是你这样做的推理速度还会更快一点"。
- **【为什么】** 这个类比的价值在于给你一个**判断"该不该去 ReLU"的标准**：如果模型正在过拟合（训练集远好于验证集），去掉几层非线性是对症的；如果模型欠拟合，去了只会更差。
- **【连接】** 以后看到任何"简化某个模块反而涨点"的现象，第一反应应是"它在做正则化"，而不是"玄学"。

### 26 迁移到 YOLO：只改下采样那两三层（01:13:00 – 01:20:03）
> **文老师**：「比如在 YOLO 当中，我曾经实验过，就改动比较麻烦。你把前面的两层、两到三层，就下采样的前面两三层，就跟它一样，不用 ReLU……对于整个模型会有那么一点提高，但提高的也只有 0.4、0.3 这个左右，确实会。……你看一篇论文，你要把论文的思想迁移到其他模型当中；你看这篇论文你就只局限到这篇论文，那有毛线用？」

- **【直译】** 具体操作：在 YOLO 的 backbone 里找到 `stride=2` 的那几个 `Conv`，**把其中前两三层的激活函数去掉（或换成 Identity）**，重训，能涨 0.3~0.4。
- **【推导/代码】** 在 yolov5 里对应的是 `models/common.py` 的 `Conv` 类，它的 `act` 默认是 `nn.SiLU()`。做法是新增一个算子（老师说的"卷积 low ReLU"其实是 `Conv + BN + 无激活`），然后在 yaml 里把对应行的 module 名换掉。老师原话："要把这个算子替换成一个叫卷积……然后就要把这个算子改名……这个后面讲 YOLO 的时候就会了。"
- **【为什么】** 老师特别强调**不要全改**：「我操全部一减，直接就凉，知道吗」。他的经验是只改最靠前的下采样层，因为**浅层特征图大、信息冗余多，丢一点非线性影响小；深层特征已经很抽象，去了就掉点**。选哪一层？他的回答很坦率：「这是凭经验……凭五年算法工程师的直觉」。
- **【连接】** 这是你毕业设计/面试项目的**绝佳候选**：改动量极小（改一个算子 + yaml 一行），有明确的论文依据（MobileNetV2），有可量化的对照实验（加/不加）。就算涨不了，你也有一份完整的对比实验报告可讲。

### 27 权重迁移训练：先用 ReLU 训，再去掉（01:20:03 – 01:25:01）
> **文老师**：「第一个版本用什么呀？用 ReLU。然后呢，你下一次训练，把这个权重迁移过来——因为 ReLU 它是没有权重的嘛——你把它迁移过来，然后再减少一些层，去掉 ReLU。……不是说你一开始训练的时候都不用 ReLU，而是什么呀？先用后不用。这是我们后面讲的一个叫权重迁移训练，是一个训练策略。」

- **【直译】** 两段式训练：**第一轮带 ReLU 正常训到收敛 → 拿这份权重作为初始权重 → 第二轮改成"去 ReLU"版本继续训**。
- **【推导/代码】** 之所以能直接迁移，是因为 **ReLU 没有可学习参数**，去掉它不改变任何一层的 `weight` / `bias` 形状，`load_state_dict()` 可以严格匹配（`strict=True` 都能过）。代码上就是 `model_v2.load_state_dict(torch.load('v1_best.pt')['model'].state_dict())`。
- **【为什么】** 老师给的理由是"训练时间会少一点"，但更本质的是**初始化质量**：从零训一个非线性不足的网络容易卡在坏的局部解，从已收敛的解出发微调等于给了它一个"好出身"（02:53:02 他又用了这个词）。
- **【连接】** 这是一条通用的"结构编辑 + 权重继承"套路，同一招后面还会出现两次：**②SE 那节的"B 模型作为初始权重再跑全量数据"；③激活函数那节的"训练用 SiLU、推理换 ReLU 再微调"**。三处是同一个方法论。收益老师给的是"大概 0.3 左右，反正就是微涨"。

> 🗀 折叠【01:22:01 – 01:26:00】关于"涨 0.3% 值不值得"的讨论（结论：模型已到 96~97% 时，0.3 可能就是验收通过与否的分界；生产 1 万片算下来不少），以及老师吐槽自己英文老写错、PPT 排版不好看。

**【小结】**
1. 倒残差 = 先升维（默认 6 倍）→ DW 卷积 → 降维，且**最后那个 1×1 不加激活（Linear Bottleneck）**；理由是 DW 能力弱需要更宽的工作面，而低维空间的 ReLU 会破坏特征。
2. s=2 的下采样分支**没有残差连接、也没有 ReLU**；等高线还原图（dim=2/3/5/15/30）是"ReLU 在低维丢信息"的实验证据。
3. 可迁移的工程技巧：把 YOLO 前两三个下采样层的激活去掉，配合"先带 ReLU 训 → 权重迁移 → 去 ReLU 再训"的两段式策略，实测 +0.3~0.4。

## Part 6 · 读懂 V2 的 t/c/n/s 结构表（01:26:00 – 01:41:03）

**【本段在讲什么】** 论文里的网络结构表长得很朴素，但**有迷惑性**：一行 `n=2, s=2` 到底是"两个 stride=2 的块"还是别的意思？老师用 15 分钟把这张表逐行拆开，给出一条铁律：**`s=2` 的那一行要拆成"下采样 1 次 + 倒残差 (n−1) 次"**。这条规则不止对 MobileNetV2 成立，ResNet、YOLO 的结构表都是这么写的。

### 28 表头四个字母的含义（01:26:00 – 01:28:02）
> **文老师**：「这个是它的输入，卷积对不对，这个 s 等于 2 步长。这个 n 是什么呢？重复一次，n 是重复的意思，这个算子重复了几次。……这个 c 是输出通道。」

- **【画面】** MobileNetV2 官方结构表，完整可读（`Input | Operator | t | c | n | s`）：
  `224²×3 conv2d – 32 1 2` / `112²×32 bottleneck 1 16 1 1` / `112²×16 bottleneck 6 24 2 2` / `56²×24 bottleneck 6 32 3 2` / `28²×32 bottleneck 6 64 4 2` / `14²×64 bottleneck 6 96 3 1` / `14²×96 bottleneck 6 160 3 2` / `7²×160 bottleneck 6 320 1 1` / `7²×320 conv2d1x1 – 1280 1 1` / `7²×1280 avgpool7x7 – – 1 –` / `1×1×1280 conv2d1x1 – k – –`。
  老师在表下手写：`T = 宽度因子 / 输出通道数 = C * T / N = 重复的次数 / s = 2 步长`，以及一段关键批注：「**进入每个 t=6 时，有 1 个 1×1 卷积，升维；如果 t=6 时，s=2 时 DW 卷积会下采样。后面的重复 s=1**」，并写下 `工业建议：MobileNetV2`。
- **【直译】** 四个字母：**t = 扩展倍数（中间层通道 = 输入通道 × t）**、**c = 输出通道**、**n = 重复次数**、**s = 第一次的步长**。
- **【⚠ 纠错】** 老师板书把 `T` 写成"宽度因子"，**这是本课最需要修正的一处**。V2 论文里 t 是 **expansion factor（扩展因子）**，管的是 block 内部升维多少倍；**宽度因子是 α（width multiplier），管的是整张表 c 这一列统一乘多少**。两者完全不是一回事。老师讲解时其实用对了（"24×6×1.0"里 6 是 t、1.0 是宽度因子），只是命名写错了，面试别照抄。

### 29 铁律：`n=2, s=2` 要拆成"下采样 1 次 + 倒残差 n−1 次"（01:28:02 – 01:32:00）
> **文老师**：「你看这里又一个 6，这一步啊，你可能很有可能你看不懂了。它这里 s 等于 2，然后这里重复几次，重复两次，那肯定不对。……n 等于 2、s 等于 2，你要拆开来：先是一个 1×1，3×3 DW s=2，然后 1×1，这是下采样；然后你这里不是重复两次吗，这里就还要给我加一个倒残差。」

- **【直译】** `s` 只作用在**这一组的第一个 block** 上；剩下的 `n−1` 个都是 `s=1` 的标准倒残差。
- **【推导/代码】** 官方实现就是这么写的：
  ```python
  for i in range(n):
      stride = s if i == 0 else 1
      layers.append(InvertedResidual(inp, c, stride, expand_ratio=t))
      inp = c
  ```
  老师用板书表达为 `1 + (n−1) = n`——他在 01:32:00 反复念了好几遍这个式子。
- **【为什么】** 若 n 个全用 s=2，224 连做 4 次就只剩 14×14，整张表的 Input 列立刻对不上。**结构表的自洽性就是这条规则的证明。**

### 30 逐行推：112²×16 那一行怎么走（01:32:00 – 01:38:01）
> **文老师**：「就是这个 2 你要拆成两步。第一步就是先下采样，下采样完了之后呢，你这个时候拿的是多少？112 的一半，56×56。然后这个通道是多少？24×6，再乘以 1.0。……那你倒残差的输入是多少？就是 56×56×(24×6)。最后的输出是 24×1.0。」

- **【画面】** 老师在表上用蓝笔逐行标注：`112²×16 bottleneck 6 24 2 2` 这一行被框起来，旁边写 `n=2, s=2, RW=1.0`、`下采样 56×56×(24×6×1.0)`、`Input 56×56×(24×6×1.0)`；下一行 `56²×24 → 2→28`，再下一行 `28²×32 → 2→14`，并在 `14²×96 n=3 s=2` 旁写"倒残差 3 次"。
- **【推导/代码】** 完整走一遍第 3 行：
  1. 输入 `112×112×16`。
  2. **下采样块**：`1×1 conv 16→96(=16×6)` → `3×3 DW s=2` → `1×1 conv 96→24 线性`。输出 `56×56×24`。
  3. **倒残差块 ×(2−1)=1 次**：`1×1 conv 24→144(=24×6)` → `3×3 DW s=1` → `1×1 conv 144→24 线性` → `+ shortcut`。输出仍是 `56×56×24`。
  4. 下一行 Input 写的是 `56²×24` —— **对上了**。
- **【为什么】** 老师特别提醒一个容易搞混的点：「所以你看到下一层这里是一个 24，这个 24 其实是这里来的，**但是他没有乘以 6**，因为你宽度因子有可能是 0.5，0.5 你就减半了」。也就是说 **c 列写的是 block 的最终输出通道（已降维后），中间那个 ×6 是 block 内部的临时值，不体现在表里**。
- **【连接】** 你以后自己数任何网络的分辨率路径，就用这个方法：**只看 s 列，s=2 出现几次就下采样几次**。V2 表里 s=2 出现 5 次（第 1、3、4、5、7 行），224 → 112 → 56 → 28 → 14 → 7，正好 5 次。

### 31 结构表会省算子：16 那一档对不上（01:35:11 – 01:39:01）
> **文老师**：「这里可能有点不对呀，那你这里应该省了一个 1×1，普通卷积它压缩不到 16 的。……只有这里对不上，但是这些地方能对上。就是绝对哪里有一个 1×1，但是省了，确实省了。就是他们模型结构经常会省一两个关键操作的。」

- **【直译】** 老师发现第二行 `112²×32 → bottleneck t=1 c=16` 有点怪：t=1 意味着不升维，那这个 block 就退化成 "DW + 1×1 降维"，中间少了一次 1×1 升维。他判断这里论文省略了写。
- **【为什么】** 实际上这正是 V2 的设计：**第一个 bottleneck 的 t=1，官方实现里确实跳过了那个 1×1 升维层**（`if expand_ratio != 1: layers.append(ConvBNReLU(inp, hidden_dim, kernel_size=1))`）。所以不是论文写错，而是"t=1 时结构确实不同"。老师的直觉方向是对的——表里确实缺一层，只是原因是"t=1 触发了特例分支"而非"论文漏写"。
- **【连接】** 这个观察比结论更有价值：**读结构表时要用"通道数对不对得上"做自检**，并且看完论文表**一定要去读官方实现代码**，两者对照才不会理解偏。

**【小结】**
1. `t/c/n/s` = 扩展因子 / 输出通道 / 重复次数 / 首块步长；**t 不是宽度因子**（老师板书写错了，这是本课首要纠错点）。
2. 铁律：`s=2` 的一行拆成"下采样 1 次 + 倒残差 (n−1) 次"，即 `1 + (n−1) = n`；ResNet、YOLO 的结构表同理。
3. c 列写的是 block 的最终输出通道，中间的 `×t` 是 block 内部临时通道，不在表里；表和代码要对照读，因为表会省算子。

## Part 7 · MobileNet V3 与 SE 通道注意力（01:41:03 – 02:28:04）

**【本段在讲什么】** V3（2019）在结构上只多了一个虚线框的 SE 模块，但老师认为"这个比较难懂"，所以花了近一小时讲**注意力机制的本质**。他给出的定义只有一句话，却相当精确：「注意力的行为：通过某种条件，重新提取特征，改变原来的评分的分布（概率）；目的：为了让损失更小（主观目的）」。然后用三张照片打比方，再把 SE 的算子链一步步画出来算清楚。最后给出一个很清醒的结论：**加注意力只有三种结局——变好、变差、一定变慢。**

### 32 V3 = V2 + 虚线 SE + 换激活函数（01:41:03 – 01:44:00）
> **文老师**：「V3 其实贼简单，V3 只需要搞懂一个就行了，但是这个比较难懂。……你看这个和这个比，是不是就只多了一个 SE？DW 是一样的，后面就是换了一个激活函数。但是它最大的变化是这里加了一个虚线，叫 SE 模块。虚线代表什么？可加可不加。」

- **【画面】** PPT 右半页，图 4-75「倒残差加入 SE 结构」，两个框：
  - **s=1 倒残差**：`channel0=128` → `1*1卷积 CBR_HS channel1=256` → `3*3卷积 DWBR_HS` → `[SE模块]（虚线框）` → `1*1卷积CB channel3=128` → `+`
  - **s=2**：`1*1卷积 CBR_HS channel1=256` → `3*3卷积 DWBR_HS s=2` → `[SE模块]（虚线）` → `1*1卷积CB channel3=128`，同样没有 `+`
  PPT 底部红字总结：「**V2 特点：引入残差，先升维后降维，保留更多特征信息；s=2 时，使用线性输出，为了更好地保留浅层特征信息。V3 在 V2 的基础上加入了 SE 模块**」。
- **【直译】** V3 相对 V2 的改动只有两处：①在 DW 之后插一个**可选的** SE 模块；②把 ReLU6 换成 **HS（Hard-Swish）**——注意框名从 `CBR6` 变成了 `CBR_HS`。
- **【为什么】** "虚线代表可加可不加"这个细节很重要：**V3 不是每个 block 都加 SE**，只在某些层加。原因在 Part 8 会讲——深层加才有效。
- **【连接】** SE 是 2018 年 SENet 的产物（ImageNet 2017 冠军），MobileNetV3 只是把它拿来用。你之后学的 CBAM、CA（Coordinate Attention）都是它的变体；YOLOv5/v8 的社区改进版里，加 SE/CBAM/CA 是最常见的"魔改"。

### 33 注意力的一句话定义（01:44:00 – 01:52:02）
> **文老师**：「所谓注意力就是什么？就是你给它加一个外在的、外部的一个条件，然后重新提取特征，重新评分，对原来的这个值重新评分。……注意力其实就是做这个事情：通过某种条件，重新提取特征，改变原来的评分分布。那么它的目的是什么呢？目的是为了让损失更小。」

- **【画面】** PPT 第 60 页（共 266 页，文件名 `深度学习框架+CNN分类+目标检测（RCNN）.pptx`）正文只有三行：
  「**SE: 通道注意力机制**」
  「**注意力的行为：通过某种条件，重新提取特征，改变原来的评分的分布（概率）;**」
  「**目的：为了让损失更小（主观目的）**」
- **【直译】** 三个动作缺一不可：**加条件 → 重新提特征 → 改评分分布**。目的只有一个：降 loss。
- **【为什么】** 这个定义的高明之处在于它**不依赖 QKV**。你用它去理解 SE（条件 = 全局平均池化的通道统计量）、CBAM（条件 = 通道 + 空间）、Self-Attention（条件 = 序列内其他 token）全都成立。老师说"现在的大模型 Transformer 都是它的升级版……应该是自注意力机制"，正是这个意思。
- **【连接】** 之后接 BEVFormer 会遇到 Spatial Cross-Attention（条件 = 多相机图像特征）和 Temporal Self-Attention（条件 = 上一帧 BEV 特征）。**用这句定义去套，你会发现它们只是"条件"不同。**

### 34 三张照片的类比：0.2/0.2/0.6 → 重新评分（01:45:00 – 01:51:00）
> **文老师**：「你们第一眼看到是一号、二号、三号，是哪一号？第三张对吧……第一个呢，其实我们就是类比的模型学习的时候，比如这个本身是 0.2、这个是 0.2，那么这是 0.6，这就是你的第一感觉，这叫模型本身的行为。现在呢，我给你加了一个什么？是不是加了一个条件？你就要重新去学特征，重新评分。」

- **【直译】** 三张 80/90 年代明星照。**无条件时**大家第一眼都选第 3 张 → 这是"模型本身的行为"，评分分布 `[0.2, 0.2, 0.6]`。老师随后加条件（"哪一张看上去最孤独"、"哪个露的最多"）→ 大家改选第 1 张 → 分布变成 `[0.6, 0.2, 0.2]`。
- **【推导/代码】** 老师在板书上算了"缩放因子"：要把 0.6 变 0.2 需要乘 **1/3**，要把 0.2 变 0.6 需要乘 **3**。这就是 SE 输出的那个 scale 向量在干的事——**只不过 SE 的 scale 被 Sigmoid 限制在 0~1，所以是"抑制不重要的通道"而不是"放大重要的"**，效果等价。
- **【为什么】** 类比里的"条件"是老师用嘴给的（主观），而神经网络里的"条件"是学出来的。老师在 02:17:24 明确回答了这个衔接：「**但是你在神经网络有主观吗？你的神经网络主观靠什么？靠损失啊。这就是你的主观行为**」——**loss 就是网络的"主观目的"**。
- **【连接】** 面试被问"什么是注意力"时别背 `softmax(QK^T/√d)V`，先说这三句（加条件→重提特征→改分布，目的降 loss），再举 SE 做例子，档次立刻不一样。

### 35 SE 的算子链：五步算清楚（01:54:00 – 02:00:01）
> **文老师**：「假设我们这个时候的特征 28×28×128……他相当来一个全局平均池化，得到的就是 1×1×128。然后呢，他这里要重新提取特征，这个是上全连接或者上 1×1 嘛。……然后他这里是 1×1，除以 4 等于多少？32。……压缩完了之后他这里再回来，就变成 1×1×128。然后他这里做了一个事情，用了一个 Sigmoid 函数。」

- **【画面】** PPT 第 60 页板书（橙色笔）完整链路：
  ```
  X ──CNN──> [28×28×128] ────────────────────────× ──> 新的特征
                  │                                ↑
             全局平均池化                     Sigmoid(1×1×128)
                  ↓                                ↑
             [1×1×128] ──1×1 conv──> 1×1×32 ──1×1 conv──> 1×1×128
                              （压缩）
  ```
- **【推导/代码】** 五步，PyTorch 写法：
  ```python
  class SE(nn.Module):
      def __init__(self, c, r=4):
          super().__init__()
          self.pool = nn.AdaptiveAvgPool2d(1)          # 28×28×128 -> 1×1×128
          self.fc1  = nn.Conv2d(c, c // r, 1)          # 1×1×128  -> 1×1×32
          self.act  = nn.ReLU()
          self.fc2  = nn.Conv2d(c // r, c, 1)          # 1×1×32   -> 1×1×128
          self.gate = nn.Sigmoid()                     # 得到 128 个 0~1 的分数
      def forward(self, x):
          s = self.gate(self.fc2(self.act(self.fc1(self.pool(x)))))
          return x * s                                 # 逐通道广播相乘
  ```
- **【为什么】** 第一步 GAP 的作用被老师一句话点透：**把 28×28 的空间信息压成一个数，得到"这个通道整体有多活跃"的全局描述**。没有这一步，你就拿不到"全局条件"，只能看局部。
- **【连接】** 注意 `fc1/fc2` 用 `Conv2d(...,1)` 而不是 `Linear` —— 因为输入是 4D 张量，1×1 卷积在数学上等价于全连接但不用 reshape。老师原话"这个是上全连接或者上 1×1 嘛，对吧，我们上 1×1 的卷积"。

### 36 为什么要先压缩到 C/4（01:58:00 – 01:59:02）
> **文老师**：「这是为了压缩。压缩是什么目的呢？压缩是为了减少参数。那为什么要减少参数量呢？因为你加了一个新的模块，你就多了一些参数。……参数呢就有原来的乘法变成加法。」

- **【推导/代码】** 算笔账，C=128，r=4：
  - **不压缩**（直接 128→128 一层 FC）：`128 × 128 = 16384` 个参数。
  - **压缩**（128→32→128 两层）：`128×32 + 32×128 = 4096 + 4096 = 8192` 个参数，**省一半**。
  - C 越大省得越多：C=512 时，`512² = 262144` vs `2×512×128 = 131072`，同样是一半；若 r=16 则省到 1/8。
  - 老师那句"原来的乘法变成加法"说的就是 `C²` → `2·C·(C/r)` 这个形式变化。
- **【为什么】** SE 是**白送的额外参数**——它不提升感受野、不改变分辨率，纯粹是加在主干上的开销。所以必须尽量小，否则"轻量化网络加个注意力反而变重"就成了笑话。
- **【画面】** SE 论文原图（图 4-78，02:37:01 帧）：`输入特征(h*w*c)` → `压缩` → `全局平均池化(1*1*c)` → `FC1(1*1*c/group)` → `relu` → `FC2(1*1*c)` → `缩放因子=sigmoid(FC2)` → `激励×` → `输出：放大/缩小特征`；老师标注 `group=4`。**注意 FC1 后那个 relu 是有的**，转写里没提。

### 37 通道相乘：为什么叫"通道"注意力、为什么"粗暴"（02:00:01 – 02:02:01, 02:23:00 – 02:25:03）
> **文老师**：「比如这个地方是 0.1，假设第一个是 0.1，那他的第一个（通道）就应该乘以 0.1……如果是第四个是 0.9，那就是 28×28 第四个乘以 0.9。它为什么叫通道呢？是因为你这里得到的是一个通道值。……但是这个变化也非常粗暴。为什么叫粗暴？它把这 0.1 把你 H、W 每个值都改了。」

- **【直译】** SE 输出的 128 个数，**每个数负责一整个通道**：第 k 个通道的 28×28=784 个数，全部乘同一个 `s_k`。
- **【推导/代码】** 广播乘法：`x` 形状 `(N,128,28,28)`，`s` 形状 `(N,128,1,1)`，`x * s` 自动广播。老师算例：`s = [0.1, 0.3, 0.1, 0.9, ...]` → 通道 0 全乘 0.1、通道 1 全乘 0.3、通道 3 全乘 0.9。
- **【为什么·两面】** 好处是**便宜**（只要 C 个数）；坏处是**粗暴**——它不区分"这个通道在图像左上角重要、右下角不重要"，一刀切。**这正是后续 CBAM（加空间注意力）、CA（把位置信息编进通道注意力）要解决的问题**。老师说"以后我们可能还会接触到其他注意力"，指的就是这条演进线。

### 38 Sigmoid 不是 Softmax：逐通道独立（02:23:00 – 02:24:00）
> **文老师**：「因为 Sigmoid 是这样，第一个通道、第二个通道加起来不会等于 1，对不对？是每个通道的值。有可能是几了？0 到 1。它不是 Softmax。Softmax 所有数都要算，对不对？这个只算一个数。」

- **【直译】** SE 的门控用 **Sigmoid** 而不是 Softmax：**128 个分数彼此独立，各自落在 0~1，加起来不等于 1**。
- **【推导/代码】** `sigmoid(z_k) = 1/(1+e^{−z_k})` 只看 `z_k` 自己；`softmax(z)_k = e^{z_k}/Σe^{z_j}` 要看全部。所以 Sigmoid 允许"所有通道都重要（全接近 1）"或"所有通道都不重要（全接近 0）"，Softmax 强制它们互相竞争。
- **【为什么】** 通道之间**不是互斥关系**——一张图里"有边缘"和"有纹理"可以同时重要。用 Softmax 会人为制造竞争，反而有害。这个区别是 SE 设计里一个很容易被忽略但很关键的选择。

### 39 加了 SE 只有三种结局（02:08:01 – 02:21:00）
> **文老师**：「你加了注意力，有两种结果：变好，或者变差，但是绝对不会不变。……所以你加 SE 就是加这种注意力，一定要注意，就只有两种结果：变好或者变差。第三，然后还变慢。变慢是一定变慢，百分之百变慢的。」

- **【直译】** 三种结局：**变好 / 变差 / 一定变慢**。前两个是概率事件，第三个是必然事件。
- **【为什么·变差的两种机制】** 老师给了很具体的分析：
  1. **学不到**——SE 那两层 FC 的特征提取能力有限，可能根本学不出有意义的通道权重（他反问："哪一个脸型的鼻子最小？哪一个昨天还在哭今天又在笑？——有可能提取不到"）。
  2. **学偏了 / 学到噪声**——「因为你这个值如果特征值大，然后它这个评分如果也大，就是两个一乘就是很大」。**大特征值 × 大权重 = 双重放大**，异常值被指数级凸显，这就是 SE 会放大噪声的数学机制。老师称之为"错误评分"。
- **【推导/代码】** "一定变慢"也是可以量化的：SE 引入了一次 GAP（全局归约，对并行不友好）+ 两次 1×1 卷积 + 一次 Sigmoid + 一次广播乘法，**且 GAP 是同步点，会打断卷积流水线**。所以哪怕 FLOPs 增加不到 1%，实测延迟也会明显上升。
- **【连接】** 记住这条结论去看论文：「**但是所有论文会告诉你，加这玩意都有用，没有来看那论文说没用的**」——发表偏倚（publication bias）是真实存在的。你自己做实验时**必须做加/不加的对照**（老师原话："所以你这个要做对比实验的"）。

> 🗀 折叠【02:03:00 – 02:08:01 & 02:11:02 – 02:22:02】学员反复追问"这个 W 怎么来的""为什么能相乘""不加是不是一样"，老师用"X′ = X × score""W 都是学习得到的，不是人设的"反复作答。核心已在卡 35~39 覆盖。

### 40 SE 的位置与输出：X′ = X × S（02:10:00 – 02:15:01）
> **文老师**：「最后的特征 out 就等于 X 乘以 S，就是你的新特征，就是重新评分的一个特征，叫重评分特征。……所以你只是改变了原来这个 X 值的一个分布，你就用 X 一撇新的这个值，然后再算完，这是一层一层地传上来的。」

- **【直译】** SE 是一个 **shape-preserving** 模块：输入 `(H,W,C)`，输出还是 `(H,W,C)`，只是数值分布变了。老师后来专门强调："因为 SE 它的通道是 H、W、C 都是不变的"。
- **【推导/代码】** `out = x * sigmoid(fc2(relu(fc1(gap(x)))))`。梯度回传时，loss 对 `s` 的梯度会传到 `fc1/fc2` 的 W 上——所以老师说"如果这个损失很大，那你就要去调整，说明你那个 FC 学的就有问题"。
- **【为什么】** shape-preserving 决定了 **SE 可以插在任何地方**——ResNet 第 20 层、30 层随便插，不用改上下游任何一层的通道数。老师说的"你搞到第 20 层、30 层，在原来的基础上给我加一个模块进去"靠的就是这个性质。

**【小结】**
1. 注意力的定义只有一句：**通过某种条件，重新提取特征，改变原来评分的分布；目的是让损失更小**（loss 就是网络的"主观"）。
2. SE 的五步：GAP → 1×1 压缩到 C/4（省一半参数）→ ReLU → 1×1 还原到 C → Sigmoid（逐通道独立 0~1）→ 逐通道广播相乘；shape 保持不变，可以插在任何层。
3. 加注意力只有三种结局：变好、变差、**一定变慢**；变差的机制是"学不到"或"大特征×大权重双重放大导致学到噪声"。必须做加/不加对照实验。

## Part 8 · 注意力涨点三条件 · 好激活函数 · NAS（02:28:04 – 02:58:00）

**【本段在讲什么】** 全课最"值钱"的两段就在这里。第一段是"**什么情况下加注意力才会涨点**"——老师给了三个可背诵的条件加一套数据筛选的具体操作，并明确说这是面试可以拿来反杀面试官的料。第二段是"**什么样的激活函数是好的**"——他拒绝逐个背激活函数名字，只给一条判据（无上界、有下界、负半轴平滑过渡），然后用它去衡量 Hard-Sigmoid 和 Swish/SiLU。最后收尾讲 NAS。

### 41 涨点三条件之一、二：先有 90 分、加在深层（02:28:04 – 02:33:00）
> **文老师**：「什么样的情况下加注意力大概率是会涨点的，而不是瞎加。……第一，你模型至少这个时候有 90 分，模型最差目前已经有 90 分，准确率有 90 分。第二个条件叫加深层网络……因为这个时候噪声少啊。」

- **【画面】** 老师用红笔在 SE 结构图右侧写下三条（原样）：
  `什么时候加注意力才会涨点？`
  `① 模型最差目前已经有 90 分`
  `② 加深层网络后【噪声少】`
  `③ 数据质量高`
  并在结构图上标注 `+0.5% ~ 1.5%`，另标 `ResNet`（说明这套做法在 ResNet 上同样适用）。
- **【为什么·条件一】** 类比很到位：「加注意力就像补课一样。当你考了 90 分，你去补课还是能考 90 分（往上）；当你是一个学渣，那 70 分你怎么补……」——**基础模型没到 90 分，说明主干特征本身就没学好，重排一堆烂特征不会变好**。
- **【为什么·条件二】** 老师给的机制：「因为前层网络的时候，那个特征提取的照片是不是很多？很多就会干扰你的学习，因为你那个（尺寸）大」。浅层特征图大、通道语义弱、噪声多；深层特征已经抽象、通道之间语义分工清晰，**这时"哪个通道重要"才是一个有意义的问题**。他强调用词要准确："**加在深层网络后**"。
- **【连接】** 这解释了 MobileNetV3 为什么 SE 是虚线（可选）——**它只在后半段的 block 里加**。你以后往 YOLO 里加注意力，别在 backbone 前两层加，往 P4/P5 或 neck 里加。

### 42 条件三：数据质量高，以及"用模型筛数据"的绝招（02:33:00 – 02:37:01）
> **文老师**：「第三个就是你的数据质量一定要高，你那些垃圾数据要给我删了……这里有个小绝招：用你训练的模型先跑，全部跑一遍训练集，分开跑，推理预测一下。……训练集当中是不是有大于比如说概率 0.6 的，你是不是可以认为它是个好数据？」

- **【推导/代码】** 完整的四步操作（老师在画面上蓝笔写了一遍）：
  1. 用当前模型 A 对**训练集和验证集分别**做一次全量推理（注意不要造成数据泄漏）。
  2. 取 **score > 0.6** 的样本作为"好数据"候选。
  3. **人再进去看一遍**——「因为有可能有些垃圾数据评分也高」，把里面的垃圾删掉。
  4. 用这份干净数据 **加上 SE 重新训练**，得到模型 B。
- **【为什么·还有第五步】** 这是最精彩的一步：「你把 B 模型作为初始权重，去把那些**所有数据**再跑一遍。这个目的其实就是为了得到一个好一点的初始权重」。**因为被删掉的"垃圾数据"里包含小目标——而小目标恰恰是你的任务要检出的，不能真删**。所以最终流程是：干净数据训出好初始权重 → 回到全量数据继续训。老师说"这个时候才有可能有奇效"。
- **【连接】** 这套"用模型给数据打分 → 筛 → 训 → 再回全量"的流程，正是现在大模型数据工程的核心套路（老师：他们天天就做这玩意儿，怎么去评估数据的质量"）。
- **【面试用法】** 老师明说了这是"出去吹牛、面试的时候可以说"的料：「他们会问你，你注意力怎么加，为什么我加注意力老不成功？那你就问他：你加注意力，有听说过三个条件吗？」

### 43 涨幅的真话：0.5~1.5，不是 3~5（02:30:00 – 02:39:01）
> **文老师**：「涨多少了？现在有些人吹得很高，涨三个点、五个点。**最多 0.5 到 1.5，我的经验是 0.5 到 1.5**。……你们现在写简历特别喜欢用 AI 写，AI 一吹就是三个点五个点，没有。CSDN 上还有涨十个点的，我只怀疑他数据没有清洗。」

- **【直译】** 把三个条件全部满足、操作也做对，SE 带来的收益是 **+0.5% ~ +1.5%**。
- **【为什么】** "涨十个点"意味着基线本身有严重缺陷（数据没清洗、超参没调、训练不充分）——**改进量大往往说明基线烂，不说明方法好**。这是评估任何论文/博客的第一道过滤器。
- **【连接】** 把本课出现的三个数字排在一起，你就有了一张"单点改进收益表"：
  | 改动 | 老师给的实测涨幅 |
  |---|---|
  | 调 depth/width 因子 | +0.3 左右（调得好） |
  | 下采样层去掉 ReLU | +0.3 ~ +0.4 |
  | 加 SE 注意力（满足三条件） | +0.5% ~ +1.5% |
  **这就是工程改进的真实量级。**（顺带：把 yolov5s 的 width 从 0.50 调到 0.375、看 mAP 掉多少，是你最容易上手的第一个改模型对照实验。）你写简历、答面试报这个区间，比报"提升 5%"可信一百倍。

### 44 什么样的激活函数是好的（02:44:00 – 02:46:00）
> **文老师**：「我们不学这种具体的函数名字，你记不住。你要学的是什么样的激活函数是好的。……叫无上界、有下界、负半轴要有一个平滑的过渡就行了。当然这里还不能太大，你想一个 x 的值太大了，是不是有问题？有可能爆嘛。」

- **【画面】** PPT 底部红字大标题：「**什么样的激活函数是好的？**」，答案一行：「**无上限，有下界。负半轴，要有平滑过度。**」（老师用蓝笔把"无上限""有下界""负半轴"三处都划了线）。
- **【直译】** 三条判据：
  1. **无上界**——正方向不饱和，梯度不会消失（ReLU 满足，Sigmoid/Tanh 不满足）。
  2. **有下界**——负方向有界，起到隐式正则、防止激活值发散（ReLU 满足，Leaky ReLU 弱满足）。
  3. **负半轴平滑过渡**——这是 ReLU 唯一不满足的一条，也是 Swish/GELU/Mish 存在的全部理由。
- **【为什么】** 老师给出的机制一句话点透：「你看他这里有一个平滑过渡，0 到 −4 之间是有个平滑过渡的，**这意味着神经元没有大量死亡**」。**ReLU 在 x<0 处导数恒为 0 → 一旦某个神经元被推到负区就再也醒不过来（Dying ReLU）**；平滑过渡意味着负区仍有微小梯度，神经元还有机会复活。
- **【连接】** 用这三条去评判你见过的所有激活函数：ReLU（✓无上界 ✓有下界 ✗不平滑）；LeakyReLU（✓✗有下界但趋向 −∞ ✓半平滑）；SiLU/Swish（✓✓✓ 全满足）；GELU（✓✓✓）；Mish（✓✓✓）。**现代网络清一色选后三个，不是巧合。**

### 45 Hard-Sigmoid 与 Swish/SiLU 的公式与代价（02:46:00 – 02:50:01）
> **文老师**：「这个激活函数叫 Hard-Sigmoid，就是 MobileNetV3 里面的。你看他最多是几了？1.0。然后这里就是他的负半轴，负半轴在 0 到负 2.5……主要是我们要记这个函数，记这个就行了。是哪一条呢？beta 取的是 1.0，就是这条。」

- **【画面·Hard-Sigmoid】** 公式分段完整可读：
  `hard_sigmoid(x) = 0            (x < −2.5)`
  `                  0.2x + 0.5   (−2.5 ≤ x ≤ 2.5)`
  `                  1            (x > 2.5)`
  优点：「为 Sigmoid 的分段线性近似 / 提高了 Sigmoid 的计算效率」；缺点：「梯度硬饱和 / 输出不为 0 均值，不利于优化 / 对一部分输入无响应」。
- **【画面·Swish】** 公式 `f(x) = x * sigmoid(βx)`，曲线图里画了 β=0.1 / 1.0 / 10.0 三条线（老师说"要记的是 β=1.0 那条"，**β=1 时 Swish 就是 SiLU**）。优点栏原文：「介于线性函数与 ReLU 函数之间的平滑函数 / **无上界、有下界、非单调** / **Swish 在深层模型上的效果优于 ReLU**，例如，仅仅使用 Swish 单元替换 ReLU 就能把 Mobile NASNetA 在 ImageNet 上的 top-1 分类准确率提高 **0.9%**，Inception-ResNet-v 的分类准确率提高 **0.6%**」；缺点栏：「**包含指数计算，速度慢**」。老师在旁边圈出 0.9%。
- **【推导/代码】** `nn.SiLU()` = `x * torch.sigmoid(x)`；`nn.Hardswish()` = `x * relu6(x+3)/6`（用分段线性代替 sigmoid，避免指数运算）。**Hard-Sigmoid / Hard-Swish 的全部存在意义就是"把 exp 换成加法和乘法"**，这在没有专用指数单元的嵌入式芯片上能省一大截。
- **【为什么】** 注意 PPT 里出现的两个数字 0.9% 和 0.6%：**这就是"换一个激活函数"的天花板量级**，和前面 SE 的 0.5~1.5 是一个数量级。老师顺口说了句"CVPR，30 万"——一篇顶会的核心贡献可能就是这 0.9%。
- **【连接】** YOLOv5 的默认激活就是 `nn.SiLU()`（老师："这个也是 YOLO 用的"）——原因你现在能解释了：三条判据全过，且 GPU 上算 exp 不贵。

### 46 工程用法：训练用 SiLU、推理换 ReLU（02:50:01 – 02:53:02）
> **文老师**：「所以这个函数你是需要（指数）……训练的时候用它，推理的时候可以不用它。训练用它，然后推理就用 ReLU，因为 ReLU 要快一点嘛。……其实正常的操作是这样的：你先用 SiLU 去训练，训练打造一个模型，把这个模型作为你第二轮训练的初始权重，然后把你的激活函数给改了，改成 ReLU。这个就相当于有一个好的出身。」

- **【直译】** 两段式：**第一轮用 SiLU 训（好优化、精度高）→ 用它当初始权重 → 第二轮换成 ReLU 微调（推理快）**。
- **【推导/代码】** 老师说他见过两种做法：
  1. **改成 ReLU 再训一次**——"我觉得这种保险一点"。
  2. **导 ONNX 的时候直接把算子换成 ReLU**，不重训——"有人这么干"，但老师自己没干过，并警告"确实有可能会掉点"。
  和 Part 5 的"去 ReLU"策略一样，**换激活函数不改变任何参数形状**，所以权重可以直接 `load_state_dict` 迁过去。
- **【为什么】** 这是"**训练求精度、推理求速度**"这类"训推分离"技巧的代表，同类还有结构重参数化（RepVGG）、BN 折叠、蒸馏——**共同点是训练态和推理态可以不是同一个图**。
- **【连接】** BEV 部署里这套思路也很常见：训练用完整的 deformable attention，推理换成算子友好的实现。你以后接触 TensorRT 插件开发会天天遇到。
- **【⚠ 术语提醒】** 老师提到了一个真实存在的命名混乱：「那是因为代码里面那个名字叫 SiLU，但是人家论文里面叫 Swish……还是要以论文为主」。准确说法是：**Swish 是论文名（`x·sigmoid(βx)`，β 可学），SiLU 是 β=1 的特例，PyTorch 里叫 `nn.SiLU`**。

### 47 收尾：四点总结与 NAS（02:54:00 – 02:58:00）
> **文老师**：「总结一下：V1 最重要的是深度因子、宽度因子、分辨率的关系。V2 其实最重要的就是引出了一个倒残差，但是我们又讲了一个工程里面可以借鉴的，就是下采样的时候可以去掉 ReLU——这是我们看论文学知识最重要的是要能迁移。第三个就是我们说的 SE……以及注意力在什么样的情况下才有效。第四个就是 SiLU 这个激活函数，以及什么样的激活函数是好的。」

- **【直译】** 老师自己给的四点考纲，和本笔记的 Part 4/5/7/8 一一对应。他明确说"具体的激活函数不用记，记不住，你就只需要记住 SiLU 就可以了"。
- **【NAS 部分】** 学员问 V3 的结构怎么来的，老师答：「谷歌有一个叫自动搜索……**V3 它是通过 NAS 这门技术搜出来的，它不是人为设计出来的**。就是用深度学习去发现深度学习的模块，自动地把这些模块进行某种组合，组合完了之后就去跑那个数据集，能够取得一个最高的分。」但他随即泼冷水：「**这个热点已经过了**……自动搜索出来的确实在某些时候还可以，但是现在已经被推翻了，它并不是一个最好的模型。」
- **【⚠ 纠错】** 老师说 NAS 是"2011 年以前的一个热点"——**这是口误**。NAS 的热潮是 **2017–2019**（NASNet 2018、MnasNet 2019、MobileNetV3 2019、EfficientNet 2019），2020 年后逐渐降温。他也坦承"这门技术我没去研究过，我讲不了"。
- **【为什么】** 这个坦率值得记：**知道一个技术的边界（"这个热点过了、我不懂"）比硬讲一通更专业**。
- **【连接】** 老师最后预告了下节课：其他几个重要的视觉注意力机制（CBAM/CA 等）+ ShuffleNet。

**【小结】**
1. 加注意力涨点的三条件：**①基线已有 90 分 ②加在深层网络后（噪声少）③数据质量高**；配套操作是"用模型给数据打分筛好数据 → 加 SE 重训 → 再拿它当初始权重回全量数据训"。真实涨幅 **+0.5%~1.5%**。
2. 好激活函数的三条判据：**无上界、有下界、负半轴平滑过渡**（防神经元大量死亡）。SiLU/Swish 全过；Hard-Sigmoid/Hard-Swish 是它们的"去指数"廉价版，为嵌入式而生。
3. 工程套路：**训练用 SiLU、推理换 ReLU，靠权重迁移接上**——和 Part 5 的"先带 ReLU 训再去掉"是同一个方法论。MobileNetV3 的结构是 NAS 搜出来的，但 NAS 这个热点已经过去。

### 复习最小集（背下这三段就等于听过这节课）

1. **三个因子怎么落到代码上**：宽度因子乘通道数（`_make_divisible(C×α, 8)`，必须被 8 整除、最小 8）；深度因子乘重复次数（`floor(n×d)`）；分辨率因子乘输入尺寸。yolov5s = `depth_multiple 0.33, width_multiple 0.50`，四个 C3 实际重复 1/2/3/1，通道 32/64/128/256/512。**调这两个数换的是速度，精度顶多 +0.3。**

2. **倒残差 + 下采样线性输出**：中间那层是 DW（没有通道间融合、能力弱），所以要先升维 6 倍再降回来；两端是低维空间，ReLU 会破坏特征（等高线还原图 dim=2 时只还原一半），所以最后那个 1×1 不加激活。**s=2 那一行要拆成"下采样 1 次 + 倒残差 (n−1) 次"**。可迁移到 YOLO：去掉前两三个下采样层的激活，配合"先带 ReLU 训 → 权重迁移 → 去掉再训"，实测 +0.3~0.4。

3. **注意力 = 通过某种条件重新提取特征、改变原来评分的分布，目的是让损失更小**。SE 五步：GAP → 1×1 压到 C/4 → ReLU → 1×1 还原 → Sigmoid（逐通道独立，不是 Softmax）→ 逐通道相乘。加了只有三种结局：变好 / 变差 / **一定变慢**。涨点三条件：**基线已有 90 分 + 加在深层 + 数据质量高**，真实涨幅 0.5%~1.5%。

### 一句话带回工位

> 看论文的价值不在于"我读懂了这篇论文"，而在于"**我能把它的思想搬到我自己的模型上去**"——V2 的"下采样不用 ReLU"、SE 的"三条件"、Swish 的"训练用它推理换 ReLU"，这三条都不是 MobileNet 专属的，它们对你手上的任何一个 backbone 都成立。
