# Part 1　深度学习断代史：LeNet-5 → AlexNet 的 14 年空白

**【本段在讲什么】**
文老师这节课先不写代码，而是从 1998 年的 LeNet-5 讲到 2012 年的 AlexNet，把中间空白的 14 年掰开讲。这段看起来像"科普闲聊"，其实是在给你**建立一条时间轴**：后面所有网络（VGG / GoogLeNet / ResNet）都要往这条轴上挂。更重要的是，他用这 14 年的三个"卡点"——算力、过拟合、数据集——把深度学习为什么必须依赖 GPU 和大规模数据这件事讲透了。最后落到 AlexNet 的三个历史贡献，以及 Top-1 / Top-5 这两个至今还在用的评价指标。

### 1　开场：先看 LeNet-5，1998 年那条起跑线（00:01:37–00:02:01）

> **文老师**：「我讲几个经典网络啊，我们先看看那个 LeNet-5。LeNet-5 呢，是 1998（年）。这是 LeNet-5，就是这里其实是有故事的啊。」

- **【直译】** 这一讲的主线是"几个经典 CNN 分类网络"，起点是 1998 年的 LeNet-5。
- **【画面】** 屏幕上是 PPT"11.卷积神经网络 LeNet5"，一张典型的 LeNet 结构示意图（输入 → 卷积 → 池化 → 卷积 → 池化 → 全连接）。左侧老师已经手写了两行红字："SVM 支持向量机 / 决策树"，用大括号归到"以前"这一栏。
- **【为什么】** 老师选择从史学切入而不是从代码切入，是因为**代码线学员最容易犯的错是"拿来就用"**——不知道一个网络诞生时解决的是什么约束，就不知道在你自己的场景里该拆掉哪一块。这一整段史学是 Part 3「VGG 怎么改」的伏笔。
- **【连接】** 你的 MNIST 默写模板（Conv2d→ReLU→MaxPool→Flatten→Linear）本质就是 LeNet-5 的结构，只是把 Sigmoid/tanh 换成了 ReLU、把平均池化换成了最大池化。也就是说你已经默写过 1998 年的 SOTA 了。

### 2　为什么空白了 14 年：三个卡点（00:02:44–00:03:26）

> **文老师**：「这 14 年为什么没有发展，对不对？其实（有几）个原因。一个原因叫算力不足……就是当时 GPU 还没(火)出来……第二个原因就是，（容易）过拟合，这种网络啊，会过拟合。第三个原因就是，当时没有一个公开的大规模的数据集。」

- **【直译】** 1998→2012 的空窗期有三个原因：① 算力不足（GPU 产业没起来）；② 网络容易过拟合；③ 没有公开的大规模评测数据集。
- **【推导/代码】** 三个原因其实是一个三元组约束：**参数量 P、数据量 N、算力 C**。深度网络要有效，需要 N ≫ P（否则过拟合）且 C 足够跑完 N×epochs。1998 年 N 只有 MNIST 的 6 万张、C 是单核 CPU，所以 P 只能压到 6 万参数量级——这就是 LeNet-5 只有 5 层的根本原因，不是当时的人想不到深层。
- **【为什么】** 老师把"过拟合"排在第二位很关键：**深度不是免费的**。层数上去、参数上去，如果数据没跟上，验证集立刻崩。这条会在 Part 3 变成一条可执行规则——"数据少就选 VGG-A（11层），不要选 D（16层）"。
- **【连接】** 这正是你在 4060 上跑 BEVFusion 只有 mini 数据集时会遇到的困境：模型容量（SECOND backbone 那么大）远超 mini 数据量，你观察到的 loss 曲线好看但指标上不去，多半就是同一个病。

### 3　李飞飞与 ImageNet：教母级的贡献（00:03:32–00:04:19）

> **文老师**：「大概是 2010 年时候，这个叫李飞飞，叫人工智能教母，搞了一个叫 ImageNet 的（数据集）。他主持的……有多少个类呢？有 1000 个类。大概（120）多万张……他搞出来了这个，然后呢，学术界就开始打比赛，就刷榜。」

- **【直译】** 李飞飞主导的 ImageNet 数据集（1000 类、百万量级图片）出现后，学术界有了统一的刷榜擂台，深度学习才有了"证明自己"的场地。
- **【画面】** 老师在 PPT 右侧手写："2010 李飞飞 / 1000个类 ImageNet"，并画了大括号归到时间轴上，与左边"1998 LeNet-5"和右上"2012年 AlexNet"三点连成一条线。
- **【推导/代码】** ⚠ 数字要校准：老师口播说"300多万张还是200多万张"，但后面自己改口说"120万张"，PPT 原文也写的是"ImageNet LSVRC-2010（数据集有 **120 万张**图像，**1000** 个不同的类别）"。ImageNet 全库约 1400 万张，ILSVRC 竞赛子集训练集约 128 万张——面试报数就报 **1000 类 / 120 万张训练图**。
- **【为什么】** 老师专门强调"你要知道李飞飞这个人物"——面试里问"深度学习为什么在 2012 年爆发"，标准答案是三件套：**数据（ImageNet）+ 算力（GPU）+ 算法（ReLU/Dropout/深层 CNN）**，缺一不可。只答算法会被追问。

> 🗀 折叠【00:04:34–00:06:40】插叙：这 14 年真正统治业界的是 SVM（支持向量机）和决策树/随机森林（集成学习），可解释性强；金融行业至今还在用它们而不用深度学习，原因是可解释性 = 安全性。老师说"有兴趣的同学可以去看看这两个"，属于扩展，不影响主线。

### 4　AlexNet 的第一个故事：断崖式领先（00:06:46–00:07:29）

> **文老师**：「2012 年我们现在有 ImageNet 了，然后他们去打比赛，这哥们当时打了个叫断崖式领先。什么叫断崖式领先？他比第二名高了 23 个点左右……所以我们现在把深度学习能'救活'的原因，第一个原因就是他做了这个比赛，把深度学习救起来了。」

- **【直译】** AlexNet 在 ILSVRC 2012 上以巨大优势夺冠，这一战把深度学习从冷宫里救了出来。
- **【推导/代码】** ⚠ "高 23 个点"是口误。真实数据：AlexNet top-5 错误率 **15.3%**，第二名（传统方法）**26.2%**，领先 ≈ **10.9 个百分点**。而 PPT 上写的 37.5% / 17.0% 是 LSVRC-2010 数据集上的 top-1 / top-5 错误率。老师批注在 PPT 上的 "62.5 83" 就是把错误率换算成正确率：100−37.5 = 62.5（top-1 acc），100−17 = 83（top-5 acc）。
- **【为什么】** 老师反复强调"断崖式"这个词，是因为**渐进式提升说服不了学术界，断崖式才能改变范式**。这也是他后面讲"你在公司里提一个奇思妙想的方案，必须拿实验结果堵领导的嘴"时的同一个逻辑。
- **【连接】** 类比你熟悉的 nuScenes 榜：BEVFusion 相对纯 LiDAR 方法的 NDS 提升也就几个点，属于渐进；真正"断崖"的是 2020 年 CenterPoint 用 anchor-free 中心点头把两阶段检测甩开的那一次。

### 5　AlexNet 的第二个故事：两块显卡与手搓分布式框架（00:08:04–00:09:23）

> **文老师**：「他在这个数据集去训练的时候，找了微软云，微软云给他提供了很多 CPU 的电脑……然后跑不动，跑了一两个月跑不动。然后刚好因为……黄（仁勋）听说了，Alex，这是他的名字……送了两块很老的显卡。然后这哥们就手搓了一个分布式的深度学习框架。」

- **【直译】** AlexNet 最初在 CPU 集群上跑了一两个月跑不动，后来拿到两块早期 NVIDIA 显卡，作者自己手写了一套双卡并行训练框架才跑出来。
- **【画面】** PPT 原文佐证了这个细节，只是数字更精确：「受限于当时 **GTX 580 GPU** 硬件的限制，原始模型使用 **2 块显卡并行训练**，随着硬件性能的提高，本文将其合并为 1 个 GPU 来实现训练，故其结构图更改为图 4-44。」——这是转写完全没有的信息。GTX 580 显存只有 3GB，装不下整个网络，才被迫做通道维度的双卡切分。
- **【推导/代码】** AlexNet 的"分组卷积（group convolution）"就是这么被逼出来的：把 96 个卷积核劈成两组各 48 个，分别放两张卡上，只在特定层交换信息。这个纯粹为省显存的 hack，后来被 ResNeXt / ShuffleNet 发扬成了正经的效率设计。
- **【连接】** 你上节课学的 **DW 卷积（depthwise）就是分组卷积把 groups 推到极限 = C 的特例**。所以"分组卷积"这条线是：AlexNet 省显存 → MobileNet 省算力 → ShuffleNet 省访存。

### 6　AlexNet 的三条历史功绩 + 训练只用两天（00:09:35–00:11:09）

> **文老师**：「牛就牛在哪里了？他就只训练了两天……然后断崖式领先，然后学术界就炸了。他解决了：第一个，他是第一个用 GPU 来训练的；第二个，他还自己搓了一个分布式的训练框架；第三个就是在 ImageNet 上从来没有人比他牛逼过。所以就奠定了从 2012 年到 2022 年，深度学习跨越式发展。」

- **【直译】** AlexNet 的三条功绩：首次用 GPU 训练、自研分布式训练框架、ImageNet 上前所未有的领先。它开启了 2012–2022 这十年的深度学习黄金期。
- **【画面】** 老师在 PPT 右侧用蓝笔框了三条批注：「① 证明了深度学习的可能性 ② **GPU 是 AI 必需品** ③ 用 3 个 3×3 = 7×7」。注意②这条是他给这一段下的最终定论。
- **【为什么】** "只训练两天"这个细节比"领先多少点"更重要——它说明**瓶颈从来不是想法，是迭代速度**。CPU 上一两个月一轮实验，你一年做不了几次尝试；GPU 上两天一轮，一个月能试十几个方案。深度学习的胜利本质上是**实验吞吐量的胜利**。
- **【连接】** 直接对应你的处境：4060 上 BEVFusion 实测 0.481 s/iter，mini 数据集一个 epoch 几分钟——正因为这个吞吐量，你才能一天试好几组超参。如果还是 CPU，你这条转岗路根本走不通。

### 7　AlexNet 的结构与 Top-1 / Top-5（00:11:49–00:14:20）

> **文老师**：「这个网络其实从结构来说的话，其实就没什么东西了……它唯一的特点就是这里，你看这里有一个 3×3，这里有一个 3×3，这里也有个 3×3，就是跟我们昨天说的，三个 3×3 就是一个 7×7……然后这里有两个指标，叫 Top-1、Top-5。Top-1 是什么呢？就是假设里有 1000 个类，你概率最大的与 GT 是一样的，就叫 Top-1。Top-5 是什么？你前五个概率当中只要有一个对就算对。」

- **【画面】** PPT 上的 AlexNet 完整数据流（这是转写里没有的核心增量）：
  `输入 227×227×3 → 卷积 k=11×11 s=4 → 55×55×96 → 最大池化 k=3×3 s=2 → 27×27×96 → 卷积 k=5×5 s=1 p=2 → 27×27×256 → 最大池化 k=3×3 s=2 → 13×13×256 → ③卷积 3×3 s=1 p=1 → 13×13×384 → ④卷积 3×3 → 13×13×384 → ⑤卷积 3×3 → 13×13×256 → 最大池化 3×3 s=2 → 6×6×256 → ⑥FC 4096 → ⑦FC 4096 → ⑧输出 1000 分类`
  老师用红圈把 ①~⑧ 标了序号，并在旁边写"**池化是不算层的，只算有参数的**"。
- **【推导/代码】** 8 层 = 5 个卷积 + 3 个全连接。**层数只数带可学习参数的层**（Conv / FC / BN 有争议），池化、激活、Dropout 都不数——这是面试里"VGG16 的 16 从哪来"的同一套数法（13 conv + 3 FC）。
- **【为什么】** Top-5 存在的历史原因是 ImageNet 有 1000 个细分类（哈士奇 vs 爱斯基摩犬），Top-1 太苛刻。但老师明确说：「在工业上就不靠谱……我们工业要的是 Top-1。」因为你的产线只会给一个判定结果，不能说"我猜是这五个之一"。
- **【连接】** 你的 BEV 场景里对应的指标是 nuScenes 的 mAP（严格）和 NDS（复合），没有 Top-5 这种宽松指标——3D 检测天然就是 Top-1 语义。

**【小结】**
① 1998→2012 的空白由算力、过拟合、数据集三个卡点共同造成，缺任何一个都爆发不了。
② AlexNet 的功绩不在结构（5 conv + 3 FC 很平庸），而在"首次 GPU 训练 + 手搓双卡并行 + 断崖式刷榜"这三件工程事。
③ 层数只数有参数的层；工业上只认 Top-1。

# Part 2　VGG 的身份证：卷卷池范式与 backbone 地位

**【本段在讲什么】**
这一段老师切到 VGG 的原始论文配置表（ConvNet Configuration，A/A-LRN/B/C/D/E 六列）。他要你记住三件事：VGG 的结构口诀"卷卷池"、它在 2014 年比赛里的战绩、以及最关键的一条——**VGG 特别适合做 backbone**。他还补了两条时间线证据：2018 年 ShuffleNet V2 间接证明了 VGG 式直筒结构最快，2022 年又有论文"让 VGG 再次伟大"。这段是全课"为什么值得花一小时改 VGG"的正当性来源。

### 8　VGG 的结构口诀：卷卷池 ×3 + 3 个 FC（00:16:07–00:16:51）

> **文老师**：「VGG 这个网络，你可能要背一背这个结构。你干五年算法的人，VGG 的结构你都背不出来，对吧？叫卷卷池，卷卷池，卷卷池，来三次，然后三次，再全连接。而且他这个也好（记）：64、128、256、512。」

- **【直译】** VGG 的结构可以压成一句口诀：**卷卷池 → 卷卷池 → (卷卷池)×3 → 3 个全连接**，通道数按 64 → 128 → 256 → 512 → 512 翻倍递增。
- **【画面】** 老师在 PPT 右下角用红笔框了一个大方块，写着「**卷卷池 → 卷卷池 → 卷卷池×3 + 3个FC**」。左上角写"2014"。配置表本体：input(224×224 RGB) → conv3-64 ×2 → maxpool → conv3-128 ×2 → maxpool → conv3-256 ×3 → maxpool → conv3-512 ×3 → maxpool → conv3-512 ×3 → maxpool → FC-4096 → FC-4096 → FC-1000 → soft-max。
- **【推导/代码】** 用 PyTorch 写就是一个可复用的 make_layers：
  ```python
  cfg_D = [64,64,'M', 128,128,'M', 256,256,256,'M', 512,512,512,'M', 512,512,512,'M']
  # 每个数字 = nn.Conv2d(in, out, 3, padding=1) + ReLU；'M' = nn.MaxPool2d(2, 2)
  ```
  全部卷积核都是 3×3、stride=1、padding=1（所以卷积不改 H/W），**只有 maxpool 在降分辨率**，每次 ÷2。这就是"卷卷池"能当口诀的原因：分辨率变化点唯一。
- **【连接】** 这个"卷积只提特征、池化(或 stride-2)只降分辨率"的解耦设计，你在 BEVFusion 的 SECOND backbone 里能看到同一套骨架：`(64,512,512) → (128,256,256) → (256,128,128)`，每个 stage 一次 stride-2 下采样 + 若干个 3×3 保持分辨率。名字变了，范式没变。

### 9　VGG 的核心考点：最适合做 BackBone（00:17:00–00:17:50）

> **文老师**：「一般没人问到底，但是问到底你答不上来，你就死翘翘。因为 VGG16 就这句话：VGG16 特别适合做 backbone，就是做其他网络的特征提取器。你搞这一行，你怎么可能不知道 VGG？」

- **【直译】** VGG 这一节唯一必须背下来的结论是：**VGG16 特别适合做 backbone / 特征提取器**。
- **【画面】** 老师用红笔在 PPT 上写并加了双下划线：「**VGG16 特别适合做 BackBone**」。这是整张 slide 上唯一被划双线的一句。
- **【为什么】** 为什么 VGG 适合做 backbone 而 GoogLeNet 不适合？三个技术原因老师后面才零散给出，这里帮你合并：
  ① **结构极度规整**——全是 3×3 直筒，砍到任意一个 maxpool 后面都能干净地引出一路特征图；Inception 的多分支 concat 输出你不好切。
  ② **多尺度中间层现成**——5 个 maxpool 天然给你 stride 2/4/8/16/32 五个层级的特征图，正好喂给 FPN。
  ③ **访存友好**——直筒结构没有分支等待，GPU 上实测吞吐比同等 FLOPs 的多分支结构高（这就是下一张卡说的 ShuffleNet V2 结论）。
- **【连接】** YOLO 系列的 backbone（DarkNet-19/53、CSPDarknet）本质上都是"VGG 直筒 + 残差/CSP 补丁"。你在 YOLO 配置文件里看到的 `[convolutional] size=3 stride=1` 连着一堆，就是卷卷池换了个写法。

### 10　两条时间线证据：ShuffleNet V2 与"让 VGG 再次伟大"（00:17:52–00:18:50）

> **文老师**：「最搞笑的是呢，（2018）年有篇论文，ShuffleNet V2 的时候，他证明了 VGG 应该是最快的，间接证明。但是 2022 年的时候，有一篇文章叫'让 VGG 再次伟大'，他做到了一个什么事情呢？让 VGG 又快又准。」

- **【画面】** 老师板书原文：「**2018, ShuffleNet V2 · 证明 VGG 最快**」「**2022(2023)? 让 VGG 再次伟大 → VGG 又快又准**」。注意板书写的是 2018，口播说成了"2012年"——以板书为准。
- **【推导/代码】** ShuffleNet V2 论文提出了四条实用准则（G1~G4），其中 **G3「网络碎片化（多分支）降低并行度」** 和 **G4「element-wise 操作不可忽视」** 恰好是对 Inception 式多分支的批评。它用实测延迟（而不是 FLOPs）证明：**同样 FLOPs 下，分支越少、通道数越均衡的直筒网络实际跑得越快**——这就是"间接证明 VGG 最快"的含义。
- **【连接补充】** "让 VGG 再次伟大"指的是 **RepVGG（CVPR 2021，Making VGG-style ConvNets Great Again）**：训练时用多分支（3×3 + 1×1 + identity）拿精度，推理时用**结构重参数化**把三条分支合并成一个 3×3 卷积核，变回纯直筒。它同时拿到了多分支的精度和直筒的速度。
- **【为什么】** 老师花这两分钟不是掉书袋，是在给你一个**范式判断**：网络设计不是单向进化，"老结构"经常因为硬件特性回潮。你评估 BEV backbone 时，别只看论文的 mAP，要看**在你的部署硬件上的实测延迟**。

### 11　2014 年的战绩：VGG vs GoogLeNet（00:18:56–00:19:23）

> **文老师**：「你要记住这个时间，是 2014 年。VGG 是 2014 年，他当时去参加这个比赛，他是分类（网络的）……冠军亚军。GoogLeNet 另外一个网络，是当时的冠军。目标检测里面的冠军，但 GoogLeNet 是亚军。也就是说，VGG 其实在特征提取这一个层面非常的强。」

- **【画面】** 老师板书原文（蓝笔）：「**VGG16 分类网络亚军，GoogLeNet 冠军 / 目标检测 VGG 冠军，GoogLeNet 亚军（特征提取）**」。
- **【推导/代码】** ⚠ 需要校准：ILSVRC-2014 的真实赛果是——**分类（classification）**：GoogLeNet 第一，VGG 第二；**定位（localization）**：VGG 第一；**检测（detection）**：GoogLeNet 第一。老师板书里的"目标检测 VGG 冠军"应该改成"**定位任务 VGG 冠军**"。面试时说错这个会被当成没读过论文。
- **【为什么】** 但老师从这个战绩里提炼的结论是对的、而且是重点：**分类输给了 GoogLeNet，定位却赢了 GoogLeNet，说明 VGG 的特征在空间上更"干净"**——定位需要精确的几何信息，多分支 concat 会把不同感受野的特征混在一起，反而模糊了空间边界。这正是 VGG 适合做检测 backbone 的深层原因。
- **【连接】** BEV 感知本质上是定位任务（要出 3D 框的中心、尺寸、朝向），对空间精度的要求远高于分类。这解释了为什么 BEV 的 backbone 至今仍偏爱规整的 SECOND / SparseConv 直筒，而不是花哨的多分支。

> 🗀 折叠【00:19:35–00:20:30】案例插叙：荣耀手机屏下指纹的活体检测算法是学员师兄做的（2022 年前后），选型选的是 GoogLeNet。老师顺带吐槽了项目组。这个案例在 01:24:03 会被重新捡起来讲模型量化，那里才有技术信息。

### 12　这一段的三件事收口（00:20:29–00:21:10）

> **文老师**：「这里就是我们就说了三个事情：第一个事情就是你这个网络结构你要记；第二个就是 VGG 特别适合做 backbone……这就是为什么要考证一下历史。」

- **【直译】** VGG 这一节的产出：① 背结构（卷卷池 + 64/128/256/512）；② 记住"最适合做 backbone"这句话；③ 理解读历史的意义——历史告诉你这个网络的定位。
- **【为什么】** 老师说"为什么要考证一下历史，其实就是这个原因"——因为**网络的历史定位决定了你在项目里该怎么用它**。VGG 的历史定位是"特征提取强、参数量爆炸"，所以正确用法是：**要它的卷积主干，砍它的全连接头**。这句话是 Part 3 全部内容的一句话总纲。
- **【连接】** 你迁移到 BEV 上，同一句话变成：**要 SECOND 的稀疏卷积主干，头换成 CenterPoint 的中心点头**。BEVFusion 就是这么组装的。

**【小结】**
① VGG 结构口诀：卷卷池 → 卷卷池 → 卷卷池×3，通道 64→128→256→512→512，尾巴三个 FC。
② 必背结论：VGG16 最适合做 backbone / 特征提取器；2018 ShuffleNet V2 侧证它最快，2021 RepVGG 让它又快又准。
③ 2014 战绩要说对：分类亚军、**定位冠军**（不是检测冠军）。

# Part 3　VGG 怎么改：A/B/C/D/E 配置的四条件选型

**【本段在讲什么】**
这是全课第一块硬骨头，也是老师自称"算法工程师最值钱"的部分。VGG 论文给了 A(11层)/A-LRN/B(13层)/C(16层)/D(16层)/E(19层) 六种配置，问题是：**你的项目该选哪一个？** 老师给出四条判据（数据量、特征复杂度、目标大小、输入图像尺寸），并给了一条无条件必改项：**FC 4096 必须砍到 256 或 128**。这一段的每一条都是经验值，但老师给了每条经验背后的推理。

### 13　先淘汰 A-LRN：LRN 已经过时（00:21:29–00:21:51）

> **文老师**：「我们看到这里有很多尺寸，有 A，有 B，有 C，有 D，还有 E。当然这里还有一个 A-LRN，LRN 是一种（归一）化的方法，现在已经淘汰了。所以我们就只有 A、B、C、D（、E）。」

- **【直译】** 配置表里的 A-LRN 那一列可以直接划掉，LRN（Local Response Normalization，局部响应归一化）这个技术已经被淘汰了。
- **【画面】** 老师用红笔在表头的 A-LRN 那一列上打了个大 ✗，并在 A / B / C / D / E 上分别画了圈标序号。
- **【推导/代码】** LRN 是 AlexNet 引入的：对同一空间位置、相邻若干通道做一次侧向抑制归一化。VGG 论文自己做的消融就发现 **A-LRN 相比 A 没有提升，还增加了 ~2% 的显存和计算**，所以后续配置全部弃用。真正接管归一化位置的是 2015 年的 **BatchNorm**——按 batch 维度对每个通道做标准化，既稳定训练又允许更大学习率。
- **【连接】** 你的 MNIST 模板里如果写了 `nn.BatchNorm2d(out_c)`，那就是 LRN 的现代继任者。BEVFusion 的 SECOND backbone 里每个 SparseConv 后面跟的也是 BN + ReLU 三件套。

### 14　必改项 ①：FC 4096 → 256 / 128（00:23:15–00:25:20）

> **文老师**：「原因在哪里啊？就是全连接的参数太多……你要减少。减少多少？256 左右就可以了，从 4096 变 256……最后一层是你的（类别数）嘛，有 10（个）。所以这边放 256 或者 128 都可以，大部分的任务够了。为什么？因为你不是 ImageNet 啊，你没有 1000 个类啊，没有 120 万张图片。」

- **【直译】** VGG 慢/大的根源是三个全连接层的参数量，必须把 FC-4096 改成 FC-256 或 FC-128，最后一层改成你自己的类别数。
- **【画面】** 老师板书：「② **全连接参数过多 → 减少：256 / 128，足够**」，以及底部一行加星号的总纲：「**☆ FC 必须要减少 256/128**」。
- **【推导/代码】** 算一下就知道有多夸张。VGG16 输入 224 时最后一层特征图是 7×7×512 = 25088：
  ```
  原版 FC1: 25088 × 4096 ≈ 1.028 亿参数
  原版 FC2:  4096 × 4096 ≈ 1678 万
  原版 FC3:  4096 × 1000 ≈ 410  万
  三层合计 ≈ 1.24 亿，占 VGG16 总参数(1.38亿)的 ~90%
  ---------------------------------------------
  改后 FC1: 25088 × 256  ≈ 642 万   （降到 1/16）
  改后 FC2:   256 × 128  ≈ 3.3 万
  改后 FC3:   128 × 10   ≈ 1280
  三层合计 ≈ 645 万
  ```
  **改一行代码，参数量从 1.24 亿降到 645 万，砍掉 95%。**
- **【为什么】** 老师给的理由是数据量：FC 的宽度是"表达能力"的上限，4096 是为了拟合 1000 类 × 120 万张才需要的容量。你只有 10 个类、几千张图，4096 维只会让你在验证集上过拟合。这是 Part 1 那条"N ≫ P"约束的直接应用。
- **【连接】** 你的 MNIST 模板 `nn.Linear(64*7*7, 128) → nn.Linear(128, 10)` 恰好就是老师推荐的写法——你其实早就在按这条经验做了，只是不知道它有名字。

### 15　PPT 上的官方三条改造建议（00:58:54，回看）

> **【画面】**（PPT 第 34 页，标题「VGG，如何改？」，转写里老师没有逐条念）
> 「1。改全连接神经元的个数，比如 4096 改成 256/128 足亦。我们的数据集，相对来说较少，不需要那么强的表达能力。
> 　2。数据少，特征容易，选 A 或者 B，网络更轻量，可以缓解过拟合。
> 　3。如果欠拟合，换 vgg16。」

- **【直译】** 这三条是老师整个 Part 3 的官方版浓缩：改 FC 宽度 / 数据少选轻量配置 / 欠拟合再加深。
- **【推导/代码】** 第 3 条给出了一个**闭环调参流程**，比单纯"选哪个"更有用：
  ```
  先上 VGG-A(11层) + FC256
    ├─ 训练 loss 降不下去、train acc 也低  → 欠拟合 → 换 VGG-D(16层) 或加宽 FC
    ├─ train acc 高、val acc 低、差距大   → 过拟合 → 退回 A / 加数据增强 / 加 Dropout
    └─ 两者都好                           → 收工
  ```
- **【为什么】** 注意这个顺序：**从小往大试，而不是从大往小砍**。因为小网络训得快、诊断快，欠拟合的信号（train acc 也上不去）比过拟合的信号更容易识别。反过来先上大网络，你会花很久分不清是过拟合还是数据脏。
- **【连接】** 同样的策略在 BEV 上：先用 mini 数据 + 小 voxel 分辨率跑通，确认 pipeline 没问题，再往上加分辨率和 backbone 宽度。你的训练计划里"无 AMP、只有 mini 数据"其实就是这一档。

### 16　选型条件 ①：数据量 > 5K / 类 才上 16 层（00:25:52–00:28:10）

> **文老师**：「一个是看数据量……数据量大你就要上 19 或者 16……经验是你有个 5000……现在有个问题，是所有 5K 还是每个类别 5K？其实最好是每个类别。如果你有两个类，你就是 1 万张；如果你四个类，就是 2 万张的时候，你直接就选 16 就行了。19 选的很少。」

- **【画面】** 老师板书：「① **看数据量** / Data > 5K（每个类），16 层 D」。
- **【推导/代码】** 阈值表整理如下（老师的经验值）：
  | 每类样本数 | 推荐配置 | 层数 |
  |---|---|---|
  | ≥ 5000 张 / 类 | D（VGG16） | 16 |
  | 极大数据 + 特征复杂 | E（VGG19） | 19，"选的很少" |
  | ~500-600 张 / 类（最常见） | **A（VGG11）** | 11 |
  | 某类只有 20 张 | 别用 VGG，先解决数据 | — |
- **【为什么】** 5000/类 这个数不是拍的：ImageNet 每类约 1300 张训练图能训 16 层，但那是有强增强 + Dropout + 大 batch 的前提。工程上没那么多正则手段，所以老师把安全线抬到 5000。**关键在"每个类"而不是"总共"**——类别不均衡时，最少的那一类决定了你能上多深。
- **【连接】** 这条对你的 BEV 训练有直接映射：nuScenes 有 10 个检测类，其中 bicycle/motorcycle/construction_vehicle 的实例数只有 car 的百分之几。你在 mini 数据上看到的那几个类 AP 为 0，就是"某个类只有 20 张"的 BEV 版本。

### 17　选型条件 ②③：特征复杂度与目标大小（00:29:30–00:30:35）

> **文老师**：「另外一个就是复杂度高的，你还是要选 D……这玩意完全靠你的感觉，靠你自己的判断，叫主观判断。你就选 D，简单你就选 A。然后目标大小……小目标你就去选 A，中大目标你就去选 D。」

- **【画面】** 板书：「② **看特征复杂度** ③ **目标的大小**」，后面标注"小目标 → 简单"。
- **【推导/代码】** 这两条为什么方向不同，值得掰一下：
  - **特征复杂度高 → 选深（D）**：复杂纹理需要更抽象的高层语义，靠层数堆出来。
  - **目标小 → 选浅（A）**：小目标经不起 5 次下采样。224 输入的小目标假设占 20×20 像素，到 VGG16 第 5 个 maxpool 后（÷32）只剩 0.6×0.6 像素——**目标已经被池化掉了**，加再多层也没用。
- **【为什么】** 老师随即补了一句关键限制：「如果真的是很小的目标，你其实不太适合用分类，就要用检测网络。分类网络是很难（做的）……一张很大的图里面就只有一个很小的目标，你又要来用一个分类来做，基本上是做不了。」——这是在划任务边界：**小目标 + 大背景 = 检测问题，不是分类问题**。
- **【连接】** 这条正是 YOLO 加 **P2 检测头**的动机：P2 是 stride=4 的浅层特征图（160×160），专门接小目标；如果只有 P3/P4/P5（stride 8/16/32），小目标在特征图上不足 1 个格子。你已经知道的 P2 头，就是"小目标选浅层"这条经验在检测网络里的制度化。

### 18　选型条件 ④：输入图像尺寸的影响（00:30:48–00:31:36）

> **文老师**：「其实还（有）第四种情况，图像尺寸的影响……比如你们现在（做的）手写数字识别，你们的大小是多少？（28×）28×1 对不对？如果你们要用 VGG，你们还要把它给我搞成 224×224×3 对不对？……你们这个（方案）其实是有点问题的。」

- **【画面】** 板书四条件完整版：「① 看数据量 ② 看特征复杂度 ③ 目标的大小 ④ **图像尺寸的影响**」。
- **【直译】** 第四条判据是输入图像的原始尺寸。老师直接点名批评：把 28×28×1 的 MNIST resize 成 224×224×3 去喂 VGG，方案有问题。
- **【为什么】** 问题有两层：① **信息量层面**——28×28 放大到 224×224 是 8 倍插值，插出来的全是"猜"的像素，不产生任何新信息，只产生模糊；② **网络结构层面**——224 输入的 VGG 有 5 次下采样，是为 224 的信息密度设计的，你喂一张实际信息只有 28×28 的图，后面十几层在处理插值噪声。
- **【连接】** 这条批评直接打到你身上——你的 MNIST 默写模板如果为了套 VGG 而 resize 到 224，就是这个反面教材。正确做法是 Part 5 的匹配律：28×28 这个尺寸应该**减层**（只保留 2 个下采样），或者干脆按老师说的"< 28 直接用全连接"。

**【小结】**
① 无条件必改：FC 4096 → 256/128，参数量从 1.24 亿砍到 645 万（-95%）。
② 四条件选型：数据量（≥5000/类才上16层）、特征复杂度（复杂选深）、目标大小（小目标选浅）、输入尺寸（决定该减几层）。
③ 调参顺序是**从小往大**：先 A + FC256，欠拟合再换 D。

# Part 4　什么叫"困难特征"：轮胎凹陷与 30 秒法则

**【本段在讲什么】**
上一段的选型条件里有一条"看特征复杂度"，学员立刻问：什么叫复杂？这一段老师用真实工业图片（轮胎侧壁凹陷检测）现场演示了简单/中等/困难三档特征长什么样，并给出一个可操作的判据——**你自己看多久能看出来**。这段没有公式，但它给了你一个在需求评审会上能用的量化语言，比"这个任务有点难"专业得多。

### 19　特征复杂度靠主观判断，但主观可以标定（00:31:53–00:32:38）

> **文老师**：「什么叫复杂？什么叫不复杂？那是你人为判断的，这个我们搞不了，没有什么（客观标准）。就是你做得多了，你一看你看得出来的。比如说像我们这个手（写数字），这简单了，这太简单了。像我们那个花，都只能算中（等）。」

- **【直译】** 特征复杂度没有客观公式，是经验判断。老师给了三个锚点：手写数字 = 简单；花卉分类 = 中等；工业缺陷 = 难。
- **【推导/代码】** 虽然老师说"搞不了"，但可以给几个半客观的代理指标（这是我补的，方便你落地）：
  - **类间距离**：不同类的平均像素/直方图差异越小越难；
  - **类内方差**：同一类的姿态/光照变化越大越难；
  - **判别区域占比**：决定类别的区域占整图面积越小越难（MNIST 是整图，轮胎凹陷可能占 1%）。
- **【为什么】** 老师坚持"靠主观"其实是对的：上面三个指标都需要先有标注数据才能算，而你在**立项阶段**做选型时数据还没有。这时候唯一可用的就是人眼判断——所以他要把人眼判断标准化。

### 20　三档特征的 30 秒判据（00:38:12–00:38:56）

> **文老师**：「困难特征就是人都觉得难搞……或者就是说，你看它需要多久？你看它需要 30 秒以上……这玩意就叫困难特征，这种啊，就是噩梦。什么叫中等特征呢？中等特征就是 30 秒以内，就是能看出来。还有简单特征，根本就不用想，像手写数字识别这种，一秒内搞定的。」

- **【直译】** 老师给的量化判据：
  | 档位 | 人眼判定耗时 | 例子 |
  |---|---|---|
  | 简单特征 | < 1 秒，不用想 | 手写数字、猫狗 |
  | 中等特征 | < 30 秒，仔细看能看出来 | 花卉细分类、明显的轮胎凹陷 |
  | 困难特征 | > 30 秒，甚至看不出来 | 微弱凹陷、需要 3D 才能测的形变 |
- **【为什么】** 这个判据的价值在于**它是标注可行性的代理指标**。如果人眼要看 30 秒以上，意味着：① 标注员会标错，你的 GT 本身就脏；② 标注成本会爆炸；③ 类间边界模糊，模型学到的会是噪声。所以"困难特征"的真正含义不是"模型难"，而是"**数据难**"。
- **【连接】** 这也是为什么老师后面会说"有的类别标注时会标一个'不确定'"——困难特征场景里，允许标注"不确定"类比强行二分类更诚实。你在 nuScenes 里见过的同类机制是 `ignore` 区域和低可见度（visibility）标记。

### 21　实例：轮胎凹陷从中等到噩梦的梯度（00:33:00–00:36:20）

> **文老师**：「那我们看看这个（轮）胎，这个是凹进去了……你们这个算难还是算简单？算中的。凹陷……这最多只能算中的。然后最恐怖的是上面，这个也正常……你看这里其实人能看出来凹了一点点，对吧？这玩意儿其实你真的有点不自信……你还看不出来，这个就可以算难的了。」

- **【画面】** 抽帧显示的是一个工业检测软件窗口，连续四张轮胎侧壁照片（暗场打光）：#97~#100 分别是凹陷明显 → 凹陷较浅 → 几乎看不出 的梯度序列。老师逐张让学员判难度。
- **【为什么】** 老师做这个演示的方法论值得学：**建立难度梯度的锚点集**。不是给一个"难"的定义，而是给一串从易到难排好序的真实样本，让你把新任务往这串里插。这是工程判断力的训练方式。
- **【连接】** 你可以对 BEV 建同样的锚点集：晴天近距离大车（简单）→ 夜间中距离行人（中等）→ 雨天远距离被遮挡的自行车（困难）。评审时说"这个 case 相当于我们锚点集里第 3 档"，比说"这个有点难"有效得多。

### 22　当 2D 特征失效时上 3D：点云也有洞（00:36:27–00:37:43）

> **文老师**：「更恐怖的就是一点都看不出来，它凹（陷）（很）平的，但是你用 3D 去测，他（就）把它测出来……那么（他们）打算用 3D 了。但是它 3D 这个其实……你看这里这么多漏洞啊，他点云这里，这些洞就是点云没有重建（出来）的。」

- **【画面】** 一张青绿色伪彩的 3D 点云重建图（#101，00:37:35），轮胎表面明显有大片黑色空洞。
- **【直译】** 当 2D 图像的困难特征已经到人眼极限时，工程上的解法是换传感器——上 3D 结构光/激光测轮廓。但 3D 也不是银弹：点云会有大量未重建的空洞。
- **【为什么】** 这是全课少有的、直接打在你 BEV 老本行上的一段。老师指出的"点云的洞"就是 LiDAR 感知的根本痛点：**稀疏性 + 反射率依赖 + 遮挡**。黑色轮胎橡胶的反射率极低，激光回波弱，直接导致点云缺失。
- **【连接】** 这正是 **BEVFusion 存在的理由**：单 LiDAR 有洞（远处稀疏、低反射率物体丢点），单相机没深度；把相机的语义/纹理和 LiDAR 的几何在 BEV 空间对齐后融合，才能互补。你组里做的 fusion 分支，解决的就是屏幕上那些黑洞。

### 23　为什么这段值得听：分类 vs 检测的任务边界（00:35:37–00:35:49）

> **文老师**：「我们现在，它这个是个检测任务，不是一个分类任务。我只是跟你们说，哪个是困难特征，哪个是简单特征。」

- **【直译】** 老师中途澄清：轮胎凹陷这个案例本身是检测任务（要框出凹陷区域），他借用它只是为了演示特征难度，不要跟当前的分类主线混了。
- **【为什么】** 这个澄清很重要，因为它暗含了一条选型规则：**判别区域占比小 → 用检测；判别区域=整图 → 用分类**。轮胎凹陷占整张图不到 1%，用分类网络做（"这张图有没有缺陷"）会被 99% 的正常区域淹没。
- **【连接】** 这就是老师后面会反复提到的 **ROI 切图二次分类**流程：先用检测网络框出候选区，把 ROI 抠出来，再用一个小分类网络做二次判定。这个两阶段范式在工业质检里是标配，也是 Part 5 全部尺寸讨论的前提场景。

**【小结】**
① 特征复杂度用"人眼判定耗时"标定：< 1 秒简单、< 30 秒中等、> 30 秒困难。
② 困难特征的真正代价是**数据脏**（标注员也会标错），不只是模型难。
③ 2D 到极限就换 3D，但点云会有空洞——这正是多模态融合的动机。

# Part 5　输入尺寸 ↔ 网络深度的匹配律

**【本段在讲什么】**
这是全课含金量最高的 20 分钟，老师自己说"这是五年的实战经验"。核心是一条双向约束：**输入图像尺寸决定你该用几层网络，同时网络的最后一层特征图不能小于某个下限**。他给了一张完整的尺寸→训练尺寸映射表，一条 resize 缩放比的红线（0.5×~2×），和一条硬下限（最后一层 CNN ≥ 49 个特征值）。这一段学完，你就有了"根据业务数据裁剪现成网络"的方法论。

### 24　图越大特征越丰富，但小图放大 = 制造垃圾特征（00:39:37–00:40:57）

> **文老师**：「图越大，特征越丰富，特征清晰就丰富。你们那个图有缺点，因为你们是黑白图。如果小图变大图会怎么样？——模糊啊，会模糊的。模糊对于我们来说是什么特征？过度模糊是什么特征？——**垃圾特征**。」

- **【直译】** 大图特征丰富，但把小图 resize 成大图不会增加信息，只会产生模糊，而过度模糊的像素对网络来说是垃圾特征（噪声）。
- **【推导/代码】** 从信号角度：双线性插值放大是低通滤波，它**不能恢复被采样丢掉的高频**。28×28 放大到 224×224，图像的有效带宽还是 28×28 的那份，但网络的第一层 3×3 卷积核在 224 尺度上看到的是 8×8 像素的插值平滑块——**第一层卷积核感受不到任何边缘**，因为边缘已经被抹成 8 像素宽的渐变了。
- **【为什么】** 老师用"垃圾特征"这个词很准：这不是"没帮助"，而是"有害"。网络会把插值产生的规则伪纹理当成特征去学，在训练集上还能过拟合出效果，一换数据就崩。
- **【连接】** 反过来在 BEV 里同样成立：把 0.075m 体素的点云强行 voxelize 到 0.05m 网格，不会让你的点云变密，只会得到更多空体素 + 更慢的训练。**分辨率要匹配传感器的原生信息密度**，这是同一条定律。

### 25　核心结论：网络输入尺寸应与原图最接近（00:41:05–00:41:45）

> **文老师**：「所以我们其实这种网络训练（时），你的网络输入尺寸应该跟原图最接近，就是图像质量啊。当然你不能也不能太大。」

- **【画面】** 板书标题被写下来了：「**图像尺寸的影响：ROI 切图分类**」（红笔圈起），下面开始列区间表。
- **【直译】** 一条总纲：训练用的输入分辨率应尽量贴近你实际拿到的图的原始分辨率，既不要大幅放大，也不要大幅缩小。
- **【为什么】** 这条为什么大家会忘？因为教程里所有代码都写 `transforms.Resize(224)`——224 是 ImageNet 的历史遗产，不是物理定律。学员照抄就把这个数当常量了。老师这一整段就是在拆掉这个思维定势。
- **【连接】** 你的默写模板里如果有 `transforms.Resize((224,224))` 这一行，从今天起要问自己一句："我的原图是多大？"——这是老师说的"算法工程师最值钱的地方"的最小可执行动作。

### 26　完整映射表：ROI 切图后该用多大训练（00:41:45–00:44:00 + 00:57:25 板书定稿）

> **文老师**：「如果你小于 128 到 64，就是 64 到 128 这个区间……那你可以用 128 来训练。如果你是大于 128 是……416 之间，那你真的可以用 224 来训练。但是如果你真的大于 416 的……那你就要变大，比如 416（甚至 448）来训练。」

- **【画面】**（00:57:25 的板书定稿，这是本课最有价值的一帧）
  ```
  图像尺寸的影响：ROI 切图分类
    64 ~ 128    →  128 来训练
    >128 ~ 416  →  224 来训练
    >416 ~ 640  →  448（极端）
    32 ~ 64     →  用 32 来训练
    < 28        →  直接用全连接
  ────────────────────────────
    ★ 最后一层 > 49 个特征值 / 256 个特征值
    ★ 224 / 2 = 112，224 × 2 = 448
    图大：最后一层 14×14 或 7×7 ⇒ 做对比实验
  ```
- **【推导/代码】** 检查这张表的自洽性——每一档的训练尺寸都落在原图尺寸的 **[0.5×, 2×]** 区间里：
  | 原图区间 | 训练尺寸 | 最坏缩放比 |
  |---|---|---|
  | 64–128 | 128 | 2.0×（放大） |
  | 128–416 | 224 | 1.75× / 0.54× |
  | 416–640 | 448 | 1.08× / 0.70× |
  | 32–64 | 32 | 0.5×（缩小） |
  完全吻合下一张卡的 2 倍红线。这张表不是拍脑袋，是从一条约束推出来的。
- **【连接】** 这条表的适用场景是**ROI 切图分类**（老师反复强调）：检测网络先框出目标，把框抠出来喂给二次分类器。抠出来的 ROI 尺寸五花八门，所以才需要这张表。

### 27　红线：resize 缩放比锁死在 0.5× ~ 2×（00:51:22–00:53:45）

> **文老师**：「因为 resize 最好的情况，就是二分之一左右……比如你是 224，那么最大就是 448，最小就是 112。就是你的范围，就是 112 到 448，这两个范围内的图像你把它 resize 到 224，其实是最好的……你如果真的面试跟我说这种情况（342 resize 到 224 却不改网络），我直接（判你）死。」

- **【画面】** 板书右下角单独列出：「**224 / 2 = 448**」（老师写的是 224 的两个极值 112 和 448）。
- **【直译】** 一条硬红线：resize 的缩放倍数控制在 0.5× 到 2× 之间。目标 224 时，原图应该在 112~448 之间。超出这个范围，要么改训练尺寸，要么改网络层数。
- **【推导/代码】** 为什么是 2 倍？可以从像素信息量估算：缩小 2× 丢掉 75% 的像素，但保留了主要的低频结构；缩小 4× 丢 93.75%，细节结构开始崩。放大同理。**2 倍是"结构还在、细节可容忍"的经验拐点**。
- **【为什么】** 老师用"面试直接判死"来加重语气，因为这个错误极其普遍且极其暴露水平：它说明你没有意识到 224 是可变量。面试官问"你的输入是怎么定的"，答"resize 到 224"就是标准的踩雷答案；正确答案是"我的 ROI 统计分布是 xx~xx，所以我选了 xx，并且相应把网络的下采样次数从 5 改成了 x"。
- **【连接】** ⚠ 转写在 00:51:20 有一句表述混乱："你到了 64，你再跟我搞到 224，你丢了接近四分之一了"——64→224 是放大 3.5 倍，不是"丢四分之一"。老师要表达的是"超出了 2 倍安全区"。以板书为准。

### 28　硬下限：最后一层 CNN 至少 49 个特征值（00:45:28–00:46:20）

> **文老师**：「128（输入），卷一次、池化一次，这里是 64、32、16、（8），这里就是 4，可不可以？——不可以。最低都是 8……四乘四这里转到全连接这边的特征太少了。行业里面就是你会看到他们一般就是 7×7 左右，也就是说至少要 49 个……你四个特征值其实代表不了什么，太少了。」

- **【画面】** 板书用蓝笔在配置表左侧竖着写下降采样链：`128 → 64 → 32 → 16 → 8`，并在右边圈红：「**> 49 个特征值 / 256 个特征值**」。
- **【推导/代码】** 128 输入过 VGG 的 5 个 maxpool：
  ```
  128 →(pool1) 64 →(pool2) 32 →(pool3) 16 →(pool4) 8 →(pool5) 4
  最后一层 = 4×4 = 16 个空间位置  ← 太少，老师判不合格
  改成只用 4 个 pool： 最后一层 = 8×8 = 64 个位置 ← 勉强合格（>49）
  ```
  而 224 输入的原版 VGG16：224 → 112 → 56 → 28 → 14 → **7**，7×7 = **49**。所以"49"这个数字不是拍的，**它就是原版 VGG16 的最后一层空间尺寸**——老师是把 VGG 的设计点直接定为下限。
- **【为什么】** 为什么 4×4=16 不够？因为最后一层特征图的每个位置对应原图的一个感受野区域，16 个位置意味着你只有 16 个"空间投票单元"。目标一旦不居中，或者判别区域偏在一角，16 个格子里可能只有 1~2 个含有信息，全连接层拿到的信号极稀疏。49 个格子（7×7）给了足够的空间冗余。
- **【连接】** BEV 里对应的量是 BEV grid 分辨率。BEVFusion 的 BEV 特征图是 128×128 = 16384 个格子，比 49 大三个数量级——因为 BEV 是密集检测任务，每个格子都要出预测，不像分类只要一个全局判定。

### 29　推论：输入变小 → 必须减层（00:46:24–00:47:05）

> **文老师**：「所以你这时候的一个选择是，把这个咔嚓（砍掉），把这个也可以干掉。我建议直接用 16×16，（下采样）两次就够了……也就是说你要对 VGG 进行改造，你选 A 的同时，其实你只需要几层？一二三层……16×16 是多少？256，256 个特征值。」

- **【直译】** 输入变小时，不仅要选轻量配置（A），还要**砍掉后面的下采样层**，让最后一层特征图停在 16×16（=256 个特征值）而不是 4×4。
- **【推导/代码】** 具体到 128 输入：
  ```python
  # 原版 VGG-A 的 cfg（5 次下采样）
  cfg_A = [64,'M', 128,'M', 256,256,'M', 512,512,'M', 512,512,'M']
  # 128 输入的改造版：只保留 3 次下采样 → 128/8 = 16，16×16 = 256 个特征值
  cfg_A_128 = [64,'M', 128,'M', 256,256,'M', 512,512]   # 后两个 'M' 砍掉
  # 接 nn.Flatten() → nn.Linear(16*16*512, 256) → nn.Linear(256, num_classes)
  ```
  注意 Linear 的输入维度随之变成 16×16×512 = 131072，太大——实战里这里应该先接一个 `nn.AdaptiveAvgPool2d(7)` 或全局平均池化把它压下来。
- **【为什么】** 老师给的两个档位（49 / 256）实际上是一个区间：**下限 49，推荐 256**。49 是能用，256 是好用。多出来的空间信息在小目标场景下尤其值钱。
- **【连接】** 这就是"减层"这个动作的完整定义——不是删卷积层（那会削弱特征提取能力），而是**删下采样点**。你在改 BEV 的 voxel encoder 时同样：要提高小目标召回，是把某个 stride-2 改成 stride-1，而不是删掉整个 block。

### 30　反方向：输入变大 → 加层到 14×14 或 7×7（00:48:19–00:51:10）

> **文老师**：「那另外一个情况，如果你是 448，我们算一下……那你最后一层就是 14×14，这可不可以？这也可以，但是我建议你这种情况加一层，再加一层就是（变成）7（×7）……你大的网络最好是（分辨率）高的，就是你图大最好是 7×7，因为特征丰富一点。」

- **【画面】** 板书顶部写 "448"，配置表右侧圈出 "14×14"，底部写「**图大，最后一层 14×14 / 7×7 ⇒ 对比（实验）**」。
- **【推导/代码】** 448 输入的两个方案：
  ```
  方案甲（不加层，5 次下采样）：448 → 224 → 112 → 56 → 28 → 14   最后 14×14×512 = 100352 个特征值
  方案乙（加一层，6 次下采样）：448 → ... → 14 → 7                 最后  7×7×512  =  25088 个特征值
  ```
  老师建议乙（加一层），理由是 14×14×512 直接接 FC 会让 FC 参数爆炸（100352×256 ≈ 2570 万），而且 14×14 的每个位置感受野还不够大、语义还不够抽象。
- **【为什么】** 注意老师留了尾巴：「也可以不加，你（做）实验吧……你去做对比。」这是这一整段的诚实之处——**经验值给方向，对比实验给结论**。他不假装 14 和 7 有理论最优解。
- **【连接】** ⚠ 转写在 00:49:00 有一处自我修正：老师先按 YOLO 的 416 算"最后一层 14×14"，但 416/32 = 13 不是 14，随即改口用 **448**（448/32 = 14）才对。板书上写的就是 448。

### 31　这条经验的元结论：算法工程师值钱在裁剪（00:51:56–00:53:10）

> **文老师**：「你输入图像的变化，那么你的网络也应该跟着变化。图小你就应该减层，图大你就应该加层。其实这是一个实战经验。要不然我们算法工程师干啥？现成的网络拿来直接用就结束了——这是很多老板的思维……所以你的算法工程师，就是在现有模型的情况下，根据你的业务数据，有选择地进行裁剪。」

- **【直译】** 把这一整段浓缩成一句：**输入变，网络就得跟着变；图小减层，图大加层**。而这个"跟着变"的动作，就是算法工程师区别于"调包侠"的地方。
- **【为什么】** 老师给出的职业定位很值得抄进你的简历语言：「在现有模型的情况下，根据你的业务数据，有选择地进行裁剪」。这句话比"熟练使用 PyTorch"有力一百倍，因为它描述的是判断力而不是操作。
- **【连接】** 你转 BEV 岗时，这条完全可以平移：「根据 nuScenes 的目标尺寸分布和车载算力预算，对 SECOND backbone 的下采样次数与通道宽度做定向裁剪，在 NDS 损失 x% 的前提下把延迟压到 y ms」——这就是 BEV 版的同一句话。

**【小结】**
① 一张表定尺寸：32-64→32 / 64-128→128 / 128-416→224 / 416-640→448 / <28→别用 CNN 用全连接。
② 一条红线：resize 缩放比锁死在 0.5×~2×（224 对应原图 112~448）。
③ 一条下限：最后一层 CNN 至少 49 个特征值（7×7），推荐 256（16×16）；**图小减下采样点，图大加下采样点**。

# Part 6　多尺度特征融合：Inception v1 → v4

**【本段在讲什么】**
这是全课第二块硬骨头，也是最能直接接到你 BEV 工作的一段。老师先用一个"人文理解"（几个人从不同角度看同一个东西）把"多尺度"讲透，再引出融合的两种方式（Add / Concat），然后打开 GoogLeNet 原论文（arXiv 1409.4842）讲 Inception 模块的并行分支结构和伪代码，最后串起 v1→v2→v3→v4 的演化：每一代都只改一件小事，每一代都是一篇顶会。这段结束时他给出了"多尺度结构的三要素"，这是一把可以用来读任何后续网络的钥匙。

### 32　多尺度的人文理解：多个观察角度（01:01:44–01:02:45）

> **文老师**：「人文理解什么叫多尺度？就是比如说我们现在（有）一个美女，我去看这个美女的理解，我张师兄去看这个美女的理解，谢导去看……杨哥去看……单姐去看这个美女的理解。这就叫多尺度，把你们所有的理解放在一起。那么我们看这个美女是不是，你观察的角度就是非常的立体了，立体而且丰富。所以多尺度呢，其实就是**多个观察角度**。」

- **【直译】** 多尺度 = 多个观察角度。一个网络用不同大小的卷积核（不同感受野）去看同一份输入，得到互补的描述，再合起来。
- **【推导/代码】** "角度"在 CNN 里的物理量就是**感受野（receptive field）**。同一层上并行放 1×1 / 3×3 / 5×5 三个核，它们在原图上看到的区域大小不同：小核抓纹理边缘，大核抓形状轮廓。
- **【为什么】** 老师用这个类比不是为了搞笑，是因为**"多尺度"这个词本身极具误导性**——初学者容易理解成"多个图像分辨率"（image pyramid）。老师的类比把它拉回正确的含义：不是把图缩放几次，是**在同一份特征图上用不同感受野并行观察**。
- **【连接】** 你已经知道的 **CA 注意力**是另一种"多角度"：它在 H 和 W 两个方向分别做池化再组合，等于从"横看"和"竖看"两个角度看同一张特征图。而 **BiFPN** 是跨层级的多尺度——把 P3/P4/P5/P6/P7 五个分辨率层级双向融合。三者是同一思想的三个尺度。

### 33　融合只有两种方式：Add 和 Concat（01:02:45–01:04:05）

> **文老师**：「那我们既然有融合，也很简单，怎么融合？加起来对不对？所以融合有两种方式，一个是 Add，就是……对这个美女的评价值，加上（另外）三个（人）的评价值，加起来除一个平均，就叫 Add……那另外一个操作是 Concat，就是把我们两个的评价堆在这里……写了十页，比如说有十页意见，叫 Concat。」
[[
]]- **【直译】** 特征融合就两种：**Add**（对应位置逐元素相加，像求平均意见）和 **Concat**（沿通道维拼接，像把十页意见叠在一起）。
- **【推导/代码】** 两者的张量层面差异：
  ```python
  # Add：要求 shape 完全一致 (B,C,H,W) + (B,C,H,W) → (B,C,H,W)
  y = x1 + x2                     # 通道数不变，信息被"压缩混合"，参数量不增
  # Concat：只要求 B,H,W 一致，C 可以不同
  y = torch.cat([x1, x2], dim=1)  # (B,C1+C2,H,W)，信息全保留，但后续卷积参数量×
  ```
  ⚠ 转写把 Add 听成了"I的"，把 Concat 写成"Concate"，见纠错表。
- **【为什么】** 选择标准（老师这里没说，但从他的类比能推出来）：**语义等价的东西用 Add**（两个人对同一件事的评分，可以平均），**语义互补的东西用 Concat**（不同模态、不同感受野的信息，不该被平均掉）。Add 更省，Concat 更全但更贵。
- **【连接】** 这条在 BEVFusion 里就是核心设计决策：相机 BEV 特征和 LiDAR BEV 特征是**异质**的（一个是语义、一个是几何），所以 BEVFusion 的 ConvFuser 用的是 **concat 后再卷积**而不是直接相加。而 ResNet 的残差连接是 Add，因为主路和 shortcut 是同质的。这两个选择你现在能解释清楚了。

### 34　多尺度是所有模型的共同追求（01:04:00–01:05:07）

> **文老师**：「这个东西其实是现在 CNN……也不是 CNN 啊，其实是所有模型都在做这个事情，我们一定要做多尺度，就多角度。说白了，你的网络好不好，除了你的输入数据（质量），另外一个影响因素就出来了，叫多尺度特征的提取……这个多尺度我们后面可以有两种尺度，一种是我们 CNN 的尺度，一种是 Transformer 里面的特征尺度，我们可以把两个尺度进行融合。」

- **【直译】** 多尺度不是 CNN 专属，是所有模型的通用手段。老师还预告了一种进阶玩法：把 CNN 的尺度和 Transformer 的尺度融合起来。
- **【为什么】** 老师把"多尺度特征提取能力"列为决定网络好坏的第二大因素（第一是输入数据质量）。这个排序值得记：**数据 > 多尺度设计 > 具体算子选择**。很多人把顺序搞反了，在算子上死磕。
- **【连接】** "CNN 尺度 + Transformer 尺度融合"正是当前 BEV 的主流形态：BEVFormer 用 Transformer 的 spatial cross-attention 从多视角图像采样，同时保留 CNN backbone 提取的多尺度特征图；BEVFusion 的 camera 分支也是 CNN backbone + FPN 多尺度 + LSS 投影。你的目标岗位天天在做这件事。

### 36　Inception naive 版：三种核 + 一个池化并行（01:09:20–01:11:10）

> **文老师**：「你看这里是我们输入的这个 X，他用一个 1×1，这是并行的……1×1 意味着什么？如果在这里的话，HW 不变，那意味着 C 变多还是变少？肯定是变少嘛。然后这是第一个分支……这里用了什么？3×3……然后这个分支就是用一个 5×5，那你卷的区域是不是要大一点？感受野是不同的。」

- **【画面】** arXiv 论文 Figure 2(a) "Inception module, naïve version"：Previous layer 同时接出四条并行分支——1×1 convolutions / 3×3 convolutions / 5×5 convolutions / 3×3 max pooling，四条分支的输出汇到顶部的 **Filter concatenation**。老师在旁边写了"并行"两个大字。
- **【推导/代码】** 老师现场写的伪代码（画面上是红字）：
  ```python
  x1 = conv1(x)                    # 1×1 分支
  x2 = conv1(conv3(x))             # 3×3 分支（naive 版里没有 conv1）
  x3 = conv1(conv5(x))             # 5×5 分支
  x4 = conv1(maxpool(x))           # 池化分支
  X  = torch.cat([x1,x2,x3,x4], dim=1)   # dim=1 因为张量是 B,C,H,W
  ```
  老师特别停下来确认 concat 的轴：「到你要在哪个（轴）走？等于几？——1，B C H W，所以要在 1。」
- **【为什么】** 为什么四个分支都能 concat？因为**所有分支都保持 H、W 不变**（3×3 用 p=1，5×5 用 p=2，maxpool 用 s=1）。这是 Inception 能成立的前提条件，也是你自己写多分支模块时最容易翻车的地方。
- **【连接】** 你的 MNIST 模板要升级成多分支，改动就是这几行。而 YOLO 的 **SPPF 模块**（Spatial Pyramid Pooling - Fast）本质就是 Inception 的池化版：用 3 个串联的 5×5 maxpool 造出等效 5/9/13 三种感受野，再 concat。

### 37　多尺度的两个来源：两种方法 + 两种感受野（01:11:00–01:12:38）

> **文老师**：「它这样就实现了多尺度。所谓多尺度，它有两种方法：第一个是两种方法来提取特征——一个是卷积，一个是池化；第二个就是感受野都不同……你一个单独的 3×3，你就只有一个感受野，然后你现在有两（三）个感受野，肯定比一个感受野相对来说要丰富一点。」

- **【直译】** Inception 的"多尺度"有两个正交来源：① **提特征的手段不同**（卷积 vs 池化）；② **感受野不同**（1×1 / 3×3 / 5×5）。
- **【推导/代码】** 感受野盘点（老师后面 01:14:50 补的）：1×1 感受野不变（=1），3×3 是 3，5×5 是 5，3×3 maxpool 也有感受野 3。所以严格说是 **3 种感受野尺度（1/3/5）× 2 种提取方式（conv/pool）**。
- **【为什么】** 为什么卷积和池化算"两种方法"？因为它们的统计性质不同：卷积是**加权求和**（线性、可学习、保留强度信息），最大池化是**取极值**（非线性、无参数、保留最显著响应、对小位移不敏感）。两者提取的是互补的统计量。
- **【连接】** 这个"两种统计量"的思路你在注意力机制里也见过：**CBAM 的通道注意力同时用 AvgPool 和 MaxPool**，然后把两条结果相加——完全是同一个设计哲学，只不过换了个场景。

### 38　Inception with dimension reduction：1×1 先压再卷（01:12:45–01:14:16）

> **文老师**：「它基于这个思想呢，就设计了这个模块，这个模块其实是稍微要记一下的，叫 Inception……你看它先用了一个 1×1 来降，这就是降（通道）……然后在这个地方来进行一个 concat。其实它的核心思想其实就（很）简单：**多尺度融合的同时，要减少参数量**。」

- **【画面】** Figure 2(b) "Inception module with dimension reductions"：相比 naive 版，3×3 和 5×5 分支前面各插了一个 1×1 卷积（降通道），池化分支后面插了一个 1×1。老师在旁边写：「**多尺度融合的同时，减少参数量（W）**」。
- **【推导/代码】** 修正后的伪代码就是老师写的那版（每条分支都套了 conv1）：
  ```python
  x1 = conv1x1_a(x)                       # 直接 1×1
  x2 = conv3x3(conv1x1_b(x))              # 先压通道再 3×3
  x3 = conv5x5(conv1x1_c(x))              # 先压通道再 5×5
  x4 = conv1x1_d(maxpool3x3_s1(x))        # 先池化再压通道
  out = torch.cat([x1,x2,x3,x4], dim=1)
  ```
- **【为什么】** 注意 1×1 在池化分支的位置是**在后面**，其他分支是**在前面**。原因：池化不改变通道数也不消耗参数，没必要先压；但池化输出的通道数会让最终 concat 结果太宽，所以在后面压。这个不对称细节体现了作者是按"参数量最小化"逐分支设计的。
- **【连接】** 这就是上节课学的 1×1 的实战落地。BEVFusion 的 fuser、CenterPoint 的 shared conv 前面，都有这种"1×1 压通道"的操作，目的一模一样。

### 39　【画面】面试高频题：1×1 卷积的六个作用（01:27:59）

> **【画面】**（PPT 标题：**面试基础题目（高频）：1x1 卷积的作用？**，老师这一页几乎没有口播，全靠画面）
> 1。1x1 卷积，**不会改变特征图的 h, w**
> 2。1x1 卷积**可以改变特征图的数量**。大家都叫升维或者降维，但实际上不改变 h、w，dim 也不改变，只是改变了输出的 channel，改变的是 shape
> 3。如果 1x1 输出的 **channel 变少**时，参数量和计算量也在下降
> 4。**增加了非线性**，增加了网络的表达能力
> 5。**空间信息的沟通和融合**（+）
> 6。**能够起到全连接的作用**

- **【推导/代码】** 同一页 PPT 右下角给了完整的量化对比（图 4-31 逐点卷积计算量），这是转写完全没有的核心数据：
  ```
  A 方案（直接 3×3）：3*3*64 → 3*3*128
     A 计算量 = 3*3*64*(3*3*128) = 663,552
     A 参数量 = 3*3*128*64       =  73,728
  B 方案（1×1 压到 16 再 3×3）：3*3*64 → 1*1*16 → 3*3*16 → 3*3*128
     B 计算量 = 3*3*64*(1*1*16) + 3*3*16*3*3*128 = 175,104
     B 参数量 = 1*1*16*64 + 3*3*128*16           =  19,456
  ```
  **参数量 73728 → 19456，降到 26%；计算量 663552 → 175104，降到 26%。**
- **【为什么】** ⚠ 老师口播说"少了近三分之一"（01:27:54），但按 PPT 数据是**只剩不到三分之一**（少了 74%）。面试报数请以 PPT 为准。
- **【连接】** 第 6 条"能够起到全连接的作用"是理解 GAP + 1×1 分类头的钥匙：当特征图是 1×1×C 时，一个 1×1 卷积在数学上就等价于一个 Linear(C, C')。Part 7 最后那个多网络集成方案就是这么用的。

### 40　Inception v2：5×5 换成两个 3×3（01:18:15–01:19:05）

> **文老师**：「根据我们昨天的知识，我现在要你们去改它，你们看到哪个模块可以修改了？——5×5。5×5 可以改成什么？对，改成两个 3×3。这个恭喜你一篇顶会就出来了。真的啊……这就是 V2。V2 就只做了一个事情，把 5×5 改成两个 3×3，它一下就上去了，又涨点了。」

- **【画面】** 老师在论文图上写「**Inception v2 · 5×5 → 2 个 3×3**」，并在旁边标了"有效↗"。
- **【推导/代码】** 为什么等价：两个串联的 3×3 卷积的感受野 = 3 + (3−1) = **5**，与一个 5×5 相同。参数对比（单通道）：
  ```
  1 个 5×5：25 个参数
  2 个 3×3：9 + 9 = 18 个参数   → 省 28%
  ```
  且多了一层非线性（中间插了一个 ReLU），表达能力反而更强。这就是"参数更少、效果更好"的双赢。
- **【为什么】** 老师说"一篇顶会就出来了"半是玩笑半是真：Inception v2/v3 的论文（Rethinking the Inception Architecture，CVPR 2016）核心贡献就是这一类分解技巧。这传递了一个重要认知：**顶会创新常常是一个非常小的、可解释的替换 + 扎实的实验**，不需要惊天动地的新概念。
- **【连接】** 这条也是 VGG 的核心论证（用 3 个 3×3 代替 7×7），Part 1 老师批注在 AlexNet 页上的那句"用 3 个 3×3 = 7×7 → 做得更深、参数更少"就是它。同一个技巧被 VGG 和 Inception v2 分别用了一次。

### 41　Inception v3：空间可分离卷积 3×3 → 3×1 + 1×3（01:19:44–01:23:00）

> **文老师**：「V3 这里，这个叫空间可分离卷积……你不是 3×3 卷积（吗），我现在改成（3×1 加 1×3）……你看原来的参数量……有 9 个参数量，现在变成多少了？——6 个。参数量是不是进一步的减少？……所以 V3 的事情，就是把这个 3×3 全部跟我换成这个叫空间可分离。」

- **【画面】** PPT 图 4-34「空间可分离卷积」的完整数据（转写没有的核心增量）：
  ```
  标准卷积  3×3 核，s=1   参数量 = 9    计算量 = 3*3*3*3 = 81
  空间可分离 3×1 + 1×3    参数量 = 6    计算量 = 3*3*3+3*3*3 = 36
  两条路径对同一个 3×3 输入（1..9）得到的结果都是 30 —— 数值等价
  ```
  老师在旁边写：「**3×3 → 1×3 + 3×1**」「W 更少，少了 3 个，30%」。
- **【推导/代码】** 推广到 k×k：参数从 k² 降到 2k。k=3 时 9→6（省 33%），k=5 时 25→10（省 60%），k 越大越划算。
- **【为什么】** ⚠ 要区分清楚两个"可分离"，这是面试高频混淆点（转写里学员也问了）：
  | 名称 | 拆在哪个维度 | 拆法 | 出处 |
  |---|---|---|---|
  | **空间可分离** | H、W（卷积核内部） | 3×3 → 3×1 + 1×3 | Inception v3 |
  | **深度可分离** | C（通道） | 3×3×C → DW(3×3, groups=C) + PW(1×1) | MobileNet |
  老师原话确认：「深度是在 C，这个（空间可分离）是在卷积核，HW，它就叫空间可分离。」
- **【连接】** 上节课你学的 **DW/PW 是深度可分离**；这节课的 3×1+1×3 是空间可分离。两者可以叠加使用——这就是老师后面说的"花样多"。

### 42　Inception v4：加残差，以及这个系列的终章（01:30:48–01:31:25）

> **文老师**：「它绝唱是 GoogLeNet 的 V4，它这个系列就再也没更新了。V4 在 V3 的技术上，技术上是什么？——加了残差。所以残差是很重要的……当然残差还没讲，你也看不懂。」

- **【画面】** PPT 上有一份完整的四代摘要（这一整块是本课最值钱的一张 slide）：
  ```
  Inception v1，引入多尺度
  V2，5x5 变 2 个 3x3
  V3，引入空间可分离卷积
  V4，引入残差
  ```
  老师在旁边写：「**CNN 想办法让 W 变小**」「精度还要保持」。
- **【直译】** Inception 四代的演化每一代只做一件事：v1 多尺度 → v2 大核分解 → v3 空间可分离 → v4 加残差。加了残差之后这个系列就停更了。
- **【为什么】** 为什么加残差之后就停了？因为残差（ResNet, 2015）解决的是"深度的可训练性"这个更根本的问题，之后网络设计的主战场转移了：从"怎么在固定深度下提效"变成"怎么把深度推到 100+ 层"。Inception 的分解技巧变成了配菜。
- **【连接】** 老师明确预告下次课（星期四）手撸 ResNet 残差块。你的 BEVFusion 里 SECOND backbone 的每个 block 就是残差结构，CenterPoint 的 shared head 前面也有残差。这是下一讲的入场券。

> 🗀 折叠【01:24:15–01:29:00】荣耀指纹项目复盘：GoogLeNet v2 量化后约 5.6MB 能跑进手机（FP16 模型 20MB）；VGG16 保存约 500MB 跑不进手机，这是 GoogLeNet 存在的意义。指纹原图 64×64 却被 resize 到 224 训练——"过拟合版本"。附带的行业吐槽略。⚠ 这段有两处数字问题见纠错表。

### 43　多尺度结构的三要素（读任何后续网络的钥匙）（01:31:41–01:33:40）

> **文老师**：「这里其实就是跟你们演示了一下特征融合的方式。特征融合一定就有一个叫**多分支结构**，它一定是多分支，这是你可以确定的。第二个一定会有**多个感受野**。那第三呢，其实你就知道，一定是 3×3、1×1……但是**花样一定非常多**。」

- **【直译】** 老师给了一把万能钥匙：任何一个"多尺度融合模块"，无论画得多复杂，都必然具备三个特征——① 多分支结构；② 多个感受野；③ 基础算子无非 3×3 / 1×1，但组合花样极多。
- **【推导/代码】** 老师现场演示"花样"怎么加：「像我们昨天（学的）分组卷积、深度分离卷积，把它跟我换成 DW，对不对？……你的参数量是不是会更小？后面再跟一个 1×1 嘛，因为 DW 后面一定会有 PW。」——即把 Inception 的 3×3 分支换成 DW+PW，就得到了一个新模块。
- **【为什么】** 这三要素的价值在于**降低阅读新论文的成本**。老师说：「你不管他画的这个结构多么奇怪……以后的（多）尺度，那个模块会非常复杂，但是他就只做了一个事情，叫多尺度。」有了这把钥匙，你看新 backbone 时先问三句：几条分支？各是什么感受野？用了哪些花样算子？三句答完，模块就读懂了。
- **【连接】** 拿它去读你熟悉的东西：**BiFPN** = 跨层级多分支 + 每条分支不同 stride 的感受野 + 加权融合的花样（learnable weights）。**CSP 结构** = 两条分支（一条过 block、一条直连）+ concat。三要素一套就通。

**【小结】**
① 多尺度 = 多个观察角度；融合只有 Add（同质、省）和 Concat（异质、全）两种。
② Inception 四代：v1 多尺度并行 → v2 5×5 拆两个 3×3 → v3 3×3 拆 3×1+1×3（空间可分离）→ v4 加残差。主线永远是"参数变小、精度保持"。
③ 三要素钥匙：多分支 + 多感受野 + 花样（DW/PW/分组/可分离），拿它可以拆解任何后续网络。

# Part 7　辅助头损失与多网络集成学习

**【本段在讲什么】**
GoogLeNet 的第二个遗产：它有三个输出头。老师从这个设计推出了两条极其实用的经验——**中间层是有意义的、可以拿来做损失**，以及**多个损失怎么配系数**（想让哪里多学，系数就调大）。这两条会一路用到目标检测的多任务损失。最后他讲了一个学员的真实创新案例：把三个 backbone（VGG/ResNet/GoogLeNet）并起来做特征融合，并给出了完整的张量流。这一段是全课离你的 BEV 工作最近的部分。

### 44　GoogLeNet 有三个输出：中间层输出（01:35:31–01:36:50）

> **文老师**：「我现在给你们画一个简单的示意图：x 图输进去，假设这是第一层，然后这是第十层，这是第二十层，然后这个就是最后的一层、输出层……他这里会有三个 Y，这是 Y1，预测 Y1；这个是预测 Y2；那么这里就是我们（最终的）Y，我们可以把它称之为 Y0……他这个模型其实有三个输出。」

- **【画面】** PowerPoint 白板上的红笔示意图：`X → [①层] → [10层] → [20层] → [输出层]`，其中 10 层和 20 层各往下引出一个箭头，标注 y₁、y₂，最后一层标 y₀。上面写「**中间层输出**」。
- **【直译】** GoogLeNet 在网络的中间位置（约第 10、第 20 层）额外接了两个分类输出头，加上最终输出一共三个头。
- **【为什么】** GoogLeNet 是 22 层，在 2014 年算极深。当时还没有 ResNet，深层网络的梯度传到浅层已经很微弱（梯度消失）。中间接头的作用是**给浅层一条直达的梯度通路**——浅层不用等梯度从 22 层传回来，中间头直接给它一份监督信号。
- **【连接】** 这就是 **YOLOv7 的 auxiliary head（辅助头）**的直系祖先，PPT 上老师也明确写了「辅助头损失（yolov7 用了，transformer 的视觉中喜欢用）」。深度监督（Deep Supervision）这个词你可以直接用在面试里。

### 45　多损失的写法：交叉熵求和（01:36:52–01:37:52）

> **文老师**：「那么他这个损失怎么算呢？那就是 Y1'（与）交叉熵……负的 Y1' log YT，这是第一个损失，加上负的 Y2' log YT，再加上负的 Y0' log YT，真实值，YT 就是真实值、GT……然后他的反向传播呢，就是三个（损失）加起来，就是 Total 损失。」

- **【画面】** 白板红笔公式（配合老师的手写）：
  ```
  total = 0.3·(−y₁' log y_t) + 0.3·(−y₂' log y_t) + 1·(−y₀' log y_t)
  ```
- **【推导/代码】** PyTorch 写法：
  ```python
  y1, y2, y0 = model(x)                      # 三个头的 logits
  ce = nn.CrossEntropyLoss()
  loss = 0.3*ce(y1, target) + 0.3*ce(y2, target) + 1.0*ce(y0, target)
  loss.backward()                            # 一次 backward，梯度自动分配到三条路径
  ```
  注意**只调一次 backward**：三项加成一个标量后，autograd 会沿计算图把梯度分别送回三条路径，中间层会同时收到"来自自己的头"和"来自后续层"两股梯度。
- **【为什么】** 三个头共享同一个 target（GT 是同一个类别标签），所以这不是多任务学习，是**同一任务的多深度监督**。
- **【连接】** CenterPoint 的多任务损失结构完全同构：`loss = λ_hm·L_heatmap + λ_reg·L_offset + λ_h·L_height + λ_dim·L_dim + λ_rot·L_rot`，只是各项是不同的任务而非不同的深度。系数怎么配是同一个问题。

### 46　系数 0.3 / 0.3 / 1 的道理：想哪里多学，系数就大（01:37:56–01:40:12）

> **文老师**：「这里有个系数，他给的系数是 0.3，论文里面给的是 0.3，这边给的是 1。可能你的第一反应，为什么加起来不得 1？……三个损失相加要比一个损失要大，对不对？然后我们以前讲正则化的时候说了一句话：**哪里大就学哪里**……1 是不是比 0.3 和 0.3 要大？那是不是我们要更关注最深层的输出呢？」

- **【画面】** 老师在旁边写了类比公式：`Loss = Loss + λ‖W‖²`，并在下面写「**哪里大 → 学哪里**」。这是把正则化的直觉迁移过来。
- **【推导/代码】** 这个直觉的数学依据：对参数 θ 的梯度 `∂total/∂θ = 0.3·∂L₁/∂θ + 0.3·∂L₂/∂θ + 1·∂L₀/∂θ`。系数直接线性缩放该项的梯度贡献。系数大 = 这一项的梯度在合力里占主导 = 优化器优先降低这一项。
- **【为什么】** 为什么最深层给 1 而不是浅层？老师说：「最深的这一层，我的**语义特征是最丰富的**，拿来做分类是最好的，所以我们要多学习一下这个地方。」PPT 上写得更清楚：「**Head3 是语义特征，CNN 分类靠语义特征。Head1 是浅层，几何信息和噪声多，所以少学一点。**」
- **【连接】** 这条经验直接可用：你调 CenterPoint 时如果发现朝向角（rot）误差大，就把 λ_rot 调大；发现小目标漏检，就调大 heatmap 项。老师给的调节幅度是"**1.5 倍左右，2 就有点夸张了**"（口播），而 PPT 上写的是"**调大（2 倍的比例去增…）**"——两处不一致，实操建议按 **1.5×→2× 逐步试**。

### 47　【画面】PPT 上的官方版损失系数指南（01:21:11）

> **【画面】**（PPT 右栏原文，转写里只讲了其中一半）
> 「辅助头损失（yolov7 用了，transfomer 的视觉中喜欢用）
> Total_loss = 0.3 * head1_loss + 0.3 * head2_loss + 1 * head3_loss
> 0.3 是论文给出的。
> 损失的任务是要尽量的小，所以那里权重大，神经网络就在那里（多学）一些（跟正则化思想是一样的）
> Head3 是语义特征。CNN 分类靠语义特征。
> Head1 是浅层，几何信息和噪声多，所以少学一点。
> **如果损失有多项的时候，可以将系数调成 0，不使用。**
> 损失系数调多大，感觉那里有问题，那里就**调大（2 倍的比例去增…）**」

- **【推导/代码】** 注意倒数第二条是转写里完全没有的：**系数可以调成 0 来关掉某一项**。这在实战里非常有用：
  ```python
  # 消融实验的标准做法：把某项系数置 0，观察指标变化
  loss = 0.0*ce(y1,t) + 0.3*ce(y2,t) + 1.0*ce(y0,t)   # 关掉 head1，验证它有没有用
  ```
  比删代码干净，比注释掉安全（网络结构不变，可以直接对比参数量一致的两次训练）。
- **【为什么】** 这条给了你一个**损失系数的调参协议**：先全开跑 baseline → 逐项置 0 做消融 → 找出真正有贡献的项 → 对指标最差的那一项按 1.5~2 倍加权。这是一个可以在周报里写出来的流程。
- **【连接】** 你在 BEVFusion 里可以完全照搬：把 camera 分支的辅助损失系数置 0，就能量化出相机分支到底贡献了多少 NDS。

### 48　辅助头只在训练用，推理丢掉（01:42:45–01:43:23）

> **文老师**：「他原来的名字叫**辅助头损失**。为什么辅助头呢？这两个头只在训练的时候用，推理的时候不要。所以他叫辅助头，辅助头损失。」

- **【直译】** 两个中间头是训练期脚手架，推理时直接丢弃，不增加任何推理开销。
- **【推导/代码】** 实现上通常这么写：
  ```python
  def forward(self, x):
      f1 = self.stage1(x); f2 = self.stage2(f1); f3 = self.stage3(f2)
      out = self.head_main(f3)
      if self.training:                      # 只有训练模式才算辅助头
          return out, self.aux1(f1), self.aux2(f2)
      return out
  ```
  用 `self.training` 开关，配合 `model.eval()` 自动切换。
- **【为什么】** 这是"**训练时复杂、推理时简单**"这一大类技巧的代表，同族的还有：RepVGG 的结构重参数化、知识蒸馏的 teacher、BN 的训练/推理双模式。**共同点是：用训练期的额外代价换推理期的零代价收益。** 这个模式在车载部署里价值极高，因为你的约束全在推理侧。
- **【连接】** YOLOv7 的 aux head 就是这么做的（lead head + aux head，推理只留 lead head）；BEVFusion 训练时的深度监督（depth supervision）分支也是训练期专用。

### 49　另一条路：三个头都保留，推理时投票（01:48:56–01:51:00）

> **文老师**：「推理的时候，那你肯定只要一个 Y……这是一种方法。然后呢，另外一个，我可不可以要三个 Y？这个如果你是三个 Y，你就要做一个投票（机制）……比如说这一层，他认为是猫，概率 60%；然后这一层他认为也是猫，50%；然后这一层有可能也认为是猫，70%，那你的结（论）肯定就是猫，加起来嘛。」

- **【直译】** 第二种用法：推理时三个头都保留，用投票或加权平均得到最终结果。
- **【推导/代码】** 老师给了两种投票方案：
  ```python
  # 方案一：概率相加（等权）
  prob = softmax(y0) + softmax(y1) + softmax(y2)
  # 方案二：按深度加权（老师给的经验值）
  prob = 0.6*softmax(y0) + 0.2*softmax(y1) + 0.2*softmax(y2)
  pred = prob.argmax(dim=1)
  ```
  老师原话：「最深的这一层，你占比多少？0.6，前面的一层分别占 0.2。就是你要设计一个投票机制。」
- **【为什么】** 老师同时给了这条路的代价：「你的检出应该会提高，但是你的误检……又在增加。」多头投票会提高召回（三个头有一个抓到就可能过阈值），但降低精确率（浅层头噪声大，会带来误报）。这是一个明确的 trade-off，不是免费午餐。
- **【连接】** 这跟 YOLO 的 TTA（Test-Time Augmentation）和 WBF（Weighted Box Fusion）是同一类操作：牺牲推理速度和精确率换召回率。产线质检里"宁可误报不可漏报"的场景才用。

### 50　三个头意见不一致 = 输出"不确定"（01:51:20–01:53:57）

> **文老师**：「当然最可怕的就是这里他认为他是狗，这层他又认为是（别的），这一票他又认为是猫，那你信哪（个）？这不能用了……三个意见不一致，我就设定为一个**疑似缺陷**，但是我不确定他。这也是方法。」

- **【直译】** 当三个头给出三个不同类别时，与其强行投票，不如输出第四种状态："不确定 / 疑似缺陷"，转人工复检。
- **【为什么】** 这是这一整段最有工程价值的一句。它把**模型不确定性**变成了一个可用的产品特性：多头的分歧程度本身就是一个免费的置信度估计（类似 Deep Ensemble 的方差）。老师说「工作当中真的有些东西是不确定的……标类别时会标一个不确定，就是大家都不知道」——GT 里本来就有不确定类，模型输出不确定完全合理。
- **【推导/代码】** 落地写法：
  ```python
  preds = [y0.argmax(1), y1.argmax(1), y2.argmax(1)]
  agree = (preds[0]==preds[1]) & (preds[1]==preds[2])
  final = torch.where(agree, preds[0], torch.full_like(preds[0], UNCERTAIN_ID))
  ```
- **【连接】** 自动驾驶里这就是**降级策略**的触发条件：多个感知源（相机/LiDAR/雷达）判断不一致时，系统不该硬选一个，而应该降低置信度、触发接管或保守减速。你在 BEV 组见过的"融合置信度"就是这个东西的工程版。

### 51　老师的读论文方法论：抽核心思想，不抄模型（01:53:00–01:53:20）

> **文老师**：「就是你看论文，并不是说你一定要用这个模型……你看一个论文，你要把他的核心思想抽出来，抽出来去用于指导你其他的任务。反正我现在是这样：我看一篇论文，我就只（记）它最核心的东西，然后把最核心的东西指导（我）在其他工作当中。」

- **【直译】** 读论文的目的不是复现模型，是提取可迁移的核心思想。
- **【为什么】** 这一段是老师讲 GoogLeNet 的元说明：GoogLeNet 这个网络你今天几乎不会用（"你现在用它也大概不会用的"），但它给的三个思想至今有效——多尺度、中间层损失、多输出投票。**思想的半衰期远长于架构的半衰期。**
- **【连接】** 这正是你转 BEV 岗要用的学习姿势：BEVFormer / BEVFusion / BEVDet 这些具体网络两年就迭代一轮，但"把多视角图像投影到统一 BEV 空间再做检测"这个思想是稳定的。面试时讲思想的迁移，比背某个网络的结构参数更有说服力。

### 52　GoogLeNet 的三条遗产总结（01:53:57–01:54:25）

> **文老师**：「这篇文章总结起来，其实它还是很有参考意义的。第一个就是**多尺度**；第二个就是我们刚才说的叫**中间层损失**，还有就是**多损失系数调节**，这是第二个意义；第三个就是**多输出的时候要自己去设计投票（机制）**，然后我们刚才说的，你的分类有可能出现一个叫'不确定'。」

- **【直译】** GoogLeNet 的三条可迁移遗产：① 多尺度特征融合；② 中间层损失 + 多损失系数调节；③ 多输出投票机制与"不确定"类。
- **【为什么】** 老师随后加了一句判断：「有没有效呢？绝对有效。就是这三个套路是有效的。基本上你在后面的网络（都能）看到这个模式。其实 YOLOv7 有，YOLOv8、YOLO11 就没有这个分支了。」——注意最后半句很重要：**YOLOv7 用了辅助头，YOLOv8/v11 又去掉了**。老师说"那其实就是某（个）地方有点不对"。
- **【连接补充】** 为什么 v8 之后去掉了？因为 v8 换成了 anchor-free + TAL（Task Aligned Assigner）标签分配，正样本质量提升后，深度监督带来的边际收益不足以抵消训练复杂度。这也印证了 Part 6 的规律：**辅助手段会随着主干问题被更好地解决而退场**（就像残差解决梯度问题后 Inception 停更）。

### 53　多网络集成：三个 backbone 并起来（01:57:03–02:00:10）

> **文老师**：「先用 A 网络，比如 VGG……反正这些网络最后一层都是 7×7 嘛，这里是 7×7×512，是吗？这个（ResNet）也是不是 7×7×512？都是的，不用想了。然后现在我们还学了一个 GoogLeNet……这里也是 7×7×512。然后这个图是 x，输进来，把这个图**同时输入三个网络**，然后把这里我把它合并（concat），就变成了 7×7×512×3 = 2048（应为 1536）。」

- **【画面】** PowerPoint 白板（02:04:33 定稿）：
  ```
                        [1张图 X]
                    ↙       ↓       ↘
                 [VGG]   [ResNet]  [GoogLeNet]
                7×7×512  7×7×512    7×7×512
                    ↘       ↓       ↙
                    concat: 7×7×(512×3)
                            ↓
                    全局平均池化 → 1×1×(512×3)
                            ↓
                 1×1 → 512  →  1×1 → 128  →  1×1 → 10 个类
  ```
- **【推导/代码】** ⚠ 老师口算"512×3 = 2048"是口误，应为 **1536**（他自己在白板上写的是 512×3，没写错）。完整代码骨架：
  ```python
  f1 = vgg_backbone(x)        # (B,512,7,7)
  f2 = resnet_backbone(x)     # (B,512,7,7)
  f3 = googlenet_backbone(x)  # (B,512,7,7)
  f  = torch.cat([f1,f2,f3], dim=1)          # (B,1536,7,7)
  f  = F.adaptive_avg_pool2d(f, 1)           # (B,1536,1,1)  ← 全局平均池化
  f  = self.conv1(f)   # 1×1: 1536 → 512
  f  = self.conv2(f)   # 1×1: 512  → 128
  out= self.conv3(f)   # 1×1: 128  → num_classes
  ```
  这里的三个 1×1 卷积就是 Part 6 第 39 张卡说的"**1×1 能起到全连接的作用**"——因为特征图已经是 1×1，1×1 卷积等价于 Linear。
- **【为什么】** 为什么先 GAP 再 1×1 而不是直接 Flatten 接 FC？因为 Flatten 后是 7×7×1536 = 75264 维，接 FC 参数量会爆炸。GAP 把空间维压掉后只剩 1536 维，参数量降三个数量级。老师原话：「长（flatten）平不用全连接，再用 global 平均池化。」
- **【连接】** 这个"多 backbone concat + GAP + 1×1 头"的结构，和 **BEVFusion 的融合模块几乎完全同构**：camera BEV 特征 + LiDAR BEV 特征 → concat → ConvFuser（几层卷积压通道）→ BEV encoder → 检测头。你现在能一眼看出 BEVFusion 的 fuser 是这个方案的 BEV 版本。

### 54　方案二：保留各自 FC，损失相加、推理投票（02:01:44–02:04:20）

> **文老师**：「另外一种就是全连接保留，然后这里得到 Y1，这里也全连接保留，这里是 Y2，这里全连接也保留，Y3。那不是把这个损失加起来，Total 对 Y1 加 Y2 加 Y3 的损失嘛……同时反向传播去更新三（个网络），因为这边都是可学习参数嘛……推理的时候现在这种情况就是要投票了。」

- **【画面】** 白板右侧红笔：`total = λ₁·y₁ + λ₂·y₂ + λ₃·y₃`，下面写「**同时 back total**」，再下面框起来写「**投票推理**」。
- **【推导/代码】** 两个方案的对比表（这是老师这一整段的产出）：
  | | 方案甲：特征级融合 | 方案乙：决策级融合 |
  |---|---|---|
  | 结构 | 砍掉三个 FC，backbone 输出 concat | 保留各自 FC，各出一个 y |
  | 损失 | 一个损失（融合后的头） | Total = λ₁L₁+λ₂L₂+λ₃L₃ |
  | 推理 | 单一输出 | 需要投票机制 |
  | 参数 | 少（只有一个头） | 多（三个头） |
  | 类比 | Early fusion | Late fusion |
- **【为什么】** 老师强调「你肯定要加系数嘛……肯定不是平衡的，要看你到时候（各网络在各）类别（上的表现）」——回到第 46 张卡的那条经验：哪个网络在你关心的类别上表现好，就给它更大的 λ。
- **【连接】** 这个"特征级 vs 决策级"的二分正是多传感器融合的经典分类法：BEVFusion 是**特征级融合**（BEV 空间对齐后 concat），而传统的后融合（每个传感器各自出检测框再做关联）是**决策级融合**。你组里的技术路线选择，本质上就是老师在这块白板上画的这两个方案。

### 55　案例的真实结局：效果反而变差了（02:04:19–02:07:20）

> **文老师**：「这个其实叫**深度网络的集成学习**……他自己搞出来了，但是他都没有吹这个牛逼……然后你们想知道实验结果是啥吗？当时我给（了）一个数据集，反而这种结果还变差了。哈哈。但是不得不说啊，这是一个比较好的主意。」

- **【直译】** 这个三网络集成方案在老师给的数据集上效果反而变差了。但老师仍然认为这是个好思路。
- **【为什么】** 为什么会变差？可以给几个可能原因（老师没展开）：① 三个 backbone 参数量三倍，小数据集上直接过拟合；② 三个网络的特征尺度/分布不一致，直接 concat 会让某一路主导；③ 三倍显存意味着 batch size 被迫减小，BN 统计变差。这些都是特征级融合的典型坑，BEVFusion 里对应的解法是**在 fuser 前对两路特征各做一次 BN/LN 对齐**。
- **【为什么·方法论】** 老师保留这个"失败案例"讲，恰恰是这节课最诚实的地方。他给的定位是：「如果你做项目效果不好的时候，你真的可以用这种思路，够你混一周的时间。」以及「你不能去跟领导汇报这个方案，你跟领导汇报，他肯定（骂）你，你这在瞎搞。你只有你自己做出来真的有效果给他，才能堵上他的嘴。」——**先跑通拿数据，再汇报**。
- **【连接】** 老师顺带提了一个真实存在的对照：「YOLO 现在有一些网络的改进，就是一个 backbone 是 Transformer 的、一个是 YOLO 的模型，两个加起来……论文里面刷了六个点。」——也就是同样的思路在论文里是有效的，差别在数据规模。

**【小结】**
① GoogLeNet 三个头 = 深度监督；系数 0.3/0.3/1，**想哪里多学系数就调大（1.5~2 倍），可以调成 0 关掉某项**。
② 辅助头训练用、推理丢；或者保留做投票，代价是召回↑误检↑；三头分歧时输出"不确定"是合法且有价值的第四态。
③ 多 backbone 集成有两条路：特征级（concat + GAP + 1×1，= BEVFusion 范式）和决策级（各自 FC + 加权损失 + 投票）。老师的实测是效果变差，但思路可复用。

## 复习最小集（三句话背下来）

1. **改网络的四条件 + 一必改**：数据量（≥5000/类才上 VGG16）、特征复杂度（复杂选深）、目标大小（小目标选浅）、输入尺寸（决定减几层）；无条件必改 **FC 4096 → 256/128**（参数量 -95%）。
2. **尺寸匹配律**：resize 缩放比锁死在 **0.5×~2×**；最后一层 CNN 至少 **49 个特征值（7×7）**、推荐 256（16×16）；**图小减下采样点、图大加下采样点**。
3. **多尺度 + 多头两把钥匙**：多尺度结构 = 多分支 + 多感受野 + 花样算子，融合只有 Add（同质）和 Concat（异质）；多头损失 `Total = 0.3L₁+0.3L₂+1L₃`，**想哪里多学系数就调大 1.5~2 倍，不想要就调成 0**，辅助头训练用、推理丢。

- **改你的 MNIST 模板**：28×28 的输入按老师的表应该"< 28 直接用全连接"或最多 2 次下采样，不要 resize 到 224。把这条写进你的默写模板注释里。
