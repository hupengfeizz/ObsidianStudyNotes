### 1 · 那 664 张特征图，你今晚就能自己生成一遍（00:03:10 – 00:31:01）【画面 00_31_53】

老师花近半小时翻特征图讲"浅层几何梯度、深层语义"，听着像风景片——但**画面里那个文件夹本身就是一份可复现的作业说明**：`00_31_53.jpg` 状态栏 **664 个项目**，命名 `{序号}_layer{L}_channel{C}.jpg`，**每层只存前 6 个通道**。

**我的判断是：这一段的价值不在他讲的内容，而在于他无意中泄露了一个你该会的技能——给模型挂 hook 导特征图。**这是调试 backbone 最常用的一招：

```python
feats = {}
def hook(name):
    def f(m, i, o): feats[name] = o.detach()
    return f
for i, m in enumerate([m for m in model.modules() if isinstance(m, nn.Conv2d)][:8]):
    m.register_forward_hook(hook(f"layer{i+1}"))
model(img); n = 0                            # img: [1,3,H,W]
for name, fm in feats.items():
    for c in range(min(6, fm.shape[1])):     # 讲者每层只存了 6 个通道
        n += 1; plt.imsave(f"{n}_{name}_channel{c}.jpg", fm[0,c].cpu().numpy(), cmap='viridis')
```

这段代码说明：**特征图可视化不需要任何专用库**，`register_forward_hook` + `imsave` 就够；hook 拿到的 `o` 是 `[B,C,H,W]`，自己挑 batch 第 0 张再逐通道存。

**⚠ 坑**：老师全程把这批图叫"热力图 / CAM"，**术语是错的**：他展示的是**逐通道特征图**（与类别无关），而 **CAM / Grad-CAM** 是按类别梯度加权的类激活图。面试说错会被抓。

**所以你该怎么做**：把这段存成 `dump_feats.py` 放进 `36_PROJECT`。以后 YOLOv5 训练出问题、或 BEVFusion 的 BEV 特征不对，第一件事是挂 hook dump 中间特征，而不是盯 loss 曲线猜。

### 2 · 池化的反向传播：一道好面试题，老师答错了（01:06:01 – 01:14:00）【画面 01_12_21】

本节第一个"题很好、但老师说错了"的地方：池化没有权重，反传时梯度怎么走？PPT 第 27 页给了答案（这段转写完全丢失，只能靠帧）：max `[[3,2],[1,0]]→3` 反向 `[[3,0],[0,0]]`，avg 反向 `[[0.25,0.25],[0.25,0.25]]`——**max 是梯度路由，avg 是梯度均分**。

```python
a = torch.tensor([[[[1.,1],[0,2]]]], requires_grad=True)
F.avg_pool2d(a, 2).backward();  print(a.grad)   # [[0.25,0.25],[0.25,0.25]]
b = torch.tensor([[[[3.,2],[1,0]]]], requires_grad=True)
F.max_pool2d(b, 2).backward();  print(b.grad)   # [[1.,0.],[0.,0.]]
y, idx = F.max_pool2d(b.detach(), 2, return_indices=True)
print(F.max_unpool2d(y, idx, 2))                # [[3.,0.],[0.,0.]]  ← 拿到路由本身
```

这段代码说明：`b.grad` 里 4 个位置只有 1 个非零——**2×2 max 池化意味着 75% 的位置梯度为 0**，"池化让梯度稀疏"是字面意思。

**⚠ 老师这里说错了**：他被追问"池化的梯度到底等于几"，最后答「**W = 1**」，还坦承"我也没去研究过"。**池化层根本没有 W**，只有路由或均分。01:14:00–01:22:00 那 8 分钟结论全不可靠。

**所以你该怎么做**：把这 6 行存成 snippet，被问到时不要背，当场跑给对方看——`return_indices=True` + `max_unpool2d` 才是"我真的知道 max 池化在做什么"的证据。

### 3 · 用 stride=2 卷积代替池化：一眼看出网络的年代（01:13:00 – 01:14:00）

这条只讲了一分钟，却是**你以后写任何 backbone 的默认选择**。看参数量就明白：

```python
nn.Conv2d(64,128,3,stride=1,padding=1)   # 3*3*64*128 = 73728
nn.MaxPool2d(2)                          # 0 参数，硬丢 75% 信息，梯度稀疏（第 2 条）
nn.Conv2d(64,128,3,stride=2,padding=1)   # 还是 73728，下采样变成可学习的
```

这段代码说明：**换成 stride=2 卷积参数一分钱不多**，但下采样规则从"硬编码取最大值"变成"网络自己学怎么降维"——**零成本升级**。

**我的判断是：这条在课上被一句话带过，但它在真实工程里的分量远高于课上给它的时间**——"看到 Conv+MaxPool 堆叠基本可判定是 2015 年前的网络"，这个判据读论文读代码天天用得上。

**所以你该怎么做**：去两个仓库验证。YOLOv5 backbone **一个下采样用的 MaxPool 都没有**（SPPF 里那三个做多尺度感受野，不改尺寸）；BEVFusion 的 SECOND 全程 `SparseConv3d(stride=2)`。以后你搭网络，下采样一律写 `Conv2d(c1,c2,3,2,1)`。

### 4 · 参数量公式：本节唯一必须背下来的东西（01:29:00 – 01:33:02）【画面 01_31_12】

三个半小时只带走一样东西的话就是它，后面六条全建立在它之上。

`01_31_12.jpg`（PPT 第 27 页，共 265 页）老师蓝笔写死 `W_count = (3×3×128×256)` = `K_h × K_w × input_C × output_C`；同帧红笔还有**网络优化四方向**：① params 少 ② 特征强 ③ FLOPs 小 ④ 网络深（旁注：**小目标不深**）。

```python
conv = nn.Conv2d(128, 256, 3, bias=False)
print(conv.weight.shape, conv.weight.numel())   # [256,128,3,3]  294912
# 加 bias 要 +out_C：294912 + 256 = 295168
```

这段代码说明：`conv.weight` 形状是 `[out_C, in_C, Kh, Kw]`——**第 0 维是"有几个核"，后三维是"一个核长什么样"**，也就是**输入通道被一个核吃掉、输出通道靠核的个数堆出来**（第 22 条铁律的另一种说法）。

**我的判断是：这个公式的重要性被课上低估了。**老师当计算题讲，实际上它是**你以后所有"改网络"操作的成本表**——
改 P2 头、加 BiFPN、换 CA 注意力，每步涨多少参数全靠它心算。

**⚠ 口径**：老师在 01:59:00 说「偏置不考虑 bias」，**本节所有数字都是 `bias=False` 口径**。

**所以你该怎么做**：拿这把尺子量你简历要写的网络。`yolov5n` 第一层 `Conv(3,16,6,2,2)` → `1728`；BEVFusion 的 `SparseConv3d(64→128,k=3)` 多一个深度维 → `221184`——公式没变，K 从二维变三维而已。

### 5 · 参数量与输入尺寸无关：这是权重共享的代码级证明（01:32:02 – 01:34:00）

听起来像冷知识，其实是全课**逻辑上最关键的一步**。

```python
c = nn.Conv2d(128, 256, 3)
print(c(torch.randn(1,128,3,3)).shape)      # [1,256,1,1]
print(c(torch.randn(1,128,300,300)).shape)  # [1,256,298,298]
print(c.weight.numel())                     # 294912  ← 同一个 c，一个参数都没变
```

这段代码说明：同一个卷积层喂 3×3 和喂 300×300 都能跑，权重数量完全一样。**这就是"权重共享"的字面证据**：同一组 W 在整张图上反复滑动。CNN 因此能吃任意尺寸输入（**前提是没有全连接层**，这个前提在第 7 条会变成一道面试题）。

**我的判断是：这里有个推论比公式本身更值钱，而老师没点破——既然参数量与 H、W 无关，"减参数"就只剩三个旋钮：K、Cin、Cout。**记住这句，后面的 1×1（拧 Cin/Cout）、3×3 堆叠（拧 K）、分组/DW（切 Cin）就不是三个孤立技巧，而是**同一搜索空间里的三种走法**——本节唯一的结构性洞察。

**所以你该怎么做**：看到任何号称"轻量化"的论文，先问它动的是 K、Cin 还是 Cout；三个都没动却说省了参数，要么在动量化剪枝，要么在吹牛。

### 6 · FLOPs 和那个 ×2：论文里最常见的口径吵架（01:34:00 – 01:41:01）【画面 01_36_28 / 01_37_18】

全课**唯一一次"电脑屏幕上的活计算"**——但不是 IDE，是 Chrome 里的 DeepSeek 页（标签页标题「卷积层FLOPs计算」）。老师照着念了一串数字：`30×30=900 → ×128=115200 → ×1152=132710400 → ×256=33973862400`，往下才给出正式公式：

$$\text{FLOPs} = H_o \times W_o \times C_{out} \times (C_{in} \times K_h \times K_w) \times 2$$

**⚠ 坑**：链里的 `33973862400` 是 **DeepSeek 自己算岔的中间量**（Cin 乘了两次），老师跟着念了一遍。**别抄。**

```python
conv_flops = lambda Ho,Wo,Cin,Cout,Kh,Kw: (Ho*Wo*Cout*(Cin*Kh*Kw), Ho*Wo*Cout*(Cin*Kh*Kw)*2)
print(conv_flops(30, 30, 128, 256, 3, 3))   # (265420800, 530841600)  MACs, FLOPs
```

这段代码说明：同一层卷积，**参数 0.29 M，FLOPs 却是 5.3 亿**——差三个数量级。
**Params 和 FLOPs 是两个独立指标**：参数与 H、W 无关，FLOPs 与 H、W 平方成正比。imgsz 640→1280，参数不涨，算力涨 4 倍。

**我的判断是：那个 ×2 是全场最容易误会的细节，老师没讲透它的实践含义。**真相是 `thop`、`ptflops`、ultralytics `model.info()` 打印的 "GFLOPs" **实际都是 MACs 口径**（不乘 2），所以你常会遇到"别人报的数是我的一半"：**先问口径，再吵架**。

**所以你该怎么做**：在 4060 上跑 yolov8 时，`model.info()` 报的 GFLOPs 在笔记里标注"MACs 口径"——简历写"模型 X GFLOPs"，你得答得出 X 乘没乘 2。

### 7 · 面试题：输入从 224 改成 416，参数量变不变（01:41:01 – 01:45:01）

### 8 · im2col：卷积在底层根本不是滑窗（01:45:01 – 01:50:04）【画面 01_49_39】

本节技术密度最高的一帧，而这段转写**完全丢失**，只能靠画面复原。

`01_49_39.jpg` 是 PPT 第 54 页（图 4-36）：输入 4×4（1–9 右下补 0），核 2×2 = `[[1,2],[4,5]]`，**stride=2**，输出 `[[46,27],[23,9]]`。老师红笔标注「卷积核 K 摊平为 **4×16**」@「输入 X 摊平为 **16×1**」= 4×1，下方红字「**卷积计算多对 1**」。

```python
x = torch.tensor([[1.,2,3,0],[4,5,6,0],[7,8,9,0],[0,0,0,0]]).view(1,1,4,4)
cols = F.unfold(x, kernel_size=2, stride=2)      # [1,4,4]：每一列是一个感受野
k    = torch.tensor([1.,2,4,5]).view(1,4)
print((k @ cols[0]).view(2,2))                   # [[46,27],[23,9]]
print(F.conv2d(x, k.view(1,1,2,2), stride=2))    # 完全相同
```

这段代码说明：`F.unfold` 把每个感受野拉成一列，卷积退化成一次普通矩阵乘；手工验第一个数 `1×1+2×2+4×4+5×5 = 46` ✓。

**我的判断是：PPT 的摊平方式（核摊成 4×16 稀疏大矩阵）和 PyTorch 的（核 1×4 乘输入 4×4）是两种等价写法但用途不同**——PPT 那种暴露稀疏性（引出第 9 条），PyTorch 那种省内存（能实际跑），课上没区分，学员后面的困惑就来自这里。另外**这就是 GPU 跑卷积快的全部原因**：它执行的是 GEMM 而不是 for 循环滑窗。

**所以你该怎么做**：看到 `F.unfold` 不要跳过——它是"手写自定义卷积"的标准入口。你在 BEVFusion 里改稀疏卷积、或验证魔改卷积算得对不对，`unfold` + 矩阵乘就是不会错的参照实现。

### 9 · 稀疏连接 + 权重共享，用数字说给面试官听（01:50:04 – 01:54:00）【画面 03_29_45】

老师说这题「十个有九个都答不上来」。**这个判断我认为是对的**——"CNN 是稀疏连接"人人会背，但**能把稀疏度算成具体数字**的人确实少。最干净的证据在课末学员那张图：输入层 **240** 个神经元（10×8×3），中间层「节点数：63」，第一个隐藏节点的公式写全 12 项、结果 −23——**240 个输入里只有 12 个参与，而这 12 个 w 被全部 63 个节点共用。**

```python
x = torch.randn(1,3,8,10); w = torch.randn(1,3,2,2)
idx  = F.unfold(torch.arange(240.).view(1,3,8,10), 2).long()   # 每列的原始下标
W_eq = torch.zeros(63, 240)
for j in range(63): W_eq[j, idx[0,:,j]] = w.flatten()           # 每行只有 12 个非 0
print(W_eq.count_nonzero().item(), W_eq.numel())               # 756 15120 → 稀疏 95%
print(torch.allclose(W_eq @ x.flatten(), F.conv2d(x,w).flatten(), 1e-5))   # True
```

这段代码说明：`allclose == True` 是关键——**卷积真的可以写成一个 63×240 的全连接矩阵乘**，只是这 15,120 个位置里只有 756 非零，而这 756 个数里**独立的只有 12 个**。"稀疏 + 共享"不是比喻，是这个矩阵的两个字面属性。

**我的判断是：老师给的答法「稀疏连接 + 权重共享」漏了第三条——平移等变性。**同一组 W 滑遍全图，意味着"猫在左上角"和"猫在右下角"激活同一批权重，这才是 CNN 泛化能力的来源。

**所以你该怎么做**：面试被问"为什么 CNN 参数比 MLP 少"，别说"因为共享权重"，报数字：**同样的连接关系，MLP 要 15,120 个参数，CNN 只要 12 个。**

### 10 · 两个 3×3 顶一个 5×5：省 28%，不是 30%（02:09:01 – 02:14:01）【画面 02_04_00】

VGG 那篇论文最出名的结论，也是**你设计网络时唯一会反复用到的"核大小"决策**。PPT：28×28 输入，一个 5×5 → 24；两个 3×3 → 26 → 24，**输出尺寸一模一样**。

```python
x = torch.randn(1,1,28,28)
print(nn.Conv2d(1,1,5)(x).shape)                                    # [1,1,24,24]
print(nn.Sequential(nn.Conv2d(1,1,3), nn.Conv2d(1,1,3))(x).shape)   # [1,1,24,24]
print(2*3*3, 5*5, 18/25)      # 18 25 0.72   → 省 28%
print(3*3*3, 7*7, 27/49)      # 27 49 0.55   → 省 45%
```

这段代码说明：两条路径 shape 完全相同 → **感受野等价**；参数从 25 降到 18，**省的是 28%，不是 PPT 写的"约 30%"**，核越大省得越多。

**我的判断是：这题的三条好处必须一次答全，而老师只强调了前两条**——① 参数少 ② 网络更深 ③ **多了一次非线性**（两个 3×3 中间夹一个 ReLU，5×5 只有一次）。**第三条最容易漏也最本质**：只为省参数的话，中间不加激活就没意义了。**⚠** 老师中途说过一句"感受野不同"，随即自我更正——**感受野完全相同**。

**所以你该怎么做**：以后看到任何 `k=5` 或 `k=7`，条件反射问"能不能拆成 3×3 堆叠"。唯一例外是 YOLOv5 第一层 `Conv(3,16,6,2,2)`——大核是为了在 stride=2 下多看一点原始像素，这例外本身就是好面试素材。

### 11 · 输出尺寸公式：老师说别背，我同意（02:15:02 – 02:17:00）

这条我替你做一个"少学一点"的判断，因为老师自己说了实话：「算那玩意儿没必要，也没有人考你」。完整公式 $H_{out} = \lfloor (H+2p-d(k-1)-1)/s \rfloor + 1$ 里真正要记的只有两个特例：

x = torch.randn(1,8,32,32)
print(nn.Conv2d(8,8,3,stride=1,padding=1)(x).shape)   # [1,8,32,32] ← same

### 12 · 1×1 卷积的六大作用：第 2、3 条答不上来直接挂（02:17:00 – 02:19:00、02:36:02）【画面 02_35_16】

老师撂了句狠话：六条里第 2、3 条**答不上来就别面了**。我认为这个分级准确——第 2、3 条是"你真的用过 1×1"的证据，其余四条背一背就会。PPT 原文六条：

1. 不改变 h、w　2. 改变特征图**数量**（习惯叫升维/降维，但 h、w、dim 都没变，改的是 **shape**）　3. 输出 channel 变少时**参数量和计算量同时下降**　4. 增加非线性　5. 空间信息的沟通融合　6. 起到全连接的作用

```python
x = torch.randn(1,64,20,20)
print(nn.Conv2d(64,16,1)(x).shape)                    # [1,16,20,20]  h/w 不动
print(nn.Conv2d(64,16,1,bias=False).weight.numel())   # 1024 = 1*1*64*16
```

这段代码说明：1×1 的参数量是 `Cin × Cout`，**公式里没有 K² 这一项**，所以它是**唯一一个"零空间代价的通道旋钮"**。

**我的判断是：老师对第 2 条的措辞值得记住**——「大家叫升维降维，但 h、w、dim 都没变，改的是 shape」。这话像抠字眼，其实点破了常见误解：**1×1 不改变张量的维度数（永远 4D），改的是 channel 这一个轴的长度**。很多人把"降维"理解成 PCA 那种，方向就跑偏了。

**所以你该怎么做**：拿这六条去读 YOLOv5 `common.py`：`Bottleneck.cv1` 是 1×1（第 3 条）、`C3` 的 `cv1/cv2/cv3` 全是 1×1（第 5 条）、`Detect` 头是 1×1（第 6 条）。**你以前跳过的每一个 `k=1` 都对应其中一条**——从今天起每看到一个就问自己是哪一条。

### 13 · 压缩-还原：73,728 → 19,456，但压不够狠会反噬（02:19:00 – 02:24:01）【画面 02_20_20】

1×1 第 3 条作用的定量版，也是 ResNet 和 YOLOv5 Bottleneck 的共同原理。`02_20_20.jpg`（PPT 图 4-31）老师红笔圈出两个数：A（直接 3×3）663552 / 73728；B（1×1 压到 16 再 3×3）175104 / 19456。

```python
A = nn.Conv2d(64,128,3,padding=1,bias=False)
B = nn.Sequential(nn.Conv2d(64,16,1,bias=False), nn.Conv2d(16,128,3,padding=1,bias=False))
print(sum(p.numel() for p in A.parameters()))   # 73728
print(sum(p.numel() for p in B.parameters()))   # 19456   → 26.4%
print(1*1*64*64 + 3*3*128*64)                   # 77824 > 73728  ← 中间设 64 反而更多
```

这段代码说明：最后一行是本条的灵魂——**加一层 1×1 本身有成本**，只有"1×1 省下来的"大于"多一层花掉的"才划算；中间通道设 64 时不但没省，还多了 4,096 个参数。

**⚠ 口径**：老师口头说"少接近三分之一"，**画面数字 19456/73728 = 26.4%，即降到约 1/4**，按 1/4 报数。

**我的判断是：学员追问"中间通道为什么是 16"，老师答"随便你设"——这个回答不够好。**它是超参没错，但不是随便设：上面那行代码证明了**压缩比必须够狠**，行业惯例压到输入通道的 1/4（ResNet Bottleneck 即 `planes` 与 `planes*4`）。老师后半句"如果不是 16，你有可能变多"说对了，只是没说为什么。

**所以你该怎么做**：看 YOLOv5 `common.py` 的 `class Bottleneck`，第一行 `c_ = int(c2 * e)`（默认 `e=0.5`）——**你以前看不懂的那个 `c_` 就是这里的 16**。看懂之后你就有了第一个旋钮：`e` 改成 0.25，参数明显下降、mAP 掉多少，今晚就能设计的消融实验。

### 14 · GAP：一行 `adaptive_avg_pool2d` 干掉一亿参数（02:26:01 – 02:34:02）【画面 02_28_16】

第 7 条那道面试题的**根本解**，也是本节投入产出比最高的知识点。手写板上老师并排写了两条路：`7×7×512 ─FLAT→ FC⇒FC⇒FC(4096)` vs `7×7×512 ⇒ 全局平均池化(h,w) ⇒ 1×1×512`，旁注「49 个求平均」。

```python
x = torch.randn(1,512,7,7)
y = F.adaptive_avg_pool2d(x, 1)                             # [1,512,1,1]
print(torch.allclose(y, x.mean(dim=(2,3), keepdim=True)))   # True ← GAP 就是求平均
print(7*7*512*4096)                                         # 102760448 ← 被干掉的那一层
print(F.adaptive_avg_pool2d(torch.randn(1,512,13,13), 1).shape)   # [1,512,1,1] ← 换尺寸也对齐
```

这段代码说明：`allclose == True` 是最有价值的一行——**GAP 就是 `x.mean(dim=(2,3))`**。最后一行说明它**天生尺寸无关**：7×7 和 13×13 进来都是 `[1,512,1,1]`，所以第 7 条那个报错永远不会出现。

**我的判断是：老师这里做的一件事特别值得学——对论文黑话的祛魅。**论文写"GAP 融合全局空间信息、增强鲁棒性"，老师翻译成「就是把 49 个数求了个平均」。这种能力比记住术语本身重要得多：以后读 BEV 论文遇到看不懂的模块，第一反应应该是"它到底做了哪几次加乘"。

**所以你该怎么做**：`Linear(25088,4096)` 是 **102,760,448** 个参数，GAP 是 **0** 个；以后你写任何分类头，第一行永远是 `nn.AdaptiveAvgPool2d(1)`。这也解释了为什么 SE / CA 注意力第一步都是 GAP——你简历要写的 CA 注意力入口就在这里。

### 15 · 一卷到底：把 Linear 改写成等价的 Conv2d（02:29:00 – 02:36:02）

第 12 条第 6 作用的兑现，而且**兑现得很彻底：权重可以直接搬过去。**

```python
lin  = nn.Linear(512, 10);  conv = nn.Conv2d(512, 10, 1)
conv.weight.data = lin.weight.data.view(10,512,1,1)   # 关键：只是 reshape，一个数都不动
conv.bias.data   = lin.bias.data
x = torch.randn(1,512,1,1)
print(torch.allclose(lin(x.flatten(1)), conv(x).flatten(1), atol=1e-6))   # True
```

这段代码说明：`Linear(512,10)` 权重是 `[10,512]`，`Conv2d(512,10,1)` 是 `[10,512,1,1]`——**元素个数一样、顺序一样，`view` 一下就转过去**，数学上同一个运算。**⚠ 前提**：必须先 GAP 让 H=W=1，否则 1×1 会在每个位置各算一次就不等价。**我的判断是：老师在画面最上方自创了一个术语「1×1 卷积 → 减少内存跨显存算子 copy 的时间」，这话很拗口，但他指向的问题是真的，只是没说清楚。**我替他补完：Conv 和 Linear 在推理引擎里是两个不同 kernel、内存布局也不同（NCHW vs 2D 矩阵），中间要 reshape/transpose，全是纯开销。**全程 Conv 才能让 TensorRT 把整段融成一个 kernel**——真实存在的部署理由，只是课上讲得太含糊。

**所以你该怎么做**：YOLO 的 `Detect` 头用的是 `nn.Conv2d(ch, self.no, 1)` 而不是 `Linear`，BEVFusion 的 CenterPoint 头也是全卷积。**以后你写检测头默认就用 1×1**——不是风格问题，是部署问题。

### 16 · 分组卷积：参数降到 1/G，代价是通道不说话了（02:41:07 – 02:47:00）【画面 02_43_21】

轻量化家族都是第 5 条"只能动 K、Cin、Cout"的具体走法，分组卷积走的是**切 Cin**。
`02_43_21.jpg` 上老师紫笔在 `1/G` 上画了圈：`Parameters_group = (K×K×Cin/G)×(Cout/G)×G` → 普通的 **1/G**。数值例（图 4-27）：Cin=4、k=3、Cout=4 → 普通 144，分 2 组共 **72**。

```python
print(nn.Conv2d(4,4,3,bias=False).weight.numel())               # 144
print(nn.Conv2d(4,4,3,groups=2,bias=False).weight.numel())      # 72   ← 1/G
print(nn.Conv2d(128,256,3,groups=4,bias=False).weight.numel())  # 73728 = 294912/4
nn.Conv2d(128,256,3,groups=5)   # ValueError: in_channels must be divisible by groups
```

这段代码说明：最后一行最实用——`Cin % G != 0` 在**构造 `nn.Conv2d` 的那一刻就抛 `ValueError`**，不是等到 forward。你改网络时通道从 64 改成 48、忘了 groups 还是 32，模型压根建不起来。

同帧紫笔写了两条缺点：「① 减 W，1/G ② **通道信息不沟通**」，并补「检出率大大的降」。第二条是本质缺陷：第 g 组的输出永远看不到第 g′ 组的输入。

**我的判断是：老师在这里给了本节最值得记的一条论文筛选判据，可惜埋在闲聊语气里**——「有人已经证明了，这玩意并不快……最快的是标准卷积，22 年证明的。」**这个判断站得住脚**：FLOPs 低 ≠ 跑得快，分组/DW 访存密度低、GPU 上经常跑不满，实测 latency 降幅远小于 FLOPs 降幅。

**所以你该怎么做**：看到 `groups>1` 立刻问"它怎么把通道沟通补回来"（答案只有两个：channel shuffle，或跟一个 1×1 PW）；**读轻量化论文，只报 FLOPs 不报实测 latency 的直接跳过**。

### 17 · 深度可分离卷积：DW 和 PW 是不可分割的一对（02:47:00 – 02:49:01）【画面 02_48_36】

DW 是分组卷积推到极限的特例，老师手写板写得非常准确：「分组卷积：最大 max ⟶ in_C = out_C = group ⟹ DW」——**DW 不是新卷积，是 `G = Cin` 时的分组卷积**。PPT 图 4-33：A（标准 3×3）663552 / 73728；B（DW+PW）339968 / 8768。

```python
dw = nn.Conv2d(64, 64, 3, padding=1, groups=64, bias=False)   # 576  = 3*3*1*64
pw = nn.Conv2d(64, 128, 1, bias=False)                        # 8192 = 1*1*64*128
print(dw.weight.numel() + pw.weight.numel(), 8768/73728)      # 8768 0.1189 ≈ 1/8.4
```

这段代码说明：`dw.weight.numel()` 只有 576，因为 `groups=64` 时每个核的通道数是 **1** 不是 64（形状 `[64,1,3,3]`）。**8768 里有 8192 来自 PW**——省下的钱几乎全是 DW 省的，PW 是为买回"通道沟通"付的必要成本。老师说的"近八分之一"（11.9%）**是准确的**。

**我的判断是："DW 和 PW 不可分割"必须当成硬规则记住，这是新手最常犯的错**——只写 `groups=c` 图便宜、不跟 1×1，精度就莫名其妙掉一大截，原因就是"通道信息不沟通"。

**所以你该怎么做**：去 YOLOv5 `common.py` 找 `class DWConv(Conv)`——它就是本条的原样实现，但传的是 `g=math.gcd(c1,c2)` 而不是 `c1`，**为的是规避第 16 条那个 `ValueError`**。课上没讲，但你读代码一定会撞上。

### 18 · 空洞卷积：免费换感受野，但不能多用（02:57:00 – 03:00:00）【画面 02_58_12】

PPT 图 4-35 给了一个**完全可复现的算例**，本节少数"你能自己验一遍"的地方，建议手敲：7×7 输入配全 1 的 3×3 核，d=1 → 63、d=2 → 73、d=3 → 75。

```python
rows = [[11,2,3,4,5,6,7],[2,13,4,5,6,7,8],[3,4,5,6,7,8,9],[4,5,6,7,8,9,10],
        [5,6,7,8,9,10,11],[6,7,8,9,10,11,12],[7,8,9,10,11,12,15]]
img = torch.tensor(rows, dtype=torch.float).view(1,1,7,7)
w = torch.ones(1,1,3,3)
print(F.conv2d(img,w,dilation=1)[0,0,2,2].item())   # 63.0
print(F.conv2d(img,w,dilation=2)[0,0,1,1].item())   # 73.0
print(F.conv2d(img,w,dilation=3).item())            # 75.0
print(nn.Conv2d(64,64,3,dilation=2,padding=2,bias=False).weight.numel())  # 36864，与 d=1 完全相同
```

这段代码说明：三个数字全部对上 PPT，算例可信；最后一行才是重点——**dilation 从 1 变 2 参数一分钱不涨**，等效核却从 3 变 5。注意 `padding=2`——**要保尺寸不变，padding 必须等于 d**。老师蓝笔写了「① 参数量不变，感受野变大 ② **空洞卷积不能太多**」，口头补充最多 2~3 层、放中间层。

**我的判断是：这个"不能太多"的告诫是对的，但老师没给术语也没给解药，听起来像玄学经验。**补上：这个现象叫 **gridding effect（网格效应/漏采样）**——连续堆叠相同 dilation 会让某些像素永远采不到；解药是**互质的 dilation 序列（HDC）**，比如 1-2-5 而不是 2-2-2。

**所以你该怎么做**：`dilation` 是最便宜的涨点旋钮——**参数不变、算力不变、感受野翻倍**。在 YOLOv5 backbone 的 P4 阶段插一层 `Conv2d(c,c,3,dilation=2,padding=2)` 就是成本极低的消融实验，但记住：最多 2~3 层、放中间、序列互质。

### 19 · 转置卷积：那个"转置"是字面意思（03:01:04 – 03:09:00）【画面 03_25_32】

全课概念最漂亮的一处，因为它和第 8 条的 im2col **共用同一张 PPT 图**：卷积是 `K 摊平 4×16 @ X 16×1` → 2×2，标注「多对 1」；转置卷积是 `K 转置 16×4 @ X 4×1` → 4×4，标注「1 对多」。**"转置"不是比喻，就是线性代数的 `W.T`**：同一个矩阵，换个方向用。

```python
x = torch.randn(1,64,20,20)
up = nn.ConvTranspose2d(64,64,4,stride=2,padding=1,bias=False)
print(up(x).shape, up.weight.numel())     # [1,64,40,40]   65536
print(F.interpolate(x, scale_factor=2, mode='bilinear', align_corners=False).shape)  # 同 shape，0 参数
```

这段代码说明：两行 shape 一模一样，但一个花了 **65,536 个参数**，另一个花 **0**。这就是老师那句「转置的 params 比较大——看到了吧，4 乘以 16」的实质：**上采样天然比下采样贵**，它要凭空造像素。

**⚠ 最实用的一条坑**：`kernel_size` 必须能被 `stride` 整除，否则输出像素覆盖次数不均匀，产生**棋盘伪影**；`stride=2` 的安全默认是 `k=4, padding=1`，上面那行就是，可以直接抄。

**我的判断是：老师用整整 8 分钟讲"鬼影"，还搬出 Hinton 2006 那张 Deep Auto-encoder 重建的数字"2"当实证，却始终没说这个现象的标准名字和成因。**"鬼影"是自造词，标准术语是 **checkerboard artifact**，成因就是上面那条整除关系——知道成因你就知道它**可以规避**，而不是"用了转置卷积必然有鬼影"。

**所以你该怎么做**：BEVFusion 的 `SECONDFPN` 用的正是 `nn.ConvTranspose2d` 做多尺度对齐。你现在知道它贵、可能有伪影（检查 `k % s == 0`），就有了"何时该换成 `F.interpolate`"的依据：显存紧张、或只做尺度对齐不需要学习时换掉它。

### 20 · 上采样只有三种方法，老师在这里说错了一个术语（03:09:00 – 03:12:01、03:22:00）【画面 03_22_28】

老师说这题面试概率约 30%，我认为**偏保守了**——问到 FPN / PAN / 分割网络必然绕到上采样。好处是**答案封闭**：只有三种。老师的 API 边界也说得清楚：「`Upsample` 只能用在最近邻和（双）线性；`ConvTranspose` 只能转置卷积」。

```python
x = torch.randn(1,64,20,20)
F.interpolate(x, scale_factor=2, mode='nearest')                        # 最快，有锯齿，0 参数
F.interpolate(x, scale_factor=2, mode='bilinear', align_corners=False)  # 平滑，0 参数（默认首选）
nn.ConvTranspose2d(64,64,4,stride=2,padding=1)(x)                       # 可学习，65536 参数
```

这段代码说明：三种方法里前两种 **0 参数**、第三种 65,536 个。所谓"双线性插值"底层就是一行线性插值做两次——x 方向一次、y 方向一次，**"bi" 指的是两个维度**。

**⚠ 老师这里说错了**：他说「严格应该叫三线性，因为求了三次」——**错的**。`bilinear` / `trilinear` 的 bi / tri **指数据的维度数，不是插值次数**：bilinear = 2D（图像 H、W），trilinear = 3D（体数据，如 CT 或 BEV 的 voxel），**2D 图像写 trilinear 会直接报错**。这个口误必须纠正：你以后做 BEV 会同时遇到两者。

**所以你该怎么做**：记住三选一：**要快 → nearest；要质量且不加参数 → bilinear；要可学习且能接受伪影 → ConvTranspose2d。**YOLOv5 默认选了第一个，下一条就是把它改成第二个。

### 22 · 多通道卷积三条铁律：全课最好的两分钟，被当成闲聊跳过了（03:28:09 – 03:30:01）【画面 03_28_30 / 03_28_52】

**它在完整版精讲里被归到"收尾闲聊"，但它是全课密度最高的两分钟**，而且不是老师讲的，是学员杨佳奇画图发群里、老师照着讲的。`03_28_30.jpg` 上三条规则用黄色高亮写死：① **特征图通道数 = 卷积核个数** ② **卷积核数量多、size 小** ③ **卷积核通道数 = 输入通道数**。

`03_28_52.jpg` 给了完整算例，每个数字都可核对：输入 `Img(RGB): 10*8*3`，三通道左上角 2×2 是 `[[1,11],[3,4]]`、`[[1,5],[12,40]]`、`[[19,101],[33,14]]`；`Kernel-1: 2*2*3` 三通道是 `[[1,0],[0,1]]`、`[[0,1],[0,0]]`、`[[0,0],[-1,0]]`；右上角 `(1+4)+(5)+(-33) = -23`，输出 `Feature Map: 9*7`。

```python
x = torch.tensor([[1.,11],[3,4],  [1,5],[12,40],  [19,101],[33,14]]).view(1,3,2,2)
k = torch.tensor([[[1.,0],[0,1]],        # w_1..w_4   → 1*1 + 4*1 = 5
                  [[0.,1],[0,0]],        # w_5..w_8   → 5
                  [[0.,0],[-1,0]]]).view(1,3,2,2)   # w_9..w_12 → −33
print(F.conv2d(x, k).item())                                        # -23.0 ← 与画面完全一致
print(F.conv2d(torch.randn(1,3,8,10), torch.randn(1,3,2,2)).shape)  # [1,1,7,9] 即 9*7
```

这段代码说明（全条最重要的一句）：**三个通道的结果是相加的，不是拼接的**——`5+5+(−33) = −23`，最后只出来**一个数**。所以一个 `2×2×3` 的核只产生 **1** 张特征图；想要 64 张就得要 64 个核，写出来就是 `nn.Conv2d(3, 64, 2)`。**第 4 条那句"输入通道被一个核吃掉、输出通道靠核的个数堆出来"在这里得到数值级证明。**

**我的判断是：这两分钟比前面三个小时的任何一段都更适合当入门材料，而它出自学员之手，这件事本身很说明问题。**老师讲了三个半小时，从没把"一个核吃掉所有输入通道、最后只吐一个数"用具体数字演示过，学员一张图就讲清了。**要给别人讲多通道卷积，直接用这张图，别用老师的 PPT。**

**所以你该怎么做**：把 `03_28_52.jpg` 和 `03_29_45.jpg` 存进笔记附件目录。下次拿到任意多通道输入（RGB 图，或 BEVFusion 里 `[B,80,180,180]` 的 BEV 特征），按三条铁律直接写出 `nn.Conv2d(in_C, 你要几张图, k)` 并预判输出 shape——这是"会用卷积"的最低标准，也是你做 MNIST 默写模板时不该再查文档的地方。

## 📌 复习最小集

1. **两个公式，一个与尺寸无关，一个强相关。** `W = Kh×Kw×Cin×Cout`；`FLOPs = Ho×Wo×Cout×(Cin·Kh·Kw)×2`。算例 `Conv2d(128,256,3)` = **294,912** 参数、30×30 下 **530,841,600** FLOPs（MACs 减半）。工具报的 GFLOPs 通常是 MACs 口径。

2. **卷积在底层是 im2col + GEMM，等价于一个稀疏的全连接。** `F.unfold(x,2,stride=2)` 复现 `[[46,27],[23,9]]`；等价 FC 矩阵 63×240 里 95% 是 0、独立参数只有 12 个——一次答完稀疏连接 + 权重共享（+ 平移等变性）。

3. **参数量家族（Cin=64 → Cout=128，k=3）**：标准 **73,728** → 1×1 压缩-还原 **19,456**（1/4）→ DW+PW **8,768**（1/8.4）；分组 = 1/G；空洞不变。**减参数只有三个旋钮：K、Cin、Cout。**

4. **四个你以前跳过的 API**：`groups=Cin` 是 DW（**必须配 1×1 PW**，`Cin%G≠0` 构造时就 `ValueError`）；`dilation=d` 免费加感受野（`k_eff=d(k−1)+1`，`padding=d` 保尺寸）；`ConvTranspose2d` 贵且要求 `k%s==0`；`adaptive_avg_pool2d(x,1)` = `x.mean(dim=(2,3))`。

5. **三条铁律（第 22 条）**：特征图通道数 = 核**个数**；核通道数 = **输入**通道数；核要多而小。多通道结果是**相加**不是拼接——一个 `2×2×3` 的核只出 1 张特征图。

6. **今晚可动手的一件事**：`yolov5n.yaml` 第 30、35 行 `'nearest'` → `'bilinear'`，同 seed 同 epoch 跑 COCO128 对比 mAP50-95。**本节唯一一个可证伪的结论。**
