## 0.1 业务场景：为什么必须逐孔 100% 检 ★★★

> **能把场景讲透，比能讲透模型更能证明你真的落地过。**

### 管壳式换热器的结构

```
        ┌─── 壳程（Shell Side）：海水 ───┐
   ┌────┴────────────────────────────────┴────┐
   │  ▓▓  ┌──────────────────────────┐   ▓▓  │
   │  管  │  换热管 × 数千根          │   管  │
   │  板  ├──────────────────────────┤   板  │
   │  ▓▓  │  换热管                   │   ▓▓  │
   └───┬──┴──────────────────────────┴───┬───┘
       └─── 管程（Tube Side）：滑油 ──────┘
```

| 部件 | 说明 |
|---|---|
| **管板（Tubesheet）** | 一块厚钢板钻满孔，固定换热管。本项目直径约 2m，管孔 3000+，孔径 14mm |
| **换热管（Tube）** | 穿过管板孔的细管，内外走不同介质 |
| **连接工艺** | 先**胀接**（液压/机械胀管使管壁贴紧孔壁）→ 再**密封焊**（管端与管板焊接） |
| **密封焊缝** | 管端一圈的**环形焊缝**，防止两侧介质互串的最后一道屏障 ← **检测对象** |

### 为什么泄漏是致命的（这段是整个项目的价值起点）

```
管程：主机滑油（Lube Oil）
壳程：海水（压力通常高于滑油侧）

一条 0.1mm 的裂纹
  ↓
海水（高压侧）串入滑油系统
  ↓
滑油被海水乳化，粘度和油膜强度骤降
  ↓
主机曲轴轴瓦失去油膜保护
  ↓
【烧瓦】—— 主机抱轴、停车
  ↓
远洋航行中失去动力 = 重大海事事故
```

> **一条 0.1mm 的裂纹，代价是一台主机和一次事故。**
> 这就是为什么验收标准里写着「**裂纹类致命缺陷零漏检**」——不是 99%，是零。

### 相关标准

| 标准 | 内容 |
|---|---|
| **NB/T 47013.5**（原 JB/T 4730） | 承压设备无损检测 · 渗透检测 |
| **GB/T 151** | 热交换器（管壳式换热器设计制造） |
| **CCS《材料与焊接规范》** | 中国船级社，船用焊接与检验要求 |
| ASME BPVC Sec. VIII / IX | 美标压力容器与焊接工艺评定（出口船舶） |
| ISO 5817 | 焊缝质量等级（B/C/D 三级） |

**验收方通常是船级社验船师**，检测记录要可追溯——这解释了为什么系统需要"结果写库 + 原图存档"这一环。

### 缺陷类型与核心矛盾

| 缺陷 | 形态 | 危害 | 检测难度 |
|---|---|---|---|
| **裂纹（Crack）** | 细长线状，可能极窄 | **致命，零容忍** | 高（窄、对比度低） |
| 气孔（Porosity） | 圆形/椭圆暗点，可能成群 | 中（超标才判废） | 中 |
| 未熔合 / 未焊透 | 焊缝与母材间的线状不连续 | 高 | 高 |
| 咬边（Undercut） | 焊趾处的沟槽 | 中 | 中 |
| 夹渣 / 焊渣残留 | 不规则暗块 | 视尺寸 | **低危害但极易与气孔混淆** |
| 焊瘤 / 余高超标 | 凸起 | 低 | 反光强，误检源 |
| **碳化物 / 氧化色** | 表面变色 | **无危害** | **与缺陷高度相似，主要误检源** |

> **核心矛盾**：真正有害的缺陷（裂纹、未熔合）**数量极少**，而无害的干扰物（碳化物、焊渣、氧化色）**大量存在且外观相似**。

## 0.2 原方案（人工渗透检测）与瓶颈 ★★☆

### PT（渗透检测）流程

```
① 预清洗        去除油污、氧化皮（清洗不净直接导致假象）
② 施加渗透液    红色/荧光渗透液，靠毛细作用渗入表面开口缺陷
③ 停留（渗透）  10–30 分钟 ← 时间瓶颈之一
④ 去除多余渗透液 关键步骤，去多了显示丢失，去少了背景污染
⑤ 施加显像剂    白色显像粉吸出缺陷内的渗透液，形成放大的红色显示
⑥ 显像停留      7–30 分钟 ← 时间瓶颈之二
⑦ 目视观察      逐孔人工看，3000+ 孔
⑧ 记录与后清洗
```

### 瓶颈

| 环节 | 问题 |
|---|---|
| **停留时间** | 渗透 + 显像合计 20–60 分钟，是化学过程，压不下去 |
| **逐孔目视** | 3000+ 孔，人眼长时间盯看，**疲劳导致漏检率显著上升** |
| **主观性** | "这个显示算不算超标"依赖个人经验，不同检验员判断不一致 |
| **可追溯性差** | 纸质记录，无图像存档，事后无法复查 |
| **化学品** | 环保与职业健康负担 |
| **总耗时** | **一件约 1 个工作日** |

### 视觉方案要同时证明三件事

```
① 检出率 ≥ 95%（验收硬指标）
② 裂纹零漏检
③ 误报率足够低 —— 否则复检的人工成本会吃掉全部收益
```

> **第三条最容易被忽略**：如果 3000 个孔里报出 600 个疑似，人工还是要看 600 个，效率提升就没了。
> **这就是为什么这个项目里 Precision 的优化投入不比 Recall 少。**

## 0.3 硬件系统与采图方案 ★★☆

### 两级定位采图

```
第一级 · 全局定位
  管板整体拍一张全局图
  → 图像处理定位所有管孔中心坐标（霍夫圆 / 模板匹配 / 分割）
  → 建立孔位索引表（孔号 ↔ 机械臂坐标）

第二级 · 逐孔近摄
  机械臂按【蛇形轨迹】遍历所有孔位
  → 每孔正对拍摄，固定工作距离
  → 一孔一张 5472×3648 高分辨率图
```

### 为什么必须逐孔近摄（能现场推算）

```
管板直径 2000mm，最小缺陷 ~0.1mm
若一张图覆盖全管板：2000mm / 5472px = 0.37 mm/px
→ 0.1mm 的缺陷【连一个像素都不到】，物理上不可能检出
```

**逐孔近摄的分辨率**（单孔视场约 30mm）：

```
30mm / 5472px ≈ 5.5 μm/px
→ 15×15px 的缺陷对应实际尺寸约 0.08mm × 0.08mm
```

这个数量级才能满足焊缝检测的精度要求。

### 蛇形轨迹的两层意义

```
→ → → → → → → →
              ↓
← ← ← ← ← ← ← ←
↓
→ → → → → → → →
```

1. **消除空回程**——相比逐行回零，对 3000+ 孔位累计节省的机械运动时间非常可观
2. **采图一致性**（更重要）：

| 一致性维度 | 意义 |
|---|---|
| **正对拍摄** | 避免透视畸变，焊缝环带在图上是正圆而非椭圆 |
| **固定工作距离** | 孔径在图像上的像素尺度恒定 → **可以关闭随机缩放增强**（见 §56） |
| **固定光照几何** | 光源与工件相对位置不变，图像统计特性稳定 |

> **这是工业视觉相比自动驾驶的一个根本差异：工业场景可以控制成像条件，因此可以利用强先验（固定尺度、固定视角、固定光照）。自动驾驶不能。**

### 成像配置

| 项 | 典型配置 |
|---|---|
| 相机 | 2000 万像素工业面阵（5472×3648），全局快门 |
| 接口 | GigE Vision / USB3 Vision |
| 镜头 | 定焦工业镜头，低畸变 |
| **光源** | **环形光源（Ring Light）**，与孔同轴 |
| 触发 | 机械臂到位信号硬触发，保证位置与曝光同步 |

### 环形光源制造的固有问题

```
        环形光源
    ╲     ╱ ╲     ╱
      ▼ ▼     ▼ ▼
   ┌──────────────┐
   │ 焊缝余高（凸起）│ ← 正对光源，镜面反射 → 【过曝】
   ├──────────────┤
   │   孔内壁      │ ← 光线难以进入 → 【欠曝，偏暗】
   └──────────────┘
```

**结果**：缺陷多在暗区（欠曝 → 对比度不足 → **漏检**）；误检集中在过曝区（高光斑点被误判 → **误检**）。

**一张图上同时存在过曝和欠曝——这就是"复合光照"的准确含义。**

## 0.4 视觉流水线全景：层层缩小搜索空间 ★★★

```
采图层：全局定位 → 孔位索引 → 蛇形轨迹 → 逐孔触发采图
        输出：5472×3648 原图 × 3000+
              ↓
① ROI 精准提取          ▸ 你负责
   YOLOv8-Seg 分割焊缝环带 → 环外填灰 → 消除孔外背景与相邻孔干扰
              ↓
② 曝光补偿              ▸ 你负责
   IAT 轻量 Transformer 自适应均衡局部亮度
              ↓
③ 重叠切图              ▸ 你负责
   沿焊缝环带裁 1280×1280 子图，重叠 250px → 目标相对尺寸 +4 倍
              ↓
④ YOLOv8 缺陷检测       ▸ 你负责
   + P2 头 / BiFPN 双线性上采样 / P3·P4 CA 注意力

              ↓
⑤ 后处理
   子图坐标映射回原图 → 跨子图去重 → 类内 NMS → 判级
```

### 设计逻辑：每一层都在提高目标的相对显著性

```
5472×3648 全图（2000 万像素）
    ↓ ROI 分割，只保留焊缝环带

    ↓ 重叠切图

```

> **这是大图小目标问题的通用解法框架：不是靠一个更强的模型，而是靠一条层层缩小搜索空间的流水线。**

## 0.5 大图小目标的通用解法框架 ★★★

### 问题的量化（能现场推算）

```
原图         5472 × 3648
网络输入     640 × 640（YOLOv8 默认）
缩放比       5472 / 640 ≈ 8.55×

最小缺陷 15×15 px
    ↓ 直接缩放
15 / 8.55 ≈ 1.75 px
```

**1.75 个像素。** 在 P3（stride 8）特征图上，它连一个特征点都占不满。

> **这不是"难检测"，是信息在预处理阶段就已经丢失了。**

### 四层解法（本项目全部用上）

| 层 | 手段 | 本项目 |
|---|---|---|
| **数据层** | 切图放大（SAHI） | 1280 子图 + 250 重叠 → 相对尺寸 ×4.3 |
| **结构层** | 加高分辨率检测头 | P2（stride 4） |
| **特征层** | 上采样方式 + 注意力 | BiFPN 双线性、P3/P4 CA |
| **损失层** | 对小目标友好的度量 | DIoU + NWD |

### 切图数学（必须能现场推算）

```
不切图：15 px → 15 / 8.55  = 1.75 px
切  图：15 px → 15 / 2.0   = 7.5  px    （1280 → 640，缩放比 2×）
提升倍数：7.5 / 1.75 ≈ 4.3×
```

**子图数量**：

```
stride = 1280 − 250 = 1030
横向 ⌈(5472−250)/1030⌉ = 6
纵向 ⌈(3648−250)/1030⌉ = 4
→ 24 张（不做 ROI）
→ 约 8–12 张（沿焊缝环带切）
→ 推理量减少 50–60%
```

### 这个方案有正式名字：SAHI

> **SAHI（Slicing Aided Hyper Inference）**，Akyon et al., ICIP 2022

标准做法包含三部分：

1. **切片微调（Slicing Aided Fine-tuning）**——训练时也在切片上训，保证训练与推理分布一致
2. **切片推理**——推理时切片 + 重叠
3. **全图推理融合**——切片结果 + 全图推理结果一起做 NMS，兼顾大小目标

开源实现 `obss/sahi`，支持 YOLOv5/v8、MMDetection、Detectron2。在小目标检测竞赛和工业检测里几乎是标配，报告的增益通常在 **AP_small +5~15%**。

### 为什么 IoU 对小目标失效（用数字说，能现场推算）

固定框尺寸，让预测框沿一个轴平移 d 像素：

```
n×n 的框平移 d：  IoU = (n−d)·n / (2n² − (n−d)·n)
```

| 平移量 | **6×6 小目标** | 36×36 正常目标 |
|---|---|---|
| 1 px | 0.71 | 0.95 |
| 2 px | 0.50 | 0.89 |
| 3 px | 0.33 | 0.85 |
| **4 px** | **0.20** | **0.80** |
| 6 px | **0（梯度消失）** | 0.71 |

> **同样 4 个像素的偏移**：大目标 IoU 只从 1.0 掉到 0.80；**小目标掉到 0.20，再多 2 px 直接归零**。

**两个后果**：

1. **训练信号陡峭不稳定**——loss 曲面像悬崖
2. **anchor 匹配困难**——正样本分配依赖 IoU 阈值，小目标很难有 anchor 超过阈值 → **训练中根本没有正样本**

## 0.6 Focal Loss 失效的完整分析 ★★★

> **这是你整份简历里最好的技术故事：有常识、有反常识、有排查、有解法。全周最硬的一块，必须啃到能手推。**

### 0.6.1 常规思路与 Focal Loss 的定义

```
问题：样本失衡（NG : 背景 = 1 : 7）
教科书答案：上 Focal Loss
```

> Lin et al., *Focal Loss for Dense Object Detection*, ICCV 2017（RetinaNet）

```
FL(p_t) = −α_t · (1 − p_t)^γ · log(p_t)

p_t = p        若 y = 1（正样本）
p_t = 1 − p    若 y = 0（负样本）
γ   = 调制指数（论文推荐 2.0）
α_t = 类别平衡权重（论文推荐 0.25）
```

**设计意图**：`(1−p_t)^γ` 把**已经分对的、置信度高的样本**权重压低，让模型专注难样本。

```
p_t = 0.9,  γ=2 → (1−0.9)²  = 0.01     权重降到 1/100
p_t = 0.99, γ=2 → (1−0.99)² = 0.0001   权重降到 1/10000
p_t = 0.5,  γ=2 → (1−0.5)²  = 0.25     权重降到 1/4
```

### 0.6.2 教科书理论 vs 实际观察的矛盾（必须先说清楚）

**按公式推，硬 FP 应该被 Focal Loss 放大**：

```
一个硬 FP：负样本（y=0），模型预测 p = 0.95（很确信是缺陷）
→ p_t = 1 − p = 0.05
→ (1 − p_t)^γ = (0.95)² = 0.9025   ← 权重接近 1，几乎没被压低
```

**所以理论上 Focal Loss 恰恰应该帮上忙。但实际它没有。**

> ⚠️ **这个矛盾必须主动讲清楚，否则被懂行的面试官抓住会很尴尬。**
> 下面四个机制解释了为什么。

### 0.6.3 机制一 · 整体梯度范数塌缩（主因）

**关键前提：我们用的是已经预训练好、置信度普遍很高的模型。**

在一个已经收敛得不错的模型上继续微调时，**绝大多数样本的 `p_t` 都很高**。

**定量演示**（假设 99% 的样本 `p_t = 0.95`，1% 是硬 FP `p_t = 0.05`）：

```
BCE 下（无调制）：
  总权重 = 0.99 × 1 + 0.01 × 1 = 1.0

Focal Loss 下（γ=2）：
  易分样本 0.99 × (1−0.95)² = 0.99 × 0.0025 = 0.002475
  硬 FP    0.01 × (1−0.05)² = 0.01 × 0.9025 = 0.009025
  总权重 = 0.0115

→ 整体梯度范数降到 BCE 的 1.15%，约 1/87
```

**两个后果**：

1. **等效学习率掉了近两个数量级**——学习率不变的情况下，训练几乎停滞
2. 硬 FP 的**相对占比确实上升了**（从 1% 升到总梯度的 78%），但**绝对量微乎其微**（0.009 vs BCE 下的 0.01，加上整体尺度塌缩，实际更新量远小于 BCE）

> **准确表述**：不是 Focal Loss 单独压低了硬 FP，而是它**把整体信号压塌了**，导致本就稀少的硬 FP 推不动模型。

### 0.6.4 机制二 · 超参需要重新整定，直接套用会劣化

Focal Loss 引入 `α`、`γ` 两个超参，并且**改变了 loss 的量纲**：

- loss 整体数值大幅变小 → 与其他分量（框回归、DFL）的相对权重全乱
- 学习率、warmup 策略都要重调
- RetinaNet 的 `α=0.25, γ=2` 是在 COCO 上**从头训练**得到的，**在小数据集微调场景下没有理由继续适用**

### 0.6.5 机制三 · 与 YOLOv8 已有机制冲突（可查证的硬事实）

> **Ultralytics YOLOv5 / YOLOv8 的超参配置里有 `fl_gamma`，默认值是 `0.0`——即默认关闭 Focal Loss。**

原因是 YOLOv8 本身已经处理了失衡问题：

| 机制 | 作用 |
|---|---|
| **TaskAlignedAssigner** | 动态正负样本分配，按"分类分数 × 定位质量"的对齐度选正样本，**本身就是一种难例聚焦** |
| BCE + DFL | 分类用 BCE，框回归用 Distribution Focal Loss |
| objectness 分支的隐式平衡 | — |

**在一个已经做了正负样本动态分配的框架上再叠一层 Focal Loss，是重复且互相干扰的。** 社区实践中开启 `fl_gamma` 通常掉点。

> **这条最有力**——它把你的经验从"我遇到了"升级为"框架作者也是这么认为的"。

### 0.6.6 机制四 · 放大错标样本

Focal Loss 放大 hard example，而 **hard example 里混着错标**。

工业焊缝数据集的边界样本（这个氧化色算不算缺陷）本身就有争议，错标率不低。Focal Loss 会把这些错标样本的权重成倍放大，**训练往错误方向走**。

### 0.6.7 解法：定制 BCE 抑制硬 FP

**思路：不用全局的、对所有样本一视同仁的调制因子，而是针对性地给硬 FP 加权。**

```python
def custom_bce(pred_logits, targets, hard_fp_mask, fp_weight=3.0):
    loss = F.binary_cross_entropy_with_logits(
        pred_logits, targets, reduction='none'
    )
    weight = torch.ones_like(loss)
    weight[hard_fp_mask] = fp_weight    # 只对【负样本 且 高置信】加权
    return (loss * weight).mean()
```

**与 Focal Loss 的本质区别**：

| | Focal Loss | 定制 BCE |
|---|---|---|
| 调制方式 | **全局函数** `(1−p_t)^γ`，对所有样本生效 | **定向加权**，只针对硬 FP |
| 副作用 | 整体梯度塌缩 | 其余样本梯度不受影响 |
| 可控性 | 只有 γ 一个旋钮 | 可指定"什么算硬 FP"、加多少权 |
| 与框架兼容 | 与 TaskAlignedAssigner 冲突 | 只改 loss 的一个分支 |

> **一句话总结（面试直接用）**：
> **Focal Loss 是"让模型少关注简单样本"，是减法；定制 BCE 是"让模型多关注这一类特定错误"，是加法。在一个已经训得不错的模型上，加法比减法安全得多。**

## 0.7 样本失衡治理：采样 / 损失 / 数据三条腿 ★★☆

### 失衡的两个层面

**层面一 · 类间相似度极高**

| 真缺陷 | 干扰物 | 相似之处 |
|---|---|---|
| 气孔 | 焊渣附着 | 都是暗色圆形/不规则块 |
| 气孔 | 碳化物斑点 | 颜色深度相近 |
| 裂纹 | 加工划痕 | 都是细长线状 |
| 未熔合 | 焊趾自然过渡线 | 都是线状不连续 |

**层面二 · 数量严重失衡**

```
单张图内：真缺陷 ~1 处，干扰物 5–8 处
数据集级：NG : 背景 ≈ 1 : 7
```

**两者叠加**：模型面对的是"一堆长得几乎一样的东西，其中只有一个是要报的"。

### 三条腿

| 层面 | 手段 | 本项目 |
|---|---|---|
| **采样层** | 弱势类重采样 | ✓ |
| **损失层** | 定制 BCE 加权抑制硬 FP | ✓（§53） |
| **数据层** | 难负样本挖掘 + Copy-Paste 合成 + 空图负样本 | ✓（§52、§53） |

> **失衡问题很少能靠单一手段解决，一般是采样、损失、数据三条一起上。**

### 难负样本挖掘（不是随机加负样本）

```
① 用当前模型跑全量数据推理
② 挑出【高置信度但实际是背景】的检出（硬 FP）
③ 按误检成因归类：
     碳化物 / 焊渣 / 孔内壁纹理 / 倒角 / 高光斑点 / 相邻孔边缘
④ 每一类构建专门的难负样本集
⑤ 回灌训练
⑥ 重新评测，追踪每一类的收敛情况
```

**归类的价值**：能定量追踪每一类误检的收敛，而不是只看一个总数。

> **这和项目一的凭空误检治理、项目二的路面截断治理、项目三的误检 checker 分类，是完全同一套方法论。**

### OHEM vs 离线挖掘

> OHEM（Online Hard Example Mining），Shrivastava et al., CVPR 2016

| | 离线挖掘 | OHEM |
|---|---|---|
| 时机 | 训练前准备数据 | 训练中动态选择 |
| 可控性 | 高（可人工确认） | 低 |
| **风险** | — | **会放大错标样本**（错标的 loss 也高） |

> **在标注质量不完美的工业数据集上，离线挖掘 + 人工确认更安全。**

### 分阶段训练

```
阶段一：全量数据训练，建立基础检出能力（保 Recall）
阶段二：加入难负样本，降低学习率微调（提 Precision）
```

**为什么分阶段**：一开始就大量负样本 → 模型倾向"什么都不报"，Recall 起不来；先建立检出能力再压误检，两个目标不互相干扰；阶段二用小学习率，避免破坏已学到的检出能力。

## 0.8 数据增强必须匹配真实分布 ★★☆

> **与项目二关掉 mosaic 是完全同一条原则。两个项目串讲。**

### 通用原则

> **数据增强不是通用配方。能"涨点"的增强，本质上是在补充训练分布中缺失的变化；如果它补充的变化在部署场景中不存在，它就是在注入噪声。**

**自检问题**：

> **这个增强产生的图像，在真实产线上有可能出现吗？**

| 增强 | 真实会出现吗 | 本项目 |
|---|---|---|
| **随机缩放** | **✗ 机械臂固定工作距离，尺度是常量** | **✗ 关闭** |
| 亮度 / 对比度扰动 | ✓ 不同工件表面状态、光源衰减 | ✓ |
| 轻微旋转 | ✓ 工件摆放有微小角度差 | ⚠️ 小幅度 |
| **Copy-Paste** | ⚠️ 只在焊缝环带内粘贴才合理 | ✓ 有约束 |
| Mosaic | ✗ 一张图里四个焊缝环带？不会 | ✗ |

### Copy-Paste 的关键约束

> Ghiasi et al., *Simple Copy-Paste is a Strong Data Augmentation Method*, CVPR 2021

```
✓ 粘贴到焊缝环带上   → 模型学到的位置先验是【真实的】
✗ 粘贴到孔内壁       → 教模型"孔内壁上会有裂纹"，这是【假先验】
✗ 粘贴到管板母材     → 同上
✗ 粘贴到倒角        → 同上
```

**为什么这条约束如此重要**：本任务的目标**位置先验极强**（缺陷只可能在焊缝上）。破坏这个先验，相当于故意让模型变笨。

**其他必须处理的细节**：

| 细节 | 说明 |
|---|---|
| 边缘融合 | 直接粘贴有硬边，需要泊松融合或高斯羽化 |
| 光照匹配 | 粘贴源和目标的亮度差异要调整，否则模型学到"亮度突变=缺陷" |
| 尺度匹配 | 保持真实物理尺寸对应的像素尺度 |
| **合成比例克制** | **占比一高，模型会过拟合到合成痕迹上**（学到"有融合边缘=缺陷"）。经验值 10–30% |

## 0.9 部署、量化与产线节拍 ★★☆

### 部署链路

```
PyTorch(.pt) → ONNX → TensorRT Builder → INT8 校准 → .engine → 工控机推理
```

### INT8 量化

| 项 | 说明 |
|---|---|
| 方式 | **PTQ**（训练后量化），几百张校准图统计激活值分布 |
| **校准集选择** | **必须覆盖过曝、欠曝、各类缺陷**，否则量化 scale 不准 |
| 收益 | 相比 FP32 约 **3–4× 加速**，显存降至 1/4 |
| 精度损失 | 通常 mAP 掉 0.5–2%，需实测 |
| 敏感层回退 | 检测头输出层、上采样层对量化敏感，可保持 FP16 |

> **本项目的有利条件**：验收标准 95%，模型做到 96.8%，**有 1.8 个百分点的量化预算**。如果模型只做到 95.2%，量化后就掉到验收线以下了。
> **这就是"精度冗余"的价值**——量产项目的模型精度不能刚好卡在验收线上，必须留出部署损耗的余量。

### 时间预算：视觉不是瓶颈（这一节最能体现系统思维）

```
单孔时间预算 = 2.5 小时 / 3000 孔 ≈ 3.0 秒/孔

机械臂移动到位     1.5–2.0 s   ← 主要瓶颈（物理运动，压不下去）
相机曝光 + 传输     0.1–0.3 s
ROI 分割推理        ~10 ms
IAT 曝光补偿        ~5 ms
切图（约 10 张）    ~5 ms
检测推理 ×10（INT8）~50–100 ms
后处理 + NMS        ~10 ms
结果写库            ~10 ms
──────────────────────────────
视觉部分合计        ~0.15 s   ← 只占 5%
```

**因此优化的关键是并行化，而非单点加速**：

```
时间轴 →
孔 N   : [移动][采图]
孔 N-1 :        [ROI][IAT][切图][检测][后处理]
孔 N-2 :                          [写库][报告]

三级流水线并行，总节拍 = max(各级耗时) 而非 sum
→ 节拍由机械臂移动时间决定
```

> **这个认知很重要**：如果只盯着模型加速（再压 20ms），对总耗时几乎没有影响。**系统级瓶颈分析比单点优化更有价值。**
> **与项目一的时延预算是同一类思维**——先搞清楚瓶颈在哪，再决定优化什么。

### 结果落库与可追溯

```
每个孔的记录：
  工件编号 / 孔号 / 采图时间
  原图路径（存档）
  检测结果（缺陷类型、位置、尺寸、置信度）
  判级结论（合格 / 复检 / 不合格）
  操作员确认状态
```

**为什么必须存原图**：船级社验收要求可追溯，争议时需要调出原始图像复核。这也为后续模型迭代提供持续的数据来源。

**Q1 ·「占比 <1%」是什么占比？**

`原理`　**是相对边长，不是面积**。

```
边长占比：15 / 5472 ≈ 0.27%
面积占比：225 / (5472×3648) ≈ 1.1 × 10⁻⁵ （十万分之一）
```

面积占比是 10⁻⁵ 量级，说"<1%"其实还说小了。**准确的说法是"相对边长不到 0.3%，面积占比在十万分之一量级"。**

`口语`　准确说是相对边长，十五除以五千四百七十二大概是千分之二点七。如果按面积算是十万分之一量级，那个数字更夸张。所以简历上写的"占比小于百分之一"其实是保守的说法。

**Q2 · 15×15px 对应多大？**

`原理`　单孔视场约 30mm：

```
30mm / 5472px ≈ 5.5 μm/px
→ 15×15 px ≈ 0.08mm × 0.08mm
```

**这个数量级正好是焊缝检测的精度要求**——裂纹宽度可能只有 0.05–0.1mm。

`口语`　单孔的视场大概三十毫米，除以五千四百七十二个像素，像素尺度是五点五微米。十五个像素大概是零点零八毫米。这个数量级正好对得上焊缝检测的精度要求，裂纹宽度可能就零点零五到零点一毫米。

**Q3 · 为什么下采样后检不出？**（必须定量）

`原理`

```
原图 5472 → 网络输入 640，缩放比 8.55×
15 px / 8.55 ≈ 1.75 px
```

**1.75 个像素**。在 P3（stride 8）特征图上，它连一个特征点都占不满——`1.75/8 = 0.22`。

> **这不是"难检测"，是信息在预处理阶段就已经丢失了。** 无论后面的网络多强都救不回来。

（这个逻辑和项目一「深度歪了检测头救不回来」是同构的——**信息在进入网络主体之前就损坏了**。）

`口语`　原图五千四百七十二，网络输入六百四十，缩放比是八点五五倍。十五个像素除以八点五五就是一点七五个像素。在 stride 为八的特征图上，它连一个特征点都占不满。
所以这不是"难检测"，是信息在预处理阶段就已经丢了，后面网络再强也救不回来。

**Q4 · 为什么不直接用大分辨率输入？**

`原理`　计算量按面积增长：

```
640×640  → 基准
1280×1280 → 4×
2560×2560 → 16×
5472×3648 → 约 49×
```

而且**显存也按面积增长**，5472×3648 的输入在训练时 batch size 只能是 1 甚至跑不起来。

**更关键的是：绝大部分像素是无效的。** 焊缝环带只占全图 15–25%，用全分辨率跑全图，等于把 75–85% 的算力花在孔内壁、母材、相邻孔上。

**切图 + ROI 是同样效果但便宜得多的做法。**

`口语`　计算量按面积增长，直接上五千多的分辨率大概是六百四十的四十九倍，显存也是，训练的时候 batch 只能是一甚至跑不起来。
更关键的是绝大部分像素是无效的——焊缝环带只占全图的百分之十五到二十五，用全分辨率跑全图等于把百分之七八十的算力花在孔内壁、母材和相邻孔上。切图加 ROI 能达到同样效果但便宜得多。

**Q5 · 为什么不用超分辨率？**

`原理`　三个理由：

1. **超分不创造信息**——它是根据先验"猜"出高频细节。对于自然图像（人脸、纹理）效果好，因为先验强；但**焊缝缺陷的形态没有那么强的先验**，超分可能"幻觉"出不存在的缺陷，或者把真缺陷平滑掉
2. **风险不对称**——超分产生的伪影在这个场景里可能直接变成误检，而误检的代价很高
3. **成本**——多一个超分网络的推理开销，而切图能达到同样的效果且是无损的

> **切图是"真的把像素放大"（用原始像素），超分是"猜出更多像素"。在检测任务上前者更可靠。**

`口语`　三个原因。一是超分不创造信息，它是根据先验猜出高频细节，对人脸、自然纹理效果好因为先验强，但焊缝缺陷的形态没那么强的先验，超分可能幻觉出不存在的缺陷，也可能把真缺陷平滑掉。二是风险不对称，超分的伪影在这个场景可能直接变成误检，代价很高。三是多一个网络的推理开销。
本质区别是切图用的是原始像素，是真的把目标放大了；超分是猜出更多像素。检测任务上前者更可靠。

**Q6 · 跟自动驾驶远距小目标是同一类吗？**

`原理`　**表现相似，约束完全不同**：

| | 焊缝检测 | 自动驾驶远距 |
|---|---|---|
| 能否切图 | **能**（离线、节拍 3 秒/孔，推理量翻倍可接受） | **不能**（10Hz 实时，硬时延预算） |
| 成像条件 | **可控**（固定距离、固定光照、正对） | 不可控 |
| 能否加高分辨率头 | 能（算力宽裕） | 很贵（P2 在车端加不起） |
| 目标是否运动 | 静止 | 运动 |
| 能否重拍 | **能**（发现异常可以重新采图） | 不能 |

> **所以两边的解法方向不同**：工业检测可以用"层层缩小搜索空间"的流水线；自动驾驶只能在网络内部想办法（改善深度监督、加时序）。

`口语`　表现相似但约束完全不同。焊缝这边能切图，因为是离线的、节拍是三秒一个孔，推理量翻倍完全可以接受；自动驾驶是十赫兹实时，有硬时延预算，切图根本不可能。另外工业场景的成像条件是可控的——固定距离、固定光照、正对拍摄，可以利用很强的先验；自动驾驶不行。
所以解法方向不一样，工业检测可以用层层缩小搜索空间的流水线，自动驾驶只能在网络内部想办法。

**Q1 · 怎么区分？**

`原理`　物理上的区别：

| | 碳化物 / 氧化色 | 焊渣 | 气孔（真缺陷） |
|---|---|---|---|
| 本质 | 表面变色，**无深度** | 表面**附着物**，凸起 | **凹陷/空洞**，有深度 |

**但在 15×15 像素上，这些线索都非常微弱。**

`口语`　物理上其实有区别。碳化物和氧化色是表面变色，没有深度，边界是渐变的；焊渣是附着上去的凸起物，形状不规则而且有镜面高光；气孔是凹进去的空洞，边界比较清晰，在环形光下内部会有特定的阴影分布。

**Q3 · 相似度和失衡，哪个更难？**

`原理`　**相似度更难。**

- **失衡**是可以用工程手段缓解的——重采样、loss 加权、数据合成，三条腿都有成熟方法
- **相似度**是信息层面的问题——如果两个东西在图像上真的长得一样，任何 loss 都救不了

**而且两者的交互让问题更糟**：失衡让模型倾向于"什么都判成背景"，而相似度让"判成背景"这个错误的代价（漏检真缺陷）难以被发现。

**实践中的解法是分层**：先用工程手段（切图、光照补偿）**提高可分性**——把信息层面的问题先解决一部分；再用失衡治理的手段去优化决策边界。

`口语`　相似度更难。失衡是可以用工程手段缓解的，重采样、loss 加权、数据合成都有成熟方法；但相似度是信息层面的问题，如果两个东西在图像上真的长得一样，任何 loss 都救不了。
而且两者是交互的——失衡让模型倾向于什么都判成背景，相似度又让这个错误不容易被发现。所以实际的解法是分层：先用切图、光照补偿这些手段提高可分性，把信息层面的问题解决一部分；再用失衡治理去优化决策边界。

**Q4 · 标注怎么保证一致？**

`原理`　**这个问题的答案是"标注规范要显式定义干扰类"。**

关键设计：

```
缺陷类（NG）：
  裂纹      —— 线状不连续，长宽比 > 3，端部尖锐
  气孔      —— 近圆形暗区，边界光滑，直径 > X px 才计
  未熔合    —— 焊缝与母材交界的线状暗痕
  咬边      —— 焊趾处连续沟槽

干扰类（非缺陷，必须【显式】定义为背景）：
  碳化物    —— 表面变色，无深度，边界渐变
  焊渣      —— 表面附着物，形状不规则，有高光
  氧化色    —— 大面积均匀变色
  孔内壁纹理 —— 加工纹路
  倒角      —— 结构性特征
```

> **关键：干扰类必须显式定义，而不是"不标就完了"。** 因为标注员需要知道"看到这个不要标"，否则会出现有人标有人不标的不一致。

**还有两条**：

1. **焊接工程师参与评审**——区分气孔和焊渣需要焊接工艺知识，普通标注员做不了，争议案例由懂工艺的人裁定
2. **金标准集**——由你和工艺人员共同确认的一小批数据作为标尺

`口语`　核心是标注规范要**显式定义干扰类**，而不是"不标就完了"。我在规范里把碳化物、焊渣、氧化色、孔内壁纹理、倒角这些都单独列出来，写清楚各自的形态特征，明确告诉标注员"看到这个不要标"。如果不写，就会出现有人标有人不标的不一致。
另外这个项目的标注需要专业知识，区分气孔和焊渣要懂焊接工艺，普通标注员做不了，所以争议案例是请焊接工程师裁定的，我们还建了一个金标准集当标尺。

**Q1 · 环形光源为什么造成这个问题？**

`原理`　几何决定的：

```
        环形光源（与孔同轴）
    ╲     ╱ ╲     ╱
      ▼ ▼     ▼ ▼
   ┌──────────────┐
   │ 焊缝余高（凸起）│ ← 表面法线正对光源 → 镜面反射直接进相机 → 过曝
   ├──────────────┤
   │   孔内壁      │ ← 被孔口遮挡，光线难以进入 → 欠曝
   └──────────────┘
```

- **焊缝余高是凸起的**，表面法线正对光源和相机，镜面反射直接进入镜头
- **孔内壁是凹进去的**，环形光的光线被孔口边缘遮挡，进不去

`口语`　是几何决定的。环形光源跟孔是同轴的，焊缝余高是凸起来的，表面法线正对光源和相机，镜面反射直接进镜头，就过曝了；孔内壁是凹进去的，环形光的光线被孔口边缘挡住，进不去，就偏暗。

**Q2 · 为什么"复合"更难？**

`原理`　**因为同一张图内同时存在两种相反的失效，全局调整无法同时改善两者**：

```
拉亮暗部 → 高光更糊（本来就饱和了）
压低高光 → 暗部更黑（本来信噪比就低）
```

**而且两个区域的问题性质不同**：

| 区域 | 问题 | 后果 |
|---|---|---|
| 暗区（孔内壁、焊趾根部） | 对比度不足，噪声占比高 | **缺陷多在这里 → 漏检** |
| 过曝区（余高） | 像素值饱和（255），信息不可恢复 | **高光斑点像缺陷 → 误检** |

`口语`　难在同一张图里同时有两种相反的失效，全局调整没法同时改善——拉亮暗部会让高光更糊，压低高光会让暗部更黑。而且两个区域的问题性质还不一样：暗区是对比度不足、噪声占比高，而缺陷恰好多在暗区，所以是漏检；过曝区是像素值饱和了、信息不可恢复，高光斑点看起来像缺陷，所以是误检。一个漏一个误，都很难受。

---

**Q3 · 为什么不换光源？**

`原理`　可以讨论几个方案和它们的代价：

| 方案 | 效果 | 代价 |
|---|---|---|
| **同轴光** | 对平面反光好 | 对孔内壁仍然进不去 |
| **低角度暗场光** | 突出凹凸缺陷（划痕、气孔边缘），抑制平面反光 | 需要额外光源，且对平坦缺陷不敏感 |
| **漫射穹顶光** | 均匀，消除高光 | 对比度下降，缺陷也变不明显 |
| **多光源组合切换** | 效果最好 | 采图时间翻倍，节拍不允许 |
| 降低曝光 | 消除过曝 | 暗区更暗，更看不见 |

**光源方案的选择不是我做的**（属于成像方案设计，是共同讨论的），但要知道**每一种都有 trade-off，没有免费午餐**。

`口语`　讨论过几个。同轴光对平面反光好但孔内壁还是进不去；低角度暗场光能突出凹凸缺陷、抑制平面反光，但对平坦的缺陷不敏感，而且要加光源；漫射穹顶光很均匀能消除高光，但整体对比度下降，缺陷也变不明显了；多光源组合切换效果最好，但采图时间翻倍，节拍不允许。
光源方案是成像方案的一部分，是大家一起定的，我主要是在给定的成像条件下用算法去补。

**Q4 · 传统方法为什么不够？**

`原理`

| 方法 | 局限 |
|---|---|
| 全局直方图均衡 | **加剧高光饱和，放大暗区噪声** |
| **CLAHE**（限制对比度自适应直方图均衡） | 分块处理，比全局好；但**块边界有伪影、参数需手调、不是学出来的** |
| Gamma 校正 | 单调映射，**无法同时处理两端** |
| Retinex 系 | 效果好但慢，参数敏感 |

**共同问题**：它们都是**固定规则**，无法根据图像内容自适应，且需要针对不同工件手调参数。

`口语`　全局直方图均衡会加剧高光饱和、放大暗区噪声。CLAHE 是分块的自适应均衡，比全局好，但块边界会有伪影，参数还得针对不同工件手调，而且它不是学出来的。Gamma 校正是单调映射，没办法同时处理两端。Retinex 系效果好但慢，参数也敏感。
共同问题是它们都是固定规则，没法根据图像内容自适应。

**Q5 · 为什么不用 HDR 多曝光融合？**

`原理`　**效果最好，但代价是采图时间。**

```
多曝光 HDR：拍 3 张不同曝光的图融合
→ 采图时间 ×3
→ 单孔从 3 秒变成 5–7 秒（曝光 + 传输都翻倍）
→ 3000 孔的总时间从 2.5 小时变成 4–6 小时
→ 产线节拍不允许
```

**这是一个明确的工程 trade-off**：用算法（IAT）换采图时间。

`口语`　HDR 效果肯定最好，但要拍三张不同曝光的图融合，采图时间翻三倍。单孔从三秒变成五到七秒，三千个孔的总时间从两个半小时变成四到六小时，产线节拍不允许。所以是用算法换采图时间，选了 IAT 这种轻量的曝光补偿。

**Q6 · 过曝的信息彻底丢了吗？**（好问题）

`原理`　**严格说是的——像素值饱和到 255 之后，那个区域的相对亮度差异不可恢复。**

但这不意味着 IAT 没用：

1. **不是所有"亮区"都饱和**——很多是"偏亮但未饱和"，这部分信息可以恢复
2. **IAT 压低亮区之后，饱和区和非饱和区的边界变清晰了**，反而更容易识别出"这是一个高光斑点"而不是缺陷
3. **暗区的提升是实打实的**——暗区没有饱和，信息只是信噪比低，拉亮能恢复

> **所以 IAT 的 Precision 提升主要来自"高光斑点不再像缺陷"，Recall 提升主要来自"暗区缺陷显现"。这是两个不同的机制。**

`口语`　严格说饱和到 255 的那部分是不可恢复的，相对亮度差异已经没了。但 IAT 还是有用，有三个原因：一是很多区域是偏亮但没饱和，这部分信息能恢复；二是把亮区压下来之后，饱和区和非饱和区的边界变清晰了，反而更容易识别出"这是个高光斑点"而不是缺陷；三是暗区的提升是实打实的，暗区没饱和，只是信噪比低，拉亮能恢复。
所以 IAT 的精确率提升主要来自高光斑点不再像缺陷，召回提升主要来自暗区缺陷显现，这是两个不同的机制。

**Q1 · 4 倍怎么算的？**（必须能现场推）

`原理`

```
不切图：5472 → 640，缩放比 8.55×，15px → 1.75 px
切  图：1280 → 640，缩放比 2.0×， 15px → 7.5 px

提升 = 7.5 / 1.75 ≈ 4.3×
```

`口语`　不切图的话原图五千四百七十二缩到六百四十，缩放比八点五五倍，十五个像素变一点七五个。切成一千二百八十的子图再缩到六百四十，只缩两倍，十五个像素变七点五个。七点五除以一点七五，大概四点三倍。

**Q2 · 重叠为什么 250px？**

`原理`　**原则：任何一个缺陷，必须至少在一张子图里是完整的。**

```
若最大缺陷尺寸 ≈ 150–200 px
则重叠量必须 > 最大缺陷尺寸
取 250 px = 最大缺陷尺寸 + 余量
```

**如果重叠不足**：一个缺陷被切成两半，两张子图各看到一半，**两边都可能检不出来**，或者检出两个残缺的框——**这是切图方案最典型的失败模式**。

`口语`　原则是任何一个缺陷至少要在一张子图里是完整的。我们最大的缺陷大概一百五到两百个像素，所以重叠量必须大于这个，取二百五十是留了余量。
如果重叠不够，一个缺陷被切成两半，两张子图各看到一半，两边都可能检不出来，或者检出两个残缺的框——这是切图方案最典型的失败模式。

**Q3 · 子图尺寸的权衡**

`原理`

| | 子图更小 | 子图更大 |
|---|---|---|
| 目标相对尺寸 | **更大，更好检** | 更小 |
| 子图数量 | **线性上升** | 更少 |
| 推理耗时 | **线性上升** | 更少 |
| 上下文信息 | **减少**（可能丢失判别所需的周边信息） | 保留 |
| 跨子图截断风险 | 上升 | 下降 |

**1280 是在「目标够大」和「推理次数可接受」之间的折中点，需要实测确定，没有理论最优值。**

`口语`　切得越小目标相对越大越好检，但子图数量和推理次数线性上升，端侧的时间预算撑不住；而且切太小会丢上下文，判别可能需要看周边的焊缝走向。切得大就反过来。一千二百八十是在这两者之间折中出来的，是实测定的，没有理论最优值。

**Q4 · 重复检出怎么处理？**

`原理`

```
重叠区域的同一个缺陷 → 在两张子图里各被检出一次
    ↓
子图坐标 → 原图坐标映射
    ↓
【在原图尺度上】做一次全局 NMS
```

> **必须在原图尺度做 NMS，不能在子图尺度做**——因为重复来自不同子图，子图内部的 NMS 看不到对方。

`口语`　重叠区的同一个缺陷会在两张子图里各被检出一次。处理方式是先把子图坐标映射回原图坐标，然后在原图尺度上做一次全局 NMS。
关键是必须在原图尺度做，不能在子图尺度做——重复是来自不同子图的，子图内部的 NMS 看不到对方。

**Q5 · 训练也要在切图上训吗？**

`原理`　**必须。这是最容易出错的地方。**

如果训练在全图上、推理在切图上，**训练和推理的分布不一致**——目标的相对尺寸、上下文范围、边缘 padding 全都不同，模型见到的是没见过的分布。

**这和项目二的 letterbox 训推不一致是同一类问题。**

正确做法：**训练时也在切片上训**（SAHI 称之为 Slicing Aided Fine-tuning）。

`口语`　必须，这是最容易出错的地方。如果训练在全图上、推理在切图上，训练和推理的分布就不一致了——目标的相对尺寸、上下文范围、边缘的 padding 全都不一样，模型见到的是没见过的分布。
这跟我在锥桶那个项目遇到的 letterbox 训推不一致是同一类问题。正确做法是训练时也在切片上训。

**Q6 · 有名字吗？**

`原理`　**SAHI（Slicing Aided Hyper Inference）**，Akyon et al., ICIP 2022。

三部分：切片微调（训练也在切片上）+ 切片推理（重叠切片）+ 全图推理融合（切片结果和全图结果一起 NMS，兼顾大小目标）。

`口语`　这套做法有个正式名字叫 SAHI，切片辅助推理，ICIP 2022 的论文，有开源实现。它包含三部分：训练时也在切片上微调、推理时重叠切片、再把切片结果和全图推理的结果一起做 NMS 来兼顾大小目标。在小目标检测竞赛和工业检测里基本是标配。

**Q1 · P2 是什么？**

`原理`　YOLOv8 默认三个检测尺度：

| 层 | Stride | 输入 640 时的网格 | 每个网格覆盖 | 适合目标 |
|---|---|---|---|---|
| P3 | 8 | 80×80 | 8×8 px | 小目标 |
| P4 | 16 | 40×40 | 16×16 px | 中目标 |
| P5 | 32 | 20×20 | 32×32 px | 大目标 |

**加入 P2（stride 4）**：160×160 网格，每格覆盖 4×4 px。

**为什么必要**：

```
切图后目标约 7.5 px
在 P3（stride 8）：7.5/8 < 1 个网格 → 只有 1 个正样本点，定位精度只有 8px
在 P2（stride 4）：7.5/4 ≈ 2 个网格 → 定位精度 4px，正样本更充分
```

`口语`　YOLOv8 默认有三个检测尺度，stride 分别是 8、16、32。P2 就是 stride 为 4 的那一层。加它的原因是切图之后目标大概七点五个像素，在 stride 为 8 的 P3 上还不到一个网格，只有一个正样本点，定位精度也只有八个像素；在 stride 为 4 的 P2 上大概两个网格，正样本更充分，定位精度也翻倍。

---

**Q2 · P2 的代价**

`原理`

```
P2 特征图尺寸是 P3 的 4 倍（160² vs 80²）
→ 该层的计算量和显存占用约 4 倍
→ 通常是整个检测头里最贵的一层
```

**所以 P2 头是"明知很贵但必须加"的选择，只在小目标是主要矛盾时才值得。**

> 这也解释了为什么**项目二（车端共网）加不起 P2**——那边有硬时延预算，这边是离线的、节拍宽裕。**同一个技术，在不同约束下的可行性完全不同。**

`口语`　P2 的特征图是 P3 的四倍大，所以那一层的计算量和显存也是四倍，通常是整个检测头里最贵的一层。所以加 P2 是明知很贵但必须加的选择，只有当小目标是主要矛盾的时候才值得。
这也是为什么锥桶那个项目加不起 P2——车端共网有硬时延预算，而焊缝这边是离线的、节拍宽裕。同一个技术在不同约束下可行性完全不一样。

**Q3 · 双线性上采样为什么有用？**

`原理`　YOLOv8 默认用 `nn.Upsample(mode='nearest')`。

**最近邻的问题**：

```
原始 2×2:        最近邻上采样 4×4:
  A  B             A  A  B  B
  C  D             A  A  B  B
                   C  C  D  D
                   C  C  D  D
```

产生**块状阶梯边界**。

**对大目标无所谓**（几十上百像素，几个像素的锯齿可忽略），但**对 7px 的小目标，几个像素的伪影就是它尺寸的一半**。

**双线性插值**产生平滑过渡，特征图上的响应更接近真实的连续分布。

**代价**：略微增加计算量；某些部署框架对 bilinear 上采样的支持不如 nearest 好（**需要确认目标平台支持**）。

`口语`　YOLOv8 默认用最近邻上采样，它会产生块状的阶梯边界。对大目标无所谓，几十上百个像素，几个像素的锯齿可以忽略；但对七个像素的小目标来说，几个像素的伪影就是它尺寸的一半了。双线性插值产生的是平滑过渡，特征图上的响应更接近真实的连续分布。
代价是稍微增加计算量，另外要确认部署平台支持 bilinear 上采样，有些框架对它的支持不如最近邻好。

---

**Q4 · CA 注意力**

`原理`　**CA = Coordinate Attention**（Hou et al., CVPR 2021）

**注意力机制的演进**：

| 机制 | 做什么 | 局限 |
|---|---|---|
| **SE**（Squeeze-Excitation） | 全局平均池化 → 通道加权 | **完全丢失空间位置信息** |
| **CBAM** | 通道注意力 + 空间注意力 | 空间注意力用局部卷积，**缺乏长程依赖** |
| **CA** | **把全局池化拆成 H 和 W 两个方向的一维池化** | — |

**CA 的核心思想**：

```
沿 W 方向池化 → 得到 (C, H, 1)：保留【垂直方向的位置信息】
沿 H 方向池化 → 得到 (C, 1, W)：保留【水平方向的位置信息】
两者拼接 → 共享 1×1 卷积 → 拆分 → 分别生成 H 和 W 方向的注意力权重
```

**这样既捕获了长程依赖（沿一个方向的全局池化），又保留了另一个方向的精确位置。**

**为什么适合本任务**：

1. 焊缝缺陷的**位置有强先验**——缺陷只出现在焊缝环带上，CA 能编码这个空间先验
2. **小目标的位置信息极其宝贵**，SE 那种全局池化会把它抹掉
3. CA **极其轻量**（参数量增加不到 1%）

`口语`　CA 是 Coordinate Attention，CVPR 2021 的。它跟 SE 和 CBAM 的区别在于：SE 是全局平均池化后做通道加权，完全丢了空间位置信息；CBAM 加了空间注意力，但用的是局部卷积，缺乏长程依赖；CA 是把全局池化拆成 H 和 W 两个方向的一维池化，沿宽度方向池化保留了垂直方向的位置，沿高度方向池化保留了水平方向的位置，这样既有长程依赖又保住了位置。
适合我们这个任务是因为缺陷的位置有强先验——只出现在焊缝环带上，CA 能编码这个空间先验；而且小目标的位置信息特别宝贵，SE 那种全局池化会把它抹掉。CA 还特别轻，参数量增加不到百分之一。

---

`口语`　小目标的特征主要在浅层高分辨率的层。P5 输入 640 的时候只有二十乘二十，一个七像素的目标在上面连一个网格都占不到，加注意力没有意义。所以加在 P3 和 P4 这两层。

**Q1 · NWD 公式**

`原理`　> Wang et al., *A Normalized Gaussian Wasserstein Distance for Tiny Object Detection*, 2021

**核心思想：把边界框建模成二维高斯分布，用分布距离代替面积重叠。**

```
边界框 (cx, cy, w, h)  →  高斯分布 N(μ, Σ)
    μ = (cx, cy)
    Σ = diag(w²/4, h²/4)

二阶 Wasserstein 距离：
    W₂²(N_a, N_b) = ‖ [cx_a, cy_a, w_a/2, h_a/2] − [cx_b, cy_b, w_b/2, h_b/2] ‖²₂

归一化成相似度：
    NWD = exp( −√(W₂²) / C )        C 为与数据集相关的常数

损失：
    L_NWD = 1 − NWD
```

`口语`　NWD 的核心思想是把边界框建模成一个二维高斯分布，中心是框的中心，协方差矩阵的对角元是宽和高的平方除以四。然后算两个高斯分布之间的二阶 Wasserstein 距离——展开之后其实就是中心坐标和半宽半高这四个量组成的向量的欧氏距离。再用一个指数函数归一化成零到一之间的相似度，损失就是一减去它。

**Q2 · IoU 为什么对小目标不友好？**（必须用数字）

`原理`　固定框尺寸，让预测框沿一个轴平移 d 像素：

| 平移量 | **6×6 小目标** | 36×36 正常目标 |
|---|---|---|
| 1 px | 0.71 | 0.95 |
| 2 px | 0.50 | 0.89 |
| 3 px | 0.33 | 0.85 |
| **4 px** | **0.20** | **0.80** |
| 6 px | **0（梯度消失）** | 0.71 |

> **同样 4 个像素的偏移**：大目标 IoU 只从 1.0 掉到 0.80；**小目标掉到 0.20，再多 2 px 直接归零**。

**两个后果**：

1. **训练信号陡峭不稳定**——IoU 对小目标位置极度敏感，loss 曲面像悬崖
2. **anchor 匹配困难**——正样本分配依赖 IoU 阈值，小目标很难有 anchor 超过阈值 → **训练中根本没有正样本**

`口语`　可以用数字说。一个六乘六的小框，预测框沿一个方向偏一个像素，IoU 从 1 掉到 0.71；偏四个像素掉到 0.2；偏六个像素直接归零，梯度就消失了。同样的偏移量在三十六乘三十六的框上，偏四个像素 IoU 还有 0.8。
带来两个问题：一是训练信号很陡，loss 曲面像悬崖，不稳定；二是正样本分配依赖 IoU 阈值，小目标很难有 anchor 能超过阈值，等于训练中根本没有正样本，那个真值就白标了。

**Q3 · NWD 好在哪？**

`原理`

| 性质 | 说明 |
|---|---|
| **永远不为零** | 即使两框完全不重叠，NWD 仍有有意义的值和梯度 |
| **对位置偏移平滑** | 指数衰减，不会像 IoU 那样断崖 |
| **尺度归一化** | 不同尺寸的目标有可比的度量 |

`口语`　三个性质。一是永远不为零，即使两个框完全不重叠，NWD 还是有有意义的值和梯度，不会梯度消失。二是对位置偏移的响应是平滑的指数衰减，不会像 IoU 那样断崖。三是做了尺度归一化，不同尺寸的目标有可比的度量。

**Q4 · 为什么是组合？**

`原理`

| 损失 | 强项 | 弱项 |
|---|---|---|
| **DIoU** | 中大目标收敛快；显式惩罚中心点距离 | 小目标失效 |
| **NWD** | 小目标梯度稳定 | 对大目标不如 IoU 系精确 |

**本项目既有 15px 的微小气孔，也有上百像素的长条裂纹**，所以两者都需要。

**DIoU 的定义**（顺带）：

```
DIoU = IoU − ρ²(b, b_gt) / c²
```

`ρ` 是两框中心距离，`c` 是最小外接框对角线。相比 GIoU，DIoU 直接优化中心距离，**收敛更快且不会出现 GIoU 那种"先扩大外接框"的绕路行为**。

`口语`　因为我们的缺陷尺度跨度很大——既有十五个像素的微小气孔，也有上百像素的长条裂纹。DIoU 对中大目标收敛快、能显式惩罚中心距，但小目标上失效；NWD 小目标梯度稳定，但对大目标不如 IoU 系精确。所以组合起来用。
顺带说 DIoU 是在 IoU 基础上减去中心点距离的平方除以最小外接框对角线的平方，比 GIoU 收敛更快，也不会出现 GIoU 那种先扩大外接框的绕路行为。

**Q5 · 权重怎么定？**

2. **按目标尺寸动态调整**——小目标偏向 NWD，大目标偏向 DIoU（NWD 原论文的建议）

⚠️ **待核实**：你们用的是哪种、系数多少。

分配环节的收益其实更大——小目标的核心问题是匹配不到正样本，换 loss 只改善了已匹配样本的优化，换分配度量才能让更多小目标有正样本。我们具体有没有改分配这块我回去确认一下。

**Q2 · 为什么用分割不用霍夫圆？**

`原理`　传统做法是霍夫圆检测定位焊缝环带。它的问题：

|---|---|

`口语`　传统做法是霍夫圆检测，但它有几个问题：焊缝环带不是完美的圆，焊接变形、余高不均，边界不规则；霍夫圆的参数很敏感，半径范围和阈值要针对不同工件调；对光照也敏感，过曝欠曝区域的边缘检测不稳定；而且遇到缺管、堵管、异形孔就没法处理。

**Q3 · 为什么填灰不填黑？**（细节题，答上加分）

`原理`　三个理由：

1. **纯黑（0）会在边界产生强梯度**，网络可能把这个人造边界当作特征学进去
2. **中性灰接近图像整体均值**，对卷积响应的扰动最小
3. **与后续的 letterbox padding 值保持一致**（YOLO 系常用 114 灰）——训练和推理链路上的填充值统一，避免引入新的分布差异

`口语`　三个理由。一是纯黑会在掩膜边界产生强梯度，网络可能把这个人造边界当成特征学进去。二是中性灰接近图像整体的均值，对卷积响应的扰动最小。三是要跟后面 letterbox 的 padding 值保持一致，YOLO 系一般用 114 那个灰值，这样整条链路上的填充值是统一的，不会引入新的分布差异。

**Q1 · Focal Loss 与动机**

`原理`

> Lin et al., *Focal Loss for Dense Object Detection*, ICCV 2017（RetinaNet）

```
FL(p_t) = −α_t · (1 − p_t)^γ · log(p_t)

p_t = p        若 y = 1（正样本）
p_t = 1 − p    若 y = 0（负样本）
γ = 2, α = 0.25（论文推荐）
```

**设计意图**：`(1−p_t)^γ` 把已经分对的、置信度高的样本权重压低，让模型专注难样本。

**我们的动机**：样本失衡 1:7，教科书答案就是上 Focal Loss。

`口语`　Focal Loss 是 RetinaNet 那篇提出来的，核心是在交叉熵前面乘一个调制因子，一减去预测置信度的伽马次方。设计意图是把已经分对的、置信度高的样本权重压低，让模型专注在难样本上。
我们的动机很直接——样本失衡是一比七，按教科书的思路就该上 Focal Loss。

**Q2 · 失效的现象**

`原理`　加上 Focal Loss 之后：

- **硬性误检**（模型高置信度报出的碳化物、焊渣）**几乎改不动**
- 训练过程中 loss 下降很慢，指标基本不动
- 与 BCE 基线相比没有明显改善，甚至更差

`口语`　加上之后现象是硬性的误检——就是模型很确信那块焊渣是缺陷的那种——几乎改不动。训练过程中 loss 下降很慢，指标基本不动，跟 BCE 基线比没有明显改善，甚至更差。

**Q3 · 按公式推，硬 FP 权重不是很高吗？**（**最关键的反问，必须主动讲清楚**）

`原理`　**这个矛盾必须自己先说出来，否则被抓住会很尴尬。**

**先承认理论**：

```
一个硬 FP：负样本（y=0），模型预测 p = 0.95
→ p_t = 1 − p = 0.05
→ (1 − p_t)^γ = (0.95)² = 0.9025   ← 权重接近 1，几乎没被压低
```

**所以按公式，Focal Loss 恰恰应该放大硬 FP，理论上应该帮上忙。**

**真正的原因是整体梯度范数塌缩**：

关键前提是**我们用的是已经预训练好、置信度普遍很高的模型**。在这样的模型上继续微调时，绝大多数样本的 `p_t` 都很高。

**定量演示**（假设 99% 样本 `p_t=0.95`，1% 是硬 FP `p_t=0.05`）：

```
BCE 下：
  总权重 = 0.99×1 + 0.01×1 = 1.0

Focal Loss（γ=2）下：
  易分样本 0.99 × (1−0.95)² = 0.99 × 0.0025 = 0.002475
  硬 FP    0.01 × (1−0.05)² = 0.01 × 0.9025 = 0.009025
  总权重 = 0.0115

→ 整体梯度范数降到 BCE 的 1.15%，约 1/87
```

**结论**：

> **不是 Focal Loss 单独压低了硬 FP，而是它把整体信号压塌了。**
> 硬 FP 的**相对占比确实上升了**（从 1% 升到总梯度的 78%），但**绝对更新量微乎其微**——在学习率不变的情况下，等效学习率掉了近两个数量级，训练几乎停滞。

`口语`　这个问题问得很好，我先承认按公式推确实是反过来的。一个硬 FP 是负样本，模型预测置信度 0.95，那 p_t 是 0.05，调制因子是 0.95 的平方等于 0.9，权重接近 1，几乎没被压低。所以理论上 Focal Loss 应该放大硬 FP 才对。
真正的问题在于**整体梯度范数塌缩**。关键前提是我们用的是已经预训练好、置信度普遍很高的模型，绝大多数样本的 p_t 都在 0.9 以上。举个数：假设百分之九十九的样本 p_t 是 0.95，调制因子是 0.0025；百分之一是硬 FP，调制因子 0.9。加权算下来总权重是 0.0115，而 BCE 是 1.0——**整体梯度范数降到百分之一点几，大概 1/87**。
所以不是 Focal Loss 单独压低了硬 FP，是它把整体信号压塌了。硬 FP 的相对占比确实上去了，从百分之一升到总梯度的百分之七十八，但绝对更新量微乎其微。学习率不变的情况下，等效学习率掉了将近两个数量级，训练基本不动。

**Q4 · 定制 BCE 怎么做的？**

`原理`

```python
def custom_bce(pred_logits, targets, hard_fp_mask, fp_weight=3.0):
    loss = F.binary_cross_entropy_with_logits(
        pred_logits, targets, reduction='none'
    )
    weight = torch.ones_like(loss)
    weight[hard_fp_mask] = fp_weight    # 只对【负样本 且 高置信】加权
    return (loss * weight).mean()
```

**「硬 FP」的判定**：`targets == 0`（负样本）**且** `sigmoid(pred_logits) > 阈值`（模型置信度高）。

**加权系数**通过实验确定——太小不起作用，太大会让模型过度保守、掉召回。

⚠️ **待核实**：实际的阈值和加权系数。

`口语`　实现上很简单：先算正常的 BCE，reduction 设成 none 拿到每个位置的 loss，然后构造一个权重张量，对"负样本而且预测置信度高"这些位置乘一个大于 1 的系数，其余保持 1，最后加权求平均。
硬 FP 的判定就是标签为负、但模型 sigmoid 输出超过某个阈值。加权系数是实验定的，太小不起作用，太大模型会过度保守、掉召回。

**Q5 · 和 Focal Loss 的本质区别？**

`原理`

| | Focal Loss | 定制 BCE |
|---|---|---|
| 调制方式 | **全局函数** `(1−p_t)^γ`，对所有样本生效 | **定向加权**，只针对硬 FP |
| 副作用 | 整体梯度塌缩 | 其余样本梯度不受影响 |
| 可控性 | 只有 γ 一个旋钮 | 可指定"什么算硬 FP"、加多少权 |
| 与框架兼容 | 与 TaskAlignedAssigner 冲突 | 只改 loss 的一个分支 |

> **一句话总结（面试直接用）**：
> **Focal Loss 是"让模型少关注简单样本"，是减法；定制 BCE 是"让模型多关注这一类特定错误"，是加法。在一个已经训得不错的模型上，加法比减法安全得多。**

`口语`　本质区别是 Focal Loss 用的是一个全局的调制函数，对所有样本一视同仁地按置信度打折，副作用是整体梯度塌缩；定制 BCE 是定向加权，只对硬 FP 这一类加权，其余样本的梯度完全不受影响。可控性上也不一样，Focal Loss 只有伽马一个旋钮，定制 BCE 可以指定什么算硬 FP、加多少权。
一句话概括：**Focal Loss 是减法，让模型少关注简单样本；定制 BCE 是加法，让模型多关注这一类特定错误。在一个已经训得不错的模型上，加法比减法安全得多。**

**Q6 · 难负样本怎么挖的？**

`原理`　**不是随机加负样本，而是精准挖掘模型确实会误检的那些。**

```
① 用当前模型跑全量数据推理
② 挑出【高置信度但实际是背景】的检出（硬 FP）
③ 按误检成因归类：
     碳化物 / 焊渣 / 孔内壁纹理 / 倒角 / 高光斑点 / 相邻孔边缘
④ 每一类构建专门的难负样本集
⑤ 回灌训练
⑥ 重新评测，追踪每一类的收敛情况
```

**归类的价值**：能定量追踪每一类误检的收敛，而不是只看一个总数。如果只有总数，你不知道是哪一类在恶化。

> **这和项目一的凭空误检治理、项目二的路面截断治理、项目三的误检 checker 分类，是完全同一套方法论。**

`口语`　不是随机加负样本，是精准挖模型确实会误检的那些。做法是用当前模型跑全量推理，挑出高置信度但实际是背景的检出，然后按成因归类——碳化物、焊渣、孔内壁纹理、倒角、高光斑点、相邻孔边缘，每一类建一个专门的难负样本集，回灌训练之后再评测，追踪每一类的收敛情况。
归类的价值是能定量追踪每一类的收敛，如果只有一个总数，你不知道是哪一类在恶化。这套方法论我在 BEV 那边治理凭空误检、在锥桶那边治理路面截断误检，用的是完全一样的循环。

**Q7 · 分阶段训练为什么有效？**

`原理`

```
阶段一：全量数据训练，建立基础检出能力（保 Recall）
阶段二：加入难负样本，降低学习率微调（提 Precision）
```

**为什么不一开始就混在一起**：

1. 一开始就大量负样本 → 模型倾向于"什么都不报"，**Recall 起不来**
2. 先建立检出能力，再压误检，**两个目标不互相干扰**
3. 阶段二用小学习率，**避免破坏已学到的检出能力**

`口语`　分两个阶段：第一阶段用全量数据训，先把基础的检出能力建起来，保召回；第二阶段加入难负样本，降低学习率微调，提精确率。
不一开始就混在一起有三个原因：一是一开始就大量负样本，模型会倾向于什么都不报，召回起不来；二是先建检出能力再压误检，两个目标不互相干扰；三是第二阶段用小学习率，避免破坏已经学到的检出能力。

**Q8 · 类内 NMS 解决什么？**

`原理`　**问题**：同一个缺陷区域，模型可能同时报出多个不同类别的框（气孔 + 焊渣 + 未熔合）。

**标准 NMS 是类内的**（同类之间才抑制），跨类不抑制。这在通用检测里是对的（一个人骑车，人和车的框都该保留），但在本任务里会造成**同一物理缺陷被重复计数**——一个缺陷报三个框，Precision 直接被拉低。

**处理方式**：

| 选项 | 做法 |
|---|---|
| A | 类内 NMS + 跨类去重（同位置只保留最高置信度的类别） |
| B | 先做类别无关的 NMS，再判类别 |
| C | 定义混淆类等价集，组内做 NMS |

> **与项目三的"跨类等价集"是同一个思路**——类别边界模糊时，不应该按严格类别处理。

`口语`　问题是同一个缺陷区域，模型可能同时报出气孔、焊渣、未熔合几个不同类别的框。标准 NMS 是类内的，跨类不抑制——这在通用检测里是对的，一个人骑车，人和车的框都该保留；但在我们这儿会造成同一个物理缺陷被重复计数，一个缺陷报三个框，精确率直接被拉低。
处理方式有几种：类内 NMS 之后再做跨类去重，同一位置只保留置信度最高的类别；或者先做类别无关的 NMS 再判类别；或者定义混淆类等价集，组内做 NMS。
这个思路跟我在评测那个项目里做的跨类等价集是一样的——类别边界模糊的时候，不该按严格类别处理。

**Q9 · 有没有别的解释？比如超参没调好？**（诚实回答加分）

`原理`　**这是一个合理的质疑，应该正面接住。**

确实还有三个可能的机制，它们和梯度塌缩是叠加的：

1. **超参需要重新整定**——Focal Loss 引入 α、γ 并**改变了 loss 的量纲**（数值大幅变小），与框回归、DFL 等分量的相对权重全乱，学习率和 warmup 都要重调。RetinaNet 的 `α=0.25, γ=2` 是在 COCO 上从头训练得到的，**微调场景下没有理由继续适用**
2. **与 YOLOv8 已有机制冲突**——TaskAlignedAssigner 本身就是一种难例聚焦，叠加是重复的（见 Q10）
3. **放大错标样本**——Focal Loss 放大 hard example，而 hard example 里混着错标。焊缝数据集的边界样本（这个氧化色算不算缺陷）本身就有争议

**诚实的说法**：我们没有做穷尽的超参搜索。可能更充分地调参能让 Focal Loss 工作，但**定制 BCE 更简单、更可控、且不与框架已有机制冲突**，所以选了后者。

`口语`　这个质疑是合理的，我不会说 Focal Loss 一定不行。确实还有几个机制是叠加的：一是超参要重新整定，Focal Loss 改变了 loss 的量纲，跟框回归、DFL 那些分量的相对权重全乱了，学习率和 warmup 都要重调，而 RetinaNet 那套参数是在 COCO 上从头训练得到的，微调场景没有理由继续适用。二是它跟 YOLOv8 的 TaskAlignedAssigner 冲突，那个本身就是一种难例聚焦，叠加是重复的。三是它会放大错标样本。
坦率说我们没有做穷尽的超参搜索，可能调得更充分能让它工作。但定制 BCE 更简单、更可控、而且不跟框架已有机制冲突，所以选了后者。

**Q1 · monkey-patch 是什么？**

`原理`　**运行时动态替换第三方库的函数或方法，而不修改其源代码。**

Python 的动态特性使这成为可能——模块、类、函数都是对象，可以在运行时被重新赋值。

`口语`　monkey-patch 就是在运行时动态替换第三方库里的函数或者方法，不去改它的源代码。Python 的动态特性让这件事变得可能——模块、类、函数都是对象，可以在运行时重新赋值。

**Q3 · 怎么实现的？**

`原理`

```python
# my_patches.py —— 独立文件，不碰框架源码
from ultralytics.utils import loss as yolo_loss

_original = yolo_loss.v8DetectionLoss.__call__

def patched_loss(self, preds, batch):
    result = _original(self, preds, batch)
    # 在这里注入自定义的硬 FP 加权逻辑
    ...
    return result

def apply():
    yolo_loss.v8DetectionLoss.__call__ = patched_loss

def revert():
    yolo_loss.v8DetectionLoss.__call__ = _original
```

**优点**：

- 框架保持原版，可随时升级
- 改动集中在一个文件，**一眼看清动了什么**
- 想跑基线只要不调用 `apply()`
- 对照实验干净，可以 `revert()`

`口语`　做法是单独写一个 patch 文件，先把原始的方法存下来，定义一个新的方法，在里面注入自定义的硬 FP 加权逻辑，然后提供 apply 和 revert 两个函数在运行时替换和还原。
好处是框架保持原版可以随时升级；改动集中在一个文件里，一眼能看清动了什么；想跑基线就不调 apply；对照实验很干净。

**Q4 · 有什么风险？**（不说风险显得没想清楚）

`原理`

| 风险 | 说明 |
|---|---|

`口语`　主要几个。一是框架升级之后 patch 可能失效，被替换的函数签名变了会静默出错或者抛异常。二是它隐式依赖框架的内部实现，那不在框架的兼容性承诺范围内。三是调试困难，堆栈里看到的是框架的代码，实际执行的是我的 patch。四是多个 patch 改同一个方法的话顺序敏感。

**Q5 · 有没有更好的做法？**（开放题）

`原理`　按侵入性从低到高：

| 方案 | 说明 | 适用 |
|---|---|---|
| **框架提供的扩展点** | 如果框架有注册自定义 loss 的接口，优先用 | 最好，但 Ultralytics 当时不完善 |
| **继承 + 覆写** | 继承 `v8DetectionLoss` 写子类，在 trainer 里替换 | 比 monkey-patch 干净 |

**诚实的说法**：继承 + 覆写通常比 monkey-patch 更干净。当时选 monkey-patch 是因为要改的位置在框架内部的调用链上，直接继承不好切入；如果重做，会先看框架有没有提供扩展点。

**Q1 · IAT 是什么？**

`原理`

> **IAT = Illumination Adaptive Transformer**
> Cui et al., BMVC 2022，*"You Only Need 90K Parameters to Adapt Light: A Light Weight Transformer for Image Enhancement and Exposure Correction"*

| 特点 | 说明 |
|---|---|
| **极致轻量** | **约 90K 参数**，比大多数增强网络小 1–2 个数量级 |
| **双分支设计** | 局部分支（逐像素调整）+ 全局分支（ISP 参数：色温、Gamma） |
| **同时处理过曝与欠曝** | 正是本任务需要的 |
| 速度快 | 可实时，适合作为前处理插入流水线 |

`口语`　IAT 是 Illumination Adaptive Transformer，BMVC 2022 的一篇，标题就叫"你只需要 9 万参数就能适应光照"。它的特点是极致轻量，大概九万个参数，比大多数增强网络小一两个数量级；结构是双分支的，一个局部分支做逐像素调整，一个全局分支预测 ISP 参数比如色温和 Gamma；而且它能同时处理过曝和欠曝，这正是我们需要的。

**Q2 · 为什么选 IAT 不用 CLAHE？**

`原理`

| 方法 | 局限 |
|---|---|
| 全局直方图均衡 | 加剧高光饱和，放大暗区噪声 |
| **CLAHE** | 分块自适应，比全局好；但**块边界有伪影、参数需针对不同工件手调、不是学习出来的** |
| Gamma | 单调映射，无法同时处理两端 |
| **HDR 多曝光融合** | 效果最好，但**采图时间 ×3，节拍不允许** |
| **IAT** | 学习式自适应，同时处理两端，90K 参数几乎不占预算 |

**三条选择理由**：

1. **过曝欠曝同时存在**——IAT 的设计目标恰好就是这个
2. **90K 参数几乎不占用推理预算**，可以直接串在检测前面
3. **学习式的自适应，不需要针对不同工件手调参数**（对比 CLAHE）

`口语`　CLAHE 是分块的自适应均衡，比全局直方图均衡好，但有三个问题：块边界会有伪影；参数要针对不同工件手调；而且它是固定规则，不是学出来的。
选 IAT 有三个理由：一是它的设计目标就是同时处理过曝和欠曝，正好对上我们的复合光照；二是它只有九万参数，几乎不占推理预算，可以直接串在检测前面；三是学习式的自适应，不用针对不同工件手调参数。
HDR 多曝光融合效果最好，但采图时间要翻三倍，产线节拍不允许。

**Q3 · 为什么 P/R 能双升？**（这个问题很关键）

`原理`　**大多数优化都是在 P 和 R 之间做权衡，双升说明解决的是信息层面的问题而非决策层面的问题。**

```
Recall ↑：暗区被拉亮 → 原本淹没在噪声里的缺陷显现出来 → 检出
Precision ↑：高光被压回 → 反光斑点不再呈现"缺陷般"的高对比特征 → 不再误报
```

**一般规律**：

| 优化类型 | 效果 |
|---|---|
| 调阈值、调 loss 权重、加负样本 | **P/R 权衡**（决策层面） |
| **改善输入质量、增加信息** | **P/R 双升**（信息层面） |

> **这个区分很值钱**——它说明你理解"什么样的改动才可能双升"。

`口语`　大多数优化都是在精确率和召回之间做权衡，能双升说明解决的是信息层面的问题，不是决策层面的。
具体机制是两个不同的方向：召回上升是因为暗区被拉亮，原本淹没在噪声里的缺陷显现出来了；精确率上升是因为高光被压回去，反光斑点不再呈现那种"缺陷般"的高对比特征，就不误报了。
一般规律是——调阈值、调 loss 权重、加负样本这些是决策层面的，必然是权衡；改善输入质量、增加信息量的，才可能双升。

**Q4 · IAT 要训练吗？用什么数据？**

`原理`　IAT 是一个学习式的模型，有两种用法：

1. **用预训练权重直接推理**——作者在公开的曝光校正数据集上训好，可以直接用
2. **在本任务数据上微调**——用配对数据（过曝/欠曝图 ↔ 正常曝光图）微调，效果更好

**本任务的困难**：**没有"正常曝光"的配对真值**——你不可能同时拍到同一个孔的过曝版和正常版（除非做 HDR 多曝光，而那正是我们要避免的）。

**可能的解法**：用预训练权重；或者用少量多曝光样本构造配对数据做微调。

⚠️ **待核实**：你们是直接用预训练权重还是微调过。

`口语`　IAT 是学习式的，有两种用法：直接用作者的预训练权重推理，或者在自己的数据上微调。
微调的困难在于我们没有配对的真值——不可能同时拍到同一个孔的过曝版和正常曝光版，除非做 HDR 多曝光，而那正是我们要避免的。可能的做法是用少量多曝光样本构造配对数据来微调。具体我们是直接用预训练权重还是微调过，我回去确认一下。

**Q6 · 会不会把真实缺陷也补偿掉？**

`原理`　**理论上有这个风险，实际影响取决于 IAT 的作用尺度。**

- IAT 做的是**局部亮度的自适应均衡**，作用尺度较大（区域级）
- 缺陷是**小尺度的高频结构**（15px 量级）

**尺度差异保护了缺陷**——IAT 拉平的是大范围的亮度不均，不会抹掉小尺度的局部对比。

**但仍有边界情况**：如果缺陷恰好占据一大片区域（大面积密集气孔），可能被当作"暗区"整体拉亮，对比度反而下降。

**验证方法**：对比 IAT 前后在缺陷区域的局部对比度（如局部标准差），确认没有下降。

`口语`　理论上有风险，实际影响取决于作用尺度。IAT 做的是局部亮度的自适应均衡，作用尺度是区域级的；而缺陷是小尺度的高频结构，十几个像素。这个尺度差异保护了缺陷——IAT 拉平的是大范围的亮度不均，不会抹掉小尺度的局部对比。
但边界情况还是有的，如果缺陷恰好占据一大片区域，比如大面积密集气孔，可能被当成暗区整体拉亮，对比度反而下降。验证方法是对比 IAT 前后缺陷区域的局部对比度，比如局部标准差，确认没有下降。

**Q7 · 前处理增强 vs 端到端训练？**（开放题）

`原理`　两条路线的对比：

| | 前处理增强（本项目） | 端到端（把增强网络和检测网络一起训） |
|---|---|---|
| 优化目标 | 增强的是"视觉质量"，不一定对检测最优 | **直接对检测目标优化** |
| 可解释性 | **好**（可以看增强后的图） | 差 |
| 模块化 | **好**（可以单独替换、单独验证） | 差 |
| 训练复杂度 | 低 | 高（需要联合训练，梯度传导） |
| 效果 | 通常略差 | 通常更好 |

**本项目选前处理的理由**：可解释性和模块化在工业交付中很重要——**客户和验收方需要能看到"增强后的图长什么样"**；而且分模块便于定位问题。

`口语`　两条路线各有取舍。端到端把增强网络和检测网络一起训，直接对检测目标优化，效果通常更好；但可解释性差，也不好单独替换和验证。
我们选前处理主要是因为可解释性和模块化在工业交付里很重要——客户和验收方需要能看到增强之后的图长什么样，而且分模块便于定位问题，是增强的问题还是检测的问题一目了然。如果纯追求指标，端到端可能更好。

**Q1 · 为什么关掉？**

`原理`　**因为采图条件是固定的**：

```
机械臂固定工作距离
正对拍摄
同一型号相机镜头
→ 孔径在图像上的像素尺度【几乎是常量】
→ 缺陷的像素尺度分布【范围很窄】
```

**随机缩放在教模型一个不存在的变化**，等于稀释了有限的训练样本，让模型去覆盖推理时根本不会遇到的尺度。

`口语`　因为我们的采图条件是固定的——机械臂固定工作距离、正对拍摄、同一型号的相机镜头，所以孔径在图像上的像素尺度几乎是常量，缺陷的像素尺度分布范围很窄。
随机缩放是在教模型一个不存在的变化，等于把有限的训练样本稀释掉，让模型去覆盖推理时根本不会遇到的尺度。

**Q2 · 尺度鲁棒性怎么办？**

`原理`　**在这个场景下不需要尺度鲁棒性——需要的是尺度专精。**

模型只需要在一个很窄的尺度范围内做到最好。放弃鲁棒性换取该范围内的精度，是正确的取舍。

**但要有边界保护**：

- 如果工作距离因机械误差有小幅波动，可以保留**很小幅度**的缩放（如 ±5%）覆盖真实波动
- 如果未来要换镜头或改工作距离，需要重新采数据训练——**这是这个决策的代价，要说出来**

`口语`　这个场景不需要尺度鲁棒性，需要的是尺度专精——模型只要在一个很窄的尺度范围内做到最好就行，放弃鲁棒性换取这个范围内的精度是正确的取舍。
但要有边界保护：如果工作距离因为机械误差有小幅波动，可以保留很小幅度的缩放，比如正负百分之五，覆盖真实波动。代价是如果未来换镜头或者改工作距离，就得重新采数据训练——这个决策的代价要说清楚。

**Q3 · 怎么验证的？**

**更严谨的验证**：统计训练集和测试集中缺陷的**实际像素尺度分布**，确认它确实很窄。如果分布很宽，说明"固定工作距离"这个前提不成立，关掉就是错的。

`口语`　做对比实验，开和关随机缩放，其余配置完全一样，对比指标。更严谨一点的做法是统计训练集和测试集里缺陷的实际像素尺度分布，确认它确实很窄——如果分布很宽，说明"固定工作距离"这个前提不成立，关掉就是错的。

自检方法很简单——问一句"这个增强产生的图像，在真实产线上有可能出现吗"。

**Q5 · 为什么召回高于精确率？**

`口语`　这是刻意选的工作点，因为代价不对称——漏检一个裂纹可能导致焊缝泄漏、海水串入滑油、主机烧瓦，是重大事故；误报一个缺陷只是多复检一个孔，成本可控。所以工作点偏向高召回。

**Q6 · 只高出验收线 1.8 个点，够吗？**（好问题）

`原理`　**这正是"精度冗余"的价值所在。**

```
验收标准        95%
模型精度        96.8%
→ 冗余          1.8 个百分点

INT8 量化通常掉 0.5–2%
→ 量化后仍在验收线附近，风险可控但不宽裕
```

**诚实的评估**：这个余量**不算宽裕**。更稳妥的做法是把模型精度做到 97–98%，或者对量化敏感层回退 FP16 来减少损失。

> **主动说出"余量不宽裕"这个判断，比声称"完全没问题"更可信。**

`口语`　这确实是个值得说的点。验收标准是 95%，模型做到 96.8%，冗余是 1.8 个百分点。而 INT8 量化通常会掉 0.5 到 2 个点，所以量化之后仍然在验收线附近，风险可控但不宽裕。
更稳妥的做法是把模型精度再往上推到 97、98，或者对量化敏感的层回退到 FP16 来减少损失。我们实际做的是后者。这也是为什么我说量产项目的模型精度不能刚好卡在验收线上，必须留部署损耗的余量。

**标准做法**：量化后必须在同一测试集上重新评测，验收用的是**量化后的模型指标**，不是 FP32 的指标。

`口语`　量化之后必须在同一个测试集上重新评测，验收用的是量化后模型的指标，不是 FP32 的。具体量化后掉了多少我回去确认一下。做法上我们对量化敏感的层——检测头输出层和上采样层——是回退到 FP16 的，就是为了控制这个损失。

**Q1 · 部署链路**

`原理`

```
PyTorch(.pt)
  ↓ torch.onnx.export
ONNX
  ↓ 算子检查 / 图优化 / 算子融合
TensorRT Builder
  ↓ INT8 校准（PTQ）
TensorRT Engine（.engine）
  ↓
工控机（IPC）+ 独立显卡 推理
```

`口语`　PyTorch 权重导出成 ONNX，检查算子兼容性，然后用 TensorRT 做图优化和算子融合，再做 INT8 校准生成 engine，最后部署到工控机上，工控机配了独立显卡。

**Q2 · INT8 量化**

`原理`

| 项 | 说明 |
|---|---|
| **方式** | **PTQ**（训练后量化），用几百张校准图统计激活值的动态范围，确定每层的量化 scale |
| **原理** | FP32 → INT8 是把浮点范围映射到 [-128, 127]，需要知道每层激活的实际分布范围 |
| **收益** | 相比 FP32 约 **3–4× 加速**，显存降至 1/4 |
| **精度损失** | 通常 mAP 掉 0.5–2%，需实测 |

**PTQ vs QAT**：

| | PTQ | QAT |
|---|---|---|
| 做法 | 训练后用校准集统计 | 训练时插入伪量化节点 |
| 精度损失 | 0.5–2% | <0.5% |
| 成本 | 低（几分钟） | 高（要重训） |

`口语`　用的是 PTQ，训练后量化。原理是把 FP32 的浮点范围映射到 INT8 的负一百二十八到一百二十七，关键是要知道每一层激活值的实际分布范围，所以要用几百张校准图统计一下，确定每层的量化 scale。收益是相比 FP32 大概三到四倍加速，显存降到四分之一，代价是精度通常掉零点五到两个点。
另一种是 QAT，训练时插入伪量化节点，精度损失能控制在半个点以内，但要重训，成本高。我们用的 PTQ。

---

**Q3 · 校准集怎么选？**（细节题，答上加分）

`原理`　**校准集必须覆盖真实推理时的输入分布**，否则统计出的量化 scale 不准。

**本任务的关键**：

```
必须覆盖：过曝图 / 欠曝图 / 各类缺陷 / 纯背景 / 不同工件
数量：几百张通常够（PTQ 不需要很多）
不能只用"好看"的图 —— 那样统计出的动态范围偏窄，
                      推理时遇到极端值会被裁剪，精度崩
```

`口语`　校准集必须覆盖真实推理时的输入分布，不然统计出来的量化 scale 就不准。我们这个场景要特别注意覆盖过曝图、欠曝图、各类缺陷、纯背景，还有不同工件。数量上几百张通常够，PTQ 不需要很多。
最容易犯的错是只用"好看"的图做校准，那样统计出的动态范围偏窄，推理时遇到极端值会被裁剪，精度就崩了。

**Q4 · 哪些层敏感？**

`原理`

| 敏感层 | 为什么 |
|---|---|
| **检测头输出层** | 直接决定置信度和框坐标，量化误差直接体现为精度损失 |
| **上采样层** | 插值本身对数值精度敏感 |
| **激活值动态范围大的层** | 量化到 256 个级别后分辨率不足 |
| 首尾层 | 通用经验，首层接收原始输入、尾层输出结果 |

**处理方式**：**混合精度**——对敏感层回退 FP16，其余用 INT8。

**怎么找敏感层**：逐层量化 + 对比输出误差（TensorRT 有相关工具），或者按经验先试首尾层和检测头。

`口语`　主要是检测头的输出层和上采样层。检测头直接决定置信度和框坐标，量化误差直接就是精度损失；上采样的插值本身对数值精度敏感。另外激活值动态范围特别大的层也敏感，量化到 256 个级别之后分辨率不够。
处理方式是混合精度，对敏感层回退到 FP16，其余用 INT8。找敏感层可以逐层量化对比输出误差，TensorRT 有相关工具，也可以按经验先试首尾层和检测头。

**Q5 · 多线程 Pipeline**

`原理`

```
时间轴 →
孔 N   : [机械臂移动][采图]
孔 N-1 :              [ROI][IAT][切图][检测][后处理]
孔 N-2 :                                    [写库][报告]

三级流水线并行
总节拍 = max(各级耗时) 而非 sum
```

**关键设计**：

- 采图线程、推理线程、写库线程解耦，用队列传数据
- 队列要设上限（背压），防止某一级慢了导致内存爆
- 推理线程可以进一步做 batch（多张子图一起推）

`口语`　设计成三级流水线：采图线程、推理线程、写库线程解耦，用队列传数据。孔 N 在采图的时候，孔 N-1 在做推理，孔 N-2 在写库，三级并行。这样总节拍等于最慢那一级的耗时，而不是各级之和。
细节上队列要设上限做背压，防止某一级慢了导致内存爆掉。推理线程还可以进一步做 batch，把一个孔的十张子图一起推。

**Q6 · 视觉推理是瓶颈吗？**（**这条最能体现系统思维**）

`原理`　**不是。瓶颈是机械臂移动。**

```
单孔时间预算 = 2.5 小时 / 3000 孔 ≈ 3.0 秒/孔

机械臂移动到位     1.5–2.0 s   (50–67%)  ← 瓶颈
相机曝光 + 传输     0.1–0.3 s   (3–10%)
视觉全链路          ~0.15 s     (5%)
  ├ ROI 分割        ~10 ms
  ├ IAT             ~5 ms
  ├ 切图            ~5 ms
  ├ 检测 ×10（INT8）~50–100 ms
  ├ 后处理 NMS      ~10 ms
  └ 写库            ~10 ms
其余余量            ~0.5 s
```

> **视觉部分只占 5%。如果只盯着模型加速（再压 20ms），对总节拍几乎没有影响。**
> **所以优化的关键是并行化和机械运动优化，不是单点模型加速。**

**与项目一的对照**：项目一里 BEVPoolv2 省的 14ms 在 40–70ms 的预算里是决定性的；这里省 20ms 毫无意义。**同一个技术动作，在不同系统里的价值完全不同——这取决于它在瓶颈路径上还是不在。**

`口语`　不是。按两个半小时三千个孔算，单孔预算是三秒。机械臂移动到位要一点五到两秒，占了一半以上，这是物理运动压不下去的；采图和传输零点一到零点三秒；整个视觉链路加起来大概零点一五秒，只占百分之五。
所以如果只盯着模型加速，再压二十毫秒，对总节拍几乎没有影响。优化的关键是并行化和机械运动优化。
这跟 BEV 那边正好形成对照——那边 BEVPoolv2 省下的十几毫秒在四十到七十毫秒的预算里是决定性的；在这里省二十毫秒毫无意义。同一个技术动作在不同系统里的价值完全不同，取决于它在不在瓶颈路径上。

| 方法论 | 本项目形态 | 在 BEV 项目里的对应 |
|---|---|---|
| **误检归类 → 难负样本 → 回灌验证** | 碳化物/焊渣/孔内壁分类挖掘 | 项目一凭空误检、项目二路面截断、项目三误检 checker 分类 |
| **数据增强必须匹配真实分布** | 关随机缩放（固定工作距离） | 项目二关 mosaic（位置先验） |
| **训推预处理必须逐位对齐** | IAT 前处理训推一致 | 项目二 letterbox 训推不一致 |
| **小目标需要专门的结构与损失** | P2 头 + NWD | 项目一中远距小目标、项目二远距锥桶 |
| **样本失衡不能靠单一手段** | 采样 + 损失 + 合成三条并行 | 项目一 CBGS + 类别加权 |
| **Focal Loss 的适用前提** | 高置信度预训练模型上失效 | 项目一同样弃用 Focal Loss |
| **系统级瓶颈分析** | 视觉只占 5%，瓶颈在机械运动 | 项目一时延预算、BEVPoolv2 换 DepthNet |
| **精度要留部署余量** | 96.8% vs 验收线 95% | 量产模型的量化预算 |
| **评测口径要对齐下游需求** | 工业检测 IoU 可以很低 | 项目二 IoU 取 0.4 |

**一句话总结（面自动驾驶岗时的收尾）**：

> 这个项目让我知道模型精度只是一部分。前处理、部署、时延预算、现场验收，每一环都可能是瓶颈。这个意识在做量产 BEV 的时候特别有用。
