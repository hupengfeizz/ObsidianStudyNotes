## 2. 业务场景：管板密封焊缝是什么，为什么必须 100% 检

### 2.1 管壳式换热器的结构

船用换热器多为**管壳式（Shell-and-Tube）**结构：

```
        ┌─── 壳程（Shell Side）：海水 ───┐
        │                                │
   ┌────┴────────────────────────────────┴────┐
   │  ▓▓  ┌──────────────────────────┐   ▓▓  │
   │  ▓▓  │  换热管 × 数千根          │   ▓▓  │
   │  管  ├──────────────────────────┤   管  │
   │  板  │  换热管                   │   板  │
   │  ▓▓  ├──────────────────────────┤   ▓▓  │
   │  ▓▓  │  换热管                   │   ▓▓  │
   └───┬──┴──────────────────────────┴───┬───┘
       │                                  │
       └─── 管程（Tube Side）：滑油 ──────┘
```

| 部件 | 说明 |
|---|---|
| **管板（Tubesheet）** | 一块厚钢板，钻满孔，用于固定换热管。本项目中直径约 2m，管孔 3000+，孔径 14mm |
| **换热管（Tube）** | 穿过管板孔的细管，内走一种介质，外走另一种 |
| **管孔连接** | 先**胀接**（液压/机械胀管使管壁贴紧孔壁）→ 再**密封焊**（管端与管板焊接） |
| **密封焊缝** | 管端一圈的**环形焊缝**，是防止两侧介质互串的最后一道屏障 ← **本项目检测对象** |

### 2.2 为什么泄漏是致命的

船用滑油冷却器的典型配置：

```
管程：主机滑油（Lube Oil）
壳程：海水（Sea Water，压力通常高于滑油侧）
```

一旦密封焊缝有微裂纹或未熔合：

```
海水（高压侧）→ 通过焊缝缺陷 → 串入滑油系统
        ↓
滑油被海水乳化，粘度和油膜强度骤降
        ↓
主机曲轴轴瓦失去油膜保护
        ↓
【烧瓦】—— 主机抱轴、停车
        ↓
远洋航行中失去动力 = 重大海事事故
```

**一条 0.1mm 的裂纹，代价是一台主机和一次事故。** 这就是为什么这个场景的验收标准里写着「裂纹类致命缺陷零漏检」——不是 99%，是零。

### 2.3 相关标准规范

| 标准 | 内容 |
|---|---|
| **NB/T 47013.5**（原 JB/T 4730） | 承压设备无损检测 · 渗透检测 |
| **GB/T 151** | 热交换器（管壳式换热器设计制造） |
| **CCS《材料与焊接规范》** | 中国船级社，船用焊接与检验要求 |
| **ASME BPVC Sec. VIII / IX** | 美标压力容器与焊接工艺评定（出口船舶常用） |
| **ISO 5817** | 焊缝质量等级（B/C/D 三级） |

**验收方通常是船级社验船师**，检测记录要可追溯——这解释了为什么系统需要"结果写库"这一环。

### 2.4 密封焊缝的典型缺陷

| 缺陷 | 形态 | 危害等级 | 检测难度 |
|---|---|---|---|
| **裂纹（Crack）** | 细长线状，可能极窄 | **致命，零容忍** | 高（窄、对比度低） |
| **气孔（Porosity）** | 圆形/椭圆暗点，可能成群 | 中（超标才判废） | 中 |
| **未熔合 / 未焊透** | 焊缝与母材间的线状不连续 | 高 | 高 |
| **咬边（Undercut）** | 焊趾处的沟槽 | 中 | 中 |
| **夹渣 / 焊渣残留** | 不规则暗块 | 视尺寸 | **低危害但极易与气孔混淆** |
| **焊瘤 / 余高超标** | 凸起 | 低 | 反光强，误检源 |
| **碳化物 / 氧化色** | 表面变色 | **无危害** | **与缺陷高度相似，主要误检源** |

**关键矛盾**：真正有害的缺陷（裂纹、未熔合）**数量极少**，而无害的干扰物（碳化物、焊渣、氧化色）**大量存在且外观相似**。这就是 §10 要解决的核心问题。

## 3. 原方案（人工渗透检测）与它的瓶颈

### 3.1 渗透检测（PT / Penetrant Testing）流程

```
① 预清洗        去除油污、氧化皮（清洗不净直接导致假象）
② 施加渗透液    红色/荧光渗透液，靠毛细作用渗入表面开口缺陷
③ 停留（渗透）  10–30 分钟 ← 时间瓶颈之一
④ 去除多余渗透液 关键步骤，去多了缺陷显示丢失，去少了背景污染
⑤ 施加显像剂    白色显像粉吸出缺陷内的渗透液，形成放大的红色显示
⑥ 显像停留      7–30 分钟 ← 时间瓶颈之二
⑦ 目视观察      逐孔人工看，3000+ 孔
⑧ 记录与后清洗
```

### 3.2 瓶颈在哪

| 环节 | 问题 |
|---|---|
| **停留时间** | 渗透 + 显像合计 20–60 分钟，是化学过程，压不下去 |
| **逐孔目视** | 3000+ 孔，人眼长时间盯看，**疲劳导致漏检率显著上升** |
| **主观性** | 「这个显示算不算超标」依赖个人经验，不同检验员判断不一致 |
| **可追溯性差** | 纸质记录，没有图像存档，事后无法复查 |
| **化学品** | 渗透液、显像剂、清洗剂，环保与职业健康负担 |
| **总耗时** | **一件约 1 个工作日** |

### 3.3 视觉方案要证明的事

不是"比人快"，而是三件事同时成立：

```
① 检出率 ≥ 95%（验收硬指标）
② 裂纹零漏检
③ 误报率足够低 —— 否则复检的人工成本会吃掉全部收益
```

**第三条最容易被忽略**：如果 3000 个孔里报出 600 个疑似，人工还是要看 600 个，效率提升就没了。**这是为什么这个项目里 Precision 的优化投入不比 Recall 少。**

## 4. 硬件系统与采图方案

### 4.1 两级定位采图

```
第一级：全局定位
  管板整体拍一张全局图
  → 图像处理定位所有管孔中心坐标（霍夫圆检测 / 模板匹配 / 分割）
  → 建立孔位索引表（孔号 ↔ 机械臂坐标）

第二级：逐孔近摄
  机械臂按【蛇形轨迹】遍历所有孔位
  → 每孔正对拍摄，固定工作距离
  → 一孔一张 5472×3648 高分辨率图
```

**为什么必须逐孔近摄，不能一张全局图搞定**：

```
管板直径 2000mm，最小缺陷 ~0.1mm
若一张图覆盖全管板：2000mm / 5472px = 0.37 mm/px
→ 0.1mm 的缺陷【连一个像素都不到】，物理上不可能检出
```

**逐孔近摄的分辨率**（假设单孔视场 ~30mm）：

```
30mm / 5472px ≈ 5.5 μm/px
→ 15×15px 的缺陷对应实际尺寸约 0.08mm × 0.08mm
```

这个数量级才能满足焊缝检测的精度要求。

### 4.2 蛇形轨迹的意义

```
→ → → → → → → →
              ↓
← ← ← ← ← ← ← ←
↓
→ → → → → → → →
```

相比逐行回零，蛇形路径**消除了每行结束后的空回程**，对 3000+ 个孔位，累计节省的机械运动时间非常可观。

**更重要的是采图一致性**：

| 一致性维度 | 意义 |
|---|---|
| **正对拍摄** | 避免透视畸变，焊缝环带在图上是正圆而非椭圆 |
| **固定工作距离** | 孔径在图像上的像素尺度恒定 → **可以关闭随机缩放增强**（见 §9.4） |
| **固定光照几何** | 光源与工件的相对位置不变，图像统计特性稳定 |

> **这是工业视觉相比自动驾驶的一个根本差异**：工业场景可以**控制成像条件**，因此可以利用强先验（固定尺度、固定视角、固定光照）。自动驾驶不能。

### 4.3 成像配置

| 项 | 典型配置 |
|---|---|
| 相机 | 2000 万像素工业面阵相机（5472×3648），全局快门 |
| 接口 | GigE Vision / USB3 Vision |
| 镜头 | 定焦工业镜头，低畸变，配合工作距离选焦距 |
| **光源** | **环形光源（Ring Light）**，与孔同轴 |
| 触发 | 机械臂到位信号硬触发，保证位置与曝光同步 |

### 4.4 环形光源带来的固有问题

环形光源是圆形工件的自然选择，但它制造了这个项目的第三大难点：

```
        环形光源
    ╲     ╱ ╲     ╱
     ╲   ╱   ╲   ╱
      ▼ ▼     ▼ ▼
   ┌──────────────┐
   │ 焊缝余高（凸起）│ ← 正对光源，镜面反射 → 【过曝】
   ├──────────────┤
   │              │
   │   孔内壁      │ ← 光线难以进入 → 【欠曝，偏暗】
   │              │
   └──────────────┘
```

**结果**：

- **缺陷多在暗区**（孔内壁、焊趾根部）→ 欠曝导致对比度不足 → **漏检**
- **误检集中在过曝区**（余高反光）→ 高光斑点被误判为缺陷 → **误检**

一张图上同时存在过曝和欠曝，**这是"复合光照"这个说法的准确含义**。见 §12。

## 6. 数据集构建与标注规范

> `▸ 你负责`：数据集构建与标注规范定义。

### 6.1 数据集的特殊困难

| 困难 | 说明 |
|---|---|
| **样本极度稀缺** | 合格率高是好事，但意味着**缺陷样本天然稀少** |
| **长条形缺陷只有几张** | 裂纹类样本个位数，长宽比极端 |
| **NG : 背景 ≈ 1 : 7** | 严重失衡 |
| **标注需要专业知识** | 区分气孔和焊渣需要焊接工艺知识，普通标注员做不了 |
| **边界模糊** | 「这个氧化色算不算缺陷」有争议 |

### 6.2 标注规范要解决的问题

**① 类别定义与判据**

```
缺陷类（NG）：
  裂纹      —— 线状不连续，长宽比 > 3，端部尖锐
  气孔      —— 近圆形暗区，边界光滑，直径 > X px 才计
  未熔合    —— 焊缝与母材交界的线状暗痕
  咬边      —— 焊趾处连续沟槽

干扰类（非缺陷，需明确标为背景）：
  碳化物    —— 表面变色，无深度，边界渐变
  焊渣      —— 表面附着物，形状不规则，有高光
  氧化色    —— 大面积均匀变色
  孔内壁纹理 —— 加工纹路
  倒角      —— 结构性特征
```

**关键设计：干扰类必须显式定义，而不是"不标就完了"。** 因为标注员需要知道"看到这个不要标"，否则会出现有人标有人不标的不一致。

**② 超长缺陷的标注方式（重要）**

```
❌ 错误做法：一条 500px 长、10px 宽的裂纹标一个大框
   问题：长宽比 50:1，anchor 完全匹配不上（见 §9.5），等于白标

✓ 正确做法：拆成若干密集小框，每个框长宽比接近 1:1–3:1
   后处理时再按空间连续性合并
```

> 这个坑在**项目二的成排锥桶**里也遇到了（框又长又细，anchor 必须重聚类）。是同一类问题。

**③ 一致性治理**

| 措施 | 说明 |
|---|---|
| 规范文档 + 正反例图库 | 每个类别配 10+ 张典型图和边界案例 |
| 金标准集 | 由你和焊接工艺人员共同确认的一小批数据 |
| 焊接工程师参与评审 | 争议案例由懂工艺的人裁定 |
| 分批抽检 | 每批标注抽检，不合格返工 |

### 6.3 数据集切分

**必须避免的泄漏**：同一个管板、同一个孔的不同角度图，不能同时出现在训练集和测试集。

**正确做法：按工件（管板）切分**，保证测试集是完全没见过的工件。

## 7. ROI 精准提取：把 2000 万像素压缩成有效区域

> `▸ 你负责`

### 7.1 为什么需要这一步

一张 5472×3648 的单孔图里：

```
焊缝环带（真正需要检测的）  ~15–25%
孔内壁                      ~30%   ← 有加工纹理，误检源
管板母材表面                ~40%   ← 有划痕、氧化，误检源
相邻孔的边缘                ~5%    ← 完全无关但外观相似
倒角                        ~5%    ← 结构性亮/暗带，误检源
```

**75–85% 的像素不仅无用，而且是主动的误检来源。**

### 7.2 方案：YOLOv8-Seg 分割焊缝环带

```
输入：单孔图（可先降采样，分割不需要全分辨率）
输出：焊缝环带的分割掩膜
处理：
   ① 掩膜外区域填充中性灰（而非纯黑/纯白）
   ② 沿掩膜外接圆环裁剪，减小图像尺寸
```

**为什么填灰而不是填黑**：

- 纯黑（0）会在边界产生强梯度，网络可能把这个人造边界当作特征；
- 中性灰接近图像整体均值，对卷积响应的扰动最小；
- 也与后续的 letterbox padding 值保持一致。

### 7.3 为什么用分割而不是圆检测

传统做法是用**霍夫圆检测**定位焊缝环带。它的问题：

| 问题 | 说明 |
|---|---|
| 焊缝环带不是完美圆 | 焊接变形、余高不均，边界不规则 |
| 参数敏感 | 半径范围、阈值需要针对不同工件调 |
| 光照敏感 | 过曝/欠曝区域的边缘检测不稳定 |
| 无法处理异常 | 缺管、堵管、异形孔 |

**分割网络学的是"焊缝环带长什么样"这个语义**，对上述变化鲁棒得多。代价是需要标注掩膜和一次额外推理。

> **在这个项目的时间预算下（3 秒/孔），多一次分割推理完全可以接受。**这是典型的"用算力换鲁棒性"。

### 7.4 配套：非焊缝间隙图作为空标注负样本

**做法**：把相邻孔之间的母材区域、纯孔内壁区域，作为**完全没有标注框的负样本图**加入训练集。

**作用**：直接告诉模型"这些纹理不是缺陷"。空图负样本是抑制误检最直接的手段。

> 同样的手段在**项目二**里用于抑制"路面截断"的捷径学习。

**效果**：Precision +2%。

### 7.5 ROI 带来的算力收益（重要且常被忽略）

```
不做 ROI：
  5472×3648 全图，1280 切图 + 250 重叠 → stride 1030
  横向 ⌈(5472-250)/1030⌉ = 6 块
  纵向 ⌈(3648-250)/1030⌉ = 4 块
  → 24 张子图

做 ROI 后：
  只沿焊缝环带切图
  → 约 8–12 张子图

推理量减少 50–60%
```

**ROI 分割不只是提精度的手段，也是省算力的手段。** 在有节拍要求的产线上，这一点和精度同样重要。

## 8. 大图小目标之一：切图策略

> `▸ 你负责`

### 8.1 问题的量化

```
原图         5472 × 3648
网络输入     640 × 640（YOLOv8 默认）
缩放比       5472 / 640 ≈ 8.55×

最小缺陷 15×15 px
    ↓ 直接缩放
15 / 8.55 ≈ 1.75 px
```

**1.75 个像素。** 在 P3（stride 8）特征图上，它连一个特征点都占不满。**这不是"难检测"，是信息在预处理阶段就已经丢失了。**

### 8.2 切图（Tiling）方案

```
子图尺寸    1280 × 1280
重叠量      250 px
滑动步长    1280 - 250 = 1030 px
```

**目标相对尺寸的提升**：

```
不切图：15 px → 15 / 8.55  = 1.75 px
切  图：15 px → 15 / 2.0   = 7.5  px    （1280 → 640，缩放比 2×）

提升倍数：7.5 / 1.75 ≈ 4.3×
```

**这就是简历里"目标相对尺寸提升约 4 倍"的来源。**

### 8.3 重叠量为什么是 250px

**原则：任何一个缺陷，必须至少在一张子图里是完整的。**

```
若最大缺陷尺寸 ≈ 150–200 px
则重叠量必须 > 最大缺陷尺寸
取 250 px = 最大缺陷尺寸 + 余量
```

**如果重叠量不足**：一个缺陷被切成两半，两张子图各看到一半，两边都可能检不出来，或者检出两个残缺的框——**这是切图方案最典型的失败模式**。

### 8.4 子图尺寸的权衡

| | 子图更小 | 子图更大 |
|---|---|---|
| 目标相对尺寸 | 更大，更好检 | 更小 |
| 子图数量 | **线性上升** | 更少 |
| 推理耗时 | **线性上升** | 更少 |
| 上下文信息 | 减少（可能丢失判别所需的周边信息） | 保留 |
| 跨子图截断风险 | 上升 | 下降 |

**1280 是在「目标够大」和「推理次数可接受」之间的折中点**，需要实测确定，没有理论最优值。

### 8.5 切图的必然副作用：重复检出

```
重叠区域的同一个缺陷，会在两张子图里各被检出一次
    ↓
子图坐标 → 原图坐标映射
    ↓
原图尺度上做一次全局 NMS
```

**必须在原图尺度做 NMS，不能在子图尺度做**——因为重复来自不同子图，子图内部的 NMS 看不到对方。

### 8.6 这个方案有正式名字：SAHI

> **SAHI（Slicing Aided Hyper Inference）**，Akyon et al., ICIP 2022

标准做法包含：

1. **切片微调（Slicing Aided Fine-tuning）**：训练时也在切片上训，保证训练与推理分布一致；
2. **切片推理**：推理时切片 + 重叠；
3. **全图推理融合**：切片结果 + 全图推理结果一起做 NMS，兼顾大小目标。

开源实现 `obss/sahi`，支持 YOLOv5/v8、MMDetection、Detectron2。

**在小目标检测竞赛和工业检测里，SAHI 几乎是标配。**报告的增益通常在 **AP_small +5~15%**。

## 9. 大图小目标之二：网络结构优化

> `▸ 你负责`

### 9.1 P2 检测头

**YOLOv8 默认的三个检测尺度**：

| 层 | Stride | 输入 640 时的网格 | 每个网格覆盖 | 适合目标 |
|---|---|---|---|---|
| P3 | 8 | 80×80 | 8×8 px | 小目标 |
| P4 | 16 | 40×40 | 16×16 px | 中目标 |
| P5 | 32 | 20×20 | 32×32 px | 大目标 |

**加入 P2（stride 4）**：

| 层 | Stride | 网格 | 覆盖 |
|---|---|---|---|
| **P2** | **4** | **160×160** | **4×4 px** |

**为什么必要**：

```
切图后目标约 7.5 px
在 P3（stride 8）上：7.5/8 < 1 个网格  → 只有 1 个正样本点，且定位精度只有 8px
在 P2（stride 4）上：7.5/4 ≈ 2 个网格  → 定位精度 4px，正样本更充分
```

**代价（必须知道）**：

```
P2 特征图尺寸是 P3 的 4 倍（160² vs 80²）
→ 该层的计算量和显存占用约 4 倍
→ 通常是整个检测头里最贵的一层
```

所以 P2 头是"明知很贵但必须加"的选择，只在小目标是主要矛盾时才值得。

### 9.2 Bi-FPN 上采样改双线性插值

**默认**：`nn.Upsample(scale_factor=2, mode='nearest')`

**最近邻插值的问题**：

```
原始 2×2:        最近邻上采样 4×4:
  A  B             A  A  B  B
  C  D             A  A  B  B
                   C  C  D  D
                   C  C  D  D
```

产生**块状阶梯边界**。对大目标无所谓（几十上百像素，几个像素的锯齿可忽略），但对 **7px 的小目标，几个像素的伪影就是它尺寸的一半**。

**双线性插值**产生平滑过渡，特征图上的响应更接近真实的连续分布。

**代价**：略微增加计算量，某些部署框架对 bilinear 上采样的支持不如 nearest 好（需要确认目标平台支持）。

### 9.3 P3 / P4 加入 CA 注意力

**CA = Coordinate Attention**（Hou et al., CVPR 2021）

**注意力机制的演进**：

| 机制 | 做什么 | 局限 |
|---|---|---|
| **SE**（Squeeze-Excitation） | 全局平均池化 → 通道加权 | **完全丢失空间位置信息** |
| **CBAM** | 通道注意力 + 空间注意力 | 空间注意力用局部卷积，**缺乏长程依赖** |
| **CA** | **把全局池化拆成 H 和 W 两个方向的一维池化** | — |

**CA 的核心思想**：

```
沿 W 方向池化 → 得到 (C, H, 1)：保留了【垂直方向的位置信息】
沿 H 方向池化 → 得到 (C, 1, W)：保留了【水平方向的位置信息】
两者拼接 → 共享 1×1 卷积 → 拆分 → 分别生成 H 和 W 方向的注意力权重
```

**这样既捕获了长程依赖（沿一个方向的全局池化），又保留了另一个方向的精确位置。**

**为什么适合本任务**：

1. 焊缝缺陷的**位置有强先验**——缺陷只出现在焊缝环带上，CA 能编码这个空间先验；
2. 小目标的位置信息极其宝贵，SE 那种全局池化会把它抹掉；
3. CA 极其轻量（参数量增加不到 1%）。

**放在 P3 / P4 而不是 P5**：小目标的特征主要在浅层，P5 的分辨率已经太低（20×20），加注意力意义不大。

### 9.4 关闭随机缩放增强（一个反直觉但正确的决定）

**常规做法**：随机缩放（scale jitter）是检测任务的标准增强，能提升尺度鲁棒性。

**本项目关闭它的理由**：

```
采图条件是【固定的】：
  · 机械臂固定工作距离
  · 正对拍摄
  · 同一型号相机镜头
→ 孔径在图像上的像素尺度【几乎是常量】
→ 缺陷的像素尺度分布【范围很窄】
```

**随机缩放在教模型一个不存在的变化**，等于稀释了有限的训练样本，让模型去覆盖推理时根本不会遇到的尺度。

> **与项目二关闭 mosaic 是完全同一个逻辑**：
> **数据增强必须匹配真实分布。能"涨点"的增强，本质是在补充训练分布中缺失的变化；如果那个变化在部署场景中不存在，增强就是在注入噪声。**
>
> 自检问题：**这个增强产生的图像，在真实产线上有可能出现吗？**

### 9.5 回归损失：DIoU + NWD

#### IoU 类损失对小目标的失效

**用具体数字说明**（NWD 论文中的经典例子）：

| 框尺寸 | 中心偏移 1px | 偏移 3px | 偏移 4px |
|---|---|---|---|
| **6×6（小目标）** | IoU = 0.53 | IoU = 0.06 | **IoU = 0** |
| 36×36（正常目标） | IoU = 0.90 | IoU = 0.73 | IoU = 0.67 |

**同样是 4 个像素的偏移**：

- 大目标 IoU 只从 1.0 掉到 0.67，梯度平缓；
- **小目标直接归零，梯度消失**。

**这带来两个问题**：

1. **训练信号陡峭不稳定**：IoU 对小目标的位置极度敏感，loss 曲面像悬崖；
2. **anchor 匹配困难**：正样本分配依赖 IoU 阈值，小目标很难有 anchor 超过阈值 → 训练中根本没有正样本。

#### NWD 怎么解决

> **NWD = Normalized Wasserstein Distance**（Wang et al., 2021，*A Normalized Gaussian Wasserstein Distance for Tiny Object Detection*）

**核心思想：把边界框建模成二维高斯分布，用分布距离代替面积重叠。**

```
边界框 (cx, cy, w, h)  →  高斯分布 N(μ, Σ)
    μ = (cx, cy)
    Σ = diag(w²/4, h²/4)

二阶 Wasserstein 距离：
    W₂²(N_a, N_b) = ‖ [cx_a, cy_a, w_a/2, h_a/2] − [cx_b, cy_b, w_b/2, h_b/2] ‖²₂

归一化成相似度：
    NWD = exp( −√(W₂²) / C )        C 为与数据集相关的常数

损失：
    L_NWD = 1 − NWD
```

**关键性质**：

| 性质 | 说明 |
|---|---|
| **永远不为零** | 即使两框完全不重叠，NWD 仍有有意义的值和梯度 |
| **对位置偏移平滑** | 指数衰减，不会像 IoU 那样断崖 |
| **尺度归一化** | 不同尺寸的目标有可比的度量 |

#### 为什么是"DIoU + NWD"组合而不是纯 NWD

| 损失 | 强项 | 弱项 |
|---|---|---|
| **DIoU** | 中大目标收敛快；显式惩罚中心点距离 | 小目标失效 |
| **NWD** | 小目标梯度稳定 | 对大目标不如 IoU 系精确 |

**组合形式**：

```
L_box = α · L_DIoU + (1−α) · L_NWD
```

α 通常按目标尺寸动态调整，或固定取 0.5 左右。

**这个项目里既有 15px 的微小气孔，也有上百像素的长条裂纹**，所以两者都需要。

**DIoU 的定义**（顺带）：

```
DIoU = IoU − ρ²(b, b_gt) / c²
```

其中 ρ 是两框中心点距离，c 是最小外接框对角线。相比 GIoU，DIoU 直接优化中心距离，**收敛更快且不会出现 GIoU 那种"先扩大外接框"的绕路行为**。

### 9.6 结构优化的整体效果

```
mAP50：89.7%（基线） → 96%+
```

## 10. 高相似背景与样本失衡

> `▸ 你负责`

### 10.1 问题的两个层面

**层面一：类间相似度极高**

| 真缺陷 | 干扰物 | 相似之处 |
|---|---|---|
| 气孔 | 焊渣附着 | 都是暗色圆形/不规则块 |
| 气孔 | 碳化物斑点 | 颜色深度相近 |
| 裂纹 | 加工划痕 | 都是细长线状 |
| 未熔合 | 焊趾自然过渡线 | 都是线状不连续 |

**层面二：数量严重失衡**

```
单张图内：真缺陷 ~1 处，干扰物 5–8 处
数据集级：NG : 背景 ≈ 1 : 7
```

**两者叠加的后果**：模型面对的是"一堆长得几乎一样的东西，其中只有一个是要报的"。

### 10.2 治理手段一：难负样本挖掘

**不是随机加负样本，而是精准挖掘模型确实会误检的那些。**

```
① 用当前模型跑全量数据推理
② 挑出【高置信度但实际是背景】的检出（硬 FP）
③ 按误检成因归类：
     碳化物 / 焊渣 / 孔内壁纹理 / 倒角 / 高光斑点 / 相邻孔边缘
④ 每一类构建专门的难负样本集
⑤ 回灌训练
⑥ 重新评测，追踪每一类的收敛情况
```

**归类的价值**：可以定量追踪每一类误检的收敛，而不是只看一个总数。如果只有总数，你不知道是哪一类在恶化。

> **与项目一的凭空误检治理、项目三的误检归类，是完全同一套方法论。**

**OHEM（Online Hard Example Mining）**：

> Shrivastava et al., CVPR 2016

在线版本——训练时自动挑出 loss 最高的样本反传。相比离线挖掘：

| | 离线挖掘 | OHEM |
|---|---|---|
| 时机 | 训练前准备数据 | 训练中动态选择 |
| 可控性 | 高（可人工确认） | 低 |
| **风险** | — | **会放大错标样本**（错标的 loss 也高） |

**在标注质量不完美的工业数据集上，离线挖掘 + 人工确认更安全。**

### 10.3 治理手段二：分阶段训练

```
阶段一：全量数据训练，建立基础检出能力（保 Recall）
阶段二：加入难负样本，降低学习率微调（提 Precision）
```

**为什么要分阶段而不是一开始就混在一起**：

- 一开始就大量负样本 → 模型倾向于"什么都不报"，Recall 起不来；
- 先建立检出能力，再压误检，两个目标不互相干扰；
- 阶段二用小学习率，避免破坏已学到的检出能力。

### 10.4 治理手段三：类内 NMS

**问题**：同一个缺陷区域，模型可能同时报出多个不同类别的框（气孔 + 焊渣 + 未熔合）。

**标准 NMS 是类内的**（同类之间才抑制），跨类不抑制。这在通用检测里是对的（一个人骑车，人和车的框应该都保留），但在本任务里会造成**同一物理缺陷被重复计数**。

**处理方式**：

```
选项 A：类内 NMS + 跨类去重（同位置只保留最高置信度的类别）
选项 B：先做类别无关的 NMS，再判类别
选项 C：定义混淆类等价集，组内做 NMS
```

> **与项目三的"跨类等价集"是同一个思路**——类别边界模糊时，不应该按严格类别处理。

**Precision 效果**：难负样本 + 分阶段训练 + 类内 NMS 合计 **Precision +10%**。

## 11. Focal Loss 失效：完整分析

> 这是整个项目最有价值的技术故事。它有常识、有反常识、有排查、有解法。

### 11.1 常规思路

```
问题：样本失衡（NG : 背景 = 1 : 7）
教科书答案：上 Focal Loss
```

**Focal Loss 的定义**（Lin et al., ICCV 2017，RetinaNet）：

```
FL(p_t) = −α_t · (1 − p_t)^γ · log(p_t)

其中：
   p_t = p        若 y = 1（正样本）
   p_t = 1 − p    若 y = 0（负样本）
   γ  = 调制指数（论文推荐 2.0）
   α_t = 类别平衡权重（论文推荐 0.25）
```

**设计意图**：`(1−p_t)^γ` 这个调制因子，把**已经分对的、置信度高的样本**权重压低，让模型专注于难样本。

```
p_t = 0.9,  γ=2  →  (1−0.9)² = 0.01     权重降到 1/100
p_t = 0.99, γ=2  →  (1−0.99)² = 0.0001  权重降到 1/10000
p_t = 0.5,  γ=2  →  (1−0.5)²  = 0.25    权重降到 1/4
```

### 11.2 实际发生了什么

**在这个项目里，Focal Loss 加上去之后，硬性误检（模型高置信度报出的碳化物、焊渣）几乎改不动。**

### 11.3 为什么失效：多重机制

这里需要说清楚，因为**教科书理论和实际观察之间有一个需要解释的落差**。

#### 机制一：整体梯度范数塌缩（最主要）

**关键前提：使用的是已经预训练好、置信度普遍很高的模型。**

在一个已经收敛得不错的模型上继续微调时：

```
绝大多数样本的 p_t > 0.9
    ↓
(1 − p_t)^γ < 0.01
    ↓
【整个 batch 的梯度范数塌缩到原来的百分之几】
    ↓
在学习率不变的情况下，等效于学习率被降低了 1–2 个数量级
    ↓
训练几乎停滞
```

**硬 FP 虽然在 Focal Loss 下的相对权重不低，但**：

1. 它们的**绝对数量极少**（一张图 5–8 个干扰物中真正被误报的更少）；
2. 在一个整体梯度已经塌缩的 batch 里，它们的贡献仍然被大量近零梯度样本稀释；
3. 结果就是**这些最该被修正的样本，实际得到的更新量微乎其微**。

> 这就是"Focal Loss 把梯度压没了"这个直观描述背后的准确机制——**不是它单独压低了硬 FP，而是它把整体信号压塌了，导致本就稀少的硬 FP 推不动模型。**

#### 机制二：超参数需要重新整定，直接套用会劣化

Focal Loss 引入了 `α`、`γ` 两个超参，并且**改变了 loss 的量纲**：

- loss 整体数值大幅变小 → 与其他 loss 分量（框回归、DFL）的相对权重全乱了；
- 学习率、warmup 策略都需要重调；
- RetinaNet 论文的 `α=0.25, γ=2` 是在 COCO 上从头训练得到的，**在小数据集微调场景下没有理由继续适用**。

#### 机制三：与 YOLOv8 已有机制冲突

**这是一个可以直接查证的事实**：

> **Ultralytics YOLOv5 / YOLOv8 的超参配置里有 `fl_gamma`，默认值是 `0.0`——即默认关闭 Focal Loss。**

原因是 YOLOv8 本身已经处理了失衡问题：

| 机制 | 作用 |
|---|---|
| **TaskAlignedAssigner** | 动态正负样本分配，按分类分数 × 定位质量的对齐度选正样本，本身就是一种难例聚焦 |
| **BCE + DFL** | 分类用 BCE，框回归用 Distribution Focal Loss |
| **objectness 分支的隐式平衡** | — |

**在一个已经做了正负样本动态分配的框架上再叠一层 Focal Loss，是重复且互相干扰的。**社区实践中，开启 `fl_gamma` 通常掉点。

#### 机制四：放大错标样本

Focal Loss 放大 hard example，而 **hard example 里混着错标**。

工业焊缝数据集的边界样本（这个氧化色算不算缺陷）本身就有争议，错标率不低。Focal Loss 会把这些错标样本的权重成倍放大，**训练往错误方向走**。

### 11.4 解法：定制 BCE 抑制硬 FP

**思路：不用全局的、对所有样本一视同仁的调制因子，而是针对性地给硬 FP 加权。**

```python
# 概念示意
def custom_bce(pred_logits, targets, hard_fp_mask, fp_weight=3.0):
    loss = F.binary_cross_entropy_with_logits(
        pred_logits, targets, reduction='none'
    )
    # 对【负样本 且 预测置信度高】的位置加权
    weight = torch.ones_like(loss)
    weight[hard_fp_mask] = fp_weight
    return (loss * weight).mean()
```

**与 Focal Loss 的本质区别**：

| | Focal Loss | 定制 BCE |
|---|---|---|
| 调制方式 | **全局函数** `(1−p_t)^γ`，对所有样本生效 | **定向加权**，只针对硬 FP |
| 副作用 | 整体梯度塌缩 | 其余样本梯度不受影响 |
| 可控性 | 只有 γ 一个旋钮 | 可以指定"什么算硬 FP"、加多少权 |
| 与框架兼容 | 与 TaskAlignedAssigner 冲突 | 只改 loss 的一个分支 |

**核心区别一句话**：

> **Focal Loss 是"让模型少关注简单样本"；定制 BCE 是"让模型多关注这一类特定错误"。前者是减法，后者是加法。在一个已经训得不错的模型上，加法比减法安全得多。**

### 11.5 monkey-patch 隔离改动

**为什么不直接改 Ultralytics 源码**：

| 问题 | 说明 |
|---|---|
| 升级困难 | 框架更新后 merge 冲突 |
| 可复现性差 | 别人拿到你的代码跑不出同样结果（他们的框架是原版） |
| 影响其他实验 | 同一个环境里跑对照实验时，基线也被改了 |
| 难以回滚 | 改了哪些地方记不清 |

**monkey-patch 的做法**：

```python
# my_patches.py —— 独立文件，不碰框架源码
from ultralytics.utils import loss as yolo_loss

_original_bce = yolo_loss.v8DetectionLoss.__call__

def patched_loss(self, preds, batch):
    result = _original_bce(self, preds, batch)
    # 在这里注入自定义的硬 FP 加权逻辑
    ...
    return result

def apply():
    yolo_loss.v8DetectionLoss.__call__ = patched_loss
```

**优点**：

- 框架保持原版，可随时升级；
- 改动集中在一个文件，一眼看清动了什么；
- 想跑基线只要不 `apply()`；
- 对照实验干净。

> **这是一个工程习惯层面的加分项**——它说明你考虑了可复现性和可维护性，而不只是"把指标调上去"。

## 12. 复合光照与 IAT 曝光补偿

> `▸ 你负责`

### 12.1 问题回顾

环形光源造成同一张图内的**双向失效**：

```
焊缝余高（凸起，正对光源）→ 镜面反射 → 过曝 → 像素值饱和（255）
                                        → 信息不可恢复
                                        → 高光斑点被误判为缺陷【误检】

孔内壁（凹陷，光线难入）  → 欠曝 → 对比度极低
                                → 暗区缺陷淹没在噪声里【漏检】
```

**难点在于"同一张图内同时存在两种相反的失效"**——全局的亮度/对比度调整（直方图均衡、Gamma 校正）无法同时改善两者：拉亮暗部会让高光更糊，压低高光会让暗部更黑。

### 12.2 传统方法及其局限

| 方法 | 局限 |
|---|---|
| 全局直方图均衡 | 加剧高光饱和，放大暗区噪声 |
| **CLAHE**（限制对比度自适应直方图均衡） | 分块处理，比全局好；但块边界有伪影，参数需手调，且不是学习出来的 |
| Gamma 校正 | 单调映射，无法同时处理两端 |
| Retinex 系 | 效果好但慢，参数敏感 |
| **多曝光融合（HDR）** | 效果最好，但**需要拍多张不同曝光的图**，采图时间翻倍——产线节拍不允许 |

### 12.3 IAT：轻量级学习式曝光补偿

> **IAT = Illumination Adaptive Transformer**
> Cui et al., BMVC 2022，*"You Only Need 90K Parameters to Adapt Light: A Light Weight Transformer for Image Enhancement and Exposure Correction"*

**核心特点**：

| 特点 | 说明 |
|---|---|
| **极致轻量** | **约 90K 参数**，比大多数增强网络小 1–2 个数量级 |
| **双分支设计** | 局部分支（逐像素调整）+ 全局分支（ISP 参数：色温、Gamma） |
| **同时处理过曝与欠曝** | 这正是本任务需要的 |
| **速度快** | 可实时，适合作为前处理插入流水线 |

**为什么适合这个项目**：

1. 过曝欠曝同时存在——IAT 的设计目标恰好就是这个；
2. 90K 参数意味着**几乎不占用推理预算**，可以直接串在检测前面；
3. 学习式的自适应，不需要针对不同工件手调参数（对比 CLAHE）。

### 12.4 效果与解释

**结果：Precision 和 Recall 双升。**

这个"双升"值得展开——大多数优化都是在 P 和 R 之间做权衡，双升说明**解决的是信息层面的问题而非决策层面的问题**：

```
Recall ↑：暗区被拉亮 → 原本淹没在噪声里的缺陷显现出来 → 检出
Precision ↑：高光被压回 → 反光斑点不再呈现"缺陷般"的高对比特征 → 不再误报
```

**一般规律**：

- 调阈值、调 loss 权重 → P/R 权衡（决策层面）
- 改善输入质量、增加信息 → **P/R 双升**（信息层面）

### 12.5 关键工程细节：训练与推理必须一致

**IAT 作为前处理，必须在训练和推理时都使用，且参数完全一致。**

如果只在推理时加，模型见到的输入分布与训练时不同，会直接崩。

> 这与**项目二的训推预处理不一致问题**是完全同一个陷阱。任何前处理模块都必须逐位对齐。

## 13. 数据稀缺与合成策略

> `▸ 你负责`

### 13.1 稀缺到什么程度

```
长条形裂纹样本：个位数张
长宽比：极端（可达 20:1 以上）
```

**几张样本是不可能训出稳定检出能力的**，但裂纹又恰恰是零容忍的致命缺陷。

### 13.2 Copy-Paste 合成

> Ghiasi et al., CVPR 2021，*Simple Copy-Paste is a Strong Data Augmentation Method for Instance Segmentation*

**基本做法**：把一张图里的目标实例抠出来，粘贴到另一张图上，同步生成标注。

**本项目的关键约束：只在焊缝环带内粘贴。**

```
✓ 粘贴到焊缝环带上   → 模型学到的位置先验是【真实的】
✗ 粘贴到孔内壁       → 教模型"孔内壁上会有裂纹"，这是【假先验】
✗ 粘贴到管板母材     → 同上
✗ 粘贴到倒角        → 同上
```

**为什么这条约束如此重要**：本任务的目标**位置先验极强**（缺陷只可能在焊缝上）。破坏这个先验，相当于故意让模型变笨——**这与项目二关闭 mosaic 的理由完全一致**。

**其他必须处理的细节**：

| 细节 | 说明 |
|---|---|
| 边缘融合 | 直接粘贴会有硬边，需要泊松融合或高斯羽化 |
| 光照匹配 | 粘贴源和目标的亮度差异要调整，否则模型学到"亮度突变=缺陷" |
| 尺度匹配 | 保持真实物理尺寸对应的像素尺度 |
| **合成比例克制** | **占比一高，模型会过拟合到合成痕迹上**，学到的是"有融合边缘=缺陷" |

**合成数据比例的经验值**：通常控制在 10–30%，需要实测确定拐点。

### 13.3 超长缺陷拆成密集小框

**问题**：一条 500×10 px 的裂纹，长宽比 50:1。

```
YOLO 的 anchor（或 anchor-free 的正样本分配）依赖 IoU / 对齐度
极端长宽比的真值框，与任何预设尺度都匹配不上
→ 该真值在训练中【分配不到正样本】
→ 等于这个标注完全没起作用
```

**解法**：

```
标注：拆成若干长宽比接近 1:1 ~ 3:1 的密集小框
训练：正常训练
后处理：按空间连续性把相邻小框合并成一条完整缺陷
```

> 同样的问题在**项目二的成排锥桶**（框又长又细）里出现，那里的解法是重新 k-means 聚类 anchor。两种解法适用于不同情况：
> - 长宽比极端但**分布集中** → 重聚类 anchor
> - 长宽比极端且**样本极少** → 拆分标注（因为几个样本不足以支撑一个专门的 anchor）

### 13.4 三条手段的组合

失衡与稀缺问题**很少能靠单一手段解决**，通常是三条一起上：

```
采样层面：弱势类重采样（提高被抽到的频率）
损失层面：定制 BCE 加权
数据层面：Copy-Paste 合成 + 难负样本精准控制
```

**"负样本的精准控制"是一个容易被误解的点**：不是简单地少放负样本（那样误检会失控），而是**把最容易误检的那些（碳化物、焊渣、孔内壁、倒角）挑出来重点放**——用有限的负样本预算，买最大的误检抑制效果。

## 14. 部署、量化与产线集成

> `▸ 你参与`

### 14.1 部署链路

```
PyTorch 训练权重（.pt）
   ↓ export
ONNX
   ↓ 图优化、算子融合
TensorRT Builder
   ↓ INT8 校准（PTQ）
TensorRT Engine（.engine）
   ↓
工控机（IPC）+ 独立显卡 推理
```

### 14.2 INT8 量化

| 项 | 说明 |
|---|---|
| **方式** | PTQ（训练后量化），用几百张校准图统计激活值分布 |
| **校准集选择** | **必须覆盖过曝、欠曝、各类缺陷**，否则量化 scale 不准 |
| **收益** | 相比 FP32 约 **3–4× 加速**，显存占用降至 1/4 |
| **精度损失** | 通常 mAP 掉 0.5–2%，需实测 |
| **敏感层回退** | 检测头输出层、上采样层对量化敏感，可保持 FP16 |

**本项目的一个有利条件**：验收标准是 95%，而模型做到了 96.8%，**有 1.8 个百分点的量化预算**。如果模型只做到 95.2%，量化后就掉到验收线以下了。

> **这是"精度冗余"的价值**——量产项目的模型精度不能刚好卡在验收线上，必须留出部署损耗的余量。

### 14.3 多线程 Pipeline

**关键洞察：视觉推理不是瓶颈，机械运动才是。**

```
单孔时间预算 = 2.5 小时 / 3000 孔 ≈ 3 秒/孔

其中：
  机械臂移动到位     1.5–2.0 s   ← 主要瓶颈（物理运动，压不下去）
  相机曝光 + 传输     0.1–0.3 s
  ROI 分割推理        ~10 ms
  IAT 曝光补偿        ~5 ms
  切图（约 10 张）    ~5 ms
  检测推理 ×10（INT8）~50–100 ms
  后处理 + NMS        ~10 ms
  结果写库            ~10 ms
  ────────────────────────────
  视觉部分合计        ~0.15 s   ← 只占 5%
```

**因此优化的关键是并行化，而非单点加速**：

```
时间轴 →
孔 N   : [移动][采图]
孔 N-1 :        [ROI][IAT][切图][检测][后处理]
孔 N-2 :                          [写库][报告]

三级流水线并行，总节拍 = max(各级耗时) 而非 sum
→ 节拍由机械臂移动时间决定
```

**这个认知很重要**：如果只盯着模型加速（比如再压 20ms），对总耗时几乎没有影响。**系统级瓶颈分析比单点优化更有价值。**

> 与**项目一的时延预算**是同一类思维——先搞清楚瓶颈在哪，再决定优化什么。

### 14.4 结果落库与可追溯

```
每个孔的记录：
  工件编号 / 孔号 / 采图时间
  原图路径（存档）
  检测结果（缺陷类型、位置、尺寸、置信度）
  判级结论（合格 / 复检 / 不合格）
  操作员确认状态
```

**为什么必须存原图**：船级社验收要求可追溯。出现争议时需要调出原始图像复核。这也为后续的模型迭代提供了持续的数据来源。

### 16.3 这个项目留下的方法论（可迁移到 BEV）

这是面自动驾驶岗位时最该讲的部分——**不要在工业检测细节上停留太久，要把话题引到方法论**。

| 方法论 | 本项目的形态 | 在 BEV 项目里的对应 |
|---|---|---|
| **误检归类 → 构建针对性难负样本 → 回灌验证** | 碳化物 / 焊渣 / 孔内壁分类挖掘 | 项目一的凭空误检治理、项目二的路面截断治理、项目三的误检 checker 分类 |
| **数据增强必须匹配真实分布** | 关闭随机缩放（固定视角） | 项目二关闭 mosaic（位置先验） |
| **训练与推理的预处理必须逐位对齐** | IAT 前处理训推一致 | 项目二的 letterbox 训推不一致排查 |
| **小目标需要专门的结构与损失** | P2 头 + NWD | 项目一的中远距小目标、项目二的远距锥桶 |
| **样本失衡不能靠单一手段** | 采样 + 损失 + 合成三条并行 | 项目一的 CBGS + 类别加权 |
| **Focal Loss 的适用前提** | 高置信度预训练模型上失效 | 项目一同样弃用 Focal Loss，选 CBGS + 温和加权 |
| **系统级瓶颈分析** | 视觉只占 5%，瓶颈在机械运动 | 项目一的时延预算、BEVPoolv2 换 DepthNet |
| **精度要留部署余量** | 96.8% vs 验收线 95%，留量化损耗 | 量产模型的量化预算 |
| **工程落地的完整性** | 前处理、部署、节拍、现场验收每环都可能是瓶颈 | 量产 BEV 的全链条意识 |

**一句话总结**：

> 「这个项目让我知道模型精度只是一部分。前处理、部署、时延预算、现场验收，每一环都可能是瓶颈。这个意识在做量产 BEV 的时候特别有用。」

## 附录 C：数量级核算表

> 这些数字用于建立直觉，被追问时可以现场推算，比死记硬背可信得多。

### C.1 成像分辨率

```
单孔视场 ≈ 30 mm
图像宽度 = 5472 px
→ 像素尺度 = 30 / 5472 ≈ 5.5 μm/px
→ 15×15 px 缺陷 ≈ 0.08 × 0.08 mm
```

### C.2 若不逐孔近摄

```
管板直径 2000 mm / 5472 px = 0.37 mm/px
→ 0.1 mm 的裂纹连 1 个像素都不到
→ 【物理上不可能检出】
```

### C.3 切图带来的相对尺寸提升

```
不切图：5472 → 640，缩放 8.55×，15px → 1.75px
切  图：1280 → 640，缩放 2.0×，  15px → 7.5px
提升：7.5 / 1.75 ≈ 4.3×
```

### C.4 子图数量

```
不做 ROI：
  stride = 1280 − 250 = 1030
  横向 ⌈(5472−250)/1030⌉ = 6
  纵向 ⌈(3648−250)/1030⌉ = 4
  → 24 张

做 ROI（只沿焊缝环带）：
  → 约 8–12 张
  → 推理量减少 50–60%
```

### C.5 时间预算

```
总节拍 = 2.5 h × 3600 / 3000 孔 = 3.0 s/孔

机械臂移动      1.5–2.0 s   (50–67%)  ← 瓶颈
采图 + 传输     0.1–0.3 s   (3–10%)
视觉全链路      ~0.15 s     (5%)
其余余量        ~0.5 s

结论：优化模型推理对总节拍影响极小，并行化才是关键
```

### C.6 人工方案对比

```
人工：渗透 + 显像停留 20–60 min（批处理）
    + 3000 孔逐孔目视
    → 约 1 个工作日（8 h）

自动：3 s/孔 × 3000 = 2.5 h
→ 效率提升约 3.2×，且可追溯、无主观差异、无化学品
```
