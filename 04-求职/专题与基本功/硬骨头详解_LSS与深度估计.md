# 硬骨头一 · LSS 三步全流程

**完成标准**：能在白纸上画出来——D⊗C 外积怎么得到视锥特征、splat 怎么落格子。

## 1.1 先建立问题意识：Lift 在解什么

单目图像做 3D 感知，本质困难是**一个像素对应的是一条射线，不是一个点**。缺的那一维就是深度。

历史上的三条路：

| 方法 | 做法 | 问题 |
|---|---|---|
| IPM（逆透视变换） | 假设世界是平面，用单应矩阵直接映射 | 只在平地成立；上下坡、有高度的物体全错 |
| 单目深度估计 + 反投影 | 先估一个确定的深度值，再反投 | 深度估错就彻底错，且无法表达不确定性 |
| **LSS** | **不选一个深度，把所有可能深度都保留，用概率加权** | 计算量大（后来被 BEVPoolv2 解决） |

> **LSS 的核心创新可以用一句话概括：把"选一个深度"这个硬决策，改成"给每个可能深度一个概率"的软分配。**

## 1.2 Lift：从 2D 特征到视锥特征

### 输入

图像经 Backbone + FPN 后得到特征图 `F ∈ R^{H×W×C_in}`（典型：704×256 输入、stride 8 → 88×32，通道 256）。

### 两个输出头

从 `F` 出两路（实现上常是**一个卷积输出 D+C 通道再 split**）：

```
DepthNet     →  α ∈ R^D        每像素的深度分布，softmax 后 Σα_d = 1
Context Conv →  c ∈ R^C        每像素的语义特征（LSS 原文 C=64，BEVDet 常用 80）
```

**BEVDepth 的关键改进**：DepthNet 额外注入**相机内参编码**——把 `fx, fy, cx, cy` 过一个 MLP，生成缩放因子作用在深度特征上（SE 式）。原因是**同样的像素尺寸，在不同焦距下对应不同的真实尺寸**，不给内参，网络学不出正确的尺度先验。多相机异构焦段（长焦/主视/广角）时这条尤其重要。

### 外积

对相机 `n`、像素 `(h, w)`：

```
Frustum[n, d, h, w, k] = α[n, d, h, w] · c[n, h, w, k]
```

形状变化：

```
α:  N × D × H × W          （深度分布）
c:  N × H × W × C          （语义特征）
─────────────────────────────────────
Frustum: N × D × H × W × C  （视锥特征）
```

### 物理含义（这段一定要能口头讲）

> 每个像素的语义特征 `c`，被按照深度概率 `α` **「撒」到这条视线上的 D 个离散位置**上。

三种情形，对应下游三种表现——**这个对应关系是后面硬骨头三的基础**：

| 深度分布 | 特征怎么落 | 下游表现 |
|---|---|---|
| 尖锐单峰、位置对 | 几乎全部集中在正确的 bin | 正常检出 |
| 平坦、不确定 | 摊薄到很多位置，每处响应都弱 | **远距漏检**（响应达不到阈值） |
| 尖锐单峰、但位置错 | 完整地落到**错误**的位置 | **位置跳变 / 凭空误检**（最危险） |

### 一个数量级感受

`N=6, D=118, H=32, W=88, C=64`：

```
6 × 118 × 32 × 88 × 64 ≈ 1.27 × 10⁹ 个 float ≈ 5 GB（FP32）
```

**这就是为什么显式构造视锥张量不可接受**，也是 BEVPoolv2 存在的理由。

## 1.3 Splat：从视锥到 BEV 平面（拍扁在这一步）

### 第一步：视锥点的三维坐标

给定像素齐次坐标 `[u, v, 1]` 和深度 `d`：

```
相机系：  P_cam = d · K⁻¹ · [u, v, 1]ᵀ
自车系：  P_ego = R_{ego←cam} · P_cam + t_{ego←cam}
```

两个必须注意的点：

- **`d` 是沿光轴的深度（z 分量），不是到光心的径向距离。** 因为 `K⁻¹[u,v,1]` 给出的是 z=1 的射线，乘 d 后 z_cam = d。这个约定在鱼眼上会出问题（见硬骨头四）。
- **有畸变时要先去畸变**，再用 `K⁻¹` 反投，否则边缘像素的射线方向是错的。

### 第二步：落格子（拍扁发生在这里）

```
i = floor((x_ego − x_min) / Δx)
j = floor((y_ego − y_min) / Δy)
超出 BEV 范围的点直接丢弃
```

**注意 z 根本没有参与索引计算。**

原论文的原话是：*assign every point to its nearest **pillar** and perform sum pooling to create a **C × H × W** tensor*。

> **pillar = 一个高度无限延伸的体素柱。**
> "拍扁"这个动作的物理含义，就是**pillar 高度无限**这个设定本身——不是某个单独的降维操作，而是网格划分方式决定的。

### 第三步：sum pooling

```
BEV[:, j, i] = Σ_{所有落入格子(i,j)的视锥点 p} Frustum[p, :]
```

**为什么是 sum 而不是 max / average**：

- **sum 保留了"命中密度"这个隐含信号**——一个格子被更多视锥点命中，说明多个像素、多个相机都认为那里有东西，数值大是有意义的；average 会把这个信息抹掉
- max 会丢掉多相机的互补信息
- **sum 配合 cumsum trick 可以避免 padding**（见下），显存友好

### 第四步：cumsum trick（实现细节，被问到能说清就够）

朴素做法要为每个 pillar 开一个定长缓冲区、padding 对齐，显存浪费严重。LSS 的做法：

```
1. 把所有视锥点按 bin id（格子编号）排序
2. 对排好序的特征做一次全局前缀和（cumsum）
3. 在每个 bin 的边界处做差分，得到该 bin 的区间和
```

反向传播也要对应实现，原论文写了自定义 autograd function。

> **记住这两步——排序 + cumsum——正是 BEVPoolv2 要消除的开销。**

### 输出

```
C × H_bev × W_bev      典型：80 × 128 × 128
```

**Splat 的输出已经是二维的 BEV 特征图（带通道），到此拍扁完成。**

## 1.4 Shoot：名字留下了，内容被换掉了

**这是所有混乱的根源，必须知道。**

LSS 原论文是一篇**运动规划**的论文。Shoot 的含义是：

> 准备 K 条候选轨迹模板，把它们"射"到 Splat 得到的 BEV 代价图上，对每条轨迹的代价求和，softmax 选出最优轨迹。

用于 3D 检测时，Shoot 这一段**整个被替换成 BEV Encoder + 检测头**。

| 阶段 | 原论文 | 检测任务中 |
|---|---|---|
| Lift | 2D 特征 → 视锥 | 相同 |
| Splat | 视锥 → BEV 平面（C×H×W） | 相同 |
| **Shoot** | **轨迹模板打分做规划** | **BEV Encoder + CenterPoint Head** |

还要知道：**时序融合不属于原始 LSS 三步中的任何一步**，它是 BEVDet4D（2022）之后才引入的。

## 1.5 白纸默写版（八步，练到能边说边画）

```
① 7 路图像 → Backbone + FPN → F (88×32×256)
② F 分两路：DepthNet → α ∈ R^D（softmax）；Context → c ∈ R^C
③ 外积 α ⊗ c → 视锥特征 N×D×H×W×C
   ⚠ 概念量，BEVPoolv2 下从不实体化
④ 每个视锥点 (u,v,d)：P_cam = d·K⁻¹[u,v,1]ᵀ → P_ego（外参）
⑤ 按 (x,y) 落格子，z 不参与 → pillar 高度无限，z 在此丢弃
⑥ 同格子内 sum pooling（原始 LSS：排序 + cumsum + 区间差分）
⑦ 输出 BEV 特征 C×H×W（80×128×128）——已是 2D
⑧ BEV Encoder → 检测头 → 3D 框
   （原论文这一段是轨迹规划，不是检测）

训练期旁路：激光多帧聚合 → 逐像素深度真值 → CE 监督 α
离线旁路：内外参固定 → 预计算 索引表 → 供 BEVPoolv2 使用
```

## 1.6 高频追问

**Q：为什么 BEVPoolv2 快 18.9 倍？**
两处开销被消除：① 视锥点→BEV 格子的**索引映射只由内外参决定**，内外参在车上固定，所以离线预计算成查找表，运行时不排序、不 cumsum；② **视锥特征张量从不显式构造**，运行时直接按索引把 `α_d · c_k` 累加进目标格子，省掉那 5GB 的中间张量。论文报告视图变换 15.5ms → 0.82ms。

**Q：在线标定更新了怎么办？**
索引表要重算。所以有在线标定的系统需要设计索引表的更新机制，或者对小幅标定漂移做容忍。

**Q：多个相机的视野重叠区怎么处理？**
两个相机的视锥点会落进同一个 BEV 格子，sum pooling 天然把它们加起来。这既是优点（互补融合）也是隐患（重叠区的响应会系统性偏大）。

**Q：BEV 网格范围和分辨率怎么权衡？**
范围越大、分辨率越细，BEV 特征图越大，后续卷积开销按面积增长。学术常用 ±51.2m / 0.8m；量产远距场景常把纵向拉到 ±100m 以上，分辨率提到 0.4m。

# 硬骨头二 · 深度为什么用分类不用回归

**完成标准**：能说出多峰、不确定性、与 splat 权重天然兼容三条。

## 2.1 三条主答案

### ① 深度歧义 / 多峰：回归会输出"平均脸"

一个像素的深度**未必唯一确定**。典型场景：

| 场景 | 为什么多峰 |
|---|---|
| **物体边缘像素** | 一个像素同时覆盖前景（车，20m）和背景（墙，80m） |
| **半透明 / 镂空** | 玻璃、铁丝网、栏杆的缝隙 |
| **反射面** | 车窗、湿路面、水面——看到的是反射的虚像 |
| **细结构** | 电线杆、路灯杆，宽度不足一个像素 |

回归一个标量深度时，L1/L2 的最优解是真值的（加权）平均：

```
真值可能是 20m 或 80m  →  回归输出 ≈ 50m
```

**50m 处既没有车也没有墙。特征被完整地涂进了空气里。**

分类可以输出双峰分布：`α_20 ≈ 0.5, α_80 ≈ 0.5`，特征被拆成两半分别落到两处——**至少有一半是对的**。

### ② 不确定性可表达

分布本身就携带置信度：

- 峰值高、熵低 → 模型很确定
- 分布平坦、熵高 → 模型不确定

回归输出一个标量，**没有任何位置能表达"我不确定"**。除非额外加一个方差头（即异方差回归），但那又要重新设计损失。

在 LSS 里这个性质还有一层实际作用：**不确定时特征被自动摊薄**，响应变弱，下游检测头拿到的置信度自然就低——这是一个天然的、不需要额外设计的降级机制。

### ③ 与 splat 天然兼容 ← **这条最关键，也最容易被漏掉**

Splat 需要的是一个权重：**"这条视线上的 D 个位置，各分多少特征？"**

softmax 出来的深度分布 `α`，**本身就是这个权重**，且满足 `Σα_d = 1`（特征总量守恒）。不需要任何额外设计。

反过来看：如果 DepthNet 回归一个标量深度 `d̂`，你还得**自己造一个分配核**——比如在 `d̂` 处放一个高斯核 `exp(−(d−d̂)²/2σ²)`。那么：

- `σ` 怎么定？固定值？还是再学一个？
- 核的形状是不是应该随场景变？
- 这个核不可学，是人为先验

**分类式深度把"分配权重"这件事变成了网络直接学的东西，省掉了一整层人为设计。**

## 2.2 另外两条（讲完三条后可以补）

### ④ 训练稳定性

远距的激光监督极其稀疏（见硬骨头四）。在少量样本上：

- L1/L2 的梯度与误差成正比（L2）或恒定（L1），**几个坏真值就能把训练带偏**
- 交叉熵作用在概率分布上，梯度天然有界

### ⑤ 输出天然有界

softmax 保证结果落在预设的 `[d_min, d_max]` 内。回归可能输出负深度、或远超探测范围的值，需要额外裁剪。

## 2.3 深度 bin 怎么划分（必被追问）

设范围 `[d_min, d_max]`，划成 D 个 bin：

| 方式 | 公式 | 特点 |
|---|---|---|
| **UD**（均匀） | `d_i = d_min + i·(d_max−d_min)/D` | 近处过密、远处过疏 |
| **LID**（线性递增） | `d_i = d_min + (d_max−d_min)·i(i+1)/(D(D+1))` | bin 宽随距离线性增长 |
| **SID**（对数） | `d_i = d_min·(d_max/d_min)^{i/D}` | 递增更激进 |

**为什么远处的 bin 应该更宽**：

1. 远处深度本来就估不准，硬要 0.5m 的分辨率是在浪费模型容量；
2. **像素误差到深度误差的放大倍数随距离平方增长**——同样 1 个像素的视差误差，10m 处对应几厘米，100m 处对应好几米。既然物理上就分辨不了，bin 划这么细没有意义。

LSS 原文用的是 UD（`[4, 45]`，间隔 1m，D=41）。BEVDepth 系常用 `[2, 58]` 间隔 0.5m（D=112）。量产长距场景会拉到 150m 以上并改用 LID。

## 2.4 训练细节（这几条能答上会很加分）

**软标签 vs one-hot**
真值深度往往落在两个 bin 之间。用 one-hot 会丢掉亚 bin 精度，常见做法是**在相邻两个 bin 上做线性插值**得到软标签。

**没有激光点的像素怎么办**
mask 掉，不参与 loss。**mask 比例通常 >80%**，所以 loss 归一化要按有效像素数，不能按总像素数——否则梯度量级会随点云密度波动。

**深度 loss 与检测 loss 的权重**
BEVDepth 里深度 loss 是辅助监督，与检测 loss 加权求和。权重过大会让网络过度拟合激光的稀疏分布，反而伤检测。

## 2.5 反问准备

**Q：那为什么不做 soft-argmax，把分布转回连续深度？**

可以，某些工作确实这么做。但两个问题：

1. **soft-argmax 就是求期望，多峰时又回到了"平均脸"问题**——20m 和 80m 双峰，期望还是 50m；
2. **LSS 需要的本来就是分布本身**，转成标量之后还得再造一个分配核撒回去，绕了一圈。

soft-argmax 适合"只要一个深度图"的任务（如单目深度估计），不适合 LSS 这种"要把特征按深度分配出去"的任务。

# 硬骨头三 · 深度是整条链的命门

**完成标准**：能说清"深度歪 → 特征涂错格子 → 检出不稳 / 位置跳变 / 凭空误检"。

## 3.1 因果链（一句话版）

> LSS 路线下，**图像特征最终落在 BEV 的哪个格子，完全由 DepthNet 预测的深度分布决定**。深度估歪了，特征就被涂到错误的格子里——**后面的检测头无论多强都救不回来**。

## 3.2 定量：误差有多大

设 100m 处深度相对误差 10%：

```
深度误差            = 10 m
BEV 网格分辨率      = 0.4 m
→ 错位             = 25 个格子
→ 相当于           ≈ 2.2 个车身长度（车长 4.5m）
```

**纵向 vs 横向误差的不对称**（这个对比很能说明问题）：

| 维度 | 主要误差来源 | 100m 处的典型量级 |
|---|---|---|
| **纵向（前后）** | **深度估计** | **米级** |
| 横向（左右） | 图像上的 2D 定位 | 分米级 |

横向误差怎么算：焦距约 1000 像素时，100m 处 1 个像素 ≈ 0.1m 横向。2D 框定位偏 5 像素 = 0.5m。

> **所以 BEV 3D 检测里，纵向误差比横向误差大一个数量级，而它几乎全部来自深度。** 这也解释了为什么"中远距位置不稳"这个问题，唯一有效的解法方向就是深度。

## 3.3 三种失效表现的机理

直接对应硬骨头一里深度分布的三种情形：

### 表现一：位置跳变 / 检出不稳

**机理**：深度分布**尖锐但位置错**，且**帧间的错法不一致**。

第 t 帧峰值在 60m，第 t+1 帧跳到 68m —— BEV 上目标框就前后跳。规控看到的是一个位置不断抖动的障碍物，轨迹预测跟着抖，控制指令跟着抖，乘客体感就是车在"犹豫"。

### 表现二：远距漏检

**机理**：深度分布**平坦**，特征被摊薄到十几个 bin 上。

```
理想：α_60 = 0.9  → 60m 那个格子拿到 90% 的特征
实际：α 平摊在 50–80m 的 15 个 bin 上 → 每个格子只有 6%
```

任何一个格子的响应都达不到检测阈值 → 漏检。**而且这个失效在近距完全看不出来**（近距深度好估），只在远距爆发。

### 表现三：凭空误检

**机理**：多个像素的深度**同时错到同一个位置**，在那里累积出一个本不该有的强响应。

为什么会"同时错到一处"——因为深度估计的误差不是独立随机的，**同一个纹理区域的像素往往一起错**。护栏、前车尾气、地库立柱的纹理与车相似，DepthNet 给出的深度也相似，于是这些错误特征在 BEV 上叠加成一个"车形"的响应。

**这就是凭空误检最常见的成因，也是它为什么难治**——它不是检测头的判别问题，是特征在空间上就被摆错了位置。

## 3.4 为什么检测头救不回来（必须能讲清）

关键在于：**这不是可分离的噪声，是空间错位。**

检测头看到的输入只有 BEV 特征图。图上 60m 处有一个强响应，检测头**没有任何信息**能判断"这个响应本该在 68m"。信息在进入检测头之前就已经损坏了。

**类比**：印刷时颜色套印错位。后期无论怎么调色调锐度，都修不回来——因为错的是位置不是颜色。

## 3.5 与其他误差源的对比

| 误差源 | 特性 | 能否被后端补偿 |
|---|---|---|
| 标定误差 | 系统性、固定偏移 | ✓ 在线标定可修正 |
| 时间同步误差 | 与车速相关的系统偏移 | ✓ 可按位姿补偿 |
| **深度估计误差** | **随机、随距离增长、空间相关** | **✗ 不可** |

## 3.6 这条在你的项目叙事里的位置

这是你**整个项目一叙事的支点**——它解释了为什么你把最多精力投在深度上，而不是去改检测头或者加数据。

标准说法：

> 我们走的是 LSS 路线，图像特征最后落在 BEV 的哪个格子，完全由 DepthNet 预测的深度分布决定。深度估歪了，后面的检测头是救不回来的。所以我先做分距离段评测确认劣化出在中远距，然后顺着深度这条线找原因，做了三件事：深度真值加密、DepthNet 加深接 CRF、LSS 投影换 BEVPoolv2 把省下的时延投给更重的 DepthNet。

# 硬骨头四 · 深度真值生成的四个坑

**完成标准**：运动补偿、动态目标拖影、遮挡剔除、鱼眼独立投影，四条都能展开。

## 4.0 基础流程与"为什么需要加密"

### 基础流程

```
激光点云（自车系）
   ↓ 外参：P_cam = R_{cam←ego}·P_ego + t
相机系 3D 点
   ↓ 内参投影：[u,v] = K·P_cam / z_cam
图像平面 (u, v, d=z_cam)
   ↓ 按 bin 边界离散化
深度 bin 索引
   ↓ 交叉熵
监督 DepthNet 的 α
```

### 单帧有多稀疏（这个数字要能说出来）

```
一帧激光点数           10–20 万
图像分辨率 1600×640    ≈ 102 万像素
理论覆盖上限           ≈ 10–20%
减去视场外、遮挡剔除后  实际 < 5%
```

更要命的是**垂直方向的线束发散**：激光的垂直角分辨率固定（如 0.2°），到了 60m 外，相邻线束的间隔就超过 1m——投到图像上是**几条离散的横线**，中间大片没有监督。

> **结论：中远距几乎没有深度监督信号。而中远距恰恰是问题最集中的距离段。** 这就是"深度真值加密"这件事的全部动机。

### 解法：多帧聚合

聚合 5–10 帧（0.5–1 秒），有效覆盖率可以提到 20–30%，远距点数增加数倍。**但直接叠会引出下面四个坑。**

---

## 4.1 坑一 · 运动补偿

### 问题

历史帧的点云是在**历史时刻的自车坐标系**下记录的。车在动，所以必须先把它们对齐到当前帧坐标系：

```
P_current = T_{current ← history} · P_history
```

`T` 来自定位模块（IMU + 轮速 + GNSS/RTK，或 SLAM）。

### 两级补偿（很多人只知道第一级）

| 级别 | 补偿什么 | 量级 |
|---|---|---|
| **帧间位姿补偿** | 相邻帧之间车辆的运动 | 10Hz 下，120km/h 时每帧 3.3m |
| **激光自身扫描畸变** | 激光旋转一圈期间车辆的移动 | 一圈 100ms，120km/h 时车已开出 3.3m |

第二级容易被忽略：**同一"帧"点云里，先扫到的点和后扫到的点，是在自车不同位置采集的**。不做去畸变，一帧点云本身就是扭曲的。做法是按每个点的时间戳插值位姿，逐点补偿。

### 误差影响

位姿误差直接体现为**点云重影**——同一堵墙在聚合后变成两堵，深度真值被污染。定位精度 5cm 的误差在聚合 10 帧后可能累积到几十厘米。

### 聚合几帧？

权衡：

- 帧数少 → 不够密，加密效果有限
- 帧数多 → 位姿误差累积、动态目标拖影更严重、计算成本上升

实践上常见 5–10 帧。

---

## 4.2 坑二 · 动态目标拖影（**实际做的时候最花时间的一块**）

### 问题量化

静态背景对齐后完全重合，没问题。但**运动中的目标会拖出一条长尾**：

```
一辆 60 km/h 的车 = 16.7 m/s
聚合 1 秒（10 帧）
→ 拖影长度 16.7 m
→ 车长只有 4.5 m
→ 拖影是车身的 3.7 倍
```

投到图像上，这条 16.7m 长的"深度带"是**完全错误的监督信号**——它告诉网络"这一片区域从 20m 到 37m 都有物体"。

而且**动态目标恰恰是检测最关心的对象**，在它身上给错监督，代价最大。

### 三种处理方式

| 方式 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **剔除** | 用真值 3D 框框住动态目标，把框内的历史帧点全删掉 | 简单可靠，绝不会引入错误监督 | 动态目标区域退回单帧稀疏度 |
| **单独补偿** | 按目标自身速度把历史点搬到当前位置 | 保留了密度 | **依赖速度真值精度，而速度真值是位置差分出来的、噪声大**（见下） |
| **混合** | 高置信度跟踪的目标做补偿，其余剔除 | 平衡 | 实现复杂，要定阈值 |

### 单独补偿为什么不好做

速度真值的来源是**相邻帧位置差分**：

```
位置真值误差 ±10cm
Δt = 0.1s
→ 速度噪声 = 0.1m / 0.1s = 1 m/s = 3.6 km/h
```

用一个有 3.6km/h 噪声的速度去补偿 1 秒的运动，会引入约 1m 的位置误差——**补偿完可能比不补偿更糟**。

> 这条和你项目一里"速度 loss 改 Smooth L1"是同一个根因（速度真值噪声大），可以串起来讲。

### 还有一个细节坑

用 3D 框剔除时，**框的边界附近点的归属是模糊的**。框标得稍大，会把车底下的地面点也一起删掉，在图像上形成一个空洞；框标得稍小，车身边缘的点会残留成拖影。实践上常对框做轻微收缩或膨胀，具体值要实验确定。

---

## 4.3 坑三 · 遮挡剔除

### 问题

聚合后的点云是一个**稠密的静态场景重建**，它包含**从当前视角看不见的点**。

具体地：激光在多个时刻从不同位置扫描，能看到当前时刻被遮挡的区域。这些点投影到当前图像时，会**穿透前景**落到同一个像素上。

```
例：前车在 5m 处，前车后面的墙在 50m 处
两者投到同一个像素 (u, v)
→ 这个像素同时有 5m 和 50m 两个"真值"
```

如果不处理，深度真值就是错的——网络会被教"这个前车表面的像素，深度是 50m"。

### 处理方式

**① z-buffer（基础做法）**

同一像素只保留**最近**的那个深度。这是图形学的标准做法。

**② 局部深度一致性检验（z-buffer 不够时的补充）**

问题在于**激光点是稀疏的，前景可能"漏"过去**——前车表面在某个像素恰好没有激光点，后面的墙点就穿过来了，z-buffer 也拦不住（因为没有更近的点可比）。

补充做法：在小邻域内（如 5×5 像素）算深度中位数，**如果某点深度显著大于邻域中位数，判为穿透点剔除**。

**③ 视差问题（容易被忽略）**

激光和相机**不同轴**（安装位置不同）。激光能看到的区域，相机未必能看到，反之亦然。基线越大，视差越明显，近距离物体尤其。严格做法要考虑两个传感器的可见性差异。

## 4.4 坑四 · 鱼眼独立投影

### 根本原因：投影模型完全不同

| 模型 | 公式 | θ→90° 时 |
|---|---|---|
| **针孔** | `r = f · tan θ` | **发散到无穷** |
| 等距（equidistant） | `r = f · θ` | 有限 |
| 等立体角（equisolid） | `r = 2f · sin(θ/2)` | 有限 |
| 体视（stereographic） | `r = 2f · tan(θ/2)` | 有限 |

其中 `θ` 是入射光线与光轴的夹角，`r` 是像点到主点的距离。

鱼眼 FOV 常达 190°，即 `θ` 接近甚至超过 90°。**针孔模型在这里数学上就不成立**——`tan 90° = ∞`。

**工程上最常用的是 Kannala-Brandt（KB）多项式模型**（OpenCV `cv::fisheye`）：

```
θ_d = θ · (1 + k₁θ² + k₂θ⁴ + k₃θ⁶ + k₄θ⁸)
r   = f · θ_d
```

### 为什么不能复用针孔的投影代码

投影函数 `π(·)` 和反投影 `π⁻¹(·)` 都不一样：

- **正向投影**（点云 → 图像）：针孔是 `K·P/z`，鱼眼要先算 `θ = atan2(√(x²+y²), z)`，代入多项式得 `θ_d`，再算像素坐标
- **反投影**（像素 → 射线）：针孔是 `K⁻¹[u,v,1]`，鱼眼要解多项式的逆（通常用牛顿迭代）

### 还有一个更隐蔽的差异：深度的定义

| | 深度 `d` 的定义 |
|---|---|
| 针孔 | **沿光轴的 z 分量**（因为 `K⁻¹[u,v,1]` 给出 z=1 的射线） |
| 鱼眼 | 更自然的是**到光心的径向距离** `‖P‖`（因为鱼眼的"视线"是从光心发散的球面） |

如果鱼眼支路沿用针孔的"z 分量"定义，**边缘视场（θ 接近 90°）的 z 分量趋近于 0**，深度 bin 划分完全失效。

> **所以鱼眼支路不只是"换个投影公式"，深度的定义、bin 的划分范围都要重新设计。** 这也是为什么很多方案干脆让鱼眼走 transformer 的 PV2BEV——注意力机制不依赖显式的投影几何，绕开了这一整套问题。

---

## 4.5 另外两条必被追问的

### 真值落在两个 bin 之间怎么办

one-hot 会丢掉亚 bin 精度。常见做法是**在相邻两个 bin 上做线性插值软标签**：

```
真值 d = 20.3m，bin 边界 20.0 / 20.5
→ label[bin_20.0] = 0.4，label[bin_20.5] = 0.6
```

### mask 的归一化

有效像素（有激光点的）通常 <20%，loss 必须**按有效像素数归一化**，不能按总像素数——否则梯度量级会随点云密度、场景开阔程度剧烈波动，训练不稳。

## 4.6 完整伪代码（能默写出骨架就够）

```python
def make_depth_gt(cur_frame, hist_frames, calib, gt_boxes):
    pts = [cur_frame.points]

    for f in hist_frames:
        p = f.points
        p = undistort_scan(p, f.per_point_timestamps, f.poses)   # 坑一·扫描畸变
        p = transform(p, T(cur_frame.pose, f.pose))              # 坑一·帧间位姿
        p = handle_dynamic(p, gt_boxes, mode='remove_or_compensate')  # 坑二
        pts.append(p)

    pts = concat(pts)

    for cam in calib.cameras:
        p_cam = to_camera(pts, cam.extrinsic)
        p_cam = p_cam[p_cam.z > 0]                    # 相机后方剔除

        if cam.is_fisheye:
            uv, d = project_fisheye(p_cam, cam.KB)    # 坑四
            # d 用径向距离而非 z
        else:
            uv, d = project_pinhole(p_cam, cam.K, cam.dist)

        uv, d = zbuffer(uv, d)                        # 坑三·同像素取最近
        uv, d = filter_penetration(uv, d, win=5)      # 坑三·邻域一致性

        bin_idx, soft = discretize(d, mode='LID', soft=True)  # 4.5
        depth_gt[cam] = (bin_idx, soft, valid_mask)

    return depth_gt
```
