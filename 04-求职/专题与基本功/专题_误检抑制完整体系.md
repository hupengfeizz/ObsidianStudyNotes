# 专题 · BEV 感知的误检抑制完整体系

> 面试官问「对于误检，你还有什么优化方案」时，答「难例挖掘回灌」只是其中一层。
> 本篇按 **成因 → 三档归属 → Loss 层面 → 阈值澄清 → 代价 → 问答** 组织。
>
> **三档归属是全篇的关键**：
> 🟦 **基线自带** —— BEVFusion / CenterPoint / LSS 本来就有，不能说成自己的
> 🟩 **自研架构** —— 这个模型特有、开源没有，但**不是你做的**，讲价值 + 划边界
> 🟨 **你做的** —— 可以完整认领、深入展开
>
> ⚠️ 标【需核实】的按实际实现确认。

# 第一部分 · 为什么会误检

## 一个关键认知：误检不是一个问题

「凭空误检」是**表象**——前方没有目标，模型输出了一个框。但导致这个表象的成因至少五种，它们在网络的不同位置发生，需要不同的对策。**混为一谈，就只能想到"多喂点负样本"这一条路。**

## 五种失效模式

### 模式一 · 特征层面：纹理被编码成了类车特征

护栏的横条纹理、地库闸机的立柱、前车尾气的团状轮廓，在低层特征上和车辆确实相似。

**特点**：在图像空间就已经错了，深度和融合都没问题，是"看错了"。

### 模式二 · 深度层面：特征被涂到了错误的格子

LSS 路线下，图像特征落在 BEV 哪个格子由深度分布决定。深度估错，特征就被涂到不该去的地方——**那个位置本来什么都没有，却凭空得到了一份类车特征**。

**特点**：纯视觉 BEV 特有，2D 检测里不存在。远距尤其严重。

### 模式三 · 表征层面：BEV 拍平丢掉了高度

压扁之后，**一根护栏立柱和一辆车在 BEV 上占的都是一小块区域**——区分它们的高度信息已经没了。

**特点**：柱状、杆状物的误检特别顽固。这也是 Occupancy 路线想解决的问题之一。

### 模式四 · 监督层面：难负样本天然稀缺

长尾场景平时跑十万公里也遇不上几次，训练集里天然就缺。模型从没见过"这种纹理不是车"的反例。

**特点**：整体指标看不出来，只在特定场景爆发。

### 模式五 · 时序层面：单帧判定缺少一致性约束

真实目标进入视野后会持续存在，凭空误检没有真实物体支撑，**突然出现、维持几帧、又突然消失**。每帧独立判定，这个差异就用不上。

**特点**：这是误检最可利用的特征——自动挖掘判据的基础。

# 第二部分 · 三档归属

## 🟦 第一档 · 基线自带（不能说成自己的优化）

| 机制 | 出处 | 对误检的作用 |
|---|---|---|
| **多模态融合** | BEVFusion 的定义性特征 | 相机误检处激光/毫米波无几何证据，融合后置信度被压。**这是最本质的误检抑制，但它是架构定义，不是优化** |
| **GaussianFocalLoss** | CenterPoint 标配 | BEV 网格十万个位置、真目标几十个，负样本占 99.9%+。没有它梯度会被易分负样本淹没 |
| **topK 稀疏回归** | CenterPoint 标配 | 只有分数最高的 128~256 个位置进入回归，低分凭空响应天然被截断 |
| **NMS 后处理** | 标配 | 去重。BEV 下比图像简单——俯视矩形没有透视遮挡歧义 |
| **时序融合** | BEVDet4D 系标配<br>（BEVFusion 原版无时序） | 真实目标三帧相互增强，偶发响应被稀释 |
| **置信度阈值** | 标配 | 截断低分输出。**见第四部分，它是调节旋钮不是解决方案** |

> **讲这一档的价值**：说明你分得清什么是基线。**主动先划这条线，后面讲自己做的部分才可信。**

## 🟩 第二档 · 自研架构（开源没有，但不是你做的）

从 `BCGOneNet_网络架构分析` 读出的九处设计。**前两处是专门为误检做的**，其余是有明确误检收益。

### 🔴 ① TrackHeadRe 的 valid / invalid 二分类 —— 最直接的一条

```
分类头              MLP(128 → 128 → 2)   区分有效 / 无效跟踪
loss_cls           CrossEntropy（valid / invalid 二分类）
det_score_thresh   0.25
activate_neg_score 2.0        ← 负样本激活
Embedding 维度      128        最大 ID 数 513    Memory 时间窗 2 秒
```

**这是模型内部对"这个检出是不是误检"的显式建模。**跟踪头不只做 ID 匹配，还专门学一个二分类判断轨迹有效性，并且有独立的负样本激活分数。

**BEVFusion 连跟踪头都没有**，更没有这个。这是把误检判别做进网络的机制，不是后处理规则。

### 🔴 ② 深度监督的 `use_projected_only: True`

```
discretize_mode     UD（均匀离散化）
enable_focal_loss   True   (alpha 0.25, gamma 2.0)
fg_weight  13       bg_weight  1
use_projected_only  True         ← 关键
```

**只在有激光点投影到的像素上算 depth loss。**没有激光点的像素完全不参与监督——**避免在无监督区域学出任意深度，进而在 BEV 上凭空产生响应**（模式二误检）。

`fg_weight 13 : bg_weight 1` 再叠 focal，是深度监督自己的前景聚焦。BEVDepth 原版没有这么细的配置。

### 🟡 ③ 近处辅助检测头的类别权重设计

```
类别 loss 权重      [0.1, 0.1, 5.0, 5.0, 0.1, 0.1]
                    CAR  TRUCK  PED   CYC  HEAD CONETANK
loss_heatmap_only   True        （只出热图，不做回归）
聚焦区域            自车正前方 0~10m
```

行人骑行人给 5.0、车只给 0.1。**一方面强化近处 VRU 的热图监督**（近处 VRU 漏检是安全问题），**另一方面刻意不让这个辅助头在车类上产生强响应**——避免和主检测头冲突、产生重复或虚假检出。

### 🟡 ④ dustbin（针孔 100+1、鱼眼 32+1）

原版 LSS 是 D 个 bin 的 softmax，**没有 dustbin**。

softmax 强制概率和为一。天空、超范围远景、完全遮挡区域**根本没有有效深度**，不给出口的话概率会被硬摊到真实 bin 上——等于把一份没意义的特征涂进 BEV 某个格子。

加 dustbin 之后这些像素把概率放进去，投影前切掉，**不参与 splat**。

```
无 dustbin：天空像素 → softmax 必须分配 → 摊到 30~40m 的 bin → BEV 凭空多一份特征
有 dustbin：天空像素 → 概率进 dustbin → 切掉 → 不参与投影 → BEV 干净
```

### 🟡 ⑤ TempInstance 实例级时序增强

```
Embedding 维度      128
num_propagated      256（每帧传播数量）
历史时间间隔        [1, 2, 3, 4] 帧
post_center_range   [-83.8, -44.8, -1, 95.4, 44.8, 5]
机制                当前帧实例 embedding 与历史帧做 cross-attn + self-attn
```

**是实例级的，不是特征级的。**特征级时序（BEVDet4D 那种）是把 BEV 特征图对齐相加；实例级是把检出的目标 embedding 在时间上关联增强。后者对"活不长的假目标"更敏感。

### 🟡 ⑥ post_center_range 硬性范围过滤

`[-83.8, -44.8, -1, 95.4, 44.8, 5]` —— 后处理阶段直接丢掉中心超出范围的检出。

### 🟡 ⑦ gaussian_sigma 按类别定制

```
gaussian_sigma  [-1, -1, 0.6, 0.65, -1, -1, -1, -1]
                CAR TRUCK PED  CYC  HEAD CONETANK
gaussian_overlap 0.1    min_radius 2
```

**只有行人 0.6、骑行人 0.65 设了自定义值，其余用默认。**CenterPoint 默认是统一的按尺寸自适应。

小目标的高斯半径如果不单独调小，相邻目标的高斯会重叠、中心位置模糊，**在两个真目标之间产生虚假峰**。

### 🟡 ⑧ rot_lidar 分支 + `use_lidar_rt: True`

检测头有一个 `rot_lidar` 分支（LiDAR 坐标系旋转），配置里 `use_lidar_vel: True`、`use_lidar_rt: True`。**用 LiDAR 的旋转平移观测**，让朝向和速度向激光几何对齐。

### 🟡 ⑨ dir_cls 方向分类分支

解 sin-cos 的前后 180° 歧义。**朝向反了会把静止车判成迎面来车**，对下游的后果和误检同级。

### 对照表

| 机制 | BEVFusion 基线 | 自研模型 | 针对误检的程度 |
|---|---|---|---|
| 跟踪 valid/invalid 二分类 | 无跟踪头 | ✅ | 🔴 **直接、显式** |
| depth `use_projected_only` | 无 | ✅ | 🔴 **阻断无监督区虚假深度** |
| 近处头类别权重设计 | 无近处头 | ✅ | 🟡 |

## 🟨 第三档 · 你做的（可以完整认领）

| 手段 | 治哪种模式 | 开源基线有吗 | 你的价值 |
|---|---|---|---|
| **时序判据自动挖掘 + 专项集回灌** | 模式四 + 利用模式五 | 无（属数据工程） | 判据设计、分层挖掘、双重质量关，整条链你走完 |
| **空图负样本抑制过度泛化** | 模式四 | 无 | 补上自动判据挖不到的长尾 |
| **PV 辅助监督** | 模式一 | BEVFusion/BEVDet 系**无**；BEVFormerV2 提过 perspective supervision | 不是首创，但**落地到 dense BEV 这条线**，并处理了论文不碰的工程问题——反投目标的遮挡过滤与降权 |
| **深度监督加密（多帧点云聚合）** | 模式二 | BEVDepth 是**单帧**激光生成真值 | 多帧运动补偿聚合、动态目标处理、遮挡剔除 |

> **深度监督加密要注意因果**：它的主要目标是提升中远距精度，但**深度准了，模式二的误检连带减少**——是同一条链上的连带收益，不是为误检专门做的。这么说比硬扯成误检方案更可信。

# 第三部分 · Loss 层面能怎么治误检

## 一个前提：loss 和数据是配套的

**loss 层面所有手段都有同一个前提——训练集里得有那些负样本。**

如果训练集里根本没有护栏被误检的样本，再怎么调 loss 权重都没用，**因为梯度无处施加**。

```
数据侧决定「有没有这些反例」
Loss 侧决定「这些反例的梯度权重有多大」
```

**这个因果关系讲出来很加分**——它说明你知道两者不能互相替代。

## 六条路径

### 1. 分类损失的负样本加权（最直接）

heatmap 分类 loss 里，对**难负样本**单独加权。你在项目四踩过完整的坑：

> Focal Loss 的机制是 `(1−p)^γ` 降低易分样本权重。但在一个已收敛的高置信度模型上追加，绝大部分样本置信度都很高，这一项把权重压到接近零，**有效参与训练的样本数急剧萎缩、梯度方差爆炸**，训练直接崩。
>
> 改用**定制 BCE 针对硬 FP 单独加权**，梯度尺度可控。

**这段经验可以直接迁移到 BEV 场景讲**——它说明你不只知道 Focal Loss 是什么，还知道它什么时候不work。

### 2. OHEM 在线难例挖掘

训练时只对损失最大的那部分负样本回传梯度。和第 1 条的区别：Focal Loss 是**软加权**（连续降权），OHEM 是**硬选择**（只取 top-k）。

项目四用过，配合难负样本库和分阶段训练。

### 3. 空间 / 区域加权

对特定区域的负样本加权。架构里近处头的类别权重 `[0.1, 0.1, 5.0, 5.0, 0.1, 0.1]` 就是这个思路——**在特定区域对特定类别定制权重**。

同理可以对误检高发区域（路侧护栏带、地库闸机位置）做负样本加权。【这个是可提但未做的方向】

### 4. 跨模态一致性约束

**用激光特征监督 heatmap** ——本质是一个跨模态一致性 loss：要求模型**只在有几何证据的地方给高响应**。

内部视频原话：「主要是用来监督了这个 heatmap，就是想让这个出框的时候进一步的贴激光。」

相机看错但激光没有支撑的位置，heatmap 响应被这条 loss 压低。

### 5. 时序一致性约束

惩罚"这一帧有、下一帧没有"的不稳定响应。**TrackHeadRe 的 valid/invalid 二分类就是这个思路的实例化**——它显式地学"这条轨迹是不是有效的"。

### 6. 深度 loss 的改造

```
use_projected_only  只在有激光点的像素算 loss   → 阻断无监督区虚假深度
fg_weight 13 : 1    深度前景聚焦
enable_focal_loss   深度 bin 之间也是极度不平衡的分类问题
```

### 7. 辅助 loss（PV 监督）

给图像端一条直接的梯度通路，从**特征判别力**这个源头减少模式一的误检。推理零开销。

## 可提但未做的 loss 方向

- **特征空间的 margin / 对比损失**：让"护栏特征"和"车特征"在特征空间拉开距离，而不只是在分类边界上分开
- **不确定性建模**：让模型输出置信度的同时输出不确定性，对高不确定的检出降权

# 第四部分 · 「调阈值」到底指什么

## 它不是 loss，是推理后处理的一个数

**「调阈值」在误检语境下特指推理时的置信度阈值（score threshold）。**

架构材料里就写着：`det_score_thresh: 0.25`

检测头输出的每个框都带一个置信度（heatmap 峰值过 sigmoid，0~1）。后处理时低于这个阈值的框直接丢掉。「调阈值」就是把 0.25 调到 0.30、0.35。

## 和 loss 的根本区别

| | 置信度阈值 | Loss |
|---|---|---|
| 作用时机 | **推理后处理** | **训练** |
| 改了要重训吗 | **不用，立刻生效** | 要 |
| 改变模型能力吗 | **不改变**，只是截断输出 | 改变 |
| 代价 | 等比例掉召回 | 训练成本 |

**这是最容易混的一处。**阈值是"输出端的闸门"，loss 是"训练时的指挥棒"。

## 为什么阈值治不了本

**误检和真实的远距弱小目标处在同一个低分区间**——一百米外的行人、被部分遮挡的车，置信度本来就不高。阈值一提，误检降了，这些目标跟着一起丢。这就是"跷跷板"。

而且它**不改变模型的判别能力**，只是把问题从"输出了错的"变成"少输出了对的"。在量产准入「全评测项无恶化」的规则下，用掉召回换误检的方案根本过不了。

> **阈值是最后的校准旋钮，不是根治手段。**

## 五种「阈值」的区分 —— 只有第一种才是「调阈值」说的那个

| # | 名称 | 在哪 | 调它影响什么 |
|---|---|---|---|
| **①** | **置信度阈值** `det_score_thresh` | 推理后处理 | ✅ **「调阈值」说的就是它**。误检 ↔ 漏检的跷跷板 |
| ② | NMS 的 IoU 阈值 | 推理后处理 | 多近的框算重复。影响的是**重复框**，不是凭空误检 |
| ③ | 评测匹配阈值（3D IoU / 中心距） | 评测脚本 | 只是**评测口径**，模型输出一个字没变 |
| ④ | 正负样本分配阈值 | 训练 | CenterPoint 里体现为高斯半径 / `gaussian_overlap` / `min_radius`，属训练配置 |
| ⑤ | 深度 bin 边界（`discretize_mode`） | 训练 + 推理 | 深度离散化粒度，和误检无直接关系 |

**①是答案，②③④⑤是"别跟它搞混的"。**

三个最容易出错的混淆：

- **①↔② 混淆**：以为"调阈值"是调 NMS。NMS 治的是同一个目标出多个框，凭空误检本来就只有一个框，NMS 拦不住。
- **①↔④ 混淆**：以为"调阈值"是调训练时的正负样本划分。那个要重训，而①改了立刻生效。
- **①↔loss 混淆**：以为"调阈值"是调损失函数。见上一节的对照表。

**被问到时先确认对方问的是哪个**，别默认。真人面试官说"阈值"九成指①，但 AI 面试官和笔试题里问②④的也不少。

# 第五部分 · 代价对照表

|---|---|---|---|---|---|

| NMS | 🟦 基线 | 重复框 | **有**（密集场景） | 低 | 0 |

| 跟踪 valid/invalid | 🟩 自研 | 五 | **有**（新目标延迟） | 低 | 低 |
| depth use_projected_only | 🟩 自研 | 二 | 无 | 0 | 0 |
| dustbin | 🟩 自研 | 二 | 无 | ~0 | ~0 |
| TempInstance | 🟩 自研 | 五 | 无 | 中 | 中 |

| **空图负样本** | 🟨 你的 | 四 | **有**（过度抑制） | 0 | 低 |

**三个结论：**

1. **越靠"提升判别能力"的手段，掉召回风险越低**；越靠"截断输出"的，风险越高。
2. **PV 辅助监督性价比最高**：推理零开销、不掉召回、直接治最常见的模式一。
3. **置信度阈值是唯一一个高风险零收益的**——它不提升任何能力，纯粹拿召回换误检。

# 第六部分 · 配套问答

## Q · 对于误检，你有哪些优化方案？

`口语`　误检不是一个问题，是几种不同的失效模式共用了同一个表象，所以对策分散在不同层次上。我先说清楚哪些是架构本来就有的，再说我做的。

　　**架构层面**，最本质的是多模态融合——相机在护栏、闸机那儿误检，激光在那个位置没有车体那样的连续曲面，毫米波也没有对应回波，融合之后这个位置缺少几何支撑，置信度被压下去。这是 BEVFusion 这条路线的定义性特征，不是优化。另外检测头那边 CenterPoint 自带的 GaussianFocalLoss 和 topK 也在压误检——十万个 BEV 格子里真目标只有几十个，负样本占九成九以上，没有这两个机制梯度会被淹没。

　　**我们模型特有的**有两处比较直接：跟踪头里有一个 valid/invalid 的二分类，显式判断一条轨迹是有效目标还是误检；深度监督那边有个 `use_projected_only`，只在有激光点的像素上算 loss，避免在没有监督的地方学出任意深度、进而在 BEV 上凭空出响应。这些是架构既有的，不是我做的。

　　**我做的集中在数据和监督两侧。**数据侧是主线：用时序判据从数据湖自动挖凭空误检的难例，分场景分层挖保证多样性，回灌之后跑全量回归确认没伤召回；另外配空图负样本抑制过度泛化。监督侧是 PV 辅助监督——检测 loss 只加在 BEV 空间，回传到图像端的梯度很弱，图像特征判别力不足就分不清护栏纹理和车，反投 3D 真值到相机做 2D 辅助监督，给图像端一条直接的梯度通路，训练期生效、推理零开销。深度监督加密主要目标是提升中远距精度，但深度准了这类误检也跟着少。

`提示`　这个回答的结构是：**先划基线 → 再讲自研架构并划清不是我做的 → 最后展开我做的**。主动划边界反而让后半段更可信。

## Q · 那 loss 层面能做什么？

`口语`　能做，而且有几条路。但有个前提要先说：**loss 层面所有手段都依赖训练集里有那些负样本**——如果根本没有护栏被误检的样本，再怎么调权重也没用，梯度无处施加。所以数据侧决定"有没有反例"，loss 侧决定"这些反例的梯度权重有多大"，两者不能互相替代。

　　具体几条。**一是难负样本的加权**，这个我在上一个项目踩过完整的坑：本来想用 Focal Loss 压硬负样本，但它在一个已经收敛的高置信度模型上失效了——`(1−p)^γ` 把绝大部分样本的权重压到接近零，有效样本数急剧萎缩、梯度方差爆炸，训练直接崩。后来改成定制的 BCE 针对硬假阳性单独加权，梯度尺度可控。

　　**二是 OHEM**，训练时只对损失最大的那部分负样本回传梯度，和 Focal Loss 的区别是它是硬选择不是软加权。

　　**三是跨模态一致性约束**——用激光特征去监督 heatmap，本质上是要求模型只在有几何证据的地方给高响应，相机看错但激光没支撑的位置响应会被压低。

　　**四是时序一致性**，惩罚这一帧有下一帧没有的不稳定响应，跟踪头那个 valid/invalid 二分类就是这个思路的实例化。

　　**五是深度 loss 的改造**，`use_projected_only` 保证不在没有激光点的像素上产生任意梯度。

　　**六是辅助 loss**，就是 PV 监督，从图像特征判别力这个源头治。

## Q · 提高置信度阈值不就行了？

`口语`　不行。先说清楚这个阈值指的是推理后处理的置信度阈值，我们配置里是 0.25——它是个推理参数，改了立刻生效不用重训，和 loss 完全是两回事。

　　它治不了本，因为**误检和真实的远距弱小目标处在同一个低分区间**——一百米外的行人、被部分遮挡的车，置信度本来就不高。阈值一提，误检降了，这些目标跟着一起丢，这就是跷跷板。

　　而且它不改变模型的判别能力，只是把问题从"输出了错的"变成"少输出了对的"。我们的准入规则是全评测项无恶化，用掉召回换误检的方案根本过不了。**阈值是最后的校准旋钮，不是根治手段。**

## Q · 为什么说多模态融合是最本质的误检抑制？

`口语`　因为其他手段都是在相机支路内部想办法——提升特征判别力、修正深度、补负样本，本质上是让**同一个观测源**判断得更准。融合引入的是**独立的观测源**：激光不看纹理直接测几何，毫米波直接测径向速度。

　　相机在护栏那儿误检出一辆车，激光在那个位置只有一排细窄的点、没有车体那样的连续曲面，毫米波也没有对应的动目标回波。三个模态证据不一致，融合之后置信度自然被压下去。真实车辆三个模态一致，置信度就高。

　　所以融合的价值不只是"提升精度"，更重要的是**互相证伪**。不过要说清楚，这是 BEVFusion 这条路线的定义性特征，是架构给的，不是优化。

## Q · dustbin 和误检有什么关系？开源模型有吗？

`口语`　有直接关系，而且**原版 LSS 是没有的**——它就是 D 个 bin 的 softmax。

　　问题在于 softmax 强制概率和为一。天空、超出探测范围的远景、完全被遮挡的区域，这些像素根本没有有效深度。不给出口的话，它们的概率会被硬摊到某几个真实的深度 bin 上，等于把一份没有意义的特征涂进 BEV 的某个格子——那个格子就凭空多了响应。

　　加一个 dustbin 通道，这些像素把概率都放进去，投影之前把这个通道切掉，它们就不参与 splat。我们针孔是 100 个 bin 加一个 dustbin，鱼眼是 32 加一个。

　　这条几乎零成本，但它是模型既有的设计，不是我加的。

## Q · 跟踪能抑制误检吗？

`口语`　能，而且我们模型里做得比较显式。跟踪头除了做 ID 匹配，还有一个 valid/invalid 的二分类——**专门学"这条轨迹是有效目标还是误检"**，用交叉熵监督，还有一个独立的负样本激活分数。

　　背后的逻辑是：凭空误检天然不连续，真实目标进视野会持续存在，误检活不了几帧。一个持续被跟踪、ID 稳定的目标可信度高；一个刚出现跟不了几帧就消失的，很可能是误检。

　　有意思的是，**这和数据闭环里的挖掘判据是同一个原理的两种用法**——模型内部用它来抑制误检，数据闭环用它来把误检捞出来做训练。

## Q · 时序为什么能抑制误检？

`口语`　因为凭空误检天然不连续。我们利用这个差异有两个层面。

　　**特征层面**：三帧时序融合，真实目标在多帧里相互增强，偶发的凭空响应被稀释。这不是显式的过滤规则，是特征融合的自然结果。

　　**实例层面**：还有一个实例级的时序增强模块，把当前帧检出的实例 embedding 和历史帧的做交叉注意力，历史时间间隔取的是一到四帧。实例级比特征级对"活不长的假目标"更敏感。

## Q · PV 辅助监督为什么能减误检？开源有吗？

`口语`　它治的是最常见的那类——纹理相似导致的。护栏横条、闸机立柱、尾气团状轮廓，在图像特征上和车确实像。

　　根因是图像端监督太弱：检测 loss 全加在 BEV 空间，梯度要穿过整个视图变换才能回传到 image backbone，路径长还被深度分布稀释。图像特征判别力不足就分不清。

　　做法是把 BEV 的 3D 真值按内外参反投到各相机，取角点外接矩形作为 2D 真值，在 image backbone 后接一个轻量检测头做辅助 loss。训练期生效、推理时整条支路剪掉，零开销。

　　**这个思路不是我首创**，BEVFormerV2 提过 perspective supervision。但 BEVFusion、BEVDet 这条 dense BEV 的线上是没有的，我们的价值在于把它落地到这条线上，并且处理了论文不碰的工程问题——反投过去的目标有些在图像上被遮挡或截断，直接监督等于教模型从看不见的地方检出目标，要做可见性判断，完全不可见的丢掉、部分遮挡的降权。

## Q · 深度不准也会导致误检吗？

`口语`　会，而且这是纯视觉 BEV 特有的一类，2D 检测里不存在。

　　LSS 路线下，图像特征落在 BEV 哪个格子完全由深度分布决定。深度估错了，特征就被涂到不该去的位置——那个格子本来什么都没有，却凭空得到了一份类车特征，检测头看到就可能出框。远距尤其严重，因为远距深度最不准。

　　我们模型在这儿有个设计值得说：深度 loss 配了 `use_projected_only`，**只在有激光点投影到的像素上算 loss**。没有激光点的地方不参与监督，避免模型在无监督区域学出任意的深度，进而在 BEV 上凭空产生响应。

## Q · BEV 拍平会不会加剧误检？

`口语`　会。BEV 把三维空间沿高度压扁成二维网格，压扁之后**一根护栏立柱和一辆车在 BEV 上占的都是一小块区域**，区分它们的高度信息已经没了。

　　所以柱状、杆状物的误检特别顽固——不是模型不够强，是这个表征本身丢掉了区分它们的关键信息。检测头虽然会单独回归一个 z，但那是在已经决定"这里有目标"之后才回归的，帮不上判别。

　　这也是 Occupancy 路线想解决的问题之一，它保留了三维结构、能表达悬空物体和异形障碍物，代价是标注和算力成本高很多。

## Q · gaussian_sigma 按类别定制和误检有关吗？

`口语`　有。高斯半径决定每个真值中心周围多大范围算正样本。**半径太大，相邻目标的高斯会重叠，中心位置变模糊，可能在两个真目标之间产生一个虚假峰。**

　　我们的配置里只有行人 0.6、骑行人 0.65 设了自定义值，其余用默认的按尺寸自适应。因为行人骑行人本来就小，用和车一样的半径规则会盖住整个身体还溢出去。CenterPoint 默认是统一规则，这是我们模型定制的一处。

## Q · 这些手段里，哪些是你做的？

`口语`　我做的主要是数据闭环那一层：时序判据的设计、从数据湖自动挖掘、分层保证多样性、专项集构造和回灌验证，这条链是我走完的；还有空图负样本。监督侧的 PV 辅助监督和深度监督加密也是我做的，虽然后者的主要目标是提升中远距精度，但对误检有连带收益。

　　多模态融合、跟踪头、时序模块、检测头这些是团队既有的架构，不是我做的，但我要能讲清它们对误检的作用——不然只讲数据侧那一层，显得对这个问题的理解是片面的。

## Q · 如果让你再往下做，还能做什么？

`口语`　几个方向。

　　**一是利用高度信息。**柱状物误检的根因是 BEV 拍平丢了高度，引入 Occupancy 或者给检测头加高度一致性约束，能从表征层面改善这一类。

　　**二是把跟踪的生命周期反馈给检测。**现在跟踪在检测之后，如果让跟踪的历史置信度反过来影响当前帧的 heatmap，就形成闭环。

　　**三是 loss 层面的区域加权。**对误检高发区域——路侧护栏带、地库闸机位置——的负样本单独加权。架构里近处头的类别权重就是这个思路的一个实例，可以推广。

　　**四是特征空间的 margin 约束。**让"护栏特征"和"车特征"在特征空间拉开距离，而不只是在分类边界上分开。

　　**五是主动学习。**现在挖掘靠固定的时序判据、靠人写规则；可以用模型自身的不确定性找候选——置信度和时序一致性矛盾的样本，往往就是模型没学明白的地方。

`提示`　不需要都做过，但要说得出**每条的动机和代价**。

# 第七部分 · 面试怎么讲

## 三十秒版

> 误检不是一个问题，是几种失效模式共用了同一个表象。**架构层面**最本质的是多模态融合——相机看错的地方激光没有几何证据，融合后置信度被压；我们模型还特有两处，跟踪头有个 valid/invalid 二分类显式判断轨迹有效性，深度 loss 有个 `use_projected_only` 避免在无监督区学出虚假深度。这些是架构给的。**我做的**集中在数据和监督两侧——时序判据自动挖掘难例回灌、空图负样本，加上 PV 辅助监督提升图像判别力。

## 展开顺序

```
① 先讲成因分层        显示你理解机制，不是背清单
② 划基线（🟦）        「这些是 BEVFusion / CenterPoint 本来就有的」
③ 讲自研架构（🟩）     「我们模型特有这几处，但不是我做的」
④ 展开你做的（🟨）     你的主场，讲完整链条
⑤ 主动说阈值不行      堵住那个必然的反问
```

## 四个不要

- **不要一上来就讲难例挖掘**——那是最后一层，先讲它会显得视野只有数据这块。
- **不要把架构能力说成自己做的**——讲清价值同时划清边界，比含糊带过强得多。
- **不要漏掉代价**——每讲一个手段带一句代价，比只讲收益可信。
- **不要把"调阈值"和"调 loss"混为一谈**——前者是推理后处理参数，后者是训练目标。
