# 项目二面试逐字稿：理论、原理、逻辑保姆版

配套简历版本：《胡鹏飞简历.pdf》项目二
项目：成排锥桶检测与改道意图识别（PV 多任务共网子任务）
核心定位：帮助你讲清楚 2D 检测链路、目标定义的演进逻辑、三轮属性头迭代的因果、数据增强与真实分布的关系、共网架构的边界，以及全部追问推导的技术口径文档。

## 0. 使用方式：这份稿子到底怎么用

### 0.1 这个项目的独特价值

项目一的卖点是"链路深"，项目二的卖点完全不同——**它是一个靠"重新定义问题"而不是"堆模型"打赢的项目**。

面试官从这个项目里想验证的是：

1. 你能不能从下游需求反推感知任务该怎么定义。
2. 你有没有"方案迭代"的真实经历——试错、归因、换路线。
3. 你对 2D 检测框架（YOLO 系）的改造能力。
4. 你知不知道通用方法（mosaic、角度回归）什么时候会失效。
5. 多任务共网下你怎么在不影响别人的前提下做自己的任务。

所以这份文档的记忆重点是：

- **目标定义的演进逻辑**，而不是网络结构。
- **三轮迭代各自为什么失败/成功**，而不是最终方案长什么样。
- **每个"弃用"背后的归因**（弃 mosaic、弃点回归、弃角度回归）。
- 边界口径：共网框架是团队的，子任务是你的。

### 0.2 面试中的万能回答结构

> 现象是什么 → 下游为什么受不了 → 根因是任务定义还是模型能力 → 方案为什么对症 → 怎么验证没伤别的

逐字稿：

"这个项目我回答问题的习惯是先看下游。锥桶检测的所有指标最终都服务一件事——规控能不能提前、稳定地发起变道。所以每个问题我会先讲它对下游的影响，再分析根因是出在任务定义上还是模型能力上。这个项目比较特别的是，多数问题的根因在任务定义——检测单个锥桶这个定义本身就注定了远距检不稳、方向拟合不准，所以我们的主要优化是重新定义目标，而不是换更大的模型。"

### 0.3 本项目的一句话主线

逐字稿：

"这个项目从头到尾没有换过网络结构，就是 YOLO 框架，涨点全部来自三次'重新定义'：把检测目标从单个锥桶重新定义成整排锥桶；把改道方向从连续量回归重新定义成离散分类；把数据增强从通用配方重新定义成匹配真实分布的定制策略。每次重新定义的依据都是同一个问题——下游到底需要什么精度的什么信息。"

提示词：

单锥桶 → 整排建模 ｜ 点回归 → 角度回归 → 双二分类 ｜ mosaic → 定制增强 ｜ 一切从下游需求反推

## 1. 项目总览逐字稿

### 1.1 30 秒版：自我介绍里带过

逐字稿：

"2D 这边我负责过前视多任务共网里的施工改道感知子任务——把成排摆放的锥桶、警示柱作为整体目标检出来，同时输出向左还是向右改道的方向，给规控提前发起变道用。是在 YOLO 框架上做的，从立项跟到量产上车。我主导了改道属性头的三轮方案迭代，也做了标注规范、数据增强策略和误检治理，最后稳定检出距离从 89 米提到 114 米。"

提示词：

成排锥桶整体检出 → 改道方向 → YOLO → 三轮迭代 → 89→114m

### 1.2 2 分钟版：面试官说"介绍一下这个项目"

逐字稿：

"这个项目是量产前视多任务网络里的一个子任务，做高速施工改道的感知。场景是高速上施工时会摆一长排锥桶把车流导到旁边车道，感知要做两件事：把这排锥桶检出来，并且给出改道方向——往左还是往右，让规控能提前发起变道。这是个 2D 任务，输入是前视针孔相机，输出 2D 框加改道方向属性。

它的难点不在模型，在任务定义。原来的方案是检测单个锥桶，三个问题：远处锥桶只有几个像素检不出来，而恰恰远处才是规控最需要的；成排锥桶互相遮挡粘连，框互相干扰；最要命的是改道方向要靠下游拿一堆散框去拟合排列方向，框本身就不稳，拟合出来的方向逐帧跳变，规控没法用。

所以核心优化是重新定义目标：把'车道内连续三个以上锥桶'定义为一个改道类整体目标，用一个大框框住整排，方向作为这个目标的属性直接输出；框和车道线强耦合，看不见的一侧沿车道线延长线外推。目标变大之后远距也能检到，稳定检出距离从 89 米提到 114 米。

方向属性我迭代了三轮：先是回归首尾锥桶的接地点，点本身在漂，方向跟着漂；再改成角度的 sin-cos 回归，还是不稳，因为角度是连续量、颗粒度太细；最后想明白了下游只需要'左还是右'，改成左右通行性的双二分类，跳变就消失了，方向准确率提升 7.3%。

另外两块工作：数据增强上经对比实验弃用了 mosaic——长焦视角下目标位置分布高度集中，拼图破坏了这个位置先验——改用 random crop 加 padding 加 HSV，顺带对齐了车端预处理；误检治理上，反光牌路牌那类相似误检用难负样本回灌，上下坡路面截断那类过度泛化用空图负样本定向抑制，施工专题的凭空误检降了 5.4%。全量回归无恶化，随 OTA 版本量产上车。"

提示词：

场景与两个输出 → 原方案三个死穴 → 整体建模 + 车道线耦合 → 三轮属性头 → 弃 mosaic → 两类误检分治 → 89→114m 上车

### 1.3 5 分钟深讲版：适合项目主问

在 2 分钟版基础上，加三块展开：

**共网背景**（放在开头）：

"先交代一下架构背景。前视这一路相机上挂着很多任务——红绿灯、施工牌、特殊障碍物，如果每个任务各跑一套网络，图像特征提取是重复计算的，车端算力吃不消。所以是多任务共网：共享 backbone 和 BiFPN 提特征，每个任务只带自己的 neck 和检测头。我这个子任务是插拔式接入的——通过 config、dataset、head、loss 四个模块挂进去，backbone 零额外开销，也可以独立开关不影响别的任务。共享部分是共网框架既有的，我做的是子任务本身。"

**标注规范**（放在整体建模之后）：

"整体建模带来一个新问题：什么算'一排'？标注员判断不一致，模型就学不出稳定的边界。所以我制定了标注规范：车道内大于等于三个锥桶才构成改道类目标；粘连的判据是底座相连；框的边界和车道线对齐。规范定了之后标注一致性上来了，这是整体建模能 work 的前提——定义变了，数据生产的规矩必须跟着变，不然新定义落不了地。"

**捷径学习**（放在误检治理处）：

"路面截断那类误检值得多说一句，它是个典型的捷径学习问题。上下坡和弯道处，路面在图像上会出现一条截断线，而训练集里施工场景往往也伴随类似的视觉特征，模型就把'路面截断'当成了'有锥桶'的线索——它学到的不是锥桶本身，是一个和锥桶伪相关的背景特征。这类问题指标上看不出来，只在特定路段爆发。治理办法是空图负样本：找一批有截断但确实没有施工的图，标注为空，给模型明确的反向梯度。"

## 2. 先把 2D 检测链路讲透

### 2.1 这个任务的链路全景

```
前视针孔相机（长焦）
    ↓
共享 Backbone（自研轻量，CSP 系）
    ↓
共享 BiFPN（多尺度特征融合）
    ↓  ——— 以上共网共享，零额外开销 ———
独立 Neck（本任务自己的）
    ↓
多头检测头：2D 框回归 + 置信度 + 类别 + 改道方向属性头
    ↓
输出：改道类整体目标框 + 左右通行性
    ↓
下游规控：提前发起变道决策
```

逐字稿：

"链路很短，这是 2D 任务的特点。图像过共享的 backbone 和 BiFPN 拿到多尺度特征——这部分是共网的，所有任务共用；然后进我自己的 neck 和检测头，输出整排锥桶的 2D 框、置信度，加一个改道方向的属性头。方向的消费方是规控，它拿到'前方施工、向左改道'这个语义就可以提前规划变道。"

### 2.2 为什么这个场景对智驾关键（能定量）

逐字稿：

"高速施工是少数必须提前很久决策的场景。锥桶阵列往往一两百米长，等开到跟前再变道就来不及了——一百公里每小时是 27.8 米每秒，从发现到完成变道至少三四秒，就是一百多米的余量。所以稳定检出距离这个指标不是刷出来好看的，89 米到 114 米，多出来的 25 米在这个速度下就是接近一秒的决策余量，够规控从急打方向变成平顺变道。"

高频追问：为什么用"稳定检出距离"而不是最远检出距离？

答：

"最远检出距离是单帧偶然事件，噪声太大——某一帧闪一下检出了 150 米，下一帧又没了，这个数没有意义。稳定检出距离要求目标进入视野后连续若干帧持续检出，规控需要的是可以依赖的持续检出。这个口径严格得多，但它才对得上下游的实际使用。"

### 2.3 YOLO 框架在这个任务上的改造点

逐字稿：

"框架是 YOLOv5 系的，但有几处必须改。第一是 anchor——整排锥桶的框是又长又扁的，宽高比和常规目标差很远，默认 anchor 完全不合适，要按自己的数据重新聚类，不做这一步收敛都困难。第二是检测头要加属性分支，输出改道方向。第三是损失，定位用 GIoU——因为长条框和预测框经常不相交，IoU 在不相交时梯度为零，GIoU 有外接矩形惩罚项才能把框拉过来；属性头用 BCE。"

### 2.4 共网架构：硬参数共享

逐字稿：

"共网是硬参数共享——backbone 和 BiFPN 的权重只有一份，所有任务共用。跟软参数共享的区别是：软共享每个任务有自己的参数、只在训练时加约束，灵活但不省算力，车端用不起。硬共享省算力省显存，代价是任务之间会互相拉扯——我的 loss 权重变化会通过共享层影响别的任务。

所以有明确的边界纪律：共享层我们不碰，只动自己的 neck、head 和 loss。即便这样，改动之后也要跑全共网的回归，确认别的任务指标没掉。真要动共享层，需要所有任务负责人一起评审。"

高频追问：BiFPN 和普通 FPN 的区别？

答：

"FPN 是单向的，自顶向下传语义；PAN 加了自底向上的一条。BiFPN 再做两件事：加同层跨越连接，让原始特征直接参与融合；给不同来源的特征加可学习权重，因为不同分辨率特征的贡献本来就不等，简单相加不合理。代价是多一点计算量。"

## 3. 四大难点不是四个散点，而是一条因果链

**总逻辑：难点 1、2、3 全部源自同一个根——"检单个锥桶"这个任务定义；难点 4 是独立的一条。**

```
检单个锥桶（原任务定义）
    ├─→ 难点1 远距小目标检不出（单锥桶太小）
    ├─→ 难点2 边界不固定（粘连锥桶逐帧分裂）
    └─→ 难点3 方向跳变（散框拟合方向天然不稳）
              ↓ 三条共同的解
        整体目标建模（重新定义"检什么"）

难点4 误检高频 ——独立成因——→ 分两类治理
```

### 3.1 难点一：远距小目标与密集粘连

#### 3.1.1 问题现象

逐字稿：

"一百米外一个锥桶在长焦图像上就几个像素，本来就在检测能力边缘；成排摆放时又互相遮挡粘连，框和框之间互相干扰、NMS 互相误杀。表现就是单锥桶检出不稳，检出距离上不去——而规控恰恰要靠检出距离决定什么时候变道。"

#### 3.1.2 为什么不用常规小目标手段（切图 / P2 头）

逐字稿：

"常规思路是切图放大或者加 P2 浅层检测头，我在焊缝检测那个项目里就是这么做的。但这个任务不适合。第一，车端算力不允许——切图推理量翻几倍，P2 头特征图大四倍，共网的时延预算给不了。第二，就算检出了单个锥桶，粘连和方向拟合的问题还是没解决。所以这里的正确做法不是提升'检小目标'的能力，是换定义——让目标本身变大。一整排锥桶几十米长，在图像上是个很大的目标，远距也能稳定检出。这就是整体建模能一次解掉三个难点的原因。"

#### 3.1.3 高频追问

**追问：整体建模的代价是什么？**

"三条。一是丢失了单锥桶的精确位置——下游拿到的是一排的范围而不是每个锥桶的坐标，好在规控的变道决策不需要单锥桶精度。二是定义边界要非常清楚，什么算一排、断开多远算两排，这逼着我们做标注规范。三是这个定义和车道线耦合，依赖车道线感知的质量。"

**追问：为什么是三个起判？**

"少于三个构不成'导流'的语义——一两个锥桶可能只是占位或遗落，三个以上连续摆放才是明确的改道意图。这个数字是和规控一起定的，是业务语义，不是模型调出来的。"

### 3.2 难点二：目标边界不固定

逐字稿：

"粘连的锥桶随自车接近会逐帧分开——远处看连成一片，近了一个个分离。框的起止点就一直在漂，同一排锥桶前后帧的框对不上，追踪和属性都不稳。

解法有两半。一半是整体建模本身——既然检的是一整排，个体分不分裂就不重要了。另一半是框和车道线强耦合：锥桶排列本来就沿车道摆，所以框的边界和车道线对齐，被遮挡看不见的一侧沿车道线延长线外推。这样框的位置有了几何约束，不纯靠外观，稳定性好得多。"

高频追问：车道线本身检不准怎么办？

答：

"这是这个设计的真实依赖。车道线感知是另一个成熟任务，精度比锥桶检测高一个档次，所以耦合是往更稳的锚上靠。但施工场景里车道线可能被磨掉或者被锥桶遮挡，这种情况下外推退化，框会回退到纯外观检测的状态——这是已知的边界条件，不是被掩盖的缺陷。"

### 3.3 难点三：改道属性输出不稳（三轮迭代，本项目最深的一条线）

#### 3.3.1 三轮方案与各自的死因

**第一轮 · 首尾锥桶接地点回归（Smooth L1）**

"输出首尾两个锥桶的接地点坐标，下游连线得到方向。死因：点本身在漂。首尾锥桶是哪两个，随着粘连分裂逐帧变化；接地点受遮挡和框抖动影响，回归出来的点噪声很大。方向是从两个漂的点连线算出来的，误差被杠杆放大——首尾点各偏几个像素，方向能偏好几度。"

**第二轮 · 排列方向角度回归（sin-cos）**

"不回归点了，直接回归整排的排列角度，用 sin-cos 两个分量表示避免周期跳变。死因和第一轮不同：sin-cos 解决了 0 和 360 度边界的数值跳变，但解决不了'连续量对输入扰动敏感'这个本质。角度是精确到度的连续输出，图像稍微变一点、框的范围漂一点，角度就跟着变几度，逐帧看还是在抖。问题不在数值表示，在任务定义——我们在输出一个比下游需求精细得多的量。"

**第三轮 · 左右通行性双二分类**

"想明白了一件事：规控要的不是角度，是'往左还是往右'。所以改成两个二分类——左侧能否通行、右侧能否通行，组合出四种状态（左可/右可/都可/都不可）。方向从连续量变成离散量，输入的小扰动不再引起输出变化，跳变消失。方向准确率提升 7.3%。"

#### 3.3.2 这条线的核心教训（必讲）

逐字稿：

"这三轮迭代最有价值的不是最终方案，是想明白了一个原则：**输出的精细度应该匹配下游的消费粒度**。前两版都在追求更精确的方向表达，但精细度本身成了不稳定的来源。下游只消费'左还是右'，你输出精确到度的角度，多出来的精度全部变成噪声。这个原则后来我在速度、动静这些属性设计上都在用。"

#### 3.3.3 高频追问

**追问：sin-cos 不是专门解决角度问题的吗，为什么还不行？**

"sin-cos 解决的是周期性——0 度和 360 度是同一个方向但数值差 360，直接回归在边界处会有巨大的错误梯度，sin-cos 把它映射到连续空间，这个问题确实解决了。但我们遇到的不稳是另一回事：连续量对输入扰动的敏感性。这两个问题经常被混为一谈，实际是完全不同的两层。"

**追问：为什么不用一个四分类，而是两个二分类？**

"两个二分类是解耦的——左侧通行性和右侧通行性各自独立判断，每个头只学一件事，样本利用率高；四分类把两个独立的语义耦合进一个 softmax，四个类互斥竞争，某个稀有组合（比如都不可通行）样本极少时会被压制。而且双二分类天然支持'左侧不确定但右侧确定'这种输出状态。"

**追问：为什么不加时序滤波把角度平滑掉？**

"滤波只能压随机噪声，压不掉系统性抖动，而且引入延迟——施工场景是逐渐接近的，方向判断需要及时更新。更重要的是，滤波是把一个定义错误的输出修补得好看一点，不如直接把定义改对。"

### 3.4 难点四：误检高频触发（两类分治）

#### 3.4.1 两类误检的区分（必须分开讲）

逐字稿：

"这个任务的误检分两类，成因完全不同，治法也不同。

第一类是相似物误检：远处的反光牌、路牌，外观和锥桶像——都是橙红色调、竖立的小目标。这是特征判别力问题，治法是把这些难负样本挖出来构建负样本库，回灌训练，让模型见足反例。

第二类更隐蔽，是路面截断误检：上下坡和弯道处，路面在图像上出现截断线，模型会在那儿凭空检出一排根本不存在的锥桶。这不是长得像的问题——那里什么都没有。"

#### 3.4.2 路面截断误检的归因：捷径学习

逐字稿：

"这类误检是典型的捷径学习。训练集里施工场景往往伴随路面视觉上的不连续——锥桶摆在那儿本来就会截断路面纹理。模型学到的不是锥桶本身的特征，而是'路面截断'这个伪相关线索。上下坡和弯道天然也有路面截断，模型就把线索当成了目标。

发现过程也值得说：指标上完全看不出来，整体误检率正常，是路测反馈某些坡道无故触发改道提示，去复现才发现的。定位方法是把这批 case 的共同点找出来——都是上下坡或弯道、画面里都有路面截断特征——然后反向验证：找一批有截断但没施工的图跑模型，确认普遍在那儿出框，归因才成立。

治理用空图负样本：把这类'有截断、无施工'的图标注为空，回灌训练，给模型明确的反向梯度——这种画面下不该有任何输出。"

高频追问：怎么确认治好了，而不是把正常检出也压掉了？

答：

"两边都要验。误检侧看施工专题评测集，凭空误检次数降了 5.4%；召回侧看正常施工场景的检出没有掉——空图负样本只教模型'截断不等于施工'，真有锥桶的时候锥桶自己的特征还在。全量回归无恶化是合入的前提。"

## 4. 核心技术追问：从原理往下推

### 4.1 mosaic 为什么在这个任务上有害

标准答案：

mosaic 把四张图缩放拼接成一张，价值在于增加单图目标数和尺度多样性。但它隐含一个假设：**目标可以出现在画面任何位置**。这个假设在本任务不成立。

逐字稿：

"前视是长焦相机，锥桶阵列在画面里的位置分布高度集中——基本都在中下部、沿车道方向延伸，这是很强的位置先验，模型可以利用它。mosaic 把目标搬到画面任意位置，等于人为制造了推理时根本不会出现的分布，模型把容量花在适应不存在的变化上，位置先验也被破坏了。对比实验确认弃用 mosaic 后指标更好。

这条能推广成一个原则：通用增强不一定通用，用之前要问它有没有破坏任务的真实分布。我在焊缝检测项目里关掉随机缩放，是同一个道理——固定视角下尺度分布是稳定的，缩放增强制造的是假变化。"

追问：那会不会过拟合到位置先验，泛化变差？

答：

"要区分'先验'和'过拟合'。位置分布集中是这个任务的物理事实——相机装在那儿、锥桶摆在路上，分布就是那样，推理时也一样。利用稳定的真实先验不叫过拟合，强行抹掉它才是浪费容量。如果哪天换相机布局，那是分布变了，重新训练是应该的。"

### 4.2 random crop + padding 为什么能弥合训推差异

逐字稿：

"这套增强还有第二个作用：对齐车端预处理。之前离线训练和车端推理的 resize 方式不一致，同一张图两边推理的置信度对不上——模型没变，输入分布变了。把训练侧的 crop 和 padding 改成和车端流水线一致之后，这个偏差消掉了，部署后的置信度一致性明显变好。

这类问题特别隐蔽：指标不是崩，是整体漂移一点，很难从结果反查。发现的办法是拿同一张图在两边分别跑，逐层对比中间特征，看从哪一层开始分叉——分叉在第一层之前，那就是预处理的问题。"

### 4.3 IoU 阈值为什么取 0.4 而不是 0.5

逐字稿：

"因为目标是一整排锥桶，框又长又窄，边界本身有模糊性——远端锥桶看不清，框到哪儿算合理是有弹性的，标注员之间都会有差异。0.5 的标准对这种长条目标过于苛刻，会把大量下游完全可用的检出判成不匹配。而下游真正关心的是'有没有、在哪个车道、往哪边改'，不是框边界精确到几个像素。把阈值定在 0.4 是让评测口径对齐业务需求，不是放水——放水是说指标不达标调阈值凑数，我们是先论证了这个精度下下游可用，再定的口径。"

### 4.4 GIoU 在这个任务上为什么重要

逐字稿：

"IoU 损失有个死穴：两个框不相交时恒为零、没有梯度，模型不知道往哪儿调。我们这个任务恰好高发这种情况——目标是长条框，训练初期预测框和真值经常完全不相交。GIoU 加了最小外接矩形的惩罚项，不相交时也有有意义的梯度，能把框先'拉'过来。对常规方形目标这个差别不明显，对长条目标很关键。"

### 4.5 标注规范为什么是整体建模的前提

逐字稿：

"整体建模引入了三个原来不存在的判断：什么算一排（≥3 个）、断开多远算两排、粘连怎么判（底座相连）。这些判断如果留给标注员自由发挥，同样的场景会标出不同的框，模型学到的边界就是模糊的——数据的不一致会直接变成输出的不稳定。所以定义变了，标注规范必须同步重写，这是我做的工作里看起来最不'算法'、但对最终效果影响最大的一块。"

### 4.6 检出距离 89→114m 是怎么来的

逐字稿：

"两个来源。主要的是整体建模——目标从单锥桶变成整排，在图像上的尺寸大了一个量级，远距检出能力自然上去。次要的是框车道线耦合带来的稳定性——远端看不清时框还有几何约束，不会时有时无，'稳定'检出距离考核的正是连续性。"

追问：这 25 米对下游意味着什么？

答："一百公里每小时下就是接近一秒的额外决策时间。变道动作本身要三秒左右，这一秒决定了规控是从容变道还是急打方向。"

### 5.1 整体建模线模板

现象（远距检不出、粘连分不开）→ 归因（单锥桶定义先天不足）→ 方案（≥3 锥桶整体建模 + 车道线耦合 + 外推）→ 代价（丢单锥桶精度、依赖车道线）→ 验证（稳定检出距离 89→114m）

背景（多任务共 backbone 省算力）→ 接入（config/dataset/head/loss 四模块，插拔式）→ 纪律（共享层不碰，改动跑全共网回归）→ 边界（框架是团队的，子任务是我的）

### 5.4 数据增强线模板

现象（mosaic 反而掉点）→ 归因（长焦位置先验被拼图破坏）→ 方案（random crop + padding + HSV）→ 附加收益（对齐车端预处理，置信度一致性）→ 原则（增强不能破坏真实分布）

## 7. 面试官可能从零基础问到专家：问答库

### 7.1 项目全景

**Q1：这个项目到底做什么？**
答：高速施工改道场景的感知。把成排锥桶作为整体目标检出，输出 2D 框和改道方向，供规控提前变道。前视单相机 2D 任务，YOLO 框架，多任务共网的一个子任务。

**Q2：和项目一什么关系？**
答：完全独立的两个网络。项目一是 BEV 多模态 3D，这个是 PV 单相机 2D，输入输出都不同。方法论上相通：都从下游需求反推感知定义，都用难负样本治误检，都在全量回归无恶化的准入约束下迭代。

**Q3：为什么这个任务不放进 BEV 里做？**
答：锥桶是小目标，一百米外在 BEV 网格里可能就一个格子，BEV 分辨率撑不住；而改道决策需要的正是远距。前视长焦 2D 是这个场景下能看得最远的传感配置。另外施工感知语义性强（是否改道、往哪改），2D 检测加属性头的表达足够，不需要 3D 定位精度。

**Q4：输出给规控的具体是什么？**
答：整排锥桶的 2D 框、置信度，加左右通行性两个二分类组成的四状态。规控结合车道线和自车位置，把它转换成变道决策。

### 7.2 目标定义/整体建模

**Q5：为什么检整排而不是单个？**
答：单锥桶三个死穴——远距太小检不出、粘连互相干扰、方向靠下游拟合散框天然不稳。整排作为一个目标，尺寸大了一个量级、个体粘连不再重要、方向变成目标自身属性。一个定义变更同时解掉三个问题。

**Q6：整排的边界怎么定？**
答：框和车道线强耦合，边界沿车道线对齐；被遮挡的远端沿车道线延长线外推。标注规范里定了：车道内 ≥3 个锥桶构成改道类，底座相连判粘连。

**Q7：如果锥桶摆得断断续续呢？**
答：标注规范里有断开距离的判据，超过就算两个目标。这正是为什么规范必须先行——这类边界情况留给标注员自由判断，数据就不一致了。

**Q8：换个场景这套定义还成立吗？**
答：整体建模可迁移的前提是"目标成组出现且组内个体不重要"——护栏、隔离墩符合，行人不符合（每个个体都要单独定位）。车道线耦合依赖场景有稳定几何参照，高速成立，无车道线的场地要换参照。

### 7.3 属性头三轮迭代

**Q9：三轮分别是什么？**
答：接地点回归（Smooth L1）→ 角度 sin-cos 回归 → 左右通行性双二分类。

**Q10：第一轮为什么失败？**
答：点本身在漂——首尾锥桶随粘连分裂逐帧变化，接地点受遮挡和框抖动影响。方向从两个漂移点连线得出，误差被杠杆放大。

**Q11：第二轮为什么也失败？**
答：和第一轮死因不同。sin-cos 解决了角度周期性，但角度是精确到度的连续量，对输入扰动天然敏感，逐帧还是抖。根因是输出比下游需求精细——下游只要左右，我们输出到度。

**Q12：第三轮为什么稳？**
答：把连续量变离散量。二分类的决策边界远比回归平坦，输入小扰动不再引起输出翻转。且双二分类解耦了左右两个独立语义，比四分类的互斥 softmax 更好学。

**Q13：四种状态都有意义吗？**
答：左可/右可对应两个改道方向；都可对应锥桶只占本车道、两侧都能走；都不可对应前方封死，要提示接管或停车。都有下游消费。

### 7.4 数据增强/训推一致

**Q14：为什么弃 mosaic？**（见 4.1）

**Q15：HSV 增强为什么保留？**
答：颜色扰动不破坏位置先验，而施工场景光照变化大——早晚、隧道口、逆光，颜色鲁棒性是真实需求。增强取舍的标准就一条：它模拟的变化在真实分布里存不存在。

**Q16：训推预处理不一致会怎样？怎么发现？**（见 4.2）

### 7.5 误检/评测

**Q17：两类误检怎么区分和治理？**（见 3.4）

**Q18：什么是捷径学习？**（见 3.4.2）

**Q19：空图负样本会不会压掉正常召回？**
答：不会，它只教"截断不等于施工"。真有锥桶时锥桶自身特征仍在。验证靠两边看：误检专题降、正常场景召回不掉，全量回归无恶化才合入。

**Q20：IoU 0.4 是不是放水？**（见 4.3）

**Q21：P/R 0.7 听起来不高？**
答：口径是 IoU 0.4 下整排长条目标的严格匹配，且评测集以施工专题的难例为主，不是均匀分布的常规场景。这个数字要和"稳定检出 114 米、方向准确率、全量无恶化"合在一起看——单独抽出来和常规检测任务的 P/R 比没有意义。

### 7.6 专家刁难题

**Q22：你这套就是 YOLO 加个属性头，技术含量在哪？**
答：网络确实不复杂，这个项目的难度在定义而不在模型。三次重新定义每次都要：归因清楚为什么旧定义不行、和规控对齐新定义的语义、重写标注规范让数据跟上、验证全量无回归。量产里"把问题定义对"的杠杆比换模型大——我们没动网络，检出距离提了 25 米。

**Q23：如果让你用今天的眼光重做？**
答：两点。一是属性头可以直接从双二分类起步，省掉前两轮——但当时的认知路径是真实的，先追求精确再发现过度精确，这个弯路本身让我建立了'输出粒度匹配下游'的原则。二是路面截断误检可以更早发现——如果一开始就做按场景切片的评测（坡道、弯道单列），而不是只看整体指标，这个问题不用等路测暴露。

**Q24：这个项目你最大的收获？**
答：目标定义比模型结构更重要。从头到尾没换网络，涨点全来自重新定义检什么、输出什么、怎么增强。之后做任何感知任务，我都会先问：下游消费什么粒度的什么信息？这决定任务该怎么定义，而不是反过来。

## 8. 临场策略

### 8.1 优先画这条链

```
下游需求（提前变道）→ 需要远距稳定检出 + 稳定方向
    → 单锥桶定义满足不了 → 整排建模 + 车道线耦合
    → 方向定义满足不了 → 三轮迭代到双二分类
    → 通用增强不匹配分布 → 定制增强
    → 两类误检分治 → 难负样本 + 空图
```

一切追问都能挂回这条链上。

### 8.2 每条方案补一句"为什么不是别的方法"

- 整体建模：为什么不是切图/P2 头（算力 + 治标不治本）
- 双二分类：为什么不是四分类（语义解耦）、不是滤波（治标）
- 弃 mosaic：为什么不是全弃增强（HSV 是真实需求）
- 空图负样本：为什么不是调阈值（跷跷板）

### 8.3 三句式兜底

"这块的原理和取舍我清楚；具体配置数值我需要回去核对；但设计逻辑是——（讲原理）。"

### 8.4 数字口径

只背五个：**89→114m、+7.3%、−5.4%、P/R 0.7@IoU0.4、≥3 锥桶**。其余一律用约数或"回去核对"。

## 10. 最后一页：只背逻辑，不背数字

### 10.1 项目主线

下游需求反推感知定义：

规控要提前变道 → 要求远距稳定检出 + 稳定方向 → 单锥桶定义不行 → 整排建模 → 方向定义不行 → 双二分类 → 分布不匹配 → 定制增强 → 两类误检 → 分治 → 全量无恶化 → 量产上车

### 10.2 五个技术动词

1. **重定义**：单锥桶 → 整排整体目标，一次解三个难点。
2. **耦合**：框与车道线绑定，用几何约束补外观不足。
3. **降粒度**：方向从连续量降到二分类，精细度匹配下游。
4. **对分布**：增强策略向真实分布对齐，弃用破坏先验的 mosaic。
5. **分治**：相似物误检和捷径学习误检分开归因、分开治理。

### 10.3 三条最重要的理论句

1. 定义句：
"检测任务的上限在目标定义就决定了——定义检单个锥桶，再强的模型也解不了方向拟合不稳。"

2. 粒度句：
"输出的精细度应该匹配下游的消费粒度，多出来的精度不是加分项，是噪声来源。"

3. 分布句：
"数据增强的标准只有一条：它模拟的变化在真实分布里存不存在。存在就是鲁棒性，不存在就是浪费容量。"

### 10.4 面试时的最终口径

逐字稿：

"我对这个项目的理解可以概括成一句话：它是一个靠把问题定义对而打赢的项目。网络从头到尾是 YOLO 没变过，检出距离提升 25 米来自把目标从单锥桶重新定义成整排；方向准确率提升来自把回归重新定义成分类；部署一致性来自把增强重新定义成匹配真实分布。每次重新定义的依据都是同一个问题——下游到底消费什么。这个从下游反推定义的习惯，是我从这个项目带走的最重要的东西。"
