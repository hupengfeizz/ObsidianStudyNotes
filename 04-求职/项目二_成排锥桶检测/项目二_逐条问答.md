## 0.1 业务场景：高速施工改道到底是什么 ★★★

> 这是你日常工作最不容易接触到的部分，但它决定了所有的技术选择。**能讲清楚场景，比能讲清楚模型更能体现"做过量产"。**

### 施工控制区的标准布置

《公路养护安全作业规程》（JTG H30）规定高速施工作业区分**六个区段**：

```
行车方向 ────────────────────────────────────────→
┌────────┬───────────┬────────┬─────────┬──────────┬────────┐
│ 警告区  │ 上游过渡区 │ 缓冲区 │  工作区  │下游过渡区 │ 终止区 │
└────────┴───────────┴────────┴─────────┴──────────┴────────┘
  标志牌    锥桶斜排     直排     实际施工    恢复车道    结束
            ↑ 本任务核心
```

| 区段 | 长度（限速 100–120） | 内容 |
|---|---|---|
| 警告区 | 1600m 以上 | 标志牌，无锥桶 |
| **上游过渡区（渐变段）** | **150–250m** | **锥桶斜向排列，把车流引到相邻车道** |
| 缓冲区 | 60–100m | 直排，安全冗余，不施工 |
| 工作区 | 视工程而定 | 两侧锥桶或护栏 |
| 下游过渡区 | 30–60m | 恢复车道 |
| 终止区 | 30m | 结束标志 |

### 渐变段长度公式（决定锥桶斜率）

```
V ≥ 60 km/h ：  L = W × V / 1.6
V < 60 km/h ：  L = W × V² / 155
```

`W` = 横向偏移宽度（m），`V` = 限速（km/h）。

**举例**：封闭一条 3.75m 车道、限速 100 km/h → `L = 3.75 × 100 / 1.6 ≈ 234m`

> **这个数字是整个项目的物理起点**：渐变段的锥桶排布是一条**斜率约 1:60 的极缓斜线**（234m 长、横移 3.75m）。这条斜线的斜率编码了"往哪边改道"——但斜率太缓，用几个离散锥桶去拟合，噪声很容易淹没信号。**这正是原方案失败的物理根源。**

### 锥桶间距与物理规格

| 位置 | 间距 |
|---|---|
| 渐变段 | 4m（部分规范取 V/3.6，即车速的米/秒数值） |
| 直线段 / 缓冲区 | 8–10m |
| 工作区两侧 | 10–20m |

| 目标 | 尺寸 | 特征 |
|---|---|---|
| **交通锥**（雪糕筒） | 高 450 / 700 / 900mm，底座 350–400mm 见方 | 橙红 + 白色反光环（GB/T 24720） |
| **警示柱** | 高 750–1000mm，直径 80–120mm | 细长，远距像素更少 |
| **防撞桶**（水马） | 高 800–1000mm，直径 500–900mm | 体积大，红白相间 |

### 关键数字：100m 外的锥桶有多大

假设前视长焦：焦距 12mm、像元 3μm → `f_pixel ≈ 4000`

```
高度 = 4000 × 0.7 / 100 = 28 px
宽度 = 4000 × 0.4 / 100 = 16 px
150m 处：高 18 px、宽 10 px  ← 单目标检测的极限区
```

再叠加远处大气散射导致的对比度下降、逆光/阴影下颜色特征消失、相邻锥桶在图像上重叠成一片。

### 为什么这个场景对智驾关键

| 维度 | 说明 |
|---|---|
| 发生频率 | 高速养护施工是常态，春秋两季尤其多 |
| 事故后果 | 施工区是高速事故高发段，撞击后可能失控、二次事故 |
| 接管代价 | 智驾在施工区不能自主变道 → 用户接管 → 直接体感差评 |
| **提前量需求** | **100km/h = 27.8m/s，一次舒适变道需 4–6 秒 → 至少 110–170m 提前量** |

> **这一行解释了为什么 KPI 是「稳定检出距离」而不是 mAP**：
> 89m 只够 3.2 秒，变道很急促；114m 有 4.1 秒，勉强够一次舒适变道。**这 25m 不是学术指标，是乘客能直接感受到的差别。**

### 改道形态分类

| 形态 | 难度 |
|---|---|
| 单侧渐变改道（封闭一条车道） | 基础形态 |
| 双侧收缩（车道变窄不变向） | 需要表达"两侧都不可通行" |
| 匝道 / 出入口改道 | 难，弯道叠加改道 |
| 移动施工（养护车 + 锥桶随车移动） | 时序上不稳定 |
| 临时事故现场（摆放不规范） | 分布外样本 |

## 0.2 原方案为什么失败 ★★★

### 原方案

```
感知：检出每一个独立的锥桶（2D 框 → 反投 3D 位置）
   ↓
规控：拿 ≥3 个锥桶的位置 → 最小二乘拟合直线 → 算斜率 → 判断改道方向
```

### 三个致命问题（能定量说出来）

**① 误差在拟合环节被放大**

```
单锥桶在 100m 处的 3D 位置误差 ≈ ±3–5m
理想斜率 = 3.75m / 234m ≈ 0.016
位置噪声 ±3m 在 20m 基线上 → 斜率噪声 ≈ ±0.15

→ 噪声是信号的 10 倍
```

**拟合结果基本是随机的。**

**② 检出率的连乘衰减**

规控需要**至少 3 个**锥桶。假设单锥桶在 100m 处检出率 0.7：

```
3 个都检出的概率 ≈ 0.7³ = 0.34
```

即使单目标检出率不低，"同时检到 3 个"这个联合事件的概率急剧下降。**这是原方案在远距失效的直接原因。**

**③ 遮挡下的系统性缺失**

视线方向与锥桶排布方向夹角很小时，后面的锥桶被前面的完全遮挡。**这不是随机漏检，是几何决定的系统性缺失**——距离越远可见的锥桶越少，而那恰恰是最需要检出的距离段。

### 结果

稳定检出距离只有 **89m**（3.2 秒提前量），变道发起晚，**误刹与用户接管频发**。

> ⚠️ **「误刹与接管」只在讲背景问题时提，不要在讲成果时声称它改善了多少——你没有那个数字。**

## 0.3 PV 多任务共网架构 ★★★

### 为什么要共网：一笔算力账

假设前视相机上有 6 个感知任务：车辆行人 2D 检测、交通灯、交通标志、车道线、小障碍物（本任务）、可行驶区域。

**在典型 CNN 检测模型里，Backbone 占总算力的 60–75%。**

```
6 个独立模型：6 × (0.7 backbone + 0.3 head) = 6.0 单位
共享 backbone：1 × 0.7 + 6 × 0.3        = 2.5 单位
→ 算力节省约 58%
```

**在车端算力是硬约束的前提下，这不是优化，是"能不能装下"的问题。**

附带收益：特征复用带来的正则化效应（多任务互为正则）、工程维护成本（一套预处理、一套部署流程、一次量化校准）。

### 硬参数共享 vs 软参数共享

| | 硬参数共享（本项目） | 软参数共享 |
|---|---|---|
| 做法 | 底层参数**完全共享**，顶层任务独立 | 每任务有自己的完整网络，用正则项约束参数相似 |
| 算力 | 省 | 不省 |
| 任务干扰 | 大（梯度直接冲突） | 小 |
| 部署 | 简单 | 复杂 |
| 量产选择 | **✓** | 极少用 |

### 共享边界

```
                      ┌→ [独立 neck] → [车辆/行人 head]
                      ├→ [独立 neck] → [交通灯 head]
输入 →[共享 Backbone]─┼→ [独立 neck] → [交通标志 head]
       [共享 BiFPN]   ├→ [独立 neck] → [车道线 head]
                      ├→ [独立 neck] → [施工物 head] ← 本任务
                      │                   ├ 检测分支（框/置信度/类别）
                      │                   └ 属性分支（改道方向）
                      └→ [独立 neck] → [可行驶区域 head]

├──── 共享层（团队维护）────┤├─── 子任务自有（你的范围）───┤
```

> `▸ 你的位置`：**共享层往后。** Backbone 与 BiFPN 是团队既有的，你直接复用、未做改动。

### BiFPN 是什么

**FPN 演进**：FPN（自顶向下单向）→ PANet（加自底向上，双向）→ **BiFPN**（双向 + 可学习加权融合 + 重复堆叠）

**BiFPN 的两个关键改动**：

1. **加权融合**——不同分辨率特征贡献不同，给每条边一个可学习权重，用快速归一化融合：`O = Σ (w_i / (ε + Σw_j)) · I_i`
2. **删除单输入节点**——只有一个输入的节点对融合没有贡献，直接删掉省算力

**为什么多任务共网喜欢 BiFPN**：不同任务需要的特征层级不同——交通灯是小目标需要高分辨率浅层，可行驶区域需要大感受野深层。BiFPN 提供一个**各层级都充分融合**的金字塔，每个 head 都能取到合适的层。

**对本任务尤其重要**：成排锥桶**横跨极大尺度范围**——近处几百像素，150m 外只有十几像素，需要 P3（stride 8）到 P5（stride 32）多层同时工作。

### 任务插拔：四模块接入

| 模块 | 内容 |
|---|---|
| **config** | 任务名、启用的特征层、head 结构、loss 权重、训练调度 |
| **dataset** | 数据加载、标注解析、该任务专属的增强 pipeline |
| **head** | 独立 neck + 检测头 + 属性头的网络定义 |
| **loss** | 该任务的损失函数与正负样本匹配策略 |

**零额外 Backbone 开销**——新任务只增加自己 head 那部分算力。

### 多任务干扰：真实存在

**现象**：改动 A 任务的 loss 权重，B 任务的指标掉了。因为共享的底层特征在被不同方向的梯度拉扯。

**学界解法**：

| 方法 | 思路 |
|---|---|
| Uncertainty Weighting (Kendall, CVPR'18) | 用任务的同方差不确定性自动学习 loss 权重 |
| GradNorm (ICML'18) | 动态调整权重使各任务梯度范数平衡 |
| PCGrad (NeurIPS'20) | 检测梯度冲突（余弦相似度为负），把冲突分量投影掉 |
| 任务采样调制 | 训练时按比例采样不同任务的 batch |

**量产的实际约束（比学界方法更硬）**：

> **你的改动合入之后，其他任务的评测项不能恶化。**

所以每次改动都要跑**全量多任务评测**，而不只是自己任务的指标。**这条规则使得共网上的任何改动都比独立模型保守得多——也是这个子任务迭代了 10 个月的直接原因。**

### 常见的工程做法：冻结共享层

微调子任务时**冻结共享 Backbone**，只训独立 neck + head。这从机制上保证了"你的改动不会恶化其他任务"，代价是子任务的上限受限于共享特征的质量。

> ⚠️ **待核实**：你们训练时共享层是否冻结。

## 0.4 目标定义：本项目真正的核心 ★★★

> **这个项目从模型结构上看没有任何新东西**——YOLOv5、GIoU、BCE，全是标准件。它的真正难度在两个判断，第一个就是目标定义。

### 从"检物体"到"检语义"

| | 传统目标检测 | 本任务 |
|---|---|---|
| 目标 | 客观存在的实体（车、人、锥桶） | **人为定义的语义结构**（成排、形成阻塞） |
| 边界 | 物体的物理轮廓，无歧义 | **由规则定义**，需要写规范 |
| 标注一致性 | 天然高 | 需要专门治理 |
| 类比 | 检测一个个字母 | 检测「一个单词」 |

> **「成排锥桶」不是一个天然存在的物体，它的边界是被定义出来的。**
> 直接后果：**标注规范的质量 = 模型精度的上限。**规范不清晰，标注员之间不一致，模型学到的就是噪声。

### 改道类的定义

```
判定条件（全部满足）：
  ① 本车道内 或 侵入本车道
  ② 连续 ≥ 3 个锥桶 / 警示柱 / 防撞桶
  ③ 对该车道形成阻塞（车辆无法沿原车道继续通行）
```

**为什么是 3 个**：延续原方案「规控需要 ≥3 个点拟合」的口径，保证前后方案的评测可比；同时 3 个也是「成排」这个概念在视觉上成立的最小数量——2 个无法区分是排布还是偶然。

### 框与车道线强耦合（关键设计）

**问题**：一排锥桶在图像上斜向延伸，它的 2D 外接框应该框到哪里？

- 只框可见的锥桶？→ 远端被遮挡的部分丢失，框长度随遮挡随机变化
- 框到消失点？→ 框异常巨大，没有物理意义

**解法**：

```
框的近端 = 最近的锥桶底座
框的远端 = 沿车道线方向的延长线外推至阻塞结束位置
不可见侧 = 沿车道线延长线外推，而不是止于最后一个可见锥桶
```

**价值三条**：

1. **框的边界有了确定的几何依据**，不再依赖"能看见几个锥桶"这个随机量
2. 遮挡不再导致框长度突变，**时序稳定性大幅提升**
3. 框的形状本身就编码了改道方向的几何信息

**代价**：标注时需要同时参考车道线，成本上升；且**依赖车道线任务的输出质量**——这也是共网的一个隐含好处，车道线任务就在同一张网络里。

### 粘连类的定义

**为什么需要**：远处锥桶因透视压缩连成一片，视觉上无法分离，但物理上是分开的。不单独建模，模型会在"一个大目标"和"多个小目标"之间反复摇摆。

**判定标准：底座相连判粘连**

```
两个相邻锥桶的底座在图像上相接或重叠 → 判为粘连
沿车道线方向连续粘连的一段 → 标注为一个粘连类目标
```

**为什么用"底座"而不是整体轮廓**（三条理由，答上很加分）：

1. 锥桶是上小下大的圆锥，**底座是最宽的部分，最先在图像上相接**
2. 底座位于地面，是**接地点**，在透视变换中位置最可靠
3. 顶部会因高度差、倾倒、背景干扰而不稳定

> **这条规范的价值：给了标注员一个可操作、无歧义的判据。**「看起来连在一起」是主观的，「底座是否相接」是客观的。

### 标注一致性治理

| 措施 | 说明 |
|---|---|
| 规范文档 + 图示 | 每条规则配正例 / 反例 / 边界案例 |
| 金标准集 | 由算法工程师亲自标注的一小批数据，作为标尺 |
| 标注员培训与考核 | 上岗前用金标准集考核 |
| 一致性度量 | 多人标同一批，算 IoU 一致性 / Cohen's Kappa |
| 争议案例回流 | 定期评审，结论更新进规范 |
| 抽检 | 每批交付抽 5–10%，不合格整批返工 |

**成排锥桶这类目标的一致性天然偏低**——"一排从哪开始到哪结束"不同人有差异。**这直接解释了为什么评测 IoU 阈值取 0.4 而不是 0.5**（见 §0.9）。

## 0.5 什么该给下游、什么不该给 ★★★

> 这是本项目第二个、也是更值钱的判断。

### 决策：粘连类检出了，但不发布

**粘连类的生命周期是不稳定的**：

```
t=0（远处）：整排锥桶完全粘连 → 1 个粘连目标，框覆盖整排
t=1（接近）：最近的 2 个开始分离 → 框的起点往前推
t=2（更近）：分离出更多 → 框继续收缩
t=3       ：粘连段只剩远端一小截 → 框很小
t=4       ：完全分离 → 目标消失
```

**三个致命后果**：

1. **无法跨帧关联**——每一帧的框覆盖的物理范围都不同，"同一个目标"这个概念不成立。跟踪器会疯狂新建 / 销毁 ID
2. **无法量化评估**——真值面临同样的定义问题，IoU 匹配的基础不存在
3. **下游无法使用**——规控拿到一个会自己生灭、边界持续漂移的目标，只能忽略它，或者被它误导

**决策：留在网络里训练，但不向下游发布。**

### 为什么还要保留这一类

1. **提供训练信号**——让网络学会区分"粘连的一片"和"独立的多个"，间接提升改道类的边界判断
2. **避免标注冲突**——如果不定义粘连类，标注员面对粘连的锥桶不知道该标一个还是标多个，会污染改道类的标注一致性
3. **保留未来可能性**——如果后续找到稳定的表达方式，可以随时开放

### 这个决策为什么重要

> **感知输出的标准不是「检得准不准」，而是「下游能不能用」。**
> 一个 mAP 很高但生命周期不稳定的输出，对下游是**负价值**——它不仅没帮助，还会引入错误决策和无谓计算。

**主动选择不发布一个已经做出来的能力，需要对系统边界有清晰认知。这比多做一个模型更能说明工程判断力。**

### 下游怎么消费这个输出

| 字段 | 类型 |
|---|---|
| 2D 框 | float×4（图像坐标） |
| 类别 | enum（改道类） |
| 置信度 | float |
| left_passable | float（左侧可通行概率） |
| right_passable | float（右侧可通行概率） |
| 跟踪 ID | int |

```
感知输出 → 跟踪（跨帧关联、滤波、稳定 ID）→ 决策
  ├ 检出稳定 + right_passable=1 → 规划向右变道轨迹
  ├ 检出稳定 + 两侧均不可通行   → 减速，准备停车或请求接管
  └ 检出不稳定                  → 保持当前策略，继续观察
```

**迟滞逻辑**：属性翻转需要连续 N 帧一致才生效，避免单帧噪声导致方向摇摆。**这是二分类建模相比角度回归的又一个好处**——概率输出天然支持迟滞阈值。

## 0.6 YOLO 系检测框架与损失 ★★☆

> 简历技术栈写了 YOLOv5、GIoU / BCE，会被问。借这个项目把 2D 检测的骨架补齐。

### YOLOv5 结构

```
输入（前视长焦常用长条形，如 1280×704）
   ↓
Backbone（CSPDarknet53 / 本项目为团队自研轻量骨干）
   ├ Focus / Conv stem
   ├ C3 模块 × N（CSP：特征分两路，一路过残差块一路直连，最后 concat）
   └ SPPF（串联三个 5×5 maxpool，等效大感受野，比 SPP 快）
   ↓ 输出 P3(1/8) P4(1/16) P5(1/32)
Neck（PANet / 本项目为 BiFPN）
   ↓
Head（三个尺度各自输出）
```

**本任务的 head 输出**（在标准 YOLOv5 上扩展）：

```
box:        4     (x, y, w, h)
objectness: 1
class:      2     (改道类 / 粘连类)
attribute:  2     (left_passable, right_passable)  ← 第三版
```

### 损失函数

```
Loss = λ_box · L_GIoU
     + λ_obj · L_BCE(objectness)
     + λ_cls · L_BCE(class)
     + λ_attr · L_BCE(attribute)
```

**为什么框回归用 GIoU 而不是 L1**：

| | L1 / L2 | IoU | **GIoU** |
|---|---|---|---|
| 尺度不变性 | ✗（大框绝对误差天然大） | ✓ | ✓ |
| 与评测指标一致 | ✗ | ✓ | ✓ |
| **无重叠时有梯度** | ✓ | **✗（IoU=0，梯度消失）** | **✓** |

**GIoU 定义**：`GIoU = IoU − |C \ (A ∪ B)| / |C|`，`C` 是同时包住 A、B 的最小外接框。

两框完全不重叠时 IoU=0 没有梯度，但 GIoU 会随距离增大趋向 −1，**梯度仍然存在，能把预测框"拉"向真值**。

**对本任务尤其重要**：成排锥桶的框**又长又细**（一排 50m 长、宽度只有一条车道），初始 anchor 与真值框经常完全不重叠。

### IoU 损失家族（了解）

| 损失 | 增加的考虑 |
|---|---|
| IoU | 重叠面积 |
| GIoU | + 最小外接框（解决不重叠） |
| DIoU | + 中心点距离（收敛更快） |
| CIoU | + 长宽比一致性 |
| **NWD** | 把框建模成高斯分布，用 Wasserstein 距离，**小目标友好** |

> NWD 你在项目四用过。本任务如果远距小目标问题更突出，NWD 也是可选项。

### Anchor 设计

YOLOv5 是 anchor-based，anchor 尺寸通过对训练集真值框做 **k-means 聚类**得到（v5 用遗传算法进一步优化）。

**本任务的特殊性**：成排锥桶的框**长宽比极端**（斜向延伸，外接框可能是 300×80）、**尺度跨度极大**（近处几百像素，远处十几像素）。

**默认 COCO anchor 完全不匹配，必须重新聚类。** 如果 anchor 与真值框的最大 IoU 低于阈值（YOLOv5 默认 0.25），该真值在训练中**根本匹配不到任何正样本**，等于白标了。

> 这与项目四「超长缺陷 anchor 失配」是同一类问题。

### YOLO 系演进（横向补齐）

| 版本 | 关键改动 |
|---|---|
| v3 | 多尺度预测、anchor-based |
| v5 | CSP、SPPF、Mosaic、自动 anchor 聚类、工程化 |
| v8 | **anchor-free**、解耦头、**TaskAlignedAssigner**、**DFL** |
| v11 | 结构进一步轻量化 |

**正负样本分配的演进**：静态 IoU 匹配 → ATSS（自适应阈值）→ SimOTA（最优传输）→ TaskAligned（分类分数 × 定位质量的对齐度）

## 0.7 数据增强必须匹配真实分布 ★★☆

> **这是这个项目最能迁移的方法论，和项目四"关随机缩放"是同一条。**

### 通用原则

> **数据增强不是通用配方。能"涨点"的增强，本质上是在补充训练分布中缺失的变化；如果它补充的变化在真实场景中不存在，它就是在注入噪声。**

**自检问题**：

> **这个增强产生的图像，在真实道路上有可能出现吗？**

| 增强 | 真实会出现吗 | 本任务采用 |
|---|---|---|
| HSV 色域变化 | ✓ 光照、天气、锥桶褪色 | **✓** |
| 等比缩放 + padding | ✓ 车端就是这么处理的 | **✓** |
| random crop | ✓ 相当于视角微扰 | **✓** |
| 水平翻转 | ✓ 但**属性标签必须同步翻转** | ⚠️ 谨慎 |
| **Mosaic（四图拼接）** | **✗ 一张图里四个角都有成排锥桶？不会** | **✗ 弃用** |
| 随机旋转 | ✗ 前视相机固定安装，图像不会旋转 | ✗ |

> ⚠️ **水平翻转是这个任务的一个隐藏陷阱**：翻转会把「向左改道」变成「向右改道」，属性标签不同步翻转就是灾难性的标签污染。

### Mosaic 为什么在本任务上有害

**Mosaic 通常有效的三个理由**：

1. 一个 batch 等效看到 4 倍图像内容，丰富上下文
2. **让目标出现在图像各种位置，打破位置先验，防止过拟合到位置**
3. 天然产生大量小目标和截断目标

**为什么在本任务上反而有害**：

> **成排锥桶在长焦前视视角下，位置分布极度集中。**

原因是物理的：前视长焦光轴与车辆前进方向近似平行；车辆沿车道行驶，锥桶就在前方路面上；消失点附近就是远处锥桶所在位置。

结果是**远距成排锥桶几乎恒定出现在画面中央偏下的一个小区域内**。这个位置分布是一个**极强的真实先验**，模型完全应该利用它。

**Mosaic 强行把目标打散到四个角，等于在教一个错误的先验。**

**对比实验结论**：开 mosaic 指标更差，且远距漏检明显增加。

## 0.8 捷径学习（Shortcut Learning）★★☆

> 「路面截断」误检是一个有正式学术名字的现象。给它一个名字的好处是：你能顺带说出排查工具和其他治理手段。

### 现象

模型在**上下坡顶点**和**急弯**处凭空检出成排锥桶——那里根本没有任何锥桶。

### 根因

模型学到了一个**统计上高度有效、但因果上完全错误**的判别特征：

```
观察：训练集中的成排锥桶场景，几乎都伴随「前方路面在某处被截断 / 消失」
     （因为锥桶阻塞了车道，可行驶路面在那里终止）

模型学到：路面截断 → 有成排锥桶

现实：路面截断还有其他原因——
     · 上坡顶点：前方路面被坡顶遮挡，视觉上"消失"
     · 下坡起点：路面突然下沉出视野
     · 急弯：路面拐出视野
     · 桥梁 / 隧道口
```

### 学术名字与经典案例

> Geirhos et al., *"Shortcut Learning in Deep Neural Networks"*, Nature Machine Intelligence, 2020

| 经典案例 | 模型实际学到的 |
|---|---|
| 狼 vs 哈士奇分类 | **背景有没有雪** |
| 肺炎 X 光分类 | **片子来自哪家医院的设备** |
| **成排锥桶检测** | **路面有没有截断** |

### 为什么特别难发现

1. **在训练集和常规验证集上完全看不出来**——因为这个相关性在训练分布中是成立的
2. 只在**分布外场景**（坡、弯）暴露，而这些场景在评测集里占比可能很低
3. **模型对自己的错误很自信**——置信度很高

### 排查工具

**Grad-CAM 是排查这类问题最快的工具**：如果模型的注意力集中在路面消失的边界而不是锥桶本身，捷径学习就实锤了。

### 治理手段

| 方法 | 思路 | 本项目 |
|---|---|---|
| **空图负样本定向抑制** | 采集"有路面截断但没有锥桶"的场景大量回灌，直接打破虚假相关 | **✓ 主要手段** |
| 难负样本按成因归类 | 分类追踪每一类的收敛情况 | **✓** |
| 反事实数据增强 | 人工合成「有截断无锥桶」「有锥桶无截断」 | 可选 |
| 因果干预 / IRM | 让模型在多个环境下保持不变的预测规则 | 学界方法 |
| 分组鲁棒优化（GroupDRO） | 优化最差子群而非平均性能 | 学界方法 |

## 0.9 评测口径与量产准入 ★★☆

### 为什么 IoU 阈值取 0.4 而不是 0.5

**不是为了让数字好看，有三条明确的技术原因**：

1. **真值边界本身有歧义**——"一排从哪开始到哪结束"标注员之间就有 ±10% 的差异（见 §0.4）
2. **框又长又细**——一个 300×80 的框，长边方向偏移 10% 就损失 10% 的 IoU，比方形框敏感得多
3. **下游不关心框的精度**——规控要的是"有没有、往哪边"，不是"框准不准"

> **用一个和下游需求不匹配的严格阈值去评测，会把大量业务上完全可用的检出判为失败。**
> **量产评测的通用原则：指标要对齐下游的实际需求，而不是照搬学术惯例。**

### 稳定检出距离的严格定义

```
目标从远处接近，当【连续 3 帧】都被检出且置信度超过阈值时，
记录【首次稳定】那一刻，【自车中心到目标中心】的直线距离。
```

三个要素缺一不可：

- **连续 3 帧**——排除偶发单帧闪现。规控需要能持续跟住的目标
- **首次稳定**——不是平均值，是最早能用的时刻
- **自车中心到目标中心**——坐标原点和测量对象要明确（自车中心 vs 前保险杠、目标中心 vs 最近点，能差几米）

### 89m → 114m 的业务含义（100km/h = 27.8m/s）

```
89m  → 3.2 秒提前量 → 变道急促，乘客不适，部分情况来不及
114m → 4.1 秒提前量 → 一次舒适变道的最低要求
```

### 需要一起看的其他维度

| 维度 | 说明 |
|---|---|
| 分距离段 P/R | 50 / 80 / 100 / 120 / 150m 各段分别统计 |
| 分场景 | 高速 / 高架 / 匝道 / 隧道口 |
| 分改道形态 | 左改道 / 右改道 / 双侧收缩 |
| 时序稳定性 | 检出闪烁率、属性翻转次数 |
| 误检 | 各类误检的**绝对次数**（不是率），按千公里归一 |
| **多任务回归** | **共网上其他任务的指标不能恶化** |

### 准入规则

```
新版本准入 = 目标指标提升
           AND 本任务全评测项无恶化
           AND 共网其他任务全评测项无恶化   ← 共网特有
```

**第三条是这个子任务迭代 10 个月的直接原因**——每次改动的验证成本远高于独立模型。

# 第 25 条

> **远距小目标与密集粘连：远处锥桶像素少、互相遮挡，单锥桶检出不稳，规控的变道触发距离受限。**

### 问题清单

| 层 | 问题 |
|---|---|
| 一 | Q1 远处锥桶到底多少像素？ |
| 一 | Q2 "密集粘连"是什么意思？为什么会粘连？ |
| 二 | Q3 为什么单锥桶检出不稳会导致触发距离受限？ |
| 二 | Q4 为什么不用小目标检测的常规手段（切图、P2 头）？ |
| 三 | Q5 遮挡是随机的还是系统性的？ |
| 三 | Q6 这跟项目一的中远距问题是同一类吗？ |

---

**Q1 · 多少像素？**

`原理`　前视长焦（f≈12mm、像元 3μm → f_pixel≈4000）：

```
100m：高 28 px、宽 16 px
150m：高 18 px、宽 10 px
```

叠加大气散射对比度下降、逆光时颜色特征消失。

`口语`　按前视长焦的焦距算，一个七十厘米高的锥桶在一百米处大概是高二十八、宽十六个像素，一百五十米就只有十几个像素了。而且远处对比度也差，逆光的时候橙红色这个最强的特征基本就没了。

---

**Q2 · 为什么会粘连？**

`原理`　**透视压缩。**锥桶在渐变段间距 4m，但沿视线方向看过去，远处相邻锥桶在图像上的**横向间隔急剧压缩**，加上锥桶本身有宽度，就在图像上连成一片。

```
100m 外一段 20m 长的锥桶排 → 只有 5 个锥桶，且互相严重遮挡
视线方向与排布方向夹角越小，遮挡越严重
```

`口语`　是透视压缩造成的。锥桶在渐变段的间距是四米，但沿视线方向看过去，远处相邻锥桶在图像上的横向间隔被压得很小，加上锥桶本身有宽度，就连成一片了。一百米外一段二十米长的锥桶排其实只有五个锥桶，而且互相遮挡得很厉害。

---

**Q3 · 为什么导致触发距离受限？**（核心，要定量）

`原理`　原方案要规控拿 **≥3 个锥桶**拟合直线。两个衰减叠加：

```
① 连乘衰减：单锥桶检出率 0.7 → 3 个都检出 = 0.7³ = 0.34
② 拟合噪声放大：单锥桶 3D 位置误差 ±3m，在 20m 基线上
                → 斜率噪声 ±0.15，而真实斜率只有 0.016
                → 噪声是信号的 10 倍
```

结果：稳定判断的距离只有 **89m**。

`口语`　因为原方案是规控拿至少三个锥桶拟合一条直线算斜率。这里有两个衰减叠在一起：一个是连乘，单锥桶检出率就算有 0.7，三个都检到就只有 0.34；另一个更要命，单锥桶的 3D 位置误差有正负三米，在二十米的基线上拟合，斜率噪声大概正负 0.15，而渐变段真实的斜率只有 0.016——**噪声是信号的十倍**，拟合结果基本是随机的。所以规控能稳定判断的距离就只有八十多米。

---

**Q4 · 为什么不用切图 / P2 头？**

`原理`　三个原因：

1. **共网约束**——这是多任务共网上的一个子任务，改 Backbone 或加 P2 头会影响**所有**任务的算力和精度，验证成本极高
2. **算力**——P2（stride 4）的特征图是 P3 的 4 倍，是检测头里最贵的一层；共网上加不起
3. **方向不对**——问题的根子不在"单个锥桶检不出"，而在"下游需要三个才能用"。**换目标定义（整体建模）比提升单目标检出率更直接**

`口语`　三个原因。一是共网的约束，改 Backbone 或者加 P2 头会影响所有任务的算力和精度，验证成本太高。二是 P2 的特征图是 P3 的四倍，是检测头里最贵的一层，共网上加不起。三是方向不对——问题的根子不在单个锥桶检不出，而在下游需要三个才能用。换目标定义比死磕单目标检出率更直接，这也是我们最后走整体建模的原因。

---

**Q5 · 遮挡是随机的还是系统性的？**

`原理`　**系统性的。** 视线方向与锥桶排布方向夹角很小时，后面的锥桶被前面的完全遮挡。**距离越远，可见的锥桶越少**——而那恰恰是最需要检出的距离段。

这意味着：**靠加数据、加模型容量都解决不了**，因为信息在成像阶段就丢了。

`口语`　是系统性的，不是随机漏检。视线方向跟锥桶排布方向的夹角很小的时候，后面的锥桶被前面的完全挡住，而且距离越远可见的越少，恰好是最需要检出的距离段。这种缺失靠加数据、加模型容量都解决不了，因为信息在成像阶段就已经丢了。

---

**Q6 · 和项目一的中远距问题是同一类吗？**

`原理`　**表现相似，根因不同**：

| | 项目一 | 项目二 |
|---|---|---|
| 根因 | 深度估计不准 → 特征涂错 BEV 格子 | 目标本身像素太少 + 几何遮挡 |
| 是 3D 还是 2D | 3D 空间定位问题 | 2D 检出问题 |
| 解法方向 | 改善深度监督 | 改变目标定义 |

共同点是**都属于"远距信息不足"这一大类**，且都需要先做分距离段评测才能定位。

`口语`　表现有点像，但根因不一样。项目一是深度估不准，特征被涂到错误的 BEV 格子里，是个 3D 定位的问题；这边是目标本身像素就少，加上几何遮挡，是 2D 检出的问题。解法方向也不一样——那边是改善深度监督，这边是改变目标定义。共同点是都属于远距信息不足，而且都得先做分距离段评测才定位得了。

**Q1 · 逐帧分裂的过程**

`原理`

```
t=0（远处）：整排完全粘连 → 1 个目标，框覆盖整排
t=1（接近）：最近的 2 个开始视觉分离 → 框的起点往前推
t=2       ：分离出更多 → 框继续收缩
t=3       ：粘连段只剩远端一小截 → 框很小
t=4       ：完全分离 → 目标消失
```

`口语`　远处的时候一整排在图像上是完全粘连的，检出一个框覆盖整排；自车越靠近，最近的两个先分开，框的起点就往前推；再近，分开的越来越多，框不断收缩；最后完全分离，这个目标就消失了。

---

**Q2 · 框漂移的问题**

`原理`　三个层面：

1. **跟踪层**——每一帧的框覆盖的物理范围都不同，跨帧关联的基础不存在，跟踪器会疯狂新建/销毁 ID
2. **评测层**——真值也面临同样的定义问题，IoU 匹配算的不是同一个东西
3. **下游层**——规控拿到一个边界持续变化的目标，无法做稳定的距离判断和轨迹规划

`口语`　三个层面的问题。跟踪上，每一帧的框覆盖的物理范围都不一样，跨帧关联的基础不存在，跟踪器会不停地新建和销毁 ID。评测上，真值也有同样的定义问题，IoU 匹配的根本不是同一个东西。下游上，规控拿到一个边界一直在变的目标，没法做稳定的距离判断。

---

**Q3 · 怎么解决的？**

`原理`　**框与车道线强耦合**：

```
框的近端 = 最近的锥桶底座
框的远端 = 沿车道线方向的延长线外推至阻塞结束位置
不可见侧 = 沿延长线外推，而不是止于最后一个可见锥桶
```

**关键**：框的边界不再依赖"能看见几个锥桶"这个随机量，而是有了确定的几何依据。遮挡不再导致框长度突变，**时序稳定性大幅提升**。

`口语`　把框和车道线强耦合起来。近端还是最近的锥桶底座，远端不是止于最后一个能看见的锥桶，而是沿着车道线方向的延长线外推到阻塞结束的位置。这样框的边界就有了确定的几何依据，不再依赖能看见几个锥桶这个随机量，遮挡也不会让框的长度突变，时序上稳定多了。

---

**Q4 · 外推怎么做？依赖什么？**

`原理`　依赖**车道线的方向**。标注时同时参考车道线，沿车道线方向把框的远端外推。

**这是共网的一个隐含好处**——车道线任务就在同一张网络里，两个任务共享同一份特征，几何一致性天然更好。

**代价**：标注成本上升（要同时看车道线），且**依赖车道线任务的输出质量**。

`口语`　依赖车道线的方向，标注的时候要同时参考车道线，沿着车道线方向把框的远端外推出去。这里有个共网的隐含好处——车道线任务就在同一张网络里，两个任务共享同一份特征，几何一致性天然会好一些。代价是标注成本上去了，而且依赖车道线的输出质量。

---

**Q5 · 车道线也检不准怎么办？**

`原理`　这是一个真实的耦合风险：

- 车道线在施工区本身就容易被遮挡或磨损
- 车道线检不准 → 外推方向错 → 框的远端错

**缓解手段**：外推距离设上限（不做无限外推）；车道线置信度低时退化为"只框可见锥桶"；标注时对车道线不清晰的场景单独标记，评测时分开统计。

⚠️ **待核实**：你们实际有没有做这个降级。

`口语`　这确实是个耦合风险，而且施工区的车道线本身就容易被遮挡或者磨损。缓解办法一般是给外推距离设上限，不做无限外推；车道线置信度低的时候退化成只框可见的锥桶；标注的时候把车道线不清晰的场景单独标记，评测的时候分开统计。具体的降级策略我回去确认一下。

---

**Q6 · 为什么不用分割？**

`原理`　几个考虑：

1. **算力**——分割头比检测头贵，共网上加不起
2. **下游接口**——规控要的是"有没有、往哪边"这个语义，不是逐像素的掩膜；给分割结果还要下游自己后处理
3. **标注成本**——分割标注成本远高于框
4. **不解决根本问题**——分割同样面临"一排从哪开始到哪结束"的定义问题，只是把边界从框换成了掩膜

`口语`　几个考虑。一是算力，分割头比检测头贵，共网上加不起。二是下游要的是"有没有、往哪边"这个语义，不是逐像素的掩膜，给分割结果规控还得自己后处理。三是分割的标注成本高得多。最关键的是它不解决根本问题——分割一样面临"一排从哪开始到哪结束"的定义问题，只是把边界从框换成了掩膜而已。

|---|---|
| 一 | Q1 改道方向属性是什么？下游怎么用？ |
| 二 | Q2 点回归为什么会跳变？ |
| 二 | Q3 角度回归为什么会跳变？ |

| 三 | Q6 跳变对下游的具体影响？ |

---

**Q1 · 属性是什么？**

`原理`　下游规控需要知道：**这个施工区要求我往左还是往右改道？** 这个信息必须从视觉判断——锥桶排布的斜向趋势指向哪一边。

`口语`　规控需要知道这个施工区是要往左还是往右改道。这个信息只能从视觉判断，就是看锥桶排布的斜向趋势指向哪一边。

---

**Q2 · 点回归为什么跳变？**

`原理`　第一版回归首尾两个接地点，失败在两处：

1. **无视觉锚点**——「一排的起点」到底是哪个锥桶的哪个位置？是第一个锥桶的底座中心？还是它的左下角？**图像上没有一个明确的视觉特征对应这个点**，标注员之间不一致，网络也学不出稳定的响应
2. **两类干扰**——改道类和粘连类的点分布规律不同（粘连类的"起点"更模糊），放在一个头里学会互相干扰

结果：连续帧之间预测点在图像上跳动幅度可达几十像素，反投到 BEV 后斜率完全不可用。

`口语`　第一版是回归首尾两个接地点。失败主要在两处：一是这个点在图像上没有明确的视觉锚点，一排锥桶的"起点"到底是哪个锥桶的哪个位置，标注和学习都不稳；二是成排类和粘连类的点分布规律不一样，放一个头里学会互相干扰。结果就是连续帧之间预测点在图像上能跳几十个像素，反投到 BEV 之后斜率完全没法用。

---

**Q3 · 角度回归为什么跳变？**（关键区分）

`原理`　**注意：这里的跳变不是周期性问题，是决策边界问题。**

改道方向的判断本质上是看角度落在哪一侧：

```
θ > 0 → 向左改道
θ < 0 → 向右改道
```

当实际排布接近正前方（`θ ≈ 0`）时——**这恰恰是最远距离、锥桶排布还没有明显偏移的时候**——一点噪声就让 θ 在 0 附近来回穿越：

```
帧 1: θ = +0.3° → 判定「向左」
帧 2: θ = −0.2° → 判定「向右」
帧 3: θ = +0.1° → 判定「向左」
```

**而且这个问题在最需要它的距离段最严重**：远处斜率小、抖得厉害；近处斜率大、反而稳定——但近处规控已经来不及变道了。

`口语`　这个跳变跟周期性没关系，是决策边界的问题。改道方向本质上是看角度落在哪一侧，角度大于零判左、小于零判右。而实际排布接近正前方的时候——也就是最远、锥桶还没有明显偏移的时候——一点噪声就让角度在零附近来回穿越，一帧判左一帧判右。更要命的是这个问题在最需要它的距离段最严重：远处斜率小抖得厉害，近处斜率大反而稳，但近处规控已经来不及变道了。

---

**Q4 · sin-cos 不是解决了周期性吗？**（最能体现理解深度的一问）

`原理`　**sin-cos 解决的是数值连续性，没有解决决策边界的稳定性。这是两件不同的事，经常被混淆。**

| | 解决什么 | 没解决什么 |
|---|---|---|
| **sin-cos** | 角度在 0/2π 处的**数值不连续**（真值 359°、预测 1°，L1 算出 358 的问题） | 判定边界处的**语义翻转** |

sin-cos 让回归目标连续了，训练更稳；但**推理时你仍然要做 `θ > 0 ?` 这个判断**，边界附近的噪声照样让语义翻转。

`口语`　sin-cos 解决的是数值连续性，没解决决策边界的稳定性，这是两件事。sin-cos 让回归的目标变连续了，避免了真值 359 度、预测 1 度算出误差 358 那种问题，训练是更稳了。但推理的时候你还是要做"角度大于零吗"这个判断，边界附近的噪声照样让语义翻过来。所以数值稳了，语义还是不稳。

---

**Q5 · 加时序滤波不就行了？**

`原理`　可以缓解，但两个问题：

1. **滤波引入延迟**——要连续 N 帧一致才翻转，等于牺牲了响应速度，而这个任务的核心 KPI 就是"多早能判断"
2. **治标不治本**——底层信号本身就在 0 附近随机游走，滤波只是把随机游走变慢，边界附近仍然会翻

**根本解法是换建模方式**——让输出天然是离散的、带概率的，这样迟滞阈值才有意义（对一个概率做迟滞，比对一个符号判断做迟滞可靠得多）。

`口语`　能缓解但不解决。一是滤波要连续几帧一致才翻转，引入了延迟，而这个任务的核心指标就是多早能判断，牺牲响应速度是本末倒置。二是底层信号本身就在零附近随机游走，滤波只是把游走变慢。根本解法是换建模方式，让输出天然是离散的、带概率的，这样做迟滞才有意义——对一个概率做迟滞，比对一个符号判断做迟滞可靠得多。

---

**Q6 · 对下游的影响？**

`原理`　规控拿到一个一帧左一帧右的方向信号，只有两个选择：**忽略它**（那这个属性就白做了），或者**被它误导**（错误变道，直接是安全事件）。实际上规控会选择忽略，退回到原来自己拟合斜率的方案——**等于整个属性头的价值归零**。

`口语`　规控拿到一帧左一帧右的信号，只能选择忽略它，或者被它误导做出错误变道。实际上规控会选择忽略，退回原来自己拟合斜率的方案，那我们这个属性头的价值就归零了。所以属性不稳定不是"精度低一点"的问题，是"这个功能能不能用"的问题。

**Q2 · 为什么误检更要命？**

| 后果 | 没有提前变道，人工接管 | **错误变道 / 误刹** |
| 严重性 | 体验差 | **安全事件** |
| 用户感知 | "它没反应" | **"它疯了"** |

一次凭空检出的"施工区"会让车在正常路段突然变道——不仅危险，而且**对用户信任的破坏是不可逆的**。

`口语`　漏检的后果是没提前变道，用户接管一下，体验差但不危险。误检是让车在正常路段突然变道，这是安全事件。而且用户感知上，漏检是"它没反应"，误检是"它疯了"，后者对信任的破坏是不可逆的。

**Q3 · 路面截断误检怎么发现的？**

`原理`　**不是从训练集或常规验证集发现的**——因为这个相关性在训练分布中是成立的，指标上完全看不出来。

发现路径通常是：

1. 路测反馈"某个上坡顶点会突然变道"
2. 复现问题帧，看可视化 → 确认是凭空检出
3. 归类多个类似 case，发现共同点是**上下坡、急弯、桥梁隧道口**
4. 抽象出共同特征：**前方路面在视觉上被截断**

`口语`　不是从训练集或者验证集发现的，指标上完全看不出来，因为这个相关性在训练分布里是成立的。是路测反馈来的——反馈说某个上坡顶点会突然变道，我去复现那些帧看可视化，确认是凭空检出，然后把多个类似的 case 归类，发现共同点是上下坡、急弯、桥梁隧道口，再抽象出来就是"前方路面在视觉上被截断"这个共同特征。

**Q4 · 为什么模型会学到这个？**

`原理`

```
训练集里的成排锥桶场景，几乎都伴随「前方路面被截断」
（因为锥桶阻塞了车道，可行驶路面在那里终止）
→ 模型学到：路面截断 = 有成排锥桶

但路面截断还有别的原因：
· 上坡顶点：路面被坡顶遮挡，视觉上"消失"
· 下坡起点：路面下沉出视野
· 急弯：路面拐出视野
· 桥梁 / 隧道口
```

这是一个**统计上高度有效、但因果上完全错误**的判别特征。而且它比"看锥桶本身"**更容易学**——路面截断是一个大范围的、低频的、高对比的视觉线索，锥桶是十几个像素的小目标。**模型会优先学容易的那个。**

`口语`　因为训练集里凡是有成排锥桶的场景，前方路面几乎都会被截断——锥桶阻塞了车道，可行驶路面在那儿终止。模型就学到"路面截断等于有锥桶"。但路面截断还有别的原因，上坡顶点被坡顶挡住、下坡下沉出视野、急弯拐出去、桥梁隧道口，这些地方就凭空检出了。
而且更麻烦的是，路面截断这个特征比锥桶本身**更容易学**——它是大范围、低频、高对比的视觉线索，锥桶只有十几个像素。模型会优先学容易的那个。

**Q5 · 有学名吗？**

`原理`　**Shortcut Learning（捷径学习）/ Spurious Correlation（虚假相关）**

> Geirhos et al., *"Shortcut Learning in Deep Neural Networks"*, Nature Machine Intelligence, 2020

经典案例：

| 案例 | 模型实际在看 |
|---|---|
| 狼 vs 哈士奇 | 背景有没有雪 |
| 肺炎 X 光分类 | 片子来自哪家医院的设备 |
| 本例 | 路面有没有截断 |

`口语`　这个有正式名字，叫捷径学习或者虚假相关，Nature Machine Intelligence 上有一篇专门讲这个的。最经典的案例是分类狼和哈士奇的模型，实际上学的是背景里有没有雪；还有肺炎 X 光片分类，模型学的是片子来自哪家医院的设备。我们这个是模型学的是路面有没有截断，不是有没有锥桶。

**Q6 · 怎么排查？**

`原理`　**Grad-CAM 是排查这类问题最快的工具**——直接看模型的注意力落在哪里。如果注意力集中在路面消失的边界而不是锥桶本身，捷径学习就实锤了。

其他手段：

- 反事实测试——人工构造"有锥桶但路面不截断""有截断但无锥桶"的样本，看模型反应
- 分组评测——按坡度、曲率分组统计误检率，看是否与这些几何因素强相关

`口语`　最快的工具是 Grad-CAM，直接看模型的注意力落在哪儿。如果注意力集中在路面消失的那条边界上、而不是锥桶身上，那基本就实锤了。另外也可以做反事实测试，构造有锥桶但路面不截断、有截断但没锥桶的样本看模型反应；或者按坡度、曲率分组统计误检率，看是不是跟这些几何因素强相关。

**Q1 · 整体建模好在哪？**

`原理`　三条：

1. **稳定性**——一排作为整体、框与车道线耦合，比单个小目标稳得多；不受"能看见几个"的影响
2. **可用性**——能直接挂改道方向属性，规控拿到就能用，不用自己拟合斜率
3. **绕过了连乘衰减**——不再需要"同时检到 3 个"这个联合事件

`口语`　三条。一是稳定，一整排作为一个目标、框跟车道线耦合，比单个小目标稳得多，也不受能看见几个的影响。二是可用，能直接挂改道方向属性，规控拿到就能用，不用自己拟合。三是绕过了原方案那个连乘衰减——不再需要"同时检到三个"这个联合事件了。

**Q2 · 代价是什么？**（必答，不说代价显得没想清楚）

`原理`　三条代价：

1. **标注成本与一致性**——"一排"的边界容易有分歧，必须写规范、做一致性治理
2. **丢了单锥桶的细粒度信息**——下游如果要单个锥桶的位置，这个模型给不了
3. **对部分遮挡更敏感**——一排被前车挡掉中间一段，整体框就不好定

> **所以不是哪个更好，是看下游要什么。**这句话要说出口。

`口语`　三条代价。一是标注成本和一致性，"一排"的边界容易有分歧，必须写规范做治理。二是丢了单锥桶的细粒度信息，下游如果要单个锥桶的位置，这个模型给不了。三是对部分遮挡更敏感，一排被前车挡掉中间一段，整体框就不好定。所以不是哪个更好，是看下游要什么——我们下游要的是"往哪边改道"这个语义，所以整体建模更合适。

**Q3 · 为什么是 3 个？**

`原理`　两个理由：

1. **延续原方案的口径**——规控原来就是拿 ≥3 个点拟合，沿用同样的阈值保证前后方案的评测可比
2. **视觉上的最小成立数量**——2 个无法区分是"排布"还是"偶然摆了两个"

`口语`　两个理由。一是延续原方案的口径，规控原来就是拿至少三个点拟合，沿用同样的阈值，前后方案的评测才可比。二是视觉上三个是"成排"这个概念成立的最小数量，两个没法区分是排布还是偶然摆了两个。

---

**Q4 · 为什么用底座？**

`原理`　三条：

1. 锥桶是上小下大的圆锥，**底座是最宽的部分，最先在图像上相接**——用底座判定的时机最早、最灵敏
2. 底座位于地面，是**接地点**，在透视变换中位置最可靠（顶部的位置受高度、倾斜影响大）
3. 顶部会因高度差（不同规格的锥桶高度不同）、倾倒、背景干扰而不稳定

> **核心价值：把主观判断变成客观判据。**「看起来连在一起」是主观的，「底座是否相接」是客观的、可验证的。

`口语`　三条。一是锥桶是上小下大的，底座最宽，在图像上最先相接，用它判定时机最早也最灵敏。二是底座在地面上、是接地点，透视变换里位置最可靠，顶部受高度和倾斜影响大。三是不同规格的锥桶高度不一样，顶部本来就参差不齐，还容易被背景干扰。
但最根本的价值是把主观判断变成了客观判据——"看起来连在一起"是主观的，"底座是不是相接"是客观的、可验证的，标注员之间才有一致口径。

**Q1 · 三版演进**

`原理`

| 版本 | 建模 | 输出类型 | 主要失效 |
|---|---|---|---|
| 一 | 首尾接地点回归（Smooth L1） | 连续，4 维 | 点无视觉锚点、漂移 |
| 二 | 排布直线角度回归（sin-cos） | 连续，2 维 | 决策边界跳变 |
| **三** | **左右通行性双二分类（BCE）** | **离散，2 个概率** | **—** |

> **一句话概括三轮的教训：前两版都在回归一个下游根本不需要的精确几何量；第三版直接输出下游真正需要的离散决策。**

`口语`　前后走了三版。第一版回归首尾两个接地点，用 Smooth L1，想法是这两个点能反投到 BEV 给规控一条斜线。第二版改成回归排布直线的角度，用 sin 和 cos 表示。第三版干脆不回归了，改成左右通行性两个二分类组合出四种状态。
概括起来，前两版都在回归一个下游根本不需要的精确几何量，第三版直接输出下游真正需要的离散决策。

**Q2 · 四种状态**

`原理`

```
输出两个独立的二分类：
  left_passable  ∈ {0,1}   左侧是否可通行
  right_passable ∈ {0,1}   右侧是否可通行

┌──────────────┬───────────────┬────────────────────────┐
│ left / right │ 语义           │ 规控动作                │
├──────────────┼───────────────┼────────────────────────┤
│  1  /  0     │ 向左改道       │ 向左变道                │
│  0  /  1     │ 向右改道       │ 向右变道                │
│  0  /  0     │ 两侧均不可通行 │ 减速 / 停车 / 请求接管   │
│  1  /  1     │ 两侧均可通行   │ （异常态，用于自检）     │
└──────────────┴───────────────┴────────────────────────┘
```

`口语`　输出两个独立的二分类，左侧能不能通行、右侧能不能通行，组合出四种状态。左通右不通就是向左改道，反过来是向右改道；两个都不通就是两侧都堵，规控要减速或者请求接管；两个都通是异常态，可以用来做自检。

**Q3 · 第一版为什么不行？**

`原理`　两个问题：

1. **无视觉锚点**——「一排的起点」在图像上没有明确的视觉特征对应。是第一个锥桶的底座中心？还是它的左下角？标注不稳，学习也不稳
2. **两类互相干扰**——改道类和粘连类的点分布规律不同（粘连类的"起点"更模糊），放在一个头里学会互相干扰

**中间改进**：把成排类和粘连类的点**拆成两组分别回归**，有改善，但漂移仍然大。

**根本问题**：**在回归一个没有视觉定义的量。**

`口语`　两个问题。一是这个点在图像上没有明确的视觉锚点，一排锥桶的"起点"到底是哪个锥桶的哪个位置，标注员之间不一致，网络也学不出稳定响应。二是成排类和粘连类的点分布规律不一样，放一个头里会互相干扰。中间我们把两类的点拆成两组分别回归，有改善但漂移还是大。
根本问题是，我们在回归一个本身就没有视觉定义的量。

---

**Q4 · 第二版为什么不行？**（和第一版失败原因完全不同）

`原理`　第二版**比第一版好**——角度是一个有明确几何意义的整体量，不依赖某个具体点的定位；标注上也更容易达成一致（画一条趋势线比标两个点容易）。

但它败在**决策边界**：

```
θ > 0 → 向左；θ < 0 → 向右

实际排布接近正前方（θ ≈ 0）时——这恰恰是最远距离
帧 1: θ = +0.3° → 「向左」
帧 2: θ = −0.2° → 「向右」
帧 3: θ = +0.1° → 「向左」
```

**而且在最需要它的距离段最严重**：远处斜率小、抖得厉害；近处斜率大、反而稳定——但近处已经来不及变道。

`口语`　第二版其实比第一版好，角度是个有明确几何意义的整体量，不依赖某个具体点，标注上也更容易一致——画一条趋势线比标两个点容易。
但它败在决策边界上。判方向是看角度落在哪一侧，而实际排布接近正前方的时候，也就是最远的时候，一点噪声就让角度在零附近来回穿越，一帧判左一帧判右。而且这个问题恰好在最需要它的距离段最严重——远处斜率小抖得厉害，近处斜率大反而稳，可近处规控已经来不及了。

---

**Q5 · 第三版为什么稳？**（五条，答全很加分）

`原理`

| 维度 | 说明 |
|---|---|
| **匹配任务本质** | 改道方向是**离散语义**，不是连续几何量。用离散建模天然稳定 |
| **消除决策边界抖动** | 二分类输出是概率，加迟滞阈值（如 >0.6 才翻转）即可完全消除跳变 |
| **表达力更强** | 能表达「两侧都不可通行」——这是角度回归**根本无法表达**的状态，而它对应真实存在的双侧收缩场景 |
| **自检能力** | (1,1) 是异常态，可作为模型置信度的一个信号 |
| **标注更容易** | 「左边能不能过」比「画一条趋势线」更容易达成一致 |
| **下游更好用** | 规控要的就是一个方向决策，不是一条直线方程 |

**类比**：这个建模方式和**转向灯的左右灯**是一致的——车辆不会输出"我要转 37.5 度"，而是输出"左"或"右"。**离散语义就该用离散建模。**

`口语`　几条。最根本的是它匹配任务本质——改道方向是个离散语义，不是连续几何量，用离散建模天然就稳。第二，二分类输出的是概率，加个迟滞阈值就能完全消除跳变，比如超过 0.6 才翻转。第三，表达力更强，能表达"两侧都不可通行"这种状态，而角度回归根本表达不了，可这个状态对应真实存在的双侧收缩场景。第四，两个都为一是异常态，可以拿来做自检。第五，标注上"左边能不能过"比"画一条趋势线"更容易一致。
其实这个建模方式跟转向灯的左右灯是一样的——车不会输出"我要转 37.5 度"，就是输出左或者右。离散语义就该用离散建模。

**Q7 · 为什么不用一个四分类？**（很好的追问，能区分理解深度）

2. **样本效率**——四分类里 (1,1) 和 (0,0) 都是稀有类，会遇到类别失衡；两个二分类各自的正负样本都相对均衡
3. **可解释性与调试**——出问题时可以定位是左侧判断错了还是右侧判断错了；四分类只知道"分类错了"
4. **迟滞更自然**——两个概率各自做迟滞，比在四个类别之间做状态机简单得多

`口语`　几个原因。最主要的是"左边能不能过"和"右边能不能过"本来就是两个独立的物理判断，各自有明确的视觉证据；四分类要模型直接学四个组合，等于把两个独立信号耦合起来了。第二是样本效率，四分类里两侧都通和两侧都不通都是稀有类，会有失衡；拆成两个二分类各自的正负样本相对均衡。第三是可调试，出问题能定位是左边判错了还是右边判错了。第四是迟滞好做，两个概率各自做迟滞，比在四个类别之间做状态机简单。

**Q1 · 为什么共网？省多少？**

`原理`　Backbone 占 CNN 检测模型总算力的 60–75%。

```
6 个独立模型：6 × (0.7 + 0.3) = 6.0 单位
共享 backbone：1 × 0.7 + 6 × 0.3 = 2.5 单位
→ 省约 58%
```

**在车端算力硬约束下，这不是优化，是"能不能装下"的问题。**

附带收益：多任务互为正则（泛化更好）、工程维护成本（一套预处理、一套部署、一次量化校准）。

`口语`　主要是算力。Backbone 在检测模型里占总算力的六到七成，六个任务各跑一个独立模型是六个单位，共享 backbone 之后大概两个半单位，省了将近六成。在车端算力是硬约束的情况下，这不是优化，是能不能装下的问题。附带的好处是多任务互为正则，泛化会好一些，另外部署维护也简单——一套预处理、一次量化校准。

**Q2 · 四模块**

`原理`

| 模块 | 内容 |
|---|---|
| **config** | 任务名、启用的特征层、head 结构、loss 权重、训练调度 |
| **dataset** | 数据加载、标注解析、该任务专属的增强 pipeline |

| **loss** | 该任务的损失函数与正负样本匹配策略 |

新任务接入只改这四处，**不碰共享层，零额外 Backbone 开销**。

`口语`　接一个新任务只需要改四个地方：config 里写任务名、用哪几个特征层、head 结构、loss 权重和训练调度；dataset 里写数据加载、标注解析和这个任务专属的增强；head 里定义独立的 neck 和检测头；loss 里写损失函数和正负样本匹配。共享层完全不碰，所以新任务只增加自己 head 那部分算力。

**Q1 · mosaic 是什么？**

`原理`　把 4 张训练图随机缩放后拼成一张，目标被打散到四个象限。

**通常有效的三个理由**：

1. 一个 batch 等效看到 4 倍图像内容，丰富上下文
2. **让目标出现在图像各种位置，打破位置先验，防止过拟合到位置**
3. 天然产生大量小目标（缩放后）和截断目标

`口语`　mosaic 是把四张训练图随机缩放后拼成一张，目标就被打散到四个角。它通常有效有三个原因：一个 batch 等效看到四倍的内容；让目标出现在图像各种位置，打破位置先验；还能天然产生一堆小目标和截断目标。

**Q2 · 为什么在本任务有害？**（核心）

`原理`

> **成排锥桶在长焦前视视角下，位置分布极度集中。**

**这个集中是物理决定的**：

- 前视长焦的光轴与车辆前进方向近似平行
- 车辆沿车道行驶，锥桶就在前方路面上
- 消失点附近就是远处锥桶所在的位置

结果：**远距成排锥桶几乎恒定出现在画面中央偏下的一个小区域内**。

**这个位置分布是一个极强的真实先验，模型完全应该利用它。** mosaic 强行把目标打散到四个角，等于**教一个错误的先验**。

`口语`　因为成排锥桶在长焦视角下的位置分布是极度集中的，而且这个集中是物理决定的——前视长焦的光轴跟车前进方向基本平行，车沿着车道走，锥桶就在前方路面上，消失点附近就是远处锥桶的位置。所以远距的成排锥桶几乎恒定出现在画面中央偏下那一小块区域。
这个位置分布是一个非常强的真实先验，模型应该利用它。mosaic 把目标打散到四个角，等于在教一个错误的先验。

**Q3 · 怎么验证的？**

`原理`　**做对比实验**：开 mosaic / 关 mosaic，其余配置完全一致，对比分距离段的 P/R 和整体指标。

**结论**：开 mosaic 指标更差，且**远距漏检明显增加**——这符合预期，因为远距目标最依赖位置先验（远距目标像素少，位置信息的相对贡献更大）。

`口语`　做了对比实验，开和关 mosaic，其余配置完全一样，对比分距离段的 P/R 和整体指标。结论是开了之后更差，而且远距漏检增加得最明显——这跟预期是一致的，远距目标像素少，位置信息的相对贡献更大，所以最依赖这个先验。

**Q4 · 会不会过拟合到位置？**（很好的反问）

`原理`　**这是一个合理的担心，但要分清"过拟合"和"利用真实先验"**：

- **过拟合**：学到的规律在部署时不成立
- **利用真实先验**：学到的规律在部署时依然成立

判断标准是：**这个位置分布在真实部署场景中会不会变？**

- 相机是固定安装的 → 不会变
- 车沿车道行驶 → 不会变
- 长焦视角 → 不会变

所以这不是过拟合，是**正确地利用了场景约束**。

**但仍有边界情况**：急弯时目标会偏离中央、上下坡时垂直位置会变。这些需要在训练数据里有足够覆盖，而不是靠 mosaic 去人为制造。

`口语`　这个担心是合理的，但要分清过拟合和利用真实先验——区别在于这个规律在部署时还成不成立。相机是固定安装的、车沿着车道走、长焦视角，这几个条件在部署时都不会变，所以这不是过拟合，是正确地利用了场景约束。
不过确实有边界情况，急弯的时候目标会偏离中央，上下坡的时候垂直位置会变。这些应该靠训练数据里有足够的真实覆盖来解决，而不是靠 mosaic 人为制造。

**Q5 · 能推广成什么原则？**（这条最值钱）

`原理`

**自检问题**：

| 增强 | 真实会出现吗 | 本任务 |

| HSV 色域变化 | ✓ | 采用 |
| 等比缩放 + padding | ✓ 车端就是这么处理 | 采用 |
| 一张图四个角都有成排锥桶 | ✗ | 弃用 |
| 图像旋转 45° | ✗ | 弃用 |

> **这条和项目四"关掉随机缩放"是完全同一个逻辑**（固定工作距离 → 尺度是常量 → 随机缩放在教不存在的变化）。**两个项目可以串讲。**

`口语`　可以推广成一条原则：数据增强必须匹配目标的真实分布。能涨点的增强，本质上是在补充训练分布里缺失的变化；如果它补充的变化在部署场景里根本不存在，那它就是在注入噪声。
自检的方法很简单——问一句"这个增强产生的图像，在真实场景里有可能出现吗"。色域变化会出现，等比缩放加 padding 车端就是这么处理的，这些就该用；一张图四个角都有成排锥桶不会出现，图像旋转四十五度也不会，这些就不该用。
我在实习那个焊缝项目上关掉随机缩放，也是同一个逻辑——机械臂固定工作距离，尺度本来就是常量，随机缩放是在教一个不存在的变化。

---

**Q6 · MixUp、CutMix 呢？**

`原理`

| 增强 | 是否适用 | 原因 |
|---|---|---|
| **MixUp**（两图加权叠加） | ✗ | 同样破坏位置先验；且产生半透明的"鬼影"目标，真实中不存在 |
| **CutMix**（贴一块到另一张图） | ✗ | 同上；且会在贴块边界产生真实中不存在的硬边 |
| **Copy-Paste**（把目标实例抠出粘贴） | ⚠️ 可能可用 | **前提是只粘到合理位置**（车道内、地面上），保持位置先验 |

> Copy-Paste 你在项目四用过，且那里的关键约束正是"只在焊缝环带内粘贴"——**同一条原则**。

`口语`　MixUp 和 CutMix 都不适用，一是同样破坏位置先验，二是它们产生的图像在真实里不存在——MixUp 会产生半透明的鬼影目标，CutMix 会在贴块边界产生硬边。
Copy-Paste 理论上可以用，但前提是只粘到合理的位置，比如车道内的地面上，保持位置先验。我在焊缝那个项目用过 Copy-Paste，当时的关键约束就是只在焊缝环带内粘贴，贴到孔内壁上模型学到的位置先验就是假的——是同一条原则。

# 第 33 条

> **采用 random crop + padding + HSV 对齐车端预处理，消除离线与车端推理的置信度差异。**

> **这是本项目最有工程价值的一段。**

### 问题清单

| 层 | 问题 |
|---|---|
| 一 | Q1 现象是什么？ |
| 一 | Q2 怎么发现的？ |
| 二 | Q3 怎么定位到是预处理的问题？ |
| 二 | Q4 车端预处理和训练侧具体差在哪？ |
| 二 | Q5 为什么远距目标最敏感？ |
| 二 | Q6 怎么解决的？ |
| 三 | Q7 这件事的真正价值是什么？ |
| 三 | Q8 有没有更彻底的做法？ |

---

**Q1 · 现象**

`原理`　**同一个模型权重**，离线在服务器上推理和车端推理，结果对不上：

- 有的目标框在离线推理置信度 **0.1**，在车端 **0.9**
- 有的反过来
- 离线评测指标好看，上车表现完全不符

**这个问题的可怕之处：它让所有离线指标失去意义。** 每次改动都必须上车实测才能确认，迭代效率直接崩塌。

`口语`　同一个模型权重，离线在服务器上推理和车端推理，结果对不上，有的框离线置信度是 0.1、车端能到 0.9，有的反过来。最可怕的是这让所有离线指标都失去意义了——每改一版都得上车实测才能确认，迭代效率直接崩了。

---

**Q2 · 怎么发现的？**

`原理`　典型发现路径：车端实测的表现和离线评测的结论不一致，且不是"略有差异"而是**方向性矛盾**（离线说好、车上说差）。反复几次之后意识到不是随机波动。

`口语`　是车端实测的表现跟离线评测的结论对不上发现的。而且不是略有差异，是方向性的矛盾——离线说这版好，上车说这版差。反复几次之后就意识到不是随机波动，是有系统性问题。

---

**Q3 · 怎么定位的？**（考排查方法，比考结论更重要）

`原理`　**标准的分段二分法**：

```
① 确认权重一致           → 对比模型文件 MD5                ✓
② 确认输入图像一致        → 保存两端的输入图像逐像素 diff   ← 问题在这里
③ 确认前处理一致          → 对比 resize / normalize / 通道顺序
④ 确认推理引擎一致        → 对比 PyTorch vs TensorRT 逐层输出
⑤ 确认后处理一致          → 对比 NMS 参数、置信度阈值
```

**关键动作：把两端的输入张量 dump 出来逐像素比对。** 一旦发现输入就不一样，后面全不用查了。

`口语`　用分段二分法一步步排。先确认权重一致，对比模型文件的 MD5。然后确认输入图像一致——把两端的输入张量 dump 出来逐像素 diff，问题就在这一步暴露的。如果输入一样，才往下查前处理、推理引擎逐层输出、后处理参数。
关键动作就是把输入 dump 出来比对，一旦发现输入就不一样，后面全不用查了。

---

**Q4 · 具体差在哪？**

`原理`

**车端预处理**（AIPP 之类的硬件前处理单元，YOLO 系标准 letterbox）：

```
原图 1920×1080
 → 等比缩放（保持长宽比）
 → padding 到目标尺寸（填充固定值，如 114 灰）
 → 归一化 / 通道转换
```

**训练侧预处理**：

```
原图 → 直接 resize 到目标尺寸（可能不保持长宽比）→ 归一化
```

**四处差异**：

| 差异 | 影响 |
|---|---|
| **长宽比是否保持** | 目标形状被拉伸 / 压缩，**远距细长的锥桶排最敏感** |
| **padding 灰边** | 模型从未见过图像边缘有大片纯灰色，边缘目标的特征分布完全不同 |
| **有效分辨率** | 等比缩放后目标的实际像素数与直接 resize 不同 |
| **插值方式** | bilinear vs nearest，在小目标上差异明显 |

`口语`　车端做的是标准的 letterbox——等比缩放保持长宽比，然后 padding 到目标尺寸，填充一个固定的灰值。训练侧是直接 resize，可能不保持长宽比。
差异有四处：一是长宽比保不保持，目标的形状会被拉伸或压缩；二是 padding 的灰边，模型从来没见过图像边缘有大片纯灰；三是等比缩放之后目标的实际像素数跟直接 resize 不一样；四是插值方式，bilinear 和 nearest 在小目标上差别明显。

---

**Q5 · 为什么远距目标最敏感？**（关键，说明为什么问题难发现）

`原理`　**远距锥桶本来就在检出边缘**——置信度就在阈值附近。输入分布的微小偏移就足以让它跨过或跨不过阈值。

**大目标不受影响，所以问题不容易被发现——它只在最关键的远距段爆发。**

`口语`　因为远距锥桶本来就在检出的边缘，置信度就在阈值附近晃，输入分布稍微偏一点就足以让它跨过或者跨不过阈值。大目标完全不受影响，所以这个问题不容易被发现——它恰好只在最关键的远距段爆发。

---

**Q6 · 怎么解决的？**

`原理`　**在训练侧把输入分布对齐车端**：

```
训练增强 pipeline 加入：
 ① 等比缩放 + padding（完全复刻车端 letterbox，包括填充值）
 ② random crop（增加位置和尺度的鲁棒性）
 ③ HSV 增强（覆盖光照变化）
```

**关键点**：

- **填充值必须一致**（YOLOv5 用 114，车端硬件可能用 0 或 128）
- **padding 的位置**（居中 / 靠边）也要一致
- 插值方式、归一化的均值方差、通道顺序（RGB / BGR）全部要对齐

`口语`　在训练侧把输入分布对齐车端。具体是在增强 pipeline 里加上等比缩放加 padding，完全复刻车端的 letterbox，包括填充值；再加 random crop 增加位置和尺度的鲁棒性，加 HSV 覆盖光照变化。
关键是细节要完全一致——填充值多少、padding 是居中还是靠边、插值方式、归一化的均值方差、通道顺序是 RGB 还是 BGR，任何一处不一致都会留下偏差。

---

**Q7 · 真正的价值？**

`原理`

> **在此之后，离线指标才可以用来判断车端表现。**

这不是一个精度优化，而是一个**基础设施修复**——它把迭代周期从「改一版 → 上车验证 → 数天」缩短到「改一版 → 离线评测 → 数小时」。

**对一个迭代了 10 个月的子任务来说，这个价值远超任何单点的精度提升。**

`口语`　这件事的价值不是涨了多少点，是让离线指标重新变得可信了。在这之前每改一版都得上车验证，周期是几天；修好之后离线评测几小时就能出结论。对一个迭代了大半年的子任务来说，这个价值远超任何单点的精度提升。

---

**Q8 · 有没有更彻底的做法？**

`原理`　更彻底的是**用同一份预处理代码**：

- 训练和部署共用一套预处理实现（如把 letterbox 写成一个跨语言可复用的模块）
- 或者在 CI 里加一个自动检查：每次发版时 dump 两端的输入张量做逐像素比对，不一致直接阻塞

**这属于工程规范层面的改进，比"这次修好了"更有价值。**

`口语`　更彻底的做法是让训练和部署共用同一份预处理实现，而不是两边各写一套。或者在流程上加一道自动检查，每次发版的时候 dump 两端的输入张量做逐像素比对，不一致就直接阻塞发版。这属于工程规范层面的，比"这次修好了"更有价值。踩过这个坑之后一般都会写进 checklist。

# 第 34 条

> **误检治理：按场景归类误检并构建难负样本库，配合空图负样本定向抑制"路面截断"类过度泛化。**

### 问题清单

| 层 | 问题 |
|---|---|
| 一 | Q1 为什么要按场景归类，而不是堆在一起？ |
| 一 | Q2 "空图负样本"是什么？为什么有效？ |
| 二 | Q3 空图的比例多少？ |
| 二 | Q4 加负样本会掉召回吗？怎么防？ |
| 三 | Q5 除了加数据还有别的办法治捷径学习吗？ |
| 三 | Q6 怎么知道这个捷径真的被打破了？ |

---

**Q1 · 为什么按场景归类？**

`原理`　**为了能定量追踪每一类的收敛情况。**

```
误检库
 ├ 外观相似
 │   ├ 红色反光牌
 │   ├ 施工标志牌
 │   └ 红色车尾
 ├ 场景混淆
 │   ├ 收费站导流
 │   └ 服务区
 └ 捷径学习（路面截断）
     ├ 上坡顶点
     ├ 下坡起点
     ├ 急弯
     └ 桥梁/隧道口
```

**价值三条**：

1. 能看到"上坡已经收敛，但急弯还在涨"，针对性补数据
2. 新版本回归时能定位到具体是哪一类退步了
3. 不同成因需要不同的治理手段（外观相似靠难负样本，捷径学习靠空图）

`口语`　为了能定量追踪每一类的收敛。如果只有一个总的误检数字，你不知道是哪一类在恶化。分类之后能看到上坡这一类已经收敛了但急弯还在涨，就可以针对性地补那一类。而且新版本回归的时候能定位到具体哪一类退步了。
还有一个原因是不同成因需要不同手段——外观相似的靠难负样本挖掘，捷径学习的靠空图负样本，混在一起就没法对症下药。

---

**Q2 · 空图负样本是什么？为什么有效？**

`原理`　**空图 = 完全没有任何目标标注的图像。**

针对捷径学习，专门采集**有路面截断但没有锥桶**的场景：各种坡度的上坡顶点、各种曲率的弯道、桥梁、隧道口、视野受限路段。

**为什么有效**：**直接打破虚假相关。**

```
模型学到的：路面截断 → 有锥桶
空图告诉它：路面截断 → 没有锥桶（大量案例）
→ 模型被迫去学真正的锥桶视觉特征
```

`口语`　空图就是完全没有任何目标标注的图像。针对路面截断这个捷径，我专门采集"有路面截断但没有锥桶"的场景——各种坡度的上坡顶点、各种曲率的弯道、桥梁、隧道口。
有效的原因是它直接打破了那个虚假相关。模型原来学到"路面截断等于有锥桶"，现在给它大量"路面截断但没有锥桶"的案例，它就被迫去学真正的锥桶视觉特征。

---

**Q3 · 空图比例？**

`原理`　需要实验确定。比例太低不起作用，太高会让模型过度保守（掉召回）。常见量级在 1:3 到 1:10（正样本:负样本）。

⚠️ **待核实**：你们的实际比例。

`口语`　这个比例是做实验定的，太低不起作用，太高模型会过度保守、掉召回。常见的量级是正负样本一比三到一比十。我们的具体配置我回去确认一下。

---

**Q4 · 会掉召回吗？怎么防？**

`原理`　**一定会有影响，这是必然的权衡。**

防护手段：

1. **回灌后跑全量评测**——不只看误检专题，要看所有距离段的召回
2. **准入规则是"无恶化引入"**——误检降了但漏检涨了，这版不能上
3. 比例通过消融确定，找到误检下降最多、召回损失可接受的那个点

`口语`　一定会有影响，这是必然的权衡。防护手段就是回灌之后跑全量评测，不只看误检那个专题，要看所有距离段的召回。我们的准入规则是全评测项无恶化，误检降了但漏检涨了的版本是不能上的。比例也是通过消融找到误检降得最多、召回损失可接受的那个点。

---

**Q5 · 除了加数据还有什么办法？**

`原理`

| 方法 | 思路 |
|---|---|
| **反事实数据增强** | 人工合成「有截断无锥桶」「有锥桶无截断」的样本 |
| **因果干预 / IRM** | 让模型在多个环境下都保持不变的预测规则 |
| **Grad-CAM 引导** | 用注意力监督，强制模型看锥桶而不是路面边界 |
| **分组鲁棒优化（GroupDRO）** | 优化最差子群的性能而非平均性能 |
| 扩大感受野 / 加上下文 | 让模型能同时看到路面截断和锥桶，学到联合判据 |

**我们选空图负样本的原因**：最直接、最可控、不改网络结构（共网上改结构成本极高）、效果可量化追踪。

`口语`　学界有几种：反事实数据增强，人工合成有截断没锥桶、有锥桶没截断的样本；因果干预类的方法，让模型在多个环境下保持不变的预测规则；用 Grad-CAM 做注意力监督，强制模型看锥桶不看路面边界；还有分组鲁棒优化，优化最差子群而不是平均。
我们选空图负样本主要是因为它最直接、最可控，不用改网络结构——共网上改结构成本极高——而且效果能量化追踪。

**Q6 · 怎么知道捷径真的被打破了？**（很好的追问）

`原理`　三条证据：

1. **分组评测**——按坡度、曲率分组统计误检率。如果误检率与坡度的相关性显著下降，说明捷径被削弱了
2. **Grad-CAM 复查**——注意力是否从路面边界转移到了锥桶本身
3. **反事实测试**——构造"有截断无锥桶"的样本，看模型是否还报

**只看总误检数下降是不够的**——可能只是模型整体变保守了（同时掉了召回），而不是真的学对了。

`口语`　三条证据。一是分组评测，按坡度和曲率分组统计误检率，看误检跟坡度的相关性有没有显著下降。二是用 Grad-CAM 复查，看注意力是不是从路面边界转移到锥桶本身了。三是反事实测试，专门构造有截断没锥桶的样本看还报不报。
只看总的误检数下降是不够的，那可能只是模型整体变保守了、同时掉了召回，不是真的学对了。

### 问题清单

|---|---|
| 一 | Q1 为什么 IoU 阈值取 0.4 而不是 0.5？ |
| 一 | Q2 0.7/0.7 是不是有点低？ |
| 二 | Q3 这个工作点是怎么选的？ |
| 二 | Q4 P 和 R 都是 0.7 是巧合吗？ |
| 三 | Q5 为什么不用 mAP？ |

---

**Q1 · 为什么 0.4？**（三条理由，不能只说一条）

`原理`

1. **真值边界本身有歧义**——"一排从哪开始到哪结束"标注员之间就有 ±10% 的差异
2. **框又长又细**——一个 300×80 的框，长边方向偏移 10% 就损失 10% 的 IoU，比方形框敏感得多
3. **下游不关心框的精度**——规控要的是"有没有、往哪边"，不是"框准不准"

> **用一个和下游需求不匹配的严格阈值去评测，会把大量业务上完全可用的检出判为失败。**

`口语`　三个原因。一是真值边界本身就有歧义，一排从哪开始到哪结束，标注员之间就有百分之十左右的差异。二是这个框又长又细，一个三百乘八十的框，长边方向偏个百分之十就损失百分之十的 IoU，比方形框敏感得多。三是下游根本不关心框有多准，规控要的是有没有、往哪边。
用一个跟下游需求不匹配的严格阈值去评测，会把大量业务上完全可用的检出判成失败。

---

**Q2 · 0.7/0.7 低吗？**（会被质疑，要能顶住）

`原理`　**要看目标类型和评测口径**：

- 成排锥桶的框边界本身就有歧义（见 Q1），IoU 对这类目标天然不友好
- **更重要的是：下游真正用的不是框有多准，是"有没有检到、往哪边改道"**
- 所以我们更看重**端到端的稳定检出距离和属性准确率**，那两个才决定规控能不能提前变道

`口语`　这个数要看目标类型。成排锥桶的框边界本身就有歧义，一排从哪儿开始到哪儿结束标注员之间都有差异，所以 IoU 对这类目标天然不友好，我们才把阈值取到 0.4。
而且下游真正用的不是框有多准，是有没有检到、往哪边改道。所以我们更看重端到端的稳定检出距离和属性准确率——那两个才决定规控能不能提前变道。框的 IoU 只是一个中间指标。

**Q3 · 工作点怎么选的？**

`原理`　P/R 是**置信度阈值的函数**，报一个 P/R 就必须说清工作点。

选择依据：

- 误检的代价高于漏检（一次误检 = 一次错误变道）→ **偏向高 precision**
- 但 recall 太低会让功能失效（检不到就没有改道感知）
- 实际是在 PR 曲线上找业务上可接受的平衡点，并由下游确认

⚠️ **待核实**：置信度阈值的具体值。

`口语`　P 和 R 是置信度阈值的函数，报这两个数就得说清工作点。选择依据是误检的代价高于漏检——一次误检就是一次错误变道——所以会偏向高 precision；但 recall 太低功能就失效了，检不到就没有改道感知。实际是在 PR 曲线上找一个业务上能接受的平衡点，而且要下游确认。具体的阈值我回去确认一下。

**Q4 · P/R 都是 0.7 是巧合吗？**

`原理`　**不完全是巧合。** 在 PR 曲线上，如果选择的是**平衡点**（P≈R，接近 F1 最大的位置），那么两者相等是自然结果。也可能是取整后的近似。

诚实的说法：这是我们选的工作点上的值，PR 曲线上还有别的工作点。

`口语`　不完全是巧合。如果在 PR 曲线上选的是平衡点，也就是接近 F1 最大的那个位置，P 和 R 相近是自然结果。也可能是取整之后的近似。准确说这是我们选的那个工作点上的值，曲线上还有别的工作点，比如可以牺牲一点召回换更高的精确率。

**Q5 · 为什么不用 mAP？**

`原理`　两个理由：

1. **mAP 是全阈值平均，会掩盖工作点的表现**——量产实际部署只用一个工作点，那个点的 P/R 才是真正生效的
2. **mAP 是平均量，会掩盖长尾**——某个场景（如匝道）的劣化会被平均掉

量产看的是**分场景专题的通过率**和**端到端指标**（稳定检出距离、属性准确率）。

`口语`　两个原因。一是 mAP 是全阈值平均的，但实际部署只用一个工作点，那个点的 P/R 才是真正生效的。二是 mAP 是平均量会掩盖长尾，某个场景比如匝道的劣化会被平均掉。所以我们看的是分场景专题的通过率，还有端到端的稳定检出距离和属性准确率。

**Q4 · 属性准确率怎么统计？**

`原理`　四状态的分类问题，理论上应该看**混淆矩阵**而不只是总准确率：

```
              预测
真值      左   右   都不通  都通
左        ✓    ✗✗    ✗      ✗
右        ✗✗   ✓     ✗      ✗
都不通    ✗    ✗     ✓      ✗
都通      ✗    ✗     ✗      ✓

✗✗ = 最严重的错误（方向完全反了，会导致错误变道）
```

**关键**：左右互相错判（✗✗）的代价远高于其他错误，应该单独统计。

⚠️ **待核实**：你们实际是按总准确率统计的，还是有分状态的统计。

`口语`　这是个四状态的分类问题，理论上应该看混淆矩阵，因为不同的错误代价不一样——左右互相错判是最严重的，会导致错误变道；把"两侧都不通"判成"向左"虽然也错，但至少不会往墙上撞。所以左右互判应该单独统计。具体我们是按总准确率还是有分状态的统计，我回去确认一下。
