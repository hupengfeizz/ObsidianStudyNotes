## 1. 项目概况

| 项 | 内容 |
|---|---|
| **任务定位** | 量产前视 PV（Perspective View，透视图 / 前视相机原图视角）多任务共网中的一个子任务 |
| **业务目标** | 检出高速 / 高架施工改道区的成排锥桶，输出 2D 框 + 向左 / 向右改道属性，供下游规控**提前发起变道** |
| **技术形态** | YOLOv5 系单阶段检测框架；复用共网的共享 Backbone + BiFPN，新增独立 neck 与多头检测头 |

| **你的角色** | 子任务的模型迭代与量产维护 |

### 1.1 这个项目的价值不在模型

先把话说在前面：**这个项目从模型结构上看没有任何新东西**——YOLOv5、GIoU、BCE，全是标准件。

它的真正难度和价值在两个判断：

1. **「成排锥桶」这个目标是我们自己定义出来的**，它不是一个天然存在的物体。定义得好不好，直接决定标注能不能收敛、模型能不能学、下游能不能用。
2. **什么该给下游、什么不该给**。项目中做了一个决策：粘连类检出了但不发布。这个决策比任何 loss 改动都更能体现对量产系统的理解。

这两点是理解整个项目的钥匙。

## 2. 业务场景：高速施工改道到底是什么

> 这一节是你日常工作最不容易接触到的部分，但它决定了所有的技术选择。

### 2.1 施工控制区的标准布置

我国《公路养护安全作业规程》（JTG H30）规定，高速公路施工作业区从上游到下游分为**六个区段**：

```
行车方向 ──────────────────────────────────────────────→

 ┌────────┬──────────┬────────┬──────────┬──────────┬────────┐
 │ 警告区  │ 上游过渡区│ 缓冲区 │  工作区   │下游过渡区 │ 终止区 │
 └────────┴──────────┴────────┴──────────┴──────────┴────────┘
   标志牌     锥桶渐变   空缓冲    实际施工     恢复车道    结束
              (斜排)     (直排)                  (斜排)
```

| 区段 | 长度（高速，限速 100–120km/h） | 内容 |
|---|---|---|
| 警告区 | 1600m 以上 | 施工标志牌、限速牌，无锥桶 |
| **上游过渡区（渐变段）** | **150–250m** | **锥桶斜向排列，把车流从原车道引导到相邻车道** ← 本任务核心 |
| 缓冲区 | 60–100m | 直线排列，作为安全冗余，不施工 |
| 工作区 | 视工程而定 | 实际施工，两侧锥桶或护栏 |
| 下游过渡区 | 30–60m | 恢复车道 |
| 终止区 | 30m | 结束标志 |

**渐变段长度公式**（这是决定锥桶斜率的关键）：

```
V ≥ 60 km/h ：  L = W × V / 1.6
V < 60 km/h ：  L = W × V² / 155
```

其中 `W` = 横向偏移宽度（m），`V` = 限速（km/h）。

举例：封闭一条 3.75m 车道、限速 100km/h → `L = 3.75 × 100 / 1.6 ≈ 234m`。

**这意味着什么**：渐变段的锥桶排布是一条**斜率约 1:60 的极缓斜线**（234m 长、横移 3.75m）。这条斜线的斜率就编码了「往哪边改道」——但斜率太缓，用几个离散锥桶去拟合，噪声很容易淹没信号。**这正是原方案不稳的物理根源。**

### 2.2 锥桶间距规范

| 位置 | 间距 |
|---|---|
| 渐变段 | 4m（部分规范 V/3.6 m，即车速的米/秒数值） |
| 直线段 / 缓冲区 | 8–10m |
| 工作区两侧 | 10–20m |

**间距 4m 意味着**：100m 外的一段 20m 长的锥桶排，图像上只有 5 个锥桶，且互相严重遮挡（视线几乎与排布方向平行时，后面的锥桶完全被前面的挡住）。

### 2.3 目标物的物理规格

| 目标 | 尺寸 | 特征 |
|---|---|---|
| **交通锥**（雪糕筒） | 高 450 / 700 / 900mm，底座 350–400mm 见方 | 橙红色 + 白色反光环，GB/T 24720 |
| **警示柱**（弹力柱 / 圆管） | 高 750–1000mm，直径 80–120mm | 细长，远距像素更少 |
| **防撞桶**（水马 / 沙桶） | 高 800–1000mm，直径 500–900mm | 体积大，红白相间 |
| **反光路障 / 施工护栏** | 变化大 | |

**关键数字：一个 700mm 高的锥桶在 100m 外占多少像素？**

假设前视长焦相机：焦距 f ≈ 12mm，像元尺寸 3μm，即 `f_pixel ≈ 4000 px`。

```
像素高度 = f_pixel × 物理高度 / 距离 = 4000 × 0.7 / 100 = 28 px
```

看起来还行，但**宽度只有 4000 × 0.4 / 100 = 16 px**，且：

- 远处大气散射导致对比度下降；
- 逆光 / 阴影下颜色特征几乎消失；
- 相邻锥桶在图像上重叠成一片。

在 150m 处高度只剩 18px、宽度 10px——**这已经是单目标检测的极限区**。

### 2.4 为什么这个场景对智驾特别关键

| 维度 | 说明 |
|---|---|
| **发生频率** | 高速养护施工是常态，尤其春秋两季 |
| **事故后果** | 施工区是高速事故高发段，撞击锥桶后可能失控、二次事故 |
| **接管代价** | 智驾在施工区不能自主变道 → 用户接管 → 直接体感差评 |
| **提前量需求** | 100km/h = 27.8m/s，一次舒适变道需要 4–6 秒 → **至少需要 110–170m 的提前量** |

**这一行解释了整个项目的 KPI 为什么是「稳定检出距离」**：89m 只够 3.2 秒，变道会很急促；114m 有 4.1 秒，勉强够一次舒适变道。这 25m 不是学术指标，是乘客能直接感受到的差别。

### 2.5 改道形态分类

| 形态 | 描述 | 难度 |
|---|---|---|
| 单侧渐变改道 | 封闭一条车道，车流向另一侧偏移 | 基础形态 |
| 双侧收缩 | 两侧都放锥桶，车道变窄不变向 | 需要判断「两侧都不可通行」 |
| 全封闭 + 借对向道 | 极端情况 | 罕见 |
| 匝道 / 出入口改道 | 弯道叠加改道 | 难，弯道本身就是误检高发区 |
| 移动施工（养护车 + 锥桶） | 锥桶随车移动 | 时序上不稳定 |
| 临时事故现场 | 锥桶摆放不规范 | 分布外样本 |

> `▸ 与你的关系`：最后两类是长尾，也是难负样本库需要重点覆盖的部分。

## 3. 原方案与它为什么不够用

### 3.1 原方案：检单个锥桶 + 规控拟合

```
感知：检出每一个独立的锥桶（2D 框 → 反投 3D 位置）
        ↓
规控：拿到 ≥3 个锥桶的位置 → 最小二乘拟合一条直线 → 算斜率 → 判断改道方向
```

这是最直观的做法，也是很多方案的起点。

### 3.2 它的三个致命问题

**① 误差在拟合环节被放大**

单个锥桶的 3D 位置误差在 100m 处约 ±3–5m（受深度估计精度限制）。拿 3 个这样的点去拟合一条**斜率本来就只有 1:60** 的线：

```
理想斜率 = 3.75m / 234m ≈ 0.016
位置噪声 = ±3m 在 20m 基线上 → 斜率噪声 ≈ ±0.15
```

**噪声是信号的 10 倍。**拟合结果基本是随机的。

**② 检出率的连乘衰减**

规控需要**至少 3 个**锥桶。假设单锥桶在 100m 处的检出率是 0.7：

```
3 个都检出的概率 ≈ 0.7³ = 0.34
```

即使单目标检出率不低，「同时检到 3 个」这个联合事件的概率会急剧下降。这是原方案在远距失效的直接原因。

**③ 遮挡下的系统性缺失**

视线方向与锥桶排布方向夹角很小时，后面的锥桶被前面的完全遮挡。**这不是随机漏检，是几何决定的系统性缺失**——距离越远，可见的锥桶越少，而这恰恰是最需要检出的距离段。

### 3.3 结果

稳定检出距离只有 **89m**（3.2 秒提前量），变道发起晚，**误刹与用户接管频发**。

## 4. PV 前视多任务共网架构

### 4.1 为什么要共网：一笔算力账

假设前视相机上有 6 个感知任务：

| 任务 | 独立模型的算力占用 |
|---|---|
| 车辆 / 行人 2D 检测 | 1× |
| 交通灯检测与颜色识别 | 1× |
| 交通标志识别 | 1× |
| 车道线检测 | 1× |
| 小障碍物 / 施工物检测 ← **本任务** | 1× |
| 可行驶区域分割 | 1× |

**在一个典型的 CNN 检测模型里，Backbone 占总算力的 60–75%。**

```
6 个独立模型：6 × (0.7 backbone + 0.3 head) = 6.0 单位
共享 backbone：1 × 0.7 + 6 × 0.3 = 2.5 单位
```

**算力节省约 58%。**在车端 SoC 算力是硬约束的前提下，这不是优化，是**能不能装下**的问题。

除了算力，共网还有两个附带收益：

- **特征复用带来的正则化效应**：多任务互为正则，共享特征泛化性通常更好；
- **工程维护成本**：一套预处理、一套部署流程、一次量化校准。

### 4.2 硬参数共享 vs 软参数共享

| | 硬参数共享（Hard Parameter Sharing） | 软参数共享（Soft） |
|---|---|---|
| 做法 | 底层网络参数**完全共享**，顶层任务独立 | 每个任务有自己的完整网络，通过正则项约束参数相似 |
| 算力 | 省 | 不省 |
| 任务干扰 | 大（梯度直接冲突） | 小 |
| 部署 | 简单 | 复杂 |
| 量产选择 | **✓ 本项目** | 极少用 |

### 4.3 本项目的共享边界

```
                        ┌──→ [独立 neck] ──→ [车辆/行人 head]
                        │
                        ├──→ [独立 neck] ──→ [交通灯 head]
输入图像                │
   ↓                    ├──→ [独立 neck] ──→ [交通标志 head]
[共享自研轻量 Backbone] ─┤
   ↓                    ├──→ [独立 neck] ──→ [车道线 head]
[共享 BiFPN]  ──────────┤
                        ├──→ [独立 neck] ──→ [施工物 head]  ← 本任务
                        │                        ├─ 检测分支（框 + 置信度 + 类别）
                        │                        └─ 属性分支（改道方向）
                        └──→ [独立 neck] ──→ [可行驶区域 head]

├────────── 共享层（团队维护）─────────┤├─── 子任务自有（你的范围）───┤
```

> `▸ 你的位置`：**共享层往后**。Backbone 与 BiFPN 是团队既有的，你直接复用、未做改动；你新增和迭代的是独立 neck 与多头检测头。

### 4.4 BiFPN 是什么、为什么用它

**FPN 演进路线**：

| 结构 | 特点 |
|---|---|
| FPN (2017) | 自顶向下单向融合，高层语义传给低层 |
| PANet (2018) | 加了自底向上路径，双向 |
| **BiFPN** (EfficientDet, 2020) | 双向 + **可学习的加权融合** + 重复堆叠 |

**BiFPN 的两个关键改动**：

1. **加权融合**：不同分辨率的特征贡献不同，给每条边一个可学习权重 `w_i`，用快速归一化融合：

```
O = Σ ( w_i / (ε + Σ w_j) ) · I_i
```

2. **删除单输入节点**：只有一个输入的节点对融合没有贡献，直接删掉，省算力。

**为什么多任务共网喜欢 BiFPN**：不同任务需要的特征层级不同——交通灯是小目标需要高分辨率浅层特征，可行驶区域需要大感受野的深层语义。BiFPN 提供了一个**各层级都充分融合**的特征金字塔，让每个任务的 head 都能取到合适的层。

> 对本任务尤其重要：**成排锥桶横跨极大尺度范围**——近处的锥桶在图像上几百像素，150m 外只有十几像素。需要 P3（stride 8）到 P5（stride 32）多个层级同时工作。

### 4.5 任务插拔：四模块接入

这是共网框架的工程设计，一个新任务接入只需要改四个地方：

| 模块 | 内容 |
|---|---|
| **config** | 任务名、启用的特征层、head 结构、loss 权重、训练调度 |
| **dataset** | 数据加载、标注解析、该任务专属的增强 pipeline |
| **head** | 独立 neck + 检测头 + 属性头的网络定义 |
| **loss** | 该任务的损失函数与正负样本匹配策略 |

**零额外 Backbone 开销**——新任务只增加自己 head 的那部分算力。

> `▸ 你的位置`：本任务的这四个模块由你维护和迭代。

### 4.6 多任务干扰：真实存在的问题

**现象**：改动 A 任务的 loss 权重，B 任务的指标掉了。因为它们共享的底层特征在被不同方向的梯度拉扯。

**学界的解法**：

| 方法 | 思路 |
|---|---|
| **Uncertainty Weighting** (Kendall, CVPR'18) | 用任务的同方差不确定性自动学习 loss 权重 |
| **GradNorm** (ICML'18) | 动态调整权重使各任务梯度范数平衡 |
| **PCGrad** (NeurIPS'20) | 检测梯度冲突（余弦相似度为负），把冲突分量投影掉 |
| **任务采样调制** | 训练时按比例采样不同任务的 batch |

**量产的实际约束（比学界方法更硬）**：

> **你的改动合入之后，其他任务的评测项不能恶化。**

所以每次改动都要跑**全量多任务评测**，而不只是自己任务的指标。这条规则的存在，使得共网上的任何改动都比独立模型保守得多——这也是为什么这个子任务迭代了 10 个月。

## 5. 目标定义与标注体系（本项目的真正核心）

> 这一章是整个项目最有价值的部分。**「成排锥桶」不是一个天然物体，它的边界是被定义出来的。**

### 5.1 从「检物体」到「检语义」的转变

| | 传统目标检测 | 本任务 |
|---|---|---|
| 目标 | 客观存在的实体（车、人、锥桶） | **人为定义的语义结构**（成排、形成阻塞） |
| 边界 | 物体的物理轮廓，无歧义 | **由规则定义**，需要写规范 |
| 标注一致性 | 天然高 | 需要专门治理 |
| 类比 | 检测一个个字母 | 检测「一个单词」 |

这个转变带来的直接后果：**标注规范的质量 = 模型精度的上限**。规范不清晰，标注员之间不一致，模型学到的就是噪声。

### 5.2 改道类的定义

```
判定条件（全部满足）：
  ① 本车道内 或 侵入本车道
  ② 连续 ≥ 3 个锥桶 / 警示柱 / 防撞桶
  ③ 对该车道形成阻塞（车辆无法沿原车道继续通行）
```

**为什么是 3 个**：延续了原方案「规控需要 ≥3 个点拟合」的口径，保证前后方案的评测可比；同时 3 个也是「成排」这个概念在视觉上成立的最小数量——2 个无法区分是排布还是偶然。

### 5.3 框与车道线强耦合（关键设计）

**问题**：一排锥桶在图像上是斜向延伸的，它的 2D 外接框应该框到哪里？

- 只框可见的锥桶？→ 远端被遮挡的部分丢失，框的长度随遮挡随机变化；
- 框到消失点？→ 框会异常巨大，且没有物理意义。

**解法：框与车道线强耦合**

```
框的近端  = 最近的锥桶底座
框的远端  = 沿车道线方向的延长线外推至阻塞结束位置
不可见侧  = 沿车道线延长线外推，而不是止于最后一个可见锥桶
```

**这个设计的价值**：

1. **框的边界有了确定的几何依据**，不再依赖「能看见几个锥桶」这个随机量；
2. 遮挡不再导致框长度突变，**时序稳定性大幅提升**；
3. 框的形状本身就编码了改道方向的几何信息。

**代价**：标注时需要同时参考车道线，标注成本上升；且**依赖车道线任务的输出质量**——这也是共网的一个隐含好处，车道线任务就在同一张网络里。

### 5.4 粘连类的定义

**为什么需要这一类**：远处的锥桶在图像上会因为透视压缩而连成一片，视觉上无法分离，但它们在物理上是分开的。如果不单独建模，模型会在「一个大目标」和「多个小目标」之间反复摇摆。

**判定标准：底座相连判粘连**

```
如果两个相邻锥桶的底座在图像上相接或重叠 → 判为粘连
沿车道线方向连续粘连的一段 → 标注为一个粘连类目标
```

**为什么用「底座」而不是整体轮廓**：

- 锥桶是上小下大的圆锥，**底座是最宽的部分，最先在图像上相接**；
- 底座位于地面，是**接地点**，在透视变换中位置最可靠；
- 顶部会因为高度差、倾倒、背景干扰而不稳定。

**这条规范的价值**：给了标注员一个**可操作、无歧义**的判据。「看起来连在一起」是主观的，「底座是否相接」是客观的。

> `▸ 你的位置`：标注规范细化由你负责。

### 5.5 标注一致性治理

量产标注项目的标准做法（本任务同样适用）：

| 措施 | 说明 |
|---|---|
| **规范文档 + 图示** | 每条规则配正例 / 反例 / 边界案例的图片 |
| **标注员培训与考核** | 上岗前用金标准集考核，通过才能接活 |
| **金标准集（Gold Set）** | 由算法工程师亲自标注的一小批数据（几百张），作为标尺 |
| **一致性度量** | 多人标注同一批数据，计算 IoU 一致性 / Cohen's Kappa |
| **争议案例回流** | 标注员标记的疑难案例定期评审，评审结论更新进规范 |
| **抽检** | 每批交付抽检 5–10%，不合格整批返工 |

**成排锥桶这类目标的一致性天然偏低**——「一排从哪开始到哪结束」不同人会有差异。这也**直接解释了为什么评测 IoU 阈值取 0.4 而不是 0.5**：真值本身就有 ±10% 的边界抖动，用 0.5 的阈值会把大量正确检出判成错误。

## 6. 改道属性建模：三轮迭代全过程

> `▸ 你的位置`：三轮迭代**全程参与，与同事一起推进**（不是独立主导）。

### 6.1 要解决的问题

下游规控需要知道：**这个施工区要求我往左还是往右改道？**

这个信息必须从视觉上判断——锥桶排布的斜向趋势指向哪一边。

### 6.2 第一版：接地点回归

**方案**

```
检测头额外输出 4 个数：(x_start, y_start, x_end, y_end)
  = 这一排锥桶的首尾两个接地点在图像上的坐标
损失：Smooth L1
```

**设计动机**：这两个点可以反投到 BEV 空间，给规控一条明确的斜线。几何信息完整，理论上最"有用"。

**失败原因**

| 问题 | 说明 |
|---|---|
| **无视觉锚点** | 「一排的起点」到底是哪个锥桶的哪个位置？是第一个锥桶的底座中心？还是它的左下角？**图像上没有一个明确的视觉特征对应这个点**，标注员之间不一致，网络也学不出稳定的响应 |
| **点漂移大** | 同一个场景连续帧之间，预测点在图像上跳动幅度可达几十像素，反投到 BEV 后斜率完全不可用 |
| **两类干扰** | 改道类和粘连类的点分布规律不同（粘连类的"起点"更模糊），放在一个头里学会互相干扰 |

**中间改进**：把成排类和粘连类的点**拆成两组分别回归**，有改善，但漂移仍然大。

**根本问题**：**在回归一个没有视觉定义的量。**

### 6.3 第二版：角度 sin-cos 回归

**方案**

```
检测头输出 2 个数：(sin θ, cos θ)
  θ = 锥桶排布直线在图像/BEV 中的方向角
损失：Smooth L1 或 L2
推理：θ = atan2(sin, cos)
```

**为什么用 sin-cos 而不直接回归 θ**：角度在 0 / 2π 处不连续。真值 359°、预测 1°，实际只差 2°，但 L1 loss 算出来是 358——梯度会把模型往完全错误的方向推。sin-cos 双分量是连续表示，消除这个跳变。

> 同样的技巧在**项目一的 CenterPoint 朝向回归**里也用到了。这是 3D 检测的标准做法。

**比第一版好在哪**：角度是一个有明确几何意义的整体量，不依赖某个具体点的定位；标注上也更容易达成一致（画一条趋势线比标两个点容易）。

**失败原因：左右临界处的跳变**

这是最关键的一点。改道方向的判断本质上是看角度落在哪一侧：

```
θ > 0  → 向左改道
θ < 0  → 向右改道
```

当实际排布接近正前方（`θ ≈ 0`）时——**这恰恰是最远距离、锥桶排布还没有明显偏移的时候**——一点点噪声就会让 θ 在 0 附近来回穿越：

```
帧 1: θ = +0.3°  → 判定「向左」
帧 2: θ = -0.2°  → 判定「向右」
帧 3: θ = +0.1°  → 判定「向左」
```

**时序上就是疯狂抖动的方向信号，规控完全没法用。**

而且这个问题**在最需要它的距离段最严重**：远处斜率小、抖得厉害；近处斜率大、反而稳定——但近处规控已经来不及变道了。

**sin-cos 解决的是数值连续性，没有解决决策边界的不稳定性。**这两件事经常被混淆。

### 6.4 第三版：左右通行性双二分类

**方案**

```
检测头输出 2 个独立的二分类：
  left_passable   ∈ {0, 1}   左侧是否可通行
  right_passable  ∈ {0, 1}   右侧是否可通行
损失：BCE（各自独立）

组合出四种状态：
┌──────────────┬───────────────┬────────────────────────┐
│ left / right │ 语义           │ 规控动作                │
├──────────────┼───────────────┼────────────────────────┤
│  1  /  0     │ 向左改道       │ 向左变道                │
│  0  /  1     │ 向右改道       │ 向右变道                │
│  0  /  0     │ 两侧均不可通行 │ 减速 / 停车 / 请求接管   │
│  1  /  1     │ 两侧均可通行   │ （异常态，用于自检）     │
└──────────────┴───────────────┴────────────────────────┘
```

**为什么这一版成功**

| 维度 | 说明 |
|---|---|
| **匹配任务本质** | 改道方向是**离散语义**，不是连续几何量。用分类建模离散量，天然稳定 |
| **消除决策边界抖动** | 二分类的输出是概率，加上迟滞阈值（如 >0.6 才翻转）即可完全消除跳变 |
| **表达力更强** | 能表达「两侧都不可通行」——这是角度回归**根本无法表达**的状态，而它对应的是真实存在的双侧收缩场景 |
| **自检能力** | (1,1) 是异常态，可以作为模型置信度的一个信号 |
| **标注更容易** | 「左边能不能过」比「画一条趋势线」更容易达成一致 |
| **下游更好用** | 规控要的就是一个方向决策，不是一条直线方程 |

**类比**：这个建模方式和**转向灯的左右灯**是一致的——车辆不会输出「我要转 37.5 度」，而是输出「左」或「右」。**离散语义就该用离散建模。**

### 6.5 三轮迭代的方法论提炼

这三版失败与成功的根本原因可以概括成一句话：

> **前两版都在回归一个下游根本不需要的精确几何量；第三版直接输出下游真正需要的离散决策。**

| | 第一版 | 第二版 | 第三版 |
|---|---|---|---|
| 建模 | 点回归 | 角度回归 | 双二分类 |
| 输出类型 | 连续（4 维） | 连续（2 维） | 离散（2 个概率） |
| 主要失效 | 点无视觉锚点、漂移 | 决策边界跳变 | — |
| 时序稳定性 | 差 | 差 | **好** |
| 表达力 | 完整几何 | 方向角 | 四状态语义 |
| 下游可用性 | 需自行判断 | 需自行判断 + 滤波 | **直接可用** |

**通用教训**：设计输出格式之前，先问「下游到底要什么」。给出比需求更精确的量，往往意味着更不稳定的量。

## 7. 检测框架、损失与训练配置

### 7.1 YOLOv5 结构回顾

```
输入 (640×640 或 长条形如 1280×704)
   ↓
Backbone (CSPDarknet53 / 本项目为自研轻量骨干)
   ├─ Focus / Conv stem
   ├─ C3 模块 × N（CSP 结构：特征图分两路，一路过残差块，一路直连，最后 concat）
   └─ SPPF（空间金字塔池化，串联三个 5×5 maxpool，等效大感受野）
   ↓ 输出 P3(1/8) P4(1/16) P5(1/32)
Neck (PANet / 本项目为 BiFPN)
   ↓
Head (三个尺度各自输出)
   每个尺度、每个 anchor 输出：
     4 (box: tx,ty,tw,th) + 1 (objectness) + C (classes) + A (属性)
```

**本任务的 head 输出**（在标准 YOLOv5 基础上扩展）：

```
box:        4     (x, y, w, h)
objectness: 1
class:      2     (改道类 / 粘连类)
attribute:  2     (left_passable, right_passable)  ← 第三版
```

### 7.2 损失函数

```
Loss_total = λ_box · L_GIoU
           + λ_obj · L_BCE(objectness)
           + λ_cls · L_BCE(class)
           + λ_attr · L_BCE(attribute)
```

**为什么框回归用 GIoU 而不是 L1**

| | L1 / L2 | IoU | **GIoU** |
|---|---|---|---|
| 尺度不变性 | ✗（大框的绝对误差天然大） | ✓ | ✓ |
| 与评测指标一致 | ✗ | ✓ | ✓ |
| 无重叠时有梯度 | ✓ | **✗（IoU=0，梯度消失）** | **✓** |

**GIoU 的定义**：

```
GIoU = IoU - |C \ (A ∪ B)| / |C|
```

其中 `C` 是同时包住 A、B 的最小外接框。当两框完全不重叠时，IoU = 0 没有梯度，但 GIoU 会随着两框距离增大而趋向 -1，**梯度仍然存在，能把预测框"拉"向真值**。

**这对本任务尤其重要**：成排锥桶的框又长又细（一排 50m 长、宽度只有一条车道），初始 anchor 与真值框经常完全不重叠。

**IoU 损失家族的演进**（了解）：

| 损失 | 增加的考虑 |
|---|---|
| IoU | 重叠面积 |
| GIoU | + 最小外接框（解决不重叠） |
| DIoU | + 中心点距离（收敛更快） |
| CIoU | + 长宽比一致性 |
| **NWD**（小目标专用） | 把框建模成高斯分布，用 Wasserstein 距离，对小目标位置偏移不敏感 |

> NWD 你在**项目四（焊缝检测）**用过。本任务如果远距小目标问题更突出，NWD 也是可选项。

### 7.3 Anchor 设计

YOLOv5 是 anchor-based，anchor 尺寸通过对训练集真值框做 **k-means 聚类**得到（YOLOv5 用遗传算法进一步优化）。

**本任务的特殊性**：成排锥桶的框**长宽比极端**（一排斜向延伸，外接框可能是 300×80 这样的形状），且**尺度跨度极大**（近处几百像素，远处十几像素）。

默认 COCO anchor 完全不匹配，必须重新聚类。如果 anchor 与真值框的最大 IoU 低于阈值（YOLOv5 默认 0.25），该真值框在训练中**根本匹配不到任何正样本**，等于白标了。

> 这与你在**项目四**遇到的「超长缺陷 anchor 失配」是同一个问题，解法也类似（重聚类 anchor / 拆分标注 / 换 anchor-free）。

### 7.4 训练配置（典型）

| 项 | 值 |
|---|---|
| 框架 | PyTorch |
| 输入分辨率 | 前视长焦常用长条形，如 1280×704 或 1920×1088 |
| Batch Size | 每卡 8–16 |
| 优化器 | SGD momentum 0.937 / AdamW |
| 学习率 | 0.01（SGD），cosine 衰减 + warmup 3 epoch |
| Epoch | 100–300（子任务微调时更少） |
| 多任务训练策略 | 各任务按比例采样 batch，或每个 iter 累积多任务梯度 |
| 冻结策略 | 微调子任务时**冻结共享 Backbone**，只训独立 neck + head（保护其他任务不受影响） |

> **冻结共享层是量产共网的常见做法**——它从机制上保证了「你的改动不会恶化其他任务」，代价是子任务能达到的上限受限于共享特征的质量。
> `▸ 待核实`：你们训练时共享层是否冻结。

### 8.4 Mosaic 消融：为什么关掉一个"通用涨点手段"

**Mosaic 是什么**：把 4 张训练图随机缩放后拼成一张，目标被打散到四个象限。

**它为什么通常有效**：

1. 一个 batch 里等效看到 4 倍的图像内容，丰富上下文；
2. 让目标出现在图像的各种位置，**打破位置先验，防止过拟合到位置**；
3. 天然产生大量小目标（缩放后）和截断目标。

**为什么在本任务上有害**：

> **成排锥桶在长焦前视视角下，位置分布极度集中。**

原因是物理的：

- 前视长焦相机的光轴与车辆前进方向近似平行；
- 车辆沿车道行驶，锥桶就在前方路面上；
- 消失点附近就是远处的锥桶所在位置。

结果是**远距成排锥桶几乎恒定出现在画面中央偏下的一个小区域内**。这个位置分布是一个**极强的真实先验**——模型完全应该利用它。

Mosaic 强行把目标打散到四个角，等于告诉模型「锥桶可能出现在图像任何位置」，**这是在教一个错误的先验**。

**对比实验结论**：开 mosaic 指标更差，且远距漏检明显增加。

**通用教训**：

> **数据增强不是通用配方，必须匹配目标的真实分布。**能"涨点"的增强，本质上是在补充训练分布中缺失的变化；如果它补充的变化在真实场景中不存在，它就是在注入噪声。

**一个可以自检的判断标准**：这个增强产生的图像，**在真实道路上有可能出现吗**？

- 光照变化（HSV）→ 会出现 ✓
- 等比缩放 + padding → 车端就是这么处理的 ✓
- 一张图里四个角都有成排锥桶 → **不会出现** ✗
- 图像旋转 45° → 不会出现 ✗

## 9. 训推一致性问题（一个典型的量产陷阱）

> `▸ 你负责定位与解决`。这是整个项目中最有工程价值的一段。

### 9.1 现象

**同一个模型权重**，离线在服务器上推理和车端推理，结果对不上：

- 有的目标框在离线推理置信度 **0.1**，在车端 **0.9**；
- 有的反过来；
- 离线评测指标好看，上车表现完全不符。

**这个问题的可怕之处**：它让**所有离线指标失去意义**。每次改动都必须上车实测才能确认，迭代效率直接崩塌。

### 9.2 排查路径

标准的分段二分法：

```
① 确认权重一致          → 对比模型文件 MD5 ✓
② 确认输入图像一致       → 保存两端的输入图像逐像素 diff  ← 问题在这里
③ 确认前处理一致         → 对比 resize / normalize / 通道顺序
④ 确认推理引擎一致       → 对比 PyTorch vs TensorRT 逐层输出
⑤ 确认后处理一致         → 对比 NMS 参数、置信度阈值
```

### 9.3 根因：预处理不一致

**车端的预处理**（以昇腾 AIPP 或类似硬件前处理单元为例）：

```
原图 1920×1080
   ↓ 等比缩放（保持长宽比）到 1280×720
   ↓ padding 到 1280×704 或 1280×1280（填充固定值，如 114 灰）
   ↓ 归一化 / 通道转换
模型输入
```

这就是 YOLO 系的标准 **letterbox** 处理。

**训练侧的预处理**：

```
原图
   ↓ 直接 resize 到目标尺寸（可能不保持长宽比）
   ↓ 归一化
模型输入
```

**差异带来的后果**：

| 差异 | 影响 |
|---|---|
| 长宽比是否保持 | 目标的形状被拉伸 / 压缩，**远距细长的锥桶排最敏感** |
| padding 灰边 | 模型从未见过图像边缘有大片纯灰色，边缘目标的特征分布完全不同 |
| 有效分辨率 | 等比缩放后目标实际像素数与直接 resize 不同 |
| 插值方式 | bilinear vs nearest 在小目标上差异明显 |

**为什么置信度能从 0.1 跳到 0.9**：远距锥桶本来就在检出边缘，输入分布的微小偏移就足以让它跨过或跨不过阈值。**大目标不受影响，所以问题不容易被发现——它只在最关键的远距段爆发。**

### 9.4 解决方案

**在训练侧把输入分布对齐车端**：

```
训练增强 pipeline 加入：
  ① 等比缩放 + padding（完全复刻车端 letterbox，包括填充值）
  ② random crop（增加位置和尺度的鲁棒性）
  ③ HSV 增强（覆盖光照变化）
```

关键点是**填充值必须一致**（YOLOv5 用 114，车端硬件可能用 0 或 128），并且 padding 的位置（居中 / 靠边）也要一致。

### 9.5 这件事的真正价值

> **在此之后，离线指标才可以用来判断车端表现。**

这不是一个精度优化，而是一个**基础设施修复**——它把迭代周期从「改一版→上车验证→数天」缩短到「改一版→离线评测→数小时」。

**通用教训**：任何端侧部署的模型，**训练时的预处理必须逐位复刻部署时的预处理**。这包括：

- resize 方式与插值算法
- padding 值与位置
- 归一化的均值方差
- 通道顺序（RGB / BGR）
- 数据类型与量化范围

这是一个每个团队都会踩一次的坑，踩过之后会写进 checklist。

## 10. 误检治理与捷径学习

### 10.1 为什么误检比漏检更要命

| | 漏检 | 误检 |
|---|---|---|
| 后果 | 没有提前变道，人工接管 | **错误变道 / 误刹** |
| 严重性 | 体验差 | **安全事件** |
| 用户感知 | "它没反应" | **"它疯了"** |

一次凭空检出的"施工区"会让车在正常路段突然变道——这不仅危险，而且**对用户信任的破坏是不可逆的**。

### 10.2 误检的三大类

**① 外观相似类**

| 误检源 | 相似点 |
|---|---|
| 远处红色反光牌 | 颜色、反光特性与锥桶一致 |
| 施工路牌 / 限速牌 | 红白配色 |
| 红色车辆尾部 | 颜色 + 大致形状 |
| 路侧红色广告牌 | 颜色 |
| 落叶 / 垃圾堆 | 远距轮廓相似 |

**② 场景结构类**

| 误检源 | 说明 |
|---|---|
| 收费站导流岛 | 有真实的锥桶或护栏，但不是施工改道 |
| 停车场 / 服务区 | 锥桶存在但语义不同 |
| 事故现场 | 有锥桶但摆放不规范 |

**③ 捷径学习类（最隐蔽、也最有价值的一类）**

### 10.3 「路面截断」：一个典型的捷径学习

**现象**：模型在**上下坡顶点**和**急弯**处凭空检出成排锥桶——那里根本没有任何锥桶。

**根因分析**

模型在训练中发现了一个**统计上高度有效、但因果上完全错误**的判别特征：

```
观察：训练集中的成排锥桶场景，几乎都伴随「前方路面在某处被截断 / 消失」
     （因为锥桶阻塞了车道，可行驶路面在那里终止）

模型学到：路面截断 → 有成排锥桶

现实：路面截断还有其他原因——
     · 上坡顶点：前方路面被坡顶遮挡，视觉上"消失"
     · 下坡起点：路面突然下沉出视野
     · 急弯：路面拐出视野
     · 桥梁 / 隧道口
```

这些场景下路面同样"截断"，模型就凭空报出了锥桶。

**这是典型的捷径学习（Shortcut Learning）/ 虚假相关（Spurious Correlation）**：

> Geirhos et al., *"Shortcut Learning in Deep Neural Networks"* (Nature Machine Intelligence, 2020)

经典案例：

- 分类狼 vs 哈士奇的模型，实际学的是「背景有没有雪」；
- 肺炎 X 光分类模型，实际学的是「片子来自哪家医院的设备」；
- **本例：成排锥桶检测模型，实际学的是「路面有没有截断」**。

**为什么这类问题特别难发现**：

1. 在**训练集和常规验证集上完全看不出来**——因为这个相关性在训练分布中是成立的；
2. 只在**分布外场景**（坡、弯）暴露，而这些场景在评测集里可能占比很低；
3. 模型的置信度还很高——它对自己的错误很自信。

### 10.4 治理方案 `▸ 你负责`

**① 误检归类**

不是简单地把误检样本堆进训练集，而是**按误检成因分类**：

```
误检库
 ├─ 外观相似
 │   ├─ 红色反光牌
 │   ├─ 施工标志牌
 │   └─ 红色车辆
 ├─ 场景混淆
 │   ├─ 收费站导流
 │   └─ 服务区
 └─ 捷径学习（路面截断）
     ├─ 上坡顶点
     ├─ 下坡起点
     ├─ 急弯
     └─ 桥梁/隧道口
```

**归类的价值**：可以**定量追踪每一类的收敛情况**。如果只有一个总的误检数字，你无法知道是哪一类在恶化。

**② 难负样本库**

针对每一类，构建专门的负样本集合，回灌训练。关键是**样本要"难"**——不是随机的负样本，而是模型确实会误检的那些。

**③ 空图负样本定向抑制**

「空图」= 完全没有任何目标的图像。

针对捷径学习，专门采集**有路面截断但没有锥桶**的场景：

- 各种坡度的上坡顶点
- 各种曲率的弯道
- 桥梁、隧道口
- 视野受限的路段

**这些样本的作用是直接打破那个虚假相关**——让模型看到「路面截断但没有锥桶」的大量案例，迫使它去学真正的锥桶视觉特征。

**④ 负样本比例的平衡**

加负样本一定会掉召回，这是必然的权衡。所以：

- 负样本比例需要通过实验确定（常见 1:3 到 1:10）；
- 每次回灌后必须跑**全量评测**，确认召回没有恶化超过阈值；
- 这正是「无恶化引入」准入规则的意义。

### 10.5 治理捷径学习的其他手段（本项目未必用到，但值得知道）

| 方法 | 思路 |
|---|---|
| 反事实数据增强 | 人工合成「有截断无锥桶」「有锥桶无截断」的样本 |
| 因果干预 / IRM | 让模型在多个环境下都保持不变的预测规则 |
| 注意力可视化（Grad-CAM） | 直接看模型在看哪里，能快速定位捷径 |
| 分组鲁棒优化（GroupDRO） | 优化最差子群的性能而非平均性能 |

> **Grad-CAM 是排查这类问题最快的工具**：如果模型的注意力集中在路面消失的边界而不是锥桶本身，捷径学习就实锤了。

## 11. 评测体系与指标口径

### 11.1 检测指标

| 指标 | 值 | 口径 |
|---|---|---|
| Precision | **0.7** | IoU 阈值 0.4 |
| Recall | **0.7** | IoU 阈值 0.4 |

**为什么 IoU 阈值取 0.4 而不是标准的 0.5**

这不是为了让数字好看，有明确的技术原因：

1. **真值边界本身有歧义**：「一排从哪开始到哪结束」标注员之间就有 ±10% 的差异（见 §5.5）；
2. **框又长又细**：一个 300×80 的框，长边方向偏移 10% 就损失 10% 的 IoU，比方形框敏感得多；
3. **下游不关心框的精度**：规控要的是「有没有、往哪边」，不是「框准不准」。

**用一个和下游需求不匹配的严格阈值去评测，会把大量业务上完全可用的检出判为失败。**

**这是量产评测的一个通用原则：评测指标要对齐下游的实际需求，而不是照搬学术惯例。**

### 11.2 端到端指标（真正决定成败的）

| 指标 | 基线 | 优化后 | 提升 |
|---|---|---|---|
| **稳定检出距离** | **89m** | **114m** | **+25m** |
| 改道方向属性准确率 | — | — | **+7.3%** |
| 施工专题集凭空误检次数 | 基线 | — | **-5.4%** |
| 全量回归 | — | — | **无恶化项** |

**「稳定检出距离」的严格定义**：

```
目标从远处接近，当【连续 3 帧】都被检出且置信度超过阈值时，
记录【首次稳定】那一刻，【自车中心到目标的直线距离】。
```

三个要素缺一不可：

- **连续 3 帧**：排除偶发的单帧闪现。规控需要能持续跟住的目标，单帧检出没有意义；
- **首次稳定**：不是平均值，是最早能用的时刻；
- **自车中心到目标**：坐标原点和测量对象要明确（自车中心 vs 前保险杠，目标中心 vs 最近点，能差几米）。

**89m → 114m 的业务含义**（100km/h = 27.8m/s）：

```
89m  → 3.2 秒提前量  →  变道急促，乘客不适，部分情况来不及
114m → 4.1 秒提前量  →  一次舒适变道的最低要求
```

### 11.3 需要一起看的其他维度

| 维度 | 说明 |
|---|---|
| 分距离段 P/R | 50m / 80m / 100m / 120m / 150m 各段分别统计 |
| 分场景 | 高速 / 高架 / 匝道 / 隧道口 |
| 分改道形态 | 左改道 / 右改道 / 双侧收缩 |
| 时序稳定性 | 检出闪烁率、属性翻转次数 |
| 误检 | 各类误检的绝对次数（不是率），按千公里归一 |
| **多任务回归** | **共网上其他 5 个任务的指标不能恶化** |

### 11.4 量产评测的准入规则

```
新版本准入 = 目标指标提升
           AND 本任务全评测项无恶化
           AND 共网其他任务全评测项无恶化
```

**第三条是共网特有的约束**，也是这个子任务迭代周期长达 10 个月的直接原因——每次改动的验证成本远高于独立模型。

## 12. 与下游规控的接口设计

> 这一节包含本项目最值得讲的一个决策。

### 12.1 发布内容

| 字段 | 类型 | 说明 |
|---|---|---|
| 2D 框 | float×4 | 图像坐标 |
| 类别 | enum | 改道类 |
| 置信度 | float | |
| left_passable | float | 左侧可通行概率 |
| right_passable | float | 右侧可通行概率 |
| 跟踪 ID | int | 跨帧关联 |

### 12.2 关键决策：粘连类检出但不发布

**粘连类的问题：生命周期不稳定**

```
t=0（远处）    ：整排锥桶在图像上完全粘连  → 1 个粘连类目标，框覆盖整排
t=1（接近）    ：最近的 2 个锥桶开始分离    → 框的起点往前推
t=2（更近）    ：分离出更多                → 框继续收缩
t=3           ：粘连段只剩远端一小截       → 框很小
t=4           ：完全分离                  → 目标消失
```

**这带来三个致命问题**：

1. **无法跨帧关联**：每一帧的框覆盖的物理范围都不同，"同一个目标"这个概念不成立。跟踪器会疯狂地新建 / 销毁 ID；
2. **无法量化评估**：真值也面临同样的定义问题，IoU 匹配的基础不存在；
3. **下游无法使用**：规控拿到一个会自己生灭、边界持续漂移的目标，只能忽略它，或者被它误导。

**决策：留在网络里训练，但不向下游发布。**

**为什么还要保留这一类**：

- 它提供了**训练信号**——让网络学会区分「粘连的一片」和「独立的多个」，间接提升改道类的边界判断；
- 它避免了**标注冲突**——如果不定义粘连类，标注员面对粘连的锥桶不知道该标一个还是标多个，会污染改道类的标注一致性；
- 保留了未来的可能性——如果后续找到稳定的表达方式，可以随时开放。

### 12.3 这个决策为什么重要

> **感知输出的标准不是「检得准不准」，而是「下游能不能用」。**

一个 mAP 很高但生命周期不稳定的输出，对下游是**负价值**——它不仅没帮助，还会引入错误决策和无谓的计算。

**主动选择不发布一个已经做出来的能力，需要对系统边界有清晰认知**。这比多做一个模型更能说明工程判断力。

### 12.4 下游怎么消费这个输出

```
感知输出（框 + 左右可通行性 + ID）
     ↓
跟踪模块：跨帧关联，滤波，稳定 ID
     ↓
决策：
  ├─ 检出稳定 + right_passable=1 → 规划向右变道轨迹
  ├─ 检出稳定 + 两侧均不可通行   → 减速，准备停车或请求接管
  └─ 检出不稳定                  → 保持当前策略，继续观察
     ↓
控制执行
```

**迟滞逻辑**：属性翻转需要连续 N 帧一致才生效，避免单帧噪声导致的方向摇摆。这是二分类建模相比角度回归的又一个好处——概率输出天然支持迟滞阈值。

| 概念 | 一句话解释 |
|---|---|
| **PV** | Perspective View，透视图 / 前视相机原图视角，与 BEV 相对 |
| **硬参数共享** | 多任务共用底层网络参数，顶层各自独立 |
| **BiFPN** | 双向加权特征金字塔，EfficientDet 提出 |
| **CSP** | Cross Stage Partial，特征分两路（一路过残差块、一路直连）再合并，省算力 |
| **SPPF** | 空间金字塔池化快速版，串联多个 maxpool 获得大感受野 |
| **GIoU** | 广义 IoU，加入最小外接框项，解决无重叠时梯度消失 |
| **NWD** | Normalized Wasserstein Distance，把框看作高斯分布，小目标友好 |
| **letterbox** | 等比缩放 + 灰边填充的图像预处理方式 |
| **AIPP** | 昇腾芯片的硬件前处理单元（AI Pre-Processing） |
