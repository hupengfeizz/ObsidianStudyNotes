### Q2 · 深度的监督信号从哪来

**你的回答**:用激光点云的深度值作为监督,DepthNet 预测每个像素的深度概率。

**得分**:4 / 5 | **标签**:—

**缺的部分**:没说投影和取值细节。面试官很可能接着问"点云投到图像上,一个下采样后的 patch 里有好几个点怎么办"。

**补充要点**:
- 点云用外参+内参投到图像平面,得到稀疏深度图。
- 特征图是下采样过的(比如 stride 8),所以真值也要下采样。**下采样时取 patch 内的最小有效深度,不是均值**。
- 为什么取 min:一个 patch 里如果同时打到前景车和背景墙,特征在这个位置表达的是前景。取均值会造出一个"车和墙之间的虚空深度",物理上什么都没有。

**你的回答**:点云稀疏,远处更明显;用历史 3 帧叠到当前帧,做运动补偿,实现稠密化。

### Q4 · 位姿变换对静止点和运动目标,效果一样吗

**你的回答**:不一样,自车在动、目标也在动,需要两个补偿。

**得分**:2.5 / 5 | **标签**:E4 表达

**方向对,但没说清"为什么不一样"**,只说了"需要两个补偿"——那是解法,不是原因。面试官问的是效果差异,你直接跳到了对策。

#### 标准答法(三句,到此为止)

> **不一样。**位姿变换补偿的是自车运动,它的隐含假设是"**世界是静止的**"。
>
> 对静止的地面、建筑、停着的车,这个假设成立,变换完点精确落回原位,叠加是干净的。
>
> 对运动目标,假设不成立——历史帧那辆车在物理世界里真的移动了。位姿变换只是把它从**历史时刻的自车坐标系**换算到**当前时刻的自车坐标系**,并没有把它从**历史位置**搬到**当前位置**。所以叠出来是一条拖影:同一辆车在不同位置留下好几份点。

**答到这里就停。**"那动态目标怎么办"是下一个问题,等面试官问。

#### 备用补充(只在面试官追"那还有别的吗"时抛)

位姿变换其实是两级,都只针对自车:

| 级别 | 做什么 | 依赖 | 对谁有效 |
|---|---|---|---|
| 帧级:自车运动补偿 | 用定位位姿把历史帧点变换到当前帧 lidar 坐标系 | IMU / 轮速 / 定位 | 静止世界 |
| 点级:去畸变 | 按每点时间戳插值位姿,补偿单帧扫描一圈内的自车运动 | 逐点时间戳 | 静止世界(修正机械式激光的畸变) |

两级都建立在同一个静止世界假设上,所以**对动态目标同样无效**——这也正好回扣主答案。

> 📌 **本题诊断同时适用于我自己**:初版这里直接给了一张分级表当"标准答案",而问题问的是"一样吗"。**表回答的是"怎么做",不是"是不是"。**这犯的正是评你 E4 的同一个错。凡是"是不是 / 会不会 / 能不能"开头的问题,第一个字必须是**是**或**不是**。

### Q5 · 前车的运动从哪拿

**你的回答**:用历史帧检出的目标做速度估计,再补偿。

**得分**:1.0 / 5 | **标签**:**E1 概念混淆(训练期 / 推理期)+ E7 层级错位**

**这是本期踩得最实的一个坑,而且踩法比初版记录的更严重。**

> 📌 **过程还原(据本人事后复述)**:第一次作答是"凭空给的一个答案",自己当时就知道依赖模型检出不对。被追问后**没有回到"来源"这个问题上,而是转去讲"怎么处理"(直接剔除)**。整个 Q5 到 Q6 的过程里,**"标注框"这三个字从头到尾没有说出口**——正确来源是面试官在点破循环依赖时带出来的,不是你答出来的。

#### 这题问的是什么

"从哪拿"是**来源题**。来源题的答案是一个名词,不是一段流程。正确答案就三个字:**标注框**。说完这三个字,这题就结束了。

你答的"直接剔除"是**拿到之后怎么用**,属于下一个问题。把下一题的答案拿来回答这一题,面试官听到的结论是:**他不知道来源。**

#### 为什么必须是标注框

判据只有一条:**训练期的监督信号,不能包含模型自己的输出。**

用检出速度去构造深度真值、再拿这份真值训练同一个网络,误差会自我强化——网络把车测远了,聚合点云跟着往远处搬,真值反过来确认了它的错误。**监督必须来自模型之外。**标注框是人标的,在模型之外,所以它合法。

#### 必然会跟的一问:推理期没有标注框怎么办

**不办,这条链在推理期根本不存在。**深度真值只有训练时需要;上车后 DepthNet 直接吐深度分布,不需要真值,自然也不需要聚合点云、不需要标注框。**多帧点云聚合是离线数据处理,不是网络的一部分。**

这一刀正好切在你混淆的地方:"推理期哪来的运动信息"和"训练期真值怎么造"是**两个时刻的两件事**,中间唯一的联系是前者训出的权重被后者加载。

#### 一句话记法

**离线造真值用标注,在线跑推理才用检出。**

#### 下次的应对模板

"从哪拿 / 从哪来"这类来源题,**首句只能是一个名词**:标注框 / 激光点云 / 网络回归 / 人工标注。给完名词再展开怎么用。

如果想不起来源,正确动作是:**先承认想不起来源,再补一句"不过拿到之后怎么处理我知道"**——面试官听到的是一个知识缺口。你当时的答法,他听到的是一个概念混乱。**这两者在评分上差很远。**

### Q6 · 那循环依赖怎么理清 / 动态目标具体怎么处理

**你的回答**:动态目标叠加会拖影(一秒能拖十多米);处理方式三种——直接剔除、按目标速度单独补偿、混合策略;并补充了两级补偿(位姿补偿 + 逐点去畸变)。

**得分**:1.5 / 5 | **标签**:**E7 层级错位**(主)+ E1(修正发生在被点破之后,不计加分)

> ⚠️ **本题在 v3 修订中由 2.5 下调至 1.5。**理由见下。

**原评价说这是"本期最好的一次救回来",那是虚高;v2 给的 2.5 分仍然偏高。**

这题的**前半问**"循环依赖怎么理清",答案只有一个词:**标注框**。你没有答。你答的是**后半问**"动态目标具体怎么处理"——三种策略和两级补偿,那部分是真存货,值 1.5 分。**前半问是这道题的重心,拿零分。**

#### 比失分更值得记的一点

你答出了"**用框剔除历史帧落框内的点**"——**那个框是从哪来的?就是标注框。**

也就是说:**你手上有正确答案的所有零件,但没把它组装起来指向"来源"这个问题。**

这说明缺的不是知识,是"**面试官问的到底是什么**"这个判断。知识缺口靠背能补,判断缺口只能靠练——这正是新增 **E7 层级错位**这一类归因的原因,详见第三节。

**真实归属**:三种策略和两级补偿的分层是你自己的存货;从错误答案走到正确答案那一步,是被面试官点破后牵引的,不是自发的。真实面试官不做这个定位,Q5 就停在错误答案上了。

**三种策略的取舍要点(记住取舍,不要只记名字)**:

| 策略 | 做法 | 代价 |
|---|---|---|
| 剔除 | 标注框框住动态目标,历史帧落框内的点全删 | 可靠,但那块区域退回单帧稀疏度 |
| 单独补偿 | 按标注框速度对框内点做刚体变换 | 保住密度,但精度依赖标注速度质量 |
| 混合 | 高质量跟踪的补偿,其余剔除 | 工程上最常用,但要定阈值 |

#### 两条极易混淆的点(本人事后确认曾混淆,单独立出)

**① 剔除和补偿是互斥的二选一,不是先后步骤。**

- **剔除 = 宁缺毋滥**:目的**不是**给动态目标稠密化,恰恰是**放弃**给它稠密化。动态目标叠三帧会散在三个位置,叠出来是拖影——**假几何比稀疏更糟**。所以删掉历史帧落在它身上的点,这块区域退回单帧稀疏度,但至少是**真的**。稠密化的收益只留给静止世界:地面、路沿、建筑、停着的车。
- **补偿 = 搬对位置**:通过跟踪 ID 关联历史帧框和当前帧框,算出**刚体位移**,把历史帧框内的点按这个位移搬到当前帧框的位置。点留下了,且搬对了,所以动态目标也能稠密化。代价是精度全靠标注框位置和跟踪 ID,框标歪、ID 跳,搬过去就是错的,而且**错得很隐蔽**。

**② 剔除时,删的是历史帧的点,判定用的也是那一帧自己的框。**

顺序是:在**第 t−1 帧的坐标系里**,用**第 t−1 帧的框**把车身上的点挑出来删掉;剩下的静止点再做位姿变换搬到当前帧。

**筛选发生在变换之前,不是之后。**常见的误解是"用当前帧的框去筛"——但那辆车在历史帧里根本不在当前帧那个框的位置上,用当前帧的框去筛**圈不住它**。必须在各自的时刻、用各自的框,把动态点就地清掉。

**最终这份聚合点云长这样**:静止区域是三帧叠加的稠密点,动态目标身上是单帧的稀疏点。**稠密化的收益按区域分配,拖影的风险也按区域切除。**

**为什么这对深度监督特别重要**:这份点云要投到图像上生成深度真值。动态目标带拖影,投上去就在那辆车周围铺出一片**错误深度**——而车恰恰是最需要测准的目标。**宁可那块像素因点少而没有监督(`fg_mask` 里直接是零),也不能给错的监督。**

**可以主动抛的一句**:"我们最后是混合策略,因为纯剔除会把动态目标周围本来就最缺监督的区域掏空,而动态目标恰恰是我们最关心的检出对象。"

### Q7 · 连续深度真值(37.4 米)怎么变成分类标签 🔴

**你的回答**:先讲了 bin 划分和加权求和,被追问三次后回答"这块确实不清楚"。

**得分**:0 / 5 | **标签**:**🔴 空白 + E5 回避 + E1 训练/推理混淆**

**这题原来给了 0.5 分,理由是"承认不会值得鼓励"。撤销。**

实际过程是:第一轮问训练侧标签,你答了推理侧的加权求和;第二轮再问,你答成了"为什么用分类不用回归";第三轮面试官明说"如果不确定,可以直接说这块是同事写的、你没细看,这比现在这样绕更好",你才承认。

**这是先绕两轮、被递台阶后才下的。**在真实面试里:(a) 前两轮答非所问会被判为 **E5 回避**,是扣分项;(b) 面试官不会递那个台阶,他会记一笔"被追问时会绕"然后继续压。所以这题按 0 分,并且**前置的两轮回避还要计入诚这一维的扣分**。

这个知识点压在简历"深度估计"四个字正下方,是必挖点,必须补。

#### 正确答案(以 BEVDepth / BEVFusion 官方实现为准)

**训练侧标签构造:硬 one-hot,零头直接丢弃。**

```
# get_downsampled_gt_depth 的核心逻辑
1. 按特征图 stride 把深度图切成 patch
2. patch 内把 0 替换成 1e5,取 min → 保证取到最近的有效点(前景优先)
3. gt = (d - (d_min - d_step)) / d_step      # 变成 bin 索引,是浮点
4. 越界的置 0
5. one_hot(gt.long(), D+1)[:, 1:]            # .long() 直接截断
```

关键就在第 5 步的 `.long()`——**直接截断,37.4 变成 37,那个 0.4 就没了**。

所以:**深度精度的天花板 = 一个 bin 的宽度**。nuScenes 默认 `dbound=[1.0, 60.0, 0.5]`,118 个 bin,每个 0.5 米,天花板就是 0.5 米。

**损失函数:BCE,不是 softmax 交叉熵。**

```
fg_mask = max(depth_labels, dim=1).values > 0.0    # 只在有激光点的像素上算
F.binary_cross_entropy(depth_preds[fg_mask], depth_labels[fg_mask])
with autocast(enabled=False)                        # 混合精度下 BCE 数值不稳
× depth_loss_factor (默认 3.0)
```

`fg_mask` 这行**正是多帧点云聚合的价值来源**:没有激光点的像素根本不参与损失。点越稀疏,参与监督的像素越少。叠多帧 = 让更多像素进入 `fg_mask`。这个因果链要能当场讲出来,是把 Q3 和 Q7 串起来的关键。

#### 推理侧:LSS 根本不塌缩

你说"最终对所有概率加权求和输出"——**这在 LSS 里是错的**。

LSS 前向是:`depth = x[:, :D].softmax(dim=1)`,然后 `depth.unsqueeze(1) * feat.unsqueeze(2)`。**完整的软分布直接参与外积**,没有 argmax,没有加权求和。

加权求和成一个标量深度图,只在你想输出深度图做可视化或评测深度精度时才做。你把深度估计任务(DORN 那类)的做法串过来了。

#### 可以主动抛的加分点

| 方案 | 做法 | 相对硬 one-hot 的好处 |
|---|---|---|
| **DFL**(Distribution Focal Loss,来自 GFL) | 37.4 → bin37 给 0.6,bin38 给 0.4 | 保住零头,突破 bin 宽天花板 |
| **LID / SID** 非均匀分箱 | 远处 bin 更宽 | 匹配"远处本来就估不准"的先验,不浪费 bin |
| BCE 而非 softmax-CE | 每个 bin 独立 sigmoid | 允许多峰(玻璃、边缘处深度本就有歧义) |

**面试话术**:"标签是硬 one-hot,`.long()` 截断,零头丢掉,所以精度上限就是一个 bin 宽。如果要更细,可以换成 DFL 那种把真值分到相邻两个 bin 上的做法,或者用 LID 非均匀分箱把 bin 往远处放宽。我们当时用的是均匀分箱 + 硬标签。"

### Q13 · 那张查找表,是从像素查格子,还是从格子查像素 🔴

**你的回答**:像素查格子,按索引取深度概率乘语义特征,再累加到目标格子。

**得分**:0 / 5 | **标签**:**🔴 E2 方向反了**

**这是 BEVPool 最核心的一点,答反了等于没懂这个优化。**

#### 标准答法(第一句必须先选边)

> **从格子查像素。**表是按输出 BEV 格子组织的,每个格子存"哪些视锥点属于我"。

先给方向,再讲为什么。**这题问的是二选一,第一句就要落到其中一边**,不能先讲机制让面试官自己去推。

#### 为什么"像素查格子"没用

如果表是像素→格子,你还是得遍历 760 万个点,每个点算出目标格子,往上加。多个点落进同一格子就有**写冲突**,要么排序做前缀和,要么用原子加。**昂贵的部分一点没省掉**,查表只省了一次坐标变换的乘法,而那本来就不是瓶颈。

#### 正确方向:表按输出 BEV 格子组织

预计算阶段就把"**哪些视锥点会落进这个格子**"这份归属关系算好、排好、存起来:
- `ranks_bev`:每个点归属哪个 BEV 格子
- `interval_starts` / `interval_lengths`:每个格子对应的点区间在哪、有多长

运行时,**每个输出格子去表里读属于自己的那串点索引,取来求和**。

**好处**:
- 每个输出格子**互相独立**,一个线程包一个格子
- 没有写冲突 → 不需要原子加
- 不需要排序(排序在离线阶段做完了)
- 不需要前缀和

**一句话记法**:🔑 **查找表是格子问点要,不是点找格子。**

#### 源码铁证(被追问时直接抛这个,比讲道理有力)

```cuda
float psum = 0;
for (int i = 0; i < interval_length; i++) {
    cur_depth = depth + ranks_depth[interval_start + i];
    cur_feat  = feat  + ranks_feat[interval_start + i] * c + cur_c;
    psum += *cur_feat * *cur_depth;
}
*cur_out = psum;          // 普通赋值,不是 atomicAdd
```

**最后一行是赋值,不是原子加。**如果是点推格子,多个线程会往同一个地址写,这里**必须**是 `atomicAdd`。写成普通赋值,只可能是因为这个线程**独占**这个输出地址——一个线程包一个格子。

第二个佐证:`interval_starts` / `interval_lengths` 的**长度等于有效格子数,不等于点数**。表是按输出格子编的索引。

#### 为什么必须是这个方向(这才是追问的第三层)

**先破一个误区:两个方向都能实现,信息是同一份,正查反查都查得到。v1 就是点推格子。**所以这不是"能不能"的问题,是"GPU 上哪个快"的问题。答成"因为只有这个方向查得到"会被当场戳穿。

| | 点推格子 | 格子拉点 |
|---|---|---|
| 线程数 | 760 万 | 几万 |
| 写冲突 | 几十个线程抢同一格子,必须原子加,排队串行 | 地址独占,零竞争,普通赋值 |
| 热点问题 | 事先不知道哪个格子挤,**热点格子拖慢整个 kernel** | 无 |
| 视锥张量 | 必须**先全部物化**再 scatter,几个 G 显存 | **根本不用存在**,按索引现取现算 |

**GPU 怕的不是线程少,是线程抢同一块内存。**

**一句话收口**:方向的选择不是为了查得到,是为了**写不打架、也不用把中间张量落地**。第二条才是 v1→v2 最大的省。

#### 易被追问:"真的完全不排序吗"

排序**在离线构表时做过一次**(`ranks_bev.argsort()`),内外参固定所以只做一次,**运行时不再排**。笼统说"不排序"站不住,这样说才准确。

> ⚠️ **知识库第 95 条有误导性,建议自行修订。**原文写"运行时直接按索引把深度概率乘上下文特征**累加进目标格子**"——这句话描述的是**数据最终去了哪**,而不是**循环按谁组织**。两种实现的结果都是"累加进了目标格子",所以这句话对两个方向**同时成立**,区分不出方向,读起来反而像"点推格子"。**判别标准只有一个:循环是按谁展开的。**

#### v1 与 v2 的区别(可主动抛,是加分点)

| 版本 | 做法 | 是否物化视锥张量 |
|---|---|---|
| 原始 LSS splat | 算 rank → 排序 → cumsum → 取区间差 | 是 |
| **BEVPool v1** | 预计算 rank 和 interval,每格子一线程直接区间求和,去掉排序和 cumsum | **仍然是** |
| **BEVPool v2** | 再多存 `ranks_depth` / `ranks_feat` 两张索引表,kernel 里现场 `depth[i] * feat[j]` 再累加 | **否,从不物化** |

v2 相对 v1 的核心增量:**把外积融进了 pooling kernel,那个几 GB 的视锥特征张量从来没在显存里存在过。**

你简历上写的是 BEVPool v1 的 cumsum 实现,所以这个 v1/v2 的分界你必须能说清,否则会被追问"那你到底实现的是哪个"。

**所以 E7 缺的不是知识,是"面试官问的到底是什么"这个判断。**这类失分在评分上等同于不会,而且因为你答得流畅,面试官不会给你第二次机会。

**纠正法**:回答前先花一秒给问题**定性**,再决定首句说什么——

| 问题类型 | 关键词 | 首句必须是 |
|---|---|---|
| 判断题 | 一样吗 / 会不会 / 能不能 / 是不是 | **是** 或 **不是** |
| 来源题 | 从哪来 / 从哪拿 / 谁提供 | **一个名词** |
| 原因题 | 为什么 / 为何不 | **最核心的那一个原因** |
| 方法题 | 怎么做 / 如何实现 | **方法名** |
| 数字题 | 多少 / 多大 | **数字**,后面再解释 |

**答不出时的正确动作**:先承认这一层答不出,再补相邻层。"来源我一时想不起来,不过拿到之后怎么处理我知道"——面试官记的是**一个知识缺口**。直接答相邻层,他记的是**概念混乱**。**两者评分差很远。**

- **E1 全部集中在"训练期 vs 推理期"这条分界线上**。这不是偶然——你的实际工作可能更偏推理侧和评测侧,训练期的实现细节接触少。这是需要专门补的一整块,不是零散知识点。
- **E4 是纯表达问题,和知识无关**,但它在面试里的杀伤力和知识漏洞一样大,因为面试官的耐心只有两句话。这个见效最快,练几次就能改。
- **E5 只出现一次但性质最重。**Q7 里连续两轮用相邻知识填时间(答推理侧、答"为什么分类不用回归"),这在面试官眼里是明确的蒙混信号,比直接说不知道差得多。而且你是在**被递台阶之后**才转为承认的——也就是说,自发的边界意识本期**根本没被测出来**,不能算作已具备。02 期要在零台阶条件下重测这一项。
