### 本场高光与至暗

**🌟 高光（6 处，全部是可复用的资产）**

1. **PV 辅助监督的完整推理**（06:18:51–06:20:11）——从「梯度回传链路长 → loss 只作用在 BEV 图上 → 梯度衰减严重 → 图像 Backbone 判别力不足 → 把真值反投到各相机 2D 图上做辅助监督」。**这是一条完整的因果链，不是一个名词。九场里最好的技术表达。**
2. **CBGS + 类别 loss 加权 + 增大高斯半径**——「增大高斯半径提升小目标检出」这个细节，只有真改过 CenterPoint 标签生成代码的人才说得出。
3. **Smooth L1 的梯度性质**——「原来是 L1 loss，在 0 到 1 这个范围内它的梯度是常数正负 1，比较波动，改成 Smooth L1 之后在 0~1 范围内收敛比较好」。**这是你在前几场答错过的知识点，这一场讲对了原理。**
4. **成排锥桶整体建模**——「一开始打算单个检出，发现单个检出的方向稳定性波动太大，改成 ≥3 个锥桶作为一个成排目标」。**「我先试了 A，发现不行，改成 B」是最有说服力的叙述结构。**
5. **改造意图检测头的三次迭代**——「首尾坐标 → 排列方向 → 最简单的二分类」。**越迭代越简单**，这是工程成熟度的直接证据。
6. **主动补部署经历**（06:30:59）——「这块时延是部署同学测的，**然后我自己的话是在个人的 Jetson 开发板上还是有搞过部署，Orin 上搞过 BEV 的部署，RK3588 板子上搞过 YOLO 的部署**」。**这是九场里第一次你在说完"有别人负责"之后主动把自己的部署经历补上。这是实打实的进步。**

**💀 至暗（4 处）**

1. **💀💀 YOLOv5 正负样本分配 —— 「这块儿稍微有点忘了」**。而且第一次你答成了数据层面的正负样本（「正样本是成排锥桶，负样本是其他目标」），面试官纠正「我指的是模型里面的正负样本选择」，你才说忘了。
2. **💀💀 YOLOv5 的 loss 由哪几部分组成 —— 连续两次答偏**。你答的是「BCE loss 做改造意图分类」，面试官两次纠正「我指的是模型的损失」「模型具体的损失是什么」，你还是绕回改造意图。**这是一个懂行的组长在同一个点上给了你三次机会。**
3. **💀 FPN 用了几层 —— 「有点记不太清了，这个项目有点时间长了」**。刚说完自己加了 P2 检测头、接在 FPN 后面，紧接着说不清 FPN 有几层。
4. **💀 标定精度 —— 「标定的话，其实不是我们模型能做的」**。又是「不是我做的」。而且这是**最后一个技术问题**，收尾印象。

#### Q7 · 「那你能大概介绍一下 BEVFusion 的网络结构，还有它的一些训练流程吗？」
`06:08:56 | 你讲了 2 分 35 秒`

**你当时怎么答的**（转写原文，已整理）：

> 「首先它是一个多模态、多传感器输入的模型，会输入相机和雷达。相机我们输入了 7 个针孔相机、4 个鱼眼相机，雷达方面有激光雷达、毫米波雷达。
>
> 它分两条支路。**相机支路**：针孔相机输出的 2D 图像，通过一个 **DepthNet 也就是深度估计网络**，把 2D 图像 **lift 抬升到三维的视锥体**；然后把视锥体给它**拍平到二维的 BEV 空间**，这就有了相机的 BEV 图。
>
> **雷达支路**：把激光和毫米波分别进行一个**体素化**，然后通过 Backbone 提取成 2D 的 BEV 空间。
>
> 然后**相机的 BEV 图和雷达的 BEV 图，在通道上进行 concat 做融合**。融合之后的 BEV 空间再进行一个 Backbone 特征提取，然后通过**检测头**输出目标的检测框——比如 3D box 的中心点、box 的尺寸、目标的速度值、动静属性，还有它的**朝向角**。」

**🌟 这是九场里对 BEVFusion 结构讲得最完整的一次。** 六个要素全部到位：多模态输入 → 相机支路（DepthNet lift → 视锥 → 拍平）→ 雷达支路（体素化 → Backbone）→ 通道 concat → 融合 Backbone → 检测头输出（中心点/尺寸/速度/动静/朝向）。

**⚠️ 但有三个可以加分而没加的地方：**

1. **没说维度**——相机 256 维、激光 64 维、concat 后 320 维；
2. **没说训练流程**——面试官明确问了「还有它的一些训练流程」，你只讲了网络结构；
3. **没说这套和开源版的差别**——尤其是你的**两阶段融合**（激光和毫米波先融过 UNet，再和相机融，最后把原始毫米波重新注入做弱模态补偿），这是最有设计感的一块，又没出场。

**✅ 该补的两段**

**关于维度和两阶段融合：**

> 「YOLOv5 的正负样本分配相比 v3/v4 有个很关键的改动，叫**跨网格匹配 + 宽高比匹配**：
>
> **第一步，anchor 匹配用的是宽高比而不是 IoU。** 老版本是算 GT 框和 anchor 的 IoU，超过阈值才算匹配。v5 改成算**宽高比的比值**：`max(GT_w/A_w, A_w/GT_w)` 和高度方向同理，**两个比值都小于阈值（默认 4.0）就算匹配上**。这样一个 GT 可以同时匹配多个 anchor，正样本数量大幅增加，训练更稳。
>
> **第二步，跨网格扩展。** 老版本只有 GT 中心点落在的那一个网格负责预测它。v5 会**额外取最近的两个相邻网格**也作为正样本——具体是看中心点在格子内偏左还是偏右、偏上还是偏下，把对应方向的邻格拉进来。**所以一个 GT 通常能产生 3 个网格 × 若干 anchor 的正样本**。
>
> **第三步，跨层。** 三个检测层（P3/P4/P5）是各自独立做上面这套匹配的，所以**同一个 GT 可能在多个尺度上都有正样本**。
>
> **剩下的所有预测位置都是负样本**，只参与 objectness 的 loss，不参与框回归和分类。
>
> **这套设计的核心目的是增加正样本数量**——正负样本极度不平衡是单阶段检测器的老问题，v5 用扩充正样本的方式来缓解，比单纯调 focal loss 更直接有效。
>
> **落到我们锥桶这个场景**，这套机制其实很关键：锥桶是小目标，如果只有中心格一个正样本，梯度信号太弱了。」

**❌ 问题的本质**：你把「我们这个任务的 loss 是什么」和「YOLOv5 这个模型的 loss 由哪几部分组成」混为一谈了。面试官问的是后者——**这是一个框架基础题**。

**✅ 正确答案（YOLOv5 的 loss 组成）**

> 「YOLOv5 的总 loss 是**三项加权和**：
>
> **一是 box loss（定位损失），用 CIoU Loss。**
> 不是 L1/L2，是直接优化 IoU 的变体。CIoU 在 IoU 的基础上加了两项：**中心点距离惩罚**（框不重叠时也有梯度，解决了纯 IoU loss 在不相交时梯度为零的问题）和**宽高比一致性惩罚**。所以它同时约束重叠度、中心对齐和形状相似。
>
> **二是 objectness loss（置信度损失），用 BCE。**
> 每个预测位置要判断「这里有没有目标」。v5 有个细节：**objectness 的回归目标不是 0/1，而是预测框和 GT 的 CIoU 值**（可以带一个比例系数）——也就是说框预测得越准，objectness 的目标值越高。**这让置信度和定位质量对齐了**，推理时用置信度做 NMS 排序才有意义。
>
> **三是 classification loss（分类损失），也用 BCE。**
> 注意是 BCE 不是 softmax 交叉熵——**每个类别独立做二分类**，支持多标签。单类别任务时这一项可以直接去掉。
>
> **三项之间有权重超参**（box / obj / cls），而且 **objectness loss 在三个检测层之间还有各自的权重**（默认 P3 : P4 : P5 = 4.0 : 1.0 : 0.4），因为小目标层的负样本更多，需要加权平衡。
>
> **回到我们的任务**：我们是单类别（成排锥桶），所以 cls loss 基本不起作用，主要是 box + obj。**改道意图我们是单独出了一个头**，用的是二分类 BCE，这个是我们自己加的，不属于 YOLOv5 原生的三项。」

**这不是「匹配」，这是「他们的下一年路线图正好是你的过去两年」。**

**✅ 该怎么答（拿到这条信息后必须当场输出）**

> 「明白了，那我说一下我听到这些之后的判断，您看对不对。
>
> **第一，从 PointPillars/CenterPoint 往 BEVFusion 走，最大的坑不在模型，在数据和标定。**
> 纯激光方案只需要点云标注，加了相机之后，**你需要相机和激光的时间同步和外参标定精度到一个新的量级**——外参角度误差 0.1° 在 100 米处就是 17 厘米。港口场景重载振动大，标定还会随时间漂。**这件事如果没准备，模型再好也出不来效果。** 我做 BEV 的时候有相当一部分精力是在处理这类问题，包括训练时加外参扰动增强让模型有容忍度。
>
> **第二，你们的场景其实比乘用车更适合 BEVFusion，有两个原因。**
> 一是**慢速**——1 米每秒到几米每秒，时延预算比乘用车宽松得多，可以用更重的模型，或者降帧率换精度，这个自由度乘用车没有；
> 二是**封闭场景**——环境相对固定，长尾分布比开放道路窄得多，**数据量的需求会小很多**。
>
> **第三，异形障碍物那块，从聚类往占据网络走是自然的下一步。**
> 聚类最大的问题是对地面分割敏感、而且没有语义。占据网络不问「这是什么」只问「这里能不能过」，对没见过的东西也能给判断。**港口堆场里掉落的集装箱配件、锁具这些，恰恰是枚举不完的。** 我们的 GOD 和 BEV 是共组的，这条线我有直接经验。

> **第四，我最想说的一点：从纯激光升级到多模态融合，投入产出比最高的第一步不是训模型，是先建分场景的评测。**

> 这是我基于今天信息的初步判断，可能有不对的地方。**我想问一句：从纯激光升级到 BEVFusion 这件事，您预期的时间窗大概是多久？**」
