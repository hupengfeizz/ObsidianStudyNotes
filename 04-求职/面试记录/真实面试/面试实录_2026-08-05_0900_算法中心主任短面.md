# 0805-0900 · 算法中心主任短面（46/100）

## 速览

架构位置类问题（GOD 与 BEV 的关系、两段式与端到端并存、白名单给谁用）整体接得住，114 米秒答，动机是修复版。丢分在三处：**BEVFormer 原理只讲出一句口号**（"与 LSS 相反方向"）；锥筒"为什么走 PV 不走 BEV"首答跑偏被"我知道 PV 是什么"打断；被问"你现在多少级"时**秒报 15 级**——职级与薪资一样是锚，报出去就定了对方的出价档位。

## 逐问逐答分析

### 一、架构位置扫射（2:17-8:00）

**Q1（2:17）"现在不都 GOD 吗？3D 感知在架构里是什么位置？"** → BEV 组与 GOD 共大组；BEV 检车/行人/骑行人动目标；GOD 基于 Occupancy 思路（口误先说"英伟达的"再改"特斯拉的"），检静态障碍物/可行驶域/锥桶水马。✅ 位置讲清了，小口误无伤。

**Q2（3:24）"整体是两段式吗？为什么还做白名单检出？"** → 原两段式，去年底起转端到端：BEV+GOD 共网、backbone 供给端到端；白名单仍有单网直出 box 给规控，不同车型走单网/共网不同策略。✅ 多套并存的复杂现状讲得有层次——这套"车型-配置-策略矩阵"的叙事已成熟。

**Q3（4:25）Backbone 是什么结构？** → 答成"共享的是 PV2BEV 图像特征提取那块"。⚠️ 问结构应答 ResNet 系+FPN 层级；答成了"共享范围"。所幸对方直接跳到雷达。

**Q4（4:56）雷达和 Camera 的 BEV 怎么做？** → 双支路标准版流畅。✅

**Q5（6:54）白名单检测结果给谁用？** → 单网输出给规控决策。✅

### 二、BEV 专题（8:17-13:55）

**Q6（8:17）"你们用 BEVFormer 还是 BEVDepth？"** → "跟开源最接近的是 BEVFusion 框架。"✅ 二选一陷阱破得对——不接选项、直接给事实。

**Q7（8:40）"简单讲讲 BEVFormer 的原理。"**

现场："我们没采用 BEVFormer……它基于 Transformer，不显式构造 depth loss，直接在 BEV 空间 query 特征，相当于与 LSS 相反的方向构造 BEV 空间。"

诊断（K13）：口号对，血肉无。完整版四句：**① BEV 平面预置一组网格化 query；② spatial cross-attention——每个 query 按标定投影回各相机，用 deformable attention 只采样投影点附近的图像特征（省算力的关键）；③ temporal self-attention——当前 query 与按自车运动对齐后的历史 BEV 特征交互，获得时序；④ 输出稠密 BEV 特征接检测头。**"与 LSS 相反"作开头句很好，后面四句必须跟上——这是 K13"两代论"卡片的核心页。

**Q8（9:29）小目标检测怎么提升？** → 三面标准版（稠密监督/加深+CRF/BEVPoolv2）。⚠️ 内容成立但答的是"远距"通用方案；**简历里现成的小目标专项——CenterPoint 高斯半径增大（小目标正样本太少，扩大半径增加监督信号）——没有调用**。"小目标"三个字应触发：高斯半径+网格分辨率+PV 辅助监督三连。

**Q9（12:01）"锥筒为什么走 PV 检测、不走 BEV 检测？"**

现场：先解释"PV 是 perspective view 透视网络"——对方打断："**我知道 PV 是什么**，我问为什么锥筒走 PV 不走 BEV。"你再答任务划分（BEV 动目标/PV 十多个关键目标子任务）。

诊断（B06）：任务划分是"现状"，不是"为什么"。技术理由三句：**锥筒物理尺寸小，BEV 网格分辨率下远距锥筒只占不到一个格子，先天检不稳；前视 2D 分辨率高得多，小目标检出上限高；改道意图只需要前向车道级信息，2D 框+车道线耦合就够，不需要 3D 定位精度**。——这题在多场出现过变体，值得单独立卡。

**Q10（13:18）锥筒检出距离多少？** → "114 米……稳定检出距离 110 米出头。"✅ 秒答（89→114m 口径命中；"114→110 出头"的软化算轻微漂移，报一个数就好）。

### 三、行为与反问（14:10-16:53）

**Q11（14:10）找工作主要原因？** → 修复版稳定输出。✅

**Q12（15:04）"你现在多少级？"** → "现在是 15 级。"

诊断（B15）：🔴 职级=薪酬带宽的坐标。华为 15 级的市场定价区间任何智驾 HR 都门儿清——**这一答等于把 0804-2003 场泄掉的 29K×14 用另一种方式又泄了一遍**。标准应对："级别体系各家口径差异很大，直接对我做过的事和带宽聊更准——贵司这个岗位定的是什么档？"（把问题反抛，还能套出对方的 banding。）

**Q13（15:15）反问** → 问对方模型情况（→共享 backbone 接 OD/LD/OCC/motion 多任务头，一站式架构；"和我们比较相似"达成共识）；问感知团队规模（→新部门、现十来人、目标 150-200 人）。✅ 两问都拿到关键信息（新部门=机会大/坑也大），收束干净。⚠️ 差一步转化："新部门从十人到两百人，最缺的是能把量产流程带进来的人——我的评测防护网和数据闭环正好是从 0 到 1 的经验"——一句就能把"相似"变成"需要我"。
