# 0805-0504 · 姿态估计公司残影拉锯场（38/100）

## 速览

这位面试官的风格是"每个数字都验算、每个机制都推演"。你的训练数字链在他手里当场崩塌（**几千万帧 × 120 轮 × 8 卡 × 2 天，四个数拼在一起物理上不成立**——而数据量前一天你还说的是 200 万）；残影问题你手里其实有正确答案（0803-1959 场说过"跨帧目标关联搬运"），本场却走进"mask 掉残影"的死胡同 6 分钟出不来。**亮点也真实**：BEVPoolv2 索引表讲出了历史最干净版本、CenterPoint 高斯分配完整、loss 权重给出了具体数字（行人2/骑行人1.5/车0.5）。最后 coding 被拒收场，基本锁死结果。

## 逐问逐答分析

### 一、数据与训练数字链（0:00-11:30）

**Q1（0:14）有增量数据后，之前的数据怎么用？** → 全量保留、新增 json 挂路径、稀缺场景（地库/闸机）重采样提占比。✅

**Q2（1:34→2:36）迭代一次多久？多少卡？训几轮？——"八卡几千万帧两天能跑完吗？"**

现场：一版两天、八卡、"一百多轮吧，120 轮一般"→ 面试官验算表示跑不完 → "数据这块我确实不是特别……**到底多少帧我确实不清楚**，数据组交付的，我只关注新增数据。"

诊断（B04×2+B03）：
1. 🔴 **四个数字构成的链条自我矛盾**：几千万帧×120 epoch 在 8 卡上两天完成，算力上差两个数量级。而"几千万帧"与前一天 0804-2003 场你自己说的"200 万帧左右"又是一对漂移。**参数卡训练页的最终口径必须让四个数互洽**（例如：全量 X 百万关键帧、每版全量 1-2 epoch + 增量重采样、8 卡 2 天、每周 1-2 版）——数字之间的乘除关系就是面试官的验算器。
2. 撤退句"到底多少帧我不清楚"把前面所有数字的可信度一并clear掉了（B03）。

**Q3（3:09-8:50）增量还是全量？有系统性迭代计划吗？** → 全量+增量上量（200 clip×40s@10Hz≈400 帧）；版本目标制（630 版抽检 90%+）；专项采集细节（蹲坐/站立/弯腰行人各 200 clip，高危场景 400）。✅ 这一段的运营细节仍然是加分的——被质疑"200 clip 微调几千万代价太高"后澄清"全量训练+几百 clip 见收益"也算圆回来了。

**Q4（8:59）模型多大？推理多少毫秒？** → 85-90ms。✅（参数量 90M 没报——问了"多大"应双答。）

**Q5（9:48）每个 epoch 都遍历几千万样本吗？** → "dataloader 提前集中处理……每次迭代处理好的数据"——含糊话术（⚠️）。诚实版："全量迭代按 epoch 走；框架是既有的，采样细节我可以确认"——下一问你其实就这么说了（框架是 4.0 既有的，我做的是 PV2BEV 和深度估计优化 ✅）。

### 二、残影拉锯战（11:59-18:30）——本场核心事故

**Q6（11:59）"多帧点云怎么融合到一起？特别是有动态物体的时候？"**

六分钟拉锯全程：
1. 你：历史 3 帧经内外参/坐标系位移到当前帧+运动补偿对齐。
2. 他：运动的部分怎么跟静态区分？→ 你："运动会出现残影……**残影部分直接 mask 掉**。"（临场发明）
3. 他：怎么判断是残影还是正常点云？→ 你：历史点投过来与当前帧距离超阈值判残影；再补"跟当前帧标注框对齐，框外的 mask 掉"。
4. 他：那投影后运动物体不就没有深度监督了？→ 你："mask 的是非目标……不会影响目标监督。"（他："什么？残影什么？"）
5. 他：**运动车辆本来稀疏，你要多帧聚合变稠密——可它的历史点都在框外，按你的说法全被 mask 了？**→ 你："只 mask 框外面的。"（自相矛盾暴露）
6. 他：所以到底是忽略残影，还是算出残影间的运动关系？→ 你："对，就是通过运动补偿……叠多帧对齐过去。"（循环，不了了之）

诊断（K01，31 场该知识点最长的一次失血）：
1. **正确答案你两天前说过**（0803-1959："不是找运动点，是跨帧目标关联，把目标点云搬运到当前帧"）——完整版三句：**自车补偿**（ego pose 对齐历史帧，解决静态场景）→ **目标补偿**（用标注真值框的跨帧关联，把每个动目标的历史点云按其自身位姿变换搬进当前帧框内——既去残影又完成稠密化）→ **兜底**（离线真值生产不受在线检出限制；残余噪声由网络容忍）。"mask 说"恰好把第二步丢了，于是每一问都在漏水。
2. 教训：**同一知识点必须只有一个版本**。你在不同场次对同一问题有两套即兴话术，撞上推演型面试官就是灾难——K01 卡片在 0825-0359 版本答对后必须锁版。

**Q7（18:31）后面加卡尔曼滤波吗？** → 检测头后接轻量卡尔曼做历史轨迹关联。✅
**Q8（19:00）检测-跟踪端到端（query 跟踪）用过吗？** → 先听成感知-规控端到端（⚠️），澄清后答"卡尔曼这块还不是完全端到端"。（K19）MOTR/query 式跟踪一句概念都没接上——"检测 query 延续到下一帧作为跟踪 query，ID 隐式维持，省掉显式关联"两句话即可及格。

### 三、机制答辩（20:06-32:10）——本场的得分区

**Q9（20:24）BEVPoolv2 具体怎么做？** → "splat 把视锥点投到 BEV 格子这步只依赖相机内外参，完全可以离线算——**BEVPoolv2 预计算索引表，提前算好每个像素投到哪个网格，推理时查表聚合不再实时计算**，省算力降时延。"✅✅ **K02 的历史最佳版本**，此答保留为标准答案。

**Q10（23:13）CenterPoint 正负样本分配策略？** → 3D 中心点投 BEV 网格 → 生成二维高斯热力图 → 半径与目标尺寸、网格分辨率相关 → 高斯值超阈值为正样本、远离中心低于阈值为负。✅ 完整。（可加一句"我们把高斯半径调大以增加小目标正样本数"——你简历里的优化点，没带出来。）

**Q11（24:33）Smooth L1 替代 L1 的机理？** → 低速场景+L1"整数损失/正负 1 梯度"+SmoothL1 解决零点附近梯度不连续。⚠️ 意思对但表述比 0804-1407 版本含糊（"整数的损失函数"这类词会减分）——又一个"版本没锁定"案例。

**Q12（26:20）CBGS 和 loss 加权的实现细节？** → CBGS：统计各类样本数、权重=总样本/类别样本、重采样平衡 ✅；loss 加权给出具体数字：**行人 2、骑行人 1.5、车 0.5** ✅✅（数字让答案立刻可信）。

**Q13（28:53-32:07）"采样比重具体怎么设？参数映射是什么意思？"** → 绕了三轮（"初始权重→验证集校验微调""有一个参数的映射"）才落到诚实答案："**手动调，根据验证集结果**。"（B06）第一轮就说"起点用逆频率，之后看各类召回手动微调——没有全自动公式"即可。

### 四、coding 拒绝与收尾（32:42-38:29）

**Q14（32:42）"咱们还有个扣题环节，方便开摄像头吗？身边有电脑吗？"**

现场："扣题环节目前还没有做准备……个人电脑没有环境……没有编辑器。"对方降低门槛（"不是 LeetCode，就是你之前做过的事情"）你仍未接，最后归因 HR："邮件只说人体姿态估计面试，没有任何信息。"

诊断（B15）：
1. 🔴 **现场编码几乎不可拒绝**——拒绝的信号强度约等于"上一场 0804-1512 的翻车我不想重演"。哪怕真的没环境："我装个 VSCode 要两分钟，或者我用在线 notepad 手写——您出题。"写得烂都比不写强。
2. 归因 HR 是二次失分：面试官只会记住"候选人拒绝了 coding"。此后所有面试一律默认自带环境（编辑器+Python 可运行）。

**Q15（34:15）看机会的原因？** → "换一个工作环境，学到更广泛的技能。"（B05）修复版（分工细→想纵向打通）没有调用，退回了薄版——又是版本锁定问题。

**Q16（35:17）反问** → 问了业务匹配度，拿到丰富信息：ego 多模态设备（IMU/红外/相机）、手部+全身姿态、**多相机系统做真值、蒸馏单相机 student**、端云软硬一体；追问 VLA、感知模型（poseformer）、相机+深度融合版本。✅ 问得不错。⚠️ 但**对方描述的"多相机真值生产+蒸馏"正是你的 3D 真值反投 2D 监督的同构物**——把"我做过 3D 真值反投多相机生成监督，和你们的多目真值-单目蒸馏是同一套思想"说出口，这场的定位就从"领域不匹配"翻成"方法论完全对口"。信息拿到了，转化为零（B10 性质，未计码）。

## 三句话总结

1. 残影拉锯的教训不是"不会"，是**一个知识点存在两个版本**——正确版两天前刚讲过，错误版当场即兴；卡片的意义就是消灭第二版本。
2. 数字链（帧数×轮数×卡数×天数）是可以被验算的——参数不是一个个背，是一组组背互洽。
3. 拒绝 coding 的成本大于写砸 coding：0804-1512 写砸了拿 35 分，本场拒绝了拿 38 分且直接出局——从此"自带环境"是面试装备的一部分。
