## 逐问逐答分析

### 一、传感器与融合（技术面试官 A，0:00-15:15）

**Q1（0:08）4D 毫米波还是普通毫米波？** → "点云是 3D 的、有时序……所以是 4D 吧。"⚠️ 推理出来的而非知道的，语气暴露不确定。0801 场总经理问过毫米波类型没答，这里二面又来——同一家公司同一题第二次。

**Q2（1:06）毫米波哪家的？型号？多少点？** → 型号"不是特别清楚，数据组给到我们直接用"；单帧 200-300 点。⚠️ 点数给了（好），型号裸放弃（B03）。传感器 BOM 是感知工程师的名片，哪怕"型号我记不准，但它是 4D 成像雷达、单帧 200-300 点、带径向速度"也完整得多。

**Q3（2:49）整体融合方案流程？** → 三支路（camera/激光/毫米波）各自特征提取 → 构造 BEV 空间 → 统一坐标系下通道级融合；毫米波与激光同路：voxel 体素化 → BEV。✅ 绕了一圈但讲清了。

**Q4（4:34）训练什么机器/车上什么算力？** → MDC 610/630，200 多 TOPS。✅（0801 场答不出的"占多少"这次依然没被追问到占比，算逃过。）

**Q5（5:03）部署优化你做了没？**

现场："我主要训模型，部署直接交给组内另一个同学，转 ONNX 转 OM 量化都是他搞；算子问题调部门开发的算子。"

诊断（B01）：**裸版"有专人负责"**——0803-1004 场的满分答法（Jetson Orin 全链路四步）一个字没出现。同一张牌，前一天打对、这一天丢掉。这题的不稳定性正是后来"部署双层句"卡片要终结的。

**Q6（6:10）车上跑了吗？** → ADS 4.0 高配模型、五六十车型（赛力斯/江淮/奥迪…）、4.0→5.0 下半年发布、BEV+GOD 共网 backbone 给端到端。✅ 信息量大、可信。⚠️ 内部版本节奏与车型名单对外说得太细（B15 计入本场综合项）。

**Q7（7:33）不同车型怎么适配？** → 主流通用模型+特殊车型单独训；**C 柱车案例**：侧视相机从后视镜位挪到 C 柱、传感器信息变化大，上半年专门做了特征提取优化；奥迪专门训模型；重卡传感器位置高、数据未采，其他组在建流程。✅✅ 有具体案例有机理，本段最佳。

**Q8（9:57）激光什么型号多少点？** → 128 线、单帧 120 万左右，"具体型号不太清楚"。⚠️ 半答。

**Q9（10:36）你的工作主要是调优？** → "对……**协助**组内一起做模型调优，整个模型也**不是我一个人完全完成的**，主要是协助大家。"

诊断（B07）：本场最重的归属弱化。面试官只是想确认你的分工，你主动把自己降级成"协助者"。标准句："模型是团队的，**深度估计与视觉特征提取这条线的优化是我主导的**——DepthNet 加深、CRF、BEVPoolv2 替换、PV 辅助监督都是我做的。"——同样诚实，但立得住。

**Q10（11:12）相机几路？怎么拼接？** → 7 针孔+4 鱼眼；内外参转换、每个视锥占一部分视角、融合成 360° 上帝视角鸟瞰。✅ 通俗准确。激光前向 120°+Ultra 版加后向。✅

**Q11-13（13:16-14:00）做多久/实习还是全职** → 两年、评测框架起步转模型优化、毕业后正式。✅

**Q14（14:03）为什么离开华为？**

现场：大版本（4.0）交付告一段落是契机 + "这边分工特别细，只做这一部分，对 BEV 上下游接触不多，想去开发自由度更高的地方得到更多锻炼。"

诊断：✅✅ **弱动机修复的现场证据**。对照 0803-1926 的"换换心情"，本场删掉了情绪词、保留了结构性理由——院士在 48:53 主动回放这个回答并表扬："你想多做一些、面宽一点，这个认识还是不错的……我们公司小就是要全面的，**你刚才这个回答挺令我满意**。"这版答案从此定型。

### 二、难例挖掘（邓老师，15:19-22:45）

**Q15（15:39）难例挖掘具体怎么做？** → 泊车凭空误检：数据湖里视频样本（10Hz 标注、约 300 帧）逐帧 for 循环 → 自车周围预置真值框与检出框 IoU 比对 → 检出≥3 帧又快速消失=突现突消 → 挖出回灌。匝道汇入误检：高速 tag+汇入场景+同判据。✅ 两个案例都完整。

**Q16（19:42）"数据湖里挖的是标注好的段子吗？"** → 修正对方理解：数据湖大部分**未标注**，有大模型推理的**预标框**；挖出后**人工质检 10% 抽检**，符合预期才送标。✅✅ 预标框+抽检机制是新鲜细节，可信度高。

**Q17（20:57）模型推理反查/badcase 回灌解释？** → 恶化场景聚类 → 制定挖掘策略 → 挖掘+实地采集两路 → 专题样本集入训练集迭代。✅

### 三、小陈参数拷问（22:47-38:23）——本场的深水区

**Q18-21（22:58-24:55）参数量？骨干？预训练？channel 比例？** → 90M 左右 ✅；卷积 ResNet ✅；开源权重+内部二次预训练 ✅；相机 256 + 激光 64 ✅。**四连中**——这些正是简历口径，说明背熟的部分是稳的。

**Q22（25:21→26:23→27:03）雷达只看前方，BEV 范围不一样——没覆盖的体素直接填 0 吗？**

现场："自适应填充……基于 BEV 空间上下文特征插值补全，不是简单填 0"；被追问"体素化的时候不就只能填 0 吗"后继续"查缺补全……保持连贯性"。

诊断（B04）：**这题的正确答案很朴素**："体素化时无点云的格子就是 0；'补'发生在特征层——卷积感受野+相机分支特征天然覆盖，无需特殊填充。"你把"特征层融合"包装成"体素自适应填充"，被懂行的人一听就是现编。**不会的细节宁可给朴素真话，不给漂亮的错话。**

**Q23（28:06→29:28）BEV 网格分辨率？范围？——"前向 160÷0.2=800 格子，显存放不下吧？"**

现场：**0.2×0.2**；前向 **−80~160**、横向 **±80**；被算账逼问后："显存做了优化——backbone 输出后同类型压缩，256 维降到 64 维再做 BEV 转换，显存降到原来 1/4。"

诊断（K05+B04，本场最大事故）：
1. 🔴 简历口径是 **0.4m / 448×224 / 前向 179.2m、横向 89.6m**。0.2m 的说法一旦说出，就要用"降维省显存"这类临场发明去圆——而小陈的算术（800 格）已经证明他在验算。**两套口径的并存从本场开始**，此后 0824/0825 场次反复被同类问题命中。
2. 唯一修法：参数卡一组数背死——0.4m、448×224、179×89.6m、10Hz+历史 2 帧 0.2s、256+64→320、90M、85-90ms。任何场合只报这一组。

**Q24（30:15）时序融合？历史几帧？几赫兹？** → 历史 3 帧、20Hz、连续 4 帧=0.2 秒。🔴 同上：与简历口径（10Hz+历史 2 帧 0.2s）矛盾（K05 第二击）。0.2 秒这个总时窗倒是两套口径唯一咬合的数。

**Q25（31:36）速度真值怎么来的？标的吗？** → "会进行速度标注……每帧人工标注，跳变会平滑处理。"⚠️ 半答——"连续帧标注框位置**差分**+平滑"这句核心当时还没长出来（0804-2003 场被逼出来后才修复）。

**Q26（32:37）动静阈值怎么划？车和人一样吗？** → "要求严格，运动特别慢零点几米每秒也打为运动。"⚠️ 分类别阈值答不出，只给了方向。可补："阈值按类别定（车/人不同），具体数值在标注规范里，我记得人的阈值更低。"

**Q27（33:10）鱼眼畸变怎么处理？** → 鱼眼不走 LSS，走 transformer cross-attention/query 构造 BEV，避开显式深度估计对畸变的敏感。✅

**Q28（34:14）"这么做是有效还是历史原因？"** → "确实是之前就这么用的；看实验记录，针孔式投影+畸变校正效果不好，transformer 对畸变鲁棒性高。"✅✅ 诚实+证据，被"了解"接受。这是"不是我做的决策"类问题的标准答法：承认沿革+给出依据。

**Q29（35:01）远处网格不画大些吗？** → 统一固定网格，兼顾近远。✅ 简洁成立。

**Q30（35:27）训练显存占多少？batch size？**

现场："单卡 50-60G"→"为什么单卡？"→"集群八卡……八卡 batch 3，单卡 batch 12？……具体占用**有点忘记了**。"训练卡为华为昇腾集群。

诊断（B04+B03）：数字链条自相矛盾（单卡 batch 12 > 八卡 batch 3？），最后裸承认忘了。训练配置（几卡、batch、一版几天、数据量）是参数卡的"训练页"，本场证明它和"系统页"一样没背。

**Q31（38:06）推理时间？** → 八九十毫秒。✅ 口径命中。

### 四、院士部分（38:28-59:50）

**Q32（38:42）轮机工程→机械硕士→感知算法，基础怎么来的？** → 读研进电子信息导师课题组做高光谱深度学习，从 YOLO 学起（V7-V11 全系列），后转 3D。✅

**Q33（40:04）"系统学习过吗？"→"也就是说你是自学的是吧？"** → "对，需要啥学啥。"⚠️ 诚实但被动地接受了"自学=非科班"的定性。更好的框架："以量产项目为纲的系统性自学——每个专题（检测/融合/部署）都过了论文-开源-落地三关，加上组内专家带教。"把"自学"变成方法论而不是缺口。

**Q34（40:49）六项专业技能怎么来的？掌握程度？** → Python 三年/无人机高光谱香蕉林生物量估计（YOLO）/工作中自学 BEV。⚠️ "掌握程度"没有分级回答——这正是后来 0825-0304 场"精通 Docker"被证伪一类问题的前身：**简历技能栏每一项都要能自评"精通/熟练/了解+一句证据"**。

**Q35（42:12）华为的培训/充电情况？** → 公开课浅显；主要 GitHub 拉代码+课程+组内交流。✅ 诚实。

**Q36-39（43:33-48:40）AI 模型开发部是什么/多大/和端到端什么关系/4.0 是规则还是端到端？** → 200 多人（上海+深圳）；BEV/GOD/PV/车道线/端到端；4.0-5.0 "完全端到端，但确实还有一些规则在里边" ✅ 诚实；BEV+GOD 共网并进端到端的演进讲了两遍。✅ 这一段整体清晰。⚠️ 但对外输出的内部组织与版本细节量偏大（B15）。

**Q40（49:44→50:23）"你对华为整个 BEV 面上的了解有多大？组织怎么分工集成？"** → 深圳 BEV 约 20 人：训练 3-4 人（主力 2-3）、共网/单网分人维护、评测分析组（复核测试部恶化 case、判断是否 BEV 责任）、部署 2 人。✅✅ 组织认知全景清楚，院士听完转入收尾。

**Q41（54:17）对感知大组的了解？** → GOD=占据网络检静态 polygon（异形车/草丛/可行驶域），问题比 BEV 少；PV 共网检锥筒/黑白名单/红绿灯/水花/匝道。✅ 广度到位。

**Q42（56:17）"我们三个核心技术：安全异常检测、极端天气路面、ODD 动态边界——你做过这些吗？"**

现场：雨雪："没有单独对天气……有段时间对雪天做过数据上量，没当主要目标研究。"ODD："分场景——园区/高速/施工路段，构造专门训练和评测，检测不同边界下的感知能力。"

诊断（K06 第三击）：**这家公司把 ODD 递到你面前第三次**（0801 场两遍+本场），你的答案依然是"数据上量+分场景评测"的外围话术，没有触及他们要的"在线判断当前环境是否越界"。三次机会、一张写好的牌（0825-0040 复盘的失效感知标准段后来才写出），是 31 场里同一知识点的最大单点损失。**好在他们还是要你了**——说明这题打中也未必加薪，但打不中一定减分。

**收尾（58:53）**：院士："欢迎你到我们这个来工作啊，胡鹏飞""你在北京有家吗？"→"没有家，租房没问题，深圳也是租房。"→"**那恭喜**，谢谢你。"✅ 干脆、不矫情，收得很好。
