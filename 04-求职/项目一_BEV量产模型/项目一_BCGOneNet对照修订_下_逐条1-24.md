# 第一部分 · 严重问题清单（一眼能被看穿的）

## 🔴 P0-1 · 第 8 条「BEVPoolv2 精度提升」——这句是硬伤

**简历原文**：

> 以 BEVPoolv2 预计算索引池化替代原 LSS 投影，**精度提升的同时**消除视图变换耗时瓶颈

**视频 B 原话**：

> 「这两个在**数学上是等价的**，它是一个工程用法」
> 「他这边论文里面……他**没有报指标差异，因为他数学上就等价的，就没有指标差异**」
> 「我觉得这个是跟他提升部署效率的，省算力……省算力之后你可以把算力放在其他地方」

**问题**：BEVPoolv2 是**数学等价的加速**，不涨点。这是论文的核心卖点之一，任何读过的人都知道。写"精度提升"会被当场纠正。

**改法（简历）**：

```
原：以BEVPoolv2预计算索引池化替代原LSS投影，精度提升的同时消除视图变换耗时瓶颈
改：以预计算索引池化替代原LSS投影，消除视图变换耗时瓶颈，省出的算力预算投给更重的DepthNet
```

**面试说法**：

> BEVPoolv2 和原始 LSS 在数学上是等价的，不涨点——它是纯粹的工程加速。价值在于**把省下来的算力腾给别的地方**，我们就是把它投给了更深的 DepthNet 和 CRF。所以准确说，涨点的不是加速本身，是加速换来的预算。

> ⚠️ **另有一条要注意**：视频 B 里还说「我们那个 LSS 推理的时候，他是**算子那边优化过一步了**，就你可能不一定有你预期那么大的提升」。
> 这与 A 材料里看到的 `grid_sample` 实现吻合——**你们的基线本身就不是朴素 LSS**。所以"加速比"这个数不要随口报，除非 v18 有实测。

## 🔴 P0-2 · 第 5 条「方向与大小误差相互耦合」——不是你们的真实问题

**简历原文**：

> 速度以 vx / vy 直接回归，**方向与大小误差相互耦合**且对离群样本敏感

**视频 B 原话**（讨论速度 loss 时的完整论证）：

> 「他们两个都是用的一个 L1 loss，我百思不得其解」
> 「你速度 0.1 跟 1.0 的 loss，比如说 **GT 是 1.0 你预测个 0.1，跟 GT 是 29 你预测个 29.1，他们的 loss 现在是一样的**，就是 L1 loss 就是这样的」
> 「你速度特别大的时候二三十，多一点少一点可能都没关系；**但你小的时候就不行了，你 0.1 跟 1.0，可能一个就是重刹一个就不重刹**」
> 「L1 loss 肯定不合理」
> 「你其实应该是一个**分类任务**」

**真实问题是**：

> **L1 是绝对误差，对不同速度量级一视同仁。但同样 0.9 m/s 的误差，在低速段决定"刹不刹车"，在高速段无关紧要。**

**这是「绝对误差 vs 相对误差 / 分段敏感度」的问题，不是「方向 vs 大小」的问题。**

**证据链闭环**：A 材料里的**速度分段 loss 权重**正是对这个问题的直接回应——

| 速度范围 | weight | 对应 |
|---|---|---|
| [0.0, 0.2] m/s | 2.5 | 接近静止 |
| **[0.2, 0.4]** | **4.0** | **缓慢移动 ← 重刹临界** |
| **[0.4, 1.67]** | **4.0** | **~6km/h 以内** |
| [1.67, 8.0] | 2.5 | ~28.8km/h |
| [8.0, 50.0] | 4.0 | 高速 |

**低速两段权重最高，正好对上视频里说的"小的时候就不行了"。**

**改法（简历）**：

```
原：速度以vx/vy直接回归，方向与大小误差相互耦合且对离群样本敏感，速度跳变与动静误判频发
改：速度以vx/vy直接回归，L1对不同速度量级一视同仁——低速段的同等绝对误差直接影响是否触发制动，
    而高速段无关紧要；叠加速度真值噪声大，速度跳变与动静误判频发
```

> ⚠️ **「方向与大小误差耦合」这个说法要不要保留？**
> 它本身不错（极坐标解耦确实解决这个），但**它不是视频里讨论的那个问题**。如果 v18 确实做了极坐标解耦，可以两个动机都写；如果没做，就只留量级问题这一条。**回去核实后再定。**

## 🔴 P0-3 · 「纯 dense BEV」这个表述不准确

**我在 §0 里写的「dense BEV 路线」，以及逐字稿里的说法，都不够精确。**

**视频 B 原话**：

> 「他**不是一个完完全全的纯 dense 的**，他只是在 heatmap 这个地方用了一个 dense」
> 「你每个预测出来之后，他是把这一块的特征……**把对应的特征给他扣出来**……去做另外一个分类头也好，回归头也好」
> 「他是一个 **topk 的操作**，就是他会把每个点预测的地方……取分数前 **256 还是 128** 个目标，然后把那块特征扣出来」
> 「**实际上相当于是 mask 的，全部都被 mask 掉了，实际上也相当于是一个 sparse 的任务了**」
> 「他除了这个 heatmap 之外，**其他都是 sparse 的**」

**准确的三层描述**：

| 层 | dense / sparse |
|---|---|
| **BEV 特征表征** | **dense**（稠密特征图 448×224） |
| **heatmap 分类** | **dense**（每个格子都预测有无） |
| **回归分支**（框/尺寸/朝向/速度/动静） | **sparse**（topK 128~256 个位置抠特征再回归） |

**这是 CenterPoint 的标准做法，但如果被问「你们回归也是 dense 的吗」，答"纯 dense"就露馅。**

**面试说法**：

> 我们的 BEV 表征是稠密的，heatmap 也是稠密预测——每个格子都判有没有目标。但**回归分支实际上是稀疏的**：heatmap 出来之后做 topK，取分数最高的一两百个位置，把那些位置的特征抠出来再回归框、尺寸、朝向、速度这些属性。没被选中的位置根本不参与回归，等于被 mask 掉了。所以严格说是"稠密表征 + 稠密分类 + 稀疏回归"，不是纯 dense。

> **这个回答本身就是加分项**——它说明你读过代码，不是只看架构图。

## 🟡 P1-4 · 第 5 条 Q6 缺一个精确的物理界限

**视频 C 原话**（讲低速难点时）：

> 「我们现在整个的 BEV 的分辨率大约是每个格子 **0.4 × 0.4**，这样子的话……如果说我们**按照三帧**，按照三帧走 0.4 的话，那么**理论上来说是一米每秒以下就很难再解出了**」
> 「因为如果说你这个速度很慢的话，它**三帧是走不出这个格子**，它就使得你这个特征在你这个格子里面就很难区分出它的这个位移」

**这是一个可以现场推算的硬界限**：

```
BEV 网格 0.4 m
时序 3 帧 @ 10Hz = 0.2 秒
→ 0.2 秒内移动不足一格（<0.4m）的目标 → 速度无法从 BEV 位移解出
→ 速度分辨率的物理下限 ≈ 0.4 / 0.2 = 2 m/s
   （视频说约 1 m/s，量级一致；实际因为特征有亚格子表达能力，界限比纯几何算的松一些）
```

**视频还补了一句缓解**：

> 「每一个格子是有这个 channel 的……比如说你有一个 64 或者 128 channel 的话，它本身这里面这个特征是**隐含了这个 sub-pixel 信息**在里面，所以说我们通过一系列的这个提取的操作，应该是可以把这个上限……」

**加进第 5 条 Q6，替换我原来那句模糊的"信噪比低"。**

## 第 1 条 · 中远距检出不稳、位置跳变

**✅ 核心论证成立，视频 B 有原话背书，且给了一个更强的说法。**

### 🆕 补进 Q4（因果链）

原文只讲了"深度歪 → 特征涂错格子 → 检出不稳"。**视频 B 补了一层更狠的**：

> 「你给他投歪了……**那个地方没有监督，你会把那个信号相当于给他抑制掉**」

**完整因果链应该是三段，不是两段**：

```
深度歪
  ↓
① 特征被涂进错误的 BEV 格子           → 位置跳变
  ↓
② 目标真实所在的格子【拿不到特征】     → 该处响应弱 → 漏检
  ↓
③ 而那个格子在训练时【有正样本标签】   → 模型被迫在"没有特征"的地方学出响应
   → 相当于把有效的监督信号抑制掉了     → 训练本身被污染
```

**第 ③ 层是原文完全没有的**：深度投歪不只是推理时错位，**它还会污染训练**——正样本位置拿不到特征，梯度回传时反而在教模型"从空特征里预测出目标"。

`口语`（升级版）

> 深度估歪了有三层后果，不只是位置错。第一层是特征被涂到错误的格子，表现为位置跳变。第二层是目标真实所在的格子拿不到特征，那儿响应弱，就是漏检。**第三层最麻烦——那个格子在训练时是有正样本标签的，模型被迫在"没有特征"的地方学出响应，等于把有效的监督信号给抑制掉了，训练本身就被污染了。** 所以深度这一环投准了，后面的监督才可能准确。

> **完整修订版见独立文件《简历全解_项目一_第5条速度_修订版.md》。** 此处只列本次新增的两点。

### 🆕 Q6 补精确的物理界限（见 P1-4）

```
BEV 格子 0.4m + 时序 3 帧(0.2s) → 低于约 1~2 m/s 的目标，帧间走不出一个格子
                                → 速度分辨率的物理下限
缓解：每格有 64/128 通道，特征隐含亚格子信息，可以通过提取操作把界限推低一些
```

`口语`

> 我们的 BEV 格子是 0.4 米、时序用 3 帧也就是 0.2 秒，**这意味着低速目标三帧都走不出一个格子**，速度根本解不出来——这是个物理界限，不是模型不够好。缓解办法是每个格子有上百个通道，特征里隐含了亚格子的位移信息，可以通过提取操作把这个界限往下推一些，但推不了太多。**所以低速段的速度 loss 权重要给得更高**，因为那一段本来就最难，而且它恰好决定刹不刹车。

## 第 17 条 · CBGS 类别平衡

### 🆕 补第四层手段：BEV 空间数据增强

视频 C：

> 「我们会在 **BEV 的层面上面来做一些 augmentation，包括一些旋转、flip 这些操作**」

**这一条值得单独说**，因为它连着 BEVDet 的一个核心贡献：

> LSS 的视图变换会把**图像空间的增强"传导"到 BEV 空间**，导致 BEV 编码器过拟合。BEVDet 的解法是**把 image-view 增强和 BEV 增强解耦**——图像端做完增强后，用对应的变换矩阵修正内参；BEV 端独立做旋转、翻转、缩放。

`口语`

> 除了采样和 loss 层面，我们在 BEV 空间也做数据增强——旋转、flip 这些。**这里有个坑值得说**：LSS 路线下，图像空间的增强会通过视图变换"传导"到 BEV，如果不做解耦，BEV 编码器会严重过拟合到那个传导关系。所以图像端做完增强要同步修正内参矩阵，BEV 端再独立做自己的增强。这是 BEVDet 那篇专门讨论过的问题。
