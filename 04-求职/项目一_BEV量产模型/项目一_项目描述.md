## 1. 项目概况

- **项目场景**：面向量产智能驾驶的行车（高速 / 城区 NOA）与泊车（地库 / 路边）场景的多模态 BEV 3D 目标检测。
- **产品定位**：感知栈中的动态目标检测模块，向下游规控输出障碍物的 3D 位置、尺寸、朝向、速度与动静属性。
- **技术路线**：Camera 为主、LiDAR / Radar 融合的 **dense BEV** 路线。相机侧走 **LSS 前向投影**系（Lift-Splat-Shoot → BEVDet → BEVDepth → BEVPoolv2），非稀疏 query 系（DETR3D / PETR / StreamPETR）。
- **交付形态**：模型随整车 OTA 版本上车。
- **你的周期**：2024.08 – 至今。项目在你入职前已上车，你接手的是**已量产模型的持续迭代**，不是从 0 立项。

### 1.1 这个项目要解决的真实矛盾

量产感知与学术刷榜是两套不同的优化目标，这是理解整个项目的前提：

| | 学术（nuScenes / Waymo 榜单） | 量产 |
|---|---|---|
| 优化目标 | mAP / NDS 的平均值 | 分场景专题的**通过率** + **不引入恶化** |
| 算力 | A100 集群，几百 ms 推理无所谓 | 车规 SoC，整链路 100ms 硬上限 |
| 数据 | 固定的 40k 帧标注集 | 百万级 clip，持续回流 |
| 失败代价 | 排名掉几位 | **一次误刹 = 一起事故 / 一次客诉** |
| 迭代方式 | 换结构、加参数 | 改 loss、补数据、调真值、抠时延 |

一个 mAP 涨了 2 个点、但在地库多触发 3 次误刹的版本，**绝对不能上车**。这条决定了后面所有的技术选择。

### 2.4 规控怎么消费你的输出（值得单独理解）

| 你的输出 | 规控怎么用 | 误差的后果 |
|---|---|---|
| 3D 框位置 | 计算安全距离、碰撞时间 TTC | 纵向漂 2m → 刹车时机错 |
| 3D 框尺寸 / 朝向 | 判断是否侵入本车道 | 朝向错 15° → 误判切入 |
| 速度 vx / vy | 预测轨迹、决定跟车 / 变道 | 速度跳变 → 加减速抖动、乘客不适 |
| 动静属性 | 静止物体可忽略 / 动态物体需跟踪 | 静止判动 → 无谓减速；动态判静 → 追尾 |
| **凭空误检** | 触发 AEB | **直接误刹，最严重的问题类型** |
| **检出距离** | 决定多早能发起变道 | 检出晚 → 变道仓促或错过 |

这张表解释了为什么这个项目的 KPI 是「检出距离」「动静通过率」「误检通过率」，而不是 mAP。

## 3. 传感器配置与车端部署环境

### 3.1 传感器布置

| 传感器 | 数量 | 典型参数 | 作用 |
|---|---|---|---|
| 针孔相机 | 7 路 | 前视长焦（30° FOV）、前视主（60°）、前视广角（120°）、侧前 ×2、侧后 ×2；2–8MP | 主视觉输入，覆盖中远距 |
| 环视鱼眼 | 4 路 | 前后左右各一，FOV 190°+，1–2MP | 近场 360° 覆盖（泊车、近距切入） |
| 激光雷达 | 1–2 | 半固态 / 转镜，120°×25° FOV，150m@10% 反射率，10Hz | 训练期深度真值；推理期 BEV 特征 |
| 毫米波雷达 | 1–5 | 前向长距 + 角雷达，250m 探测 | 速度直接测量、恶劣天气冗余 |

**7 路针孔的典型布置逻辑**：长焦看远（200m 外的小目标）、主视覺看中距、广角看近距和大角度切入，侧向覆盖相邻车道。三个前视焦段不同，同一个目标在不同距离由不同相机主导。

### 3.2 传感器的双重角色（这个项目最核心的概念之一）

**点云在这个模型里扮演两个完全不同的角色：**

| | 训练期 | 推理期 |
|---|---|---|
| 用途 | 投影到图像生成**逐像素深度真值**，监督 DepthNet | 走点云编码器出**BEV 特征**，与视觉 BEV 特征融合 |
| 对应方法 | BEVDepth | BEVFusion |
| 训练完还需要吗 | 不需要 | 需要，是真实输入 |

**判别方法**：把激光拔掉，模型还能不能前向？

- 只有训练期角色 → 能前向，纯视觉推理（BEVDepth 式）
- 有推理期角色 → 不能前向，这条支路直接断（BEVFusion 式）

**这个项目是「双角色」**——两个都有。

**但技术方向是**：提升纯视觉能力、降低对激光的依赖。原因很直接——激光雷达单颗成本仍在数百到上千美元，能去掉就是每台车的净利润。你做的深度优化正是服务这个目标：**深度估得越准，视觉支路越强，对激光的依赖就越低**。

### 3.3 标定与同步

- **内参**：焦距 fx/fy、主点 cx/cy、畸变系数。针孔用 5 参数径向切向模型；鱼眼用等距（equidistant）或 KB 模型，畸变系数 4 个。
- **外参**：各传感器到自车坐标系（后轴中心）的 6DoF 变换。标定误差 0.5° 在 100m 处就是 **0.87m 的横向偏移**——这是 BEV 位置误差的重要来源。
- **时间同步**：相机曝光与激光扫描的硬件触发同步。50ms 的不同步，在 120km/h（33m/s）下就是 **1.65m 误差**。
- **激光运动畸变**：激光旋转扫描一圈 100ms，期间车已经开出 3.3m，点云需要按 IMU 位姿做**去畸变**（motion compensation）才能用。

### 3.4 车端计算平台

| 平台 | 算力（INT8） | 备注 |
|---|---|---|
| 单 Orin X | 254 TOPS | 主流单板方案 |
| 双 Orin X | 508 TOPS | 高阶智驾常见 |
| 地平线 J5 | 128 TOPS | |
| 华为 MDC 610 | 200+ TOPS | |

**关键认知**：标称 TOPS 与实际可用算力差距很大。真实模型的**算力利用率通常只有 20–40%**，因为访存带宽、算子调度、非规整算子（如 BEVPool、可变形卷积）都会掉效率。所以「254 TOPS」不等于你能跑 254 TOPS 的模型。

**BEV 感知模型的典型资源占用**：

- 模型参数量：20–80M
- 单帧推理：25–60ms（INT8）
- 显存 / 内存：2–6GB
- 感知模块总时延预算：**100ms（10Hz）**，其中检测模型分到 40–60ms

## 4. 算法总体架构（全链路数据流）

```
                          ┌─────────── 训练期专用 ───────────┐
                          │                                  │
7×针孔图像 ──→ Image Backbone ──→ Neck(FPN) ──┬──→ PV辅助检测头 ──→ 2D辅助loss
   1920×1080                (ResNet/RegNet)   │
   ↓ resize+crop                              ├──→ DepthNet ──→ 深度分布 D (118 bins)
```

### 4.1 BEV 空间的定义

这是所有讨论的坐标系基础：

| 参数 | 典型值 | 说明 |
|---|---|---|
| 坐标原点 | 自车后轴中心 | x 向前、y 向左、z 向上 |
| 纵向范围 | [-80m, +160m] | 前向要覆盖高速检出需求 |
| 横向范围 | [-40m, +40m] | 覆盖相邻数条车道 |
| BEV 网格分辨率 | 0.4m–0.8m | 学术常用 0.8m，量产远距常降到 0.4m |
| BEV 特征图尺寸 | 128×128 或 200×200 | 分辨率与范围的乘积 |
| 高度维 | 压缩掉 | dense BEV 把 z 方向拍平，只在检测头回归 z |

**为什么把高度拍平**：俯视图下车辆不会互相重叠，二维平面已经足够表达空间关系；保留 z 维会让特征图变成 3D，计算量涨一个数量级。

### 4.2 为什么深度是整条链的命门

LSS 路线下，**图像特征最终落在 BEV 的哪个格子，完全由 DepthNet 预测的深度分布决定**。

深度歪了 → 特征被"涂"到错误的格子 → 后面的检测头无论多强都救不回来。表现出来就是三件事：

1. **位置漂移**：目标框在 BEV 上前后跳动；
2. **凭空误检**：错误位置累积了本不该有的特征响应；
3. **远距漏检**：远处特征被涂散，响应不够强。

这解释了为什么在这个项目里，深度是投入产出比最高的优化方向。

## 5. 相机支路详解 `▸ 你的主战场`

### 5.1 LSS（Lift-Splat-Shoot）完整流程

**Lift（提升）**：把 2D 特征提升到 3D 视锥

对图像特征图上的每个像素 `(u,v)`：

- DepthNet 输出一个**离散深度分布** `D ∈ R^{118}`（把 [1m, 60m] 按 0.5m 切成 118 个 bin，做 softmax）
- 同时输出**上下文特征** `C ∈ R^{80}`
- 两者做**外积**：`Frustum(u,v) = D ⊗ C ∈ R^{118×80}`

物理含义：**把这个像素的语义特征，按深度概率"涂抹"到这条视线上的 118 个位置**。如果 DepthNet 很确定目标在 20m，那 20m 那个 bin 的权重接近 1，特征几乎全部集中在那；如果不确定，特征就摊薄在一段范围上。

**Splat（拍扁）**：视锥点 → BEV 网格

- 用内外参把每个视锥点 `(u, v, d)` 变换到自车坐标系 `(x, y, z)`
- 找到它落在哪个 BEV 格子
- 同一格子内的所有视锥特征做 **sum pooling**

**Shoot**：在检测任务里就是接检测头。（原论文里是做运动规划，"shoot"出轨迹）

### 5.2 深度为什么用分类而不是回归

| | 回归（直接输出一个深度值） | 分类（输出深度分布） |
|---|---|---|
| 多峰情况 | 半透明 / 边缘像素会输出两个真值的平均，错得离谱 | 可以表达"可能在 10m 也可能在 30m" |
| 不确定性 | 无法表达 | 分布的熵天然就是置信度 |
| 与 LSS 的兼容 | 需要额外处理 | 直接就是 splat 的权重 |
| 训练稳定性 | 远距样本少时容易崩 | 交叉熵更稳 |

**深度 bin 的划分方式**：

- **UD（均匀）**：`[1, 60]` 均分 118 份，每份 0.5m。近处过密、远处过疏。
- **LID（线性递增）**：bin 宽度随距离线性增长，远处 bin 更宽。因为远处本来就估不准，硬要 0.5m 精度是浪费。
- **SID（对数）**：更极端的递增。

量产长距场景常用 LID，比如 `[1, 150]` 分成 150 个 bin，1m 处 bin 宽 0.3m，150m 处 bin 宽 4m。

### 5.3 BEVPoolv2：为什么快 18 倍

**原始 LSS 的 Splat 有两个致命开销**：

1. **显式构造视锥特征张量**：`6 相机 × 118 深度 × 16 × 44 空间 × 80 通道 ≈ 4000 万个 float`，显存爆炸；
2. **排序 + 前缀和**：把所有视锥点按 BEV 格子 ID 排序（GPU 上排序很贵），再做 cumsum，再区间差分。

**BEVPoolv2 的关键洞察**：

> 视锥点 → BEV 格子的**索引映射只由内外参决定**。内外参在车上是固定的（除非在线标定更新），所以这个索引可以**离线预计算**一次，存成查找表。

运行时只需要：按预计算的索引，直接把对应的 `D[i] × C[j]` 累加到目标格子。**不排序、不 cumsum、不显式构造视锥张量**。

**公开数据**（BEVPoolv2 论文，nuScenes 配置）：视图变换耗时 **15.5ms → 0.82ms，加速 18.9 倍**；显存占用大幅下降。

**这就是"用加速换精度"的来源**：视图变换原本是相机支路最大的耗时项，省下来的十几 ms 正好够把 DepthNet 从 3 层加深到 6–8 层、再接一个 CRF 模块。

### 5.4 DepthNet 的结构演进

| 版本 | 结构 | 效果 |
|---|---|---|
| BEVDet | 简单 1×1 卷积输出深度分布 | 基线 |
| **BEVDepth** | 加入**相机内参编码**（把 fx/fy 通过 MLP 注入特征，因为同样的像素尺寸在不同焦距下对应不同真实尺寸）+ 显式深度监督 | nuScenes mAP 0.359 → 0.412 |
| **BEVNeXt** | 深度输出后接 **CRF（条件随机场）**做空间平滑，利用邻域一致性抑制深度噪声 | 进一步提升，尤其远距 |

**CRF 在这里做什么**：相邻像素如果在图像上颜色 / 特征相似，它们的深度大概率也接近。CRF 用这个先验做一次全局优化，把孤立的深度噪点拉回邻域的一致值。代价是增加一点推理耗时。

### 5.5 深度真值生成（你的核心工作，讲最细）

**基础做法**：

```
激光点云 (x,y,z) → 按外参变换到相机系 → 按内参投影到图像平面 (u,v,d)
                 → 每个像素取深度 d → 按 bin 离散化 → 交叉熵监督 DepthNet
```

**问题**：单帧激光在图像上极其稀疏。

- 一帧激光约 **10–20 万点**，投到 1600×640 的图像上，**有效像素覆盖率不到 5%**；
- 而且激光点在垂直方向按线束分布，远处线束发散，**60m 外基本只剩零星几个点**；
- 结果就是中远距几乎没有监督信号 → 深度估不准 → 你的问题来源。

**解法：多帧点云聚合加密**

聚合 10 帧（1 秒）能把有效覆盖率提到 20–30%，远距点数增加数倍。但直接叠会出四个问题：

**① 运动补偿**
历史帧的点云是在历史时刻的自车坐标系下的，必须按自车位姿（来自 IMU / 轮速 / 定位）把它们对齐到当前帧坐标系：

```
P_current = T_current←history · P_history
```

位姿误差会直接体现为点云"重影"，所以对定位精度有要求。

**② 动态目标拖影（最花时间的一块）**
静态背景对齐后完全重合，但**运动中的车辆会拖出一条长尾**——一辆 60km/h 的车在 1 秒内移动 16.7m，聚合后会在图像上形成一条 16.7m 长的"深度带"，这是完全错误的监督信号。

三种处理方式：

| 方式 | 做法 | 优缺点 |
|---|---|---|
| 剔除 | 用真值 3D 框框住动态目标，把框内的历史帧点全部删掉 | 简单可靠，但动态目标区域回到单帧稀疏度 |
| 单独补偿 | 按目标自身的运动（来自跟踪的速度）把历史点搬到当前位置 | 保留了密度，但依赖速度真值精度 |
| 混合 | 高置信度跟踪的目标做补偿，其余剔除 | 实际常用 |

**③ 遮挡剔除**
聚合后的点云里，被前景遮挡的背景点也会投影到图像上，导致同一个像素同时有前景深度（5m）和背景深度（50m）。处理方式是做 **z-buffer**：同一像素只保留最近的深度；或者用局部深度一致性检验剔除离群。

**④ 鱼眼单独处理**
鱼眼的投影模型完全不同（等距模型 `r = f·θ` 而非针孔的 `r = f·tan θ`），必须按各自的畸变模型独立投影，不能复用针孔的投影代码。

**效果**：中远距深度误差下降约 15%。

### 5.6 PV 辅助监督（BEVFormerV2 思路）

**问题**：检测 loss 只作用在 BEV 空间，反向传播到 image backbone 时梯度已经很弱（中间隔了视图变换、融合、时序等多层），图像特征学不充分。

**解法**：

```
BEV 3D 真值框 → 按内外参反投影到各相机图像平面 → 生成 2D 框真值
image backbone 输出 → 接一个轻量 2D 检测头 → 与反投的 2D 真值算 loss
```

**核心优势**：这个辅助头**只在训练期存在，推理时直接摘掉**，零额外时延。在有硬时延预算的量产场景，这一点是决定性的——同样的精度提升，如果要付出 5ms 推理代价，很可能就上不了车。

**落地细节（论文不讲、但实际必须做的）**：

1. **遮挡过滤**：3D 框反投过去，有些目标被前车完全遮挡，图像上根本看不见。直接拿来监督就是在教模型"从空气里检测出车"，是纯噪声。需要用深度关系或可见性判断过滤掉。
2. **截断降权**：目标只有一部分在画面内时，2D 框不完整，应该降低 loss 权重。
3. **尺寸过滤**：反投后小于几个像素的目标直接丢弃。
4. **多相机去重**：同一个 3D 目标可能同时出现在两个相机的视野里，各自独立监督即可，但要注意两边的可见性不同。

## 6. 点云支路、融合与时序

### 6.1 点云编码器的两条路线

| | PointPillars | VoxelNet / SECOND |
|---|---|---|
| 空间划分 | 只在 x-y 分格，z 方向不切（"柱子"） | x-y-z 三维体素 |
| 特征提取 | 柱内点做 PointNet → 2D 伪图像 → 2D 卷积 | 体素内做 PointNet → 3D 稀疏卷积 → 压缩到 BEV |
| 速度 | 快，全 2D 卷积，部署友好 | 慢，3D 稀疏卷积算子在车端支持差 |
| 精度 | 略低（丢了高度细节） | 更高 |
| 典型配置 | pillar 0.2m×0.2m | voxel 0.075m×0.075m×0.2m |

量产**倾向 PointPillars 系**，因为 3D 稀疏卷积在车端 SoC 上往往没有高效实现，而 PointPillars 全是标准 2D 算子。

### 6.2 Radar 的特殊价值

毫米波常被低估，但它有两个视觉和激光都给不了的东西：

1. **直接测速**：多普勒效应直接测出径向速度，不需要跨帧差分。这对速度估计是硬增益。
2. **恶劣天气穿透**：雨雾雪中激光衰减严重、相机失效，毫米波基本不受影响。

代价是**分辨率极低**（角分辨率几度）、**杂波多**（金属井盖、护栏都会强反射）。所以 Radar 通常不独立出检测结果，而是作为特征融合进去，或者用于速度校正。

### 6.3 BEV 特征级融合

各模态特征都被统一到同一个 BEV 网格上之后，融合就变成了一个特征图对齐问题。三种典型做法：

| 方式 | 实现 | 特点 |
|---|---|---|
| **Concat + Conv** | 通道维拼接后过几层卷积 | 最简单、最快、量产常用 |
| **注意力融合** | 让网络学习每个位置上各模态的权重 | 能自适应（如远处更信激光、近处更信视觉），但慢 |
| **BEVFusion 式** | 各模态独立编码到统一 BEV 表征，再用卷积融合 | 保留模态独立性，某模态失效时不崩 |

**融合层要解决的核心工程问题是模态降级**：

- 激光被泥水糊住 / 硬件故障
- 相机被阳光直射过曝 / 逆光
- 某路相机被遮挡

量产系统必须保证**任一模态失效时，输出降级但不崩溃**。常见做法是训练时随机 drop 某个模态（modality dropout），强迫网络不过度依赖单一模态。

### 6.4 时序融合

**做什么**：把历史帧的 BEV 特征按自车位姿对齐到当前帧，再聚合。

```
BEV_history(t-1) --ego motion 变换--> 对齐到 t 时刻坐标系 --> 与 BEV(t) 聚合
```

**为什么有效**：

1. **速度估计**：单帧图像根本无法估计速度（一张静止照片看不出车在动），必须靠时序；
2. **遮挡缓解**：目标在当前帧被遮挡，但历史帧可见，特征还在；
3. **稳定性**：抑制单帧的检测闪烁（这一帧有、下一帧没有）；
4. **远距增益**：远处目标单帧信噪比低，多帧累积等效于增加曝光。

**用几帧**：

| 方案 | 帧数 | 说明 |
|---|---|---|
| BEVDet4D | 1 帧历史 | 最简单，只为了算速度 |
| BEVFormer | 1 帧（但用 RNN 式递归，隐含长历史） | |
| SOLOFusion | 16 帧长时序 | 精度高，但显存和时延代价大 |
| 量产典型 | 4–8 帧 | 平衡点 |

**聚合方式**：concat 后卷积（最简单）、加权求和、可变形注意力对齐（处理位姿误差）。

## 7. 检测头、输出定义与下游接口

### 7.1 CenterPoint Head

**为什么 anchor-free 适合 BEV**：俯视图下目标不会互相重叠（车不会叠在车上），所以"一个中心点对应一个目标"的假设成立。这省掉了 3D anchor 的设计（3D anchor 需要枚举尺寸和朝向，组合爆炸）和正负样本匹配的复杂度。

**输出分支**：

| 分支 | 维度 | 说明 | Loss |
|---|---|---|---|
| heatmap | `H×W×num_class` | 每类的中心点热力图，高斯分布 | Gaussian Focal Loss |
| offset | `H×W×2` | 中心点在格子内的亚像素偏移 | L1 |
| height | `H×W×1` | 目标中心的 z 坐标 | L1 |
| size | `H×W×3` | log(l), log(w), log(h) | L1 |
| rotation | `H×W×2` | **sin(yaw), cos(yaw)** | L1 |
| velocity | `H×W×2` | vx, vy | Smooth L1 |
| 动静属性 | `H×W×1` | 二分类 | BCE |

**朝向为什么用 sin-cos 而不是直接回归角度**：角度在 0 和 2π 处不连续，一个真值 359° 的目标，模型预测 1° 实际只差 2°，但 L1 loss 算出来是 358——梯度会把模型往完全错误的方向推。sin-cos 双分量表示是连续的，没有这个跳变问题。

> 这个技巧你在**项目二的改道属性头**里也用过（角度 sin-cos 回归），两个项目可以互相印证。

### 7.2 后处理

- **Rotated NMS**：3D 框有朝向，IoU 计算需要旋转框相交面积，比 2D NMS 贵；
- **置信度阈值**：量产的工作点选择很讲究——阈值低了误检多（误刹），高了漏检多（追尾）。通常按**类别**和**距离段**分别设阈值，比如行人的阈值低于车辆（漏检行人代价更大）；
- **跟踪接口**：检测结果送入跟踪模块（常用匈牙利匹配 + 卡尔曼滤波），输出带 ID 的稳定 track。

## 8. 数据资产、真值生产与标注体系

### 8.1 数据规模量级

| 数据集 | 规模 | 说明 |
|---|---|---|
| nuScenes | 1000 段 20s clip，40k 标注帧 | 学术基准 |
| Waymo Open | 1150 段，20 万帧 | 学术基准 |
| **量产数据湖** | **百万级 clip，PB 级存储** | 车队持续回传 |
| 单版本训练集 | 50 万 – 200 万帧标注 | 从数据湖挑选 |

### 8.2 数据从哪来

1. **量产车队回传**：装车的量产车在用户日常驾驶中触发条件回传（不是全量回传，带宽和存储都不允许）；
2. **触发规则**：接管、急刹、系统降级、检测置信度异常、跟踪 ID 频繁切换等；
3. **专项采集**：针对某个专题（如地库闸机）派采集车定向采；
4. **难例挖掘**：从数据湖中按规则检索 `▸ 你的工作`；
5. **仿真 / 合成**：极端场景（碰撞前、异常天气）用仿真补。

### 8.3 3D 真值怎么生产

这是整个链条里最贵的一环：

```
① 激光多帧聚合 → 生成稠密的静态场景点云
② 预标注模型（离线大模型，不受时延约束）出初始 3D 框
③ 人工在点云 + 图像上精调框
④ 时序 ID 关联（同一目标跨帧一致的 track id）
⑤ 速度真值 = 相邻帧位置差分 / Δt
⑥ 质检抽查
```

**成本**：一帧多目标 3D 标注的市场价约 **10–50 元**，一个 50 万帧的训练集就是数百万到千万级的标注成本。所以**预标注模型的质量直接决定标注成本**，这也是为什么各家都在做离线大模型自动标注。

**关键：速度真值是差分出来的，噪声很大**

- 位置真值本身有 ±10cm 误差
- 差分后：`0.1m / 0.1s = 1 m/s = 3.6 km/h` 的速度噪声
- 远距目标位置误差更大，速度噪声可以到 10km/h

**这直接解释了为什么速度 loss 要用 Smooth L1 而不是 L1**：L1 对离群样本的梯度是常数 ±1，一批噪声真值就能把训练带偏；Smooth L1 在小误差区间是二次的、大误差区间是线性的，对离群点更宽容。

### 8.4 数据切分的陷阱

**错误做法**：把所有帧混在一起随机切分 train/val。

**为什么错**：同一段 clip 里相邻帧几乎一模一样（10Hz 采样，0.1s 内场景变化极小）。随机切分会让**几乎相同的帧同时出现在训练集和验证集**，验证指标虚高，完全没有泛化意义。

**正确做法**：**按 clip / 场景切分**。同一段 clip 的所有帧必须整体归属于训练集或验证集。

进一步的做法是按**地理区域**、**时间段**、**天气**切分，确保验证集测的是真泛化能力。

### 8.5 冻结测试集

量产项目必须有一个**冻结的、不参与任何训练和调参的测试集**，用于版本间的公平对比。这个集合一旦定下就不再修改（否则历史版本的指标不可比）。所有"对比商发基线"的数字都应该在这个集合上产生。

## 9. 训练流程与工程配置

### 9.1 典型配置

| 项 | 典型值 |
|---|---|
| 框架 | PyTorch + MMDetection3D / 自研训练平台 |
| 硬件 | 8–32 卡 A100 80G / A800 |
| 分布式 | DDP，SyncBN |
| 精度 | AMP 混合精度（FP16 + FP32 master weights） |
| Batch Size | 每卡 2–8（BEV 模型显存占用大） |
| 优化器 | AdamW，lr 2e-4，weight decay 0.01 |
| 学习率策略 | Cosine annealing + 500–2000 iter warmup |
| 训练轮数 | 12–24 epoch（量产大数据量下 epoch 数更少） |
| 训练时长 | 全量训练 3–7 天 |
| 图像 backbone 预训练 | ImageNet / nuImages / 内部大规模 2D 检测数据 |

### 9.2 数据增强（BEV 特有）

BEV 3D 检测的增强比 2D 复杂，因为**图像增强和 BEV 空间增强必须几何一致**：

| 增强 | 做法 | 注意 |
|---|---|---|
| 图像端 resize / crop / flip | 常规 | **必须同步修改内参矩阵**，否则投影就错了 |
| BEV 空间旋转 | 绕 z 轴旋转整个场景 | 需同步旋转真值框和外参 |
| BEV 空间缩放 | 整体缩放 | 同上 |
| BEV flip | 左右翻转 | 需同时翻转图像和点云 |
| GT-Paste | 把其他帧的目标点云粘进来 | 点云检测常用，多模态下要同时处理图像，很难做，通常不用 |
| CBGS | 按类别频率重采样 | 见 §10.6 |

**最容易出 bug 的地方**：图像做了 crop 之后忘记改内参 `cx, cy`，或者 BEV 旋转后忘记同步外参。这类 bug 不会报错，只会让精度莫名其妙掉几个点。

## 10. 技术难点、对比方案与效果

> 格式：问题原因 → 候选方案 → 生产选择 → 效果

### 10.1 中远距目标漂移与检出不稳 `▸ 你投入最多`

**问题原因**

- 100m 外的车辆在 1600×640 图像上只有 **15×10 像素**左右；
- 单帧激光在该距离覆盖率不足 1%，**深度监督信号几乎为零**；
- DepthNet 深度分布发散 → 特征涂散到多个 BEV 格子 → 响应弱、位置抖。

**候选方案对比**

| 方案 | 精度增益 | 时延代价 | 结论 |
|---|---|---|---|
| 提高输入分辨率（704×256 → 1600×640） | 大 | **+15–25ms** | 量产付不起 |
| 加深 / 加宽 DepthNet | 中 | +5–8ms | 有条件采用 |
| 深度真值多帧聚合加密 | 中 | **0（仅训练期）** | **必选** |
| 深度输出接 CRF 平滑 | 小–中 | +2–3ms | 采用 |
| LSS → BEVPoolv2 | 精度略升 | **-14ms** | **必选** |
| 长时序融合（16 帧） | 中 | +10ms、显存翻倍 | 不采用 |

**生产选择**：`深度真值加密 + BEVPoolv2 + 加深 DepthNet + CRF`

组合逻辑是关键：**先用 BEVPoolv2 省出 14ms，再把这 14ms 投给更重的 DepthNet 和 CRF**。净时延基本持平，精度显著提升。这就是"用加速换精度"的等价交换。

**效果**：中远距深度误差 **-15%**；平均检出距离提升至 **131.5m**。

### 10.2 鱼眼畸变导致近场几何失配

**问题原因**：鱼眼 FOV 190°，边缘畸变极强。按针孔模型（`r = f·tan θ`）近似处理时，在 θ 接近 90° 处 tan 发散，几何完全失配。

**候选方案对比**

| 方案 | 问题 |
|---|---|
| 统一按针孔模型近似 | 近场定位误差大，边缘目标位置错得离谱 |
| 先去畸变展开成类针孔图 | 展开会**损失边缘视场**（190° 展不成平面），且插值引入伪影 |
| 分块去畸变（切成多个虚拟针孔） | 可行但工程复杂，块边界目标会断 |
| **独立走 PV2BEV Transformer** | 注意力机制不依赖显式投影几何，对畸变和标定误差更鲁棒 |

**生产选择**：鱼眼独立走 transformer PV2BEV，深度真值按鱼眼畸变模型独立投影。

**为什么针孔不也用 transformer**：BEV query 的数量随探测范围的**平方**增长。

- 鱼眼覆盖近场 ±20m，0.4m 分辨率 → 100×100 = **1 万 query**
- 针孔覆盖 ±160m，同分辨率 → 800×800 = **64 万 query**

交叉注意力的计算量与 query 数成正比，64 万 query 的 transformer 在车端完全不可行。**这是一个纯粹由算力约束决定的折中方案**，不是最优设计——理想状态是统一架构。

### 10.3 凭空误检（长尾难负样本）`▸ 你主导`

**问题原因**

- 护栏的竖直纹理、前车尾气的团状结构、地库立柱、闸机横杆，在图像上与车辆局部纹理高度相似；
- 更隐蔽的是**深度估计错误引发的误检**：深度歪了导致某个位置累积了本不该有的特征响应；
- **这类难例在数据湖里没有标签，检索不出来**——你不能用"标签=误检"去搜，因为误检本来就没有标签。

**候选方案对比**

| 方案 | 可行性 |
|---|---|
| 人工大规模筛查 | 百万级 clip，成本不可接受 |
| loss 层面加权抑制背景 | 治标，且容易连带掉召回 |
| 提高置信度阈值 | 直接掉召回，不可接受 |
| **时序判据自动挖掘** | **可行**：真实目标在时序上连续，凭空误检的特征是"突现突消" |
| 场景规则批量捞（按 GPS 捞地库 / 闸机） | 辅助手段，效率高但不精准 |

**时序判据的具体设计**

```
对每个 track：
  if 生命周期 ≤ N 帧（如 3 帧）
     and 出现时置信度已经很高（不是渐进浮现）
     and 消失时没有被遮挡的合理解释
     and 期间位置跳变大 / 速度不合物理
  → 标记为疑似凭空误检候选
```

挖出候选后送人工快速复核确认，再按场景（地库 / 闸机 / 护栏 / 尾气）归类构建难负样本专项集回灌训练。

**关键的反向风险**：负样本加多了会掉召回。所以回灌后必须跑全量防护网确认真车的召回没有恶化——这正是"无恶化引入"这条准入规则存在的意义。

**效果**：泊车误检率 **-3.7%**；凭空误检通过率 **+5.1%**。

### 10.4 图像端梯度弱 `▸ 你主导`

见 §5.6。效果：方案已合入主干训练配置。

### 10.5 速度跳变与动静误判 `▸ 你主导`

**问题原因**

1. **误差耦合**：直接回归 vx / vy 时，"方向偏 30° 但大小准"和"方向准但大小偏 30%"这两种情况，L1 loss 可能相近，**但对规控的影响完全不同**——方向错会导致轨迹预测错，大小错只影响跟车距离。
2. **真值噪声**：速度真值由位置差分得到，噪声可达 3–10 km/h（见 §8.3），L1 对离群样本梯度恒定，容易被坏真值带偏。
3. **自相矛盾输出**：动静属性判为"静止"但速度输出 5m/s，下游不知道该信哪个。

**生产选择**（三条全上）

| 改动 | 作用 |
|---|---|
| L1 → **Smooth L1** | 抑制离群真值的梯度贡献 |
| vx/vy → **极坐标解耦**：速度模长 \|v\| 与朝向 θ 分别监督 | 两种误差解耦，可以分别加权（规控更在意方向就给方向更大权重） |
| 与**动静属性联合约束** | 静止判定与速度输出一致性，消除自相矛盾 |

**朝向的周期性问题**：极坐标下 θ 同样有 0/2π 跳变，同样用 **sin-cos 双分量**解决。

**效果**：速度与动静专题通过率 **+3.5%**；已合入主干。

### 10.6 类别与距离分布失衡 `▸ 你主导`

**问题原因**（nuScenes 的真实分布可作参考）

| 类别 | 占比 |
|---|---|
| 车辆（car） | ~60% |
| 卡车 / 巴士 | ~10% |
| 行人 | ~20% |
| 骑行人（bicycle/motorcycle） | **~3%** |

距离维度同样失衡：**80% 以上的标注目标在 50m 以内**，100m 外的目标不足 3%。

**候选方案对比**

| 方案 | 效果 | 副作用 |
|---|---|---|
| **CBGS**（Class-Balanced Grouping and Sampling） | 按类别频率重采样，稀有类别出现频率提高 4–5 倍 | 训练集膨胀，训练时间增加 |
| 类别 loss 加权 | 简单直接 | 权重过大会**显著增加该类误检** |
| Focal Loss | 理论上适合失衡 | **在已预训练的高置信度模型上会失效**（见下） |
| 定向补采数据 | 根本解法 | 周期长、成本高 |

**为什么不用 Focal Loss（重要）**

Focal Loss 的调制因子是 `(1-p)^γ`。它的设计前提是"模型对大部分样本还没学好，p 分布在中间区间"。

但在一个**已经预训练好、置信度普遍很高（p→1）**的模型上继续训练时：

```
(1-p)^γ → 0
```

**几乎所有样本的权重都被压到接近 0，梯度信号整体消失，训练直接失效。**

> 这个坑你在**项目四（焊缝缺陷检测）**踩过并解决过——当时改成了定制 BCE 抑制硬 FP。两个项目的这条经验完全一致，可以串起来讲。

**生产选择**：CBGS 重采样 + 温和的类别 loss 加权。

**效果**：弱势类别（行人 / 骑行人）召回提升。

## 11. 评测体系与指标口径

### 11.1 学术指标（了解即可）

**nuScenes NDS**：

```
NDS = 0.5 × mAP + 0.5 × (1/5)Σ(1 - min(1, TP_error))
```

其中 5 个 TP 误差项：

| 缩写 | 全称 | 含义 |
|---|---|---|
| mATE | Average Translation Error | 平移误差（m） |
| mASE | Average Scale Error | 尺寸误差（1-IoU） |
| mAOE | Average Orientation Error | 朝向误差（rad） |
| **mAVE** | Average Velocity Error | **速度误差（m/s）** |
| mAAE | Average Attribute Error | 属性误差 |

**nuScenes 的 mAP 用中心距离而非 IoU 匹配**（阈值 0.5/1/2/4m 平均），因为 3D IoU 对小目标过于苛刻。

### 11.2 量产指标（真正用的）

| 维度 | 指标 |
|---|---|
| **距离** | 平均检出距离、首次稳定检出距离、分距离段的 P/R |
| **稳定性** | 跨帧 ID 连续性、检出闪烁率、3D 框抖动幅度 |
| **误检** | 分场景的凭空误检次数 / 千公里 |
| **速度动静** | 速度误差分布、动静误判率 |
| **时延** | 目标进入视野到稳定输出的帧数 |
| **准入** | **全专题无恶化** |

### 11.3 你的数字口径

| 指标 | 数值 | 口径 |
|---|---|---|
| 平均检出距离 | **131.5m** | 对比商发基线，冻结测试集 |
| 动静属性通过率 | **+3.5%** | 动静专题评测集 |
| 凭空误检通过率 | **+5.1%** | 误检专题评测集 |
| 泊车误检率 | **-3.7%** | 泊车专项集 |
| 中远距深度误差 | **-15%** | 分距离段深度评测 |
| 全评测项 | **无恶化引入** | 全量防护网回归 |

**"稳定检出距离"的标准定义**：目标从远处接近，**连续 N 帧（通常 3 帧）**被检出且置信度超过阈值时，记录**自车中心到目标中心的直线距离**。用"连续 3 帧"是为了排除偶发的单帧闪现。

### 11.4 为什么量产不能只看 mAP

mAP 是一个**平均量**，它会掩盖长尾问题：

- 一个版本在 99.9% 的常规场景涨了，在 0.1% 的地库场景多了 3 次误刹 → mAP 涨，但**不能上车**；
- 一个版本整体持平，但把远距漏检修好了 → mAP 几乎不动，但**是好版本**。

所以量产的评测输出不是一个标量，而是一张**分层 diff 报表**：按场景 × 按距离 × 按类别 × 按问题类型，每一格都给出相对基线的优化 / 恶化。任一格恶化超过阈值 → 不准入。

> 这套体系正是你的**项目三（评测防护网与数据闭环）**在做的事，两个项目互相支撑。

## 12. 部署、量化与时延预算

### 12.1 部署链路

```
PyTorch 模型
   ↓ torch.onnx.export
ONNX
   ↓ 算子检查 / 图优化 / 自定义插件
TensorRT Builder（或厂商工具链）
   ↓ INT8 校准（PTQ）或 QAT
TensorRT Engine（.plan）
   ↓
车端 SoC 推理
```

### 12.2 BEV 模型的部署难点

| 难点 | 说明 | 解法 |
|---|---|---|
| **BEVPool 算子不标准** | ONNX 没有对应算子 | 写 TensorRT **自定义插件**（CUDA kernel） |
| 可变形注意力（鱼眼支路） | 同样非标准算子 | 自定义插件 |
| 视锥特征张量巨大 | 中间张量显存爆 | BEVPoolv2 本身就解决了这个 |
| 多相机 batch | 6–7 路图像要并行处理 | batch 维度打包，注意 batch=7 时的算子效率 |
| 时序特征缓存 | 历史 BEV 特征需要跨帧保存 | 车端维护 feature buffer，注意内存对齐 |

### 12.3 量化

| 方式 | 说明 | 精度损失 |
|---|---|---|
| **PTQ**（训练后量化） | 用几百张校准图统计激活值分布，确定量化 scale | 通常 mAP 掉 0.5–2% |
| **QAT**（量化感知训练） | 训练时插入伪量化节点 | 损失 <0.5%，但要重训 |
| **混合精度** | 对量化敏感层（DepthNet 输出、softmax、注意力）回退 FP16 | 常用的折中 |

**深度分布这一层特别敏感**：softmax 输出的概率分布量化到 INT8 后，118 个 bin 的细微差异会被抹平，深度精度明显下降。所以这一层通常保持 FP16。

### 12.4 时延预算（典型 10Hz 系统）

| 环节 | 预算 |
|---|---|
| 图像 ISP + 预处理 | 5–10ms |
| Image Backbone（×7 路） | 15–25ms |
| DepthNet + 视图变换 | 5–12ms |
| 点云编码 | 5–10ms |
| BEV 融合 + 时序 | 5–10ms |
| 检测头 | 3–5ms |
| 后处理 + NMS | 2–5ms |
| **感知模块合计** | **40–70ms** |
| 预测 + 规划 + 控制 | 剩余 |
| **端到端上限** | **100ms（10Hz）** |

**BEVPoolv2 的价值在这张表里就很清楚了**：视图变换从 15.5ms 降到 0.82ms，等于在总共 40–70ms 的预算里凭空多出 14ms——这 14ms 可以买到更深的 DepthNet、CRF 模块，或者更高的输入分辨率。**在量产里，时延就是硬通货。**

## 13. 版本迭代与交付流程

```
① 问题输入          路测反馈 / 客诉 / 竞品对标 → 问题归类 → 立项本轮专题
        ↓
② 复现与定位  ◄──── ▸ 你的核心工作
   本地复现问题帧 → 分层评测（按距离/场景/类别）定位劣化环节
        ↓
③ 方案设计与消融
   小规模训练做 A/B，确认增益来源，排除混淆因素
        ↓
④ 合入主干
   有效方案进主干训练配置，做代码评审
        ↓
⑤ 全量训练
   8–32 卡，3–7 天
        ↓
⑥ 自验          ◄──── ▸ 你负责
   防护网全量回归 → 出优化/恶化 diff 报表
        ↓
⑦ 送测准入      ◄──── ▸ 你负责
   无恶化项才能送测
        ↓
⑧ 系统级测试
   上车实测、场景库回归、路试里程
        ↓
⑨ 封版 / OTA 交付
```

**"无恶化引入"是量产最硬的一条规则**。它的意思是：你可以不涨，但不能让任何一个已经修好的问题重新出现。因为每一个历史 bad case 背后可能都是一次真实的客诉或事故。

这条规则也解释了为什么量产迭代慢——不是技术难，是每一次改动都要证明"没有破坏任何已有能力"，而这个证明的成本极高。

## 附录 B：两条技术路线的全局对比

| | 前向投影（Push / LSS 系） | 后向查询（Pull / BEVFormer 系） |
|---|---|---|
